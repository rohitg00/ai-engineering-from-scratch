Each folder holds the raw files of one experiment, copied unchanged from the run, except where this file says so. One file sits beside the folders, the machine record of the x86 server guest. `labsum.py` in the folder above computes one summary for each data set into `summary/`, and `python3 capture/run.py --check` computes them again and compares. No file here was typed by hand.

The Mac is an Apple M1 Max with 10 cores and 64 GiB, macOS 26.2, Python 3.13.12, Ollama 0.31.1, and PostgreSQL 14.21. Other work ran on it during every timed run. It ran Ubuntu 24.04, Python 3.13.18, PostgreSQL 16.15, Redis 7.0.15, and Docker 29.1.3. `x86-guest-machine.txt` records these. In T03 and in the old T10, T15, and T16 folders its models are fakes with a fixed delay. The `-x86` folders from T02 to T19, and `failure-drill-x86/`, use Qwen3 4B (`qwen3:4b-instruct-2507-q4_K_M`) on Ollama 0.31.1 on CPU. They set temperature 0 and seed 42. Their scripts set no `num_ctx`, so Ollama used its default context. During T02, `ollama ps` showed a context of 4096, and no other folder records it. The folders that end in `-x86-real` set a context of 8192. The counts of T07 and T08 also use Qwen3 8B with reasoning off. The folders that end in `-mac-real` use Qwen3 4B on Ollama 0.31.1 on the GPU of the Mac, with temperature 0, seed 42, and the default context of the server, 262144. T04 also uses Qwen3 8B with reasoning for #38484, and T06 uses five models. Another agent ran API rows on the Mac during these runs, and each block row holds the output of `uptime`.

## Rows not to use in the x86 folders

- `T07-approvals-x86/01-cases.jsonl`: the G3 rows. Their shape check never matched, because the parent state holds no subgraph messages while it waits. `02-g3-rerun.jsonl` holds G3, and the summary takes it from there. No time of T07 is used.
- `T08-parallel-tools-x86/04-toolnode.jsonl`: the rows with `"warmup": true`, which the summary leaves out. The reply of Qwen3 4B for 1 call held 2 identical calls, so those `ToolNode` rows are 2-call rows.
- `T18-evaluate-leak-x86/02-evaluate-noflush.jsonl`: the POST counts of `noenv:agent`, because those posts happen at exit. The summary uses 02 only for `GET /info`.
- `T19-pytest-plugin-x86/`: with tracking on, the error types come from the `{}` answers of the recorder and the guard, as on the Mac. The run names come from a rough match on the body.
- `T05-retries-x86/`: the 429 and 500 rows are statuses that the relay sent in place of the model, not errors of a provider. The manual names them so.
- `T11-middleware-cost-x86/`: the absolute microseconds depend on the load of 14 to 25. The manual uses the share of the run and the ratio of node hooks to wrap hooks.
- `T02-crash-resume-x86/01-agent-matrix.jsonl` and `02-agent-matrix-rep5-19.jsonl`: the `num_ctx` value in the header, `server default 8192`. `ollama ps` showed a context of 4096 during the run, and every prompt was under 400 tokens. Reps 0 to 4 ran three keys in shuffled rounds of 90 trials, and reps 5 to 19 two keys in rounds of 56, so the load around a trial differs between the files.
- `internals/`: the times of each run, because Ollama shared the guest at a load near 22. The manual uses counts, orders, and the share of framework time.
- `T17-claims-x86/02-nolimit.jsonl`: one run, which shared Ollama for a few minutes with the G3 rerun of T07, so its pace is approximate.
- The `num_ctx` value `server default 8192` in the headers of the `-x86` folders. `lr_common.py` writes that string, but `chat()` sets no `num_ctx`. No record shows the context of those runs, except `ollama ps` during T02.
- The `-x86-real` folders: `settings.num_ctx` in the header, for the same reason. The scripts set `num_ctx` 8192, and the header records it as the top-level `num_ctx`.
- `T15-agent-server-x86-real/02-load.jsonl`: `ollama_busy_s` where `model_overlap_max` is above 1, because Ollama's `total_duration` includes its own queue.
- `T10-long-threads-x86-real/`: use `bytes.main_total` for thread size, because the recall probes ran on forks of the thread. `00-rate-probe.jsonl` only chose the turn count.
- `T16-concurrency-x86-real/`: the p99 of checkpoint calls at 16 and 64 threads as database time, because it holds event loop wait.
- `T15-agent-server-x86-real/`: no `00-*` file is kept.
