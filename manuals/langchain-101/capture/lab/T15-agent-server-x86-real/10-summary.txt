T15 Agent Server under langgraph dev with a real model. The x86 server guest, 2026-11-15.
Versions: langgraph-cli 0.4.43, langgraph-api 0.18.0, langgraph-runtime-inmem 0.38.0, langgraph 1.2.22, langchain 1.5.0, langchain-ollama 1.1.0, in a separate venv built from the lab lock file (Python 3.13.18).
Model qwen3:4b-instruct-2507-q4_K_M via ChatOllama, temperature 0, seed 42, num_ctx 8192 (explicit), num_predict 128. Ollama 0.31.1 on CPU serves one request at a time.
App t15rapp/: graph "agent" = create_agent with ChatOllama and an async add tool, system prompt "You are a calculator assistant. Use the add tool for every addition, then answer in one short sentence."; graph "loopagent" = create_agent with a ping tool that always answers "pong. Not finished yet: call ping again." (the T17 forever prompt). A middleware writes each model call (start, end, tokens, Ollama total_duration) to t15r-events.jsonl, tagged by a marker in the prompt.
Servers: `langgraph dev --no-browser --no-reload` with no jobs setting (dev-default) and with --n-jobs-per-worker 10 (dev-njobs10). Driver t15r_drive.py; t15r_summarize.py writes 09-summary-table.txt. Each request created a thread and ran one run.
"Server added" = client time of the run minus the time inside model calls (measured in the graph). "Wait before first model" = time from the request to the start of the first model call.

n: recursion 3 runs at recursion_limit 25 plus 1 run without config stopped at 120 s; floor 10 runs per method per server; workers 10 background runs per server; load 10 runs at 1 and 4 clients and 32 runs at 16 clients per server (104 runs). All 104 load runs, 40 floor runs and 20 worker runs returned the right sum, 0 errors.

Results
- Recursion stop (dev-default): with {"recursion_limit": 25} the run ended with status error, GraphRecursionError, after 13 model calls and 12 ping calls, 23.8-24.2 s, 3/3. Same counts as T17 in a script. Without config the run was still running at 120 s after 58 model calls and 58 ping calls; the driver cancelled it (status interrupted). The server applied no low default to a create_agent graph.
- Time per run at 1 client: 5.1-5.5 s, of which the model was 4.4-4.5 s (2 calls). dev-default added 1,013-1,015 ms per run (p50), nearly all before the first model call (1,002-1,004 ms). dev-njobs10 added 638-661 ms p50 (range 530-1,020 ms). runs.wait and runs.create+join were the same. So the fixed cost is about 0.6-1.0 s per run, 14-23% of a 4.4 s Qwen3 4B run (the fake run's ~1 s floor holds).
- Jobs per worker: 10 background runs. dev-default ran 1 at a time (starts 4.5 s apart), 47.1 s. dev-njobs10 started all 10 at 0.63-0.66 s, and Ollama answered their model calls one at a time; wall 44.4 s. Throughput the same.
- Load (runs/s; model calls/s): dev-default 1 client 0.185 (0.37), 4 clients 0.222 (0.44), 16 clients 0.223 (0.45); dev-njobs10 0.191, 0.224, 0.226 (0.38, 0.45, 0.45). Output about 10 tokens/s throughout.
  Where the queue sits: dev-default queues runs in the server: at 16 clients run p50 70.7 s, of which 66.2 s before the first model call, model 4.4 s per run. dev-njobs10 starts up to 10 runs at once and the queue moves into Ollama: at 16 clients run p50 56.0 s, model time per run 43.8 s (each call waits in Ollama), server-side wait p50 11.6 s (runs beyond 10 waited up to 38 s).
- Effective model throughput: 0.44-0.45 model calls/s, about 0.22 two-call runs/s. Neither --n-jobs-per-worker nor client count changed it.

Changes against the fake run (fake model 50 ms): jobs per worker still defaults to 1 under langgraph dev, and the ~1 s floor is still there, but with a real CPU model the setting does not raise throughput (fake: 7.7 -> 56.3 runs/s at 100 clients; real: 0.223 -> 0.226 runs/s at 16). It only moves the queue from the server into the model server. The recursion stop of an agent is the same 13 model calls at limit 25 as in a script.
Rows not to use: ollama_busy_s in 02-load.jsonl when model_overlap_max > 1 (Ollama total_duration includes its own queue wait). 00-smoke.jsonl is a smoke run. The double texting rows of the old folder used the model-free slow graph and stay valid; the model-free loop rows (10007) stay valid; the langgraph up rows stay valid.
