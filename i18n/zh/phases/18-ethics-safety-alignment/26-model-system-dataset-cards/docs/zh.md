# 模型卡、系统卡与数据集卡

> 三种文档格式构成了 AI 透明度的框架。Model Cards(Mitchell 等,2019)——模型的"营养成分标签":训练数据、量化分解分析、伦理考量、注意事项;Hugging Face 上仅有 0.3% 的模型卡记录了伦理考量(Oreamuno 等,2023)。Datasheets for Datasets(Gebru 等,2018,CACM)——动机、构成、收集过程、标注、分发、维护;类比电子元器件数据手册。Data Cards(Pushkarna 等,Google,2022)——模块化的分层细节(远视、侧视、微观),作为面向不同读者的边界对象。2024–2025 年进展:通过 LLM 自动生成(CardGen,Liu 等,2024);HF 上模型卡的详细程度与最高 29% 的下载量增长相关(Liang 等,2024);可验证证明(Laminator,Duddu 等,2024);针对碳/水足迹的可持续性报告扩展(Jouneaux 等,2025 年 7 月);EU/ISO 监管卡片正在兴起。System Cards(Sidhpurwala 2024;Meta 系统级透明度工作;"Blueprints of Trust" arXiv:2509.20394)——覆盖安全能力、提示注入防护、数据外泄检测、与人类价值观对齐的端到端 AI 系统文档。

**Type:** Build
**Languages:** Python(标准库,模型卡 + 数据集卡 + 系统卡生成器)
**Prerequisites:** Phase 18 · 18(安全框架)、Phase 18 · 24(监管)
**Time:** ~60 分钟

## 学习目标

- 描述 Mitchell 等 2019 年的原始模型卡与 Gebru 等 2018 年的数据集卡。
- 描述 Data Cards 的远视/侧视/微观分层。
- 描述 System Cards 及其端到端覆盖范围。
- 陈述三项 2024–2025 年进展(自动生成、可验证证明、可持续性报告)。

## 问题所在

监管框架(第 24 课)和实验室安全政策(第 18 课)都要求文档。文档格式从模型专属(模型卡)演进到数据集专属(数据集卡),再到系统专属(系统卡)。每种格式针对不同的透明度范围。2024–2025 年的自动化与可验证证明工作解决了长期存在的采纳问题。

## 核心概念

### Model Cards(Mitchell 等,2019)

章节:
- 模型详情。
- 预期用途。
- 因素(评估中相关的人口或环境因素)。
- 指标。
- 评估数据。
- 训练数据。
- 量化分析(按因素分解)。
- 伦理考量。
- 注意事项与建议。

采纳问题:Oreamuno 等 2023 年对 Hugging Face 模型卡的审计发现,仅有 0.3% 记录了伦理考量。

### Datasheets for Datasets(Gebru 等,2018)

类比电子元器件数据手册。章节:
- 动机(为何创建该数据集)。
- 构成(包含什么内容)。
- 收集过程(如何组装而成)。
- 标注(如适用)。
- 用途(预期用途、禁止用途、风险)。
- 分发。
- 维护。

发表于 CACM 2021。数据集卡是上游文档;模型卡依赖于数据集卡的准确性。

### Data Cards(Pushkarna 等,Google,2022)

模块化的分层细节。三个缩放级别:
- **远视(Telescopic)。** 面向非专家的高层摘要。
- **侧视(Periscopic)。** 面向 ML 从业者的中层概览。
- **微观(Microscopic)。** 面向审计员的详细特征级文档。

边界对象框架:不同的读者从同一份文档中提取不同的信息。

### System Cards

范围:端到端 AI 系统,包括模型 + 安全栈 + 部署环境。典型章节包括:
- 安全能力。
- 提示注入防护。
- 数据外泄检测。
- 与既有人类价值观的对齐。
- 事件响应。

Sidhpurwala 2024 以及 Meta 的系统级透明度工作。"Blueprints of Trust"(arXiv:2509.20394)将 System Card 形式化为 Model Cards 在部署层的补充。

### 2024–2025 年进展

- **CardGen(Liu 等,2024)。** 通过 LLM 自动生成模型卡;报告称在标准化的 Mitchell 2019 字段上比许多人工撰写的卡片更具客观性。
- **下载相关性(Liang 等,2024)。** 详细的模型卡与 HF 上最高 29% 的更高下载率相关——采纳压力如今来自市场,而不仅仅是合规驱动。
- **Laminator(Duddu 等,2024)。** 通过硬件 TEE / 密码学签名实现可验证证明——使模型卡能够携带主张的证明,而不只是主张本身。
- **可持续性(Jouneaux 等,2025 年 7 月)。** 针对碳、水和计算能耗足迹的扩展;新兴 ISO 标准。
- **监管卡片。** EU AI Act(第 24 课)GPAI 实践守则透明度章节要求将模型卡作为合规产物。

## 动手使用

`code/main.py` 为一个玩具部署生成最小化的模型卡、数据集卡和系统卡。每一份都遵循规范的章节结构。你可以检查格式并比较三种范围。

## 交付

本课产出 `outputs/skill-card-audit.md`。给定一份模型卡、数据集卡或系统卡,它会审计章节覆盖率、数值分解,以及是否存在可验证证明。

## 练习

1. 运行 `code/main.py`。检查生成的卡片。找出薄弱的章节(仅有占位符),并说明什么样的证据可以加强它们。

2. 扩展模型卡,增加跨两个人口群体的量化分解分析(第 20 课)。

3. 阅读关于 0.3% 采纳率的 Oreamuno 等 2023。提出一项针对模型卡规范的结构性修改,以提高伦理考量章节的采纳率。

4. Laminator(Duddu 等,2024)使用 TEE 实现可验证证明。设计一个模型卡字段,用于携带评估结果的密码学证明,并描述验证者的角色。

5. 为你过去的一个项目或一个假设部署编写一份 System Card(是 System Card,不是 Model Card)。指出对第三方审计员而言价值最高的章节。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------------|------------------------|
| Model Card | "Mitchell 卡" | Mitchell 等 2019 年的 ML 模型标准文档 |
| Datasheet | "Gebru 数据集卡" | Gebru 等 2018 年的数据集标准文档 |
| Data Card | "Pushkarna 卡" | Google 2022 年的模块化分层数据文档 |
| System Card | "部署卡" | 包括安全栈在内的端到端 AI 系统文档 |
| 边界对象 | "不同读者,同一文档" | Data Cards 框架:同一文档服务于不同受众 |
| 可验证证明 | "Laminator 证明" | 附加在文档主张上的密码学或 TEE 证明 |
| 可持续性字段 | "碳 / 水足迹" | 2025 年新兴的环境核算扩展 |
