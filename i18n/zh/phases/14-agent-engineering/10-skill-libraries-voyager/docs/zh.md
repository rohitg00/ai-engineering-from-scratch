# 技能库与终身学习(Voyager)

> Voyager(Wang 等,TMLR 2024)将可执行代码视为技能。技能可命名、可检索、可组合,并通过环境反馈进行改进。这是 Claude Agent SDK 技能、skillkit 以及 2026 年技能库模式的参考架构。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07(MemGPT)、Phase 14 · 08(Letta Blocks)
**Time:** ~75 分钟

## 学习目标

- 说出 Voyager 的三个组成部分——自动课程、技能库、迭代提示机制——以及各自的作用。
- 解释为什么 Voyager 将动作空间设为代码,而不是原始命令。
- 实现一个基于 stdlib 的技能库,包含注册、检索、组合和基于失败的改进。
- 将 Voyager 的模式映射到 2026 年的 Claude Agent SDK 技能和 skillkit 生态。

## 问题

在每个会话中都从零开始重建所有能力的智能体有三个问题:

1. **浪费 token。** 每个任务都重新引出相同的推理。
2. **丢失进度。** 会话 A 中学到的修正无法迁移到会话 B。
3. **无法完成长程组合。** 复杂任务需要能力层级;一次性提示无法表达它们。

Voyager 的答案是:将每个可复用的能力视为一段命名的代码,存储在库中,可按相似度检索,可与其他技能组合,并通过执行反馈改进。

## 概念

### 三个组成部分

Voyager(arXiv:2305.16291)围绕以下内容构建智能体:

1. **自动课程。** 一个好奇心驱动的提议器根据智能体当前的技能集和环境状态选择下一个任务。探索是自底向上的。
2. **技能库。** 每个技能都是可执行代码。任务成功时添加新技能。技能通过查询与描述之间的相似度检索。
3. **迭代提示机制。** 失败时,智能体接收执行错误、环境反馈和自我验证输出,然后改进该技能。

Minecraft 评估(Wang 等,2024):相比基线,独特物品多 3.3 倍,石制工具快 8.5 倍,铁制工具快 6.4 倍,地图探索距离长 2.3 倍。这些数字是 Minecraft 特定的,但模式可迁移。

### 动作空间 = 代码

大多数智能体输出原始命令。Voyager 输出 JavaScript 函数。一个技能是:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。以描述和嵌入为键存储。作为程序而非提示检索。

这就是 2026 年的 Claude Agent SDK 技能:一段命名的、可检索的代码,加上智能体按需加载的指令。

### 技能检索

新任务"制作钻石镐"。智能体:

1. 嵌入任务描述。
2. 查询技能库中相似度最高的 top-k 技能。
3. 检索出 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等。
4. 用检索到的原语 + 新逻辑组合出新技能。

这就是 MCP 资源(Phase 13)和 Agent SDK 技能实现的模式:在知识/代码表面上进行检索,范围限定于当前任务。

### 迭代改进

Voyager 的反馈循环:

1. 智能体编写一个技能。
2. 技能针对环境运行。
3. 返回三种信号之一:`success`、`error`(带堆栈跟踪)、`self-verification failure`。
4. 智能体将该信号作为上下文重写技能。
5. 循环直至成功或达到最大轮数。

这就是 Self-Refine(Lesson 05)应用于带环境接地验证的代码生成。CRITIC(Lesson 05)是同一模式,只是用外部工具作为验证器。

### 课程与探索

Voyager 的课程模块根据智能体已有什么和还没做什么来提议任务,比如"在湖边建一个庇护所"。提议器使用环境状态 + 技能清单来选择略高于当前能力的任务——探索的最佳点。

对生产智能体而言,这转化为一个"缺什么"算子:给定当前技能库和某个领域,我们还没有覆盖哪些技能?团队通常以课程评审的形式手动实现这一点。

### 该模式失效之处

- **技能库腐化。** 同一技能以略有不同的描述被添加 10 次。在写入时添加去重;检索只返回一个。
- **组合技能漂移。** 父技能依赖的子技能被改进了。为技能做版本管理;固定在 v1 的父技能不会自动升级到 v3。
- **检索质量。** 基于技能描述的向量检索在库超过几百个技能后性能下降。用标签过滤和硬约束来补充("仅限带有 `category=tooling` 的技能")。

## 动手构建

`code/main.py` 实现了一个基于 stdlib 的技能库:

- `Skill` — 名称、描述、代码(字符串形式)、版本、标签、依赖。
- `SkillLibrary` — 注册、搜索(token 重叠)、组合(依赖的拓扑排序)和改进(更新时版本号递增)。
- 一个脚本化智能体,注册三个原语技能,组合出第四个,遇到一次失败,然后改进。

运行它:

```
python3 code/main.py
```

追踪输出显示了库写入、检索、组合、一次失败的执行,以及 v2 改进——完整呈现 Voyager 的循环。

## 实际应用

- **Claude Agent SDK 技能**(Anthropic)——2026 年的参考实现:每个技能包含描述、代码和指令;在智能体会话期间按需加载。
- **skillkit**(npm: skillkit)——面向 32+ 个 AI 编码智能体的跨智能体技能管理。
- **自定义技能库**——领域特定(面向数据智能体的 SQL 技能、面向基础设施智能体的 Terraform 技能)。Voyager 模式可按比例缩小。
- **OpenAI Agents SDK `tools`**——低端场景;每个工具就是一个轻量级技能。

## 上线部署

`outputs/skill-skill-library.md` 可为任意目标运行时生成一个 Voyager 形态的技能库,内置注册、检索、版本管理和改进。

## 练习

1. 在 `compose()` 中添加一个依赖环检测器。当技能 A 依赖 B,而 B 又依赖 A 时会发生什么?报错还是警告?
2. 实现按技能的版本锁定。当父技能组合子技能 `crafting@1` 时,对 `crafting@2` 的改进不得静默升级父技能。
3. 将 token 重叠检索替换为 sentence-transformers 嵌入(或 BM25 的 stdlib 实现)。在一个包含 50 个技能的玩具库上测量 retrieval@5。
4. 添加一个"课程"智能体:给定当前技能库和领域描述,提议 5 个缺失的技能。每周调用一次。
5. 阅读 Anthropic 的 Claude Agent SDK 技能文档。将该玩具库移植到 SDK 的技能 schema。可发现性方面有什么变化?

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|------------------------|------------------------|
| 技能 | "可复用的能力" | 一段命名的代码 + 描述,可按相似度检索 |
| 技能库 | "智能体的操作记忆" | 技能的持久化存储,可搜索、可组合 |
| 课程 | "任务提议器" | 由当前能力差距驱动的自底向上目标生成器 |
| 组合 | "技能 DAG" | 技能调用技能;执行时拓扑排序 |
| 迭代改进 | "自我修正循环" | 环境反馈 + 错误 + 自我验证回灌到下一版本 |
| 动作空间即代码 | "程序化动作" | 对时间上扩展的行为输出函数,而非原始命令 |
| 写入时去重 | "技能坍缩" | 近似重复的描述坍缩为一个规范技能 |
