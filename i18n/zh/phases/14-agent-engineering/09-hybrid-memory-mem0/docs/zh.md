# 混合记忆:向量 + 图 + KV

> 混合记忆并行运行三个存储——向量用于语义相似度,KV 用于快速事实查找,图用于实体关系推理——并配有一个评分层,在检索时融合三者的结果。这是外部记忆中广泛使用的生产模式;Mem0(Chhikara et al., 2025)是其中一个参考实现。

**Type:** Build
**Languages:** Python(标准库)
**Prerequisites:** Phase 14 · 07(MemGPT)、Phase 14 · 08(Letta Blocks)
**Time:** 约 75 分钟

## 学习目标

- 解释为什么单一存储(仅向量、仅图、仅 KV)不足以支撑智能体记忆。
- 说出 Mem0 的三个并行存储以及各自优化的方向。
- 描述 Mem0 的融合评分——相关性、重要性、时近性——以及为什么它是加权和而非层级结构。
- 在标准库中实现一个玩具级的三存储记忆系统,包含一个写入所有三个存储的 `add()`,以及一个融合结果的 `search()`。

## 问题所在

单一存储在三类查询中总有一类会出错:

- **语义相似度** —— "我们上周讨论过智能体漂移的哪些内容?"向量占优;KV 和图都查不到。
- **事实查找** —— "用户的电话号码是什么?"KV 占优;向量浪费资源,图则大材小用。
- **关系推理** —— "哪些客户共用同一个计费实体?"图占优;向量和 KV 都无法回答。

生产环境的智能体在一次会话中会同时发出这三类查询。单一存储的记忆对其中两类永远是错的。Mem0 的贡献在于把三者接入统一的 `add`/`search` 接口,并配有一个融合三者的评分函数。

## 核心概念

### 三个存储并行

Mem0(arXiv:2504.19413,2025 年 4 月)在 `add(text, user_id, metadata)` 时:

1. 从文本中提取候选事实(LLM 驱动的步骤)。
2. 将每条事实写入向量存储(嵌入),用于语义搜索。
3. 将每条事实以 (user_id, fact_type, entity) 为键写入 KV 存储,实现 O(1) 查找。
4. 将每条事实作为带类型的边写入图存储(Mem0g),用于关系查询。

在 `search(query, user_id)` 时:

1. 向量存储按嵌入余弦相似度返回 top-k。
2. KV 存储按查询导出的 (user_id, type, entity) 键返回直接命中。
3. 图存储返回从查询实体可达的子图。
4. 评分层融合三者的结果。

### 融合评分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性** —— 向量余弦、KV 精确匹配、图路径权重。
- **重要性** —— 写入时打标或通过学习获得(某些事实更重要:姓名、ID、政策)。
- **时近性** —— 距上次写入或读取的时间按指数衰减。

权重按产品调优。聊天智能体调高 `w_recency`;合规智能体调高 `w_importance`;检索智能体调高 `w_relevance`。

### Mem0g 与时序推理

Mem0g 增加了一个冲突检测器。当一条新事实与已有边矛盾时,已有边被标记为无效但不删除。时序查询("用户三月份所在的城市是哪里?")在按时间有效的子图上遍历。

这正是 Letta 的失效模式所推广的合规级行为。

### 基准数字

Mem0 论文报告的数据(2025 年):

- **LoCoMo**(长对话记忆):91.6
- **LongMemEval**(长程情景记忆):93.4
- **BEAM 1M**(1M token 记忆基准):64.1

对比基线(全上下文 128k LLM、平面向量存储、平面 KV)都落后 10 分以上。基准数字本身不足以证明选择的合理性——运行形态才是关键——但这些数字表明融合设计并非可有可无的细节。

### 作用域分类

Mem0 按作用域划分记忆:

- **用户记忆** —— 跨会话持久化,以 `user_id` 为键。
- **会话记忆** —— 在单个线程内持久化。
- **智能体记忆** —— 每个智能体实例的状态。

每次写入都会选定一个作用域。检索可以跨作用域查询,并对每个作用域使用各自的权重。不加思考地混用作用域,就会出现"助手把 Bob 的项目告诉了 Alice"这类事故。

### 这种模式在哪里会出问题

- **嵌入漂移。** 在最初一百次查询中看起来正常的向量结果,会随着语料增长而退化。定期对使用最多的前 N 条记录重新嵌入。
- **KV 模式蔓延。** `(user_id, type, entity)` 起初很简单,直到每个团队都加上自己的 `type`。每季度审计一次类型集合。
- **图爆炸。** 一个嘈杂的提取器每条消息添加 50 条边。限制每次 `add` 调用的图写入数量;丢弃低置信度的边。

## 动手构建

`code/main.py` 在标准库中实现了三存储模式:

- `VectorStore` —— 用朴素的词元重叠相似度作为嵌入的替身。
- `KVStore` —— 以 `(user_id, fact_type, entity)` 为键的字典。
- `GraphStore` —— 带类型的边(subject, relation, object, valid)。
- `Mem0` —— 顶层门面,包含 `add()`、`search()`、融合评分和作用域感知检索。
- 一个多用户、多会话对话的完整执行追踪。

运行:

```
python3 code/main.py
```

输出展示了三条独立的召回路径以及融合后的 top-k。调整 `main()` 顶部的评分权重,观察排名的变化。

## 使用它

- **Mem0(Apache 2.0)** —— 生产可用。用 Postgres + Qdrant + Neo4j 自托管,或使用托管云服务。
- **Letta** —— 三层 core/recall/archival;自带向量与图后端。
- **Zep** —— 商业替代方案,带时序知识图谱和事实提取。
- **自建** —— 当你需要对提取器(合规)或融合权重(时近性主导的语音智能体)进行精确控制时。

## 练习

1. 用真正的嵌入模型(sentence-transformers、Ollama、OpenAI embeddings)替换玩具级向量相似度。在一段合成的长对话上测量 recall@10。排名在 1000 次写入后是否会漂移?
2. 添加一个时序查询:`search(query, as_of=timestamp)`。只返回在该时间点或之前有效的记录。哪个存储需要最多的改动?
3. 实现一个冲突检测器:如果新事实与图中的边矛盾,使旧边失效并记录两者。在"用户住在柏林" -> "用户住在里斯本"上测试。
4. 为融合评分器添加一个 `user_feedback` 维度(对检索到的记录点赞)。你如何防止被钻空子(智能体只返回它已经喜欢的记录)?
5. 阅读 Mem0 文档(`docs.mem0.ai`)。将玩具实现移植为 `mem0` 客户端调用。在同样的 20 条测试查询上比较检索质量。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------------------|------------------------|
| 混合记忆 | "向量加图加 KV" | 三个存储并行写入,检索时融合 |
| 事实提取 | "记忆摄取" | 将文本拆分为(实体、关系、事实)元组的 LLM 步骤 |
| 融合评分 | "相关性排序" | 相关性、重要性、时近性的加权和 |
| 作用域 | "记忆命名空间" | user / session / agent —— 决定谁能看到什么 |
| Mem0g | "记忆图" | 带时序有效性的类型化边,用于关系查询 |
| 时序失效 | "软删除" | 将矛盾的边标记为无效;从不删除 |
| 嵌入漂移 | "检索腐烂" | 向量质量随语料增长而退化;需定期重新嵌入 |
