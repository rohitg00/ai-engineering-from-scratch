# 分块策略对比

> 分块决定了检索器最多能召回什么。边界切错,任何嵌入模型、重排序器或 LLM 都无法在下游修复损失。

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 11 课程 04(嵌入)、06(RAG)、07(进阶 RAG);Phase 19 Track B 基础(课程 20-29)
**Time:** 约 90 分钟

## 学习目标
- 从零实现五种分块策略:固定窗口、句子、递归切分、语义聚类和基于 markdown 标题的结构切分。
- 在一个带金标答案区间的固定语料库上测量 recall@k,并解释为什么某种策略在散文类文本上胜出,而另一种策略在技术文档上胜出。
- 学会读取块长分布,并识别每种策略引入的失败模式:孤立句子、符号中间截断、仅含标题的块、语义漂移。
- 不运行基准测试,仅通过检查三个属性(文档类型、平均段落长度、格式是否带有显式结构)来为新语料库选择默认策略。

## 问题所在

每个 RAG 流水线的起点都是把源文档切成足够小(让嵌入模型能处理)、又足够大(让每个片段承载一个自洽的完整概念)的片段。在哪里切分不是超参数,它是检索器能返回内容的上限。

一个询问"预算中止阈值是什么样的"的查询,只有当承载中止阈值的块可达时才能成功。如果固定窗口切分器把阈值数值从上下文中切走了,嵌入就会落入另一个聚类,BM25 得分下降,重排序器看到的是噪声,LLM 生成的答案就是错的。2024 年的论文 "LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs" 测量到,仅分块选择这一项就能带来 35% 的检索召回绝对波动。2025 年关于上下文块标题的后续工作缩小了差距,但没有完全消除。

本课将五种策略并列构建,在一个带金标答案区间的固定语料库上运行,并让你亲自读取召回数据。

### 固定窗口

暴力基线。每 N 个字符切一刀。可选地设置重叠,使得在位置 N 被切断的句子能在起点为 N - overlap 的块中完整出现。快速、确定性强,但对边界处理很糟糕。把它作为对照组,而不是默认选择。

### 句子

用正则表达式或简单状态机按句子边界切分,将一个或多个句子打包进块,直到达到目标字符预算。不会在单词中间切断,但仍会在段落和章节中间切断。这是许多早期 RAG 流水线的默认选择,对没有其他结构的散文文本也是合理选择。

### 递归切分

由 2023 年前后的各类库推广的层级策略。先尝试用最强的分隔符切分(双换行、段落),失败则退到下一级(单换行),再退到句子,最后到字符。当块满足预算时递归终止。对于结构不一致的文档表现出色,因为它能按区域自适应。

### 语义聚类

对每个句子做嵌入。把共享同一主题质心的连续句子聚成簇。当与质心的滚动相似度降到阈值以下时切分。边界反映的是语义,而不是字符。构建更慢且依赖嵌入模型,但对段内切换话题的文档更具韧性。

### 结构化 markdown 标题

对于携带显式结构的文档(markdown、reStructuredText、RFC 风格的编号章节),在标题边界切分。每个块包含该标题及其下方直到同级或更高级别的下一个标题之前的所有内容。每主题的块最小,但只在语料库格式良好时可用。

### recall@k 如何衡量边界选择

金标查询携带答案区间在源文档中的确切字符偏移量。分块之后你要问:检索器返回的 top-k 个块中,是否有任何一个与金标区间重叠?如果有,该查询的 recall@k 为 1;如果没有,则为 0。对查询集取平均。对每种策略运行同样的评估,结果的差异会告诉你哪种边界策略能在你的语料库上胜出。

## 动手实现

`code/main.py` 实现了:

- `fixed_window(text, size, overlap)` - 基线。
- `sentence_chunks(text, target)` - 简单的句子打包器。
- `recursive_split(text, separators, target)` - 层级递归。
- `semantic_chunks(text, similarity_threshold)` - 基于质心的聚类,构建在确定性的 mock 嵌入之上。
- `structural_markdown(text)` - 感知标题的切分器。
- `mock_embed(text, dim)` - 基于哈希的嵌入,使循环可离线运行。
- `DenseIndex` - 与 Phase 19 Track B 混合检索课中使用的形状相同。
- `eval_recall(strategy, corpus, queries, k)` - 对比循环。
- 一个 `main()`,在固定语料库上运行每种策略并打印 recall@k 表格。

运行它:

```bash
python3 code/main.py
```

输出是一张小表格,每种策略一行,每个 k 一列。句子策略在结构化 fixture 上落败。结构化 markdown 在 markdown fixture 上获胜。递归切分在混合 fixture 上保持竞争力,因为递归会自适应。语义聚类在没有可用结构线索的散文 fixture 上获胜。

## 表格掩盖不了的失败模式

**孤立句子。** 句子打包可能产生缺失主题句的块,嵌入因此指向错误的聚类。

**符号中间截断。** 固定窗口在代码或 YAML 内部会把标识符切成两半,两半都嵌入为噪声。

**仅含标题的块。** 结构化 markdown 会产生只包含 `## Title` 的块。过滤掉它们,或者将下一个块的第一个段落附加进去。

**语义漂移。** 当语料库主题高度一致时,语义聚类会切分过少。一个 5000 字符的块把许多具体答案塞进一个弥散的嵌入里。将语义切分与硬性字符上限结合使用。

**过期嵌入。** 语义聚类依赖嵌入模型。更换模型即意味着更换分块。将分块模型与检索模型分开固定版本,或一并重建索引。

## 不跑基准也能选默认策略

三个属性决定新语料库的默认分块器。

| 属性 | 取值 | 默认策略 |
|----------|-------|---------|
| 文档类型 | 无结构的散文 | 递归切分,目标 800 |
| 文档类型 | Markdown / RFC / API 文档 | 结构化 markdown |
| 文档类型 | 代码 | AST 感知(超出本课范围;见 Phase 19 课程 02) |
| 段落长度 | 长、单一主题 | 句子,目标 500 |
| 段落长度 | 短、主题混杂 | 语义,阈值 0.6 |

拿不准时,选择递归切分。它是最强的单一策略基线。

## 使用

生产实践:

- 在发布新流水线之前运行评估;不要信任你的库的默认策略。
- 每次更换嵌入模型或语料库构成时重新运行评估;胜出策略依赖于语料库。
- 将策略名持久化到每个块的元数据中,以便日后归因性能回退。

## 练习

1. 增加第六种策略:使用 `tiktoken` 代替字符计数的 token 窗口。在同一 fixture 上与固定窗口对比。
2. 向散文 fixture 注入 30% 的代码块,重新运行表格。解释为什么除结构化 markdown 外所有策略的召回率都下降。
3. 把确定性嵌入替换为你项目真实供应商的嵌入。测量语义聚类的召回差异。报告策略之间的差距是扩大还是缩小。
4. 为每个块增加 `summary` 字段:一句话的质心描述。将摘要附加到块正文后重新运行评估,测量召回提升。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------------|------------------------|
| Recall@k | "我们找对块了吗?" | top-k 个块中有任一块与金标答案区间重叠的查询比例 |
| 块重叠 | "滑动窗口" | 把前一个块的最后 N 个字符重新包含进下一个块 |
| 结构切分器 | "感知标题的块" | 在 H1/H2/H3 边界切分;标题文本属于块的一部分 |
| 语义分块器 | "感知主题的块" | 嵌入句子,按质心相似度聚类,在漂移处切分 |
| 质心漂移 | "主题切换" | 滚动均值与下一句之间的余弦相似度跌破阈值 |
