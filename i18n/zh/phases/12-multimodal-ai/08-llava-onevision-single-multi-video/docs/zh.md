# LLaVA-OneVision：单图、多图、视频统一于一个模型

> 在 LLaVA-OneVision(Li 等，2024 年 8 月)之前，开源 VLM 世界存在多条独立的技术路线：LLaVA-1.5 面向单图，Mantis、VILA 等多图模型，以及 Video-LLaVA、Video-LLaMA 等视频模型。各自在自家基准上称雄，在其余场景上失败。LLaVA-OneVision 的论点是：单一课程即可训练出一个模型在全部三种场景上占据主导，且涌现的任务迁移效应(单图技能迁移到视频、多图推理迁移到单图)优于各专家模型之和。配方看似简单：一个在各场景间保持恒定的视觉 token 预算，加上一条从单图到 OneVision(多图)再到视频的显式课程。本课解读这个预算、这条课程，以及涌现行为。

**Type:** Build
**Languages:** Python(标准库，token 预算求解器 + 课程规划器)
**Prerequisites:** Phase 12 · 05(LLaVA),Phase 12 · 06(任意分辨率)
**Time:** ~180 分钟

## 学习目标

- 设计一个在单图、多图和视频输入间保持恒定的视觉 token 预算。
- 排列训练课程顺序，使技能从单图迁移到视频而不发生灾难性遗忘。
- 解释为什么在课程得当的情况下，同等参数量的单一模型能胜过专家模型。
- 说出 LLaVA-OneVision 报告的三项涌现能力：多相机推理、set-of-mark 提示、iPhone 截图智能体。

## 问题

图像、多图和视频对模型的压力各不相同。

单图需要高分辨率 token(AnyRes,约 2880 个视觉 token)以捕捉 OCR 和细粒度细节。每样本预算：一张图，2880 个 token。

多图需要若干中等分辨率的图像(每张约 576 个 token),使跨图推理能装进上下文。每样本预算：4-8 张图，每张 576,共 2300-4600 个 token。

视频需要大量低分辨率帧(池化后每帧约 196 个 token)以捕捉时序动态。每样本预算：8-32 帧，每帧 196,共 1600-6200 个 token。

如果训练分开的模型，你只能选一个预算。如果训练一个模型，你需要预算在各场景间合理缩放而不撑爆上下文。

在 OneVision 之前，默认答案是“训练一个场景，忽略其他场景”。Video-LLaVA 通过额外的训练阶段把视频改造成图像模型的扩展。LLaVA-NeXT 通过切片增加了多图支持。没有一个能干净地处理全部三种场景。

## 概念

### OneVision token 预算

LLaVA-OneVision 选择一个统一的视觉 token 预算，每样本约 3000-4000 个 token,按场景不同分配：

- 单图：AnyRes-9(3x3 切片 + 缩略图)，每片 384 分辨率、729 个 patch,激进的双线性池化 2x2 → 每片 182。总计：9 * 182 + 182 = 1820 个 token。或 AnyRes-4,每片 729 = 2916 + 729。
- 多图：每张图中等分辨率(384,不切片)，729 个 token,不池化。预算 6 张图 → 4374 个 token。
- 视频：32 帧，384 分辨率，激进的 3x3 双线性池化 → 每帧 81 个 token。总计：32 * 81 = 2592 个 token。

这种分配使总 token 数大致恒定。LLM 永远不会看到撑爆上下文的批次。编码器在各场景下产生不同的几何结构，但 LLM 消耗相同的预算。

### 三阶段课程

LLaVA-OneVision 分三个阶段训练：

1. 单图 SFT(阶段 SI)。全部数据为单图加文本。以高分辨率 AnyRes 输入训练。这教会感知、OCR 和细粒度理解。使用 LLaVA-NeXT 数据加上 OneVision 专属的单图数据。
2. OneVision SFT(阶段 OV)。混合单图 + 多图 + 视频(均匀采样帧)。在统一 token 预算下训练。这教会模型处理异构的批次形状。不重置权重——从阶段 SI 继续训练。
3. 任务迁移(阶段 TT)。继续以目标任务为主的混合数据，依据产品在多图或视频上加重。可选的部署前微调。

关键：课程顺序很重要。先视频或多图训练，即使数据相同，其图像性能也差于先单图训练。论文对此做了明确消融。

### 为什么课程有效

单图训练构建感知基座。patch token 携带细粒度视觉特征；LLM 学会将它们与文本整合。多图和视频引入结构性挑战(哪张图是哪张、什么先发生)，没有强感知基座很难学习。

如果从零开始同时训练所有场景，模型会欠拟合感知(每批次单图数据有限)并过拟合结构(大量多图 / 视频数据)。结果：一个遵循跨图推理模式但视觉上浅薄的模型。

课程排序让你从阶段 SI 获得感知能力，再从阶段 OV 获得组合 / 时序推理，且两者都不丢失。

### 涌现的跨场景技能

LLaVA-OneVision 论文报告了三项涌现能力：

1. 多相机推理。分别用多图 + 视频训练；推理时要求对多相机驾驶场景进行推理。尽管训练中从未见过这种确切格式，模型正确地整合了各视角。
2. Set-of-mark 提示。用户在图像中用编号标记标注物体；模型推理“标记 3 相对标记 7 在做什么”。既未在标记上训练，也未在标注上训练；从空间定位 + 多图参照的组合中学到。
3. iPhone 截图智能体。用户提供 iPhone 屏幕截图并要求规划下一步点击。在 UI 截图、用户操作流程视频以及多图前后对上训练。泛化到智能体用例。

这些不是被训练的任务；它们从课程的组合结构中涌现。

### 视觉 token 池化

token 预算需要池化。OneVision 在 2D patch 网格上使用双线性插值：24x24 = 576 个 patch 变为 12x12 = 144(2 倍因子)或 8x8 = 64(3 倍因子)。池化在 patch 网格空间而非 token 空间进行，以保持局部性。

每个场景的池化因子选择本身就是一个超参数。池化越少 = token 越多 = 表征越丰富。池化越多 = token 越少 = 能容纳更多帧 / 图像。

### LLaVA-OneVision-1.5

2025 年的后续工作(LLaVA-OneVision-1.5,arXiv 2509.23661)在训练数据、模型权重和代码上“完全开放”。在部分基准上追平了专有模型的差距，并普及了这一配方。相同的课程，更多的数据，更好的基础 LLM。无架构改动。

### 与 Qwen2.5-VL 对比

Qwen2.5-VL(第 12.09 课)做了不同的选择。它使用 M-RoPE 和动态 FPS 而非固定池化。其预算随输入缩放——1 分钟视频比 5 秒视频使用更多 token。LLaVA-OneVision 固定预算并缩放池化。两者都可行；它们以可配置性换取可预测性。

## 使用它

`code/main.py` 是一个面向 OneVision 风格 VLM 的课程与预算规划器。给定每样本 token 预算和目标场景配比(比如 40% 单图、30% 多图、30% 视频)，它会：

- 为每个场景分配分辨率、池化因子和帧数。
- 检查每个场景是否都 fits 在共享预算内。
- 报告预期 token 数、LLM FLOPs,以及哪些场景 token 不足。
- 打印逐阶段训练日程。

用它来规划 OneVision 微调，或对 VLM 部署的每请求成本做健全性检查。

## 交付

本课产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每样本预算，它输出 AnyRes 因子、每帧池化、视频帧数以及课程阶段权重。无论何时训练或微调统一场景 VLM,都使用它。

## 练习

1. 你的产品支持 80% 单图、10% 多图(2-4 张)、10% 视频(8-16 帧)。设计 token 预算。你会把省下的(因不做重多图而节省的)预算用在哪里？

2. 阅读 LLaVA-OneVision 第 4.3 节(涌现能力)。提出课程很可能解锁但论文未报告的第四项涌现技能。

3. 交换课程顺序——先多图，再单图，后视频。预测哪些基准会退化并解释原因。

4. 论文报告视频基准仅用每样本 8 帧训练。这能否泛化到推理时的 30 秒视频？最先崩坏的是什么——token 预算还是时序推理？

5. 24x24 patch 到 12x12 的双线性池化是每维 4 倍缩减。用标准库 Python 实现该池化，并验证每个 2x2 块的均值与双线性输出一致。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------------|------------------------|
| OneVision 场景 | “单图、多图或视频” | 统一 VLM 处理的三种输入形状之一；预算在各场景间保持恒定 |
| Token 预算 | “每样本多少 token” | LLM 在每个训练 / 推理样本看到的视觉 token 总数，通常 3000-4000 |
| 课程 | “训练顺序” | 为涌现迁移选择的阶段排序(单图 → 多图 → 视频) |
| 双线性池化 | “token 缩减” | 对 patch 网格(2D)应用双线性插值以减少 token 数并保持局部性 |
| 涌现技能 | “没训练过，却能用” | 推理时出现且无对应训练数据的能力，源于课程的组合性 |
| AnyRes-k | “k 切片设置” | k 个固定分辨率的子切片加一个缩略图，典型 k ∈ {4, 9} |
| 任务迁移 | “跨场景泛化” | 在单图上学到、通过共享骨干应用于视频(反之亦然)的技能 |
