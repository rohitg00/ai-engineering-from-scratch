# MIO 与任意到任意流式多模态模型

> GPT-4o 带来了一款大多数开源模型难以复刻的产品：一个能听语音、看视频并实时回应的智能体。截至 2024 年底，开放生态的回答是 MIO（Wang et al.，2024 年 9 月）。MIO 对文本、图像、语音和音乐进行分词，在交错的序列上训练一个因果 Transformer，并实现任意模态到任意模态的生成。AnyGPT（Zhan et al.，2024 年 2 月）是概念验证；MIO 是规模放大；Unified-IO 2（Allen AI，2023 年 12 月）是带视觉 + 动作接地能力的近亲。本课解读任意到任意模式——四个分词器、一个 Transformer、流式友好的解码。

**Type:** Learn
**Languages:** Python（标准库，四模态分词分配器 + 流式解码循环）
**Prerequisites:** 阶段 12 · 11（Chameleon），阶段 6（语音与音频）
**Time:** 约 120 分钟

## 学习目标

- 设计一个共享词表，在不冲突的前提下容纳文本、图像、语音和音乐 token。
- 在压缩与重建的权衡上，比较 SEED-Tokenizer（图像）与 SpeechTokenizer 残差 VQ（语音）。
- 解释构建任意到任意生成能力的四阶段课程训练。
- 说出三种开放的任意到任意方案及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题所在

统一多模态模型说起来容易，规模化构建却很难。2024 年之前的大多数“任意到任意”系统都是流水线式的：视觉模型 → 文本表示 → 语音模型 → 音频。每一跳都会损失信息、增加延迟，并使训练复杂化。GPT-4o 的演示视频展示了亚秒级响应的单模型替代方案；开放系统落后了数月。

工程挑战：

- 每种模态都必须有分词器，压缩程度需足以重建，且产出 token 的速率要能被 Transformer 消费。
- 单一词表必须为文本（32k+）、图像（16k+）、语音（4k+）、音乐（8k+）分配空间。至少需要四万多个条目。
- 训练数据必须覆盖每一种输入-输出对（文本→图像、图像→语音、语音→图像等），否则模型必须具备组合能力。
- 推理必须足够快地流式输出 token，以满足对话延迟（首个音频字节时间 <500ms）。

## 概念

### 四种模态，四个分词器

MIO 的分词器栈：

- 文本：标准 BPE，词表约 32000。
- 图像：SEED-Tokenizer（2023）——带离散码本的量化 VAE，4096 个条目，每张图像 32x32 个 token。
- 语音：SpeechTokenizer 残差 VQ（2023）——将 16kHz 波形编码为 8 个层级码本；第一层是粗粒度内容，后续层补充韵律和说话人身份。
- 音乐：类似的残差 VQ（Meta 的 MusicGen / Encodec 系列），4-8 个码本。

每种模态产生整数 token。这些 token 在共享词表中拥有互不重叠的 ID 区间：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

总计：约 48k 词表。输入嵌入和输出投影覆盖全部区间。

### 流式解码

语音生成使用残差 VQ。Transformer 预测基础（第 0 层）语音 token；并行解码的残差量化器预测后续各层。每个第 0 层 token 在 16kHz 下大约对应 50ms 的音频。

流式模式：

1. 用户对着麦克风说话；实时音频分词器每 50ms 输出语音 token。
2. MIO 在 token 到达时进行消费（提示词预填充 + 增量前向）。
3. 输出 token 在生成时流式输出；并行语音解码器以约 50-150ms 的延迟将它们转换为音频采样。
4. 首个音频字节时间：MIO 论文中约 300-500ms，接近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互补的流式语音 LLM 设计。其中 Moshi 在单块 GPU 上实现了 160ms 的往返延迟。

### 四阶段课程

MIO 的训练课程：

1. 阶段 1 —— 对齐。大规模模态对语料：文本-图像、文本-语音、文本-音乐。每一对使用其各自的词表片段。训练共享词表。
2. 阶段 2 —— 交错。多模态交错文档（带图片 + 视频的博客、带转录的播客等）。训练跨模态上下文。
3. 阶段 3 —— 语音增强。额外音频数据，在不损失文本能力的前提下提升语音质量。
4. 阶段 4 —— SFT。跨模态指令微调：VQA、图像描述、旁白、语音到语音对话。

缺少任一阶段都会使特定能力退化：跳过阶段 2，模型会丢失跨模态上下文；跳过阶段 3，语音质量会很差。

### 视觉思维链

MIO 引入了视觉思维链：模型将中间图像 token 作为推理步骤输出。对于“猫在爬树吗？”这个问题，模型：

1. 输出 `<image>` token 来渲染场景（来自输入图像或草图）。
2. 输出分析该草图的文本。
3. 输出最终答案。

渲染出的中间图像充当草稿板。空间推理任务的基准成绩有所提升。这一思想类似于文本推理中的思维链。

### 任意到任意领域的竞争者

- AnyGPT（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），设计类似。
- Unified-IO 2（arXiv:2312.17172）：增加视觉动作输出、深度、法线。任务多样性更高，规模更小。
- NExT-GPT（arXiv:2309.05519）：LLM + 模态专属扩散解码器。并非单模型方案。
- CoDi（arXiv:2305.11846）：可组合扩散；通过共享潜空间实现任意到任意。

MIO 是最接近纯 token 任意到任意的方案。AnyGPT 是其概念上的前身。

### 延迟预算

对于对话式产品，每个组件的延迟都很重要：

- 麦克风到音频 token：约 50ms。
- 预填充（音频 token + 历史）：8B 模型上约 100ms。
- 首个输出 token：约 50ms。
- 并行残差 VQ + 语音解码器：约 100-150ms。

首个音频字节总时间：最低约 300ms。GPT-4o 声称约 250ms。Moshi 声称 160ms。根据公开基准，MIO/AnyGPT 处于 400-600ms 区间。

### 为什么任意到任意依然困难

即使在 2026 年，开放任意到任意模型在两个方面仍落后于闭源模型：

- 语音质量。残差 VQ 分词器是有损的；与 ElevenLabs 级别的语音相比，对话式语音听起来像机器人。
- 跨模态推理。让模型“唱出你所看到的内容”的失败率仍然高于纯视觉任务。

这些是开放的研究问题。Qwen3-Omni（第 12.20 课）是 2025 年最先进的开放尝试。

## 使用它

`code/main.py`：

- 定义四模态词表分配并将其打印出来。
- 通过分词器路由器路由一组多模态输入（文本、图像、音频片段、音乐）。
- 模拟文本到语音响应的流式解码并进行延迟计数。
- 在给定编码器、预填充和解码器延迟的情况下，计算预期的首个音频字节时间。

## 练习

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标应该是多少？列出消耗时间的各个组件。

2. SpeechTokenizer 残差 VQ 使用 8 个码本。提出为什么必须并行解码残差各层（相对于顺序解码），以及它带来多少延迟节省。

3. 你的词表有 32k 文本 + 4k 图像 + 4k 语音。再加上 8k 音乐和约 10 个分隔符。在隐藏维度为 4096 时，嵌入矩阵的参数成本是多少？

4. 视觉思维链会输出一张中间图像。哪类问题会因此受益？哪类问题会被额外的 token 损害？

5. 阅读 Moshi（arXiv:2410.00037）。描述其“内心独白”技术，并与 MIO 的视觉思维链进行比较。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------------|------------------------|
| Any-to-any | “多模态输入/输出” | 一个以任意方向接受和输出文本、图像、语音和音乐的单一模型 |
| Residual-VQ | “语音分词器栈” | 多码本分词，每层补充信息；基础层是内容，后续层是韵律 |
| SEED-Tokenizer | “图像编码” | MIO 使用的带 4096 条目码本的离散图像分词器 |
| Chain-of-visual-thought | “视觉草稿板” | 模型在给出最终答案之前生成一张中间图像作为推理步骤 |
| Time-to-first-audio-byte | “TTFAB” | 从用户语音到首个音频输出的延迟；对话体验需 <500ms |
| Four-stage curriculum | “训练配方” | 对齐 -> 交错 -> 语音增强 -> SFT，按此顺序 |
