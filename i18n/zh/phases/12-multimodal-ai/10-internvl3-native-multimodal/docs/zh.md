# InternVL3：原生多模态预训练

> InternVL3 之前的每个开源 VLM 都遵循同一个三步配方：拿一个在数万亿文本 token 上训练过的文本 LLM，装上一个视觉编码器，然后再微调接缝。这行得通，但会积累对齐债——文本 LLM 把全部预训练预算都花在了纯文本上，并不能原生理解视觉 token。当你事后加入视觉时，LLM 必须重新学习如何将视觉输入与它的文本推理联系起来，同时又不遗忘文本。InternVL3（Zhu et al.，2025 年 4 月）拒绝了这种事后拼接的做法：一次预训练，从第一步开始就让文本与多模态交错进行。结果是：78B 参数的开源模型在 MMMU-Pro 上与 Gemini 2.5 Pro 相当。本课解读原生预训练的理由，以及采用它之后会发生哪些变化。

**Type:** Learn
**Languages:** Python（标准库、训练语料混合器）
**Prerequisites:** Phase 12 · 05, Phase 12 · 07（配方）
**Time:** ~120 分钟

## 学习目标

- 解释为什么事后拼接的 VLM 训练会累积对齐债，并引用三个可测量的症状（灾难性遗忘、答案漂移、视觉-文本不一致）。
- 描述 InternVL3 的原生预训练语料配比，以及为什么 text : interleaved : caption 的比例很重要。
- 比较 V2PE（可变视觉位置编码）与 Qwen2-VL 的 M-RoPE。
- 说出视觉分辨率路由器（ViR）和解耦视觉-语言（DvD）部署优化。

## 问题

事后拼接的 VLM 训练是默认做法。LLaVA、BLIP-2、Qwen-VL、Idefics——全都是拿一个已经预训练好的 LLM（Llama、Vicuna、Qwen、Mistral）再加视觉。训练阶段通常是：

1. 冻结 LLM + 冻结视觉编码器 + 可训练的投影器，在图文对上训练以对齐嵌入。
2. 解冻 LLM，在指令数据（LLaVA-Instruct、ShareGPT4V）上训练。
3. 可选的任务特定微调。

由此出现三个对齐债的症状：

- 灾难性遗忘。事后拼接的 VLM 会遗忘纯文本技能。GSM8K 分数下降 5-10 分。Hellaswag 分数下降。纯文本 agent 出现退化。
- 答案漂移。同一个视觉问题的细微措辞变化会得到不同答案。视觉编码器与 LLM 之间的绑定弱于 LLM 自身 token 之间的绑定。
- 视觉-文本不一致。VLM 能正确描述一张图像，然后回答一个与自身描述相矛盾的问题。视觉 token 无法像文本那样参与 LLM 的内部一致性检查。

这些症状有充分的文档记录。MM1.5 第 4 节对它们进行了量化。LLaVA-OneVision 的消融实验暗示了它们的存在。原生预训练是解决方案。

## 概念

### 原生多模态预训练

InternVL3 在一个从第一步起就是原生多模态的语料库上从零训练。配比是：

- 40% 纯文本数据（FineWeb、Proof-Pile-2 等）
- 35% 图文交错数据（OBELICS、MMC4 风格）
- 20% 配对的图文描述数据
- 5% 视频文本数据

视觉 token、文本 token 和跨模态交互从第一个梯度步起就共同参与同一个损失。没有对齐预训练，没有投影器冻结阶段，没有需要恢复的灾难性遗忘。

基础模型的训练是单一阶段。之后是指令微调，但基础模型已经把视觉 token 当作一等公民来理解。

### V2PE（可变视觉位置编码）

Qwen2-VL 使用固定轴分配的 M-RoPE。InternVL3 引入了 V2PE：位置编码随模态类型（文本、图像、视频）变化，并带有可学习的缩放。实践中：

- 文本 token 使用 1D 位置（文本索引）。
- 图像 patch 使用 2D 位置（行、列）。
- 视频帧使用 3D 位置（时间、行、列）。

三者共享同一个 RoPE 频率基座，但每个频段的隐藏维分配是可学习的参数，而非固定切分。预训练期间可以自由权衡时间与空间的频率分辨率。

V2PE 的消融结论：在相同计算量下，视频基准上比 M-RoPE 高 1-2 分。算不上革命，但更干净。

### 视觉分辨率路由器（ViR）

部署优化。并非所有图像都需要全分辨率编码。一张只有单个低细节物体的照片以 1280px 原生分辨率编码会浪费 token。ViR 是一个小型分类器，在编码之前预测回答该问题所需的最低分辨率。

路由分三档：低分辨率（256 token）、中（576）、高（2048+）。在生产流量中，60% 的查询用低或中档就足够了。净效果：同等质量下吞吐量提升 2-3 倍。

### 解耦视觉-语言部署（DvD）

当你服务一个大型 VLM 时，视觉编码器对每张图像只运行一次，而 LLM 对每个输出 token 都要自回归运行。两个组件的瓶颈不同（视觉 = 卷积 + 注意力的 GPU 显存带宽；LLM = KV cache）。DvD 把它们拆分到不同的 GPU 上，中间用流式传输衔接。

对于一个 8B 模型 + 400M 编码器，DvD 相比共置部署大约使单节点吞吐量翻倍。

### 单阶段 vs 多阶段质量

InternVL3 的主要基准结论：在 78B 参数下，与 Gemini 2.5 Pro 的 MMMU-Pro 持平。在 38B 下，与 GPT-4o 持平。在 8B 下，领先开源 8B 排行榜。全部来自"单阶段预训练 + 指令微调"配方。

对齐债假设是可测量的：InternVL3-8B 每单位视觉基准增益损失的文本基准分数（MMLU、GSM8K）少于 Qwen2.5-VL-7B。这个模型更像一个通才，因为训练是一个整体，而不是两段。

### InternVL3.5 与 InternVL-U

InternVL3.5（2025 年 8 月）扩展了这个配方。同样的原生预训练方法，更多数据，更多参数。MMMU 的提升是渐进式的。

InternVL-U（2026 年）加入了统一生成——通过在同一骨干之上的 MMDiT 头输出图像。"U" 代表"理解 + 生成"，对标 Transfusion 风格的统一模型（第 12.13 课）。同一个原生预训练骨干同时支持理解头和生成头。

### 原生预训练的权衡

原生预训练不是免费的：

- 计算。从零训练一个新 VLM 的成本与训练文本 LLM 相同——数百万 GPU 小时。事后适配复用现有 LLM 权重，省下大部分成本。
- 数据。大规模的图文交错语料很稀少。OBELICS 有 1.41 亿文档；MMC4 有 5.71 亿。而纯文本动辄 15T token。多模态预训练数据稀缺是硬约束。
- 基础 LLM 复用。原生预训练放弃了日后更换新 LLM 的选项。事后拼接可以只重训适配器，就把 Llama-3.1 换成 Llama-4。

InternVL3 押注的是：对齐债的代价高于失去复用的代价。基准支持了这一主张。但其生产成本让未来的实验室无法低成本复制。事后拼接的 VLM 会继续存在，因为对大多数项目来说它们仍然更便宜。

## 使用它

`code/main.py` 是一个训练语料混合器和 ViR 路由模拟器。它可以：

- 接受目标语料配比（%text、%interleaved、%caption、%video），并计算每种模态的预期步数。
- 在一批查询上模拟 ViR 路由（分布：50% 低细节、30% 中等、20% 高细节），并报告平均 token 数。
- 在给定编码器与 LLM FLOPs 的情况下，报告 DvD 吞吐量估计。
- 并排打印事后拼接 vs 原生预训练在参数、计算、数据和预期对齐债症状方面的对比。

## 发布它

本课产出 `outputs/skill-native-vs-posthoc-auditor.md`。给定一个拟议的 VLM 训练计划，它会审计应该采用原生还是事后拼接，标记对齐债风险，并推荐语料配比。当你在评估一个新的开源 VLM 项目并需要选择训练策略时使用它。

## 练习

1. 估算 InternVL3-8B（原生预训练）与 LLaVA-OneVision-7B（事后拼接）之间的计算量差。GPU 小时之比大约是多少？是什么造成了这个差距？

2. InternVL3 报告的配比是 40% text / 35% interleaved / 20% caption / 5% video。如果你的目标任务是视频重负载的，请提出一个新的配比，并论证基础模型为什么仍然需要大量文本和图文描述数据。

3. 阅读 MM1.5 第 4 节关于遗忘的内容。指出事后拼接训练出现最大退化的确切基准。该退化的代价是多少？

4. ViR 将 60% 的流量路由到低分辨率编码。它会错误路由哪类查询（明明需要高分辨率却送到了低分辨率）？提出三种路由器失效模式。

5. DvD 将视觉和 LLM 拆分到不同 GPU。在什么样的流量模式下，DvD 会损害而非提升吞吐量？

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|-----------------|------------------------|
| 原生多模态预训练 | "从零一起训练" | 文本 + 图像 + 视频 token 从第 1 步起就参与损失，而不是事后拼接 |
| 对齐债 | "事后惩罚" | 把视觉拼接到冻结 LLM 上所带来的、可测量的文本技能退化和答案一致性下降 |
| V2PE | "可变视觉位置编码" | 按模态可学习的位置编码分配；InternVL3 对 M-RoPE 的继任方案 |
| ViR | "分辨率路由器" | 在编码前为每个查询选择所需最低分辨率的小型分类器，节省推理 token |
| DvD | "解耦部署" | 视觉编码器在一个 GPU，LLM 在另一个 GPU，流式衔接；使大型 VLM 吞吐量翻倍 |
| InternVL-U | "统一理解 + 生成" | 2026 年的后续版本，在原生预训练骨干上加入图像生成头 |
| 交错语料 | "OBELICS / MMC4" | 文本与图像按自然阅读顺序混合的文档；原生预训练的原材料 |
