# 失败模式 — MAST、群体思维、单一文化、级联错误

> 2026 年的参考分类法是 **MAST**(Cemri 等，NeurIPS 2025,arXiv:2503.13657),该分类法基于 7 个最先进开源 MAS 的 1642 条执行轨迹，显示出 **41–86.7% 的失败率**。三大根因类别：**规范问题**(41.77%)——角色模糊、任务定义不清；**协调失败**(36.94%)——通信中断、状态失同步；**验证缺口**(21.30%)——缺少校验、没有质量检查。**群体思维**(Groupthink)系列(arXiv:2508.05687)补充了：单一文化坍塌(相同基座模型 → 相关性错误)、从众偏差(智能体相互强化错误)、心智理论缺陷、混合动机动态、级联可靠性失败。级联示例：重试风暴，一次支付失败触发订单重试，订单重试又触发库存重试，最终压垮库存服务(数秒内 10 倍负载——需要熔断器)。记忆投毒：某个智能体的幻觉进入共享记忆，下游智能体将其当作事实；准确率逐渐衰减，使得根因诊断非常痛苦。**STRATUS**(NeurIPS 2025)报告通过专门的检测 / 诊断 / 验证智能体，缓解成功率提升了 1.5 倍。本课将失败模式视为一等工程目标。

## 问题

多智能体系统在真实任务上的失败率为 41–86.7%(Cemri 等 2025 在 7 个开源 MAS 上测得)。这不是“多加几个智能体”就能调试的。这些失败有结构性原因。MAST 分类法给出了类别划分。本课将每个类别映射到具体的检测、诊断和缓解模式，让这些数字不再显得随意。

2026 年的生产实践是将失败模式视为设计输入。只有当你能对每一个 MAST 类别指出所部署的缓解措施时，你的架构才算“足够好”。

## 概念

### MAST 类别

**规范问题(占失败的 41.77%)。** 智能体的任务定义不够严格。示例：

- 角色模糊：两个智能体都认为自己是审核者。
- 任务欠规范：用户想要特定角度，却只说“总结一下”。
- 成功标准隐式：智能体无法判断自己是否成功了。

缓解措施：
- 编写明确的角色契约。每个智能体的提示词说明它*做什么和不做什么*。
- 每个任务配套验收测试。在智能体开始之前，定义“完成即意味着 X”。
- 预检规范检查：在派发之前由另一个智能体审查任务定义。

**协调失败(36.94%)。** 通信或状态中断。

示例：
- 两个智能体在无同步的情况下更新共享状态。
- 消息在智能体之间丢失(队列故障、超时)。
- 状态漂移：智能体 A 认为任务已完成；智能体 B 仍在执行。

缓解措施：
- 带乐观并发控制的版本化共享状态。
- 关键消息要求显式确认(重试直至收到 ack)。
- 定期状态同步检查点；尽早发现漂移。

**验证缺口(21.30%)。** 输出没有独立检查。

示例：
- 一个智能体宣称成功；无人验证。
- 智能体链中每个都信任前一个的输出。
- 涌现的组合行为缺少测试覆盖。

缓解措施：
- 独立验证者智能体(第 13 课)。只读、访问独立数据源。
- 显式交接契约：“A 的输出必须先通过检查器 C,B 才能开始。”
- 结果日志记录，用于事后分析。

### 群体思维系列(arXiv:2508.05687)

当智能体趋同或相互模仿时，会出现五种相关失败：

**单一文化坍塌。** 相同基座模型或训练数据 → 相关性错误。三个智能体共享同一个 LLM 时，它们也共享它的幻觉。

**从众偏差。** 智能体向声音最大或最自信的同伴靠拢，即使对方是错的。

**心智理论缺陷(ToM)。** 智能体无法对彼此的信念建模；协调随之瓦解(第 18 课)。

**混合动机动态。** 激励部分一致的智能体漂向折中地带，却谁都不满意。

**级联可靠性失败。** 一个组件的错误模式触发依赖组件中的错误模式。

### 级联示例 — 重试风暴

2026 年典型的事故模式：

```
payment service fails 10% of requests
   ↓
order agent retries payment (exponential backoff but naive)
   ↓
each retry is a new order-inventory check
   ↓
inventory service sees 2x normal load
   ↓
inventory service starts timing out
   ↓
every order retries inventory check
   ↓
inventory service sees 10x normal load
   ↓
cluster goes down
```

修复方法是经典方案：**熔断器**。当下游错误率超过阈值时，短路并返回缓存或默认结果。再加上每个请求的重试预算上限。

熔断器是少数几个可以直接从分布式系统照搬、无需修改的多智能体失败缓解手段之一。

### 记忆投毒(回顾)

来自第 13 课：一个智能体的幻觉成为共享记忆中的事实；下游智能体基于被投毒的事实进行推理。用 MAST 术语来说，这是共享内存层的验证缺口。

准确率逐渐衰减是症状。你不会得到崩溃；你会得到难以根因定位的缓慢漂移。

缓解措施：仅追加日志、来源追溯、不可写入的验证者。已在第 13 课中覆盖。

### STRATUS — 用于失败检测的专用智能体

STRATUS(NeurIPS 2025)报告，当部署以下角色时，缓解成功率提升 1.5 倍：

- **检测智能体。** 监视症状模式(高分歧、重试激增、准确率漂移)。
- **诊断智能体。** 给定症状后，从 MAST 分类法推断可能的根因。
- **验证智能体。** 在应用缓解措施后，检查症状是否消除。

这是将 SRE 风格的事件响应应用于智能体系统。这三个角色都可以是带有专用提示词的 LLM 智能体。

### 失败模式审计

2026 年的一项最佳实践是每年(或每个主要版本发布时)进行失败模式审计：

1. **轨迹抽样。** 收集约 1000 条真实执行轨迹。
2. **归类。** 将每条轨迹的失败映射到 MAST + 群体思维类别。
3. **计算按类别的失败率。** 哪些类别在你的系统中占主导？
4. **对缓解措施排序。** 哪个修复能消除最多失败？
5. **挑选 2-3 项缓解措施。** 实施；下季度复审。

这种纪律比具体选择更重要。没有审计，失败会混入噪声，永远不会得到系统性解决。

### 系统静默失败时

最危险的失败类别是静默正确性失败。大声失败的系统(崩溃、异常、告警)可以被监控。产生看似合理但错误的输出的系统，无法通过异常日志检测。这就是为什么验证缺口尽管只占数量的 21.30%,却是单次失败代价最高的类别。

投入于：
- 抽样人工复核。
- 黄金数据集回归测试。
- 重要输出的跨智能体交叉检查。

### 失败与缓慢失败

有些失败是即时的；有些是缓慢的。即时失败(超时、模式不匹配、认证错误)检测成本低。缓慢失败(记忆投毒、单一文化漂移、角色模糊)检测和预防成本高。

2026 年的工程做法：为缓慢失败部署代理指标，以便在漂移变成可见错误之前捕捉到它。一致率、重试率、输出长度分布，以及相邻智能体版本之间的编辑距离，都是有用的代理指标。

## 上线

生产环境中的失败模式纪律：

- **每季度进行 MAST 审计。** 而非每年。随着系统增长，类别分布会变化。
- **处处使用熔断器。** 每次对依赖服务的出站调用。默认打开阈值为 5-10% 错误率。
- **黄金数据集。** 小而高质量、经人工审核。每周对其运行回归测试。
- **STRATUS 三件套。** 检测 + 诊断 + 验证智能体监控生产。先只上检测智能体；当症状噪声大时再加诊断。
- **失败预算。** 按类别为失败率设定明确的 SLO。超出预算触发停止发布的讨论。

## 练习

1. 运行 `code/main.py`。确认熔断器限制了重试风暴。改变失败阈值并观察其权衡。
2. 实现**缓慢失败代理指标**：3 个并行智能体间的一致率。当它急剧下降时，触发告警。通过逐渐关联智能体输出来模拟单一文化漂移。
3. 阅读 Cemri 等(arXiv:2503.13657)。选择他们 7 个 MAS 系统之一，映射其前 3 大失败类别。这与 MAST 的预测相比如何？
4. 阅读群体思维论文(arXiv:2508.05687)。判断五种模式中哪一种在生产中最难检测。提出一个代理指标。
5. 为你熟悉的一个具体多智能体系统设计 STRATUS 风格的检测-诊断-验证三件套。检测监视哪些症状？诊断推荐哪些缓解措施？验证如何确认其有效？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| MAST | “2026 年的分类法” | Cemri 2025;3 个根因类别 + 14 个失败子类型。 |
| 规范问题 | “角色模糊” | 任务或角色定义不足；智能体不知道该做什么。 |
| 协调失败 | “状态漂移” | 智能体之间通信或同步中断。 |
| 验证缺口 | “没人检查” | 输出未经独立验证即被接受。 |
| 群体思维系列 | “同质化失败” | 单一文化、从众、ToM 缺陷、混合动机、级联。 |
| 单一文化坍塌 | “相同模型，相同幻觉” | 共享基座模型或训练数据导致的相关性错误。 |
| 重试风暴 | “级联错误放大” | 一次失败触发重试，放大下游负载。 |

| STRATUS | “事件响应三件套” | 检测 + 诊断 + 验证智能体。缓解成功率提升 1.5 倍。 |
