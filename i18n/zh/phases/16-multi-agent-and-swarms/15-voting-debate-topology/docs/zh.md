# 投票、自洽性与辩论拓扑

> 最廉价的聚合方式:采样 N 个独立智能体,进行多数投票。Wang 等人 2022 年的自洽性(self-consistency)用一个模型采样 N 次实现了这一点。多智能体方法通过**异构**智能体对其加以扩展,以摆脱单一化(monoculture)——不同模型、不同提示词、不同温度、不同上下文。在多数投票之外,辩论拓扑也很重要:MultiAgentBench(arXiv:2503.01935, ACL 2025)评估了星型/链式/树形/图状协作结构,发现**图状拓扑最适合研究类任务**,但在约 4 个智能体以上会出现"协作税"。AgentVerse(ICLR 2024)记录了两种涌现模式——自愿行为和从众行为——而从众既是特性(达成共识)也是风险(群体思维,第 24 课)。本课将梳理拓扑空间,构建每种变体,并度量协作税。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 07(心智社会与辩论), Phase 16 · 14(共识与 BFT)
**Time:** ~75 分钟

## 问题

辩论可以提升准确率(Du 等人,arXiv:2305.14325),也可能使其下降。辩论是否有帮助取决于四个结构性选择:

1. 谁与谁通信(拓扑)。
2. 轮数是多少(Du 2023:轮数和智能体数量各自独立地产生影响)。
3. 智能体是否异构(不同的基础模型打破单一化)。
4. 是否存在对抗性声音(steel-manning 与 straw-manning 之别)。

那些把"跑 5 个智能体再投票"硬套到任务上的团队,往往比单个智能体表现更差。这些失败并非随机,而是随拓扑和异构性而变化。本课就是那张拓扑地图。

## 概念

### 自洽性:单模型基线

Wang 等人 2022 年("Self-Consistency Improves Chain of Thought Reasoning")在温度 > 0 下对同一模型采样 N 次,并对推理路径的答案进行多数投票。在 GSM8K 上的结果:N=40 次采样相比单次贪心解码带来显著提升。自洽性是多智能体投票的单智能体前身。

局限:自洽性只用一个基础模型,错误在构造上就是相关的。如果模型存在系统性偏差,所有 N 个样本都会共享这一偏差。

### 多智能体投票:异构扩展

用 N 个*不同*的智能体替代 N 次采样。不同的基础模型(Claude、GPT、Llama)、不同的提示词、不同的工具访问权限。好处:错误不相关。代价:不同智能体成本不同;协调它们会增加开销。

异构辩论在 2026 年的规范名称是 **A-HMAD** —— Adversarial Heterogeneous Multi-Agent Debate(对抗性异构多智能体辩论)。该名称并未被普遍采用,但论文中用它指代"不同模型进行辩论,从而减少单一化崩溃导致的相关错误"。

### 四种拓扑

```
star                chain               tree                graph

    ┌─A─┐           A─B─C─D         ┌──A──┐              A───B
    │   │                           │     │              │ × │
    B   C                           B     C              D───C
    │   │                          / \   / \
    D   E                         D   E F   G           (fully connected)
```

星型:一个中心节点,其余节点只与中心通信。等价于没有旁路通信的 supervisor-worker。
链式:线性结构,每个智能体只看到前一个的输出。类似流水线。
树形:层次化结构,用于层次化智能体系统(第 06 课)。
图状:任意节点互通,包括全连接团和任意 DAG。

### 协作税(MultiAgentBench)

MultiAgentBench(MARBLE, ACL 2025, arXiv:2503.01935)在包含研究、编码和规划的任务套件上对星型、链式、树形、图状拓扑进行了基准测试。关键测量结果:

- **图状**拓扑在研究类任务上胜出。信息任意流动;智能体可以互相批评。
- **星型**在快速问答的事实型任务上胜出。中心负责过滤和汇总。
- **链式**在分步流水线(分阶段精炼)上胜出。
- 图状拓扑在约 4 个智能体以上出现**协作税**。墙钟时间和 token 成本的增长快于质量的提升。

4 个智能体的上限是经验性的,而非根本性的。它反映了 2026 年 LLM 的上下文容量:每个智能体的上下文都会被同伴的输出填满,一旦人人都能看到所有人的输出,再增加第 N+1 个智能体的边际价值就会下降。

### 多智能体辩论策略("Should we be going MAD?")

arXiv:2311.17371 是 2023 年对 MAD 策略的综述。一个被他人重复验证的关键发现:在结构上与自洽性*相似*(独立采样 + 聚合)的 MAD 变体,在相同预算下往往不如自洽性。当智能体真正异构且辩论具有对抗性结构(有一个智能体专门反对)时,MAD 的帮助最大。

### AgentVerse 涌现模式

AgentVerse(ICLR 2024, https://proceedings.iclr.cc/paper_files/paper/2024/file/578e65cdee35d00c708d4c64bce32971-Paper-Conference.pdf)记录了多智能体辩论中即使没有显式设计也会涌现的两种行为:

- **自愿。** 智能体在无人提示的情况下主动提供帮助("我可以执行下一步")。有用之处:它把子任务分配给能力最强的智能体。
- **从众。** 智能体调整自己的立场以迎合批评者,即使批评者是错的。这是谄媚(sycophancy)在辩论中的等价物(第 14 课)。

从众正是"辩论到达成一致为止"会奖励恃强凌弱者的原因。以有界轮数加上独立的裁判可以缓解。

### 异构性:真正能移动准确率的旋钮

2024–2026 年实践文献中的一个规律:把 N 个智能体之一换成不同的基础模型,带来的准确率提升大于把 N 增加 1。直觉在于单一化——每个新的独立错误来源,都比一个额外的相关样本更有价值。

在极限情况下,异构性胜过数量。在大多数有清晰标准答案的任务上,三个不同的模型胜过同一个模型的五个副本。

### 陪审团方法

Sibyl 框架(见 Minsky-LLM 文献的引用)将"陪审团"形式化——一小组专门化智能体在每个阶段通过投票精炼答案。与单纯的多数投票不同,陪审团有角色分工:一个智能体负责盘问,一个提供上下文,一个评估合理性。陪审团方法介于单纯投票(廉价、易陷入单一化)和完整 MAD(昂贵、易从众)之间。

### 何时投票加辩论占优

- 问题有标准答案(事实、数学、代码行为)。投票收敛才有意义。
- 智能体可以访问不同的来源或工具(异构性可用)。
- 轮数有界(通常 2–3 轮),且有独立的裁判或验证器。
- 预算允许 3–5 个智能体。图状拓扑下超过 5–7 个,协作税就会占主导。

### 何时投票加辩论有害

- 问题属于观点型。智能体会收敛到看起来最自信的答案,而不是最正确的答案。
- 所有智能体共享同一个基础模型。单一化使共识毫无意义。
- 轮数无界。从众总是获胜。
- 任务简单。N=5 的自洽性单智能体更便宜且同样准确。

## 动手构建

`code/main.py` 实现:

- `run_star(agents, hub, question)` —— 中心轮询每个 worker 并聚合。
- `run_chain(agents, question)` —— 顺序精炼。
- `run_tree(root, children, question)` —— 层次化,深度为 2 的聚合。
- `run_graph(agents, question, rounds)` —— 全互联辩论,有界轮数。
- 一个脚本化的异构性旋钮:每个智能体有一个 `error_bias`,表示其系统性错误倾向。
- 一个测量框架,以 N=3、5、7 运行每种拓扑,并报告 (accuracy, total_tokens, wallclock_simulated)。

运行:

```
python3 code/main.py
```

预期输出:一张 拓扑 × N → (accuracy, tokens, latency) 的表格。在研究类任务上,图状拓扑在 N=3–5 时胜出;快速事实型任务上星型胜出;N=7 的图状拓扑展现协作税(延迟的膨胀快于准确率的提升)。

## 使用

`outputs/skill-topology-picker.md` 是一个技能,它读取任务描述并推荐一种拓扑(星型/链式/树形/图状)、一个 N(智能体数量)、一个异构性配置(要使用的基础模型)以及一个轮数上限。

## 上线

对于任何集成:

- 从**单个强基础模型的 N=5 自洽性**开始。这是廉价的基线。
- 如果准确率重要,升级到 **N=3 的异构投票**。测量差值。
- 只有当任务具有结构性(研究类、多步骤)且有界轮数可行时,才升级到**辩论拓扑**。
- 始终记录少数派簇。当少数派持续正确时,你就拥有了一个多样性信号。
- 在准确率之外同时记录墙钟时间和 token。"以 10 倍成本换取更高准确率"是一个商业决策。

## 练习

1. 运行 `code/main.py`。绘制图状拓扑的协作税曲线:accuracy vs N,tokens vs N。曲线在哪个 N 处出现拐点?

3. 为图状拓扑添加一个不投票、只对最终共识打分的"裁判"角色。这是否会改变涌现出的从众行为?
4. 阅读 AgentVerse 论文(ICLR 2024)。判断你的实现最强烈地表现出哪种涌现行为。你能通过修改提示词引出相反的行为吗?
5. 阅读 MultiAgentBench(arXiv:2503.01935)第 4 节(拓扑实验)。使用你的框架在论文的某个任务上复现"图状拓扑在研究类任务上胜出"的结果。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| Self-consistency | "采样 N 次,投票" | Wang 2022。单模型,N 次温度>0 采样,对推理路径进行多数投票。 |
| Heterogeneity | "不同的模型" | 由不同基础模型或提示词族组成的集成。打破单一化。 |
| MAD | "多智能体辩论" | 智能体在多轮中交换批评意见的统称。见 Du 2023。 |
| A-HMAD | "Adversarial Heterogeneous MAD" | 强调不同模型 + 对抗性结构的 MAD 变体。 |
| Topology | "谁与谁通信" | 星型、链式、树形、图状。决定信息流向。 |
| Coordination tax | "收益递减" | 图状拓扑下约 4 个智能体以上,成本增长快于质量提升。 |
| Volunteer behavior | "无人提示的帮助" | AgentVerse 涌现模式:智能体主动提出执行某一步。 |
| Conformity behavior | "压力下的附和" | AgentVerse 涌现模式:智能体与批评者保持一致。 |
| Jury | "小型专门小组" | Sibyl 风格的集成,具有角色分工(盘问者、上下文、评分者)。 |
