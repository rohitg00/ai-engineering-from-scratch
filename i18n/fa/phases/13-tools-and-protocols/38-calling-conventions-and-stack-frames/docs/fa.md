# تماس با کنوانسیون ها و فریم های استیک: سیستم V، ویندوز x64 و AArch64

> یک تجزیه نشان می دهد که کدام یک از ثبت کننده ها یک تابع را می خوانند. تنها ABI می گوید که این ثبت کننده ها چه معنایی دارند و ABI توسط عنوان موضوع انتخاب می شود، بنابراین این درس ابتدا سر را می خواند و سپس هر ثبت کننده را با قاعده ای که آن را در آنجا قرار داده است بررسی می کند.

**Type:** Build
**Languages:** Python, TypeScript, C, x86-64 and AArch64 assembly
**Prerequisites:** Phase 13 · 32 (ELF from scratch), Phase 13 · 33 (disassembly and control flow)
**Time:** ~140 minutes

## اهداف یادگیری

- کنوانسیون تماس را از عنوان موضوع انتخاب کنید: ELF x86-64 سیستم V psABI است، COFF AMD64 مایکروسافت x64 است، ELF AArch64 AAPCS64 است، Mach-O arm64 نسخه ای از اپل است.
- پیشگام یک تابع بایت به بایت برای هر ABI را رمزگذاری کنید و هر ثبت ذخیره شده، آدرس بازگشت و اشاره کننده فریم را در تعویض آن از اشاره کننده ستاک ورود قرار دهید.
- ثبت پارامتر یک تابع از ثبت هایی که قبل از نوشتن آن می خواند و سلاٹس استدلال های سقف از بارگذاری های بالای اشاره کننده سقف ورود وارد کنید.
- به دنباله های مستقل سیستم V از نقاط موقعیت مایکروسافت x64 و هر دو از شمارشگر NGRN و NSRN AAPCS64 بگویید.
- هر نتیجه گیری را با امضای منبع، قانون مشخصات و داده های خود را در `.pdata`،`.xdata`و`.eh_frame`. .
- مقایسه کنید که چگونه Ghidra، IDA، Binary Ninja، radare2، rizin، و angr نام و بازیابی از همان حقایق، و ثبت کنید که در آن محصول با منبع مخالف است.

## مشکل

تو جمع آوری کردی`convention.c`برای لینوکس x86-64 در `-O2`و از رادار2.6.2.4 خواستند تا استدلال های `eight_args`جوابش با هفت تا بود:`rdi`،`rsi`،`rdx`،`r8`،`r9`،`rsp+0x8`و`rsp+0x10`. منبع C هشت پارامتر داره . بايت ها می خوانند`%rcx`دقیقاً یک بار، در`leaq (%rdx,%rcx), %rax`، و بازیافت متغیر ابزار یک ثبت نام را که فقط در داخل یک آدرس ظاهر می شود، شمارش نمی کند.

سپس نسخه ویندوز از همان فایل را در رزین 0.9.1 باز کرد.`amd64`و پیدا شد`r8`،`rcx`،`rdx`، و سه نقطه ی سقف. این شی COFF است، بنابراین کنوانسیون مایکروسافت x64 است، استدلال چهارم ثبت کننده `r9`دو ابزار در یک منبع مختلف را از دست می دهند.

یک لیست یک سری دستورالعمل ها است. یک کنوانسیون تماس یک قرارداد است که خارج از لیست می باشد: چه ثبت کننده ها استدلال های حمل، که تماس گیرنده باید حفظ کند، در کجا آدرس بازگشت و استدلال های دسته قرار دارد و چه چیزی باید تماس گیرنده بالای اشاره کننده دسته باقی بماند. چهار سند قرارداد مهم رو در اين مورد مشخص ميکنه سیستم V AMD64 psABI (ورژن 1.0, ساخت تاریخ 12 مارس 2025) بخش 3.2.1 تا 3.2.3. کنوانسیون تماس های Microsoft x64، استفاده از استیک و صفحات پیشگام و اپیلگ (تاریخ صفحه از 2018-12-17 تا 2025-03-19). بازوی AAPCS64 انتشار 2025Q4 (23 ژانویه 2026) بخش 6.1 تا 6.9. نوتاژ پلتفرم آرم 64 اپل این درس این قوانین را می خواند، آنها را به یک فایل C که به سه روش مرتب شده است، اعمال می کند و تحلیلگر را ایجاد می کند که یک لیست را به یک لیست چک شده از مکان های پارامتر، ثبت های ذخیره شده و فریم آفسیت ها تبدیل می کند.

## یک سرنوشت کتاب قوانین را انتخاب می کند

`convention.c`دوتا وظیفۀ دارد:`leaf_add`،`eight_args`،`mixed`،`by_value`،`big_ret`،`sum_varargs`،`keeps`، و پنج نفر از تماس گیرندگان`extern`عملکردهای مشابهی.`long long`، چون`long`این برنامه 4 بایت در هدف MSVC و 8 بایت در بقیه است و یک ساختار است که تغییر اندازه تغییرات کنوانسیون است. اپل کلینگ 17.0.0 آن را هفت بار از این دستگاه مرتب:`-target x86_64-unknown-linux-gnu`،`x86_64-pc-windows-msvc`و`aarch64-unknown-linux-gnu`در`-O0`و`-O2`و`arm64-apple-macos`در`-O2`هیچ عنوان لینوکس و ویندوز نصب نشده است، بنابراین فایل آنچه را که نیاز دارد اعلام می کند و فقط شامل clang خود است `stdarg.h`و`stddef.h`. .

`describe_object()`در`code/main.py`شماره جادويي 4 بايت و يک فيلد ماشين را مي خواند و نام قرارداد را مي دهد:

| Header | Field | Value | Rulebook |
|---|---|---|---|
| `7f 45 4c 46` ELF | `e_machine` at offset 0x12 | 62 | System V AMD64 psABI |
| `64 86` COFF | `Machine` at offset 0 | 0x8664 | Microsoft x64 |
| `7f 45 4c 46` ELF | `e_machine` | 183 | AAPCS64 |
| `cf fa ed fe` Mach-O 64 | `cputype` at offset 4 | 0x0100000c | AAPCS64 with Apple differences |

این سه قرارداد تقریبا در هر ردیف جدول زیر با هم متفق نیستند. هر مقدار از سند نامگذاری شده در ردیف سر نوشته شده است و هر یک از آنها با یک آزمایش با فکسچرها بررسی می شود.

| Rule | System V psABI | Microsoft x64 | AAPCS64 |
|---|---|---|---|
| Integer arguments | `%rdi %rsi %rdx %rcx %r8 %r9`, next free register | `RCX RDX R8 R9`, by position | `x0` to `x7`, by NGRN |
| Floating-point arguments | `%xmm0` to `%xmm7`, next free register | `XMM0` to `XMM3`, by position | `v0` to `v7`, by NSRN |
| Integer result | `%rax`, then `%rdx` | `RAX` | `x0`, then `x1` |
| Floating-point result | `%xmm0`, then `%xmm1` | `XMM0` | `v0` |
| Result too large for registers | address passed in `%rdi` "as if it were the first argument", returned in `%rax` | pointer in `RCX`, arguments shifted right, returned in `RAX` | address in `x8`, `x0` to `x7` untouched |
| Callee-saved | `%rbp %rbx %r12` to `%r15` | `RBX RBP RDI RSI RSP R12` to `R15`, `XMM6` to `XMM15` | `r19` to `r29`, `SP`, low 64 bits of `v8` to `v15` |
| First stack argument on entry | `8(%rsp)` | `40(%rsp)`, above a 32-byte shadow store | `0(sp)` |
| Below the stack pointer | 128-byte red zone | "considered volatile" | no red zone (Apple: 128 bytes) |
| Alignment at the call | `(%rsp + 8)` multiple of 16 on entry | 16-byte aligned outside prolog and epilog | `SP mod 16 = 0` |
| Variadic marker | `%al` holds an upper bound on vector registers used | floats duplicated in the integer register | none in registers; Apple uses 8-byte stack slots |

## سیستم V: دو ردیف ثبت مستقل و یک منطقه قرمز

psABI 3.2.3 هر هشت بائیتی از هر استدلال را به عنوان INTEGER، SSE یا MEMORY طبقه بندی می کند و سپس ثبت نام ها را از دو لیست که با هم تعامل ندارند اختصاص می دهد. "INTEGER" "ریستارهای بعدی موجود در ردیف %rdi، %rsi، %rdx، %rcx، %r8 و %r9" را می گیرد. SSE می گیرد `%xmm0`به`%xmm7`"اگر برای هر هشت باایت یک استدلال هیچ رکوردی در دسترس نباشد، کل استدلال در استیک منتقل می شود" و استدلال های حافظه "در استیک به ترتیب معکوس (از راست به چپ) فشار می شوند".

`eight_args(a, b, c, d, e, f, g, h)`در`-O2`27 بایت است:

```text
      10: 48 01 fe                     	addq	%rdi, %rsi
      13: 48 8d 04 0a                  	leaq	(%rdx,%rcx), %rax
      17: 48 01 f0                     	addq	%rsi, %rax
      1a: 4c 01 c0                     	addq	%r8, %rax
      1d: 4c 01 c8                     	addq	%r9, %rax
      20: 48 03 44 24 08               	addq	0x8(%rsp), %rax
      25: 48 03 44 24 10               	addq	0x10(%rsp), %rax
      2a: c3                           	retq
```

شش تا کادر و دو تا بار`8(%rsp)`و`16(%rsp)`. شکل 3.3 از psABI "دلیل حافظه 8byte 0" را به `16(%rbp)`چه وقت`%rbp`پایه فریم است، که `8(%rsp)`قبل از هر فشار وارد شدن`g`ساعت 8ه`h`در 16 سالگی

`mixed(int i, double d, long long l, float f)`دو لیست رو نشان ميده`%edi`و`%rsi`, اولین و دومین ثبت INTEGER.`%xmm0`و`%xmm1`، اولین و دومین ثبتات SSE.`cvtsi2sd %edi, %xmm2`و`%xmm2`یک کالا از خاکستری است که تابع قبل از خواندن آن می نویسد. یک تحلیلگر که به مقصد `cvtsi2sd`به عنوان یک مطالعه یک استدلال سوم نقطه شناور اختراع می کند. رادار2 دقیقاً همین کار را کرد و گزارش داد`mixed`مثل`(double arg1, double arg2, double arg3)`در`xmm0`،`xmm1`،`xmm2`. .

`by_value(struct pair p)`یک ساختار 16 بایت به عنوان دو 8 بایت کامل در `%rdi`و`%rsi`، و به همان روش آن را بازمی گرداند:`leaq 0x1(%rdi), %rax; leaq -0x1(%rsi), %rdx; retq`.`big_ret(long long seed)`32 بایت را باز می گرداند که کلاس حافظه است و psABI می گوید "کارگر فضای را برای ارزش بازمی گردد فراهم می کند و آدرس این ذخیره را به %rdi می گذرد انگار که اولین استدلال است". `seed`به سمت`%rsi`، و تابع با شروع می شود`movq %rdi, %rax`چون "در بازگشت %rax آدرس که توسط تماس گیرنده در %rdi وارد شده است را در خود خواهد داشت".

منطقه قرمز دیگر امضای سیستم V است. psABI 3.2.2: "جای ۱۲۸ بایت فراتر از محل که توسط %rsp اشاره شده است، به عنوان محفوظ محسوب می شود و نباید توسط کنترل کننده های سیگنال یا قطع تغییر یابد".`-O0`،`eight_args`.`pushq %rbp; movq %rsp, %rbp`و بعد شش مغازه رو به`-0x8(%rbp)`از طریق`-0x30(%rbp)`بدون هیچ`subq`مغازه ها 48 بايت زیر شاخص ستک قرار دارن`-O2`ساخت`sum_varargs`88 بایت را با `subq $0x58, %rsp`و بعد قسمت ذخیره سازی را در `-0x58(%rsp)`تا`-0x80(%rsp)`: 128 بايت در زیر اشاره ستک، تمام منطقه قرمز.`-mno-red-zone`و`leaf_add`به دست می آید`pushq %rax`و یک`addq $0x8, %rsp`تا 8 بايت از مردم محلی رو بالای اشاره دار نگه داره

تماس های مختلف یک ثبت اضافه می کنند. "%al به عنوان استدلال پنهان برای مشخص کردن تعداد ثبت های ویکتور استفاده می شود" یک مرز بالا از 0 تا 8. `call_varargs`با هم ميگيره`xorl %eax, %eax`در`-O2`و`movb $0x0, %al`در`-O0`.`sum_varargs`اول ميخواد:`testb %al, %al; je`هشتم پرواز`movaps %xmmN`در زمان استفاده از هیچ رکورد متری ذخیره می شود.

## مایکروسافت x64: موقعیت ها، یک فروشگاه سایه و هیچ منطقه قرمز

قوانین مایکروسافت موقعیت دارند. "دلگرهای کامل در ثبت RCX، RDX، R8 و R9 عبور می کنند.دلگرهای نقطه شناور در XMM0L، XMM1L، XMM2L و XMM3L عبور می کنند. " و "هر استدلال نقطه شناور و دوگانه دقت در چهار پارامتر اول در XMM0 - XMM3 عبور می شود. بسته به موقعیت. " همان `mixed`به عنوان`%ecx`،`%xmm1`،`%r8`،`%xmm3`: slot 0 یک int است، بنابراین `RCX`؛ سلايت 1 دو برابر است، پس`XMM1`؛ سلايت 3 يه شناوريه، پس`XMM3`.`XMM0`و`XMM2`خالی بمون

تماس گیرنده باید فضای کافی را برای ذخیره کردن چهار پارامتر ثبت نام، حتی اگر تماس گیرنده این تعداد پارامتر را نداشته باشد، اختصاص دهد. صفحات آن را فروشگاه سایه یا آدرس خانه می نامند و چهار سلاٹ "فعالانه متعلق به تابع تماس" هستند. در ورود `0(%rsp)`آدرس بازگشت است`8(%rsp)`به`39(%rsp)`این چهار خانه است و اولین بحث در این باره`40(%rsp)`.`eight_args`در`-O2`میخواد`0x28(%rsp)`،`0x30(%rsp)`،`0x38(%rsp)`،`0x40(%rsp)`: ۴۰، ۴۸، ۵۶، ۶۴

طرف تماس دهنده حساب حساب را نشان می دهد.`call8`در`-O2`.`subq $0x48, %rsp`و بعد مغازه هاي 5، 6، 7، 8 در`0x20(%rsp)`به`0x38(%rsp)`قبل از`movl $1, %ecx`و دوستان. 72 بايت 32 برای فروشگاه سایه، 32 برای چهار استدلال ستک و 8 برای اینکه آدرس بازگشت در یک مرز 16 بايت است. `call_varargs`فقط استدلال ها رو ثبت ميکنه و هنوز هم ميفرسه`subq $0x28, %rsp`: 32 تا براي فروشگاه سايه و 8 تا براي همبيني`keeps`سه تا ثبت نام غیر متغیر (24 بایت) را فشار می دهد و سپس `subq $0x20, %rsp`، پس اون`ext`32 بايت سايه خود را در زیر آدرس بازگشت پیدا می کند.

ساختارها قاعده ی خود را دنبال می کنند. "هر استدلال ای که در 8 بایت قرار ندارد، یا 1، 2، 4 یا 8 بایت نیست، باید با مرجع عبور شود". و "منظرات 16 بایت با مرجع عبور می شوند". `by_value`بنابراین یک اشاره به یک کپی در `%rdx`، بعد از يه نشانگر نتيجه پنهان در`%rcx`: "کارگر باید حافظه را برای ارزش بازگشت اختصاص دهد و یک اشاره را به عنوان استدلال اول به آن منتقل کند. سپس استدلال های باقیمانده یک استدلال به سمت راست منتقل می شود". `call_pair`نسخه رو در `0x20(%rsp)`با`movaps`، گذرگاه`leaq 0x20(%rsp), %rdx`, با `leaq 0x38(%rsp), %rcx`و میخواد`.b`از`0x40(%rsp)`. .

هیچ منطقه قرمز وجود ندارد. "همه حافظه فراتر از آدرس فعلی RSP نامناسب محسوب می شود: OS یا یک debugger ممکن است این حافظه را در طول یک جلسه debug کاربر یا یک دستیار قطع تغییر نامناسب تغییر دهد. "`-O0` `leaf_add`8 بايت از مردم محلی رو ميخواد و باشون ميگيره`pushq %rax`در ورود و`popq %rcx`قبل از`retq`، دو تا دستورات یک بايت به جای یک`subq`و یک`addq`صفحه استفاده از استیک صفحه ای را تعریف می کند که می تواند این کار را انجام دهد: "یک تابع ورق یک است که نیازی به ورود به جدول عملکرد ندارد. نمی تواند تغییرات را در هر گونه ثبت نام غیر متغیر، از جمله RSP انجام دهد".

"برای عملکردهای وارارگ یا نمونه های اولیه، هر مقدار نقطه شناور باید در register عمومی مربوطه دوبرابر شود".`sum_varargs`در`-O2`فروشگاه ها`%rdx`،`%r8`،`%r9`به`0x18(%rsp)`،`0x20(%rsp)`،`0x28(%rsp)`بعد از يک`pushq %rax`, که در حال تعویض ورود 16, 24, 32: خانه های دوم، سوم و چهارم register پارامترها است.`va_list`.`leaq 0x18(%rsp), %rax`، خونه ي`%rdx`، اولین بحث نامعلوم

## AAPCS64 و آنچه اپل تغییر می کند

AAPCS64 6.8.2 یک لیست از قوانین را با دو شمارش کننده انجام می دهد. C.9: یک استدلال ادغام "به بیت های کمتر قابل توجه در x [NGRN]" و افزایش NGRN کپی می شود. C.1 برای استدلال های نقطه شناور با NSRN همین کار را انجام می دهد. C.12: ترکیبی از حداکثر `8 - NGRN`دو کلمه "در registers عمومی استفاده متوالی کپی شده است". C.13 تنظیم می کند "NGRN به 8" هنگامی که یک استدلال به استیک می رود، بنابراین هیچ چیز به registers پس از آن باز نمی گردد. `eight_args`استفاده`x0`به`x7`و هرگز به دسته دست نزنه`mixed`.`w0`،`d0`،`x1`،`s1`.`by_value`.`x0`و`x1`داخل و خارج

6.9 می گوید نتیجه ای که در سوابق منتقل می شود "در همان سوابق بازگردانده می شود"، در غیر این صورت " آدرس بلوک حافظه به عنوان یک استدلال اضافی به تابع در x8 منتقل می شود". `big_ret`نوشته شده`str x0, [x8]`،`stur q0, [x8, #0x8]`،`str x9, [x8, #0x18]`و هرگز ننوشته`x0`.`call_big`مجموعه ها`mov x8, sp`و`seed`در اين جا ماند`x0`، چون 6.9 اضافه می کند "هیچ الزامی برای calllee برای حفظ ارزش ذخیره شده در x8 وجود دارد" و `x8`یکی از پرونده های استدلال نیست.

## جمع کننده دو بار همان حقایق را نوشت

یک پیشگویی تجزیه یک مشتق است. سازنده یک دوم را برای unwinder منتشر می کند، و هر دو باید موافق باشند.

در ویندوز دومین مشتق این است`.pdata`و`.xdata`. ساختش رو`-O2`بدون هدف`-fno-asynchronous-unwind-tables`و`llvm-objdump -h`نمایش ها`.xdata`با متری 0x34 با متری`.pdata`از 0x48 بایت. 0x48 برابر 72 است، شش`RUNTIME_FUNCTION`نوشته های 12 بایت با 3 `IMAGE_REL_AMD64_ADDR32NB`هر يک از 6 نفر`sum_varargs`،`keeps`،`call8`،`call_varargs`،`call_pair`و`call_big`. شش تابع دیگر برگ ها هستند و صفحه مدیریت استثناء می گوید "اگر جستجو یک ورودی از جدول عملکرد را پیدا نکند، فرض می شود کد بخشی از یک تابع برگ است و RSP مستقیماً به اشاره کننده بازگشت مراجعه می کند".

.`.xdata`بائتهای برای `keeps`.`01 07 04 00 07 32 03 30 02 70 01 60`.`UNWIND_INFO`با نسخه در 3 بیت و پرچم در 5 بیت شروع می شود: نسخه 1، هیچ پرچم نیست. اندازه OfProlog 7 است، CountOfCodes 4 است، FrameRegister و FrameOffset 0 هستند. هر یک `UNWIND_CODE`یک تعویض در پیشگام و یک بایت از کد و اطلاعات.`07 32`: در آفست 7، آپ 2 است `UWOP_ALLOC_SMALL`، اطلاعات 3 يعني`3 * 8 + 8 = 32`بايت ها`03 30`: op 0 است`UWOP_PUSH_NONVOL`، ثبت شماره 3`rbx`.`02 70`.`rdi`.`01 60`.`rsi`. کد ها به ترتیب اجرا برعکس ذخیره می شوند و به همان سه فشار و 32 بیت اختصاص داده می شوند که باایت ها هستند `56 57 53 48 83 ec 20`.`sum_varargs`ورود این است`01 01 01 00 01 02 00 00`: یک پیشگویی یک بایت با یک کد`UWOP_ALLOC_SMALL`از 8 بايت. اين همونطوريه که اوني که ميخواد ببينه`pushq %rax`: یک تخصیص، چون`%rax`و هيچ چيز نجات نميده

2. دستگیرش کن`llvm-objdump -d -r FILE.o`قبل از هر چیز دیگری بایت های پیشگام و ثبت های ذخیره شده را بخوانید و اندازه فریم را با فشارها و `sub`. .
3. یک ثبت که امضا توضیح نمی دهد یک اشاره پنهان، یک نشانگر متغیر، یا یک ثبت سکریچ است که تحلیلگر برای یک استدلال اشتباه گرفته است. آخرین مورد یک خطا در جدول اثرات است. آن را با یک قانون عمومی برای این دستورالعمل حل کنید.
4. چک هایی که با هم موافق نیستند را بخوانید هر کدام قانون را که بر آن است، نام می دهند، بنابراین اولین چیزی که باید بررسی کنید، قانون است، سپس بایت ها، سپس تحلیلگر.
5. وقتی که این شی داده های باز شده را داشته باشد، چک متقابل را اجرا کنید. دو مشتق که با هم موافقند، قوی ترین شواهد این درس تولید می کنند.
6. وقتی ابزار دیگری نصب شده است، محصول آن را با دستور دقیق ضبط کنید و مقایسه کنید. جایی که شما موافق هستید شما سه مشتق دارید. جایی که متفاوت است شما یک فهرست خاص و یک دستورالعمل خاص برای نگاه کردن دارید، و این یک یافته برای درس 35 است.

- وآره، اون کلي مختلف ميگه`%al`، خانه ها`rdx, r8, r9`در 16، 24، 32، نجات می دهد `x1`به`x7`و`q0`به`q7`، یا نشان دهنده ی دسته تماس گیرنده را در اپل می خواند

## روش های شکست تولید

| Failure | What the weak tool reports | What the analysis must prove |
|---|---|---|
| COFF object read as System V | `rdi` and `rsi` as arguments that the function never reads | The header says 0x8664; the convention is Microsoft x64 |
| Register read only inside a `lea` | Seven arguments for an eight-argument function | Base and index registers are reads |
| `cvtsi2sd` destination counted as a read | A third double argument in `xmm2` | The first write to `xmm2` is a write; `mixed` has two SSE arguments |
| Positional slots read as sequences | `xmm0` named as the double argument on Windows | Slot 1 is `XMM1`, slot 3 is `XMM3` |
| `push rbp` taken as a frame pointer | A frame pointer in an `-O2` function that uses `rbp` as an accumulator | Only `mov %rsp, %rbp` after the push creates one |
| Red zone measured from the entry stack pointer | 216 bytes "below the stack pointer" | 128 bytes below the current stack pointer after an 88-byte `sub` |
| Shadow store treated as locals | Stack arguments at 8 to 32 | Microsoft stack arguments start at 40 |
| `lea` treated as a load | A stack argument at `0x60(%rsp)` in a variadic callee | `lea` computes `overflow_arg_area`; it loads nothing |
| Hidden pointer read as a normal argument | `big_ret(void *, long long)` | The pointer is stored through and copied to `rax`, `rax`, or stays in `x8` |
| Deepest CFA compared with the prologue frame | A mismatch on a caller that pushes outgoing arguments | Compare with the deepest stack pointer the body reaches |
| Convention asserted from the ISA | `amd64` for a COFF object | The format picks the rulebook, then the ISA picks the registers |
| Prototype trusted from one tool | Three doubles, or sixteen variadic parameters | The source signature or a second derivation must agree |
