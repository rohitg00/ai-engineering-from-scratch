# Капстоун 12 — конвейер понимания видео (сцены, QA, поиск)

> Twelve Labs превратила Marengo + Pegasus в коммерческий продукт. VideoDB выпустила CRUD-API для видео. AI2 опубликовала открытые контрольные точки VLM Molmo 2. Gemini с длинным контекстом обрабатывает часы видео нативно. TimeLens-100K задал ориентир для временной привязки (temporal grounding) в промышленном масштабе. Конвейер 2026 года устоялся: сегментация сцен, подпись и векторное представление (эмбеддинг) для каждой сцены, выравнивание транскрипта, мультивекторный индекс и запрос, который отвечает временными метками (start, end) вместе с превью кадров. Капстоун — это приём 100 часов видео, прохождение публичных бенчмарков и измерение галлюцинаций на вопросах о подсчёте и действиях.

**Тип:** Капстоун
**Языки:** Python (конвейер), TypeScript (UI)
**Предварительные требования:** этап 4 (CV), этап 6 (речь), этап 7 (трансформеры), этап 11 (инженерия LLM), этап 12 (мультимодальные системы), этап 17 (инфраструктура)

## Проблема

QA по длинным видео (long-form video QA) — самая требовательная к пропускной способности мультимодальная задача в масштабах 2026 года. Gemini 2.5 Pro умеет нативно читать двухчасовое видео, но для приёма 100 часов видео в доступный для запросов корпус всё равно нужен индекс на уровне сцен. Продакшен-конвейер сочетает сегментацию сцен (TransNetV2 или PySceneDetect), создание подписей к каждой сцене с помощью VLM (Gemini 2.5, Qwen3-VL-Max или Molmo 2), выравнивание транскрипта (Whisper-v3-turbo с временными метками по словам) и мультивекторный индекс, который хранит рядом подпись, эмбеддинг кадра и транскрипт. Конвейер запросов отвечает временными метками (start, end) и превью кадров.

Бенчмарки публичные (ActivityNet-QA, NeXT-GQA) плюс собственный набор из 100 запросов. Галлюцинации на вопросах о подсчёте и действиях — известный сложный класс сбоев; капстоун явно измеряет его.

## Концепция

При приёме параллельно работают три конвейера. **Сегментация сцен** разрезает видео на сцены. **Создание подписей VLM** генерирует подпись для каждой сцены и эмбеддинг кадра из ключевого кадра. **Выравнивание ASR** формирует временные метки по словам. Три потока объединяются по (scene_id, диапазон времени). Каждая сцена получает три типа векторов в мультивекторном индексе (Qdrant): эмбеддинг подписи, эмбеддинг ключевого кадра, эмбеддинг транскрипта.

В момент запроса вопрос на естественном языке отправляется сразу по всем трём векторам; результаты объединяются методом слияния по обратным рангам (RRF, reciprocal rank fusion); адаптер временной привязки (в стиле TimeLens) уточняет окно (start, end) внутри лучшей сцены. VLM-синтезатор (Gemini 2.5 Pro или Qwen3-VL-Max) принимает запрос, лучшие сцены и обрезанные кадры и отвечает с указанием источника по временным меткам и превью кадра.

Измерение галлюцинаций имеет значение. Вопросы на подсчёт («сколько человек вошло в комнату?») и вопросы о действиях («повар наливает раньше, чем помешивает?») печально известны своей ненадёжностью. Отчитывайтесь о точности отдельно от описательных вопросов.

## Архитектура

```
video file / URL
      |
      v
PySceneDetect / TransNetV2  (scene segmentation)
      |
      +--- per-scene keyframe --- VLM caption + frame embedding
      |                            (Gemini 2.5 Pro / Qwen3-VL-Max / Molmo 2)
      |
      +--- audio channel --- Whisper-v3-turbo ASR + word timestamps
      |
      v
multi-vector Qdrant: {caption_emb, keyframe_emb, transcript_emb}
      |
query:
  dense queries against all three -> RRF merge -> top-k scenes
      |
      v
TimeLens / VideoITG temporal grounding (refine start/end within scene)
      |
      v
VLM synth: query + top scenes + frame previews
      |
      v
answer + (start, end) timestamps + frame thumbs + citations
```

## Стек

- Сегментация сцен: TransNetV2 (лидер по состоянию на 2024–26 годы) или PySceneDetect
- ASR: Whisper-v3-turbo через faster-whisper с временными метками по словам
- VLM для подписей и ответов: Gemini 2.5 Pro, Qwen3-VL-Max или Molmo 2
- Временная привязка: адаптер, обученный на TimeLens-100K, или VideoITG
- Индекс: Qdrant с поддержкой мультивекторности (подпись / кадр / транскрипт)
- UI: Next.js 15 с видеоплеером HTML5 и миниатюрами сцен
- Оценивание: ActivityNet-QA, NeXT-GQA, собственный набор из 100 вопросов с ручной разметкой
- Бенчмарк галлюцинаций: подмножества с вопросами на подсчёт и действия с ручной разметкой

## Реализация

1. **Обходчик приёма (ingest walker).** Принимайте URL YouTube или локальные MP4. При необходимости уменьшайте разрешение до 720p. Сохраняйте `{video_id, file_path}`.

2. **Сегментация сцен.** Запустите TransNetV2 или PySceneDetect, чтобы получить `[{scene_id, start_ms, end_ms, keyframe_path}]`. Ориентир для 100 часов: ~6k-8k сцен.

3. **Проход ASR.** Запустите Whisper-v3-turbo на аудио; экспортируйте временные метки по словам; разбейте на фрагменты транскрипта по сценам.

4. **Создание подписей VLM.** Для каждой сцены вызывайте Gemini 2.5 Pro (или Qwen3-VL-Max) с ключевым кадром и коротким шаблоном подписи. Получайте подпись и эмбеддинг кадра.

5. **Мультивекторный индекс.** Коллекция Qdrant с тремя именованными векторами. Полезная нагрузка: `{video_id, scene_id, start_ms, end_ms, keyframe_url}`.

6. **Запрос.** Вопрос на естественном языке порождает три плотных (dense) запроса; объединение методом слияния по обратным рангам (RRF); top-k=5 сцен.

7. **Временная привязка.** Запустите адаптер в стиле TimeLens на лучшей сцене, чтобы уточнить окно (start, end) внутри сцены.

8. **VLM-синтез.** Вызовите Gemini 2.5 Pro с запросом, тремя лучшими клипами сцен (в виде изображений или коротких клипов) и транскриптами. Требуйте цитирования `(video_id, start_ms, end_ms)`.

9. **Оценивание.** Запустите ActivityNet-QA и NeXT-GQA. Соберите собственный набор из 100 запросов. Отчитывайтесь об общей точности и разбивке по классам (подсчёт, действия, описание).

## Упражнения

1. Замените Gemini 2.5 Pro на Qwen3-VL-Max на этапе создания подписей. Отчитайтесь об изменении качества подписей на выборке из 50 сцен с человеческой оценкой.

2. Сведите эмбеддинг кадра для каждой сцены к одному агрегированному (pooled) вектору вместо мультивекторного представления. Измерьте деградацию поиска.

3. Постройте режим «строгий подсчёт»: синтезатор извлекает каждый посчитанный экземпляр с временной меткой, а пользователь кликом подтверждает его. Измерьте, снижает ли проверка пользователем частоту галлюцинаций.

4. Замерьте стоимость приёма: часов видео на доллар для трёх вариантов VLM. Выберите оптимальную точку.

5. Добавьте транскрипт с диаризацией говорящих: запустите диаризацию говорящих pyannote на аудио и создайте эмбеддинги транскриптов по каждому говорящему. Продемонстрируйте запросы вида «что Алиса сказала о X?».

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| Scene segmentation (сегментация сцен) | «Обнаружение смены плана» | Разбиение видео на сцены по границам планов |
| Multi-vector index (мультивекторный индекс) | «Подпись + кадр + транскрипт» | Коллекция Qdrant с именованными векторами для каждого представления |
| Temporal grounding (временная привязка) | «Когда именно это произошло» | Уточнение окна (start, end) для ответа на запрос |
| Frame embedding (эмбеддинг кадра) | «Визуальное представление» | Векторный эмбеддинг ключевого кадра; используется для визуального сходства сцен |
| RRF fusion (слияние методом RRF) | «Слияние по обратным рангам» | Стратегия объединения нескольких ранжированных списков по обратным рангам; классический приём гибридного поиска |
| Counting hallucination (галлюцинация при подсчёте) | «Ошибка в подсчёте» | Известный сбой VLM на вопросах вида «сколько X» |
| ActivityNet-QA | «Бенчмарк QA по видео» | Бенчмарк точности QA для длинных видео |
