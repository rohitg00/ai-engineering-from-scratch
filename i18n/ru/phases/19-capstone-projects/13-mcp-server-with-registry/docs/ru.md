# Капстоун 13 — сервер MCP с реестром и управлением

> Model Context Protocol перестал быть будущим и в 2026 году стал стандартной спецификацией использования инструментов по умолчанию. Anthropic, OpenAI, Google и каждая крупная IDE поставляют MCP-клиенты. Pinterest опубликовала свою внутреннюю экосистему MCP-серверов. AAIF Registry формализовал метаданные возможностей по адресу `.well-known`. AWS ECS опубликовала эталонное развёртывание без сохранения состояния (stateless). Block со своим goose-agent поместила тот же протокол внутрь размещённого ассистента. Форма продакшена 2026 года такова: транспорт StreamableHTTP, области доступа OAuth 2.1, ограничение политиками OPA и реестр, который позволяет платформенным командам обнаруживать, проверять и включать серверы. Постройте это от начала до конца.

**Тип:** Итоговый проект
**Языки:** Python (сервер, через FastMCP) или TypeScript (@modelcontextprotocol/sdk), Go (сервис реестра)
**Предварительные требования:** этап 11 (инженерия LLM), этап 13 (инструменты и MCP), этап 14 (агенты), этап 17 (инфраструктура), этап 18 (безопасность)
**Задействованные этапы:** P11 · P13 · P14 · P17 · P18
**Время:** 25 часов

## Проблема

MCP стал общим языком (lingua franca) для использования инструментов. Claude Code, Cursor 3, Amp, OpenCode, Gemini CLI и практически каждый управляемый агент теперь потребляют MCP-серверы. Продакшн-сложность не в написании серверов (FastMCP делает это простым), а в их развёртывании в масштабе с корпоративными требованиями: области доступа OAuth для каждого тенанта, политики OPA для деструктивных инструментов, масштабирование StreamableHTTP без сохранения состояния, реестр для обнаружения, журналы аудита на каждый вызов инструмента. Внутренняя экосистема MCP компании Pinterest и спецификация AAIF Registry задают планку 2026 года.

Вы построите MCP-сервер, предоставляющий 10 внутренних инструментов (Postgres только для чтения, листинг S3, Jira, Linear, Datadog и т. д.), UI реестра для обнаружения на уровне платформы и шлюз одобрения человеком для деструктивных инструментов. Нагрузочный тест демонстрирует горизонтальное масштабирование StreamableHTTP. Журнал аудита удовлетворяет требованиям корпоративной проверки безопасности.

## Концепция

Редакция MCP 2026 года предписывает StreamableHTTP как транспорт по умолчанию. В отличие от более ранней формы stdio-и-SSE, StreamableHTTP по умолчанию не сохраняет состояние (stateless): единая HTTP-конечная точка принимает запросы JSON-RPC, стримит ответы и поддерживает долгоживущие соединения для уведомлений. Отсутствие состояния означает горизонтальную масштабируемость за балансировщиком нагрузки.

Авторизация — это OAuth 2.1 с областями доступа для каждого инструмента. Токен несёт области доступа вроде `jira:read`, `s3:list`, `postgres:query:readonly`. MCP-сервер проверяет области доступа в момент вызова инструмента, а не только при старте сессии. Для инструментов высокого риска сервер отклоняет любой вызов, чья область доступа не повышена до `approved:by:human` за последние N минут — это повышение приходит из карточки ревью в Slack.

Реестр — отдельный сервис. Каждый MCP-сервер предоставляет документ `.well-known/mcp-capabilities` с манифестом инструментов, URL транспорта, требованиями авторизации. Реестр опрашивает, проверяет и индексирует их. Платформенные команды используют UI реестра, чтобы увидеть, какие инструменты доступны, какие области доступа им нужны и какие команды ими владеют.

## Архитектура

```
MCP client (Claude Code, Cursor 3, ...)
          |
          v
StreamableHTTP over HTTPS (JSON-RPC + streaming)
          |
          v
MCP server (FastMCP) behind load balancer
          |
   +------+------+---------+----------+------------+
   v             v         v          v            v
Postgres    S3 listing  Jira       Linear     Datadog
(read-only) (paged)     (read)     (read)     (query)
          |
   +------+-------------+
   v                    v
 OPA policy gate   destructive tool MCP (separate server)
                        |
                        v
                   human approval via Slack
                        |
                        v
                   audit log (append-only, per-tenant)

  registry service
     |
     v  GET /.well-known/mcp-capabilities from each server
     v
     UI: search / validate / enable-disable / ownership
```

## Стек

- Серверный фреймворк: FastMCP (Python) или `@modelcontextprotocol/sdk` (TypeScript)
- Транспорт: StreamableHTTP поверх HTTPS (без сохранения состояния)
- Авторизация: OAuth 2.1 с идентичностью рабочей нагрузки (workload identity) через SPIFFE / SPIRE
- Политика: правила OPA / Rego для каждого инструмента; сервис принятия решений по политике на каждый запрос
- Реестр: самостоятельно размещаемый (self-hosted), потребляет манифесты `.well-known/mcp-capabilities`
- Одобрение человеком: интерактивное сообщение Slack для деструктивных инструментов
- Развёртывание: AWS ECS Fargate или Fly.io, один сервер на тенанта либо общий сервер с разграничением по тенантам (tenant scoping)
- Аудит: структурированный JSONL в бакете для каждого тенанта, с указанием происхождения (lineage) для каждого вызова

## Реализация

1. **Поверхность инструментов.** Предоставьте 10 внутренних инструментов: запрос к Postgres только для чтения, листинг объектов S3, поиск/получение в Jira, поиск/получение в Linear, запрос метрик Datadog, поиск дежурного в PagerDuty, GitHub только для чтения, поиск в Notion, поиск в Slack, чтение из Salesforce. У каждого инструмента типизированная схема и метка области доступа.

2. **Сервер FastMCP.** Подключите инструменты. Настройте транспорт StreamableHTTP. Добавьте промежуточное ПО (middleware) для интроспекции токена OAuth и применения областей доступа.

3. **Политика OPA.** Политика Rego для каждого инструмента: какие области доступа разрешают вызов, какое маскирование PII применяется, какие ограничения размера полезной нагрузки действуют. Сервис принятия решений вызывается при каждом вызове инструмента.

4. **Сервис реестра.** Отдельный сервис на Go или TS, который опрашивает `.well-known/mcp-capabilities` у зарегистрированных серверов, проверяет по JSON Schema и предоставляет UI со списком / поиском / проверкой / включением-выключением.

5. **Манифест возможностей.** Каждый сервер предоставляет `.well-known/mcp-capabilities` со списком инструментов, требованиями авторизации, URL транспорта, командой-владельцем, SLO.

6. **Разделение деструктивных инструментов.** Инструменты, изменяющие состояние (создание в Jira, создание в Linear, запись в Postgres), живут на втором MCP-сервере с более строгим потоком авторизации: токены должны иметь область доступа `approved:by:human`, повышенную через карточку в Slack в течение 15 минут.

7. **Журнал аудита.** JSONL только для добавления на каждого тенанта: `{timestamp, user, tool, args_redacted, response_redacted, outcome}`. Маскирование PII через Presidio перед записью.

8. **Нагрузочный тест.** 100 одновременных клиентов на StreamableHTTP. Продемонстрируйте горизонтальное масштабирование, добавив вторую реплику; покажите, как балансировщик нагрузки перераспределяет запросы без привязки к сессии (session stickiness).

9. **Тесты на соответствие.** Прогоните официальный набор тестов на соответствие MCP (conformance suite) против обоих серверов. Пройдите все обязательные разделы.

## Упражнения

1. Добавьте новый инструмент (поиск в Confluence). Поставьте его через процесс проверки реестра, не трогая основной сервер.

2. Напишите политику OPA, которая маскирует результаты запросов Postgres, содержащие столбцы с именами `email`, `ssn` или `phone`. Проверьте на пробном запросе.

3. Сравните StreamableHTTP и stdio по локальной задержке. Приведите p50/p95 на вызов.

4. Реализуйте квоту для каждого тенанта: максимум N вызовов в минуту на инструмент на тенанта. Примените через второе правило OPA.

5. Прогоните набор тестов на соответствие MCP из [mcp-conformance-tests](https://github.com/modelcontextprotocol/conformance) и исправьте каждый сбой.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| StreamableHTTP | «Транспорт MCP 2026 года» | HTTP без сохранения состояния + стриминг; заменяет SSE + stdio для сетевых серверов |
| Capability manifest (манифест возможностей) | «Well-known-документ» | `.well-known/mcp-capabilities` со списком инструментов, авторизацией, URL транспорта |
| OPA / Rego | «Движок политик» | Open Policy Agent для авторизации вызовов инструментов по внешним правилам |
| Scope elevation (повышение области доступа) | «Одобрено человеком» | Короткоживущая область доступа, выдаваемая через одобрение в Slack, требуется для деструктивных инструментов |
| Registry (реестр) | «Обнаружение инструментов» | Сервис, индексирующий MCP-серверы по их манифестам возможностей |
| Workload identity (идентичность рабочей нагрузки) | «SPIFFE / SPIRE» | Криптографическая идентичность сервиса для выдачи токенов OAuth |
| Conformance suite (набор тестов на соответствие) | «Тесты спецификации» | Официальный набор тестов MCP для проверки корректности StreamableHTTP + манифеста инструментов |
