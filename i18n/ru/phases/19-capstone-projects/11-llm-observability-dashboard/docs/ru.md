# Итоговый проект 11 — дашборд наблюдаемости и оценивания LLM

> Langfuse перешла на модель с открытым ядром. Arize Phoenix опубликовала соответствия GenAI semconv 2026 года. Helicone и Braintrust одновременно сделали ставку на атрибуцию затрат по пользователю. OpenLLMetry от Traceloop стал де-факто стандартом инструментирования SDK. Типичная продакшен-архитектура — ClickHouse для трасс, Postgres для метаданных, Next.js для интерфейса и небольшая армия заданий оценивания (DeepEval, RAGAS, LLM-судья), работающих со сэмплированными трассами. Постройте один самостоятельно развёрнутый дашборд, принимайте данные как минимум от четырёх семейств SDK и продемонстрируйте обнаружение внедрённой регрессии менее чем за пять минут.

**Тип:** Capstone
**Языки:** TypeScript (интерфейс), Python / TypeScript (приём данных + оценивание), SQL (ClickHouse)
**Предварительные требования:** этап 11 (инженерия LLM), этап 13 (инструменты), этап 17 (инфраструктура), этап 18 (безопасность)
**Задействованные этапы:** P11 · P13 · P17 · P18
**Время:** 25 часов

## Проблема

Каждая команда, работающая с продакшен-трафиком ИИ в 2026 году, держит плоскость наблюдаемости рядом с моделью. Атрибуция затрат. Обнаружение галлюцинаций. Мониторинг дрейфа. Сигнал джейлбрейка. SLO-дашборды. Оповещения об утечке PII. Эталонные решения с открытым исходным кодом — Langfuse, Phoenix, OpenLLMetry — сошлись на семантических соглашениях GenAI OpenTelemetry как на схеме приёма данных. Теперь можно инструментировать OpenAI, Anthropic, Google, LangChain, LlamaIndex и vLLM одним SDK и получать совместимые спаны.

Вы построите самостоятельно развёрнутый дашборд, который принимает данные как минимум от четырёх семейств SDK, прогоняет небольшой набор заданий оценивания над сэмплированными трассами, обнаруживает дрейф и рассылает оповещения. Планка измерения: при намеренно внедрённой регрессии (промпт, который начинает выдавать PII) дашборд обнаруживает её и отправляет оповещение менее чем за пять минут.

## Концепция

Приём данных идёт по OTLP HTTP. SDK производит спаны в формате GenAI-semconv: `gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.response.id`, `llm.prompts`, `llm.completions`. Спаны попадают в ClickHouse для колоночной аналитики; метаданные (пользователи, сессии, приложения) попадают в Postgres.

Оценивание выполняется как пакетные задания над сэмплированными трассами. DeepEval оценивает достоверность, токсичность и релевантность ответа. RAGAS оценивает метрики поиска, когда трасса несёт контекст поиска. Пользовательские LLM-судьи выполняют предметно-ориентированные проверки (утечка PII, ответ вне политики). Результаты прогонов оценивания записываются обратно в тот же ClickHouse как спаны оценивания, связанные с родительской трассой.

Обнаружение дрейфа отслеживает распределения в пространстве эмбеддингов во времени (PSI или дивергенция KL на эмбеддингах промптов), а также тренды оценок. Оповещения поступают в Prometheus Alertmanager, а затем в Slack / PagerDuty. Интерфейс реализован на Next.js 15 с Recharts.

```

  OpenAI SDK  +  Anthropic SDK  +  Google GenAI SDK
  LangChain + LlamaIndex + vLLM
       |
       v
  OpenTelemetry SDK with GenAI semconv
       |
       v  OTLP HTTP

       |
       +-------------+-----------+
       v             v           v
   ClickHouse    Postgres    S3 archive
   (spans)       (metadata)  (raw events)
       |
       +---> eval jobs (DeepEval, RAGAS, LLM-judge)
       |     sampled or all-trace
       |     write eval spans back
       |
       +---> drift detector (PSI / KL on prompt embeddings)
       |
       +---> Prometheus metrics -> Alertmanager -> Slack / PagerDuty
       |
       v
   Next.js 15 dashboard (Recharts)
```

## Стек

- Приём данных: SDK OpenTelemetry + семантические соглашения GenAI; транспорт OTLP HTTP
- Коллектор: OpenTelemetry Collector с процессором сэмплирования по хвосту (для контроля затрат)
- Хранение: ClickHouse для спанов, Postgres для метаданных, S3 для архива сырых событий
- Оценивание: DeepEval, RAGAS 0.2, набор оценщиков Arize Phoenix, пользовательский LLM-судья
- Дрейф: PSI / KL на объединённых эмбеддингах промптов (sentence-transformers), еженедельно
- Оповещения: Prometheus Alertmanager -> Slack / PagerDuty
- Интерфейс: Next.js 15 App Router + Recharts + серверные действия
- SDK, поддерживаемые из коробки: OpenAI, Anthropic, Google GenAI, LangChain, LlamaIndex, vLLM

## Реализация

1. **Конфигурация коллектора.** OpenTelemetry Collector с приёмником OTLP HTTP, модулем сэмплирования по хвосту, сохраняющим 100% трасс с ошибками и 10% успешных, и экспортёрами в ClickHouse и S3.

2. **Схема ClickHouse.** Таблица `spans` со столбцами, отражающими GenAI semconv: `gen_ai_system`, `gen_ai_request_model`, `input_tokens`, `output_tokens`, `latency_ms`, `prompt_hash`, `trace_id`, `parent_span_id`, плюс JSON-контейнер для длинных полезных нагрузок. Добавьте вторичные индексы по user_id и app_id.

3. **Тест покрытия SDK.** Напишите небольшое клиентское приложение, использующее каждый SDK (OpenAI, Anthropic, Google, LangChain, LlamaIndex, vLLM), с автоинструментированием OpenLLMetry. Убедитесь, что каждый производит канонические GenAI-спаны, которые попадают в ClickHouse.

4. **Задания оценивания.** Задание по расписанию читает сэмплированные трассы за последние 15 минут и прогоняет DeepEval по достоверности, токсичности и релевантности ответа. Результаты — это спаны оценивания, связанные с родительской трассой.

5. **Пользовательский LLM-судья.** Судья утечки PII: получив ответ, вызывает защитную LLM, чтобы оценить вероятность утечки PII. Ответы с высокой оценкой попадают в очередь триажа.

6. **Обнаружение дрейфа.** Еженедельное задание вычисляет PSI между распределением объединённых эмбеддингов промптов за текущую неделю и базовым распределением за последние четыре недели. Если PSI выше порога — оповещение.

7. **Дашборд.** Next.js 15 со страницами: обзор (спаны/с, затраты по пользователям, задержка p95), трассы (поиск + каскадная диаграмма), оценивание (тренд достоверности, токсичность), дрейф (PSI во времени), оповещения.

8. **Цепочка оповещений.** Экспортёр Prometheus считывает агрегированные оценки и перцентили задержки; Alertmanager направляет предупреждения в Slack, а критические нарушения — в PagerDuty.

9. **Проверка регрессии.** Внедрите баг: оцениваемый чат-бот начинает утекать поддельные номера SSN в 1% случаев. Измерьте MTTR: от развёртывания бага до оповещения в Slack.

## Поставка

`outputs/skill-llm-observability.md` — это результат поставки. При наличии LLM-приложения дашборд принимает его трассы, прогоняет оценивание, оповещает о дрейфе и показывает в Next.js разбивку затрат по пользователям.

5. Постройте политику сэмплирования по хвосту, которая сохраняет 100% трасс с токсичностью > 0.5 плюс 10% стратифицированной выборки остальных. Измерьте внесённое смещение сэмплирования.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| GenAI semconv | «Атрибуты OTel для LLM» | Спецификация OpenTelemetry 2025 года для атрибутов LLM-спанов (система, модель, токены) |
| Сэмплирование по хвосту (tail sampling) | «Сэмплирование постфактум» | Коллектор решает, сохранить или отбросить трассу после её завершения (может заглянуть в ошибки) |
| PSI | «Индекс стабильности популяции» | Метрика дрейфа, сравнивающая два распределения; > 0.2 обычно сигнализирует о значимом дрейфе |
| LLM-судья (LLM-judge) | «Оценивание моделью» | LLM, оценивающая вывод другой LLM по рубрике (достоверность, токсичность, PII) |
| Политика сэмплирования по хвосту (tail-sampling policy) | «Правило сохранения» | Правило, определяющее, какие трассы сохранять, а какие отбрасывать; ошибочные + доля выборки |
| Спан оценивания (eval span) | «Связанная трасса оценивания» | Дочерний спан, несущий оценку, связанную со спаном исходного вызова LLM |
| Стоимость на пользователя (cost per user) | «Юнит-экономика» | Затраты в долларах, атрибутированные user_id за окно времени; ключевая продуктовая метрика |
