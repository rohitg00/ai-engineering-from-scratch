# Капстоун 14 — сервер инференса со спекулятивным декодированием

> Спекулятивное декодирование — дешёвая черновая модель предлагает токены, а целевая проверяет их за один проход — теперь стало оптимизацией, готовой к промышленной эксплуатации, а не исследовательским трюком. EAGLE-3 в vLLM 0.7 обеспечивает пропускную способность 2.5-3x на реальном трафике. P-EAGLE (AWS 2026) продвинул параллельную спекуляцию ещё дальше. SpecForge от SGLang обучала черновые головы в промышленном масштабе. Хаб Speculators от Red Hat опубликовал согласованные черновые модели для распространённых открытых моделей. TensorRT-LLM сделал спекулятивное декодирование полноценной возможностью на NVIDIA. Продакшен-стек обслуживания 2026 года — это vLLM или SGLang с черновыми моделями семейства EAGLE, квантованием FP8 или INT4 и HPA по времени ожидания в очереди. Задача этого капстоуна — обслуживать две открытые модели с пропускной способностью 2.5x+ от базового уровня и полным отчётом по хвостовой задержке.

**Тип:** Капстоун
**Языки:** Python (обслуживание), C++ / CUDA (анализ ядер), YAML (конфигурации)
**Предварительные требования:** Фаза 3 (глубокое обучение), фаза 7 (трансформеры), фаза 10 (LLM с нуля), фаза 17 (инфраструктура)
**Задействованные фазы:** P3 · P7 · P10 · P17
**Время:** 30 часов

## Проблема

Спекулятивное декодирование (speculative decoding) стало типовой практикой в 2026 году. Черновые головы EAGLE-3 обучаются на скрытых состояниях целевой модели и предсказывают N токенов вперёд; целевая модель проверяет их за один проход. Доля принятия (acceptance rate) в 60-80% превращается в 2-3-кратный прирост сквозной пропускной способности. vLLM 0.7 интегрирует это нативно. SGLang + SpecForge даёт вам конвейер обучения. Speculators от Red Hat публикует согласованные черновые модели для Llama 3.3 70B, Qwen3-Coder-30B MoE, GPT-OSS-120B.

Мастерство здесь — в эксплуатации обслуживания, а не в самой модели. Доля принятия дрейфует вместе с распределением трафика (ShareGPT против кода против доменных данных). Хвостовая задержка при отклонении хуже, чем без спекуляции — вы обязаны отчитываться по p99 при нескольких размерах пакета, а не только по установившейся пропускной способности в токенах в секунду. Стоимость на 1M токенов в сравнении с API Anthropic / OpenAI — это рычаг доверия.

## Концепция

У спекулятивного декодирования два слоя. **Черновая** модель (draft model; голова EAGLE-3, ngram или модель меньшего размера, согласованная с целевой) предлагает k кандидатных токенов на шаг. **Целевая** модель (target model) проверяет все k за один проход; принятый префикс заменяет жадный путь. Доля принятия зависит от согласованности черновой и целевой моделей и от распределения входных данных.

EAGLE-3 превосходит черновые модели на ngram на большей части трафика. P-EAGLE запускает параллельную спекуляцию для более глубоких деревьев черновых токенов. Компромисс: задержка P99 при отклонении выше, потому что проверочный проход крупнее. Конфигурация обслуживания должна отчитываться по задержке, сгруппированной по размерам пакета, чтобы выявлять это.

Развёртывание — в Kubernetes. vLLM 0.7 запускает одну реплику на GPU или на шард тензорного параллелизма. HPA автомасштабируется по времени ожидания в очереди, а не по CPU. Квантование FP8 (Marlin) и INT4 (AWQ) удерживает объём памяти GPU в пределах H100 / H200. Сквозной отчёт включает пропускную способность, долю принятия, p50/p99 при размере пакета 1/8/32 и $/1M токенов.

## Архитектура

```
request ingress
    |
    v
vLLM server (0.7) or SGLang (0.4)
    |
    +-- draft: EAGLE-3 heads | P-EAGLE parallel | ngram fallback
    +-- target: Llama 3.3 70B | Qwen3-Coder-30B | GPT-OSS-120B
    |     quantized FP8-Marlin or INT4-AWQ
    |
    v
verify pass: batch k draft tokens through target
    |
    v (accept prefix; resample for rejected suffix)
    v
token stream back to client
    |
    v
Prometheus metrics: throughput, acceptance rate, queue wait, latency p50/p99
    |
    v
HPA on queue-wait metric
```

## Стек

- Обслуживание: vLLM 0.7 или SGLang 0.4
- Методы спекуляции: черновые головы EAGLE-3, параллельная спекуляция P-EAGLE, резервный вариант на ngram
- Обучение черновых моделей: SpecForge (SGLang) или Red Hat Speculators
- Целевые модели: Llama 3.3 70B, Qwen3-Coder-30B MoE, GPT-OSS-120B
- Квантование: FP8 (Marlin), INT4 AWQ
- Развёртывание: Kubernetes + плагин устройств NVIDIA; HPA по метрике времени ожидания в очереди
- Оценивание: ShareGPT, MT-Bench-v2, GSM8K, HumanEval для измерения доли принятия по разным доменам
- Референс: спекулятивное декодирование TensorRT-LLM как базовый уровень от вендора

## Реализация

1. **Подготовка целевой модели.** Выберите Llama 3.3 70B. Квантуйте в FP8 через Marlin. Разверните под vLLM 0.7 на 1xH100 (или с тензорным параллелизмом 2x).

2. **Источник черновой модели.** Возьмите согласованную черновую голову EAGLE-3 из Red Hat Speculators (или обучите её через SpecForge). Загрузите в конфигурацию спекулятивного декодирования vLLM.

3. **Базовые показатели.** До включения спекуляции: токены/с при размере пакета 1/8/32, задержка p50/p99, утилизация GPU. Опубликуйте.

4. **Включите EAGLE-3.** Переключите конфигурацию; перезапустите тот же бенчмарк. Отчитайтесь об ускорении, доле принятия, изменении хвостовой задержки p99.

5. **P-EAGLE.** Включите параллельную спекуляцию; измерьте более глубокое дерево черновых токенов в сравнении с последовательным EAGLE-3. Отчитайтесь о точке перегиба, где P-EAGLE помогает, а где вредит.

6. **Доменный трафик.** Пропустите через один и тот же сервер трафик ShareGPT, HumanEval и доменно-специфичный трафик. Измерьте долю принятия для каждого распределения. Определите, когда черновая модель начинает дрейфовать.

7. **Вторая целевая модель.** Прогоните тот же конвейер на Qwen3-Coder-30B MoE. Черновая модель здесь сложнее (шум маршрутизации MoE). Отчитайтесь.

8. **HPA в K8s.** Разверните под K8s с HPA, отслеживающим `queue_wait_ms`. Продемонстрируйте масштабирование при утроении нагрузки.

9. **Сравнение стоимости.** Посчитайте $/1M токенов в сравнении с Anthropic Claude Sonnet 4.7 и OpenAI GPT-5.4 на том же наборе для оценивания. Опубликуйте.

## Упражнения

1. Измерьте деградацию доли принятия, когда черновая модель отстаёт от целевой на одну версию (например, дрейф Llama 3.3 -> 3.4). Постройте оповещение для мониторинга.

2. Реализуйте резервный переход на ngram: если доля принятия EAGLE-3 падает ниже порога, переключайтесь на черновые модели на ngram. Отчитайтесь об улучшении надёжности.

3. Проведите контролируемый эксперимент с MoE: одна и та же Qwen3-Coder-30B с внесённым шумом маршрутизации и без него. Измерьте чувствительность доли принятия черновой модели.

4. Расширьте до H200 (141 ГБ). Отчитайтесь о выигранном запасе по размеру модели на реплику и о том, можете ли вы обслуживать неквантованную Llama 3.3 70B.

5. Проведите бенчмарк спекулятивного декодирования TensorRT-LLM на том же оборудовании H100. Отчитайтесь, где оно выигрывает в сравнении с vLLM.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| Черновая модель | «Спекулятор» | Маленькая модель, которая предлагает N токенов для проверки целевой моделью |
| EAGLE-3 | «архитектура черновой модели 2026 года» | Черновая голова, обученная на скрытых состояниях целевой модели; доля принятия ~75% |
| P-EAGLE | «параллельная спекуляция» | Дерево черновых ветвей, проверяемое за один проход целевой модели |
| Доля принятия | «доля попаданий» | Доля черновых токенов, принятых без повторного сэмплирования |
| Квантование | «FP8 / INT4» | Веса пониженной точности, чтобы уместить больше модели в памяти GPU |
| Время ожидания в очереди | «метрика HPA» | Время, которое запрос проводит в очереди ожидания до начала инференса |
| Хаб Speculators | «согласованные черновые модели» | Хаб Red Hat Neural Magic с черновыми моделями EAGLE для распространённых открытых моделей |
