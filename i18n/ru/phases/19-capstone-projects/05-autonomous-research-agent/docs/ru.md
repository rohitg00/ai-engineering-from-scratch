# Капстоун 05 — Автономный исследовательский агент (класс AI-Scientist)

> AI-Scientist-v2 от Sakana публиковал полноценные статьи. Agent Laboratory проводила эксперименты. Allen AI делилась трассировками. Форма 2026 года — это поиск по дереву в цикле «план-выполнение-проверка» над экспериментами, бюджетируемая стоимость, выполнение кода в песочнице, модуль подготовки текста в LaTeX с визуальной обратной связью и автоматизированный ансамбль рецензентов в стиле NeurIPS. Задача капстоуна — построить такую систему, прогнать её от начала до конца в пределах $30 на статью и пройти проверку красной командой на выход за пределы песочницы, которую задокументировала Sakana.

**Тип:** Капстоун
**Языки:** Python (код агента и песочницы), LaTeX (выходной документ)
**Предварительные требования:** Этап 2 (машинное обучение), этап 3 (глубокое обучение), этап 7 (трансформеры), этап 10 (большие языковые модели с нуля), этап 14 (агенты), этап 15 (автономные системы), этап 16 (мультиагентные системы), этап 18 (безопасность)
**Задействованные этапы:** P0 · P2 · P3 · P7 · P10 · P14 · P15 · P16 · P18
**Время:** 40 часов

## Проблема

Автономные исследовательские агенты перешагнули порог в 2026 году. AI-Scientist-v2 от Sakana AI был опубликован в Nature со сгенерированными статьями, которые прошли рецензирование на воркшопе. ShinkaEvolve (ICLR 2026) расширила эту линию до эволюционирующих гипотез. Agent Laboratory от AMD выпустила воспроизводимые трассировки. Эти агенты — не магия: это цикл «план-выполнение-проверка», работающий над деревом кандидатных экспериментов, с ограничениями по стоимости, песочницами с фиксированными начальными значениями генераторов и автоматизированным рецензированием. Мастерство — в самом цикле, в бюджете и в подходе к безопасности.

Вы осваиваете этот цикл, реализуя его для исходной идеи в узкой предметной области (например, абляции разреженности внимания в трансформере на 100M параметров). Ценность не в том, чтобы открыть что-то новое с первого прогона. Ценность — в инфраструктуре: поиске по дереву, песочнице для экспериментов, цикле «автор-рецензент», отчёте красной команды. Команда Sakana задокументировала сбои с выходом за пределы песочницы; ваш агент должен пройти такую же проверку красной командой.

## Концепция

Агент выполняет поиск по дереву с раскрытием в первую очередь наиболее перспективного узла (best-first search). Узлы — это спецификации экспериментов: (гипотеза, конфигурация, код, ожидаемый результат). Шаг расширения предлагает дочерние узлы с небольшими правками (сменить оптимизатор, изменить размер пакета, исключить компонент абляцией). Каждый дочерний узел выполняется в свежей песочнице с жёстким ограничением ресурсов. Результаты возвращаются в функцию оценивания, которая ранжирует узлы по (новизна × качество × оставшийся бюджет). Дерево растёт, пока бюджет не исчерпан, после чего лучшая ветвь оформляется в статью.

Модуль подготовки текста мультимодален. Он генерирует черновик в LaTeX, компилирует его, рендерит иллюстрации и передаёт отрендеренный PDF обратно в режим анализа изображений Claude Opus 4.7 для критики вёрстки, читаемости иллюстраций и соответствия утверждений доказательствам. Ансамбль рецензентов из пяти LLM-судей выставляет оценки в стиле NeurIPS (новизна, строгость, ясность, воспроизводимость, влияние); если среднее значение падает ниже порога, статья возвращается автору вместе с критикой.

Безопасность здесь несущая конструкция. Каждый эксперимент выполняется в песочнице E2B или Daytona без исходящего сетевого трафика, с ограничением фактического времени выполнения и фиксированными лимитами ресурсов. Шаг генерации кода агентом проходит через слой политик, который блокирует системные вызовы, позволяющие выйти за пределы песочницы. Отчёт красной команды воспроизводит поверхность атаки, задокументированную Sakana (форк-бомбы, выходы за пределы файловой системы, написанные LLM сетевые вызовы).

## Архитектура

```
seed idea + domain
      |
      v
  literature search (Semantic Scholar + OpenAlex + FAISS cache)
      |
      v
  LangGraph plan-execute-verify tree
      |
      v
  +--- expand node ----+      per-node sandbox
  |                    |      (E2B / Daytona)
  v                    v      resource caps
  child_1           child_k   no network egress
  |                    |      deterministic seeds
  v                    v
  run experiment       run experiment
  |                    |
  v                    v
  score nodes by (novelty, quality, budget)
      |
      v
  best branch -> LaTeX writer
      |
      v
  compile + vision critique (Opus 4.7 vision)
      |
      v
  reviewer ensemble (5 LLM judges, NeurIPS rubric)
      |
      v
  paper.pdf + review.md + trace.json
```

## Стек

- Оркестрация: LangGraph с контрольными точками и этапами подтверждения человеком
- Поиск по дереву: собственная реализация поиска с раскрытием в первую очередь наиболее перспективного узла по узлам экспериментов (в стиле AB-MCTS из Sakana v2)
- Песочница: E2B на каждый эксперимент, резервный вариант Docker-in-Docker; ограничения ресурсов через cgroups
- Литература: Semantic Scholar Graph API + OpenAlex + локальный FAISS-кеш аннотаций
- Подготовка текста: шаблон LaTeX + Claude Opus 4.7 (режим анализа изображений) для критики иллюстраций и вёрстки
- Рецензент: ансамбль из 5 судей (Opus 4.7, GPT-5.4, Gemini 3 Pro, DeepSeek R1, Qwen3-Max) со взвешенной агрегацией
- Фреймворк для экспериментов: PyTorch 2.5 для физических экспериментов, W&B для логирования
- Наблюдаемость: Langfuse для трассировок агента, жёсткий бюджет $30 на статью

## Реализация

1. **Исходная идея и определение области.** Возьмите исходную идею (например, «исследовать паттерны разреженности в картах внимания трансформеров до 1B параметров»). Определите пространство поиска: модели, наборы данных, вычислительный бюджет.

2. **Проход по литературе.** Запросите у Semantic Scholar + OpenAlex 50 наиболее цитируемых релевантных статей; закешируйте аннотации локально; сгенерируйте дайджест области на 1 страницу.

3. **Каркас дерева.** Инициализируйте корень исходной гипотезой. Реализуйте `expand(node) -> children` с предложениями небольших правок (одно изменение конфигурации на дочерний узел). Реализуйте `score(node)` как взвешенное произведение новизна × качество × бюджет.

4. **Обёртка песочницы.** Каждый эксперимент выполняется командой `docker run --network=none --memory=8g --cpus=2 --pids-limit=256 --read-only` (или эквивалентной политикой E2B). Начальные значения генераторов записываются в песочницу; результаты монтируются обратно только для чтения.

5. **Цикл «план-выполнение-проверка».** `plan` предлагает дочерние узлы. `execute` запускает песочницу, собирает логи и метрики. `verify` выполняет модульные проверки метрик (снизились ли потери? изолировала ли абляция эффект?). Для узлов со сбоем в дереве сохраняется причина сбоя.

6. **Подготовка текста.** После исчерпания бюджета выберите лучшую ветвь. Отрендерите иллюстрации с помощью matplotlib. Сгенерируйте черновик в LaTeX через Claude Opus 4.7 с трассировкой ветви в контексте. Скомпилируйте. Передайте скомпилированный PDF обратно в режим анализа изображений Opus 4.7 для критики. Повторяйте цикл.

7. **Ансамбль рецензентов.** Пять судей оценивают черновик по (новизна, строгость, ясность, воспроизводимость, влияние) с рубриками в стиле NeurIPS. Если среднее < 4.0/5, верните черновик автору с критикой. Жёсткая остановка после 3 переписываний.

8. **Проверка красной командой.** Создайте или интегрируйте набор состязательных задач, нацеленных на песочницу: форк-бомбы, попытки эксфильтрации данных по сети, выходы за пределы файловой системы, сгенерированные LLM метасимволы командной оболочки. Убедитесь, что все они блокируются. Оформите результаты.

9. **Воспроизводимость.** Каждая статья поставляется с JSON-трассировкой поиска по дереву, начальными значениями генераторов, ссылками на прогоны W&B, конфигурациями песочницы и README, воспроизводящим всё от начала до конца.

## Поставка

Итоговый навык — `outputs/skill-ai-scientist.md`. При наличии исходной идеи + предметной области + бюджета $30 он прогоняет полный конвейер и выдаёт статью, готовую к рецензированию, вместе с пакетом воспроизводимости.

| Вес | Критерий | Как измеряется |
|:-:|---|---|
| 25 | Качество статьи | Слепое рецензирование по рубрике в сравнении с опубликованными статьями воркшопов |
| 20 | Экспериментальная строгость | Базовые линии, начальные значения генераторов, абляции; каждое утверждение подкреплено ячейкой в таблице результатов |
| 20 | Дисциплина по стоимости и вычислениям | Соблюдается потолок $30/статью, отслеживается через Langfuse |
| 20 | Безопасность | Проверка песочницы красной командой пройдена; сетевая политика и аварийный выключатель проверены |
| 15 | Воспроизводимость | Повторный запуск одной командой с идентичными начальными значениями генераторов воспроизводит статью |
| **100** | | |

## Упражнения

1. Прогоните конвейер для трёх разных исходных идей в одной предметной области. Сравните, какие части поиска по дереву пересекаются. Определите дублирующиеся впустую потраченные вычисления.

2. Добавьте этап подтверждения человеком перед выполнением эксперимента для узлов с оценочной стоимостью выше $5. Измерьте, насколько снижается общая стоимость.

3. Замените ансамбль рецензентов на одного судью. Измерьте долю ложных принятий на отложенном наборе заведомо плохих статей.

4. Добавьте тест красной команды на эксфильтрацию данных по сети: агент пишет код, который пытается выполнить `curl` на внешний адрес. Убедитесь, что политика `--network=none` блокирует это. Запишите попытку в журнал.

5. Сравните ваш поиск по дереву с плоской случайной базовой линией (тот же бюджет, без стратегии расширения). Сообщите прирост по новизна × качество.
