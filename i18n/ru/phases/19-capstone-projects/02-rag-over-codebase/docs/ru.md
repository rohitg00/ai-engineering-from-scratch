# Капстоун 02 — RAG над кодовой базой (семантический поиск по нескольким репозиториям)

> Каждая серьёзная инженерная организация в 2026 году использует внутренний поиск по коду, который понимает смысл, а не просто строки. Sourcegraph Amp, ответы по кодовой базе от Cursor, корпоративный граф Augment, repomap от Aider, внутренний MCP Pinterest — все они устроены одинаково. Загрузить множество репозиториев, распарсить с помощью tree-sitter, встроить фрагменты уровня функций и классов, выполнить гибридный поиск, реранжировать, ответить с цитатами. В этом капстоуне вам предстоит построить систему, которая обрабатывает 2 млн строк кода в 10 репозиториях и выдерживает инкрементальную переиндексацию при каждом git push.

## Проблема

К 2026 году каждый передовой агент для кодирования поставляется со слоем поиска по кодовой базе, потому что одни лишь контекстные окна не решают вопросы, затрагивающие несколько репозиториев. Контекст Claude на 1M токенов помогает, но не устраняет потребность в ранжированном поиске. Наивный косинусный поиск по сырым фрагментам портит результаты на сгенерированном коде, на дублировании в монорепозиториях и на длинном хвосте редко импортируемых символов. Промышленное решение — гибридный поиск (плотный + BM25) по фрагментам, учитывающим AST, с реранкером, опирающимся на граф ссылок между символами.

Вы осваиваете это, индексируя настоящий флот репозиториев — а не один учебный репозиторий — и измеряя MRR@10, достоверность цитирования и инкрементальную актуальность. Отказы носят инфраструктурный характер: монорепозиторий на 100 тыс. файлов, push, затрагивающий половину файлов, запрос, который требует пройти через четыре репозитория, чтобы ответить правильно.

## Концепция

Конвейер загрузки, учитывающий AST, парсит каждый файл с помощью tree-sitter, извлекает узлы функций и классов и разбивает на фрагменты по границам узлов, а не по фиксированным окнам токенов. Каждый фрагмент получает три представления: плотный эмбеддинг (Voyage-code-3 или nomic-embed-code), разреженные термы BM25 и короткое резюме на естественном языке. Резюме добавляет третью извлекаемую модальность — пользователи спрашивают «как авторизуется X», и резюме упоминает «authz», даже если в коде есть только `check_permission`.

Поиск гибридный. Запрос одновременно запускает плотный поиск и поиск по BM25, объединяет топ-k и передаёт объединение кросс-энкодерному реранкеру (Cohere rerank-3 или bge-reranker-v2-gemma-2b). Реранжированный список поступает в синтезатор с длинным контекстом (Claude Sonnet 4.7 с кешированием промптов или самостоятельно развёрнутая Llama 3.3 70B) с инструкцией цитировать каждое утверждение по файлу и диапазону строк. Ответы без цитат отклоняются постфильтром.

Инкрементальная актуальность — это инфраструктурная задача. Git push запускает diff: какие файлы изменились, какие символы изменились. Переэмбеддингу подвергаются только затронутые фрагменты. Затронутые межфайловые рёбра символов (импорты, вызовы методов) пересчитываются. Индекс остаётся согласованным без переобработки 2 млн строк при каждом коммите.

## Архитектура

```
git push --> webhook --> ingest worker (LlamaIndex Workflow)
                           |
                           v
             tree-sitter parse + AST chunk
                           |
            +--------------+----------------+
            v              v                v
          dense        BM25 index       summary (LLM)
        (Voyage / bge)  (Tantivy)        (Haiku 4.5)
            |              |                |
            +------> Qdrant / pgvector <----+
                            |
                            v
                      symbol graph (Neo4j / kuzu)
                            |
  query --> LangGraph agent (retrieve -> rerank -> synth)
                            |
                            v
                 Claude Sonnet 4.7 1M context
                            |
                            v
                 answer + file:line citations
```

## Стек

- Парсинг: tree-sitter с 17 грамматиками языков (Python, TS, Rust, Go, Java, C++ и др.)
- Плотные эмбеддинги: Voyage-code-3 (хостинг) или nomic-embed-code-v1.5 (self-host), резервный вариант bge-code-v1
- Разреженный индекс: Tantivy (Rust) с BM25F, с взвешиванием полей по имени символа и телу
- Векторная БД: Qdrant 1.12 с гибридным поиском либо pgvector + pgvectorscale для команд с объёмом менее 50 млн векторов
- Модель резюмирования фрагментов: Claude Haiku 4.5 или Gemini 2.5 Flash, с кешированием промптов
- Реранкер: Cohere rerank-3 или самостоятельно развёрнутый bge-reranker-v2-gemma-2b
- Оркестрация: LlamaIndex Workflows для загрузки, LangGraph для агента запросов
- Синтезатор: Claude Sonnet 4.7 (контекст 1M) с кешированием промптов
- Граф символов: Neo4j (управляемый) или kuzu (встраиваемый) для рёбер импортов и вызовов
- Наблюдаемость: спаны Langfuse на каждый этап поиска и синтеза

## Реализация

1. **Обходчик загрузки.** Обходите git-историю при каждом push hook. Собирайте изменённые файлы. Для каждого файла парсите с помощью tree-sitter, извлекайте узлы функций и классов с их полным диапазоном исходного текста. Формируйте записи фрагментов `{repo, path, start_line, end_line, symbol, body}`.

2. **Резюмирование фрагментов.** Группируйте фрагменты в вызовы Haiku 4.5 с кешированием промптов на системной преамбуле. Промпт: «Summarize this function in one sentence, naming its public contract and side effects». Сохраняйте резюме вместе с фрагментом.

3. **Пул эмбеддингов.** Две параллельные очереди: плотная (Voyage-code-3, пакет 128) и резюмирующая (та же модель, но на строке резюме). Записывайте векторы в Qdrant с полезной нагрузкой `{repo, path, start_line, end_line, symbol, kind}`.

4. **Индекс BM25.** Взвешенный по полям индекс Tantivy: вес имени символа 4, вес тела символа 1, вес резюме 2. Позволяет обрабатывать запросы «найти функцию с именем X» наряду с «найти функцию, которая делает X».

5. **Граф символов.** Для каждого фрагмента фиксируйте рёбра: импорты (этот файл использует символ Y из репозитория Z), вызовы (эта функция вызывает метод M класса C), наследование. Храните в kuzu. Используется во время запроса для расширения поиска через границы репозиториев.

6. **Агент запросов.** LangGraph с тремя узлами. `retrieve` запускает плотный поиск и BM25 параллельно, дедуплицирует по (repo, path, symbol). `rerank` запускает кросс-энкодер на топ-50 и оставляет топ-10. `synth` вызывает Claude Sonnet 4.7 с реранжированными фрагментами в контексте, кеширует системный промпт, требует цитаты file:line.

7. **Обеспечение цитирования.** Разбирайте вывод модели; любое утверждение без якоря `(repo/path:start-end)` помечается для повторного запроса или отбрасывается. Пользователю возвращается ответ только с цитатами.

8. **Инкрементальная переиндексация.** При каждом webhook вычисляйте diff на уровне символов. Переэмбеддингу подвергаются только фрагменты, чей текст изменился. Пересчитывайте рёбра символов для фрагментов, чьи импорты изменились. Измеряйте: push с 50 файлами переиндексируется менее чем за 60 секунд для флота на 2 млн строк кода.

9. **Оценивание.** Разметьте 100 межрепозиторных вопросов с эталонными ответами file:line. Измеряйте MRR@10, nDCG@10, достоверность цитирования (доля утверждений с проверяемыми якорями) и задержку p50/p99.

## Упражнения

1. Замените Voyage-code-3 на самостоятельно развёрнутый nomic-embed-code. Измерьте разницу в MRR@10. Сообщите, закрывается ли разрыв при включённом реранжировании.

2. Внедрите в корпус 20% сгенерированного кода (шаблонный код, произведённый LLM) и переоцените результаты. Понаблюдайте за отравлением поиска. Добавьте флаг «generated» в полезную нагрузку и понизьте вес таких попаданий.

3. Сравните гибридный поиск Qdrant с pgvector + pgvectorscale на объёме вашего корпуса. Сообщите p99 при размере пакета 1.

4. Добавьте проверку дрейфа на основе сэмплирования: еженедельно перезапускайте оценку на 100 вопросах. Оповещайте при падении MRR@10 более чем на 5%.

5. Расширьте систему до межъязыкового разрешения символов: функция на Python, вызывающая сервис на Go через gRPC. Используйте граф символов, чтобы связать их.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| AST-aware chunking (разбиение с учётом AST) | «Разбиение на уровне функций» | Разрезание кода по границам узлов tree-sitter, а не по фиксированным окнам токенов |
| Hybrid search (гибридный поиск) | «Плотный + разреженный» | Параллельный запуск BM25 и векторного поиска, объединение топ-k, реранжирование |
| Cross-encoder rerank (кросс-энкодерное реранжирование) | «Ранжирование второго этапа» | Модель, которая оценивает каждую пару (запрос, кандидат) совместно, точнее косинусного сходства |
| Prompt caching (кеширование промптов) | «Закешированный системный промпт» | Функция Claude / OpenAI 2026 года, дающая скидку до 90% на повторяющиеся токены префикса |
| Symbol graph (граф символов) | «Граф кода» | Рёбра импортов, вызовов, наследования между файлами и репозиториями |
| Citation faithfulness (достоверность цитирования) | «Доля обоснованных ответов» | Доля утверждений, которые пользователь может проверить, перейдя по якорю и прочитав указанный фрагмент |
| Incremental re-index (инкрементальная переиндексация) | «Время от push до поиска» | Время от git push до момента, когда изменённые символы становятся доступны для запроса |
