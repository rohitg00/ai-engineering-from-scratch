# Капстоун 09 — агент миграции кода (обновление языка / рантайма на уровне репозитория)

> MigrationBench от Amazon (миграция с Java 8 на 17) и мигратор Google App Engine с Py2 на Py3 задают планку 2026 года. OpenRewrite от Moderne выполняет детерминированные переписывания AST в промышленном масштабе. Grit решает ту же задачу с помощью DSL в стиле codemod. Продуктовый паттерн объединяет оба подхода: детерминированный субстрат для безопасных переписываний плюс агентный слой для неоднозначных случаев, песочница для сборок по каждой ветке и тестовый харнесс, который переключается на «зелёный» статус перед открытием PR. Задача капстоуна — мигрировать 50 реальных репозиториев и опубликовать долю успешных прохождений с таксономией отказов.

**Тип:** Capstone**Языки:** Python (agent), Java / Python (targets), TypeScript (dashboard)**Предварительные требования:** Фаза 5 (NLP), Фаза 7 (transformers), Фаза 11 (LLM engineering), Фаза 13 (tools), Фаза 14 (agents), Фаза 15 (autonomous), Фаза 17 (infrastructure)**Задействованные фазы:** P5 · P7 · P11 · P13 · P14 · P15 · P17

## Проблема

Крупномасштабная миграция кода — одно из самых чистых промышленных применений агентов для написания кода образца 2026 года. Эталонный результат очевиден (проходит ли набор тестов после миграции?), выгода реальна (миграция флота на Java 8 — это проект масштаба целой команды), а бенчмарки публичны (подмножество из 50 репозиториев MigrationBench). OpenRewrite от Moderne берёт на себя детерминированную часть. Агентный слой обрабатывает всё, с чем не справляются рецепты OpenRewrite: неоднозначные переписывания, дрейф сборочной системы, синтаксис из длинного хвоста, поломки транзитивных зависимостей.

Вы построите агента, который принимает репозиторий на Java 8 (или репозиторий на Python 2) и выдаёт мигрированную ветку с зелёным CI. Вы измерите долю успешных прохождений, сохранность покрытия тестами, стоимость на репозиторий и построите таксономию отказов. Сравнение бок о бок с чисто детерминированным базовым решением покажет, где на самом деле кроется ценность агента.

## Концепция

У конвейера два слоя. **Детерминированный субстрат** (OpenRewrite для Java, libcst для Python) безопасно выполняет основную массу механических переписываний: импорты, сигнатуры методов, правки null-safety, try-with-resources, замены устаревших API. Он быстрый и производит diff, пригодный для аудита. **Агентный слой** (OpenAI Agents SDK или LangGraph поверх Claude Opus 4.7 и GPT-5.4-Codex) обрабатывает случаи, с которыми не справляются рецепты: обновления файлов сборки (Maven/Gradle/pyproject), конфликты транзитивных зависимостей, нестабильные тесты, пользовательские аннотации.

Каждый репозиторий получает песочницу Daytona с предустановленным целевым рантаймом. Агент работает итеративно: запускает сборку, классифицирует отказы, применяет исправление, перезапускает. Жёсткие лимиты: 30 минут на репозиторий, $8 на репозиторий, 20 ходов агента. Если все тесты проходят и дельта покрытия не отрицательная, ветка открывает PR. Если нет, репозиторий заносится в класс отказа с доказательствами.

Таксономия отказов — это и есть результат поставки. На 50 репозиториях: что ломалось? Транзитивные зависимости? Пользовательские аннотации? Версия инструмента сборки? Нестабильные тесты, не связанные с миграцией? Каждый класс получает счётчик и показательный diff. Будущие авторы рецептов смогут нацелиться на первые три.

## Архитектура

```
target repo
      |
      v
OpenRewrite / libcst deterministic recipes
   (safe, fast, auditable, ~70-80% of fixes)
      |
      v
Daytona sandbox per branch
      |
      v
agent loop (Claude Opus 4.7 / GPT-5.4-Codex):
   - run build -> capture failures
   - classify failures (build, test, lint)
   - apply fix (patch or retry recipe)
   - rerun
   - budget: 30 min, $8, 20 turns
      |
      v
test + coverage delta gate
      |
      v (passed)
open PR
      |
      v (failed)
file under failure class + attach repro
```

## Стек

- Детерминированный субстрат: OpenRewrite (Java) или libcst (Python)
- Агент: OpenAI Agents SDK или LangGraph поверх Claude Opus 4.7 + GPT-5.4-Codex
- Песочница: Daytona devcontainer на каждую ветку, предустановленный целевой рантайм (Java 17 / Python 3.12)
- Системы сборки: Maven, Gradle, uv (Python)
- Бенчмарки: подмножество из 50 репозиториев Amazon MigrationBench (Java 8 в 17), репозитории Google App Engine Py2-в-Py3
- Тестовый харнесс: параллельный раннер, покрытие через Jacoco (Java) или coverage.py (Python)
- Наблюдаемость: Langfuse + пакет трассировки на репозиторий со всеми фрагментами diff
- Дашборд: дашборд таксономии отказов со счётчиками по классам и показательными diff

## Реализация

1. **Проход рецептов.** Сначала запустите рецепты OpenRewrite (Java) или libcst (Python). Отловите 70-80% миграций, которые носят механический характер. Закоммитьте как коммит «recipe».

2. **Пробная сборка.** Песочница Daytona: установите целевой рантайм, запустите сборку. Если зелёная — переходите сразу к тестам. Если красная — передавайте управление агенту.

3. **Цикл агента.** LangGraph с инструментами: `run_build`, `read_file`, `edit_file`, `run_test`, `git_diff`. Агент классифицирует отказ (зависимость, синтаксис, тест, инструмент сборки) и применяет точечное исправление. Перезапуск.

4. **Потолки бюджета.** 30 минут (wall-clock) на репозиторий, $8 по стоимости, 20 ходов агента. Любое превышение останавливает работу и заносит репозиторий в класс «budget_exhausted» с текущим diff.

5. **Шлюз тестов и покрытия.** После того как сборка становится зелёной, запустите набор тестов. Сравните покрытие с базовым репозиторием. Если покрытие упало более чем на 2%, занесите в класс «coverage_regression».

6. **Открытие PR.** При успехе запушьте ветку, откройте PR с diff и сводкой о том, какие рецепты применились и какие коммиты создал агент.

7. **Таксономия отказов.** Для каждого неуспешного репозитория присвойте класс: `dep_upgrade_required`, `build_tool_drift`, `custom_annotation`, `test_flake`, `syntax_edge_case`, `budget_exhausted`. Постройте дашборд.

8. **Прогон на 50 репозиториях.** Выполните на подмножестве MigrationBench. Сообщите долю успешных прохождений по классам, стоимость на репозиторий, сохранность покрытия и сравнение с чисто детерминированным базовым решением.

## Поставка

`outputs/skill-migration-agent.md` — это результат поставки. Получив репозиторий, он выполняет детерминированные рецепты, а затем цикл агента, чтобы выдать зелёную мигрированную ветку, либо заносит репозиторий в класс таксономии.

## Упражнения

1. Запустите конвейер миграции только с OpenRewrite (без агента). Сравните долю успешных прохождений с полным конвейером. Определите случаи, где именно агент делает разницу.

2. Реализуйте проверку «lint-clean»: после миграции запустите линтер стиля (spotless для Java, ruff для Python). Проваливайте PR, если появляются новые ошибки линтера. Измерьте долю случаев, когда покрытие сохранено, но стиль деградировал.

3. Добавьте оптимизатор «minimal-diff»: после того как ветка агента проходит тесты, вторым проходом обрежьте лишние изменения. Сообщите сокращение размера diff.

4. Расширьте систему до третьей миграции: с Node 18 на Node 22. Переиспользуйте обёртку песочницы; замените слой рецептов на собственный codemod.

5. Измерьте время до первой зелёной сборки (TTFGB) как метрику UX. Цель: p50 меньше 10 минут.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| Deterministic substrate (детерминированный субстрат) | «Движок рецептов» | OpenRewrite / libcst: декларативные переписывания AST с гарантиями безопасности |
| Codemod (кодмод) | «Программа, изменяющая код» | Правило переписывания, которое механически меняет исходный код |
| Build drift (дрейф сборки) | «Рассинхронизация версий инструментов» | Едва заметные изменения поведения Maven / Gradle / uv между мажорными версиями |
| Failure class (класс отказа) | «Категория из таксономии» | Промаркированная причина, по которой репозиторий не мигрировал: зависимость, синтаксис, тест, инструмент сборки, бюджет |
| Coverage delta (дельта покрытия) | «Сохранность покрытия» | Изменение процента покрытия тестами от базовой к мигрированной ветке |
| Agent turn (ход агента) | «Раунд вызова инструмента» | Один цикл «план → действие → наблюдение» в цикле агента |
| Budget exhaustion (исчерпание бюджета) | «Упёрлись в потолок» | Репозиторий исчерпал лимит 30 мин / $8 / 20 ходов, не пройдя миграцию |
