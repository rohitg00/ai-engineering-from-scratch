# Патчи визуального энкодера

> Визуальной модели, которая читает пиксели, нужен токенизатор для пикселей. Патч-эмбеддинг и есть этот токенизатор. Разрежьте изображение на сетку квадратов, разверните каждый квадрат в вектор, спроецируйте его через один линейный слой, а затем добавьте 2D-сигнал позиции, чтобы трансформер знал, где именно в исходном изображении находился каждый квадрат.

**Тип:** Build**Языки:** Python**Предварительные требования:** Фаза 19 уроки 30-37 (Track B foundations)**Время:** ~90 минут
## Цели обучения

- Токенизируйте изображение в последовательность патч-эмбеддингов фиксированной длины.
- Реализуйте проекцию патчей на основе `Conv2d`, которая математически эквивалентна связке unfold-затем-linear.
- Постройте детерминированный 2D-синусоидальный эмбеддинг позиции, чтобы порядок токенов кодировал пространственное положение.
- Проверьте количество патчей, форму эмбеддинга и эквивалентность `Conv2d`/unfold на синтетической фикстуре.

## Проблема

Трансформер потребляет последовательность векторов. Изображение — это сетка с 3 каналами. Если читать каждый пиксель как токен, длина последовательности взрывается: RGB-изображение 224x224 — это 150,528 токенов, а такое количество 12-слойный трансформер не может себе позволить в механизме внимания. Если читать изображение как один гигантский плоский вектор, теряется локальность, которую слой внимания уже не может восстановить. Задача входной части энкодера — сжать сетку пикселей в несколько сотен токенов, каждый из которых обобщает квадратную область.

Патч-эмбеддинг решает эту задачу одной линейной проекцией. Изображение 224x224, разрезанное на патчи 16x16, даёт сетку 14x14 из 196 патчей. Каждый патч разворачивается из `(3, 16, 16) = 768` значений пикселей в один вектор, а затем линейный слой отображает его в скрытую размерность модели. Трансформер видит 196 токенов размерности `hidden` (обычно 768) плюс CLS-токен. Это уже последовательность, с которой остальная часть сети может работать.

## Концепция

```mermaid
flowchart LR
  Image[224x224x3 image] --> Cut[cut into 16x16 patches]
  Cut --> Grid[14x14 grid of patches]
  Grid --> Flatten[flatten each patch]
  Flatten --> Proj[linear projection]
  Proj --> Tokens[196 tokens of dim hidden]
  Tokens --> Pos[add 2D sinusoidal position]
  Pos --> Out[final token sequence]
```

### Почему патчи, а не пиксели

Внимание квадратично растёт с длиной последовательности. Последовательность из 196 токенов стоит `196 * 196 = 38,416` оценок внимания на голову на слой; последовательность из 150,528 токенов стоит `150,528 * 150,528 = 22.6 billion`. Патчи дают снижение вычислений внимания в 590,000 раз, а один участок 16x16 несёт достаточно сигнала для задач высокоуровневого зрения. Ценой является потеря мелкой пространственной детализации внутри одного патча, поэтому нижестоящие мультимодальные стеки часто запускают вторую ветку высокого разрешения, когда важна точная локализация.

### Почему достаточно линейной проекции

Каждый патч рассматривается как независимый вектор. Проекция обучает базис: детекторы границ, цветовые фильтры, простые текстуры. Один линейный слой невелик (`768 * 768 = 589,824` параметров для ViT-Base) и обучается быстро. Существуют и более глубокие свёрточные stem-блоки («гибридный» ViT), но стандартом остаётся плоская линейная проекция, и большинство современных энкодеров с открытыми весами используют именно такую форму.

### Приём с `Conv2d`

`Conv2d(in_channels=3, out_channels=hidden, kernel_size=patch_size, stride=patch_size)` без паддинга даёт тот же численный результат, что и связка unfold-затем-linear, потому что каждая выходная позиция вычисляет скалярное произведение пикселей патча с одним фильтром. Свёртка и есть проекция патчей, и большинство продакшен-кодовых баз реализуют её именно так, потому что это быстрее на GPU и требует на один reshape меньше.

### Эмбеддинги позиции

После проекции токены не несут никакого порядка. 2D-синусоидальный эмбеддинг даёт каждому токену фиксированный сигнал, кодирующий его позицию `(row, col)`. Половина размерности эмбеддинга кодирует позицию по строке с помощью sin/cos на нескольких частотах; другая половина кодирует позицию по столбцу. Кодирование детерминировано, поэтому можно менять разрешение без переобучения, и оно чисто интерполируется на сетки, которых модель никогда не видела во время обучения.

| Компонент | Форма | Параметры |
|-----------|-------|------------|
| Проекция патчей (`Conv2d`) | `(hidden, 3, patch, patch)` | `3 * P * P * hidden + hidden` |
| Эмбеддинг позиции (фиксированный) | `(num_patches, hidden)` | 0 (вычисляется, не обучается) |
| CLS-токен (обучаемый) | `(1, hidden)` | `hidden` |

Для ViT-Base/16 при разрешении 224: 590,592 параметра в проекции, 768 в CLS-токене и ноль для синусоидальной позиции. В следующем уроке (59) поверх этой входной части будет собран 12-слойный трансформер.

### Эквивалентность как проверка на здравый смысл

Шаг патчинга можно записать двумя способами: проекцией `Conv2d` и явной связкой unfold-затем-linear. При одинаковых весах они должны давать одинаковый результат. Если это не так, математика unfold неверна, и весь остальной энкодер построен на песке. Тесты в этом уроке проверяют именно эту эквивалентность.

## Реализация

`code/main.py` реализует:

- `PatchEmbed` — `nn.Module`, оборачивающий `Conv2d` для проекции патчей.
- `sinusoidal_2d(grid_h, grid_w, dim)` — функцию без состояния, которая строит таблицу 2D-позиций.
- `VisionFrontEnd`, который объединяет патч-эмбеддинг, добавление CLS в начало последовательности и сложение с позицией в один forward pass.
- Вспомогательную функцию `synthesize_image(seed)`, которая строит детерминированную фикстуру 224x224x3 из `numpy.random`.
- Демонстрацию, которая пропускает одно фикстурное изображение через входную часть и выводит форму результата, норму CLS-токена и одну строку эмбеддинга позиции.

Запустите его:

```bash
python3 code/main.py
```

Результат: фикстура 224x224 токенизируется в последовательность формы `(1, 197, 768)`. Первый токен — CLS; следующие 196 — токены патчей. Нормы эмбеддинга позиции одинаковы в пределах строки — это характерная черта синусоидального сигнала.

## Применение

Одна и та же входная часть с патчами встречается в каждой современной vision-language модели: CLIP ViT-L/14, SigLIP, DINOv2, семейство Qwen-VL и стек InternVL — все они начинаются с проекции патчей `Conv2d` плюс сигнал позиции. Различия между семействами находятся дальше по конвейеру (CLS против пулинга без CLS, регистровые токены, разные размеры патчей — 14 против 16, динамическое разрешение через интерполированные позиции). Входная часть из этого урока — тот фундамент, на котором строится каждая из этих моделей.

## Тесты

`code/test_main.py` покрывает:

- количество патчей соответствует `(image_size / patch_size) ** 2`
- форма результата соответствует `(batch, num_patches + 1, hidden)`
- проекция `Conv2d` совпадает с ручной связкой unfold-затем-linear на небольшой фикстуре
- таблица синусоидальных позиций детерминирована между вызовами
- CLS-токен транслируется по измерению батча без утечек

Запустите их:

```bash
python3 -m unittest code/test_main.py
```

## Упражнения

1. Замените синусоидальную позицию на обучаемый `nn.Parameter` и сравните значение функции потерь на первой эпохе на крошечной синтетической задаче классификации. Обучаемые позиции выигрывают при фиксированном разрешении; синусоидальные — когда после обучения разрешение меняется.

2. Замените `Conv2d` на явную связку `nn.Unfold` плюс `nn.Linear` и убедитесь, что результаты совпадают с точностью до допуска по float. Та же математика, два способа её записать.

3. Добавьте поддержку не квадратных размеров патчей (например, 32x16 для входов с широким соотношением сторон) и проверьте, что таблица позиций корректно обрабатывает не квадратные сетки.

4. Профилируйте шаг патчинга при размерах батча 1, 8, 64. Проекция патчей редко является узким местом; доминируют слои внимания дальше по конвейеру.

5. Обучите входную часть как замороженный экстрактор признаков на синтетическом наборе данных с 4 классами фигур (круги, квадраты, треугольники, звёзды). Выход CLS-токена должен линейно разделяться.

## Ключевые термины

| Термин | Что это значит |
|------|---------------|
| Патч | Квадратная подобласть изображения, обычно 14x14 или 16x16 |
| Патч-эмбеддинг | Линейная проекция одного развёрнутого патча в скрытую размерность |
| Длина последовательности | Количество токенов после токенизации на патчи, обычно плюс CLS |
| Синусоидальная позиция | Фиксированный сигнал sin/cos, кодирующий 2D-координаты сетки |
| CLS-токен | Обучаемый вектор, добавляемый в начало последовательности как голова пулинга |
