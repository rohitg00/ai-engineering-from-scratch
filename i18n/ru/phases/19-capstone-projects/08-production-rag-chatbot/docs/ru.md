# Капстоун 08 — продакшен-RAG-чат-бот для регулируемой вертикали

> Harvey, Glean, Mendable и LlamaCloud в 2026 году используют одну и ту же продакшен-форму. Приём документов через docling или Unstructured и ColPali для визуального контента. Гибридный поиск. Реранжирование с помощью bge-reranker-v2-gemma. Синтез ответа моделью Claude Sonnet 4.7 с промпт-кешированием при доле попаданий 60-80%. Защита с помощью Llama Guard 4 и NeMo Guardrails. Наблюдение через Langfuse и Phoenix. Оценка с помощью RAGAS на эталонном наборе из 200 вопросов. Постройте такую систему в регулируемой предметной области (юриспруденция, клинические исследования, страхование) — капстоун считается сданным, когда пройдены эталонный набор, red-team-проверка и дашборд дрейфа.

## Проблема

RAG в регулируемой предметной области (юридические контракты, протоколы клинических испытаний, страховые полисы) — самая часто внедряемая продакшен-форма 2026 года, потому что ROI очевиден, а ставки конкретны. Harvey (Allen & Overy) построила её для юриспруденции. Mendable поставляет вариант для документации разработчиков. Glean покрывает корпоративный поиск. Паттерн таков: высокоточный приём документов, гибридный поиск с реранжированием, синтез с принудительным цитированием и промпт-кешированием, защита несколькими уровнями безопасности и непрерывный мониторинг дрейфа.

Сложность не в модели. Она в соответствии нормативным требованиям с учётом юрисдикции (HIPAA, GDPR, SOC2), аудируемости на уровне цитат, контроле затрат (промпт-кеширование даёт скидку 60-90% при высокой доле попаданий), обнаружении галлюцинаций через метрику достоверности RAGAS и обнаружении дрейфа, когда исходные документы обновляются, а индекс не успевает за ними. Этот капстоун просит вас поставить всё это на эталонном наборе из 200 вопросов вместе с набором red-team-проверок.

## Концепция

У конвейера две стороны. **Приём (ingestion)**: docling или Unstructured разбирают структурированные документы; ColPali обрабатывает документы с насыщенной визуальной частью; фрагменты получают резюме, теги и метки доступа на основе ролей. Векторы попадают в pgvector + pgvectorscale (до 50M векторов) или Qdrant Cloud; параллельно работает разреженный BM25. **Диалог**: LangGraph управляет памятью и многоходовыми диалогами; каждый запрос проходит гибридный поиск, реранжируется с помощью bge-reranker-v2-gemma-2b, синтезируется моделью Claude Sonnet 4.7 (с промпт-кешированием), выход проходит через Llama Guard 4 и NeMo Guardrails, и формируется ответ с привязкой к цитатам.

Стек оценивания состоит из четырёх слоёв. **Эталонный набор (golden set)** (200 размеченных пар вопрос-ответ с цитатами) для проверки корректности. **Red-team-набор** (джейлбрейки, попытки извлечения PII, вопросы вне предметной области) для проверки безопасности. **RAGAS** для автоматической оценки достоверности / релевантности ответа / точности контекста на каждом ходу. **Дашборд дрейфа** (Arize Phoenix), еженедельно отслеживающий качество поиска и оценку галлюцинаций.

Промпт-кеширование — рычаг управления затратами. Claude 4.5+ и GPT-5+ поддерживают кеширование системного промпта и найденного контекста. При доле попаданий 60-80% стоимость одного запроса падает в 3-5 раз. Конвейер нужно проектировать со стабильными префиксами (сначала системный промпт + реранжированный контекст), чтобы достичь высокой доли попаданий в кеш.


## Стек

- Приём (ingestion): Unstructured.io или docling для структурированных документов; ColPali для визуально насыщенных PDF
- Векторная база данных: pgvector + pgvectorscale до 50M векторов; в остальных случаях Qdrant Cloud
- Разреженный поиск: Tantivy BM25 с весами полей
- Оркестрация: LlamaIndex Workflows (приём) + LangGraph (диалог)
- Реранкер: bge-reranker-v2-gemma-2b с самостоятельным хостингом или размещённый Voyage rerank-2
- LLM: Claude Sonnet 4.7 с промпт-кешированием; резервный вариант — Llama 3.3 70B с самостоятельным хостингом
- Оценивание: RAGAS 0.2 онлайн, DeepEval для наборов проверок на галлюцинации и джейлбрейки
- Наблюдаемость: Langfuse с самостоятельным хостингом и очередью аннотирования; Arize Phoenix для отслеживания дрейфа
- Защитные ограничения: классификатор входа/выхода Llama Guard 4, политика NeMo Guardrails v0.12, очистка PII через Presidio
- Комплаенс: метки доступа на основе ролей на фрагментах; теги юрисдикции для GDPR/HIPAA

## Реализация

1. **Приём.** Разберите свой корпус (1000-10000 документов для серьёзной реализации) с помощью Unstructured или docling. Для отсканированных / визуально насыщенных страниц направляйте их через ColPali. Получите фрагменты с резюме, метками ролей и тегами юрисдикции.

2. **Индексирование.** Плотные эмбеддинги (Voyage-3 или Nomic-embed-v2) в pgvector + pgvectorscale. Побочный BM25-индекс через Tantivy. Фильтры по роли и юрисдикции в качестве payload.

3. **Гибридный поиск.** Сначала фильтрация по роли и юрисдикции; затем параллельно плотный поиск + BM25; слияние методом reciprocal rank fusion; топ-20 в реранкер; топ-5 в синтез.

4. **Синтез с промпт-кешированием.** Системный промпт + статические политики в заголовке кеша; реранжированный контекст как расширение кеша; вопрос пользователя как некешируемый суффикс. Целевая доля попаданий в кеш в стабильном режиме — 60-80%.

5. **Защитные ограничения.** Llama Guard 4 на входе; правила NeMo Guardrails блокируют вопросы вне предметной области или запрещённые политикой темы; Presidio очищает случайные PII в выходе; постфильтр принудительного цитирования.

6. **Эталонный набор.** 200 пар вопрос-ответ, размеченных экспертом предметной области полями (ответ, цитаты). Оцените агента по точному совпадению цитат, корректности ответа и достоверности (RAGAS).

7. **Red-team-проверка.** 50 состязательных промптов: джейлбрейки (PAIR, TAP), попытки эксфильтрации PII, вопросы вне предметной области, межюрисдикционные утечки. Оценивайте по принципу «прошёл/не прошёл» и уровню серьёзности.

8. **Дашборд дрейфа.** Arize Phoenix еженедельно отслеживает качество поиска (nDCG, достоверность цитат). Оповещение при падении на 5%.

9. **Отчёт по затратам.** Langfuse: доля попаданий промпт-кеша, токены на запрос, разбивка $/запрос по этапам.

## Упражнения

1. Постройте второй срез корпуса под другой юрисдикцией (например, HIPAA наряду с GDPR). Продемонстрируйте, что фильтрация по роли и юрисдикции предотвращает межюрисдикционную утечку на зонде из 20 вопросов.

2. Измерьте долю попаданий промпт-кеша за неделю продакшен-трафика. Определите, какие запросы ломают префикс кеша. Перестройте конвейер.

3. Добавьте многоходовую память с буфером резюме на 10 тыс. токенов. Измерьте, падает ли достоверность по мере роста диалога.

4. Замените Claude Sonnet 4.7 на Llama 3.3 70B с самостоятельным хостингом. Измерьте изменение $/запрос и достоверности.

5. Добавьте режим «не уверен»: если верхние оценки после реранжирования ниже порога, агент отвечает «У меня нет достаточно уверенных цитат» вместо ответа по существу. Измерьте снижение ложной уверенности.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| Prompt caching (промпт-кеширование) | «Закешированы система + контекст» | Функция Claude/OpenAI: токены закешированного префикса со скидкой 60-90% при попадании |
| RAGAS | «Оценщик RAG» | Автоматическая оценка достоверности, релевантности ответа, точности контекста |
| Golden set (эталонный набор) | «Размеченный набор для оценивания» | 200+ пар вопрос-ответ, размеченных экспертами, с цитатами; эталонная истина |
| Jurisdiction tag (тег юрисдикции) | «Метка комплаенса» | Область действия GDPR/HIPAA/SOC2, привязанная к фрагментам; обеспечивается фильтром поиска |
| Citation faithfulness (достоверность цитирования) | «Доля обоснованных ответов» | Доля утверждений, подкреплённых извлекаемыми фрагментами источника |
| Drift (дрейф) | «Деградация качества поиска» | Еженедельное изменение nDCG или оценки цитирования; порог оповещения — 5% |
| Red team (red-team-проверка) | «Состязательное оценивание» | Предрелизные зонды на джейлбрейки, извлечение PII, вопросы вне предметной области |
