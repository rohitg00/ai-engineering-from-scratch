# Капстоун 07 — Сквозной конвейер дообучения (от данных до SFT, DPO и обслуживания)

> Модель 8B, обученная на ваших собственных данных, согласованная методом DPO по вашим собственным предпочтениям, квантованная, использующая спекулятивное декодирование и обслуживаемая с измеримой стоимостью $/1M токенов. Открытый стек 2026 года — это Axolotl v0.8, TRL 0.15, Unsloth для итерации, GPTQ/AWQ/GGUF для квантования, vLLM 0.7 с EAGLE-3 для обслуживания. Задача капстоуна — воспроизводимо прогнать весь конвейер от начала до конца: на входе YAML, на выходе обслуживаемая конечная точка, — и опубликовать карточку модели по стандарту Model Openness Framework 2026 года.

**Тип:** Capstone**Языки:** Python (pipeline), YAML (configs), Bash (scripts)**Предварительные требования:** Фаза 2 (ML), Фаза 3 (DL), Фаза 7 (transformers), Фаза 10 (LLMs from scratch), Фаза 11 (LLM engineering), Фаза 17 (infrastructure), Фаза 18 (safety)**Задействованные фазы:** P2 · P3 · P7 · P10 · P11 · P17 · P18
**Время:** 35 часов
## Проблема

Каждая серьёзная ИИ-команда в 2026 году держит наготове конвейер дообучения. Не потому, что она поставляет передовую базовую модель, а потому, что измеримые выигрыши находятся именно в нисходящей адаптации — доменном SFT, DPO по размеченным предпочтениям, дистиллированных черновиках для спекулятивного декодирования, обслуживании с EAGLE-3. Axolotl v0.8 обрабатывает конфигурации SFT с несколькими GPU. TRL 0.15 обрабатывает DPO и GRPO. Unsloth даёт быструю итерацию на одном GPU. vLLM 0.7 с EAGLE-3 повышает пропускную способность декодирования в 2–3 раза без потери качества. Инструментарий работает; мастерство — в YAML-файлах, гигиене данных и дисциплине оценивания.

Вы проведёте базовую модель 8B (Llama 3.3, Qwen3 или Gemma 3) через SFT, затем через DPO на данных для конкретной задачи, квантуете её для обслуживания и измерите прирост по lm-evaluation-harness, RewardBench-2, MT-Bench-v2 и MMLU-Pro. Вы подготовите карточку модели по стандарту Model Openness Framework 2026 года. Суть — в воспроизводимости: одна команда заново прогоняет весь конвейер от начала до конца.

## Концепция

Конвейер состоит из пяти стадий. **Данные**: дедупликация (MinHash / Datatrove), фильтрация качества (классификатор в стиле Nemotron-CC), очистка от персональных данных (PII), проверка гигиены разбиения на предмет контаминации публичных бенчмарков. **SFT**: YAML для Axolotl, ZeRO-3 на 8xH100, косинусное расписание, упакованные последовательности, 2–3 эпохи. **DPO или GRPO**: конфигурация TRL, 1 эпоха, пары предпочтений — либо размеченные человеком, либо оцененные моделью, подбор beta. **Квантование**: GPTQ + AWQ + GGUF для гибкости развёртывания. **Обслуживание**: vLLM 0.7 со спекулятивными головами EAGLE-3 (или SGLang со SpecForge), развёртывание в K8s, HPA по времени ожидания в очереди.

Абляции — это и есть результат работы: SFT-only против SFT+DPO против SFT+GRPO на трёх бенчмарках для конкретной задачи. Метрики обслуживания: токены/с при батче 1 / 8 / 32, доля принятия EAGLE-3, $/1M токенов. Оценка безопасности: доля прохождения Llama Guard 4. Карточка модели: оценки смещения (bias), seed для воспроизводимости, лицензирование данных.

## Реализация

1. **Конвейер данных.** Запустите дедупликацию Datatrove на исходном корпусе. Примените классификатор качества в стиле Nemotron-CC. Presidio очищает данные от PII. Запишите обучающее и валидационное разбиения с явным seed.

2. **Проверка контаминации.** Для каждого валидационного разбиения вычислите MinHash относительно тестовых наборов MMLU-Pro, MT-Bench-v2, RewardBench-2. Отклоняйте любое пересечение.

3. **Axolotl SFT.** YAML с ZeRO-3, FA3, упаковкой последовательностей. 2–3 эпохи на 8xH100. Логирование в W&B.

4. **TRL DPO / GRPO.** Возьмите контрольную точку SFT, прогоните одну эпоху DPO на парах предпочтений (или GRPO с проверяемым вознаграждением на математике/коде). Подберите beta.

5. **Квантование.** Получите три кванта: GPTQ-INT4-Marlin, AWQ-INT4, GGUF-Q4_K_M для llama.cpp. Зафиксируйте размер и номинальную пропускную способность.

6. **Обслуживание со спекулятивным декодированием.** Конфигурация vLLM 0.7 с черновыми головами EAGLE-3, обученными через Red Hat Speculators. Измерьте долю принятия и хвостовую задержку при батче 1 / 8 / 32. Сообщите $/1M токенов в сравнении с Anthropic / OpenAI на том же оценивании.

7. **Матрица оценивания.** Запустите lm-eval-harness, RewardBench-2, MT-Bench-v2, MMLU-Pro на базовой модели, SFT-only, SFT+DPO, SFT+GRPO. Составьте таблицу.

8. **Оценка безопасности.** Доля прохождения Llama Guard 4 на dev-наборе. Фильтр вывода ShieldGemma-2.

9. **Карточка модели.** Шаблон MOF 2026: данные, обучение, оценивание, безопасность, лицензия, раздел воспроизводимости с YAML-файлами и SHA коммитов.

## Поставка

`outputs/skill-finetuning-pipeline.md` описывает результат поставки. Одна команда прогоняет данные через SFT, через DPO, через квантование, через обслуживание, через оценивание — и выдаёт карточку модели и обслуживаемую конечную точку.

## Ключевые термины

| Термин | Что говорят люди | Что это означает на самом деле |
|------|-----------------|------------------------|
| Axolotl | «SFT-тренер» | Унифицированный тренер на YAML для SFT, DPO и дистилляции |
| TRL | «Тюнер предпочтений» | Библиотека Hugging Face для DPO, GRPO, PPO на LLM |
| GRPO | «Group-relative policy optimization» | RL-рецепт DeepSeek R1 с проверяемыми вознаграждениями |
| EAGLE-3 | «Черновик спекулятивного декодирования» | Черновые головы, предсказывающие N токенов вперёд; vLLM проверяет целевой моделью |
| MOF | «Model Openness Framework» | Стандарт 2026 года для оценки релизов моделей по данным, коду, лицензии |
| Contamination check (проверка контаминации) | «Гигиена разбиения» | Обнаружение утечки тестового набора в обучающий на основе MinHash |
| Acceptance rate (доля принятия) | «Метрика EAGLE / MTP» | Доля черновых токенов, принятых целевой моделью |
