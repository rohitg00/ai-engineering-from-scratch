# Капстоун 01 — терминальный агент для написания кода

> К 2026 году форма агента для написания кода устоялась. TUI-харнесс, план с сохранением состояния, поверхность инструментов, изолированная в песочнице, цикл, который планирует, действует, наблюдает, восстанавливается. Claude Code, Cursor 3 и OpenCode с расстояния 50 футов выглядят одинаково. Этот капстоун просит вас построить такого агента целиком — от CLI на входе до pull request на выходе — и измерить его результаты в сравнении с mini-swe-agent и Live-SWE-agent на SWE-bench Pro. Вы узнаете, почему сложная часть — это не вызов модели, а цикл работы с инструментами, песочница и потолок затрат в прогоне на 50 ходов.

**Тип:** Капстоун
**Языки:** TypeScript / Bun (харнесс), Python (скрипты оценивания)
**Предварительные требования:** Этап 11 (инженерия LLM), этап 13 (инструменты и протоколы), этап 14 (агенты), этап 15 (автономные системы), этап 17 (инфраструктура)
**Задействованные этапы:** P0 · P5 · P7 · P10 · P11 · P13 · P14 · P15 · P17 · P18
**Время:** 35 часов

## Проблема

В 2026 году агенты для написания кода стали доминирующей категорией ИИ-приложений. Claude Code (Anthropic), Cursor 3 с Composer 2 и Agent Tabs (Cursor), Amp (Sourcegraph), OpenCode (112k звёзд), Factory Droids и Google Jules — все они поставляют вариации одной и той же архитектуры: терминальный харнесс, поверхность инструментов с разграничением прав, песочница и цикл «план → действие → наблюдение», построенный вокруг передовой модели. Передний край узок — Live-SWE-agent достиг 79.2% на SWE-bench Verified с Opus 4.5, — но инженерное мастерство здесь широко. Большинство отказов — не ошибки модели. Это нестабильность цикла работы с инструментами, отравление контекста, неконтролируемый рост стоимости токенов и деструктивные операции с файловой системой.

Об этих агентах нельзя рассуждать со стороны. Нужно построить одного из них, увидеть, как цикл падает на 47-м ходу, когда ripgrep возвращает 8 МБ совпадений, и переделать слой обрезки вывода. В этом и заключается смысл капстоуна.

## Концепция

У харнесса четыре поверхности. **План** поддерживает объект состояния в стиле TodoWrite, который модель переписывает на каждом ходу. **Действие** диспетчеризирует вызовы инструментов (чтение, редактирование, запуск, поиск, git). **Наблюдение** захватывает stdout / stderr / коды завершения, обрезает вывод и передаёт сводку обратно. **Восстановление** обрабатывает ошибки инструментов, не раздувая контекстное окно и не зацикливаясь бесконечно. Форма 2026 года добавляет ещё один элемент: **хуки**. `PreToolUse`, `PostToolUse`, `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `Notification`, `Stop` и `PreCompact` — настраиваемые точки расширения, через которые оператор внедряет политику, телеметрию и защитные ограничения (guardrails).

Песочница — это E2B или Daytona. Каждая задача запускается в свежем devcontainer с git worktree, смонтированным в режиме чтения-записи. Харнесс никогда не обращается к файловой системе хоста. Worktree уничтожается при успехе или при неудаче. Контроль затрат обеспечивается на трёх уровнях: потолок токенов на ход, бюджет в долларах на сессию и жёсткий лимит ходов (обычно 50). Слой наблюдаемости — это спаны OpenTelemetry с семантическими соглашениями GenAI (GenAI semantic conventions), передаваемые в локально развёрнутый Langfuse.

## Архитектура

```
  user CLI  ->  harness (Bun + Ink TUI)
                  |
                  v
           plan / act / observe loop  <--->  Claude Sonnet 4.7 / GPT-5.4-Codex / Gemini 3 Pro
                  |                          (via OpenRouter, model-agnostic)
                  v
           tool dispatcher (MCP StreamableHTTP client)
                  |
     +------------+------------+----------+
     v            v            v          v
  read/edit    ripgrep     tree-sitter   git/run
     |            |            |          |
     +------------+------------+----------+
                  |
                  v
           E2B / Daytona sandbox  (worktree isolated)
                  |
                  v
           hooks: Pre/Post, Session, Prompt, Compact
                  |
                  v
           OpenTelemetry -> Langfuse (spans, tokens, $)
                  |
                  v
           PR via GitHub app
```

## Стек

- Рантайм харнесса: Bun 1.2 + Ink 5 (React в терминале)
- Доступ к моделям: унифицированный API OpenRouter с Claude Sonnet 4.7, GPT-5.4-Codex, Gemini 3 Pro, Opus 4.5 (для самых сложных задач)
- Транспорт инструментов: Model Context Protocol StreamableHTTP (редакция MCP 2026 года)
- Песочница: песочницы E2B (JS SDK) или devcontainer-контейнеры Daytona
- Поиск по коду: подпроцесс ripgrep, парсеры tree-sitter для 17 языков (предкомпилированные)
- Изоляция: `git worktree add` на задачу, очистка при успехе / неудаче
- Харнесс для оценивания: SWE-bench Pro (проверенное подмножество) + Terminal-Bench 2.0 + собственный отложенный набор из 30 задач
- Наблюдаемость: OpenTelemetry SDK с семантическими соглашениями `gen_ai.*` → локально развёрнутый Langfuse
- Публикация PR: GitHub App с токеном с детализированными правами доступа, область действия которого ограничена целевым репозиторием

## Реализация

1. **TUI и цикл команд.** Разверните проект на Bun с использованием Ink. Принимайте команду `agent run <repo> "<task>"`. Выводите разделённый экран: панель плана (сверху), поток вызовов инструментов (в середине), бюджет токенов (снизу). Добавьте отмену по Ctrl-C, которая перед выходом запускает хук `SessionEnd`.

2. **Состояние плана.** Определите типизированную схему TodoWrite (элементы pending / in_progress / done с заметками). Модель переписывает всё состояние на каждом ходу как вызов инструмента — не позволяйте ей изменять его инкрементально. Сохраняйте план в `.agent/state.json`, чтобы после сбоя можно было возобновить работу.

3. **Поверхность инструментов.** Определите шесть инструментов: `read_file`, `edit_file` (с предпросмотром diff), `ripgrep`, `tree_sitter_symbols`, `run_shell` (с таймаутом), `git` (status / diff / commit / push). Предоставляйте их через MCP StreamableHTTP, чтобы харнесс не зависел от конкретного транспорта. Каждый инструмент возвращает обрезанный вывод (ограничение — 4k токенов на вызов).

4. **Обёртка песочницы.** Каждая задача порождает песочницу E2B. Создавайте новую ветку командой `git worktree add -b agent/$TASK_ID`. Все вызовы инструментов выполняются внутри песочницы. Файловая система хоста недоступна.

5. **Хуки.** Реализуйте все восемь типов хуков 2026 года. Подключите как минимум четыре пользовательских хука: (a) защита `PreToolUse` от деструктивных команд, которая блокирует `rm -rf` за пределами worktree, (b) учёт токенов в `PostToolUse`, (c) инициализация бюджета в `SessionStart`, (d) запись итогового пакета трассировки в `Stop`.

6. **Цикл оценивания.** Клонируйте подмножество из 30 задач SWE-bench Pro Python. Прогоните ваш харнесс на каждой из них. Сравните с mini-swe-agent (минимальным базовым решением) по pass@1, числу ходов на задачу и стоимости в долларах на задачу. Запишите результаты в `eval/results.jsonl`.

7. **Контроль затрат.** Жёсткие ограничения: 50 ходов, 200k контекста, $5 на задачу. Хук `PreCompact` сжимает более ранние ходы в блок предыдущего состояния на отметке 150k, освобождая место для новых наблюдений без потери плана.

8. **Публикация PR.** При успехе финальный шаг — это `git push` и вызов GitHub API, который открывает PR с планом и сводкой изменений в теле.

## Применение

```
$ agent run ./my-repo "Fix the race condition in worker.rs"
[plan]  1 locate worker.rs and enumerate mutex uses
        2 identify shared state under contention
        3 propose fix, verify tests

```

## Поставка

Итоговый навык (skill) находится в `outputs/skill-terminal-coding-agent.md`. Получив путь к репозиторию и описание задачи, он запускает полный цикл «план → действие → наблюдение» в песочнице и возвращает URL PR и пакет трассировки. Рубрика для этого капстоуна:

| Вес | Критерий | Как измеряется |
|:-:|---|---|
| 25 | pass@1 SWE-bench Pro относительно базового решения | Ваш харнесс против mini-swe-agent на 30 сопоставленных Python-задачах |
| 20 | Ясность архитектуры | Разделение «план / действие / наблюдение», поверхность хуков, схема инструментов — оценивается в сравнении со структурой Live-SWE-agent |
| 20 | Безопасность | Тесты на побег из песочницы, запросы разрешений; защита от деструктивных команд успешно проходит проверку красной командой |
| 20 | Наблюдаемость | Полнота трассировки (100% вызовов инструментов охвачены спанами), учёт токенов на ход |
| 15 | UX разработчика | Холодный старт < 2с, восстановление после сбоя возобновляет план, Ctrl-C аккуратно отменяет выполнение на середине инструмента |
| **100** | | |

## Упражнения

1. Замените базовую модель с Claude Sonnet 4.7 на Qwen3-Coder-30B, обслуживаемую через vLLM. Сравните pass@1 и стоимость на задачу. Укажите, где открытая модель показывает результат хуже.

2. Добавьте субагента `reviewer`, который читает список изменений перед публикацией PR и может запросить цикл доработки. Измерьте, снижают ли ложноположительные ревью долю успешных прохождений SWE-bench ниже базового уровня одноагентной схемы (подсказка: обычно да).

3. Проведите стресс-тест песочницы: напишите задачу, которая пытается выполнить `curl` внешнего URL, и задачу, которая пытается писать за пределы worktree. Убедитесь, что обе блокируются хуком PreToolUse. Логируйте попытки.

4. Реализуйте сжатие в `PreCompact` с использованием меньшей модели (Haiku 4.5). Измерьте, насколько теряется точность плана при трёхкратном сжатии.

5. Замените транспорт MCP StreamableHTTP на stdio. Замерьте холодный старт и задержку на вызов. Выберите победителя для исключительно локального использования.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|------------------------|
| Харнесс | «Цикл агента» | Код вокруг модели, который диспетчеризирует инструменты, поддерживает состояние плана и обеспечивает соблюдение бюджетов |
| Хук | «Слушатель событий агента» | Пользовательский скрипт, который харнесс запускает на одном из восьми событий жизненного цикла |
| Worktree | «Git-песочница» | Связанный git-чекаут по отдельному пути; можно уничтожить, не затрагивая основной клон |
| TodoWrite | «Состояние плана» | Типизированный список элементов pending/in-progress/done, который модель переписывает на каждом ходу |
| StreamableHTTP | «Транспорт MCP» | Редакция MCP 2026 года: долгоживущее HTTP-соединение с двунаправленным стримингом; заменяет SSE |
| Потолок токенов | «Бюджет контекста» | Лимит входных+выходных токенов на ход или на сессию; запускает сжатие или завершение |
| pass@1 | «Доля успеха с одной попытки» | Доля задач SWE-bench, решённых с первого прогона без повторных попыток и подглядывания в тестовый набор |
