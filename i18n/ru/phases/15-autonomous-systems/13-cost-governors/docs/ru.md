# Бюджеты на действия, лимиты итераций и регуляторы затрат

> У среднего агента для электронной коммерции месячные затраты на LLM подскочили с $1,200 до $4,800 после того, как команда включила навык «order-tracking». Это не баг ценообразования. Это агент, который нашёл новый цикл и продолжал тратить внутри него. Microsoft Agent Governance Toolkit (2 апреля 2026 года) закрепляет защиту от этого класса сбоев: `max_tokens` на запрос, токенный и денежный бюджет на задачу, лимиты по дням/месяцам, лимиты итераций, многоуровневая маршрутизация моделей, кеширование промптов, оконное ограничение контекста, контрольные точки с участием человека для дорогостоящих действий, аварийные выключатели при превышении бюджета. Anthropic Claude Code Agent SDK поставляет те же примитивы под другими именами. Лимиты скорости расходования — например, отключение доступа при трате свыше $50 за 10 минут — ловят циклы быстрее, чем месячные лимиты.

**Тип:** Learn**Языки:** Python (stdlib, layered cost-governor simulator)**Предварительные требования:** Фаза 15 · 10 (режимы разрешений), Фаза 15 · 12 (устойчивое выполнение)**Время:** ~60 минут
## Проблема

Автономные агенты тратят настоящие деньги на каждом ходу. Плохой вывод чат-бота — это плохой ответ; плохой цикл агента — это счёт. Задокументированный в индустрии термин для этого типа сбоя — «Denial of Wallet» (истощение кошелька): агент продолжает рассуждать, продолжает вызывать инструменты, продолжает набирать счёт, и ничто его не останавливает, потому что ничего не было спроектировано для остановки.

Решение — не одно число. Это стек лимитов на разных временных масштабах и с разной степенью детализации: на запрос, на задачу, на час, на день, на месяц. Хорошо спроектированный стек ловит неконтролируемый цикл в течение минут, медленную утечку — в течение часов, а неудачный релиз — в течение дня. Тот же стек вообще удерживает бюджет, когда агент долгоживущий и автономный.

Это инженерный урок: математика здесь тривиальна, а команды подводит именно дисциплина. Все лимиты из списка ниже названы либо в Microsoft Agent Governance Toolkit, либо в документации Anthropic Claude Code Agent SDK.

## Концепция

### Стек регуляторов затрат (cost-governor stack)

1. **`max_tokens` на запрос.** Просто. Не позволяет одному вызову сгенерировать неограниченное по размеру завершение.
2. **Токенный бюджет на задачу.** За весь прогон — не более N токенов. Жёсткая остановка при достижении лимита.
3. **Денежный бюджет на задачу.** То же самое, что и токенный бюджет, но в валюте. `max_budget_usd` в Claude Code.
4. **Лимит на вызовы инструмента.** Не более N вызовов `WebFetch`, N вызовов `shell_exec` и т. д.
5. **Лимит итераций (`max_turns`).** Общее число итераций цикла агента; предотвращает бесконечные циклы рассуждений.
6. **Лимит по минутам/часам/дням/месяцам.** Скользящие окна. Ловит утечки на разных временных масштабах.
7. **Лимит скорости расходования (financial velocity limit).** Например: «если траты превышают $50 за 10 минут — отключить доступ». Ловит выгорание бюджета из-за цикла раньше, чем сработает месячный лимит.
8. **Многоуровневая маршрутизация моделей.** По умолчанию — модель поменьше; переход на более крупную модель только тогда, когда классификатор считает, что задача этого требует.
9. **Кеширование промптов.** Системный промпт и стабильная часть контекста хранятся в кеше провайдера; стоимость повторной отправки в токенах близка к нулю.
10. **Оконное ограничение контекста (context windowing).** Сжатие/суммаризация, удерживающие активный контекст ниже порога; прямое снижение стоимости в токенах.
11. **Контрольные точки с участием человека (HITL) для дорогостоящих действий.** Перед действием, заведомо дорогим (долгий вызов инструмента, крупная загрузка, дорогое переключение на более мощную модель), требуется подтверждение человека.
12. **Аварийный выключатель при превышении бюджета.** Сессия прерывается при срабатывании любого лимита. Срабатывание фиксируется; для повторного включения нужен отдельный путь.

### Почему нужен стек, а не один лимит

Один месячный лимит ловит неконтролируемого агента только после того, как кошелёк уже пуст. Один лимит на запрос вообще ничего не ловит на уровне сессии. Разные типы сбоев требуют разных временных масштабов:

- **Неконтролируемый цикл** (агент застрял в повторах с интервалом 5 секунд): ловится лимитом скорости расходования.
- **Медленная утечка** (агент выполняет примерно в 2 раза больше работы на задачу, чем ожидалось): ловится дневным лимитом.
- **Неудачный релиз** (новая версия расходует в 5 раз больше токенов): ловится недельным/месячным лимитом.
- **Легитимный всплеск** (реальный спрос, а не баг): ловится часовым/дневным лимитом с понятным логом.

### Бюджетные механизмы среды запуска

Claude Code Agent SDK предоставляет (по публичной документации):

- `max_turns` — лимит итераций.
- `max_budget_usd` — денежный лимит; сессия прерывается при превышении.
- `allowed_tools` / `disallowed_tools` — списки разрешённых и запрещённых инструментов.
- Точки хуков перед использованием инструмента для собственного учёта затрат.

Сочетайте с лестницей режимов разрешений (урок 10). Сессия `autoMode` без `max_budget_usd` — это нерегулируемая автономность. Anthropic прямо формулирует, что Auto Mode требует бюджетного контроля; классификатор режима никак не учитывает затраты.

### EU AI Act и OWASP Agentic Top 10

Microsoft Agent Governance Toolkit покрывает требования OWASP Agentic Top 10 и статьи 14 EU AI Act (человеческий надзор). Для продакшена в ЕС логирование и обеспечение соблюдения лимитов не являются опциональными.

### Наблюдаемый случай: $1,200 → $4,800

Реальный случай из документации Microsoft: у агента для электронной коммерции месячные затраты утроились после добавления нового инструмента. Инструмент позволял агенту опрашивать статус заказа в каждой сессии. Не было ни детекции циклов, ни лимита на инструмент, ни оповещения о росте от недели к неделе. Решением стали лимит на инструмент и оповещение о дневном росте. Это шаблон: каждая новая поверхность инструмента — это новый потенциальный цикл; каждому новому инструменту нужны собственный лимит и собственное оповещение.

## Применение

`code/main.py` симулирует прогон агента с многоуровневым стеком регуляторов затрат и без него. Смоделированный агент через несколько ходов сползает в цикл опроса; многоуровневый стек ловит это в пределах окна скорости расходования, тогда как единый месячный лимит сработал бы только через несколько дней.

## Поставка

`outputs/skill-agent-budget-audit.md` проводит аудит стека регуляторов затрат для предлагаемого развёртывания агента и отмечает отсутствующие уровни.

## Упражнения

1. Запустите `code/main.py`. Убедитесь, что на траектории с циклом опроса лимит скорости расходования срабатывает раньше лимита итераций. Затем отключите лимит скорости расходования и измерьте, сколько агент «потратит», прежде чем его поймает лимит итераций.

2. Спроектируйте набор лимитов по инструментам для браузерного агента (урок 11). Какому инструменту нужен самый жёсткий лимит? Какой инструмент можно оставить без ограничений без риска?

3. Изучите документацию Microsoft Agent Governance Toolkit. Перечислите все типы лимитов, названные в тулките. Сопоставьте каждый с одним из типов сбоя (неконтролируемый цикл, медленная утечка, неудачный релиз, всплеск).

4. Оцените стоимость ночного прогона без присмотра для реалистичной задачи (например, «разобрать 50 issues в репозитории»). Установите `max_budget_usd` на уровне 2x от вашей точечной оценки. Обоснуйте выбор коэффициента 2x.

5. `max_budget_usd` в Claude Code срабатывает по суммарным затратам сессии. Спроектируйте дополняющий его лимит скорости расходования, который вы бы обеспечивали извне. Что запускает отключение и как выглядит повторное включение?

## Ключевые термины

| Термин | Как обычно говорят | Что это значит на самом деле |
|---|---|---|
| Истощение кошелька (Denial of Wallet) | «Неконтролируемый счёт» | Цикл агента, который продолжает расходовать средства, а лимита для его остановки нет |
| max_tokens | «Лимит на запрос» | Максимальный размер одного завершения |
| max_turns | «Лимит итераций» | Максимальное число итераций цикла агента за сессию |
| max_budget_usd | «Денежный аварийный выключатель» | Лимит затрат за сессию; при превышении сессия прерывается |
| Лимит скорости расходования | «Лимит темпа» | Ограничение затрат за короткий интервал (например, $50 / 10 min) |
| Многоуровневая маршрутизация | «Сначала малая модель» | По умолчанию используется дешёвая модель; переход на более дорогую — только по решению классификатора |
| Кеширование промптов | «Кешированный системный промпт» | Кеш на стороне провайдера снижает стоимость повторной отправки в токенах почти до нуля |
| Контрольная точка HITL | «Шлюз подтверждения человеком» | Перед дорогостоящим действием требуется подтверждение человека |
