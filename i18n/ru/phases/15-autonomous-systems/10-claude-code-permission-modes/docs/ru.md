# Режимы разрешений для автономных агентов

> Лестница разрешений — градация уровней автономности от проверки каждого действия до одобрения всех действий — определяет, что автономный агент может делать без запроса в управляющей среде. В Claude Code, на примере которого построен этот урок, есть шесть таких режимов: «plan» запрашивает разрешение перед каждым действием, «default» (в интерфейсе — «Manual») — только перед рискованными, «acceptEdits» автоматически одобряет запись файлов, но по-прежнему требует подтверждать выполнение команд оболочки, а «bypassPermissions» одобряет всё. Auto Mode — режим разрешений `auto` — вместо пошагового одобрения использует отдельную модель-классификатор: она проверяет каждое действие перед выполнением и блокирует всё, что выходит за рамки запроса. Бюджеты действий задаются через `max_turns` и `max_budget_usd`. Доступность `auto` зависит от тарифного плана, настроек организации, модели и провайдера, а Anthropic прямо указывает, что одного классификатора недостаточно.

**Тип:** Learn**Языки:** Python (stdlib, two-stage classifier simulator)**Предварительные требования:** Фаза 15 · 01 (Long-horizon agents), Фаза 15 · 09 (Coding-agent landscape)**Время:** ~45 минут
## Проблема

Автономный агент для программирования на вашей машине — это отдельная категория безопасности. Поверхность атаки — это всё, до чего агент может дотянуться: файловая система, сеть, учётные данные, буфер обмена, любая вкладка браузера, любой открытый терминал. Брюс Шнайер и другие публично отмечали это: агенты, использующие компьютер, — не «обновление функций» чат-ботов, а инструмент нового типа с новым профилем риска.

Система разрешений Claude Code — это ответ Anthropic. Вместо одного переключателя «автономно / не автономно» есть шесть режимов, образующих лестницу возможностей: plan → default → acceptEdits → … → bypassPermissions. Каждый режим — это свой компромисс между скоростью и объёмом проверки на каждое действие. Auto Mode (март 2026 года) добавляет отдельную модель-классификатор, которая убирает одобрение с критического пути пользователя: она проверяет каждое действие перед выполнением и блокирует всё, что выходит за рамки запроса.

Инженерный вопрос: что эта система улавливает, что она упускает и какой режим на самом деле оправдан для данной задачи?

## Концепция

### Шесть режимов разрешений

| Режим | Поведение | Когда использовать |
|---|---|---|
| `plan` | Агент предлагает план; пользователь одобряет весь план целиком; каждое действие проверяется перед выполнением | Незнакомая задача; код, близкий к продакшену; первое использование агента в репозитории |
| `default` | В интерфейсе обозначен как «Manual». Агент выполняет действия; запрашивает пользователя перед любым «рискованным» действием (выполнение команд оболочки, деструктивные операции, сетевые вызовы) | Большинство интерактивных сессий работы с кодом |
| `acceptEdits` | Запись файлов одобряется автоматически; выполнение команд оболочки и сетевые вызовы по-прежнему запрашивают подтверждение | Проход рефакторинга по множеству файлов |
| `auto` | Отдельная модель-классификатор проверяет каждое действие перед выполнением и блокирует всё, что выходит за рамки запроса | Длительные прогоны без присмотра в ограниченном рабочем пространстве |
| `dontAsk` | Никогда не запрашивает разрешение; действия, заранее не разрешённые правилами, отклоняются | Эфемерные песочницы, задачи CI, исследовательские скрипты |
| `bypassPermissions` | Одобряет всё | Документировано как «только внутри эфемерных контейнеров, которые вы готовы выбросить» |

(Названия выше совпадают с публичной документацией Claude Code; в интерфейсе режим `default` обозначен как «Manual».)

### Auto Mode на одной странице

Auto Mode (запущен 24 марта 2026 года) — первый режим разрешений, который передаёт пошаговое одобрение действий модели. Структура:

1. **Отдельная модель-классификатор.** Проверяет каждое предложенное действие перед выполнением с учётом заявленной задачи и текущего состояния сессии и блокирует всё, что выходит за рамки запроса. Решение о заблокированных действиях передаётся пользователю.
2. **Ограниченная доступность.** Предлагается ли режим `auto` вообще, зависит от тарифного плана, настроек организации, модели и провайдера.

Механизмы управления бюджетом идут вместе с классификатором:

- `max_turns` — общее количество итераций в сессии.
- `max_budget_usd` — предел в долларах, при достижении которого сессия прерывается.
- лимиты на количество действий по каждому инструменту (не более N вызовов `WebFetch` и т. п.).

### Что улавливает система

- Прямолинейную инъекцию промпта (prompt injection) во входные данные инструмента, где внедрённая инструкция соответствует известной рискованной форме действия.
- Повторяющиеся циклы вызовов инструментов — классификатор может увидеть, что действие N+1 почти идентично действию N, повторённому пять раз подряд.
- Явно выходящие за рамки команды оболочки в сессии, которая иначе ограничена только редактированием файлов.

### Что система может упустить

- **Тонкую инъекцию промпта**, которая модулирует поведение, не порождая ни одного помеченного действия. Косвенная инъекция промпта не является полностью устранимой уязвимостью (руководитель отдела готовности OpenAI, 2025, о браузерных агентах — см. урок 11).
- **Неправильное поведение на уровне смысла.** Каждое отдельное действие может выглядеть безопасным, при этом составленная из них траектория вредоносна. Классификатор оценивает действие; он не восстанавливает заново намерение пользователя.
- **Эксфильтрацию через легитимные каналы.** Запись данных в файл, которым вы владеете, с последующим `git push` в публичный репозиторий — это последовательность разрешённых действий, проблема в которой заключена именно в их сочетании.

### Рамка исследовательского превью

Anthropic выпустила Auto Mode как исследовательское превью. В документации прямо сказано, что классификатор — это слой, а не решение: ожидается, что пользователи будут сочетать Auto Mode с бюджетами, списками разрешений, изолированными рабочими пространствами и аудитом траекторий (уроки 12–16). Рамка превью также отражает документированный разрыв между оцениванием и развёртыванием (урок 1) — классификатор, проходящий офлайн-оценивания, может вести себя иначе в реальной сессии, где контекст пользователя неоднозначен.

### Где эта лестница живёт в вашем рабочем процессе

- Незнакомая задача: начните с `plan`. Прочитать план дешевле, чем откатывать неудачный прогон.
- Известный рефакторинг: `acceptEdits` экономит много кликов подтверждения.
- Прогон без присмотра в фоне: `auto` только внутри рабочего пространства, чей радиус поражения вы измерили (без учётных данных, без монтирования продакшена, без исходящего трафика, на который вы не давали согласия).
- Эфемерные контейнеры: `dontAsk` / `bypassPermissions` допустимы тогда и только тогда, когда контейнер и его учётные данные одноразовые.

## Применение

`code/main.py` моделирует классификатор, проверяющий действия, в виде двухступенчатого конвейера. Это учебное упрощение: реальный режим `auto` использует отдельную модель-классификатор, а не документированный двухступенчатый контракт. Этап 1 — это дешёвое правило по ключевым словам над предложенными действиями; Этап 2 — более медленный ревьюер на основе нескольких правил. Драйвер подаёт короткую синтетическую траекторию (безопасные действия, попытка инъекции промпта, повторяющийся цикл) и показывает, где классификатор ловит проблему, а где упускает.

## Поставка

`outputs/skill-permission-mode-picker.md` сопоставляет описание задачи с подходящим режимом разрешений, ограничениями бюджета и требуемой изоляцией.

## Упражнения

1. Запустите `code/main.py`. Какой тип синтетического действия никогда не помечается Этапом 1, но всегда улавливается Этапом 2? Какой не улавливается ни тем, ни другим?

2. Расширьте набор правил Этапа 1, чтобы улавливать конкретную известную вредоносную форму (например, `curl $ATTACKER/exfil`). Измерьте долю ложных срабатываний на выборке безобидных действий.

3. Прочитайте документацию Anthropic «How the agent loop works». Перечислите каждое внешнее состояние, к которому агент обращается по умолчанию в режиме `default`. Какие из них вам нужно было бы отдельно оградить перед запуском `auto` без присмотра?

4. Спроектируйте бюджет для 24-часового прогона без присмотра: `max_turns`, `max_budget_usd`, лимиты по инструментам, списки разрешений. Обоснуйте каждое число.

5. Опишите одну траекторию, где каждое отдельное действие одобрено классификатором, но составленное из них поведение несогласовано. (Урок 14 рассматривает, как аварийные выключатели и канареечные токены решают эту проблему.)

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|---|---|---|
| Режим разрешений | «Сколько агенту позволено» | Одна из шести именованных политик, управляющих одобрением отдельных действий |
| Режим plan | «Спрашивать перед любым действием» | Агент составляет план; пользователь одобряет его перед выполнением |
| acceptEdits | «Разрешить ему записывать файлы» | Запись файлов одобряется автоматически; выполнение команд оболочки по-прежнему требует подтверждения |
| auto | «Автоматическое одобрение» | Отдельная модель-классификатор проверяет каждое действие и блокирует выход за рамки запроса |
| bypassPermissions | «Одобрять всё» | Одобряет всё; предназначен для эфемерных контейнеров |
| Этап 1 (симулятор) | «Быстрая проверка по ключевым словам» | Простое правило над предложенными действиями в `code/main.py` |
| Этап 2 (симулятор) | «Глубокая проверка» | Более медленный ревьюер на основе нескольких правил для помеченных действий в `code/main.py` |
| Исследовательское превью | «Ещё не общедоступно» | Так Anthropic обозначает функции, для которых ещё изучаются сценарии отказа |
