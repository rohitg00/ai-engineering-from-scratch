# Обнаружение речевой активности и чередование реплик — Silero, Cobra и приём flush

> Каждый голосовой агент живёт или умирает по двум решениям: говорит ли пользователь прямо сейчас и закончил ли он? VAD отвечает на первый вопрос. Определение конца реплики (turn detection) (VAD + пауза после речи + модель семантической конечной точки) отвечает на второй. Ошибитесь в любом из них — и ваш ассистент либо обрывает пользователей, либо никогда не замолкает.

**Тип:** Build**Языки:** Python**Предварительные требования:** Фаза 6 · 11 (Real-Time Audio), Фаза 6 · 12 (Voice Assistant)**Время:** ~45 минут
## Проблема

Три отдельных решения, которые голосовой агент принимает на каждом 20-мс фрагменте:

1. **Это кадр — речь?** — VAD. Бинарное решение, покадровое.
2. **Начал ли пользователь новое высказывание?** — обнаружение начала (onset detection).
3. **Закончил ли пользователь?** — end-pointing (конец реплики).

Наивный ответ (энергетический порог) не работает при любом шуме — трафик, клавиатура, гул толпы. Ответ 2026 года: Silero VAD (открытый, на основе глубокого обучения) + модель определения конца реплики (semantic endpointing) + откалиброванная по VAD пауза после речи (silence hangover).

## Концепция

![Каскад VAD: энергия → Silero → детектор реплик → приём flush](../assets/vad-turn-taking.svg)

### Трёхуровневый каскад VAD

**Уровень 1: энергетический затвор.** Самый дешёвый. Порог RMS на уровне -40 dBFS. Отфильтровывает очевидную тишину, но срабатывает на любой шум выше порога.

**Уровень 2: Silero VAD** (2020-2026, MIT). 1M параметров. Обучена на 6000+ языках. Выполняется примерно за 1 мс на 30-мс фрагмент на одном CPU-потоке. 87,7% TPR при 5% FPR. Открытый вариант по умолчанию.

**Уровень 3: семантический детектор реплик.** Модель определения конца реплики (turn-detection) от LiveKit (2024-2026) или ваш собственный небольшой классификатор. Отличает «паузу в середине фразы» от «человек закончил говорить». Использует лингвистический контекст (интонацию и последние слова), а не только тишину.

### Ключевые параметры и их значения по умолчанию

- **Порог.** Silero выдаёт вероятность; речь классифицируется при &gt; 0.5 (по умолчанию) или &gt; 0.3 (чувствительный режим). Более низкий порог = меньше обрезанных первых слов, больше ложных срабатываний.
- **Минимальная длительность речи.** Отклоняйте речь короче 250 мс — обычно это кашель или скрип стула.
- **Пауза после речи (silence hangover; end-pointing).** После того как VAD возвращается к 0, ждите 500-800 мс, прежде чем объявить конец реплики. Слишком коротко → перебиваете пользователя. Слишком долго → ощущается медлительным.
- **Буфер перед речью (pre-roll buffer).** Храните 300-500 мс аудио до срабатывания VAD. Предотвращает обрезку слова «hey».

### Приём flush (Kyutai, 2025)

У потоковых STT-моделей есть задержка упреждения (look-ahead) (500 мс для Kyutai STT-1B, 2,5 с для STT-2.6B). Обычно вам пришлось бы ждать столько же времени после конца речи, чтобы получить транскрипт. Приём flush: когда VAD фиксирует конец речи, **отправьте сигнал flush в STT**, который принудительно вызывает немедленный вывод. STT обрабатывает данные со скоростью ~4× от реального времени, поэтому 500-мс буфер обрабатывается примерно за 125 мс.

Сквозной результат: 125 мс VAD + flush STT = разговорная задержка.

### Сравнение VAD в 2026 году

| VAD | TPR @ 5% FPR | Задержка | Лицензия |
|-----|--------------|---------|---------|
| WebRTC VAD (Google, 2013) | 50,0% | 30 мс | BSD |
| Silero VAD (2020-2026) | 87,7% | ~1 мс | MIT |
| Cobra VAD (Picovoice) | 98,9% | ~1 мс | коммерческая |

## Постройте это

### Шаг 1: энергетический затвор

```python
def energy_vad(chunk, threshold_dbfs=-40.0):
    rms = (sum(x * x for x in chunk) / len(chunk)) ** 0.5
    dbfs = 20.0 * math.log10(max(rms, 1e-10))
    return dbfs > threshold_dbfs
```

### Шаг 2: Silero VAD на Python

```python
from silero_vad import load_silero_vad, get_speech_timestamps

vad = load_silero_vad()
audio = torch.tensor(waveform_16k, dtype=torch.float32)
segments = get_speech_timestamps(
    audio, vad, sampling_rate=16000,
    threshold=0.5,
    min_speech_duration_ms=250,
    min_silence_duration_ms=500,
    speech_pad_ms=300,
)
for s in segments:
    print(f"{s['start']/16000:.2f}s - {s['end']/16000:.2f}s")
```

### Шаг 3: конечный автомат определения конца реплики

```python
class TurnDetector:
    def __init__(self, silence_hangover_ms=500, min_speech_ms=250):
        self.state = "idle"
        self.speech_ms = 0
        self.silence_ms = 0
        self.silence_hangover_ms = silence_hangover_ms
        self.min_speech_ms = min_speech_ms

    def update(self, is_speech, chunk_ms=20):
        if is_speech:
            self.speech_ms += chunk_ms
            self.silence_ms = 0
            if self.state == "idle" and self.speech_ms >= self.min_speech_ms:
                self.state = "speaking"
                return "START"
        else:
            self.silence_ms += chunk_ms
            if self.state == "speaking" and self.silence_ms >= self.silence_hangover_ms:
                self.state = "idle"
                self.speech_ms = 0
                return "END"
        return None
```

### Шаг 4: скелет приёма flush

```python
def flush_on_end(stt_client, audio_buffer):
    stt_client.send_audio(audio_buffer)
    stt_client.send_flush()
    return stt_client.recv_transcript(timeout_ms=150)
```

STT (Kyutai, Deepgram, AssemblyAI) должен поддерживать flush, чтобы это работало. Потоковый Whisper — нет: он работает блоками и всегда ждёт полные фрагменты.

## Применение

| Ситуация | Выбор VAD |
|-----------|-----------|
| Открытый, быстрый, общего назначения | Silero VAD |
| Коммерческий колл-центр | Cobra VAD |
| На устройстве (телефон) | Silero VAD ONNX |
| Исследования / диаризация | pyannote segmentation |
| Резервный вариант без зависимостей | WebRTC VAD (устаревший) |
| Нужно качественное определение конца реплики | Silero + LiveKit turn-detector в связке |

Эмпирическое правило: никогда не выпускайте в продакшен только энергетический VAD, если у вас действительно нет других вариантов.

## Ловушки

- **Фиксированный порог.** Работает в тишине, не работает в шуме. Либо калибруйте на устройстве, либо переходите на Silero.
- **Слишком короткая пауза после речи.** Агент перебивает пользователя на полуслове. 500-800 мс — оптимальный диапазон для разговорной речи.
- **Слишком длинная пауза.** Ощущается медлительным. Проведите A/B-тест с целевыми пользователями.
- **Отсутствие буфера перед речью.** Теряются первые 200-300 мс аудио пользователя. Всегда держите скользящий буфер перед речью.
- **Игнорирование семантического end-pointing.** Фраза «Хм, дайте подумать...» содержит длинные паузы. Пользователи ненавидят, когда их обрывают на полумысли. Используйте LiveKit turn-detector или аналог.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py`. Он симулирует последовательность речь + тишина + речь + кашель и тестирует три уровня VAD.
2. **Среднее.** Установите `silero-vad`, обработайте 5-минутную запись, подберите порог, чтобы минимизировать и обрезку первых слов, и ложные срабатывания. Приведите значения precision/recall.
3. **Сложное.** Постройте мини-детектор реплик: Silero VAD + 3-слойный MLP на эмбеддингах последних 10 слов (используйте sentence-transformers). Обучите на вручную размеченном наборе данных с метками конца реплики. Превзойдите чистый Silero на 10% по F1.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| VAD | Детектор голоса | Бинарное решение на уровне кадра: это речь? |
| Turn detection (определение конца реплики) | End-pointing | VAD + пауза после речи + семантическая конечная точка. |
| Silence hangover (пауза после речи) | Время ожидания после речи | Время ожидания перед объявлением конца реплики; 500-800 мс. |
| Pre-roll (буфер перед речью) | Буфер перед речью | Хранить 300-500 мс аудио до срабатывания VAD. |
| Flush trick (приём flush) | Хак от Kyutai | VAD → flush-STT → 125 мс вместо задержки 500 мс. |
| Semantic endpoint (семантическая конечная точка) | «Он правда закончил?» | ML-классификатор, который учитывает слова, а не только тишину. |
| TPR @ FPR 5% | Точка ROC-кривой | Стандартный бенчмарк VAD; 87,7% для Silero, 50% для WebRTC. |
