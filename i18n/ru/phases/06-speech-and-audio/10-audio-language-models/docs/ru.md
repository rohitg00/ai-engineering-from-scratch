# Аудио-языковые модели — Qwen2.5-Omni, Audio Flamingo, GPT-4o Audio

> Аудио-языковые модели 2026 года рассуждают над речью + звуками окружения + музыкой. Qwen2.5-Omni-7B соответствует GPT-4o Audio на MMAU-Pro. Audio Flamingo Next превосходит Gemini 2.5 Pro на LongAudioBench. Разрыв между открытыми и закрытыми моделями практически закрыт — за исключением задач с несколькими аудио, где все находятся около уровня случайности.

**Тип:** Learn**Языки:** Python**Предварительные требования:** Фаза 6 · 04 (ASR), Фаза 12 · 03 (Vision-Language Models), Фаза 7 · 10 (Audio Transformers)**Время:** ~45 минут
## Проблема

У вас есть 5 секунд аудио: лай собаки, чей-то крик «stop!», затем тишина. Полезные вопросы охватывают несколько осей:

- **Транскрипция.** «Что было сказано?» — территория ASR.
- **Семантическое рассуждение.** «Человек в опасности?» — требует совместного понимания лая + крика + тишины.
- **Музыкальное рассуждение.** «Какие инструменты играют мелодию?»
- **Поиск по длинному аудио.** «В каком месте этой 90-минутной лекции преподаватель объяснял градиентный спуск?»

Единая модель, отвечающая на всё это одним промптом, — это **аудио-языковая модель** (LALM / ALM). Отличается от чистого ASR: LALM выдаёт свободные ответы на естественном языке, а не только транскрипты.

## Концепция

![Аудио-языковая модель: аудиоэнкодер + проектор + LLM-декодер](../assets/alm-architecture.svg)

### Шаблон из трёх компонентов

Каждая LALM 2026 года имеет один и тот же скелет:

1. **Аудиоэнкодер.** Whisper encoder · BEATs · CLAP · WavLM · либо собственный энкодер конкретной модели.
2. **Проектор.** Линейный слой или MLP, соединяющий признаки аудиоэнкодера с пространством токен-эмбеддингов LLM.
3. **LLM.** Декодер на базе Llama / Qwen / Gemma. Принимает чередующиеся текстовые и аудио-токены; генерирует текст.

Обучение:

- **Этап 1.** Заморозить энкодер + LLM; обучать только проектор на данных ASR / captioning.
- **Этап 2.** Полное или LoRA-дообучение на задачах следования инструкциям с аудио (QA, рассуждение, понимание музыки).
- **Этап 3 (опционально).** Добавление голосового ввода/вывода с помощью речевого декодера. Так делают Qwen2.5-Omni и AF3-Chat.

### Где LALM полезны в 2026 году

- **Комплаенс-аудит записей колл-центра.** «Упомянул ли агент обязательное уведомление?»
- **Доступность.** Описание звуковых событий для глухих пользователей (не только транскрипция).
- **Модерация контента.** Обнаружение агрессивной речи + угрожающего тона + фонового контекста.
- **Разбивка на главы подкастов / встреч.** Смысловое резюме, а не только реплики говорящих.
- **Анализ музыкального каталога.** «Найти все треки со сменой тональности в B-секции».

### Где они (пока) НЕ полезны

- Тонкая музыкальная теория (ниже уровня аккордов).
- Рассуждение с привязкой к говорящему в длинных разговорах (деградирует после 10 минут).
- Сравнение нескольких аудио (22-26% — едва выше случайности).
- Потоковое рассуждение в реальном времени (большинство работают офлайн, пакетно).

## Постройте это

### Шаг 1: запрос к Qwen2.5-Omni

```python
from transformers import AutoModelForCausalLM, AutoProcessor

processor = AutoProcessor.from_pretrained("Qwen/Qwen2.5-Omni-7B")
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-Omni-7B", torch_dtype="auto")

audio, sr = load_wav("clip.wav", sr=16000)
messages = [{
    "role": "user",
    "content": [
        {"type": "audio", "audio": audio},
        {"type": "text", "text": "What sounds do you hear, and what's happening?"},
    ],
}]
inputs = processor.apply_chat_template(messages, tokenize=True, return_tensors="pt")
output = model.generate(**inputs, max_new_tokens=200)
print(processor.decode(output[0], skip_special_tokens=True))
```

### Шаг 2: паттерн проектора

```python
import torch.nn as nn

class AudioProjector(nn.Module):
    def __init__(self, audio_dim=1280, llm_dim=4096):
        super().__init__()
        self.down = nn.Linear(audio_dim, llm_dim)
        self.act = nn.GELU()
        self.up = nn.Linear(llm_dim, llm_dim)

    def forward(self, audio_features):
        return self.up(self.act(self.down(audio_features)))
```

Вот и всё. Проектор обычно — это 1-3 линейных слоя. Его обучение на парах ASR (аудио → транскрипт) — это претекстная задача этапа 1.

### Шаг 3: бенчмаркинг MMAU / LongAudioBench

```python
from datasets import load_dataset
mmau = load_dataset("MMAU/MMAU-Pro")

correct = 0
for item in mmau["test"]:
    answer = call_model(item["audio"], item["question"], item["choices"])
    if answer == item["correct_choice"]:
        correct += 1
print(f"Accuracy: {correct / len(mmau['test']):.3f}")
```

Указывайте результат по каждой категории (речь / звук / музыка / несколько аудио) отдельно. Агрегированные цифры скрывают, где модель ошибается.

## Ловушки

- **Излишнее доверие на задачах с несколькими аудио.** Если вашей задаче нужно «в каком клипе X», уровень производительности, близкий к случайному, — это реальность.
- **Деградация на длинном аудио.** После 10 минут привязка к говорящему у большинства моделей ломается. Сначала выполните диаризацию (урок 6), затем суммируйте.
- **Галлюцинации на тишине.** Та же проблема в стиле Whisper унаследована LALM, использующими Whisper-энкодер. Используйте VAD-фильтрацию.
- **Cherry-picking в бенчмарках.** Блог-посты поставщиков выделяют лучшие категории. Запустите подмножество MMAU-Pro с несколькими аудио самостоятельно.
