# Основы аудио — волновая форма, дискретизация, преобразование Фурье

> Волновая форма — это исходный сигнал. Спектрограмма — это представление. Mel-признаки — форма, удобная для ML. Каждый современный пайплайн ASR и TTS проходит по этой лестнице, и первая ступень — понимание дискретизации и преобразования Фурье.

**Тип:** Learn

**Предварительные требования:** Фаза 1 · 06 (Векторы и матрицы), Фаза 1 · 14 (Распределения вероятностей)

## Проблема

Микрофон производит сигнал «давление относительно времени». Ваша нейросеть потребляет тензоры. Между ними — стек соглашений, нарушение которых порождает молчаливые баги: модель обучается нормально, но WER удваивается, TTS выдаёт шипение, или система клонирования голоса запоминает микрофон вместо говорящего.

Каждый баг в речевых системах сводится к одному из трёх вопросов:

1. На какой частоте дискретизации записаны данные и чего ожидает модель?
2. Не появился ли в сигнале алиасинг?
3. Вы работаете с необработанными отсчётами или с частотным представлением?

Разберитесь с этим — и оставшаяся часть Фазы 6 станет посильной. Ошибётесь — и даже Whisper-Large-v4 будет выдавать мусор.

## Концепция

![Визуализация волновой формы, дискретизации, ДПФ и частотных бинов](../assets/audio-fundamentals.svg)

**Волновая форма.** Одномерный массив чисел с плавающей точкой в диапазоне `[-1.0, 1.0]`. Индексируется номером отсчёта. Чтобы перевести в секунды, разделите на частоту дискретизации: `t = n / sr`. 10-секундный клип на 16 кГц — это массив из 160,000 чисел с плавающей точкой.

**Частота дискретизации (sr).** Сколько отсчётов в секунду. Распространённые частоты в 2026 году:

| Частота | Применение |
|------|-----|
| 8 кГц | Телефония, устаревший VOIP. Найквист на 4 кГц убивает согласные. Не подходит для ASR. |
| 16 кГц | Стандарт для ASR. Whisper, Parakeet, SeamlessM4T v2 — все используют 16 кГц. |
| 22.05 кГц | Обучение TTS-вокодеров для более старых моделей. |
| 24 кГц | Современный TTS (Kokoro, F5-TTS, xTTS v2). |
| 44.1 кГц | CD-аудио, музыка. |
| 48 кГц | Кино, профессиональное аудио, высококачественный TTS (VALL-E 2, NaturalSpeech 3). |

**Найквист—Шеннон.** Частота дискретизации `sr` позволяет однозначно представить частоты вплоть до `sr/2`. Граница `sr/2` — это *частота Найквиста*. Энергия выше Найквиста подвергается *алиасингу* — сворачивается в более низкие частоты — и искажает сигнал. Всегда применяйте фильтр нижних частот перед понижением частоты дискретизации.

**Битовая глубина.** 16-битный PCM (знаковый int16, диапазон ±32,767) — универсальный формат обмена. 24 бита — для музыки, 32-битный float — для внутренней DSP-обработки. Библиотеки вроде `soundfile` читают int16, но отдают массивы float32 в диапазоне `[-1, 1]`.

**Преобразование Фурье.** Любой конечный сигнал — это сумма синусоид на разных частотах. Дискретное преобразование Фурье (ДПФ) вычисляет для `N` отсчётов `N` комплексных коэффициентов — по одному на каждый частотный бин. `bin k` соответствует частоте `k · sr / N` Гц. Модуль — это амплитуда на данной частоте, угол — фаза.

**FFT.** Быстрое преобразование Фурье: алгоритм со сложностью `O(N log N)` для вычисления ДПФ, когда `N` — степень двойки. Каждая аудиобиблиотека использует FFT «под капотом». FFT по 1024 отсчётам на частоте 16 кГц даёт 512 полезных частотных бинов, охватывающих диапазон 0–8 кГц с разрешением 15.6 Гц.

**Кадрирование и оконная функция.** Мы не применяем FFT ко всему клипу целиком. Мы разбиваем его на перекрывающиеся *фреймы* (обычно 25 мс с шагом 10 мс), умножаем каждый фрейм на оконную функцию (Ханна, Хэмминга), чтобы устранить разрывы на границах, а затем применяем FFT к каждому фрейму. Это кратковременное преобразование Фурье (Short-Time Fourier Transform, STFT). Урок 02 продолжает эту тему.

## Постройте это

### Шаг 1: прочитайте клип и постройте график волновой формы

`code/main.py` использует только модуль стандартной библиотеки `wave`, чтобы демонстрация не имела внешних зависимостей. В продакшене вы будете использовать `soundfile` или `torchaudio.load` (оба возвращают кортежи `(waveform, sr)`):

```python
import soundfile as sf
waveform, sr = sf.read("clip.wav", dtype="float32")  # shape (T,), sr=int
```

### Шаг 2: синтезируйте синусоиду с нуля

```python
import math

def sine(freq_hz, sr, seconds, amp=0.5):
    n = int(sr * seconds)
    return [amp * math.sin(2 * math.pi * freq_hz * i / sr) for i in range(n)]
```

Синусоида 440 Гц (концертный ля) на 16 кГц в течение 1 секунды — это 16,000 чисел с плавающей точкой. Запишите с помощью `wave.open(..., "wb")`, используя 16-битное PCM-кодирование.

### Шаг 3: вычислите ДПФ вручную

```python
def dft(x):
    N = len(x)
    out = []
    for k in range(N):
        re = sum(x[n] * math.cos(-2 * math.pi * k * n / N) for n in range(N))
        im = sum(x[n] * math.sin(-2 * math.pi * k * n / N) for n in range(N))
        out.append((re, im))
    return out
```

`O(N²)` — годится для `N=256`, чтобы убедиться в корректности, но бесполезен для реального аудио. В реальном коде вызывают `numpy.fft.rfft` или `torch.fft.rfft`.

### Шаг 4: найдите доминирующую частоту

Индекс пика модуля `k_star` соответствует частоте `k_star * sr / N`. При запуске на синусоиде 440 Гц должен получиться пик в бине `440 * N / sr`.

### Шаг 5: продемонстрируйте алиасинг

Дискретизируйте синусоиду 7 кГц с частотой 10 кГц (Найквист = 5 кГц). Тон 7 кГц выше Найквиста и сворачивается в `10 − 7 = 3 kHz`. Пик FFT появляется на 3 кГц. Это классическая демонстрация алиасинга и причина, по которой каждый ЦАП/АЦП оснащается фильтром нижних частот с прямоугольной АЧХ.

## Применение

Стек, который вы реально будете использовать в продакшене в 2026 году:

| Задача | Библиотека | Почему |
|------|---------|-----|
| Чтение/запись WAV/FLAC/OGG | `soundfile` (обёртка над libsndfile) | Самый быстрый, стабильный, возвращает float32. |
| Ресэмплинг | `torchaudio.transforms.Resample` или `librosa.resample` | Встроенный корректный антиалиасинг. |
| STFT / Mel | `torchaudio` или `librosa` | Дружественны к GPU; экосистема PyTorch. |
| Потоковая обработка в реальном времени | `sounddevice` или `pyaudio` | Кроссплатформенные привязки к PortAudio. |
| Проверка файла | `ffprobe` или `soxi` | CLI, быстрый, показывает sr/каналы/кодек. |

Правило принятия решения: **сначала приведите в соответствие частоту дискретизации, а всё остальное потом**. Whisper ожидает 16 кГц, моно, float32. Подайте на вход 44.1 кГц стерео — и получите мусор, который будет выглядеть как баг модели.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Частота дискретизации | Сколько отсчётов в секунду | Частота в Гц, с которой АЦП измеряет сигнал. |
| Найквист | Максимальная частота, которую можно представить | `sr/2`; энергия выше этого порога сворачивается вниз. |
| Битовая глубина | Разрешение каждого отсчёта | `int16` = 65,536 уровней; `float32` = 24-битная точность в `[-1, 1]`. |
| ДПФ | Преобразование Фурье для последовательностей | `N` отсчётов → `N` комплексных частотных коэффициентов. |
| FFT | Быстрый вариант ДПФ | Алгоритм `O(N log N)`, требующий, чтобы `N` было степенью двойки. |
| Частотный бин | Частотный столбец | `k · sr / N` Гц; разрешение = `sr / N`. |
| STFT | То, что скрывается за спектрограммой | FFT по фреймам с оконной функцией во времени. |
| Алиасинг | Странные частотные «призраки» | Энергия выше Найквиста, отражающаяся вниз в более низкие бины. |
