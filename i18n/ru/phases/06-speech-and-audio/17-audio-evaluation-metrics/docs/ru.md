## Проблема

У каждой аудиозадачи несколько метрик, каждая измеряет разную ось. Использование неверной метрики — вот как получается модель, которая отлично выглядит на вашей панели показателей и ужасно ведёт себя в продакшене. Канонический список 2026 года:

| Задача | Основная метрика | Вторичная метрика |
|------|---------|-----------|
| ASR | WER | CER · RTFx · задержка первого токена |
| TTS | MOS / UTMOS | SECS · WER по обратному прогону через ASR · CER · TTFA |
| Клонирование голоса | SECS (ECAPA-косинус) | MOS · CER |
| Верификация говорящего | EER | minDCF · FAR / FRR в рабочей точке |
| Диаризация | DER | JER · спутывание говорящих |
| Классификация аудио | top-1 · mAP | macro F1 · полнота по классам |
| Генерация музыки | FAD | CLAP · MOS панели прослушивания |
| Аудио-языковая модель | MMAU-Pro | LongAudioBench · AudioCaps FENSE |
| Потоковый S2S | задержка P50/P95 | WER · MOS |

### Метрики ASR

**WER (Word Error Rate, доля ошибок по словам).** `(S + D + I) / N`. Приводите к нижнему регистру, удаляйте пунктуацию, нормализуйте числа перед оцениванием. Используйте `jiwer` или `whisper_normalizer` от OpenAI. &lt; 5% = паритет с человеком на чтении вслух.

**CER (Character Error Rate, доля ошибок по символам).** Та же формула, на уровне символов. Используется для тональных языков (мандаринский, кантонский), где сегментация на слова неоднозначна.

**RTFx (обратный коэффициент реального времени).** Секунды аудио, обработанные за секунду настенного времени. Чем выше, тем лучше. Parakeet-TDT достигает 3380×. Whisper-large-v3 — около 30×.

**Задержка первого токена.** Настенное время от аудиовхода до первого токена транскрипта. Критично для потоковой передачи. Deepgram Nova-3: ~150 мс.

### Метрики TTS

**MOS (Mean Opinion Score, средняя оценка мнения).** Оценка человека от 1 до 5. Золотой стандарт, но медленный. Собирайте 20+ слушателей на образец, 100+ образцов на модель.

**UTMOS (2022-2026).** Обученный предиктор MOS. Коррелирует ~0,9 с человеческим MOS на стандартных бенчмарках. F5-TTS: UTMOS 3,95; эталон (ground truth): 4,08.

**SECS (Speaker Encoder Cosine Similarity, косинусное сходство энкодера говорящего).** Для клонирования голоса. ECAPA-эмбеддинг, косинус между эталоном и клонированным выводом. &gt; 0,75 = узнаваемый клон.

**WER по обратному прогону через ASR.** Прогоните Whisper по выводу TTS, вычислите WER относительно входного текста. Ловит регрессии разборчивости. SOTA 2026 года: &lt; 2% CER.

**TTFA (time-to-first-audio, время до первого аудио).** Настенная задержка. Kokoro-82M: ~100 мс; F5-TTS: ~1 с.

### Специфика клонирования голоса

**SECS + MOS + CER** как тройка. Клонирование с высоким SECS, но низким MOS означает верный тембр, но неестественность; обратная ситуация означает естественный голос, но неверного говорящего.

### Верификация говорящего

**EER (Equal Error Rate, уровень равных ошибок).** Порог, при котором частота ложных принятий (False Accept Rate) равна частоте ложных отказов (False Reject Rate). ECAPA на VoxCeleb1-O: 0,87%.

**minDCF (min Detection Cost, минимальная стоимость обнаружения).** Взвешенная стоимость в выбранной рабочей точке (часто FAR=0,01). Более значима для продакшена, чем EER.

### Диаризация

**DER (Diarization Error Rate, доля ошибок диаризации).** `(FA + Miss + Confusion) / total_speaker_time`. Пропущенная речь + ложная тревога речи + спутывание говорящих, каждое как доля. Встречи AMI: DER ~10-20% реалистично. pyannote 3.1 + коммерческий Precision-2: &lt;10% DER на хорошо записанном аудио.

**JER (Jaccard Error Rate, доля ошибок Жаккара).** Альтернатива DER, устойчива к смещению из-за коротких сегментов.

### Классификация аудио

Мультиметочная задача: **mAP (mean Average Precision, средняя точность)** по всем классам. AudioSet: 0,548 mAP для BEATs-iter3.

Взаимоисключающая многоклассовая: **top-1, top-5 accuracy**. Speech Commands v2: 99,0% top-1 (Audio-MAE).

Несбалансированная: **macro F1** + **полнота по классам**. Отчитывайтесь по классам — агрегированная точность скрывает, какие классы дают сбой.

### Генерация музыки

**FAD (Fréchet Audio Distance, расстояние Фреше по аудио).** Расстояние между распределениями VGGish-эмбеддингов настоящего и сгенерированного аудио. MusicGen-small на MusicCaps: 4,5. MusicLM: 4,0. Меньше — лучше.

**CLAP Score.** Оценка соответствия текст-аудио с использованием эмбеддингов CLAP. &gt; 0,3 = разумное соответствие.

**MOS панели прослушивания.** По-прежнему последнее слово для потребительской музыки. Suno v5 ELO 1293 на TTS Arena (по результатам парных предпочтений людей).

### Аудио-языковые бенчмарки

**MMAU (Massive Multi-Audio Understanding).** 10 тыс. пар аудио-вопрос-ответ.

**MMAU-Pro.** 1800 сложных пунктов, четыре категории: речь / звук / музыка / мульти-аудио. Случайный уровень 25% при 4 вариантах. Gemini 2.5 Pro в целом ~60%; мульти-аудио ~22% по всем моделям.

**LongAudioBench.** Многоминутные клипы с семантическими запросами. Audio Flamingo Next превосходит Gemini 2.5 Pro.

**AudioCaps / Clotho.** Бенчмарки для составления описаний (captioning). Метрики SPICE, CIDEr, FENSE.

### Потоковая передача речь-в-речь

**Задержка P50 / P95 / P99.** Настенное время от конца речи пользователя до первого слышимого ответа. Moshi: 200 мс; GPT-4o Realtime: 300 мс.

**WER / MOS** на выводе.

**Отзывчивость на прерывание (barge-in).** Время от прерывания пользователем до отключения звука ассистентом. Целевое значение &lt; 150 мс.

## Постройте это

### Шаг 1: WER с нормализацией

```python
from jiwer import wer, Compose, ToLowerCase, RemovePunctuation, Strip

transform = Compose([ToLowerCase(), RemovePunctuation(), Strip()])
score = wer(
    truth="Please turn on the lights.",
    hypothesis="please turn on the light",
    truth_transform=transform,
    hypothesis_transform=transform,
)
# ~0.17
```

### Шаг 2: WER обратного прогона TTS через ASR

```python
def ttr_wer(tts_model, asr_model, texts):
    errors = []
    for txt in texts:
        audio = tts_model.synthesize(txt)
        recog = asr_model.transcribe(audio)
        errors.append(wer(truth=txt, hypothesis=recog))
    return sum(errors) / len(errors)
```

### Шаг 3: SECS для клонирования голоса

```python
from speechbrain.inference.speaker import EncoderClassifier
sv = EncoderClassifier.from_hparams("speechbrain/spkrec-ecapa-voxceleb")

emb_ref = sv.encode_batch(load_wav("reference.wav"))
emb_clone = sv.encode_batch(load_wav("cloned.wav"))
secs = torch.nn.functional.cosine_similarity(emb_ref, emb_clone, dim=-1).item()
```

### Шаг 4: FAD для генерации музыки

```python
from frechet_audio_distance import FrechetAudioDistance
fad = FrechetAudioDistance()
score = fad.get_fad_score("generated_folder/", "reference_folder/")
```

### Шаг 5: EER для верификации говорящего (тот же код, что в Уроке 6)

```python
def eer(same_scores, diff_scores):
    thresholds = sorted(set(same_scores + diff_scores))
    best = (1.0, 0.0)
    for t in thresholds:
        far = sum(1 for s in diff_scores if s >= t) / len(diff_scores)
        frr = sum(1 for s in same_scores if s < t) / len(same_scores)
        if abs(far - frr) < best[0]:
            best = (abs(far - frr), (far + frr) / 2)
    return best[1]
```

## Используйте это

Сопровождайте каждый деплой фиксированным набором оценок (eval harness), который запускается при каждом обновлении модели. Три главных правила:

1. **Нормализуйте перед оцениванием.** Нижний регистр, удаление пунктуации, разворачивание чисел. Указывайте правило нормализации в отчёте.
2. **Отчитывайтесь по распределениям, а не по средним.** P50/P95/P99 для задержки. Полнота по классам для классификации. По категориям для MMAU.
3. **Запускайте один канонический публичный бенчмарк.** Даже если ваши продакшен-данные отличаются, отчётность по Open ASR / TTS Arena / MMAU позволяет рецензентам сравнивать «яблоки с яблоками».

## Подводные камни

- **Экстраполяция UTMOS.** Обучена на чистой речи в стиле VCTK; плохо оценивает шумное / клонированное / эмоциональное аудио.
- **Смещение панели MOS.** 20 работников Amazon Mechanical Turk ≠ 20 целевых пользователей. Платите за доменную панель, если ставки высоки.
- **FAD зависит от эталонного набора.** Сравнивайте с одним и тем же эталонным распределением по всем моделям.
- **Агрегированный WER.** 5% WER в целом может скрывать 30% WER на акцентированной речи. Отчитывайтесь по демографическому срезу.
- **Насыщение публичных бенчмарков.** Большинство передовых моделей близки к потолку на стандартных бенчмарках. Постройте собственный отложенный набор, отражающий ваш трафик.

1. **Лёгкое.** Запустите `code/main.py`. Вычислите WER / CER / EER / SECS / FAD-подобную метрику / MMAU-подобную метрику на игрушечных входных данных.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| WER | Оценка ASR | `(S+D+I)/N` на уровне слов после нормализации. |
| CER | Символьный WER | Для тональных языков или посимвольных систем. |
| MOS | Мнение человека | Оценка 1-5; 20+ слушателей × 100 образцов. |
| UTMOS | ML-предиктор MOS | Обученная модель; коррелирует ~0,9 с человеческим MOS. |
| SECS | Сходство клона голоса | ECAPA-косинус между эталоном и клоном. |
| EER | Оценка верификации говорящего | Порог, при котором FAR = FRR. |
| DER | Оценка диаризации | (FA + Miss + Confusion) / total. |
| FAD | Качество генерации музыки | Расстояние Фреше на VGGish-эмбеддингах. |
| RTFx | Пропускная способность | Секунды аудио на секунду настенного времени. |
