# Спекулятивное декодирование и EAGLE-3

> Фаза 7 · Урок 16 доказал математику: правило отклонения Левиафана точно сохраняет распределение верификатора. Этот урок рассматривает продакшн-спекулятивное декодирование 2026 года с точки зрения стека обучения. EAGLE-3 превратил драфт-модель из дешёвого приближения в специально спроектированную крошечную сеть, обученную на собственных скрытых состояниях верификатора, и добавил цикл тестирования во время обучения (training-time test), выравнивающий её распределения при обучении и выполнении вывода (инференс). Результат: сквозное ускорение в 3–6.5 раза, доля принятых токенов выше 0.9 в чате и никаких компромиссов в распределении. Каждый продакшн-стек инференса в 2026 году включает его по умолчанию.

## Проблема

Авторегрессионное декодирование на модели 70B работает со скоростью примерно 35 токенов в секунду на H100. GPU далёк от насыщения. Потолком является пропускная способность памяти: каждый токен загружает 70B весов из HBM, выполняет один шаг арифметики и производит одно число с плавающей точкой. Вычислительные блоки большую часть времени простаивают.

Спекулятивное декодирование превращает это в проблему пропускной способности, которую реально можно решить. Дешёвый драфт предлагает `N` токенов за `N` небольших прямых проходов. Верификатор запускается один раз на префиксе вместе со всеми `N` драфтами. Если распределение верификатора в позиции `i` согласуется с драфтом (в статистическом смысле, который мы уточним), мы принимаем токен; если нет — отклоняем его и сэмплируем поправку из остаточного распределения. Один большой прямой проход производит до `N+1` принятых токенов вместо одного.

Теорема, которая имеет значение — это Leviathan, Kalman, Matias (ICML 2023): результирующее распределение идентично тому, что дало бы прямое сэмплирование из верификатора. Не приблизительно. Идентично. Это и есть вся причина, по которой спекулятивное декодирование приемлемо в продакшне — это чистая оптимизация задержки без компромисса по качеству.

Фаза 7 · Урок 16 дала вам математику. Этот урок даёт стек обучения. Хороший драфт обеспечивает в 2 раза большее ускорение, чем просто дешёвый. EAGLE, EAGLE-2 и EAGLE-3 (Li et al., 2024–2025) превратили принцип «драфт = уменьшенная версия той же модели» в точную инженерную дисциплину. Продакшн-серверы инференса 2026 года по умолчанию используют EAGLE-3.

## Концепция

### Инвариант: отклоняющее сэмплирование Левиафана

Пусть `p(t)` — распределение драфта для следующего токена при некотором префиксе, а `q(t)` — распределение верификатора. Сэмплируем токен драфта `d ~ p`. Принимаем с вероятностью `min(1, q(d) / p(d))`. При отклонении сэмплируем из остаточного распределения `(q - p)_+ / ||(q - p)_+||_1`. Результирующие выборки распределены согласно `q`. Это верно независимо от того, насколько плох `p` — чем он хуже, тем чаще происходит отклонение, но результат остаётся точным.

Выстраиваем `N` таких вызовов подряд, используя один прямой проход верификатора на `prefix + d_1 + ... + d_N`. Верификатор возвращает `q_1, q_2, ..., q_{N+1}` одновременно. Проходим слева направо. При первом отклонении в позиции `j` сэмплируем из `residual(q_j, p_j)` и останавливаемся. При полном принятии сэмплируем один бонусный токен из `q_{N+1}`.

### Что определяет ускорение

Пусть `α` — ожидаемая доля принятия на токен драфта. Пусть `c = cost(draft) / cost(verifier)` — соотношение стоимостей. Ожидаемое количество принятых токенов за один прямой проход верификатора:

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

Ожидаемое общее время на один принятый токен: `(N * c + 1) / E[accepted]`. Минимизируйте это по `N` — получите оптимальную точку. Для `α = 0.8, c = 0.05`: оптимальное `N` около 5–7, ускорение 3.2×. Для `α = 0.95, c = 0.02`: оптимальное `N` около 8–10, ускорение приближается к 5×.

Самый мощный рычаг — это `α`. Переход от `α = 0.6` (ванильный драфт) к `α = 0.9` (EAGLE-3) при фиксированном `N = 5` увеличивает ожидаемое количество принятых токенов за прямой проход верификатора с 2.2 до 4.1. Почти 2-кратный прирост пропускной способности при том же верификаторе.

### Двухлетний прогресс

**Ванильное спекулятивное декодирование (Leviathan, 2023).** Драфт-модель — независимо обученная большая языковая модель (LLM) меньшего размера из того же семейства. Легко подключить, `α ≈ 0.6`, ускорение около 2× в лучшем случае.

**EAGLE-1 (Li et al., 2024).** Драфт — крошечный трансформер, обычно один-два слоя, который принимает скрытое состояние последнего слоя верификатора на вход и напрямую предсказывает следующий токен. Поскольку драфт видит представление признаков верификатора, его распределение намного ближе к распределению верификатора. `α` поднимается до 0.7–0.8.

**EAGLE-2 (Li et al., 2024).** Добавляет динамическое дерево драфта: вместо единой последовательности из `N` токенов предлагается небольшое дерево кандидатов, каждый из которых оценивается верификатором за один прямой проход с древовидным вниманием (tree attention), после чего выбирается путь с наивысшей вероятностью. Длина драфта становится адаптивной на каждом шаге. `α` на токен принятого пути поднимается выше 0.85.

**EAGLE-3 (Li et al., 2025, NeurIPS).** Ещё два изменения. Во-первых, полностью убрана функция потерь на предсказание признаков — EAGLE-1/2 обучали драфт соответствовать скрытым состояниям верификатора, что ограничивает пользу от увеличения объёма данных. EAGLE-3 обучается напрямую предсказывать токены. Во-вторых, тестирование во время обучения (TTT): при обучении драфта его собственные предыдущие предсказания подаются обратно на вход на протяжении нескольких шагов, точно так же, как это происходит при инференсе. Это согласует распределения при обучении и тестировании и останавливает накопление ошибок. Измеренное ускорение: до 6.5× в чате, прирост пропускной способности на 38% при размере пакета 64 в SGLang на H100.

### Откат KV-кеша

Верификация расширяет KV-кеш верификатора на `N` записей за один проход. Если отклонение происходит в позиции `j`, содержимое кеша после позиции `j-1` теперь неверно. Две распространённые реализации: запись во временный буфер с фиксацией при принятии (vLLM, TensorRT-LLM) либо хранение физического KV-кеша вместе с логической длиной и усечение при отклонении. В любом случае стоимость отката — байты на слой и голову, что пренебрежимо мало по сравнению со стоимостью прямого прохода.

Для поиска по дереву EAGLE-2 верификатор запускает механизм внимания с некаузальной маской, учитывающей топологию дерева. Инженерная реализация требует аккуратности, но вычисление представляет собой стандартный вызов FlashAttention с пользовательской маской.

## Реализация

См. `code/main.py`. Это полный спекулятивный цикл Левиафана со всеми составляющими: предложение серии из N токенов, параллельный проход верификатора, отклонение по позициям, остаточное сэмплирование, бонусный токен, откат KV-кеша и эмпирическая проверка того, что результирующее распределение совпадает с прямым сэмплированием из `q`.

### Шаг 1: правило отклонения

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### Шаг 2: остаточное распределение

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### Шаг 3: полный спекулятивный шаг

Функция `spec_step` предлагает `N` токенов из `p`, затем верифицирует их все за один параллельный расчёт `q`. Для каждого предложенного токена применяется правило отклонения, и при первом отклонении сэмплируется поправка из остатка. Если всё принято, выдаётся бонусный токен из `q_{N+1}`.

### Шаг 4: учёт отката KV

Симулятор отслеживает логическую `kv_length` на каждого воркера. При принятии `k` драфтов `kv_length += k`. При отклонении в позиции `j` содержимое кеша уже записано после `j`, но логическая длина устанавливается в `prefix_length + j + 1` — на одну позицию за токеном поправки. Последующие чтения усекаются до логической длины.

### Шаг 5: проверка Левиафана

Запустите 50 000 спекулятивных шагов. Посчитайте эмпирическое распределение принятых токенов. Сравните с 50 000 прямыми выборками из `q`. Статистика хи-квадрат должна оставаться заметно ниже критического значения. Теорема подтверждается на практике.

### Шаг 6: ускорение против α

Изменяйте качество драфта, отклоняя `p` от `q` с разной амплитудой. Измерьте `α`, затем постройте ожидаемое количество токенов за прямой проход верификатора как функцию `α` и `N`. Код выводит таблицу, показывающую, как качество драфта уровня EAGLE-3 (`α ≈ 0.9`) даёт 4–5 токенов за прямой проход верификатора.

## Применение

Продакшн-уровень `vllm serve` с EAGLE-3:

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

Согласно статье EAGLE-3, пропускная способность SGLang с EAGLE-3 при размере пакета 64 на H100 примерно в 1.38 раза выше, чем при обычном декодировании с пакетом того же размера.

Когда стоит применять спекулятивное декодирование:

- Любая интерактивная чат-нагрузка, где p50-задержка важнее пиковой пропускной способности.
- Генерация кода и структурированный вывод (JSON, SQL). `α` выше 0.9, потому что целевое распределение сильно предсказуемо.
- Генерация длинных текстов (тысячи токенов). Амортизированное ускорение продолжает окупаться.

Когда не стоит:

- Очень маленькие модели (< 3B). Драфт не намного дешевле верификатора.
- Небольшие развёртывания с размером пакета 1 на CPU. Накладные расходы памяти на драфт-модель могут того не стоить.
- Сэмплирование с очень высокой температурой для творческих задач, где `α` рушится.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Правило Левиафана | «min(1, q делить на p)» | Принятие или отклонение по схеме Бернулли с вероятностью `min(1, q(d)/p(d))`; если при отклонении сэмплировать из остаточного распределения, распределение верификатора сохраняется в точности |
| Остаточное распределение | «положительная часть q минус p, нормализованная» | `(q - p)_+`, ограниченное снизу нулём и повторно нормализованное, — правильное распределение для сэмплирования при отклонении |
| Доля принятия α | «как часто драфт оказывается прав» | Ожидаемая вероятность успеха испытания Бернулли для каждого токена по правилу отклонения; определяет всю математику ускорения |
| EAGLE-1 | «драфт по скрытому состоянию» | Крошечный драфт-трансформер, получающий на вход скрытое состояние последнего слоя верификатора (Li et al., 2024) |
| EAGLE-2 | «динамическое дерево драфта» | EAGLE-1 плюс дерево возможных продолжений, оцениваемых за один проход верификатора с древовидным вниманием |
| EAGLE-3 | «тестирование во время обучения» | Отказывается от функции потерь на предсказание признаков и обучается напрямую предсказывать токены, получая при обучении собственные выходные данные на вход |
| Тестирование во время обучения (TTT) | «устранение смещения экспозиции» | При обучении драфт запускается авторегрессионно, чтобы распределения входных данных при обучении и тестировании совпадали; это прямой аналог планового сэмплирования |
| Откат KV-кеша | «отменить отклонённые драфты» | Учётная операция, которая после отклонения сбрасывает KV-кеш верификатора до длины принятого префикса |
| Бонусный токен | «бесплатный токен» | Когда приняты все `N` драфтов, из `q_{N+1}` сэмплируется ещё один токен без дополнительных затрат на верификатор |
| Древовидное внимание | «проверить много кандидатов одновременно» | Внимание с некаузальной маской, учитывающей топологию дерева драфта; вычисляет `q_i` для каждого узла дерева за один прямой проход |

- [Li et al. — EAGLE-3: Scaling up Inference Acceleration via Training-Time Test (arXiv:2503.01840, NeurIPS 2025)](https://arxiv.org/abs/2503.01840) — продакшн-стандарт 2026 года
- [Cai et al. — Medusa: Multiple Decoding Heads (arXiv:2401.10774)](https://arxiv.org/abs/2401.10774) — альтернативный подход без драфта
