# Нативное разреженное внимание (DeepSeek NSA)

> При 64k токенов внимание съедает 70–80% задержки декодирования. У каждой лаборатории, разрабатывающей открытые модели, есть план, как это исправить. NSA от DeepSeek (лучшая статья ACL 2025) — тот подход, который прижился: три параллельные ветви внимания — сжатые крупноблочные токены, выборочно сохранённые мелкозернистые токены и скользящие окна для локального контекста — объединённые через обучаемый гейт. Механизм согласован с аппаратным обеспечением (дружественен к ядрам), нативно обучаем (работает уже на этапе предварительного обучения, а не пристёгнут к инференсу задним числом) и при декодировании на 64k токенов работает быстрее FlashAttention, при этом не уступая по качеству полному вниманию или превосходя его. В этом уроке мы реализуем все три ветви от начала до конца и покажем, почему разреженность полностью дифференцируема на всём пути вычислений.

**Тип:** Build
**Языки:** Python (stdlib)
**Предварительные требования:** Фаза 7 · 12 (KV-кеш, flash-attention), фаза 7 · 15 (варианты внимания), фаза 10 · 16 (дифференциальное внимание)
**Время:** ~60 минут

## Проблема

Полное внимание при длине последовательности N стоит `O(N^2)` по времени и `O(N)` по KV-кешу на слой. При 64k токенов цифры по вычислениям и пропускной способности памяти катастрофичны. Оценка из статьи NSA: внимание составляет 70–80% общей задержки декодирования при 64k. Всё, что идёт дальше по конвейеру, — TTFT, токенов в секунду, стоимость на миллион токенов — определяется стоимостью внимания.

Разреженное внимание — очевидный ответ. Предыдущие попытки делятся на две категории. Разреженность с фиксированным паттерном (скользящее окно, страйдовая, блочно-локальная) отбрасывает информацию и не справляется с задачами дальнего восстановления. Разреженность на этапе инференса (обрезка KV-кеша, H2O, StreamingLLM) применяется к модели, предварительно обученной на плотном внимании, и даёт лишь часть потенциального ускорения, потому что модель никогда не обучалась направлять информацию через разреженный паттерн.

Native Sparse Attention (Yuan et al., DeepSeek + PKU + UW, лучшая статья ACL 2025, arXiv:2502.11089) делает и то, и другое: паттерн разреженности модель изучает во время предварительного обучения, а реализован он как алгоритм, согласованный с ядрами GPU, который действительно даёт экономию вычислений на инференсе. Через два года NSA или его прямой потомок станет вниманием по умолчанию для каждой передовой модели с длинным контекстом.

## Концепция

### Три параллельные ветви

Для каждого запроса NSA выполняет внимание трижды, против трёх разных представлений KV-кеша:

1. **Сжатая ветвь.** Токены группируются в блоки размера `l` (обычно 32 или 64). Каждый блок сжимается в один суммарный токен с помощью небольшого обучаемого MLP. Запрос применяет внимание к этим сжатым токенам, получая крупноблочное представление всей последовательности.

2. **Выбранная ветвь.** С помощью оценок внимания из сжатой ветви определяются top-k блоков, наиболее релевантных текущему запросу. Из этих блоков считываются мелкозернистые (несжатые) токены, и запрос применяет к ним внимание. Внимание сжатой ветви можно рассматривать как сигнал маршрутизации для отбора.

3. **Ветвь скользящего окна.** Запрос применяет внимание к последним `W` токенам (обычно 512) для локального контекста. Эта ветвь улавливает насыщенные структурой краткосрочные паттерны (синтаксис, локальная кореференция), которые могут упустить две другие.

Выходы трёх ветвей объединяются через обучаемый позиционный гейт:

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` — это веса гейта, получаемые из небольшого MLP над запросом. Они не обязаны в сумме давать 1 — они могут взвешивать ветви независимо.

### Почему это «нативно обучаемо»

Шаг отбора (top-k блоков) дискретен. Дискретные операции разрывают поток градиента. Предыдущие работы по разреженному вниманию либо пропускали обратное распространение через отбор (что ограничивало обучение), либо использовали непрерывные релаксации, которые не давали настоящей разреженности на инференсе.

NSA обходит эту проблему: внимание сжатой ветви — это и есть дифференцируемое крупноблочное внимание по всей последовательности. Операция top-k просто переиспользует лучшие оценки внимания из сжатой ветви, чтобы выбрать, какие мелкозернистые блоки загружать. Градиенты текут через оценки сжатой ветви (которые влияют и на сжатый выход, и на логику отбора), а вклад выбранных блоков в итоговый выход тоже дифференцируем. Недифференцируемая операция `top_k` ничего не меняет в прямом вычислительном графе: она лишь определяет, какие блоки загружаются из памяти.

Именно поэтому NSA можно использовать в предварительном обучении целиком, от начала до конца. Модель учится совместно направлять информацию через три ветви, порождая разреженный паттерн, который на инференсе действительно даёт обещанное ускорение.

### Ядро, согласованное с аппаратным обеспечением

Ядро NSA спроектировано под современные иерархии памяти GPU. Ядро загружает запросы по группам GQA (внешний цикл), выбирает соответствующие разреженные KV-блоки для каждой группы (внутренний цикл) и выполняет внимание в SRAM. Поскольку каждая группа запросов видит одни и те же выбранные блоки (отбор происходит на уровне группы запросов, а не отдельной головы), загрузки KV амортизируются по всей группе. Арифметическая интенсивность остаётся высокой.

В статье сообщается, что ядра на Triton работают в 9 раз быстрее FlashAttention при декодировании на 64k, причём коэффициент ускорения растёт вместе с длиной последовательности. Предоставлены и прямые, и обратные ядра.

### Бюджет вычислений

Пусть `N` — длина последовательности, `l` — размер блока сжатия, `k` — количество отбираемых top-k блоков, `w` — размер скользящего окна, `b` — размер выбираемого блока (обычно равен `l`).

- Сжатая ветвь: `O(N/l)` ключей на запрос, итого `O(N * N / l)`.
- Выбранная ветвь: `O(k * b)` ключей на запрос, итого `O(N * k * b)`.
- Ветвь скользящего окна: `O(w)` ключей на запрос, итого `O(N * w)`.

Итого: `O(N * (N/l + k*b + w))`.

При `N = 64k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос составляет `1000 + 1024 + 512 = 2536 keys`. Полное внимание — `64000 keys`. Сокращение вычислений в 25 раз.

При `N = 128k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос — `2000 + 1024 + 512 = 3536 keys`. Полное внимание — `128000 keys`. Сокращение в 36 раз. Выигрыш растёт вместе с длиной последовательности — в этом и весь смысл.

### Как это сравнивается

| Метод | Дифференцируемость | Реальное ускорение инференса | Воспроизведение на больших расстояниях |
|--------|---------------|----------------------|-------------------|
| Только скользящее окно | да | да | не справляется |
| Страйдовое / блочно-разреженное | да | да | частично |
| Обрезка KV (H2O, StreamingLLM) | Н/П (только инференс) | да | частично |
| MoBA (Moonshot) | частично | да | хорошо |
| NSA | да (нативно) | да (9x при 64k) | не уступает полному вниманию |

MoBA (Moonshot, arXiv:2502.13189) была опубликована одновременно и использует похожий подход «три лучше одной», применяя принцип MoE к блокам внимания. NSA и MoBA — две архитектуры, которые нужно знать для предварительного обучения с длинным контекстом в 2026 году.

## Реализация

`code/main.py` реализует три ветви на короткой синтетической последовательности и показывает:

- MLP сжатия (для наглядности используется простая базовая реализация на основе усреднения; настоящий NSA использует обучаемый MLP).
- Отбор top-k блоков, управляемый оценками сжатой ветви.
- Внимание скользящего окна по последним `w` токенам.
- Гейтированное объединение.
- Вывод количества вычислений в сравнении с полным вниманием.

### Шаг 1: сжатие токенов в блоки

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### Шаг 2: внимание сжатой ветви

Выполните softmax-внимание запроса к сжатым ключам. Оценки сжатой ветви одновременно служат сигналом для отбора top-k.

### Шаг 3: отбор top-k блоков

Выберите индексы `k` сжатых блоков с наивысшими оценками. Загрузите исходные несжатые токены из этих блоков и выполните на них внимание.

### Шаг 4: внимание скользящего окна

Возьмите последние `w` токенов и выполните к ним стандартное внимание.

### Шаг 5: гейт и объединение

Небольшой MLP над запросом выдаёт три веса гейта. Итоговый выход — взвешенная сумма выходов трёх ветвей.

### Шаг 6: подсчёт вычислений

Выведите количество ключей, к которым применяется внимание на запрос, для каждой ветви и суммарно. Сравните с `N` (полное внимание). На синтетике из 1024 токенов при `l = 32, k = 4, w = 128` NSA видит `32 + 128 + 128 = 288` ключей на запрос против 1024 для полного внимания — в 3,5 раза меньше.

## Применение

NSA уже используется в собственном конвейере предварительного обучения DeepSeek с длинным контекстом. Статус интеграции в публичных инференс-стеках по состоянию на апрель 2026 года:

- **Внутренняя инфраструктура DeepSeek**: нативная поддержка; опубликованные веса используют NSA или его преемника DSA (Deepseek Sparse Attention).
- **vLLM**: экспериментальная поддержка NSA в разработке для весов DeepSeek-V3.x.
- **SGLang**: опубликованы бенчмарки NSA; путь в продакшен следует за vLLM.
- **llama.cpp / CPU**: не поддерживается; накладные расходы на декомпозицию ядра не оправдываются при пропускной способности CPU.

Когда стоит использовать NSA:

- Запуск предварительного обучения или продолженного обучения, нацеленный на контекст от 64k и выше, при серьёзном вычислительном бюджете.
- Инференс собственных контрольных точек DeepSeek с длинным контекстом. Веса нативно поддерживают NSA.

Когда не стоит:

- Обслуживание уже существующей модели, предварительно обученной на плотном внимании. Встроить NSA задним числом без продолженного обучения нельзя.
- Контекст менее 16k. Накладные расходы на три ветви перевешивают экономию.
- Интерактивный чат с пакетом из одного запроса. Декодирование, чувствительное к задержке, выигрывает, но только при длинном контексте.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Сжатая ветвь | «Общее представление» | Внимание по усреднённым в пределах блоков ключам, обеспечивающее глобальный контекст при O(N/l) ключей на запрос |
| Выбранная ветвь | «Блоки top-k» | Мелкозернистое внимание по `k` блокам с наивысшими оценками сжатой ветви |
| Скользящее окно | «Локальный контекст» | Внимание по последним `W` токенам для краткосрочных паттернов |
| Нативная обучаемость | «Предварительное обучение сразу с разреженностью» | Паттерн разреженности изучается во время предварительного обучения, а не добавляется задним числом на этапе инференса |
| Размер блока сжатия l | «Размер группы для общего представления» | Количество токенов, объединяемых в одно суммарное представление; обычно 32–64 |
| Top-k | «Блоки, которые нужно сохранить» | Число сжатых блоков, из которых считываются несжатые токены; обычно 16 |
| Скользящее окно W | «Радиус локального внимания» | Обычно 512; меньшее значение ухудшает локальную связность, большее расходует вычислительные ресурсы впустую |
| Гейт ветвей | «Как объединить три ветви» | Выход позиционного MLP, взвешивающий вклады трёх ветвей |
| Согласованность с аппаратным обеспечением | «Разреженность, удобная для ядра» | Паттерн разреженности выбран так, чтобы фактическое ядро GPU обеспечивало теоретическое ускорение |
| DSA | «Преемник NSA» | Deepseek Sparse Attention — архитектура, пришедшая на смену NSA в линейке DeepSeek |
