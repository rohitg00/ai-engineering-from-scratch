# Градиентный чекпоинтинг и пересчёт активаций

> Обратное распространение ошибки хранит каждую промежуточную активацию. При 70B параметров и контексте 128K это 3 TB активаций на ранг. Чекпоинтинг обменивает FLOPs на память: пересчитать вместо того, чтобы сохранить. Вопрос в том, какие сегменты отбросить, и ответ не «все».

**Тип:** Build
**Языки:** Python (с numpy, опционально torch)
**Предварительные требования:** Фаза 10, урок 04 («Предварительное обучение Mini-GPT»), фаза 10, урок 05 («Масштабирование и распределённые вычисления»)
**Время:** ~70 минут

## Проблема

Обучение трансформера сохраняет для каждого слоя входы каждой операции, которая дифференцируется в обратном проходе: входы внимания, проекции Q/K/V, выход softmax, входы FFN, выходы нормализации и остаточный поток. Для слоя со скрытым размером `d`, длиной последовательности `L`, батчем `B` это порядка `12 * B * L * d` чисел с плавающей точкой на слой.

При `d=8192, L=8192, B=1` это 800 MB/слой в BF16. Модель из 64 слоёв — это 51 GB активаций — и это до умножения на размер микробатча, до добавления промежуточных значений softmax внимания (`L^2` на голову) и до учёта частичных копий при тензорном параллелизме.

Двусторонний счёт: веса в BF16 плюс состояние оптимизатора могут поместиться в 80GB, но активации выталкивают вас за этот предел. Градиентный чекпоинтинг (он же пересчёт активаций, activation recomputation) — стандартное решение. Отбросьте большую часть активаций; повторно выполните прямой проход во время обратного, чтобы получить их снова. Цена: дополнительные FLOPs. Выгода: память падает пропорционально отношению числа сегментов чекпоинтинга к общему числу слоёв.

Сделанный наивно, чекпоинтинг стоит примерно на 33% больше FLOPs прямого прохода за шаг. Сделанный хорошо — по принципу «умного отбора» Korthikanti et al. — вы экономите память в 5 раз при накладных расходах на FLOPs менее 5%. А с матричными умножениями в FP8, выгрузкой в FSDP и MoE с экспертным параллелизмом это действительно важно: вы не можете позволить себе ни лишнюю память, ни впустую потраченные вычисления.

## Концепция

### Что на самом деле нужно обратному проходу

`output = layer(input)`. Обратному проходу нужны `grad_input` и `grad_params`. Чтобы их вычислить, ему требуются:

- `input` (чтобы вычислить `grad_params = input.T @ grad_output` для линейных слоёв);
- некоторые промежуточные значения производных активаций (производная ReLU/GELU/softmax зависит от значения активации).

Прямой проход сохраняет их автоматически в графе автоградиента. Каждый `tensor.retain_grad()` и каждая операция, которой нужен её вход, удерживают на него ссылку.

### Наивный полный чекпоинтинг

Разбейте сеть на `N` сегментов. Во время прямого прохода сохраняйте только *вход* каждого сегмента. Когда обратному проходу нужны промежуточные значения, заново выполните прямой проход сегмента, чтобы материализовать их, а затем продифференцируйте.

Пример: 32-слойный трансформер, разбитый на 32 сегмента по 1 слою.

- Память: 32 входа слоёв (маленькие) против 32 * (объём активаций на слой) (огромный).
- Дополнительные вычисления: 1 дополнительный прямой проход на сегмент, то есть примерно на 33% больше FLOPs прямого прохода в сумме (поскольку обратный проход в 2 раза дороже прямого, полный шаг становится 1 + 1 + 2 = 4 единицы вместо 1 + 2 = 3).

Это оригинальный рецепт Chen et al. 2016: одна контрольная точка через каждые `sqrt(L)` слоёв, чтобы сбалансировать память и вычисления. При L=64 это 8 контрольных точек.

### Выборочный чекпоинтинг (Korthikanti, 2022)

Не все активации стоят одинаково. Выход softmax внимания — это `B*L*L*heads`, растущий *квадратично* с длиной последовательности. Скрытая активация FFN — это `B*L*4d`, растущая линейно. При длинных последовательностях softmax доминирует.

Выборочный чекпоинтинг сохраняет дешёвые для хранения активации (линейные проекции, остатки) и пересчитывает только дорогие (внимание). Вы платите минимум FLOPs за пересчёт, но экономите память O(L^2).

Megatron-Core реализует это как «выборочный» (selective) пересчёт активаций. Используется в большинстве промышленных запусков обучения 2024+ годов.

### Выгрузка активаций

Альтернатива пересчёту: перенести активации в оперативную память CPU между прямым и обратным проходом. Требует пропускной способности PCIe; полезно, когда простаивающая пропускная способность превышает стоимость повторной материализации. Смешанные стратегии распространены: контрольные точки для одних слоёв, выгрузка для других.

FSDP2 предоставляет выгрузку как полноценную встроенную опцию. Она особенно эффективна, когда GPU упирается в память, но у обмена данными CPU-GPU есть запас.

### Модель стоимости пересчёта

FLOPs на шаг при наивном чекпоинтинге через каждые `k` слоёв из `L`:

```
flops_fwd_normal = L * f_layer
flops_bwd_normal = 2 * L * f_layer
flops_total_normal = 3 * L * f_layer

flops_fwd_ckpt = L * f_layer
flops_recompute = L * f_layer  # one extra forward per layer in the segment
flops_bwd_ckpt = 2 * L * f_layer
flops_total_ckpt = 4 * L * f_layer
overhead = 4 / 3 - 1 = 0.33 = 33%
```

При выборочном чекпоинтинге вы пересчитываете только ядро внимания, а не весь слой:

```
flops_recompute_selective = L * f_attention ~= L * f_layer * 0.15
overhead_selective = (3 + 0.15) / 3 - 1 = 0.05 = 5%
```

### Модель экономии памяти

Объём активаций на слой: `A`. Для `L` слоёв общая память активаций: `L * A`.

Полный чекпоинтинг (размер сегмента 1): сохраняется только `L * input_volume` (~`L * 1/10 A` для стандартного трансформера). Экономия ~`9 * L * A * 1/10`.

Чекпоинтинг через каждые `k` слоёв: сохраняется `L/k * A` плюс объём в `k-1` слоёв внутри активного сегмента.

При `k = sqrt(L)` память и стоимость пересчёта обе масштабируются как `sqrt(L)` — оптимальный компромисс для слоёв с равномерной стоимостью.

### Когда не стоит чекпоинтить

- Самые внутренние слои этапа конвейера, уже находящегося в работе. Им всё равно нужно завершиться.
- Первый и последний слои, если они доминируют по вычислениям на этапе (редко в трансформерах).
- Ядра внимания, уже использующие FlashAttention — Flash уже быстро пересчитывает softmax, так что дополнительный чекпоинтинг на уровне слоя даёт мало сверх этого.

### Паттерны реализации

1. **Обёртка-функция:** оберните сегмент в `torch.utils.checkpoint.checkpoint(fn, input)`. PyTorch сохраняет только `input`, пересчитывает всё остальное при обратном проходе.

2. **На основе декораторов:** пометьте слои как поддерживающие чекпоинтинг; тренер решает на этапе конфигурации, какие сегменты обернуть.

3. **Ручной явный пересчёт:** напишите обратный проход самостоятельно, вызывая пользовательский `recompute_forward`, который дублирует прямой проход с сохранённым входом.

Все три способа дают одинаковый функциональный результат. Обёртки — стандартная идиома.

### Взаимодействие с TP / PP / FP8

- **Тензорный параллелизм:** при пересчёте входы контрольных точек необходимо собрать или заново распределить; учитывайте стоимость обмена данными.
- **Конвейерный параллелизм:** типичный паттерн — чекпоинтить прямой проход каждого этапа конвейера, чтобы микробатчи в обратном порядке могли переиспользовать память активаций.
- **Пересчёт в FP8:** истории amax, обновляемые при пересчёте, должны совпадать с историями исходного прямого прохода, иначе масштаб FP8 «уплывёт». Большинство фреймворков делают снимок масштаба.

## Реализация

### Шаг 1: игрушечная модель с сегментами

```python
import numpy as np


def linear_forward(x, w, b):
    return x @ w + b


def relu(x):
    return np.maximum(x, 0)


def layer_forward(x, w1, b1, w2, b2):
    h = relu(linear_forward(x, w1, b1))
    return linear_forward(h, w2, b2)


def model_forward(x, params):
    activations = [x]
    h = x
    for w1, b1, w2, b2 in params:
        h = layer_forward(h, w1, b1, w2, b2)
        activations.append(h)
    return h, activations
```

### Шаг 2: наивный обратный проход, требующий всех активаций

```python
def model_backward(grad_output, activations, params):
    grads = [None] * len(params)
    g = grad_output
    for i in range(len(params) - 1, -1, -1):
        w1, b1, w2, b2 = params[i]
        x_in = activations[i]
        h_pre = linear_forward(x_in, w1, b1)
        h = relu(h_pre)
        gh = g @ w2.T
        gw2 = h.T @ g
        gb2 = g.sum(axis=0)
        g_pre = gh * (h_pre > 0)
        gx = g_pre @ w1.T
        gw1 = x_in.T @ g_pre
        gb1 = g_pre.sum(axis=0)
        grads[i] = (gw1, gb1, gw2, gb2)
        g = gx
    return g, grads
```

### Шаг 3: память чекпоинтинга через каждые k

```python
def model_forward_checkpointed(x, params, k=4):
    saved_inputs = [x]
    h = x
    for i, (w1, b1, w2, b2) in enumerate(params):
        h = layer_forward(h, w1, b1, w2, b2)
        if (i + 1) % k == 0:
            saved_inputs.append(h)
    return h, saved_inputs


def model_backward_checkpointed(grad_output, saved_inputs, params, k=4):
    grads = [None] * len(params)
    g = grad_output
    segments = [(j * k, min((j + 1) * k, len(params))) for j in range(len(saved_inputs))]
    for seg_idx in range(len(saved_inputs) - 1, -1, -1):
        start, end = segments[seg_idx]
        if start >= end:
            continue
        x_in = saved_inputs[seg_idx]
        _, seg_acts = model_forward(x_in, params[start:end])
        g, seg_grads = model_backward(g, seg_acts, params[start:end])
        for j, gr in enumerate(seg_grads):
            grads[start + j] = gr
    return g, grads
```

### Шаг 4: модель стоимости

```python
def checkpoint_cost(n_layers, segment_size, flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }


def selective_checkpoint_cost(n_layers, attention_fraction=0.15,
                              flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * attention_fraction * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }
```

### Шаг 5: оценщик памяти

```python
def activation_memory_mb(n_layers, hidden=8192, seq=8192,
                        batch=1, bytes_per_value=2):
    per_layer = 12 * batch * seq * hidden * bytes_per_value
    return n_layers * per_layer / 1e6


def memory_after_checkpoint(n_layers, segment_size, hidden=8192,
                           seq=8192, batch=1, bytes_per_value=2):
    n_seg = max(1, n_layers // segment_size)
    saved = (n_seg + segment_size) * 1 * batch * seq * hidden * bytes_per_value
    return saved / 1e6
```

### Шаг 6: оптимальный размер сегмента

```python
def optimal_segment(n_layers):
    return int(round(np.sqrt(n_layers)))
```

### Шаг 7: решение о выборочном чекпоинтинге

```python
def should_recompute(layer_type, activation_bytes, recompute_flops_ratio):
    if layer_type == "attention" and activation_bytes > 100 * 1e6:
        return True
    if layer_type == "ffn" and activation_bytes > 500 * 1e6:
        return recompute_flops_ratio < 0.1
    return False
```

## Применение

- **torch.utils.checkpoint**: `from torch.utils.checkpoint import checkpoint` — канонический враппер в PyTorch. Оборачивает функцию; сохраняет только входы, пересчитывает при обратном проходе.
- **Пересчёт активаций Megatron-Core**: поддерживает режимы `selective`, `full` и `block`. Стандарт в промышленном обучении 2024+ годов.
- **Выгрузка в FSDP2**: `module.to_empty(device="cpu")` с `offload_policy` в FSDP2 переносит шардированные активации на CPU вместо пересчёта.
- **DeepSpeed ZeRO-Offload**: выгрузка состояний оптимизатора и активаций на CPU, дополняющая чекпоинтинг.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|----------------------|
| Градиентный чекпоинтинг | «Экономия памяти за счёт повторного прямого прохода» | Сохраняются только входы сегментов; во время обратного прохода промежуточные значения пересчитываются, чтобы получить тензоры, необходимые для вычисления градиентов |
| Пересчёт активаций | «То же самое, что и чекпоинтинг» | Принятое в высокопроизводительных вычислениях название той же техники |
| Размер сегмента (k) | «Сколько слоёв приходится на одну контрольную точку» | Число слоёв, промежуточные значения которых отбрасываются и совместно материализуются заново |
| Выборочный чекпоинтинг | «Трюк Korthikanti» | Пересчитываются только дорогие для хранения активации (softmax внимания), а дешёвые сохраняются |
| Полный чекпоинтинг | «Наивный вариант» | В каждом сегменте пересчитываются промежуточные значения всех слоёв |
| Блочный чекпоинтинг | «Крупная гранулярность» | Контрольные точки создаются для целых блоков трансформера; это самый крупный уровень гранулярности |
| Накладные расходы по FLOPs | «Плата вычислениями» | Дополнительные FLOPs на шаг = (recompute FLOPs) / (fwd + bwd FLOPs); 33% для наивного и 5% для выборочного варианта |
| Выгрузка активаций | «Перенести на CPU» | Активации перемещаются в оперативную память CPU на время между прямым и обратным проходами; это альтернатива пересчёту |
| Правило sqrt-L | «Классический оптимум» | Для слоёв с одинаковой вычислительной стоимостью оптимальный интервал между контрольными точками равен sqrt(L) слоёв |
| Объём softmax внимания | «Проблема O(L^2)» | L^2 * heads * batch floats; при длинном контексте этот объём доминирует в памяти активаций |
