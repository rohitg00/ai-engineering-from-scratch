# Спекулятивное декодирование и EAGLE

> Генерация одного токена фронтир-моделью LLM требует полного прямого прохода через миллиарды параметров. Этот прямой проход чрезмерно избыточен: большую часть времени гораздо меньшая модель может правильно угадать следующие 3-5 токенов, и большой модели остаётся лишь *проверить* догадку. Когда догадка верна, вы получаете 5 токенов по цене одного. Спекулятивное декодирование (Leviathan et al. 2023) сделало это точным, а EAGLE-3 (2025) подняло частоту принятия примерно до 4.5 токена на проверку — ускорение в 4-5 раз при том же распределении выходов.

**Тип:** Build
**Языки:** Python (с numpy)
**Предварительные требования:** фаза 10, урок 12 (оптимизация инференса); фаза 10, урок 04 (предварительное обучение Mini-GPT)
**Время:** ~75 минут

## Проблема

Пропускная способность декодирования для модели класса 70B на H100 обычно составляет 40-80 токенов в секунду. Каждый токен требует полного прямого прохода с чтением всех весов модели из HBM. Вы не можете уменьшить модель, не изменив её выход. Вы не можете увеличить размер батча сверх лимита памяти. Вы застряли — если только не заставите модель выдавать больше одного токена за прямой проход.

Авторегрессионная генерация выглядит по своей природе последовательной: `x_{t+1} = sample(p(· | x_{1:t}))`. Но здесь есть возможность для параллелизма. Если бы у вас был дешёвый предсказатель, говорящий «следующие 4 токена, вероятно, [a, b, c, d]», вы могли бы проверить все 5 позиций за **один прямой проход большой модели** и принять самый длинный совпадающий префикс.

Leviathan, Kalai, Matias (2023, "Fast Inference from Transformers via Speculative Decoding") сделали это точным с помощью хитрого правила принятия/отклонения, сохраняющего распределение сэмплирования целевой модели. То же самое распределение выходов, в 2-4 раза быстрее.

## Концепция

### Схема с двумя моделями

- **Целевая модель (target model)** `M_p`: большая, медленная, высококачественная модель, из которой вы на самом деле хотите получать сэмплы. Распределение: `p(x)`.
- **Модель-черновик (draft model)** `M_q`: маленькая, быстрая, менее качественная модель. Распределение: `q(x)`. Меньше в 5-30 раз.

На каждом шаге:

1. Модель-черновик авторегрессионно предлагает `K` токенов: `x_1, x_2, ..., x_K ~ q`.
2. Целевая модель выполняет ОДИН прямой проход по всем `K+1` позициям параллельно, вычисляя `p(x_k)` для каждого предложенного токена.
3. Принять/отклонить каждый токен слева направо по модифицированному правилу выборки с отклонением (rejection sampling), описанному ниже. Принять самый длинный совпадающий префикс.
4. Если какой-либо токен отклонён, сэмплировать замену из скорректированного распределения и остановиться. Иначе сэмплировать один бонусный токен из `p(· | x_1...x_K)`.

Если черновик идеально совпадает с целевой моделью, вы получаете K+1 токенов на один прямой проход целевой модели. Если черновик ошибся уже на позиции 1, вы получаете только 1 токен.

### Правило точности

Спекулятивное декодирование **доказуемо эквивалентно по распределению сэмплированию из p**. Правило отклонения:

```
For each drafted token x_t:
    r ~ Uniform(0, 1)
    if r < p(x_t) / q(x_t):
        accept x_t
    else:
        sample replacement from residual: (p - q)+ / ||(p - q)+||_1
        stop
```

где `(p - q)+` обозначает положительную часть поточечной разности. Когда черновик и цель согласны (`p ≈ q`), вероятность принятия близка к 1. Когда они расходятся, остаточное распределение построено так, чтобы итоговый сэмпл всё равно был в точности из `p`.

**Жадный случай.** Для сэмплирования при temperature=0 просто проверьте `argmax(p) == x_t`. Если да — примите; если нет — выведите `argmax(p)` и остановитесь.

### Ожидаемое ускорение

Если частота принятия черновика на уровне токена равна `α`, ожидаемое число токенов, произведённых за один прямой проход целевой модели, равно:

```
E[tokens] = (1 - α^{K+1}) / (1 - α)        # K = draft length, α in [0, 1]
```

При `α = 0.8, K = 4`: `(1 - 0.8^5)/(1 - 0.8) = 3.36` токена на проход. Один прямой проход целевой модели стоит примерно `cost_q * K + cost_p` (K шагов черновика плюс одна проверка целевой моделью). Если `cost_p >> cost_q * K`, коэффициент ускорения по пропускной способности составляет `3.36× / 1 = 3.36×`.

Единственный по-настоящему важный параметр — `α`, который целиком зависит от того, насколько черновик согласован с целевой моделью. Хороший черновик — это всё.

### Обучение черновика: дистилляция

Случайная маленькая модель — плохой черновик. Стандартный рецепт — дистилляция из целевой модели:

1. Выберите небольшую архитектуру (~1B для целевой модели 70B, ~500M для целевой модели 7B).
2. Прогоните целевую модель по большому текстовому корпусу; сохраните её распределения следующего токена.
3. Обучите черновик по KL-дивергенции относительно распределения целевой модели (а не относительно эталонных токенов).

Результат: `α` обычно составляет 0.6-0.8 на коде, 0.7-0.85 на чате на естественном языке. Ускорение в продакшене 2-3×.

### EAGLE: черновик-дерево + переиспользование признаков

Li, Wei, Zhang, Zhang (2024, "EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty") обнаружили две неэффективности в стандартном спекулятивном декодировании:

1. Черновик выполняет K последовательных шагов, каждый полным стеком. Но черновик мог бы переиспользовать признаки (скрытые состояния) целевой модели из последней проверки — целевая модель уже вычислила богатые представления, которые черновик заново выводит с нуля.
2. Черновик выдаёт линейную цепочку. Если бы черновик мог выдавать *дерево* кандидатов (в каждом узле несколько догадок), единственный прямой проход целевой модели мог бы проверить несколько путей-кандидатов параллельно через маску внимания дерева и выбрать самую длинную принятую ветвь.

Изменения EAGLE-1:
- Вход черновика = финальное скрытое состояние целевой модели в позиции t, а не сырые токены.
- Архитектура черновика = 1 слой декодера трансформера (а не отдельная маленькая модель).
- Выход = дерево из K = 4-8 кандидатов на глубину, глубина 4-6.

EAGLE-2 (2024) добавляет динамическую топологию дерева: дерево расширяется там, где черновик неуверен, и остаётся узким там, где он уверен. Повышает `α_effective` без увеличения стоимости проверки.

EAGLE-3 (Li et al. 2025, "EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test") убирает фиксированную зависимость от признаков верхнего слоя и обучает черновик с новой функцией потерь «имитации во время тестирования» — черновик обучается на выходах, соответствующих распределению целевой модели во время тестирования, а не на обучающем распределении с принудительной подачей правильного контекста. Частота принятия растёт с 0.75 (EAGLE-2) до 0.82 (EAGLE-3), а среднее число токенов на проверку — с 3.0 до 4.5.

### Проверка с маской внимания дерева

Когда черновик выдаёт дерево, целевая модель проверяет его за один прямой проход, используя **маску внимания дерева (tree attention mask)** — каузальную маску, кодирующую топологию дерева, а не чистую линию. Каждый токен обращает внимание только на своих предков в дереве. Проверочный проход по-прежнему один прямой проход, одно матричное умножение; топологическая маска стоит лишь несколько дополнительных записей KV.

```
        root
       /    \
      a      b
     / \    / \
    c  d   e   f
```

Если `a, b` — конкурирующие кандидаты на первый токен, а `c, d, e, f` — кандидаты на второй токен, все шесть позиций проверяются за один прямой проход. Выход — самый длинный префикс вдоль любого принятого пути.

### Когда это выигрывает, а когда нет

**Выигрывает:**
- Чат / автодополнение с предсказуемым текстом (код, обычный английский, структурированный вывод). `α` высокая.
- Настройки с неиспользуемыми вычислительными ресурсами GPU во время декодирования (этап, ограниченный пропускной способностью памяти). Черновик-дерево использует доступные FLOPs.

**Проигрывает / не даёт выигрыша:**
- Сильно стохастические выходы (креативное письмо при высокой температуре). `α` падает к `1/|vocab|`.
- Пакетное обслуживание с очень высокой конкурентностью — батчинг уже заполняет FLOPs, места для проверки дерева почти не остаётся.
- Очень маленькие целевые модели, где черновик не намного меньше.

Промышленные команды обычно сообщают об ускорении в 2-3× по времени выполнения на чате, 3-5× на генерации кода и почти нулевом выигрыше на креативном письме.

## Реализация

`code/main.py`:

- Эталонная `speculative_decode(target, draft, prompt, K, temperature)`, реализующая точное правило отклонения и проверяющая, что она сохраняет распределение целевой модели (эмпирическая KL < 0.01 против обычного сэмплирования целевой моделью).
- Черновик-дерево в стиле EAGLE, строящий дерево глубины K с ветвлением по top-p.
- Построитель маски внимания дерева, создающий правильный каузальный паттерн для верификатора.
- Стенд измерения частоты принятия, запускающий оба варианта на крошечной языковой модели (дистиллированный GPT-2-small из целевой GPT-2-medium).

```python
def speculative_step(p_target, q_draft, K, temperature=1.0):
    """One round of speculative decoding. Returns list of accepted tokens."""
    # 1. Draft K tokens
    draft_tokens = []
    q_probs = []
    state = draft_state_init()
    for _ in range(K):
        probs = softmax(q_draft(state) / temperature)
        t = np.random.choice(len(probs), p=probs)
        draft_tokens.append(t)
        q_probs.append(probs[t])
        state = draft_step(state, t)

    # 2. Target computes p at every drafted position + 1 extra
    p_probs_all = target_forward_batched(p_target, draft_tokens, temperature)

    # 3. Accept/reject left-to-right
    accepted = []
    for k, tok in enumerate(draft_tokens):
        r = np.random.uniform()
        if r < p_probs_all[k][tok] / q_probs[k]:
            accepted.append(tok)
        else:
            residual = np.maximum(p_probs_all[k] - q_probs[k], 0)
            residual /= residual.sum()
            accepted.append(np.random.choice(len(residual), p=residual))
            return accepted
    # 4. All K accepted → sample bonus token from target
    accepted.append(np.random.choice(len(p_probs_all[-1]), p=p_probs_all[-1]))
    return accepted
```

## Применение

- **vLLM** и **SGLang** поставляют спекулятивное декодирование как полноценную встроенную возможность. Флаги: `--speculative_model`, `--num_speculative_tokens`. Поддержка EAGLE-2/3 через флаг `--spec_decoding_algorithm eagle`.
- **NVIDIA TensorRT-LLM** нативно поддерживает деревья Medusa и EAGLE.
- **Эталонные модели-черновики**: `Qwen/Qwen3-0.6B-spec` (черновик для Qwen3-32B), `meta-llama/Llama-3.2-1B-Instruct-spec` (черновик для 70B).
- **Головы Medusa** (Cai et al. 2024, "Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads"): вместо модели-черновика добавьте K параллельных голов предсказания к самой целевой модели. Проще в развёртывании, немного ниже частота принятия, чем у EAGLE.

## Упражнения

1. Реализуйте точное правило отклонения и эмпирически проверьте его. Запустите 10 тыс. сэмплов через `speculative_decode` и через обычное сэмплирование целевой моделью; вычислите TV-расстояние между двумя распределениями выходов. Должно быть < 0.01.

2. Вычислите формулу ускорения. При фиксированных `α` и `K` постройте график ожидаемого числа токенов на прямой проход целевой модели. Найдите оптимальное K для α ∈ {0.5, 0.7, 0.9}.

3. Обучите крошечный черновик. Возьмите целевую модель GPT-2 на 124M и дистиллируйте черновик GPT-2 на 30M на 100M токенов с KL-функцией потерь. Измерьте `α` на отложенном тексте. Ожидается: 0.6-0.7.

4. Реализуйте черновик-дерево в стиле EAGLE. Вместо цепочки пусть черновик выдаёт три наиболее вероятные ветви на каждой глубине. Постройте маску внимания дерева. Проверьте, что целевая модель принимает самую длинную верную ветвь.

5. Измерьте режимы сбоя. Запустите спекулятивное декодирование при temperature=1.5 (высокая стохастичность). Покажите, что α схлопывается, и алгоритм оказывается медленнее обычного декодирования из-за накладных расходов черновика.

## Ключевые термины

| Термин | Как его называют | Что он означает на самом деле |
|------|-----------------|------------------------|
| Целевая модель | «Большая модель» | Медленная высококачественная модель, из распределения которой требуется получать сэмплы (распределение p) |
| Модель-черновик | «Спекулятор» | Небольшой быстрый предсказатель (распределение q), который в 5-30 раз меньше |
| K / длина черновика | «Опережение» | Число предполагаемых токенов за один проверочный проход |
| α / частота принятия | «Доля попаданий» | Вероятность того, что предложенный черновиком токен будет принят |
| Точное правило отклонения | «Проверка принятия» | Сравнение r < p/q, сохраняющее распределение целевой модели |
| Остаточное распределение | «Скорректированное p-q» | (p - q)+ / ||(p - q)+||_1 — распределение, из которого сэмплируется токен при отклонении |
| Построение черновика-дерева | «Ветвящееся предположение» | Черновик выдаёт дерево кандидатов, которое проверяется за один проход с помощью древовидной маски внимания |
| Маска внимания дерева | «Топологическая маска» | Каузальная маска, кодирующая топологию дерева так, чтобы каждый узел обращал внимание только на своих предков |
| Головы Medusa | «Параллельные головы» | K дополнительных голов предсказания в самой целевой модели; отдельная модель-черновик не нужна |
| Переиспользование признаков в EAGLE | «Черновик на скрытом состоянии» | Вместо сырых токенов черновик получает последнее скрытое состояние целевой модели, благодаря чему сам черновик становится меньше |
| Функция потерь с имитацией во время тестирования | «Обучение EAGLE-3» | Черновик обучается на выходах, соответствующих распределению целевой модели во время тестирования, а не с принудительной подачей правильного контекста |
