# A2A — протокол взаимодействия агентов

> Google анонсировала A2A в апреле 2025 года; к апрелю 2026 года спецификация доступна по адресу https://a2a-protocol.org/latest/specification/, и её поддерживают более 150 организаций. A2A — горизонтальное дополнение к MCP (Урок 13): там, где MCP вертикален (агент ↔ инструменты), A2A одноранговый (агент ↔ агент). Он определяет карточки агентов (обнаружение), задачи с артефактами (текст, структурированные данные, видео), непрозрачные жизненные циклы задач и аутентификацию. Промышленные системы всё чаще сочетают MCP с A2A. Google Cloud добавила поддержку A2A в Vertex AI Agent Builder в течение 2025–2026 годов.

**Тип:** Learn + Build**Языки:** Python (stdlib, `http.server`, `json`)**Предварительные требования:** Фаза 16 · 04 (Primitive Model)**Время:** ~75 минут
## Проблема

Вашему агенту нужно вызвать другого агента на другой системе. Как? Можно открыть HTTP-конечную точку, определить нестандартную JSON-схему и надеяться, что другая сторона говорит на том же языке. Каждая пара агентов превращается в индивидуальную интеграцию.

A2A — это универсальный протокол передачи данных для такого вызова. Стандартное обнаружение, стандартная модель задач, стандартный транспорт, стандартные артефакты. Как HTTP+REST, но для агентов как полноправных участников.

## Концепция

### Четыре элемента

**Карточка агента (Agent Card).** JSON-документ по адресу `/.well-known/agent.json`, описывающий агента: имя, навыки, конечные точки, поддерживаемые модальности, требования к аутентификации. Обнаружение происходит через чтение карточки.

```
GET https://agent.example.com/.well-known/agent.json
→ {
    "name": "code-review-agent",
    "skills": ["review-python", "review-typescript"],
    "endpoints": {
      "tasks": "https://agent.example.com/tasks"
    },
    "auth": {"type": "bearer"},
    "modalities": ["text", "structured"]
  }
```

**Задача (Task).** Единица работы. Асинхронный объект с состоянием и жизненным циклом: `submitted → working → completed / failed / canceled`. Клиент отправляет задачу, опрашивает её или подписывается на обновления.

**Артефакт (Artifact).** Тип результата, порождаемого задачей. Текст, структурированный JSON, изображение, видео, аудио. Артефакты типизированы, поэтому разные модальности являются полноправными.

**Непрозрачный жизненный цикл (opaque lifecycle).** A2A не предписывает, *как* удалённый агент решает задачу. Клиент видит переходы состояний и артефакты; реализация вольна использовать любой фреймворк.

### Разделение MCP/A2A

- **MCP** (Урок 13): агент ↔ инструмент. Агент читает/пишет через JSON-RPC на сервер инструментов. По умолчанию не имеет состояния.
- **A2A**: агент ↔ агент. Одноранговый протокол; обе стороны — агенты с собственными рассуждениями.

Промышленные мультиагентные системы используют оба протокола. Одноранговый узел A2A вызывает инструменты MCP на своей стороне. Такое разделение сохраняет чистоту двух зон ответственности.

### Поток обнаружения

```
Client                     Agent server
  ├──GET /.well-known/agent.json──>
  <──Agent Card JSON─────────────
  ├──POST /tasks {skill, input}──>
  <──201 task_id, state=submitted
  ├──GET /tasks/{id}──────────────>
  <──state=working, 42% done──────
  ├──GET /tasks/{id}──────────────>
  <──state=completed, artifacts──
```

Либо со стримингом: SSE-подписка на `/tasks/{id}/events` для push-обновлений.

### Аутентификация

A2A поддерживает три распространённых паттерна:

- **Bearer-токен** — OAuth2 или непрозрачный токен.
- **mTLS** — взаимный TLS; организации подтверждают идентичность друг другу.
- **Подписанные запросы** — HMAC поверх полезной нагрузки.

Аутентификация объявляется в карточке агента; клиенты обнаруживают требования и следуют им.

### 150+ организаций к апрелю 2026 года

Внедрение в корпоративном секторе обеспечило масштаб A2A. Главное: A2A стал способом, которым корпоративные агентные системы пересекают границы доверия. Google Cloud добавила поддержку A2A в Vertex AI Agent Builder; Microsoft Agent Framework поддерживает его; большинство крупных фреймворков (LangGraph, CrewAI, AutoGen) поставляются с адаптерами A2A.

### Где A2A побеждает

- **Межорганизационные вызовы.** Агент в компании A вызывает агента в компании B. Без A2A каждая пара — это индивидуальный контракт.
- **Разнородные фреймворки.** Агент на LangGraph вызывает агента на CrewAI, который вызывает кастомного Python-агента. A2A всё нормализует.
- **Типизированные артефакты.** Видеорезультат, структурированный JSON, аудио — всё полноправно.
- **Долгоживущие задачи.** Непрозрачный жизненный цикл вместе с опросом делает многочасовые задачи простыми в реализации.

### Где A2A не справляется

- **Микровызовы, чувствительные к задержке.** Жизненный цикл A2A асинхронен. Субмиллисекундное взаимодействие агент-агент сюда не вписывается; используйте прямой RPC.
- **Тесно связанные агенты в одном процессе.** Если оба агента работают в одном процессе Python, HTTP-обмен A2A избыточен.
- **Небольшие команды.** Накладные расходы спецификации реальны; агентам только для внутреннего использования формальность может быть не нужна.

### A2A против ACP, ANP, NLIP

В 2024–2026 годах появилось несколько смежных спецификаций:

- **ACP** (IBM/Linux Foundation) — предшественник A2A, более узкая область применения.
- **ANP** (Agent Network Protocol) — с упором на одноранговое обнаружение, децентрализация в приоритете.
- **NLIP** (Ecma Natural Language Interaction Protocol, стандартизирован в декабре 2025 года) — тип содержимого на естественном языке.

На апрель 2026 года A2A — наиболее широко принятый одноранговый протокол. Сравнение см. в arXiv:2505.02279 (Liu et al., «A Survey of Agent Interoperability Protocols»).

## Реализация

`code/main.py` реализует минимальный сервер и клиент A2A с использованием `http.server` и JSON. Сервер:

- открывает `/.well-known/agent.json`,
- принимает `POST /tasks`,
- управляет состоянием задачи,
- возвращает артефакты по `GET /tasks/{id}`.

Клиент:

- получает карточку агента,
- отправляет задачу,
- опрашивает до завершения,
- читает артефакт.

Запустите:

```
python3 code/main.py
```

Скрипт запускает сервер в фоновом потоке, затем запускает клиента против него. Вы увидите полный поток: обнаружение, отправку, опрос, артефакт.

## Применение

`outputs/skill-a2a-integrator.md` проектирует интеграцию A2A: содержимое карточки агента, схемы задач, выбор аутентификации, стриминг против опроса.

## Поставка

Чек-лист:

- **Зафиксируйте версию спецификации.** A2A всё ещё развивается; карточка агента должна объявлять версию протокола.
- **Идемпотентное создание задач.** Дублирующиеся отправки (повторы из-за сети) должны порождать одну задачу.
- **Схемы артефактов.** Объявляйте, какие формы возвращает агент; потребители должны их валидировать.
- **Ограничение частоты запросов + аутентификация.** A2A обращён вовне; применяйте стандартные меры веб-безопасности.
- **Очередь недоставленных сообщений для неудачных задач.** Со временем анализируйте закономерности повторяющихся типов сбоев.

## Упражнения

1. Запустите `code/main.py`. Убедитесь, что клиент обнаруживает сервер и получает правильный артефакт.
2. Добавьте на сервер второй навык (например, «summarize»). Обновите карточку агента. Напишите клиента, который выбирает навык в зависимости от типа задачи.
3. Реализуйте конечную точку SSE-стриминга: `/tasks/{id}/events`, которая генерирует изменения состояния. Что клиенту нужно делать по-другому?
4. Прочитайте спецификацию A2A (https://a2a-protocol.org/latest/specification/). Найдите три вещи, которые спецификация требует, но которые эта демонстрация не реализует.
5. Сравните A2A (обнаружение через карточку агента) с MCP (перечисление возможностей на стороне сервера через `listTools`). В чём компромисс между самоописывающимися агентами и опросом возможностей?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| A2A | «Агент-агент» | Одноранговый протокол для вызова агентами других агентов в разных системах. Google, 2025. |
| Agent Card | «Визитная карточка агента» | JSON по адресу `/.well-known/agent.json`, описывающий навыки, конечные точки, аутентификацию. |
| Task | «Единица работы» | Асинхронный объект с состоянием и жизненным циклом; при завершении порождает артефакты. |
| Artifact | «Результат» | Типизированный вывод: текст, структурированный JSON, изображение, видео, аудио. Медиа как полноправные объекты. |
| Opaque lifecycle | «Как это решается — дело агента» | Клиент видит переходы состояний; сервер волен выбирать фреймворк и инструменты. |
| Discovery | «Поиск агента» | `GET /.well-known/agent.json` возвращает карточку. |
| MCP vs A2A | «Инструменты против равноправных узлов» | MCP: вертикальное взаимодействие агент ↔ инструмент. A2A: горизонтальное взаимодействие агент ↔ агент. |
| ACP / ANP / NLIP | «Родственные протоколы» | Смежные спецификации; A2A — наиболее принятый протокол в 2026 году. |
