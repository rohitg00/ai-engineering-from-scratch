# Передачи и рутины — оркестрация без сохранения состояния

> Swarm от OpenAI (октябрь 2024) свёл мультиагентную оркестрацию к двум примитивам: **рутинам** (инструкции + инструменты в виде системного промпта) и **передачам** (инструмент, возвращающий другого Agent). Никакой машины состояний, никакого ветвящегося DSL — LLM выполняет маршрутизацию, вызывая нужный инструмент передачи. OpenAI Agents SDK (март 2025) — это преемник для продакшена. Сам Swarm остаётся самым чистым концептуальным образцом — весь его исходный код умещается в несколько сотен строк. Паттерн стал вирусным, потому что поверхность API сводится примерно к «агент = промпт + инструменты; передача = функция, возвращающая агента». Ограничение: отсутствие состояния, так что память — проблема вызывающей стороны.

**Тип:** Learn + Build**Языки:** Python (stdlib)**Предварительные требования:** Фаза 16 · 04 (Primitive Model)**Время:** ~60 минут
## Проблема

Каждый мультиагентный фреймворк хочет, чтобы вы выучили его DSL: узлы и рёбра LangGraph, crews и tasks CrewAI, GroupChat и managers AutoGen. Эти DSL — настоящие абстракции, но из-за них всё ощущается тяжелее, чем должно быть.

Swarm движется в противоположном направлении: используйте возможность вызова инструментов, которая у модели уже есть. Передачи становятся вызовами инструментов. Оркестратором выступает тот агент, который в данный момент ведёт разговор. Машина состояний неявно заложена в системных промптах агентов.

## Концепция

### Два примитива

**Рутина (routine).** Системный промпт, который определяет роль агента и доступные ему инструменты. Представьте это как ограниченный набор инструкций: «ты агент триажа; если пользователь спрашивает о возврате средств, передай его агенту по возвратам».

**Передача (handoff).** Инструмент, который агент может вызвать и который возвращает новый объект Agent. Рантайм Swarm обнаруживает возвращённое значение Agent и переключает активного агента на следующий ход.

Это вся абстракция целиком.

```
def transfer_to_refunds():
    return refund_agent  # Swarm sees Agent return → switch active agent

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

Системный промпт агента триажа заставляет его выбирать нужную передачу на основе сообщения пользователя. Маршрутизацию выполняет вызов инструментов LLM.

### Почему это стало вирусным

- **Маленький API.** Всего два понятия для изучения.
- **Использует то, что модель уже умеет.** Вызов инструментов уже готов к продакшену у всех провайдеров.
- **Никакой нагрузки машины состояний.** Вам не нужно описывать граф; промпты агентов сами описывают, кому они передают управление.

### Компромисс отсутствия состояния

Swarm намеренно не сохраняет состояние между запусками. Фреймворк хранит историю сообщений в течение одного запуска, но ничего не сохраняет постоянно. Память, непрерывность, долго выполняющиеся задачи — всё это проблема вызывающей стороны.

В продакшен-версии (OpenAI Agents SDK, март 2025) именно это стало одним из главных изменений: SDK добавляет встроенное управление сессиями, защитные ограничения и трассировку, сохраняя при этом примитив передачи.

### Когда Swarm/передачи подходят

- **Паттерны триажа.** Агент первой линии направляет пользователя к специалисту.
- **Передачи на основе навыков.** «Если задаче нужен код — вызови программиста; если нужно исследование — вызови исследователя».
- **Короткие, ограниченные диалоги.** Поддержка клиентов, преобразование FAQ в тикет, простые рабочие процессы.

### Когда Swarm не справляется

- **Долгие сессии с общей памятью.** Передача сбрасывает состояние разговора до промпта нового агента плюс история. Без памяти, управляемой вызывающей стороной, постоянного состояния между агентами не существует.
- **Параллельное выполнение.** Передача происходит по одной за раз — переключается активный агент. Параллелизм требует, чтобы вызывающая сторона сама оркестрировала несколько запусков Swarm.
- **Аудит и повтор.** Запуски без сохранения состояния сложно воспроизвести точно; выбор передачи, который делает LLM, не детерминирован.

### OpenAI Agents SDK (март 2025)

Продакшен-преемник добавляет:

- **Состояние сессии.** Устойчивый поток диалога между запусками.
- **Защитные ограничения.** Хуки проверки входных и выходных данных.
- **Трассировка.** Каждый вызов инструмента и передача логируются.
- **Фильтры передачи.** Управляют тем, какой контекст переходит при передаче.

Примитив передачи сохраняется; вокруг него добавляется продакшен-эргономика.

### Swarm против GroupChat

Оба подхода используют маршрутизацию на основе LLM, но различаются тем, **кто выбирает следующего**:

- GroupChat: селектор (функция или LLM) выбирает следующего говорящего извне.
- Swarm: текущий агент выбирает своего преемника, вызывая инструмент передачи.

Swarm — это «агент решает, что дальше»; GroupChat — это «менеджер решает, что дальше». Решение Swarm живёт в вызове инструмента активного агента; решение GroupChat — в `GroupChatManager`.

```figure
sw-handoff-routing
```

## Реализация

`code/main.py` реализует Swarm с нуля: dataclass Agent, механизм передачи (инструмент возвращает Agent) и цикл выполнения, который обнаруживает переключение агентов.

Демонстрация: агент триажа направляет к специалистам по возвратам, продажам или поддержке. У каждого специалиста свои инструменты. Цикл выполнения печатает каждую передачу.

Запуск:

```
python3 code/main.py
```

## Поставка

Чек-лист:

- **Логирование передач.** Каждая передача записывает событие трассировки с агентом-источником, агентом-получателем и снимком контекста.
- **Правила передачи контекста.** Определите, что переходит при передаче: полная история (дорого), последние N сообщений или сводка.
- **Защитное ограничение на передачу.** Передача специалисту с другими правами доступа к инструментам должна быть аутентифицирована — иначе инъекция промпта может вынудить нежелательные передачи.
- **Обнаружение циклов.** Два агента, перекидывающие управление туда-обратно, — распространённый сбой; обнаруживайте его простой проверкой последних K передач по кольцу.
- **Резервный агент.** Если целевой агент для передачи не существует, переключайтесь на безопасный вариант по умолчанию.

## Упражнения

1. Запустите `code/main.py`, направьте запрос агенту триажа к агенту по возвратам. Убедитесь, что на втором ходу активным агентом становится агент по возвратам.
2. Добавьте правило обнаружения циклов: если одни и те же два агента передавали управление друг другу 3 раза подряд, принудительно завершайте работу. Спроектируйте резервный вариант.
3. Прочитайте документацию OpenAI Agents SDK о фильтрах передачи. Реализуйте версию «сводка при передаче»: исходящий агент сжимает контекст в сводку по пунктам, прежде чем управление принимает входящий агент.
4. Сравните передачу в Swarm с селектором GroupChatManager. Какой паттерн усугубляет проблему инъекции промпта и почему?
5. Прочитайте cookbook по Swarm (https://developers.openai.com/cookbook/examples/orchestrating_agents). Определите одно явное архитектурное решение Swarm, которое OpenAI Agents SDK изменил или сохранил.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| Рутина (routine) | «Промпт агента» | Системный промпт + список инструментов. Определяет роль и доступные передачи. |
| Передача (handoff) | «Перевод на другого агента» | Инструмент, который активный агент может вызвать и который возвращает нового Agent. Рантайм переключает активного агента. |
| Отсутствие состояния (stateless) | «Нет памяти между запусками» | Swarm ничего не сохраняет постоянно; память — ответственность вызывающей стороны. |
| Активный агент | «Кто сейчас говорит» | Агент, который в данный момент ведёт разговор. Передача меняет это. |
| Передача контекста | «Что переходит при передаче» | Политика, определяющая, какую историю видит принимающий агент: полную, последние N сообщений или сводку. |
| Цикл передач | «Агенты перекидывают друг друга» | Сбой, при котором два агента бесконечно передают управление друг другу. |
| OpenAI Agents SDK | «Продакшен-версия Swarm» | Преемник марта 2025 года; добавляет сессии, защитные ограничения и трассировку поверх примитива передачи. |
| Фильтр передачи | «Проверка на передаче» | Функция SDK для проверки и изменения контекста на границе передачи. |
