# Групповой чат и выбор говорящего

> Оркестрация общего разговора объединяет N агентов в одном разговоре; функция-селектор (LLM, round-robin или своя логика) выбирает, кто говорит следующим. Это архетип эмерджентного мультиагентного разговора — агенты не знают своей роли в статическом графе, они просто реагируют на общий пул сообщений. AutoGen GroupChat и AG2 GroupChat — эталонные реализации: семантика GroupChat из AutoGen v0.2 была сохранена в форке AG2; AutoGen v0.4 переписал её как событийно-ориентированную модель акторов. В феврале 2026 года Microsoft перевела AutoGen в режим поддержки и объединила его с Semantic Kernel в Microsoft Agent Framework (RC, февраль 2026). Примитив GroupChat сохраняется и в AG2, и в Microsoft Agent Framework — изучите его один раз, используйте везде.

**Тип:** Learn + Build**Языки:** Python (stdlib)**Предварительные требования:** Фаза 16 · 04 (Primitive Model)**Время:** ~60 минут
## Проблема

Статические графы (LangGraph) отлично подходят, когда рабочий процесс известен заранее. Реальные разговоры не статичны: иногда программист обращается к рецензенту, иногда — к исследователю, иногда — к автору текста. Жёсткое прописывание каждой возможной передачи хода приводит к взрывному росту числа рёбер. Вам нужны *агенты, реагирующие на общий пул сообщений*, с некоторой функцией, решающей, кто говорит следующим.

Именно это и делает AutoGen GroupChat.

## Концепция

### Структура

```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

Каждый агент видит каждое сообщение. На каждом ходу вызывается функция-селектор, которая выбирает, кто будет говорить следующим.

### Три варианта селектора

**Round-robin.** Фиксированный цикл. Детерминированный. Масштабируется линейно по N, но игнорирует контекст — программист получает ход, даже если тема — юридическая проверка.

**LLM-selected.** Вызов LLM, которая читает недавний пул сообщений и возвращает наиболее подходящего следующего говорящего. Учитывает контекст, но медленный: каждый ход добавляет вызов LLM. Вариант по умолчанию в AutoGen.

**Custom.** Python-функция с произвольной логикой на ваше усмотрение. Типичный вариант: LLM-selected с резервными правилами (например, «всегда передавать ход верификатору сразу после программиста»).

### API ConversableAgent

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager` хранит селектор. Когда агент завершает ход, менеджер вызывает селектор, который возвращает следующего агента. Цикл продолжается до тех пор, пока не выполнится условие завершения.

### Завершение

Три распространённых паттерна:

- **Максимум раундов (Max rounds).** Жёсткое ограничение на общее число ходов.
- **Токен «TERMINATE».** Агенты могут выдать сигнальное сообщение; менеджер останавливается, когда оно появляется.
- **Проверка достижения цели (Goal-reached check).** Лёгкий верификатор запускается на каждом ходу и останавливает чат, когда цель достигнута.

### История развития: форки и слияния

В начале 2025 года Microsoft начала масштабную переработку AutoGen (v0.4) на основе событийно-ориентированной модели акторов. Сообщество форкнуло семантику GroupChat из AutoGen v0.2 в AG2, сохранив API, который уже интегрировали ранние пользователи.

В феврале 2026 года Microsoft объявила, что AutoGen перейдёт в режим поддержки, а событийно-ориентированная модель акторов войдёт в состав **Microsoft Agent Framework** (RC, февраль 2026, теперь объединён с Semantic Kernel). Концепция GroupChat сохраняется в обеих ветках; детали реализации различаются. AG2 — предпочтительный upstream для кода, совместимого с v0.2.

### Когда GroupChat подходит

- **Эмерджентные разговоры.** Вы не хотите заранее прописывать каждого возможного следующего говорящего.
- **Задачи со смешением ролей.** Программист спрашивает исследователя, исследователь спрашивает архивариуса, архивариус снова спрашивает программиста. Поток не является DAG.
- **Исследовательское решение задач.** Представьте «мозговой штурм на совещании», а не «сборочную линию».

### Когда это не работает

- **Строгий детерминизм.** LLM-селектор может быть непоследовательным. Один и тот же промпт, разные прогоны, разные следующие говорящие.
- **Каскады подобострастия (sycophancy).** Агенты уступают тому, кто говорил увереннее всех. Явно противодействуйте этому в промпте.
- **Раздувание контекста (context bloat).** Каждый агент читает каждое сообщение; после 10 ходов контекст становится огромным. Используйте проекции (урок 15), чтобы ограничить область видимости.
- **Доминирующие агенты (hot speakers).** Один агент доминирует в разговоре, потому что селектор благоволит его специализации. Введите балансировку говорящих как функцию селектора.

### Групповой чат против супервизора

Те же примитивы, но разные значения по умолчанию:

- Супервизор: один агент планирует, остальные выполняют. Селектор — это «спросить планировщика, что делать».
- Групповой чат: все агенты равноправны; селектор — это функция над общим пулом сообщений.

Оба паттерна используют четыре примитива из урока 04. Групповой чат по умолчанию использует LLM-selected оркестрацию и общее состояние на весь пул.


## Применение

`outputs/skill-groupchat-selector.md` настраивает селектор GroupChat для конкретной задачи — round-robin, LLM-selected или custom, и какие входные данные селектора использовать (недавние сообщения, специализации агентов, счётчики ходов).

## Поставка

Чек-лист:

- **Ограничение максимального числа раундов.** Всегда. 10-20 для типовых задач.
- **Метрика баланса говорящих.** Отслеживайте число ходов на агента; сигнализируйте, когда дисбаланс превышает порог.
- **Токен завершения.** `TERMINATE` или выделенный агент-верификатор.
- **Проекция или ограниченная память.** После ~10 сообщений стоит давать каждому агенту только ограниченный обзор, чтобы предотвратить раздувание контекста.
- **Логирование селектора.** Для вариантов LLM-selected логируйте и входные данные селектора, и его выбор. Иначе отладка невозможна.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| GroupChat | «Агенты в одной комнате чата» | Общий пул сообщений + функция-селектор. Примитив AutoGen / AG2. |
| Speaker selection | «Кто говорит следующим» | Функция, которая выбирает следующего агента. Round-robin, LLM-selected или custom. |
| GroupChatManager | «Ведущий встречи» | Компонент AutoGen, который владеет селектором и управляет циклом ходов. |
| ConversableAgent | «Базовый агент» | Базовый класс AutoGen; агент, который может отправлять и получать сообщения. |
| Termination token | «Слово-стоп» | Сигнальная строка (обычно `TERMINATE`), которая завершает чат. |
| Hot speaker | «Один агент доминирует» | Режим сбоя, при котором селектор постоянно выбирает одного и того же агента. |
| Context bloat | «Пул растёт без ограничений» | Каждый агент читает все предыдущие сообщения; контекст растёт с числом ходов. |
| Projection | «Ограниченный обзор» | Специфичный для роли обзор общего пула, предотвращающий раздувание контекста. |
