# Роевая оптимизация для LLM (PSO, ACO)

> Биоинспирированная оптимизация переживает возвращение в контексте LLM. **LMPSO** (arXiv:2504.09247) использует PSO, где скорость каждой частицы — это промпт, а LLM генерирует следующего кандидата; хорошо работает на структурированных последовательных выводах (математические выражения, программы). **Model Swarms** (arXiv:2410.11163) трактует каждую экспертную LLM как частицу PSO на многообразии весов модели и сообщает о **среднем приросте 13,3%** по сравнению с 12 базовыми методами на 9 наборах данных всего на 200 примерах. **SwarmPrompt** (ICAART 2025) гибридизирует PSO и алгоритм серого волка для оптимизации промптов. **AMRO-S** (arXiv:2603.12933) — это специалисты по феромонам, вдохновлённые ACO, для маршрутизации в мультиагентных LLM-системах — **ускорение в 4,7 раза**, интерпретируемые свидетельства маршрутизации, обновление с контролем качества и асинхронностью, которое отделяет инференс от обучения. В этом уроке реализуется PSO над пространством параметров промпта и ACO над маршрутизацией агентов, измеряется, почему эти классические алгоритмы подходят для эпохи LLM, и когда это не так.

## Проблема

У вас есть промпт, который набирает 62% в вашей оценке задачи. Вы хотите его улучшить. Наивный ход — ручная подстройка без градиента, которая плохо масштабируется. Обучению с подкреплением нужны сигналы вознаграждения и достаточное число прогонов для обучения. Обратное распространение через промпты по сути невозможно — промпт представляет собой дискретную строку, а не дифференцируемый параметр.

Классическая биоинспирированная оптимизация — PSO для непрерывных пространств поиска, ACO для выбора пути — была спроектирована именно для этого режима: без градиента, на основе популяции, с дешёвой оценкой. Соедините их с LLM для шага поиска без градиента — и получите на удивление практичный оптимизатор.

Те же паттерны применимы к *маршрутизации* агентов в мультиагентных системах. Феромонный след в стиле ACO фиксирует, какой агент лучше всего справился с каким типом задачи, позволяет маршрутизатору использовать этот след и снижает интенсивность феромонов со временем, чтобы маршруты можно было переоткрыть.

## Концепция

### Краткое напоминание о PSO (Kennedy & Eberhart 1995)

Particle Swarm Optimization (роевая оптимизация частиц): популяция частиц в непрерывном пространстве поиска. У каждой частицы есть позиция `x_i` и скорость `v_i`. На каждой итерации:

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
evaluate fitness(x_i)
update p_best_i if improved
update g_best if global best
```

Где `p_best` — собственный лучший результат частицы, `g_best` — лучший результат роя, `w, c1, c2` — веса инерции, когнитивного и социального компонентов, `r1, r2` — случайные множители.

### PSO над выводами LLM — LMPSO

arXiv:2504.09247 адаптирует PSO для структурированных выводов, сгенерированных LLM (математические выражения, программы). Каждая частица — это кандидат-вывод. Скорость — это *промпт*, описывающий, как изменить текущий вывод в направлении личного/глобального лучшего. LLM генерирует новый вывод из промпта скорости. «Инерция» скорости — это промпт вроде «вносите небольшие постепенные изменения».

Это хорошо работает, когда:
- Вывод структурирован (поддаётся разбору, оценке).
- Оценка пригодности автоматическая (прогоны тестов, вычисление арифметики).
- Популяция небольшая (~10–30 частиц), так что общее число вызовов LLM остаётся управляемым.

Это плохо работает, когда оценка пригодности требует проверки человеком — стоимость на итерацию становится непомерной.

### Model Swarms

arXiv:2410.11163 переносит PSO с уровня вывода на уровень *модели*. Каждая «частица» — это экспертная LLM (параметры). Рой сдвигает параметры к коллективному лучшему через обновление без градиента. Сообщается: средний прирост 13,3% по сравнению с 12 базовыми методами на 9 наборах данных, всего на 200 примерах на итерацию.

Ключевая идея в том, что экспертные модели LLM уже находятся рядом друг с другом в общем многообразии параметров (веса адаптеров, дельты LoRA). PSO в этом маломерном подпространстве дёшев и эффективен.

### Краткое напоминание об ACO (Dorigo 1992)

Ant Colony Optimization (муравьиная оптимизация): муравьи обходят граф; на каждом пути есть феромонный след. Вероятности перемещения муравья взвешиваются силой феромона. Муравьи, завершившие задачу, откладывают феромон пропорционально качеству решения. Феромон со временем распадается.

### AMRO-S — ACO для маршрутизации агентов

arXiv:2603.12933 использует ACO для маршрутизации в мультиагентных системах. Каждый тип задачи — «пункт назначения»; каждый агент — возможный маршрут. Феромоны усиливают маршруты, дающие хорошие результаты. Ключевые вклады:

- **Интерпретируемые свидетельства маршрутизации.** Сила феромона — человекочитаемый сигнал.
- **Обновление с контролем качества и асинхронностью.** Феромоны обновляются только после прохождения проверок качества, что отделяет инференс от обучения.
- **Ускорение в 4,7 раза** на бенчмарке мультиагентной маршрутизации.

Контроль качества имеет значение: без него быстрые, но неправильные агенты накапливают феромон, и система закрепляется на плохих маршрутах.

### Когда использовать PSO / ACO для LLM

**Используйте PSO, когда:**
- Пространство поиска непрерывно или отображается на непрерывные параметры (эмбеддинги промптов, веса LoRA, числовые параметры генерации).
- Оценка пригодности дешёвая и автоматическая.
- Популяция может быть небольшой (10–30).

**Используйте ACO, когда:**
- У вас есть задача маршрутизации или выбора пути.
- Решения усиливаются со временем (одни и те же типы задач возвращаются снова).
- Вам нужны интерпретируемые свидетельства для решений о маршрутизации.

**Не используйте ни то, ни другое, когда:**
- Оценка пригодности требует проверки человеком (слишком дорого на итерацию).
- Пространство поиска дискретно и комбинаторно таким образом, что PSO его не покрывает (используйте вместо этого генетические алгоритмы).
- Решениям в реальном времени требуется строгая задержка (PSO/ACO сходятся медленно по сравнению с однопроходными эвристиками).

### Почему биоинспирированные методы всё ещё побеждают

Градиентным методам нужны дифференцируемые сигналы. Выводы LLM и решения о маршрутизации не тривиально дифференцируемы. Псевдоградиентные методы (маршрутизаторы, обученные с подкреплением, тюнеры промптов в стиле DPO) работают, но требуют дорогостоящего обучения.

PSO и ACO нужна лишь функция *оценки*. Если вы можете оценить кандидат-вывод или решение о маршрутизации, вы можете оптимизировать это пространство. Это существенно снижает порог применимости.

### Практические ограничения

- **Бюджет популяции.** N частиц × T итераций × стоимость на оценку. При оценках LLM по ~$0.02 за вызов PSO с 20 частицами на 50 итераций стоит ~$20. Планируйте соответственно.
- **Разведка против эксплуатации.** Скорость распада феромона и инерция PSO образуют компромисс; слишком быстрый распад → забывание решений; слишком медленный → застревание в ранних локальных оптимумах.
- **Катастрофический дрейф.** Оба алгоритма могут сойтись, а затем разойтись, если ландшафт пригодности смещается (новое распределение данных). Отслеживайте стабильность лучшего значения пригодности.

## Реализация

`code/main.py` реализует:

- `LMPSO` — PSO над числовыми параметрами промпта (температура, веса top_k). «Генерация LLM» каждой частицы моделируется как скриптовая функция пригодности. Алгоритм выполняется 30 итераций и показывает сходимость g_best.
- `AMRO_S` — маршрутизация в стиле ACO. 3 агента, 4 типа задач, матрица феромонов, 100 маршрутизированных задач. Выводит распределение (тип задачи → выбор агента) во времени, чтобы показать формирование следа.
- Сравнение: случайная маршрутизация против маршрутизации ACO на одном и том же потоке задач. Измеряются качество и задержка.

Запуск:

```
python3 code/main.py
```

Ожидаемый вывод:
- LMPSO: пригодность g_best улучшается от случайной до близкой к оптимальной за 30 итераций.
- AMRO-S: таблица феромонов стабилизируется на правильном агенте для каждого типа задачи; маршрутизация ACO опережает случайную примерно на 30–40% по качеству, а также снижает задержку (меньше повторных попыток).

## Применение

`outputs/skill-swarm-optimizer.md` помогает выбрать между PSO, ACO, генетическими алгоритмами и градиентными оптимизаторами для задач оптимизации LLM/агентов.

## Поставка

- **Начинайте с малого.** 10–20 частиц, 20–50 итераций. Масштабируйте только если кривая сходимости показывает явный выигрыш.
- **Логируйте феромоны или g_best на каждой итерации.** Отладка роевых оптимизаторов без следа мучительна.
- **Обновления с контролем качества.** Особенно для маршрутизации ACO: быстрые, но неправильные агенты не должны накапливать феромон.
- **Сбрасывайте распад при сдвиге распределения.** Когда распределение вашей оценки меняется, устаревшие феромоны становятся неактуальными; сбрасывайте или временно удваивайте скорость распада.
- **Ограничивайте стоимость на итерацию.** Выводите метрику стоимости на итерацию. PSO, который стоит $500 за итерацию и даёт прирост 0,5%, непригоден для продакшена.

## Упражнения

1. Запустите `code/main.py`. Понаблюдайте за сходимостью LMPSO. Меняйте размер популяции 5, 10, 20, 50. При каком размере время до сходимости выходит на плато?

3. Добавьте контроль качества в AMRO-S: отложение феромона только для прогонов с оценкой > 0,7. Как это меняет сходимость по сравнению с версией без контроля?
4. Прочитайте LMPSO (arXiv:2504.09247). Сопоставьте идею статьи «скорость как промпт» с вашей числовой скоростью. Что теряется при моделировании, а что сохраняется?
5. Прочитайте AMRO-S (arXiv:2603.12933). Реализуйте развязанный «быстрый путь инференса» с асинхронным обновлением феромонов. Как это меняет задержку системы под устойчивой нагрузкой?
