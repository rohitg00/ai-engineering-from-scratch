# MARL — MADDPG, QMIX, MAPPO

> Наследие обучения с подкреплением в мультиагентной координации, которое до сих пор формирует системы LLM-агентов в 2026 году. **MADDPG** (Lowe et al., NeurIPS 2017, arXiv:1706.02275) ввёл централизованное обучение с децентрализованным исполнением (Centralized Training, Decentralized Execution, CTDE): каждый критик видит состояния и действия всех агентов во время обучения; во время тестирования запускаются только локальные акторы. Работает для кооперативных, конкурентных и смешанных сценариев. **QMIX** (Rashid et al., ICML 2018, arXiv:1803.11485) — это декомпозиция ценности с монотонной сетью смешивания; Q-значения отдельных агентов объединяются в совместное Q так, что `argmax` распределяется без противоречий — доминирует на StarCraft Multi-Agent Challenge (SMAC). **MAPPO** (Yu et al., NeurIPS 2022, arXiv:2103.01955) — это PPO с централизованной функцией ценности; «на удивление эффективен» на particle-world, SMAC, Google Research Football, Hanabi при минимальной настройке гиперпараметров. Эти алгоритмы лежат в основе обучения политик для команд агентов, которым нужно действовать децентрализованно. MAPPO — это **базовый вариант кооперативного MARL по умолчанию в 2026 году**. В этом уроке каждый из них строится на основе небольшой игрушечной grid-world-среды, чтобы закрепить три идеи на уровне мышечной памяти перед тем, как переходить к обучению LLM-агентов.

**Тип:** Learn**Языки:** Python (stdlib, small NumPy-free implementations)**Предварительные требования:** Фаза 09 (Reinforcement Learning), Фаза 16 · 09 (Parallel Swarm Networks)**Время:** ~90 минут
## Проблема

Системы LLM-агентов всё чаще обучают политики для координации между агентами: когда уступить, когда действовать, к какому напарнику обратиться. Литература, которая объясняет, как обучать такие политики, — это мультиагентное обучение с подкреплением (Multi-Agent Reinforcement Learning, MARL), которое появилось ещё до волны LLM и располагает небольшим набором доминирующих алгоритмов.

Читать статьи по MARL без словаря паттернов мучительно. Централизованное обучение с децентрализованным исполнением (CTDE), декомпозиция ценности и централизованные критики — не модные словечки, а конкретные ответы на конкретные проблемы:

- Независимое RL (каждый агент учится сам по себе) нестационарно с точки зрения каждого агента. Плохо.
- Централизованное RL (один агент управляет всеми) не масштабируется и нарушает ограничения на исполнение.
- CTDE берёт лучшее от обоих подходов: обучение с глобальной информацией, развёртывание с локальными политиками.

## Концепция

### Три среды, которые используют статьи

- **Particle World (мультиагентная среда с частицами).** Простая 2D-физика с кооперативными/конкурентными задачами. Изначальный тестовый стенд MADDPG.
- **StarCraft Multi-Agent Challenge (SMAC).** Кооперативное микроуправление, частичная наблюдаемость. Тестовый стенд QMIX. Дискретные действия, непрерывные состояния.
- **Google Research Football, Hanabi, MPE.** Базовые бенчмарки MAPPO.

У разных сред разные типы действий и наблюдений. Алгоритмы подбираются соответственно.

### MADDPG (2017) — паттерн CTDE

У каждого агента `i` есть актор `mu_i(o_i)`, который отображает собственное наблюдение в действие. У каждого агента также есть критик `Q_i(x, a_1, ..., a_n)`, который видит все наблюдения и все действия во время обучения. Актор обновляется методом градиента политики (policy gradient) на основе оценки критика.

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

Почему CTDE: во время обучения нам известны действия всех агентов; мы используем это, чтобы снизить дисперсию оценки каждого критика. Во время развёртывания каждый агент видит только `o_i` и вызывает `mu_i(o_i)`.

Режим отказа: критики растут вместе с числом агентов N (вход включает все действия). Без приближений не масштабируется дальше ~10 агентов.

### QMIX (2018) — декомпозиция ценности

Только для кооперативных задач. Глобальное вознаграждение представлено суммой — монотонной функцией от Q-значений отдельных агентов:

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

Монотонность гарантирует, что `argmax_a Q_tot` можно вычислить, если каждый агент независимо выберет `argmax_{a_i} Q_i`. Это **именно то свойство децентрализованного исполнения**, которое нужно. Во время обучения сеть смешивания формирует `Q_tot` из Q-значений отдельных агентов.

Почему QMIX побеждает на SMAC: кооперативное микроуправление в StarCraft подразумевает однородных агентов, локальные наблюдения и глобальное вознаграждение — идеальное соответствие декомпозиции ценности.

Режим отказа: ограничение монотонности накладывает жёсткие рамки; в некоторых задачах структура вознаграждения не раскладывается монотонно (когда один агент жертвует собой ради команды). Расширения (QTRAN, QPLEX) ослабляют это ограничение.

### MAPPO (2022) — недооценённый вариант по умолчанию

Multi-Agent PPO: PPO с централизованной функцией ценности. У каждого агента своя политика; все агенты используют общую (или индивидуальную для каждого агента) функцию ценности, которая видит полное состояние. Yu et al. в 2022 году сравнили MAPPO с MADDPG, QMIX и их расширениями на пяти бенчмарках и обнаружили:

- MAPPO не уступает или превосходит off-policy методы MARL на particle-world, SMAC, Google Research Football, Hanabi, MPE.
- Требуется минимальная настройка гиперпараметров.
- Стабильное обучение; воспроизводимость между сидами (seeds).

До этой статьи сообщество недооценивало on-policy MARL. В 2026 году MAPPO — базовый вариант по умолчанию для кооперативного MARL; любой новый метод должен его превзойти.

### Почему это должно волновать инженеров LLM-агентов

Три прямых применения:

1. **Обучение маршрутизатора.** Мета-агент выбирает, какой субагент обрабатывает задачу. Это задача MARL с N децентрализованными субагентами и одним централизованным маршрутизатором. MAPPO подходит.
2. **Возникновение ролей.** В симуляциях генеративных агентов обучение агентов со временем принимать взаимодополняющие роли — это замаскированная задача MARL. Декомпозиция ценности в стиле QMIX обеспечивает взаимодополняемость по построению.
3. **Мультиагентное использование инструментов.** Когда агенты делят инструменты и конкурируют за бюджет, обучение их через CTDE даёт готовые к развёртыванию локальные политики, соблюдающие ограничения ресурсов.

Практическая оговорка: в 2026 году большинство продакшен-систем LLM-агентов задают свои политики промптами, а не обучают их. MARL вступает в игру, когда есть (a) много данных о взаимодействиях, (b) чёткий сигнал вознаграждения и (c) готовность вкладываться в инфраструктуру обучения.

### CTDE как архитектурный паттерн за пределами RL

Даже без обучения CTDE — полезный архитектурный паттерн:

- На этапе *проектирования* предполагайте полную видимость команды.
- Во время *выполнения* обеспечивайте децентрализованное исполнение: каждый агент видит только `o_i`.

Этот паттерн заставляет явно выделять состояние каждого агента и заранее думать о частичной наблюдаемости. Многие продакшен-системы с несколькими агентами молчаливо предполагают общее состояние везде — дисциплина CTDE этого не допускает.

### Проблема нестационарности

Когда несколько агентов учатся одновременно, среда каждого агента (которая включает политики остальных) нестационарна. Классические доказательства для одноагентного RL перестают работать. Все алгоритмы MARL из этого урока решают эту проблему:

- MADDPG: глобальный критик видит все действия, поэтому его оценка ценности стационарна.
- QMIX: декомпозиция ценности переносит обучение в пространство совместного Q, где оптимальность чётко определена.
- MAPPO: централизованная функция ценности гасит дисперсию, вызванную изменениями политик других агентов.

В системах LLM-агентов нестационарность проявляется так: «мой агент работал в прошлом месяце, а теперь, когда изменился тот агент выше по цепочке, мой ведёт себя неправильно». Обучение MARL с CTDE — принципиальное решение; исправления на уровне промптов быстрее, но менее долговечны.

## Реализация

`code/main.py` реализует демонстрации трёх паттернов, все на крошечном кооперативном grid-world с 2 агентами:

- Среда: 2 агента на сетке 4x4, одна награда-«таблетка» (pellet). Вознаграждение = 1, если любой агент достигает таблетки; задача завершается.
- `IndependentAgents` — каждый агент рассматривает остальных как часть среды. Базовый вариант.
- `MADDPGStyle` — централизованный критик вычисляет совместную ценность; политики акторов обновляются на её основе. Сценарное улучшение политики.
- `QMIXStyle` — декомпозиция ценности с монотонным смесителем (mixer).
- `MAPPOStyle` — централизованная функция ценности; политики обновляются относительно общей базовой линии (baseline).

Все четыре варианта запускают одни и те же эпизоды и выводят среднее число шагов до цели. Варианты с CTDE сходятся к более коротким путям, чем независимый базовый вариант.

Запуск:

```
python3 code/main.py
```

Ожидаемый результат: независимым агентам требуется в среднем ~6 шагов; варианты с CTDE сходятся к ~3.5 шагам (оптимум для сетки 4x4 — 3 шага). Разница между паттернами проявляется, несмотря на сценарные политики.

## Поставка

MARL редко встречается в продакшене. Когда вы всё же его используете:

- **Начинайте с MAPPO.** Статья 2022 года закрепила его в качестве базового варианта; воспроизведение его первым экономит недели погони за более изощрёнными методами.
- **Журналируйте поток наблюдений и действий каждого агента.** Отлаживать MARL без трасс по каждому агенту безнадёжно.
- **Отделяйте код обучения от кода исполнения.** CTDE — это дисциплина; пусть путь исполнения действительно видит только `o_i`.
- **Предупреждение о формировании вознаграждения (reward shaping).** MARL исключительно чувствителен к дизайну вознаграждения. Одна ошибка координации в формировании — и агенты научатся её эксплуатировать. Проводите состязательные тесты.
- **Для LLM-агентов** сначала рассматривайте политики на уровне промптов. Вкладывайтесь в обучение MARL только тогда, когда одновременно присутствуют данные о взаимодействиях, сигнал вознаграждения и инфраструктура.

## Упражнения

1. Запустите `code/main.py`. Измерьте разрыв в числе шагов до цели между независимыми агентами и агентами в стиле MAPPO. Растёт разрыв или сокращается на сетке 6x6?
2. Реализуйте конкурентный вариант: два агента, одна таблетка, вознаграждение получает только тот, кто добрался первым. Какой паттерн лучше справляется с конкуренцией? Исторически — MADDPG.
3. Прочитайте раздел 3 статьи MADDPG (arXiv:1706.02275). Реализуйте точное правило обновления критика символически в псевдокоде своими словами.
4. Прочитайте статью MAPPO (arXiv:2103.01955). Почему авторы утверждают, что централизованная ценность + PPO превосходит off-policy MARL на их бенчмарках? Перечислите три самых сильных утверждения.
5. Примените CTDE как архитектурный паттерн к гипотетической системе LLM-агентов (например, агент-исследователь + агент-суммаризатор + агент-программист). Какая совместная информация доступна на этапе проектирования, но недоступна во время выполнения?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| MARL | «Мультиагентное RL» | Обучение с подкреплением для мультиагентных систем. |
| CTDE | «Централизованное обучение, децентрализованное исполнение» | Обучение с глобальной информацией; развёртывание с локальными политиками. |
| MADDPG | «Мультиагентный DDPG» | CTDE с критиком для каждого агента, видящим все наблюдения и действия. |
| QMIX | «Декомпозиция ценности» | Монотонное смешивание Q-значений отдельных агентов. Кооперативный. |
| MAPPO | «Мультиагентный PPO» | PPO с централизованной функцией ценности. Базовый вариант по умолчанию в 2026 году. |
| Декомпозиция ценности | «Сумма отдельных Q» | Совместное Q, представленное как монотонная функция от Q-значений отдельных агентов. |
| Нестационарность | «Движущиеся цели» | Среда каждого агента меняется по мере того, как учатся остальные. Ключевая проблема MARL. |
| On-policy / off-policy | «Учиться на текущем опыте / на воспроизведённом опыте» | PPO — on-policy (MAPPO); DDPG и Q-learning — off-policy. |
| SMAC | «StarCraft Multi-Agent Challenge» | Бенчмарк кооперативного микроуправления; родная площадка QMIX. |
