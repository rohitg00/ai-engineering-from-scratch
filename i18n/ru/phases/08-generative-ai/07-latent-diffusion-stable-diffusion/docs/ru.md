# Латентная диффузия и Stable Diffusion

> Диффузия в пространстве пикселей на изображениях 512×512 — это форменное военное преступление в вычислениях. Ромбах и соавторы (2022) заметили, что для генерации изображения не нужны все 786 тыс. измерений — достаточно того объёма, который передаёт семантическую структуру, а остальное восстановит отдельный декодер. Запустите диффузию внутри латентного пространства VAE. Именно эта идея и есть Stable Diffusion.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 8 · 02 (VAE), этап 8 · 06 (DDPM), этап 7 · 09 (ViT)
**Время:** ~75 минут

## Проблема

Диффузия в пространстве пикселей при 512² означает, что U-Net работает с тензорами формы `[B, 3, 512, 512]`. Каждый шаг сэмплирования — это ~100 GFLOPS для U-Net с 500 млн параметров. Пятьдесят шагов — это 5 TFLOPS на одно изображение. Обучение на миллиарде изображений делает вычислительные затраты абсурдными.

Большая часть этих FLOPs уходит на прогон через сеть перцептивно неважных деталей — высокочастотной текстуры, которую VAE с потерями мог бы просто сжать. Идея Ромбаха: один раз обучить VAE (*первый этап*), заморозить его и запускать диффузию целиком в 4-канальном латентном пространстве 64×64 (*второй этап*). Та же U-Net. В 16 раз меньше пикселей. Примерно в 64 раза меньше FLOPs при сопоставимом качестве.

Это и есть рецепт Stable Diffusion. SD 1.x / 2.x использовали U-Net на 860 млн параметров над латентами `64×64×4`, SDXL — U-Net на 2,6 млрд параметров над `128×128×4`, SD3 заменила U-Net на диффузионный трансформер (Diffusion Transformer, DiT) с согласованием потоков (flow matching). Flux.1-dev (Black Forest Labs, 2024) поставляется с DiT-MMDiT на 12 млрд параметров. Все они работают на одной и той же двухэтапной основе.

## Концепция

![Латентная диффузия: сжатие с помощью VAE и диффузия в латентном пространстве](../assets/latent-diffusion.svg)

**Два этапа, обучаемых раздельно.**

1. **Этап 1 — VAE.** Энкодер `E(x) → z`, декодер `D(z) → x`. Целевое сжатие: понижение разрешения в 8× по каждой пространственной оси + подбор числа каналов так, чтобы итоговый размер латента составлял ~1/16 от числа пикселей. Функция потерь = реконструкция (L1 + перцептивная LPIPS) + KL (с малым весом, чтобы `z` не приводился слишком близко к гауссовскому распределению, поскольку точное сэмплирование из `z` не требуется). Часто обучается с состязательной функцией потерь, чтобы декодированные изображения были чёткими.

2. **Этап 2 — диффузия на `z`.** Рассматриваем `z = E(x_real)` как данные. Обучаем U-Net (или DiT) очищать `z_t` от шума. На этапе инференса: сэмплируем `z_0` с помощью диффузии, затем `x = D(z_0)`.

**Текстовое кондиционирование.** Два дополнительных компонента. Замороженный текстовый энкодер (CLIP-L для SD 1.x, CLIP-L+OpenCLIP-G для SD 2/XL, T5-XXL для SD3 и Flux). Инъекция через перекрёстное внимание (cross-attention): каждый блок U-Net принимает `[Q = image features, K = V = text tokens]` и подмешивает их. Токены — единственный способ, которым текст влияет на изображение.

**Функция потерь идентична уроку 06.** Тот же MSE по шуму в стиле DDPM / согласования потоков. Меняется только предметная область данных.

## Постройте это

`code/main.py` надстраивает игрушечный одномерный «VAE» (энкодер и декодер тождественного отображения — для наглядности; настоящий VAE был бы свёрточной сетью) поверх DDPM из урока 06 и добавляет обусловливание по классу с управлением без классификатора (classifier-free guidance). Это показывает, что одна и та же функция потерь диффузии работает как на сырых одномерных значениях, так и на закодированных — в этом и есть ключевая идея.

### Шаг 1: энкодер/декодер

```python
def encode(x):    return x * 0.5          # toy "compression" to smaller scale
def decode(z):    return z * 2.0
```

У настоящего VAE есть обученные веса. В учебных целях этого линейного отображения достаточно, чтобы показать: диффузия работает над `z`, не заботясь об исходном пространстве данных.

### Шаг 2: диффузия в пространстве `z`

Тот же DDPM, что и в уроке 06. Данные, которые видит сеть, — это `z = E(x)`. После сэмплирования `z_0` декодируйте с помощью `D(z_0)`.

### Шаг 3: управление без классификатора

Во время обучения отбрасывайте метку класса в 10% случаев (заменяя её нулевым токеном). На этапе инференса вычислите и `ε_cond`, и `ε_uncond`, затем:

```python
eps_cfg = (1 + w) * eps_cond - w * eps_uncond
```

`w = 0` = без управления (максимальное разнообразие), `w = 3` = значение по умолчанию, `w = 7+` = перенасыщение / избыточная резкость.

### Шаг 4: текстовое кондиционирование (концепция, не код)

Замените метку класса выходом замороженного текстового энкодера. Подайте текстовый эмбеддинг в U-Net через перекрёстное внимание:

```python
h = h + CrossAttention(Q=h, K=text_embed, V=text_embed)
```

Это единственное существенное различие между диффузионной моделью с обусловливанием по классу и Stable Diffusion.

## Подводные камни

- **Рассинхронизация масштаба VAE.** У VAE в SD 1.x есть константа масштабирования (`scaling_factor ≈ 0.18215`), которая применяется после кодирования. Если её забыть, U-Net обучается на латентах с сильно искажённой дисперсией. Она зашита в каждый чекпоинт.
- **Текстовый энкодер молча работает неправильно.** SD3 нуждается в T5-XXL с >=128 токенами, а откат к варианту только с CLIP — это потеря информации. Всегда проверяйте `use_t5=True`, иначе точность следования промпту рушится.
- **Смешивание латентных пространств.** SDXL, SD3 и Flux используют разные VAE. LoRA, обученная на латентах SDXL, не будет работать на SD3. Hugging Face diffusers 0.30+ отказывается загружать несовместимые чекпоинты.
- **Слишком высокий CFG.** При `w > 10` получаются перенасыщенные, «маслянистые» изображения, а модель переобучается под промпт ценой разнообразия. Оптимальный диапазон — `w = 3-7`.
- **Утечка негативных промптов.** Пустой негативный промпт превращается в нулевой токен; заполненный негативный промпт становится `ε_uncond`. Это не одно и то же; некоторые конвейеры молча используют по умолчанию нулевой токен.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py` с коэффициентом управления `w ∈ {0, 1, 3, 7, 15}`. Зафиксируйте среднее значение сэмпла по классам. При каком `w` средние значения по классам расходятся за пределы средних значений реальных данных?
2. **Среднее.** Замените игрушечный линейный энкодер на пару энкодер/декодер на основе tanh-MLP с функцией потерь реконструкции. Переобучите диффузию на новых латентах. Меняется ли качество сэмплов?
3. **Сложное.** Настройте реальный инференс Stable Diffusion с помощью diffusers: загрузите `sdxl-base`, выполните 30 шагов Euler с CFG=7, замерьте время. Затем переключитесь на `sdxl-turbo` с 4 шагами и CFG=0. Тот же сюжет, разное качество — опишите, что изменилось и почему.

## Ключевые термины

| Термин | Как его обычно называют | Что он означает на самом деле |
|------|-----------------|-----------------------|
| Первый этап | «VAE» | Обученная пара энкодер/декодер; сжимает 512² до 64². |
| Второй этап | «U-Net» | Диффузионная модель над латентным пространством. |
| CFG | «Коэффициент управления» | `(1+w)·ε_cond - w·ε_uncond`; настраивает силу обусловливания. |
| Нулевой токен | «Эмбеддинг пустого промпта» | Безусловный эмбеддинг, используемый для `ε_uncond`. |
| Перекрёстное внимание | «Как текст попадает внутрь» | Каждый блок U-Net применяет внимание к текстовым токенам как K и V. |
| DiT | «Диффузионный трансформер» | Замена U-Net трансформером над латентными патчами; лучше масштабируется. |
| MMDiT | «Мультимодальный DiT» | Архитектура SD3: потоки текста и изображения с совместным вниманием. |
| Коэффициент масштабирования VAE | «Магическое число» | Делит латенты на ~5.4, чтобы диффузия работала в пространстве с единичной дисперсией. |

## Заметка о продакшене: запуск Flux-12B на потребительской GPU с 8 ГБ

эталонная интеграция Flux — это канонический рецепт для вопроса «у меня потребительская GPU, смогу ли я это выпустить?». Тот же трюк с тремя рычагами, который перечисляет производственная литература по инференсу, применяется здесь к диффузионному DiT:

1. **Поэтапная загрузка.** У Flux есть три сети, которым никогда не нужно одновременно находиться в VRAM: текстовый энкодер T5-XXL (~10 ГБ в fp32), CLIP-L (маленький), MMDiT на 12 млрд параметров и VAE. Сначала закодируйте промпт, *удалите* энкодеры, загрузите DiT, выполните шумоподавление, *удалите* DiT, загрузите VAE, декодируйте. В потребительские GPU с 8 ГБ помещается только один этап за раз.
2. **4-битное квантование через bitsandbytes.** `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16)` и для T5-энкодера, и для DiT. Сокращает потребление памяти в 8 раз, падение качества при генерации изображений по тексту незаметно — по бенчмаркам Aritra (ссылка в ноутбуке).
3. **Выгрузка на CPU (CPU offload).** `pipe.enable_model_cpu_offload()` автоматически перемещает модули между CPU и GPU по мере продвижения каждого прямого прохода. Добавляет 10-20% к задержке, но благодаря этому конвейер вообще запускается.

Расчёт памяти такой: `10 GB T5 / 8 = 1.25 GB` после квантования, `12 B params × 0.5 bytes = ~6 GB` для квантованного DiT, плюс активации. В терминологии stas00 это крайняя точка инференса при TP=1 — без модельного параллелизма, с максимальным квантованием. В продакшене вы бы запускали TP=2 или TP=4 на H100, а для одного дев-ноутбука это как раз такой рецепт.
