## Проблема

Вам нужен сэмплер для `p_data(x)`. GAN играют в минимаксную игру, которая часто расходится. VAE выдают размытые сэмплы из-за гауссовского декодера. На самом деле нужна целевая функция обучения, которая (a) представляет собой единственную стабильную функцию потерь (без седловой точки, без минимакса), (b) является нижней границей `log p(x)` (то есть даёт правдоподобия) и (c) даёт сэмплы качества уровня SOTA.

Соль-Дикстайн и др. (2015) дали теоретический ответ: определить марковскую цепь `q(x_t | x_{t-1})`, которая постепенно добавляет гауссовский шум, и обучить обратную цепь `p_θ(x_{t-1} | x_t)` убирать этот шум. Хо, Джейн и Аббил (2020) показали, что функцию потерь можно свести к одной строке — предсказыванию шума — и привели математику в порядок. В 2020 году это было курьёзом. В 2021 году это дало сэмплы уровня SOTA. В 2022 году это стало Stable Diffusion. В 2026 году это уже субстрат отрасли.

## Концепция

![DDPM: добавление шума в прямом процессе и его удаление в обратном](../assets/ddpm.svg)

**Прямой процесс `q`.** Добавляем гауссовский шум за `T` небольших шагов. Замкнутая форма — причина, по которой вся эта математика вычислительно доступна, — состоит в том, что накопленный шаг тоже является гауссовским:

```
q(x_t | x_0) = N( sqrt(α̅_t) · x_0,  (1 - α̅_t) · I )
```

где `α̅_t = ∏_{s=1..t} (1 - β_s)` для расписания `β_t`. Выберите `β_t` линейно от 1e-4 до 0.02 на протяжении T=1000 шагов, и `x_T` окажется приблизительно равно `N(0, I)`.

**Обратный процесс `p_θ`.** Обучаем нейросеть `ε_θ(x_t, t)`, предсказывающую добавленный шум. Имея `x_t`, убираем шум по формуле:

```
x_{t-1} = (1 / sqrt(α_t)) · ( x_t - (β_t / sqrt(1 - α̅_t)) · ε_θ(x_t, t) )  +  σ_t · z
```

где `σ_t` — это либо `sqrt(β_t)`, либо обучаемая дисперсия. Выражение выглядит громоздко, но это чистая алгебра — решение относительно `x_{t-1}` по апостериорному распределению `q(x_{t-1} | x_t, x_0)` с подстановкой вместо `x_0` его оценки, предсказанной по шуму.

**Функция потерь при обучении.**

```
L_simple = E_{x_0, t, ε} [ || ε - ε_θ( sqrt(α̅_t) · x_0 + sqrt(1 - α̅_t) · ε,  t ) ||² ]
```

Берём `x_0` из данных, выбираем случайный `t`, сэмплируем `ε ~ N(0, I)`, вычисляем зашумлённый `x_t` за один шаг по замкнутой форме и делаем регрессию на шум. Одна функция потерь, без минимакса, без KL, без трюков с репараметризацией.

**Сэмплирование.** Начинаем с `x_T ~ N(0, I)`. Повторяем обратный шаг от `t = T` до `1`. Готово.

## Почему это работает

Три интуитивных объяснения:

1. **Убирать шум легко; генерировать — сложно.** При `t=T` данные представляют собой чистый шум — сети нужно решить тривиальную задачу. При `t=0` сети нужно лишь подчистить несколько пикселей. При промежуточных `t` задача сложна, но через одни и те же веса сети проходит множество градиентов со всех уровней шума.

2. **Сопоставление скор-функции (score matching) под другим именем.** Винсент (2011) доказал, что предсказание шума эквивалентно оценке `∇_x log q(x_t | x_0)` — *скор-функции*. Обратное SDE использует эту скор-функцию, чтобы подниматься по градиенту плотности — это направленное случайное блуждание к областям высокой вероятности.

3. **ELBO сводится к обычной MSE.** У полной вариационной нижней границы есть член KL для каждого временного шага. При параметризации DDPM эти члены KL упрощаются до MSE на предсказании шума с конкретными коэффициентами; Хо отбросил коэффициенты (назвав эту функцию потерь «простой»), и качество при этом *улучшилось*.

## Постройте это

`code/main.py` реализует одномерный DDPM. Данные — это смесь с двумя модами. «Сеть» — крошечный MLP, который принимает `(x_t, t)` и выдаёт предсказанный шум. Обучение использует функцию потерь из одной строки. Сэмплирование повторяет обратную цепь.

### Шаг 1: прямое расписание (замкнутая форма)

```python
betas = [1e-4 + (0.02 - 1e-4) * t / (T - 1) for t in range(T)]
alphas = [1 - b for b in betas]
alpha_bars = []
cum = 1.0
for a in alphas:
    cum *= a
    alpha_bars.append(cum)
```

### Шаг 2: сэмплирование `x_t` за один шаг

```python
def forward_sample(x0, t, alpha_bars, rng):
    a_bar = alpha_bars[t]
    eps = rng.gauss(0, 1)
    x_t = math.sqrt(a_bar) * x0 + math.sqrt(1 - a_bar) * eps
    return x_t, eps
```

### Шаг 3: один шаг обучения

```python
def train_step(x0, model, alpha_bars, rng):
    t = rng.randrange(T)
    x_t, eps = forward_sample(x0, t, alpha_bars, rng)
    eps_hat = model_forward(model, x_t, t)
    loss = (eps - eps_hat) ** 2
    return loss, gradient_step(model, ...)
```

### Шаг 4: обратное сэмплирование

```python
def sample(model, alpha_bars, T, rng):
    x = rng.gauss(0, 1)
    for t in range(T - 1, -1, -1):
        eps_hat = model_forward(model, x, t)
        beta_t = 1 - alphas[t]
        x = (x - beta_t / math.sqrt(1 - alpha_bars[t]) * eps_hat) / math.sqrt(alphas[t])
        if t > 0:
            x += math.sqrt(beta_t) * rng.gauss(0, 1)
    return x
```

Для одномерной задачи с 40 временными шагами и MLP из 24 нейронов это позволяет выучить смесь с двумя модами примерно за 200 эпох.

## Обусловливание по времени

Сети нужно знать, какой именно временной шаг она сейчас очищает от шума. Есть два стандартных варианта:

- **Синусоидальный эмбеддинг.** Как позиционное кодирование трансформера. `embed(t) = [sin(t/ω_0), cos(t/ω_0), sin(t/ω_1), ...]`. Пропускается через MLP и распространяется по соответствующим измерениям сети.
- **Обусловливание через FiLM / групповую нормализацию.** Проецируем эмбеддинг в поканальные масштаб/смещение (FiLM) на каждом блоке.

Наш учебный код использует синусоидальный эмбеддинг → конкатенацию. Промышленные U-Net используют FiLM.

## Подводные камни

- **Расписание имеет большое значение.** Линейное `β` — это расписание по умолчанию в DDPM, но косинусное расписание (Николь и Дхариваль, 2021) даёт лучший FID при том же объёме вычислений. Переключайтесь на другое расписание, если качество выходит на плато.
- **Эмбеддинг временного шага хрупок.** Передача сырого `t` в виде числа с плавающей точкой работает для игрушечной одномерной задачи, но не работает для изображений; всегда используйте полноценный эмбеддинг.
- **V-предсказание и ε-предсказание.** В узких режимах (очень маленькое или очень большое t) у `ε` плохое отношение сигнал/шум. V-предсказание (`v = α·ε - σ·x`) более стабильно; SDXL, SD3 и Flux используют именно его.
- **Управление без классификатора (classifier-free guidance).** На этапе инференса вычисляется как условный, так и безусловный `ε`, затем `ε_cfg = (1 + w) · ε_cond - w · ε_uncond` при `w ≈ 3-7`. Разбирается в уроке 08.
- **1000 шагов — это много.** В продакшене используют DDIM (20-50 шагов), DPM-Solver (10-20 шагов) или дистилляцию (1-4 шага). См. урок 12.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Прямой процесс | «Добавление шума» | Фиксированная марковская цепь `q(x_t \| x_{t-1})`, разрушающая данные. |
| Обратный процесс | «Удаление шума» | Обучаемая цепь `p_θ(x_{t-1} \| x_t)`, восстанавливающая данные. |
| Расписание β | «Лестница шума» | Дисперсия на каждом шаге; линейная, косинусная или сигмоидная. |
| α̅ | «Альфа с чертой» | Накопленное произведение `∏(1 - β)`; даёт `x_t` из `x_0` в замкнутой форме. |
| Простая функция потерь | «MSE по шуму» | `\|\|ε - ε_θ(x_t, t)\|\|²`; все вариационные выкладки сводятся к этому. |
| ε-предсказание | «Предсказать шум» | На выходе — добавленный шум; стандарт для DDPM. |
| V-предсказание | «Предсказать скорость» | На выходе — `α·ε - σ·x`; лучшее обусловливание по всем t. |
| DDPM | «Статья» | Хо и др., 2020; линейное β, 1000 шагов, U-Net. |
| DDIM | «Детерминированный сэмплер» | Немарковский сэмплер, 20-50 шагов, та же целевая функция обучения. |
| Управление без классификатора | «CFG» | Смешивание условных и безусловных предсказаний шума для усиления обусловливания. |

## Заметка о продакшене: инференс диффузии — это вопрос количества шагов

В статье про DDPM выполняется T=1000 обратных шагов. Никто не поставляет это в продакшен в таком виде. Каждый реальный инференс-стек выбирает одну из трёх стратегий — и каждая из них чётко ложится на продакшен-рамку «откуда берётся задержка»:

1. **Более быстрый сэмплер, та же модель.** DDIM (20-50 шагов), DPM-Solver++ (10-20), UniPC (8-16). Прямая замена обратного цикла; обученные веса `ε_θ` остаются нетронутыми. Сокращает задержку в 20-50 раз.
2. **Дистилляция.** Обучаем модель-ученика воспроизводить модель-учителя за меньшее число шагов: Progressive Distillation (2 → 1), Consistency Models (произвольное число шагов → 1-4), LCM, SDXL-Turbo, SD3-Turbo. Сокращает задержку ещё в 5-10 раз, требует переобучения.
3. **Кеширование и компиляция.** `torch.compile(unet, mode="reduce-overhead")`, диффузионные бэкенды TensorRT-LLM, механизм внимания `xformers`/SDPA, веса в bf16. Сокращает задержку на шаг примерно в 2 раза. Комбинируется с (1) и (2).

Для продакшен-сервера диффузии разговор о бюджете такой же, как и в производственной литературе для LLM: задержка — это `num_steps × step_cost + VAE_decode`, пропускная способность — это `batch_size × (num_steps × step_cost)^-1`. TTFT мал (один шаг); эквивалент TPOT — это полное время ответа, потому что с точки зрения пользователя генерация изображения происходит «всё сразу».
