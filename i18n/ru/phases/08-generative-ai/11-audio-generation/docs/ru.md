# Генерация аудио

> Аудио — это одномерный сигнал с частотой дискретизации 16-48 кГц. Пятисекундный клип — это 80-240 тыс. сэмплов. Трансформеры не применяют механизм внимания непосредственно к последовательности такой длины. Решение для каждой продакшен-модели генерации аудио в 2026 году одинаковое: нейросетевой кодек (Encodec, SoundStream, DAC) сжимает аудио до дискретных токенов с частотой 50-75 Гц, а трансформер или диффузионная модель генерирует токены.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 6 · 02 (аудиопризнаки), фаза 6 · 04 (ASR), фаза 8 · 06 (DDPM)
**Время:** ~45 минут

## Проблема

Три задачи генерации аудио:

1. **Синтез речи (text-to-speech).** По тексту создать речь. Чистая речь занимает узкую полосу частот и обладает выраженной фонетической структурой — хорошо решается трансформером над токенами. VALL-E (Microsoft), NaturalSpeech 3, ElevenLabs, OpenAI TTS.
2. **Генерация музыки.** По промпту (текст, мелодия, последовательность аккордов, жанр) создать музыку. Распределение гораздо шире. MusicGen (Meta), Stable Audio 2.5, Suno v4, Udio, Riffusion.
3. **Аудиоэффекты / звуковой дизайн.** По промпту создать фоновый звук или шумовые эффекты (Foley). AudioGen, AudioLDM 2, Stable Audio Open.

Все три работают на одной основе: нейросетевой аудиокодек + авторегрессионная генерация по токенам (token-AR) или диффузия.

## Концепция

![Генерация аудио: токены кодека + трансформер или диффузия](../assets/audio-generation.svg)

### Нейросетевые аудиокодеки

Encodec (Meta, 2022), SoundStream (Google, 2021), Descript Audio Codec (DAC, 2023). Свёрточный энкодер сжимает форму волны в вектор на каждый временной шаг; остаточное векторное квантование (residual vector quantization, RVQ) преобразует каждый вектор в каскад из K индексов кодовой книги. Декодер выполняет обратное преобразование. Аудио 24 кГц при 2 кбит/с с использованием 8 кодовых книг RVQ на частоте 75 Гц = 600 токенов/сек.

```
waveform (16000 samples/sec)
    └─ encoder conv ─┐
                     ├─ RVQ layer 1 → indices at 75 Hz
                     ├─ RVQ layer 2 → indices at 75 Hz
                     ├─ ...
                     └─ RVQ layer 8
```

### Две генеративные парадигмы поверх кодека

**Авторегрессия по токенам (token-autoregressive).** Развернуть токены RVQ в последовательность, запустить трансформер только с декодером (decoder-only). MusicGen использует «отложенный параллелизм» (delayed parallel) для генерации K потоков кодовых книг параллельно со сдвигом по каждому потоку. VALL-E генерирует речевые токены из текстового промпта + 3-секундного образца голоса.

**Латентная диффузия.** Упаковать токены кодека как непрерывные латенты или моделировать их категориальной диффузией. Stable Audio 2.5 использует согласование потоков (flow matching) на непрерывных аудиолатентах. AudioLDM 2 использует диффузию по цепочке текст → мел-спектрограмма → аудио.

Тенденция 2024-2026: согласование потоков побеждает для музыки (более быстрый инференс, более чистые сэмплы), в то время как token-AR всё ещё доминирует в речи, поскольку авторегрессионная модель по токенам по своей природе каузальна и хорошо поддерживает потоковую генерацию.

## Реализация

`code/main.py` симулирует основную идею: обучить крошечный трансформер предсказания следующего токена на синтетических последовательностях «аудиотокенов», сгенерированных из двух различных «стилей» (чередование низких и высоких токенов для стиля A, монотонная рампа для стиля B). Обусловить генерацию стилем и выполнить сэмплирование.

### Шаг 1: синтетические аудиотокены

```python
def make_tokens(style, length, vocab_size, rng):
    if style == 0:  # "speech-like": alternating
        return [i % vocab_size for i in range(length)]
    # "music-like": ramp
    return [(i * 3) % vocab_size for i in range(length)]
```

### Шаг 2: обучение крошечного предсказателя токенов

Биграммный предсказатель, обусловленный стилем. Суть в паттерне: токены кодека → обучение с перекрёстной энтропией → авторегрессионное сэмплирование.

### Шаг 3: условное сэмплирование

По токену стиля и начальному токену сэмплировать следующий токен из предсказанного распределения. Продолжать 20-40 токенов.

## Подводные камни

- **Качество кодека ограничивает качество выхода.** Если кодек не может достоверно представить звук, никакое качество генератора не поможет. DAC — текущий лучший открытый вариант.
- **Накопление ошибки RVQ.** Каждый слой RVQ моделирует остаток предыдущего. Ошибки на слое 1 распространяются дальше. Сэмплирование с температурой 0 на более высоких слоях помогает.
- **Музыкальная структура.** 30 секунд токенов — это 20 тыс.+ токенов при 75 Гц. Сложно для трансформеров. MusicGen использует скользящее окно + продолжение промпта; Stable Audio использует более короткие клипы + кроссфейд.
- **Артефакты на границах.** Кроссфейд между сгенерированными клипами требует аккуратного сложения с перекрытием (overlap-add).
- **Аппетит к чистым данным.** Генераторам музыки нужны десятки тысяч часов лицензированной музыки. Судебный иск RIAA против Suno / Udio (2024) вывел эту проблему на поверхность.
- **Этика клонирования голоса.** 3-секундного образца плюс текстового промпта достаточно для VALL-E / XTTS / ElevenLabs, чтобы клонировать голос. Каждой продакшен-модели нужны обнаружение злоупотреблений + списки отказа от использования (opt-out).

## Итоговое задание

Сохраните `outputs/skill-audio-brief.md`. Навык принимает аудиобриф (задача, длительность, стиль, голос, лицензия) и выводит: модель + хостинг, формат промпта (жанровые теги, дескрипторы стиля, структурные маркеры), цепочку кодек + генератор + вокодер, протокол сида и план оценивания (MOS / оценка CLAP / CER для TTS / A/B-тестирование пользователями).

## Упражнения

1. **Лёгкое.** Запустите `code/main.py` и явно задайте стиль. Убедитесь, что сгенерированные последовательности соответствуют паттерну стиля.
2. **Среднее.** Добавьте отложенное параллельное декодирование: смоделируйте 2 потока токенов, которые должны оставаться со сдвигом в 1 шаг. Обучите совместный предсказатель.
3. **Сложное.** Используйте HuggingFace transformers, чтобы запустить MusicGen-small локально. Сгенерируйте 10-секундный клип с тремя разными промптами; проведите A/B-сравнение соответствия стилю.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Кодек | «Нейросетевое сжатие» | Кодировщик и декодировщик аудио; на выходе обычно получаются токены с частотой 50-75 Гц. |
| Остаточное векторное квантование (RVQ) | «Остаточное векторное квантование» | Каскад из K квантователей; каждый из них моделирует остаток предыдущего. |
| Токен | «Один символ кодека» | Дискретный индекс в кодовой книге; типичные размеры — 1024 или 2048. |
| Отложенный параллелизм | «Кодовые книги со сдвигом» | Генерация K потоков токенов со ступенчатыми сдвигами для сокращения длины последовательности. |
| Согласование потоков (flow matching) | «Главный прорыв 2024 года для аудио» | Альтернатива диффузии с более прямой траекторией и быстрым сэмплированием. |
| Голосовой промпт | «3-секундный образец» | Эмбеддинг говорящего или префикс токенов, который направляет клонирование голоса. |
| Мел-спектрограмма | «Визуальное представление» | Перцептивная спектрограмма логарифмических амплитуд; используется многими системами TTS. |
| Вокодер | «Из мел-спектрограммы в звуковую волну» | Нейросетевой компонент, преобразующий мел-спектрограммы обратно в аудио. |

## Заметка о продакшене: аудио — это потоковая задача

Аудио — единственная выходная модальность, которую пользователи ожидают получать *по мере генерации*, а не целиком за раз. В продакшен-терминах это значит, что важно время на выходной токен (Time Per Output Token, TPOT), поскольку целевая пропускная способность — это скорость прослушивания пользователем, а не скорость чтения. Для аудио 16 кГц, токенизированного с частотой ~75 токенов/сек (Encodec), сервер должен генерировать ≥75 токенов/сек на пользователя, чтобы воспроизведение оставалось плавным.

Два архитектурных следствия:

- **Аудиомодели на основе согласования потоков не могут стримиться тривиально.** Stable Audio 2.5 и AudioCraft 2 рендерят клип фиксированной длины за один проход. Для стриминга нужно разбивать клип на фрагменты и перекрывать границы — по сути, скользящее окно диффузии — что добавляет 100-300 мс задержки по сравнению с моделью token-AR на кодеке.

Если продукт — это «живой голосовой чат» или «продолжение музыки в реальном времени», выбирайте путь token-AR на кодеке. Если это «отрендерить 30-секундный клип при отправке», согласование потоков выигрывает по качеству и общей задержке.
