# StyleGAN

> Большинство генераторов подмешивают `z` во все слои одновременно. StyleGAN разделил это: сначала отобразите `z` в промежуточный `w`, затем *внедряйте* `w` на каждом уровне разрешения через AdaIN. Это единственное изменение распутало латентное пространство и на семь лет сделало фотореалистичные лица решённой задачей.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 8 · 03 (GAN), этап 4 · 08 (нормализация), этап 3 · 07 (CNN)
**Время:** ~45 минут

## Проблема

DCGAN отображает `z` в изображение через стек транспонированных свёрток. Проблема: `z` управляет всем сразу — позой, освещением, идентичностью, фоном — всё спутано вместе. Сдвиньтесь вдоль одной оси `z` — изменятся все четыре. Вы не можете спросить у модели «тот же человек, другая поза», потому что представление не факторизуется таким образом.

Karras et al. (2019, NVIDIA) предложили: перестаньте подавать `z` напрямую в свёрточные слои. Подайте на вход сети константный тензор `4×4×512`. Обучите 8-слойный MLP, отображающий `z ∈ Z → w ∈ W`. Внедряйте `w` на каждом уровне разрешения через *адаптивную нормализацию экземпляров* (AdaIN): нормализуйте каждую карту признаков свёртки, затем масштабируйте и сдвигайте аффинными проекциями `w`. Добавьте послойный шум для стохастических деталей (поры кожи, пряди волос).

Результат: `W` имеет примерно ортогональные оси для «высокоуровневого стиля» (поза, идентичность) и «тонкого стиля» (освещение, цвет). Вы можете обменивать стили между двумя изображениями, используя `w` изображения А для уровней низкого разрешения и `w` изображения Б — для уровней высокого разрешения. Это открыло редактирование, кросс-доменную стилизацию и целое направление исследований «инверсии StyleGAN».

## Концепция

![StyleGAN: сеть отображения + AdaIN + послойный шум](../assets/stylegan.svg)

**Сеть отображения.** `f: Z → W`, 8-слойный MLP. `Z = N(0, I)^512`. `W` не обязана быть гауссовой — она обучает форму, адаптированную под данные.

**Сеть синтеза.** Начинается с обучаемой константы `4×4×512`. Каждый блок разрешения: `upsample → conv → AdaIN(w_i) → noise → conv → AdaIN(w_i) → noise`. Разрешения удваиваются: 4, 8, 16, 32, 64, 128, 256, 512, 1024.

**AdaIN.**

```
AdaIN(x, y) = y_scale · (x - mean(x)) / std(x) + y_bias
```

где `y_scale` и `y_bias` получены аффинными проекциями `w`. Нормализуйте по карте признаков, затем измените её стиль. «Стиль» здесь — это статистики первого и второго порядка карты признаков.

**По-слойный шум.** Одноканальный гауссов шум, добавляемый к каждой карте признаков, масштабируемый обучаемым поканальным коэффициентом. Управляет стохастическими деталями, не затрагивая глобальную структуру.

**Приём усечения.** При инференсе: сэмплируйте `z`, вычислите `w = mapping(z)`, затем `w' = ŵ + ψ·(w - ŵ)`, где `ŵ` — среднее `w` по многим примерам. `ψ < 1` обменивает разнообразие на качество. Почти в каждом демо StyleGAN используется `ψ ≈ 0.7`.

## StyleGAN 1 → 2 → 3

| Версия | Год | Нововведение |
|---------|------|------------|
| StyleGAN | 2019 | Сеть отображения + AdaIN + шум + прогрессивное наращивание. |
| StyleGAN2 | 2020 | Демодуляция весов заменяет AdaIN (устраняет артефакты-«капли»); архитектура с пропускающими и остаточными соединениями; регуляризация длины пути. |
| StyleGAN3 | 2021 | Свёртка без алиасинга + эквивариантные ядра; устраняет прилипание текстуры к пиксельной сетке. |
| StyleGAN-XL | 2022 | Условная по классу, 1024², ImageNet. |
| R3GAN | 2024 | Ребрендинг с более сильной регуляризацией; закрывает разрыв с диффузией на FFHQ-1024, используя в 20 раз меньше параметров. |

В 2026 году StyleGAN3 остаётся стандартом для (a) фотореализма в узком домене при высоком FPS, (b) адаптации домена по нескольким примерам (обучение на новом наборе данных из 100 изображений, заморозка сети отображения), (c) редактирования на основе инверсии (найти `w`, восстанавливающий настоящее фото, затем редактировать этот `w`). Для генерации изображений по тексту в открытом домене это не тот инструмент — там правит диффузия.

## Постройте это

`code/main.py` реализует игрушечный «облегчённый StyleGAN» в одном измерении: отображающий MLP, функцию синтеза, которая берёт обучаемый константный вектор и модулирует его масштабом и сдвигом, полученными из `w`, и послойный шум. Он показывает, что внедрение `w` через аффинную модуляцию даёт такие же или лучшие результаты, чем конкатенация `z` со входом генератора.

### Шаг 1: сеть отображения

```python
def mapping(z, M):
    h = z
    for i in range(num_layers):
        h = leaky_relu(add(matmul(M[f"W{i}"], h), M[f"b{i}"]))
    return h
```

### Шаг 2: адаптивная нормализация экземпляров

```python
def adain(x, w_scale, w_bias):
    mu = mean(x)
    sd = std(x)
    x_norm = [(xi - mu) / (sd + 1e-8) for xi in x]
    return [w_scale * xi + w_bias for xi in x_norm]
```

Поканальные масштаб и сдвиг для каждой карты признаков получаются из `w` через линейную проекцию.

### Шаг 3: послойный шум

```python
def add_noise(x, sigma, rng):
    return [xi + sigma * rng.gauss(0, 1) for xi in x]
```

Сигма для каждого канала обучаема.

## Ловушки

- **Артефакты-«капли».** StyleGAN 1 производил бесформенную «каплю» на картах признаков, потому что AdaIN обнулял среднее. Демодуляция весов StyleGAN 2 исправляет это, масштабируя веса свёртки вместо активаций.
- **Прилипание текстуры.** Текстуры StyleGAN 1 и 2 следовали за координатами пикселей, а не координатами объекта (заметно при интерполяции). Свёртки без алиасинга StyleGAN 3 исправляют это оконными sinc-фильтрами.
- **Покрытие мод.** Усечение с `ψ < 0.7` даёт чистые результаты, но сэмплирует из узкого конуса; используйте `ψ = 1.0`, если нужно разнообразие.
- **Инверсия ведёт к потерям.** Инверсия настоящего фото в `W` обычно выполняется через оптимизацию или энкодер (e4e, ReStyle, HyperStyle). Результаты дрейфуют при большом числе итераций.

## Применение

| Сценарий использования | Подход |
|----------|----------|
| Фотореалистичные человеческие лица (аниме, продукт, узкий домен) | StyleGAN3 FFHQ / кастомное дообучение |
| Редактирование лица по фото | Инверсия e4e + направления StyleSpace / InterFaceGAN |
| Замена лица / перенос мимики | StyleGAN + энкодер + смешивание |
| Конвейеры аватаров | StyleGAN3 с ADA для дообучения на малых данных |
| Адаптация домена по нескольким изображениям | Заморозить сеть отображения, дообучить синтез |
| Мультимодальная или обусловленная текстом генерация | Не используйте — берите диффузию |

Для продуктовых демо, где ответ — «фото лица человека», StyleGAN превосходит диффузию по стоимости инференса (один прямой проход, <10 мс на 4090) и чёткости при том же уровне качества.

## Ключевые термины

| Термин | Как его называют | Что он на самом деле означает |
|------|-----------------|-----------------------|
| Сеть отображения | «MLP» | `f: Z → W`, 8 слоёв, отделяет геометрию латента от статистики данных. |
| Пространство W | «Пространство стиля» | Выход сети отображения; его факторы примерно разделены. |
| AdaIN | «Адаптивная нормализация экземпляров» | Нормализует карту признаков, затем масштабирует и сдвигает проекцией `w`. |
| Приём усечения | «Пси» | `w = mean + ψ·(w - mean)`, ψ<1 обменивает разнообразие на качество. |
| Регуляризация длины пути | «Регуляризация PL» | Штрафует большие изменения изображения на единицу изменения `w`; делает `W` более гладким. |
| Демодуляция весов | «Исправление StyleGAN2» | Нормализует веса свёртки вместо активаций; устраняет артефакты-«капли». |
| Без алиасинга | «Приём StyleGAN3» | Оконные sinc-фильтры; устраняет прилипание текстуры к пиксельной сетке. |
| Инверсия | «Найти w для настоящего изображения» | Оптимизировать или закодировать `x → w` так, чтобы `G(w) ≈ x`. |

## Заметка о продакшене: почему StyleGAN всё ещё используется в 2026 году

StyleGAN3 на 4090 генерирует лицо FFHQ 1024² менее чем за 10 мс — `num_steps = 1`, без декодирования VAE, без прохода перекрёстного внимания. В продакшен-терминах это нижняя граница задержки для любого генератора изображений. 50-шаговый конвейер SDXL + декодирование VAE при том же разрешении занимает ~3 секунды. Это разрыв в **300 раз**, и для продуктов в узком домене (сервисы аватаров, конвейеры для документов, удостоверяющих личность, генерация стоковых лиц) он побеждает по совокупной стоимости владения (TCO).

Два эксплуатационных следствия:

- **Ни планировщика, ни батчера.** Статичный батч при целевой загрузке оптимален. Непрерывный батчинг (необходимый для LLM и диффузии) не даёт никакой выгоды, потому что каждый запрос требует одинаковое число FLOPs.
- **Усечение с `ψ` — регулятор безопасности.** `ψ < 0.7` сэмплирует из узкого конуса диапазона сети отображения. Это единственный рычаг, которым слой обслуживания может управлять дисперсией примеров. Понижайте `ψ` при пиковой нагрузке, повышайте — для премиум-пользователей.
