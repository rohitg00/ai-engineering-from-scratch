# Оценивание — FID, CLIP Score, предпочтения людей

> Каждый лидерборд генеративных моделей ссылается на FID, CLIP score и процент побед из арены человеческих предпочтений. У каждой метрики есть уязвимость, которой упорный исследователь может воспользоваться. Если вы не знаете об этих уязвимостях, вы не сможете отличить реальное улучшение от подгонки под метрику.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 8 · 01 (Таксономия), фаза 2 · 04 (Метрики оценивания)
**Время:** ~45 минут

## Проблема

Генеративная модель оценивается по *качеству сэмплов* и *соответствию условию*. Ни у одного из этих критериев нет замкнутой формы измерения. Ваша модель должна отрендерить 10 000 изображений; что-то должно присвоить им числа; вы должны доверять этим числам в разных семействах моделей, разрешениях, архитектурах. Три метрики пережили испытание 2014-2026 годов:

- **FID (расстояние Фреше для признаков Inception).** Расстояние между двумя распределениями — реальным и сгенерированным — в пространстве признаков сети Inception. Чем ниже, тем лучше.
- **CLIP score.** Косинусное сходство между CLIP-эмбеддингом сгенерированного изображения и CLIP-эмбеддингом текста промпта. Чем выше, тем лучше. Измеряет соответствие промпту.
- **Предпочтения людей.** Столкнуть две модели лицом к лицу на одном промпте, дать людям (или модели уровня GPT-4) выбрать лучшую, агрегировать в рейтинг Эло.

Вы также встретите: IS (оценка Inception, в основном больше не используется), KID, CMMD, ImageReward, PickScore, HPSv2, MJHQ-30k. Каждая исправляет один провал предыдущей.

### FID — качество сэмплов

Heusel et al. (2017). Шаги:

1. Извлечь признаки Inception-v3 (2048-мерные) для N реальных изображений и N сгенерированных.
2. Подогнать гауссиан к каждому пулу: вычислить средние `μ_r, μ_g` и ковариации `Σ_r, Σ_g`.
3. FID = `||μ_r - μ_g||² + Tr(Σ_r + Σ_g - 2 · (Σ_r · Σ_g)^0.5)`.

Интерпретация: расстояние Фреше между двумя многомерными гауссианами в пространстве признаков. Ниже = более похожие распределения.

Провалы:
- **Смещение при малом N.** FID — это среднеквадратичное значение по распределению признаков; малое N недооценивает ковариацию, давая ложно заниженный FID. Всегда используйте N ≥ 10 000.
- **Зависимость от Inception.** Inception-v3 обучена на ImageNet. Домены, далёкие от ImageNet (лица, искусство, изображения с текстом), дают бессмысленный FID. Используйте доменно-специфичный экстрактор признаков.
- **Подгонка под метрику.** Переобучение под приор Inception даёт низкий FID без улучшения визуального качества. Побороть это можно с помощью CMMD (ниже).

### CLIP score — соответствие промпту

Radford et al. (2021). Для сгенерированного изображения + промпта:

```
clip_score = cos_sim( CLIP_image(x_gen), CLIP_text(prompt) )
```

Усреднение по 30 тыс. сгенерированных изображений → скаляр, сравнимый между моделями.

Провалы:
- **Собственные слепые зоны CLIP.** У CLIP слабое композиционное рассуждение («красный куб на синей сфере» часто не удаётся). Модели могут показывать хороший CLIP score, не следуя по-настоящему сложным промптам.
- **Смещение по коротким промптам.** У коротких промптов в реальных данных больше совпадений CLIP-изображение. У более длинных промптов CLIP score механически ниже.
- **Подгонка промпта.** Добавление в промпт «высокое качество, 4k, шедевр» завышает CLIP score без улучшения связи изображения с текстом.

CMMD (Jayasumana et al., 2024) исправляет часть этих недостатков: использует признаки CLIP вместо Inception и максимальное среднее расхождение вместо расстояния Фреше. Эта метрика лучше обнаруживает тонкие различия в качестве.

### Предпочтения людей — эталон истины

Выбрать пул промптов. Сгенерировать моделью A и моделью B. Показать пары людям (или сильному LLM-судье). Агрегировать победы в рейтинг Эло или Bradley-Terry. Бенчмарки:

- **PartiPrompts (Google)**: 1600 разнообразных промптов, 12 категорий.
- **HPSv2**: 107 тыс. аннотаций людей, широко используется как автоматизированный прокси.
- **ImageReward**: 137 тыс. пар предпочтений изображение-промпт, лицензия MIT.
- **PickScore**: обучен на 2,6 млн предпочтений Pick-a-Pic.
- **Арены изображений в стиле Chatbot-Arena**: https://imagearena.ai/ и другие.

Провалы:
- **Дисперсия судей.** У неэкспертов предпочтения отличаются от экспертов. Используйте оба варианта.
- **Распределение промптов.** Отобранные вручную промпты благоприятствуют одному семейству. Всегда документируйте это.
- **Взлом вознаграждения LLM-судьёй.** GPT-4-судью можно обмануть красивым, но неверным результатом. Триангулируйте с людьми.

## Использование вместе

Отчёт об оценивании для продакшена должен включать:

1. FID на 10-30 тыс. сэмплов относительно отложенного реального распределения (качество сэмплов).
2. CLIP score / CMMD на тех же сэмплах относительно их промптов (соответствие).
3. Процент побед в слепой арене против предыдущей модели (общее предпочтение).
4. Анализ провалов: 50 случайно отобранных выходов, помеченных по известным проблемам (анатомия рук, рендеринг текста, согласованное количество объектов).

Любая единичная метрика — это ложь. Три подтверждающие друг друга метрики + качественный обзор — это уже утверждение.

## Реализация

`code/main.py` реализует FID, аналог CLIP score и агрегацию Эло на синтетических «векторах признаков» (используются 4-мерные векторы вместо признаков Inception). Вы увидите:

- Вычисление FID на малом N и на большом N — смещение.
- «CLIP score» как косинусное сходство между пулами признаков.
- Правило обновления Эло из синтетического потока предпочтений.

### Шаг 1: FID в четыре строки

```python
def fid(real_features, gen_features):
    mu_r, cov_r = mean_and_cov(real_features)
    mu_g, cov_g = mean_and_cov(gen_features)
    mean_diff = sum((a - b) ** 2 for a, b in zip(mu_r, mu_g))
    trace_term = trace(cov_r) + trace(cov_g) - 2 * sqrt_cov_product(cov_r, cov_g)
    return mean_diff + trace_term
```

### Шаг 2: косинусное сходство в стиле CLIP

```python
def clip_like(image_feat, text_feat):
    dot = sum(a * b for a, b in zip(image_feat, text_feat))
    norm = math.sqrt(dot_self(image_feat) * dot_self(text_feat))
    return dot / max(norm, 1e-8)
```

### Шаг 3: агрегация Эло

```python
def elo_update(r_a, r_b, winner, k=32):
    expected_a = 1 / (1 + 10 ** ((r_b - r_a) / 400))
    actual_a = 1.0 if winner == "a" else 0.0
    r_a_new = r_a + k * (actual_a - expected_a)
    r_b_new = r_b - k * (actual_a - expected_a)
    return r_a_new, r_b_new
```

## Подводные камни

- **FID при N=1000.** Эвристика ненадёжна при N ниже 10 тыс. Статьи, сообщающие FID при малом N, подгоняются под метрику.
- **Сравнение FID между разрешениями.** Изменение размера до 299×299 в Inception меняет распределение признаков. Сравнивайте только при совпадающем разрешении.
- **Отчёт по одному сиду.** Запускайте минимум 3 сида. Сообщайте стандартное отклонение.
- **Завышение CLIP score через негативные промпты.** Некоторые конвейеры повышают CLIP score за счёт чрезмерной подгонки под промпт. Проверяйте на визуальное насыщение.
- **Смещение Эло из-за пересечения промптов.** Если обе модели видели тестовый промпт при обучении, Эло бессмысленен. Используйте отложенные наборы промптов.
- **Смещение платной толпы в оценке людьми.** Аннотаторы Prolific, MTurk смещены в сторону молодых / технически подкованных. Смешивайте с приглашёнными экспертами по искусству/дизайну.

## Применение

Продакшен-протокол оценивания в 2026 году:

| Компонент | Минимум | Рекомендуется |
|--------|---------|-------------|
| Качество сэмплов | FID на 10 тыс. сэмплов относительно отложенных реальных данных | + CMMD на 5 тыс. сэмплов + FID на подмножестве для каждой категории |
| Соответствие промпту | CLIP score на 30 тыс. сэмплов | + HPSv2 + ImageReward + ответы на вопросы в стиле VQA |
| Предпочтения | 200 слепых пар против базовой модели | + 2000 пар для оценивания людьми + LLM-судья + Chatbot Arena |
| Анализ провалов | 50 результатов, помеченных вручную | 500 результатов, помеченных вручную, + автоматический классификатор безопасности |

Все четыре опоры в одном отчёте = утверждение. Любая одна отдельно = маркетинг.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| FID | «Расстояние Фреше для признаков Inception» | Расстояние Фреше между гауссовскими аппроксимациями признаков Inception для реальных и сгенерированных данных. |
| CLIP score | «Сходство текста и изображения» | Косинусное сходство между эмбеддингами изображения и текста в CLIP. |
| CMMD | «Замена FID» | MMD по признакам CLIP; меньшее смещение и отсутствие предположения о гауссовском распределении. |
| IS | «Оценка Inception» | Exp KL(p(y|x) || p(y)); слабо коррелирует с качеством современных моделей и больше не используется. |
| HPSv2 / ImageReward / PickScore | «Обученные прокси-метрики предпочтений» | Небольшие модели, обученные на предпочтениях людей и используемые как автоматические судьи. |
| Elo | «Шахматный рейтинг» | Агрегация попарных побед по модели Bradley-Terry. |
| PartiPrompts | «Набор промптов для бенчмарка» | 1600 промптов в 12 категориях, подготовленных Google. |
| FD-DINO | «Замена на основе самообучения» | Расстояние Фреше по признакам DINOv2; лучше подходит для доменов за пределами ImageNet. |

## Заметка о продакшене: оценивание — это тоже инференс-нагрузка

Запуск FID на 10 тыс. сэмплов означает генерацию 10 тыс. изображений. Для 50-шаговой SDXL base при 1024² на одном L4 это ~11 часов инференса с одиночными запросами. Бюджеты на оценивание реальны, и картина в точности соответствует сценарию офлайн-инференса (максимизация пропускной способности, игнорирование TTFT):

- **Пакетируйте максимально жёстко, забудьте про задержку.** Офлайн-оценивание = статическое пакетирование максимально возможного размера, помещающегося в память. `pipe(...).images` с `num_images_per_prompt=8` на 80 ГБ H100 выполняется в 4-6 раз быстрее по времени выполнения, чем одиночные запросы.
- **Кешируйте признаки реальных данных.** Извлечение признаков Inception (для FID) или CLIP (для CLIP score, CMMD) по эталонному набору реальных данных выполняется *один раз* и сохраняется в `.npz`. Не пересчитывайте это для каждого оценивания.

Для CI / регрессионных проверок: запускайте FID + CLIP score на подмножестве из 500 сэмплов на каждый PR (~30 минут); полный FID на 10 тыс. + HPSv2 + Эло запускайте ночью.
