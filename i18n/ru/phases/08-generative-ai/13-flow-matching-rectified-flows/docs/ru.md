# Сопоставление потоков и ректифицированные потоки

> Диффузионные модели требуют 20-50 шагов сэмплирования, потому что идут по искривлённому пути от шума к данным. Сопоставление потоков (flow matching; Lipman et al., 2023) и ректифицированный поток (rectified flow; Liu et al., 2022) обучают прямолинейные пути. Более прямые пути означают меньше шагов, а значит — более быстрый инференс. Stable Diffusion 3, Flux.1 и AudioCraft 2 в 2024 году перешли на сопоставление потоков.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 8 · 06 (DDPM), фаза 1 · математический анализ
**Время:** ~45 минут

## Проблема

Обратный процесс DDPM — это 1000-шаговое стохастическое блуждание от `N(0, I)` обратно к распределению данных. DDIM свернул его до 20-50 детерминированных шагов. Хочется меньше шагов — в идеале один. Препятствие в том, что ОДУ, описывающее обратный процесс, является жёстким (stiff); путь искривлён.

Если бы модель можно было обучить так, чтобы путь от шума к данным был *прямой линией*, единственный шаг Эйлера от `t=1` к `t=0` сработал бы. Сопоставление потоков строит это напрямую: определяется прямолинейная интерполяция от `x_1 ∼ N(0, I)` к `x_0 ∼ data`, обучается векторное поле `v_θ(x, t)` для соответствия его производной по времени, при инференсе выполняется интегрирование.

Ректифицированный поток (Liu 2022) идёт дальше: итеративно выпрямляет пути с помощью процедуры повторного построения потока (reflow), дающей всё более линейное ОДУ. После двух итераций этой процедуры 2-шаговый сэмплер соответствует качеству 50-шагового DDPM.

## Концепция

![Сопоставление потоков: прямолинейная интерполяция между шумом и данными](../assets/flow-matching.svg)

### Прямолинейный поток

Определим:

```
x_t = t · x_1 + (1 - t) · x_0,   t ∈ [0, 1]
```

где `x_0 ~ data` и `x_1 ~ N(0, I)`. Производная по времени вдоль этой прямой линии постоянна:

```
dx_t / dt = x_1 - x_0
```

Определим нейросетевое векторное поле `v_θ(x_t, t)` и обучим его соответствовать этой производной:

```
L = E_{x_0, x_1, t} || v_θ(x_t, t) - (x_1 - x_0) ||²
```

Это функция потерь **условного сопоставления потоков** (conditional flow matching, Lipman 2023). Обучение не требует симуляции: ОДУ никогда не разворачивается. Достаточно сэмплировать `(x_0, x_1, t)` и выполнить регрессию.

### Сэмплирование

При инференсе выученное векторное поле интегрируется *назад* во времени:

```
x_{t-Δt} = x_t - Δt · v_θ(x_t, t)
```

Начните с `x_1 ~ N(0, I)` и делайте шаги Эйлера вниз до `t=0`.

### Ректифицированный поток (Liu 2022)

Прямолинейный поток работает, но выученные пути *на самом деле не прямые* — они искривляются, потому что многие `x_0` могут отображаться в один и тот же `x_1`. Этап повторного построения ректифицированного потока:

1. Обучить модель потока v_1 со случайным сопоставлением пар.
2. Сэмплировать N пар `(x_1, x_0)`, интегрируя v_1 от `x_1` до её точки приземления `x_0`.
3. Обучить v_2 на этих парных примерах. Поскольку пары теперь «согласованы с ОДУ», прямолинейный интерполянт между ними действительно более пологий.
4. Повторить.

На практике 2 итерации повторного построения потока приводят почти к линейности, обеспечивая 2-4-шаговый инференс. SDXL-Turbo, SD3-Turbo, LCM — все они являются моделями, дистиллированными из моделей сопоставления потоков.

### Почему это победило для изображений в 2024 году

Три причины:

1. **Обучение без симуляции** — никакого разворачивания ОДУ при обучении, тривиально реализуется.
2. **Лучшая геометрия функции потерь** — прямые пути дают согласованное отношение сигнал/шум, тогда как ε-функция потерь DDPM имеет плохое SNR на краях расписания.
3. **Более быстрый инференс** — 4-8 шагов при качестве SDXL-Turbo; 1 шаг с дистилляцией согласованности.

## Точная связь между сопоставлением потоков и DDPM

Сопоставление потоков с гауссовым условным путём — это диффузия *с конкретным расписанием шума*. Выберите расписание `x_t = α(t) x_0 + σ(t) x_1`, и сопоставление потоков восстанавливает диффузию, переформулированную в форме Стратоновича, с `v = α'·x_0 - σ'·x_1`. Для гауссовых путей эти два подхода алгебраически эквивалентны.

Что дало сопоставление потоков: *ясную* цель (простую скорость), более чистую функцию потерь и возможность экспериментировать с негауссовыми интерполянтами.

## Реализация

`code/main.py` реализует одномерное сопоставление потоков на двухмодовой гауссовой смеси. Векторное поле `v_θ(x, t)` — это небольшая многослойная нейросеть (MLP), обучаемая с прямолинейной целью. При инференсе выполняется интегрирование в 1, 2, 4 и 20 шагов Эйлера, и сравнивается качество сэмплов.

### Шаг 1: функция потерь при обучении

```python
def train_step(x0, net, rng, lr):
    x1 = rng.gauss(0, 1)
    t = rng.random()
    x_t = t * x1 + (1 - t) * x0
    target = x1 - x0
    pred = net_forward(x_t, t)
    loss = (pred - target) ** 2
    # backprop + update
```

### Шаг 2: многошаговый инференс

```python
def sample(net, num_steps):
    x = rng.gauss(0, 1)
    for i in range(num_steps):
        t = 1.0 - i / num_steps
        dt = 1.0 / num_steps
        x -= dt * net_forward(x, t)
    return x
```

### Шаг 3: сравнение числа шагов

Ожидается, что 4-шаговый сэмплер уже соответствует качеству 20-шагового — существенно для задержки.

## Подводные камни

- **Параметризация времени.** Сопоставление потоков использует `t ∈ [0, 1]`, где `t=0` соответствует данным, а `t=1` — шуму. DDPM использует `t ∈ [0, T]`, где `t=0` соответствует данным, а `t=T` — шуму. То же направление, другой масштаб. Статьи постоянно путают это.
- **Выбор расписания.** Прямая линия ректифицированного потока — это «то самое» расписание сопоставления потоков, но можно использовать косинусное или логит-нормальное сэмплирование t (так делает SD3) для лучшего охвата масштаба.
- **Стоимость повторного построения потока.** Генерация парного набора данных для этой процедуры — это полный проход инференса на каждый сэмпл. Выполняйте её только тогда, когда действительно нужен 1-2-шаговый инференс.
- **Управление без классификатора (classifier-free guidance) по-прежнему применимо.** Просто замените ε на v в линейной комбинации: `v_cfg = (1+w) v_cond - w v_uncond`.

## Упражнения

1. **Лёгкое.** Запустите `code/main.py` и сравните MSE для 1 шага против 20 шагов относительно истинного распределения данных.
2. **Среднее.** Перейдите от равномерного сэмплирования `t` к логит-нормальному (концентрирует сэмплирование около среднего t). Улучшается ли качество модели?
3. **Сложное.** Реализуйте одну итерацию повторного построения потока: сгенерируйте парные (x_0, x_1), интегрируя первую модель, обучите вторую модель на парах и сравните качество 1-шагового сэмплирования.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Сопоставление потоков | «Прямолинейная диффузия» | Обучение `v_θ(x, t)` на соответствие `x_1 - x_0` вдоль интерполянта. |
| Ректифицированный поток | «Повторное построение потока» | Итеративная процедура, выпрямляющая выученные потоки. |
| Поле скоростей | «v_θ» | Выход модели — направление, в котором нужно перемещать `x_t`. |
| Прямолинейный интерполянт | «Путь» | `x_t = (1-t)·x_0 + t·x_1`; производная цели вычисляется тривиально. |
| Сэмплер Эйлера | «Решатель ОДУ первого порядка» | Простейший интегратор; хорошо работает, когда пути прямые. |
| Логит-нормальное t | «Сэмплирование SD3» | Концентрация сэмплирования `t` около средних значений, где градиенты наиболее сильны. |
| Дистилляция согласованности | «Одношаговый сэмплер» | Обучение модели-ученика напрямую отображать любое `x_t` в `x_0`. |
| CFG со скоростью | «v-CFG» | `v_cfg = (1+w) v_cond - w v_uncond`; тот же приём, но с новой переменной. |

## Заметка о продакшене: Flux.1-schnell — сопоставление потоков на максимальной скорости

Главный продакшен-успех сопоставления потоков — Flux.1-schnell: DiT на основе этого метода, дистиллированный до 1-4 шагов инференса при сохранении качества уровня Flux-dev. Ноутбук Нильса «Запуск Flux на машине с 8 ГБ памяти» — эталонный рецепт развёртывания: кодирование T5 + CLIP, квантованное шумоподавление MMDiT (за 4 шага для schnell против 50 для dev), декодирование VAE. Учёт стоимости:

| Вариант | Шаги | Задержка при 1024² на L4 | Общее число FLOPs (относительное) |
|---------|-------|------------------------|------------------------|
| Flux.1-dev (исходный) | 50 | ~15 с | 1.0× |
| Flux.1-schnell | 4 | ~1.2 с | 0.08× (в 12× быстрее) |
| SDXL-base | 30 | ~4 с | 0.25× |
| SDXL-Lightning, 2 шага | 2 | ~0.3 с | 0.03× |

Продакшен-правило: **база на сопоставлении потоков + дистилляция = стандарт 2026 года для быстрой генерации изображений по тексту.** Каждый крупный вендор поставляет эту комбинацию: SD3-Turbo (SD3 + поток + дистилляция), Flux-schnell (Flux-dev + выпрямление ректифицированного потока), CogView-4-Flash. Чисто диффузионные базы сохраняются только для устаревших контрольных точек.
