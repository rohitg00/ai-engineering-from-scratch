# Автокодировщики и вариационные автокодировщики (VAE)

> Обычный автокодировщик сжимает, а затем восстанавливает. Он запоминает. Он не генерирует. Добавьте один приём — заставьте код выглядеть гауссовым — и получите сэмплер. Именно этот приём, репараметризация `z = μ + σ·ε`, — причина, по которой у каждой модели латентной диффузии и согласования потоков (flow matching), которой вы пользуетесь в 2026 году, на входе стоит VAE.

## Проблема

Сожмите 784-пиксельную цифру MNIST в код из 16 чисел, а затем восстановите. Обычный автокодировщик отлично справится с MSE реконструкции, но пространство кода окажется бесформенной кашей. Возьмите случайную точку в пространстве кода, декодируйте её — и получите шум. У него нет сэмплера. Это модель сжатия, наряженная во что-то другое.

На самом деле вам нужно: (a) пространство кода — это чистое, гладкое распределение, из которого можно сэмплировать, скажем, изотропная гауссиана `N(0, I)`, (b) декодирование любого сэмпла даёт правдоподобную цифру, и (c) энкодер и декодер всё ещё хорошо сжимают. Три цели, одна архитектура, одна функция потерь.

VAE Кингмы 2013 года решает эту проблему, обучая энкодер выдавать *распределение* `q(z|x) = N(μ(x), σ(x)²)`, притягивая это распределение к априорному `N(0, I)` через штраф KL, а затем сэмплируя `z` из `q(z|x)` перед декодированием. При инференсе энкодер отбрасывается, сэмплируется `z ~ N(0, I)`, выполняется декодирование. Именно штраф KL заставляет пространство кода быть структурированным.

В 2026 году VAE редко поставляются как самостоятельная модель — по чистому качеству изображений их превзошла диффузия, — но они остаются энкодером по умолчанию для каждой модели латентной диффузии (SD 1/2/XL/3, Flux, AudioCraft). Изучив VAE, вы изучите невидимый первый слой любого используемого вами конвейера обработки изображений.

## Концепция

![Автокодировщик и VAE: приём репараметризации](../assets/vae.svg)

**Автокодировщик.** `z = encoder(x)`, `x̂ = decoder(z)`, потери = `||x - x̂||²`. Пространство кода неструктурировано.

**Энкодер VAE.** Выдаёт два вектора: `μ(x)` и `log σ²(x)`. Они определяют `q(z|x) = N(μ, diag(σ²))`.

**Приём репараметризации.** Сэмплирование из `q(z|x)` недифференцируемо. Представьте сэмплированное значение в виде `z = μ + σ·ε`, где `ε ~ N(0, I)`. Теперь `z` — детерминированная функция от `(μ, σ)` плюс шум, не зависящий от обучаемых параметров, — градиенты проходят через `μ` и `σ`.

**Функция потерь.** Нижняя граница правдоподобия (ELBO), два слагаемых:

```
loss = reconstruction + β · KL[q(z|x) || N(0, I)]
     = ||x - x̂||²  + β · Σ_i ( σ_i² + μ_i² - log σ_i² - 1 ) / 2
```

Реконструкция подталкивает `x̂` к `x`. KL подталкивает `q(z|x)` к априорному распределению. Между ними компромисс. Малое β (<1) = более чёткие сгенерированные образцы, пространство кода менее гауссово. Большое β (>1) = более чистое пространство кода, более размытые сгенерированные образцы. β-VAE (Higgins 2017) сделал эту ручку знаменитой и положил начало исследованиям разделения факторов (disentanglement).

**Сэмплирование.** При инференсе: возьмите `z ~ N(0, I)`, пропустите через декодер. Один прямой проход — никакого итеративного сэмплирования, как в диффузии.

## Постройте это

`code/main.py` реализует крошечный VAE без numpy или torch. Вход — 8-мерные синтетические данные, взятые из 2-компонентной смеси гауссиан в 8-мерном пространстве. Энкодер и декодер — MLP с одним скрытым слоем. Мы реализуем активацию tanh, прямой проход, функцию потерь и обратный проход, написанный вручную. Не для продакшена — для педагогики.

### Шаг 1: прямой проход энкодера

```python
def encode(x, enc):
    h = tanh(add(matmul(enc["W1"], x), enc["b1"]))
    mu = add(matmul(enc["W_mu"], h), enc["b_mu"])
    log_sigma2 = add(matmul(enc["W_sig"], h), enc["b_sig"])
    return mu, log_sigma2
```

`log σ²` вместо `σ`, чтобы выход сети был неограничен (функция softplus от σ — ловушка: градиенты затухают при σ ≈ 0).

### Шаг 2: репараметризация и декодирование

```python
def reparameterize(mu, log_sigma2, rng):
    eps = [rng.gauss(0, 1) for _ in mu]
    sigma = [math.exp(0.5 * lv) for lv in log_sigma2]
    return [m + s * e for m, s, e in zip(mu, sigma, eps)]

def decode(z, dec):
    h = tanh(add(matmul(dec["W1"], z), dec["b1"]))
    return add(matmul(dec["W_out"], h), dec["b_out"])
```

### Шаг 3: ELBO

```python
def elbo(x, x_hat, mu, log_sigma2, beta=1.0):
    recon = sum((a - b) ** 2 for a, b in zip(x, x_hat))
    kl = 0.5 * sum(math.exp(lv) + m * m - lv - 1 for m, lv in zip(mu, log_sigma2))
    return recon + beta * kl, recon, kl
```

Точный KL в замкнутой форме, потому что оба распределения гауссовы. Не нужно вычислять интеграл численно. В 2026 году люди всё ещё поставляют код с монте-карло-оценками KL — это в 3 раза медленнее без всякой причины.

### Шаг 4: генерация

```python
def sample(dec, z_dim, rng):
    z = [rng.gauss(0, 1) for _ in range(z_dim)]
    return decode(z, dec)
```

Вот и вся генеративная модель. Пять строк.

## Ловушки

- **Коллапс апостериорного распределения (posterior collapse).** Слагаемое KL так агрессивно тянет `q(z|x) → N(0, I)`, что `z` перестаёт нести информацию о `x`. Решение: постепенное увеличение β (β-annealing: начать с β=0 и поднять до 1), свободные биты (free bits) либо не учитывать KL на неактивных измерениях.
- **Размытые сгенерированные образцы.** Гауссово правдоподобие декодера подразумевает реконструкцию по MSE, что байесовски оптимально для L2 (среднего) — а среднее набора правдоподобных цифр это размытая цифра. Решение: дискретный декодер (VQ-VAE, NVAE), либо использовать VAE только как энкодер и надстроить диффузию над латентами (именно так делает Stable Diffusion).
- **β слишком большое, слишком рано.** См. коллапс апостериорного распределения. Начинайте с β≈0.01 и постепенно поднимайте.
- **Слишком маленькая размерность латента.** 16-D подходит для MNIST, 256-D — для ImageNet 256², 2048-D — для ImageNet 1024². VAE Stable Diffusion сжимает 512×512×3 → 64×64×4 (в 32 раза по пространственной площади, в 32 раза по каналам).

## Применение

Стек VAE в 2026 году:

| Ситуация | Выбор |
|-----------|------|
| Энкодер латентов изображения для диффузии | Stable Diffusion VAE (`sd-vae-ft-ema`) или Flux VAE |
| Энкодер латентов аудио | Encodec (Meta), SoundStream или DAC (Descript) |
| Латенты для видео | Пространственно-временные патчи Sora, Latte VAE, WAN VAE |
| Обучение разделённых представлений | β-VAE, FactorVAE, TCVAE |
| Дискретные латенты (для моделирования трансформером) | VQ-VAE, RVQ (ResidualVQ) |
| Непрерывные латенты для генерации | Обычный VAE, затем обусловьте модель потока или диффузии в этом латентном пространстве |

Модель латентной диффузии — это VAE, между энкодером и декодером которого живёт диффузионная модель. VAE выполняет грубое сжатие, а диффузионная модель делает основную работу. Тот же паттерн для видео (VAE + видео-диффузионный DiT) и аудио (Encodec + трансформер MusicGen).

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Автокодировщик | Сеть кодирования-декодирования | `x → z → x̂`, обучение по MSE. Не генеративная модель. |
| VAE | Автокодировщик со сэмплером | Энкодер выдаёт распределение, штраф KL формирует пространство кода. |
| ELBO | Нижняя граница правдоподобия | `log p(x) ≥ recon - KL[q(z\|x) \|\| p(z)]`; точна при `q = p(z\|x)`. |
| Репараметризация | `z = μ + σ·ε` | Переписывает стохастический узел как детерминированную часть плюс чистый шум. Позволяет выполнять обратное распространение ошибки через сэмплирование. |
| Априорное распределение | `p(z)` | Целевое распределение латента, обычно `N(0, I)`. |
| Коллапс апостериорного распределения | «KL-слагаемое побеждает» | Энкодер игнорирует `x`, выдаёт априорное распределение; декодеру приходится галлюцинировать. |
| β-VAE | Настраиваемый вес KL | `loss = recon + β·KL`. Больше β = лучше разделены факторы, но сильнее размытие. |
| VQ-VAE | Дискретный латент | Заменяет непрерывный `z` ближайшим вектором кодовой книги; позволяет моделировать трансформером. |

## Заметка о продакшене: VAE — самый горячий участок диффузионного сервера

В конвейере Stable Diffusion / Flux / SD3 VAE вызывается дважды за запрос — один раз для энкодинга (при img2img / дорисовке (inpainting)) и один раз для декодирования. При 1024² проход декодера часто оказывается самым большим пиком памяти активаций во всём конвейере, потому что он апсемплит латенты `128×128×16` обратно в `1024×1024×3`. Два практических следствия:

- **Разбивайте декодирование на срезы или тайлы.** `diffusers` предоставляет `pipe.vae.enable_slicing()` и `pipe.vae.enable_tiling()`. Тайлинг обменивает небольшой артефакт по шву на память `O(tile²)` вместо `O(H·W)`. Необходимо для 1024²+ на потребительских GPU.
- **bf16 для декодера, fp32-арифметика для финального ресайза.** VAE SD 1.x был выпущен в fp32 и *молча выдаёт NaN* при приведении к fp16 на 1024²+. SDXL поставляется с `madebyollin/sdxl-vae-fp16-fix` — всегда предпочитайте вариант fp16-fix или используйте bf16.
