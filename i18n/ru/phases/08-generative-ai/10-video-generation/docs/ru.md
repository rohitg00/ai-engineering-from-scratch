# Генерация видео

> Изображение — это двумерный тензор. Видео — трёхмерный. Теория та же; вычисления сложнее в 10-100 раз. Sora от OpenAI (февраль 2024) доказала, что это возможно. К 2026 году Veo 2, Kling 1.5, Runway Gen-3, Pika 2.0 и WAN 2.2 поставляют продакшен-видео из текста в 1080p — а стек с открытыми весами (CogVideoX, HunyuanVideo, Mochi-1, WAN 2.2) отстаёт всего на 12 месяцев.

**Тип:** Build
**Языки:** Python
**Требования:** Этап 8 · 07 (латентная диффузия), этап 7 · 09 (ViT), этап 8 · 06 (DDPM)
**Время:** ~45 минут

## Проблема

10-секундное видео 1080p при 24 fps — это 240 кадров по 1920×1080×3 пикселей. Это ~1,5 ГБ сырых данных на клип. Диффузия в пространстве пикселей неосуществима. Нужны:

1. **Пространственно-временное сжатие.** VAE, кодирующий видео целиком, а не отдельные кадры, в последовательность пространственно-временных патчей.
2. **Временная согласованность.** Кадры должны сохранять общее содержание, освещение и идентичность объектов на протяжении секунд. Сеть должна моделировать движение.
3. **Вычислительный бюджет.** Обучение на видео в 10-100 раз дороже, чем на изображениях, при том же размере модели.
4. **Обусловливание.** Текст, изображение (первый кадр), аудио или другое видео. Большинство продакшен-моделей принимают все четыре варианта.

Архитектура, которая это решила, — **диффузионный трансформер (Diffusion Transformer, DiT)**, применяемый к пространственно-временным патчам и обучаемый на огромных наборах данных из промптов, описаний и видео. Та же функция потерь диффузии, что и в уроке 06.

## Концепция

![Видеодиффузия: патчификация, DiT, декодирование](../assets/video-generation.svg)

### Патчификация

Кодируем видео с помощью 3D VAE (обучаемое пространственно-временное сжатие). Латент имеет форму `[T_latent, H_latent, W_latent, C_latent]`. Разбиваем на патчи размера `[t_p, h_p, w_p]`. Для моделей в стиле Sora `t_p = 1` (патчи по кадру) или `t_p = 2` (каждые два кадра). 10-секундное видео 1080p сжимается примерно до 20 000-100 000 патчей.

### Пространственно-временной DiT

Трансформер обрабатывает плоскую последовательность патчей. У каждого патча есть 3D позиционный эмбеддинг (время + y + x). Внимание обычно факторизуется:

- **Пространственное внимание (spatial attention)** — внутри патчей каждого кадра.
- **Временное внимание (temporal attention)** — между кадрами в одной и той же пространственной позиции.
- **Полное 3D-внимание (full 3D attention)** дороже в 16-100 раз; применяется только при низком разрешении или в исследованиях.

### Текстовое обусловливание

Перекрёстное внимание (cross-attention) с крупным текстовым энкодером (T5-XXL для Sora, CogVideoX-5B тоже использует T5-XXL). Длинные промпты имеют значение — обучающий набор Sora содержал подробные повторные описания, сгенерированные GPT, в среднем по 200 токенов на клип.

### Обучение

Стандартная функция потерь диффузии (предсказание ε или v) на пространственно-временных латентах. Данные: видео из веба + ~100 млн отобранных клипов + синтетические текстовые описания. Вычисления: 10 000+ GPU-часов даже для небольшого исследовательского запуска; масштаб Sora — 100 000+.

## Постройте это

`code/main.py` моделирует ключевую идею пространственно-временного DiT: патчификация небольшого синтетического видео, добавление позиционного эмбеддинга для каждого патча и денойзинг всей последовательности с помощью внимания в стиле трансформера над патчами. Без numpy, на чистом Python. Мы показываем, что временная согласованность возникает даже в одномерном случае, если патчи соседних кадров используют общий денойзер и общие позиционные эмбеддинги.

### Шаг 1: патчификация синтетического одномерного «видео»

```python
def make_video(T_frames=8, rng=None):
    # a "video" is a sequence of 1-D values following a smooth trajectory
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### Шаг 2: позиционный эмбеддинг для каждого кадра

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### Шаг 3: денойзер видит всю последовательность

Вместо того чтобы очищать от шума каждый кадр по отдельности, наша крошечная сеть объединяет значения всех кадров с их позиционными эмбеддингами и предсказывает шум сразу для всех кадров.

### Шаг 4: проверка временной согласованности

После обучения сэмплируем видео. Измеряем разницу между соседними кадрами. Если модель выучила временную структуру, эти разницы остаются меньше, чем при независимом сэмплировании каждого кадра.

## Подводные камни

- **Независимое покадровое сэмплирование = мерцание.** Если запускать диффузию изображений отдельно для каждого кадра, результат мерцает, потому что шум каждого кадра независим. Видеодиффузия устраняет это, связывая кадры через внимание или общий шум.
- **Наивное 3D-внимание = OOM.** Полное 3D-внимание на латенте 10-секундного видео 1080p — это сотни миллиардов операций. Факторизуйте его на пространственное и временное.
- **Качество описаний данных важнее размера.** Главное улучшение Sora по сравнению с предыдущими работами — обучение на описаниях, детализированных примерно в 10 раз сильнее (клипы, переразмеченные GPT-4). Технический отчёт OpenAI прямо об этом говорит.
- **Обусловливание по первому кадру.** Большинство продакшен-моделей также принимают изображение в качестве первого кадра. Это режим генерации видео по изображению; обучение включает и этот вариант.
- **Дрейф физики.** Длинные клипы (>10 с) накапливают тонкие несогласованности. Помогает генерация скользящим окном в сочетании с привязкой к ключевым кадрам.

## Упражнения

1. **Лёгкое.** В `code/main.py` сравните разницу между соседними кадрами для (а) независимого покадрового сэмплирования и (б) совместного сэмплирования последовательности. Приведите среднее значение и дисперсию этих разниц.

3. **Сложное.** Используйте HuggingFace diffusers, чтобы запустить CogVideoX-2B на локальном GPU. Замерьте время 20 шагов инференса при 720p для 6-секундного клипа. Профилируйте пространственно-временное внимание, чтобы найти узкое место.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Видео-VAE | «3D VAE» | Энкодер, сжимающий `(T, H, W, C)` в пространственно-временной латент. |
| Патчи | «Токены» | 3D-блоки фиксированного размера из латента; вход для DiT. |
| Факторизованное внимание | «Пространственное + временное» | Применение внимания сначала по пространству, затем по времени без полного 3D-внимания. |
| Генерация видео по изображению (I2V) | «Оживить эту фотографию» | Модель принимает изображение и текст и выдаёт видео, которое начинается с этого изображения. |
| Обусловливание по ключевым кадрам | «Якорные кадры» | Закрепление конкретных кадров для управления развитием видео. |
| Кисть движения | «Указание направления» | Элемент интерфейса, в котором пользователь рисует векторы движения поверх изображения. |
| Повторное описание | «Подробные описания» | Использование LLM для повторной разметки обучающих клипов подробными промптами. |
| Мерцание | «Временной артефакт» | Несогласованность между соседними кадрами; устраняется связанным денойзингом. |

## Заметка о продакшене: латенты видео — это проблема пропускной способности памяти

10-секундный клип 1080p при 24 fps — это 240 кадров × 1920 × 1080 × 3 ≈ 1,5 ГБ сырых пикселей. После 4-кратного сжатия видео-VAE (`2 × spatial × 2 × temporal`) латент занимает ~100 МБ на запрос. Пропустите это через пространственно-временной DiT за 30 шагов с размером пакета 1 — и вы будете перемещать ~3 ГБ за шаг через HBM: узкое место — пропускная способность памяти, а не FLOPs.

Три продакшен-рычага — все прямо из главы об инференсе в литературе по продакшен-инференсу:

- **TP по DiT.** Модели генерации видео по тексту обычно имеют ≥10 млрд параметров. TP=4 на 4 H100 — стандарт; для моделей класса 405B — PP=2 × TP=2. Задержка на шаг падает примерно линейно с ростом TP вплоть до ограничений операции all-reduce.
- **Пакетная обработка кадров = непрерывная пакетная обработка (continuous batching).** На этапе генерации видео концептуально представляет собой пакет кадров, связанных вниманием. Применима непрерывная пакетная обработка (планирование «на лету»): начинайте рендерить кадр `t+1`, пока кадр `t-1` ещё возвращается, если архитектура модели допускает генерацию скользящим окном.
- **Кеш предварительного заполнения (prefill) на уровне клипа.** При генерации видео по изображению обусловливание по первому кадру аналогично предварительному заполнению промпта у LLM: вычисляем его один раз и переиспользуем во всех проходах временного декодера. По сути, это KV-кеш для видео.
