# Многоголовое внимание

> Одна голова внимания учит одно отношение за раз. Восемь голов учат восемь. Головы бесплатны. Берите их больше.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 02 (самовнимание с нуля)
**Время:** ~75 минут

## Проблема

Одна голова самовнимания вычисляет одну матрицу внимания. Эта матрица захватывает один вид связи — обычно тот, который минимизирует функцию потерь на том сигнале обучения, который есть. Если в ваших данных перепутаны согласование подлежащего и сказуемого, кореференция, дальний дискурс и синтаксическое разбиение на фрагменты, одна голова размазывает их все в одно распределение функции softmax и теряет половину сигнала.

Решение из статьи Vaswani 2017 года: запустить несколько функций внимания параллельно, каждую со своими проекциями Q, K, V, и конкатенировать выходы. Каждая голова работает в подпространстве меньшей размерности `d_model / n_heads`. Общее число параметров остаётся тем же. Выразительная мощность растёт.

Многоголовое внимание — стандартный механизм каждого трансформера, выпускаемого в 2026 году. Спор идёт только о том, *сколько* голов брать и разделяют ли ключи и значения проекции: во внимании со сгруппированными запросами (Grouped-Query Attention), многозапросном внимании (Multi-Query Attention) и многоголовом латентном внимании (Multi-head Latent Attention).

## Концепция

![Многоголовое внимание: разбиение, вычисление внимания и конкатенация](../assets/multi-head-attention.svg)

**Разбиение.** Возьмите `X` формы `(N, d_model)`. Спроецируйте в Q, K, V, каждая формы `(N, d_model)`. Измените форму на `(N, n_heads, d_head)`, где `d_head = d_model / n_heads`. Транспонируйте в `(n_heads, N, d_head)`.

**Параллельное внимание.** Запустите механизм внимания на основе масштабированного скалярного произведения внутри каждой головы. Каждая голова выдаёт `(N, d_head)`. Головы работают на разных подпространствах эмбеддинга и никак не взаимодействуют друг с другом в процессе самого вычисления внимания.

**Конкатенация и проекция.** Соберите головы обратно в `(N, d_model)` и умножьте на обучаемую выходную матрицу `W_o` формы `(d_model, d_model)`. Именно в `W_o` головы получают возможность смешиваться.

**Почему это работает.** Каждая голова может специализироваться, не конкурируя с остальными за бюджет представления. Исследования зондирования 2019–2024 годов показывают отдельные роли голов: позиционные головы, головы, обращающие внимание на предыдущий токен, копирующие головы, головы для именованных сущностей, индукционные головы (лежащие в основе обучения в контексте).

**Родословная вариаций 2026 года:**

| Вариант | Головы Q | Головы K/V | Используется в |
|---------|---------|-----------|---------|
| Многоголовое внимание (MHA) | N | N | GPT-2, BERT, T5 |
| Многозапросное внимание (MQA) | N | 1 | PaLM, Falcon |
| Внимание со сгруппированными запросами (GQA) | N | G (например, N/8) | Llama 2 70B, Llama 3+, Qwen 2+, Mistral |
| Многоголовое латентное внимание (MLA) | N | сжаты до низкого ранга | DeepSeek-V2, V3 |

GQA стал современным выбором по умолчанию, поскольку сокращает память KV-кеша в `N/G` раз, сохраняя почти полное качество. MLA идёт ещё дальше, сжимая K/V в латентное пространство и восстанавливая их обратно во время вычислений — это стоит FLOPs, но экономит гораздо больше памяти.

## Построение

### Шаг 1: разбиение голов из уже готового одноголового внимания

Возьмите `SelfAttention` из урока 02 и оберните его парой операций разбиения и конкатенации. Реализацию на NumPy см. в `code/main.py`; логика такова:

```python
def split_heads(X, n_heads):
    n, d = X.shape
    d_head = d // n_heads
    return X.reshape(n, n_heads, d_head).transpose(1, 0, 2)  # (heads, n, d_head)

def combine_heads(H):
    h, n, d_head = H.shape
    return H.transpose(1, 0, 2).reshape(n, h * d_head)
```

Одно изменение формы и одно транспонирование. Без циклов. Именно это делает PyTorch внутри `nn.MultiheadAttention`.

### Шаг 2: запуск внимания на основе масштабированного скалярного произведения для каждой головы

Каждая голова получает свой срез Q, K, V. Внимание превращается в пакетное матричное умножение:

```python
def mha_forward(X, W_q, W_k, W_v, W_o, n_heads):
    Q = X @ W_q
    K = X @ W_k
    V = X @ W_v
    Qh = split_heads(Q, n_heads)         # (heads, n, d_head)
    Kh = split_heads(K, n_heads)
    Vh = split_heads(V, n_heads)
    scores = Qh @ Kh.transpose(0, 2, 1) / np.sqrt(Qh.shape[-1])
    weights = softmax(scores, axis=-1)
    out = weights @ Vh                    # (heads, n, d_head)
    concat = combine_heads(out)
    return concat @ W_o, weights
```

На реальном оборудовании `Qh @ Kh.transpose(...)` — это один `bmm`. GPU видит единое пакетное матричное умножение формы `(heads, N, d_head) × (heads, d_head, N) -> (heads, N, N)`. Добавление голов ничего не стоит.

### Шаг 3: вариант внимания со сгруппированными запросами

Меняются только проекции ключа и значения. Q получает `n_heads` групп; K и V получают `n_kv_heads < n_heads` групп и повторяются, чтобы соответствовать друг другу:

```python
def gqa_project(X, W, n_kv_heads, n_heads):
    kv = split_heads(X @ W, n_kv_heads)       # (kv_heads, n, d_head)
    repeat = n_heads // n_kv_heads
    return np.repeat(kv, repeat, axis=0)      # (n_heads, n, d_head)
```

Во время инференса это экономит память, потому что в KV-кеше живут только `n_kv_heads` копий, а не `n_heads`. Llama 3 70B использует 64 головы запросов при 8 KV-головах — сокращение кеша в 8 раз.

### Шаг 4: исследуем, что выучила каждая голова

Запустите MHA на коротком предложении с 4 головами. Для каждой головы выведите матрицу внимания `(N, N)`. Вы увидите, что разные головы выделяют разную структуру даже при случайной инициализации — это отчасти сигнал, отчасти вращательная симметрия в подпространствах.

## Применение

В PyTorch однострочная версия:

```python
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
```

GQA начиная с PyTorch 2.5+:

```python
from torch.nn.functional import scaled_dot_product_attention

# scaled_dot_product_attention auto-dispatches Flash Attention on CUDA.
# For GQA, pass Q of shape (B, n_heads, N, d_head) and K,V of shape
# (B, n_kv_heads, N, d_head). PyTorch handles the repeat.
out = scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)
```

**Сколько брать голов?** Практические правила от продакшн-моделей 2026 года:

| Размер модели | d_model | n_heads | d_head |
|------------|---------|---------|--------|
| Малая (~125M) | 768 | 12 | 64 |
| Базовая (~350M) | 1024 | 16 | 64 |
| Большая (~1B) | 2048 | 16 | 128 |
| Передовая (~70B) | 8192 | 64 | 128 |

`d_head` почти всегда оказывается равен 64 или 128. Это единица измерения того, сколько может «увидеть» одна голова. Опуститесь ниже 32 — и головы начнут бороться с масштабирующим фактором `sqrt(d_head)`; поднимитесь выше 256 — и потеряете выгоду от «множества маленьких специалистов».

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Голова (head) | «Отдельная цепь внимания» | Одна проекция Q/K/V размерности `d_head = d_model / n_heads` со своей матрицей внимания. |
| d_head | «Размерность головы» | Скрытая ширина в расчёте на голову; почти всегда 64 или 128 в продакшне. |
| Разбиение / объединение (split / combine) | «Трюки с изменением формы» | Изменение формы и транспонирование `(N, d_model) ↔ (n_heads, N, d_head)` до и после вычисления внимания. |
| W_o | «Выходная проекция» | Матрица `(d_model, d_model)`, применяемая после конкатенации голов; место, где головы смешиваются. |
| MQA | «Одна KV-голова» | Многозапросное внимание: единая общая проекция K/V. Наименьший KV-кеш, некоторая потеря качества. |
| GQA | «Стандарт со времён Llama 2» | Внимание со сгруппированными запросами и `n_kv_heads < n_heads`; K/V повторяются для соответствия Q. |
| MLA | «Трюк DeepSeek» | Многоголовое латентное внимание: K, V сжимаются в латент низкого ранга и распаковываются при вычислении внимания. |
| Индукционная голова (induction head) | «Цепь, лежащая в основе обучения в контексте» | Пара голов, обнаруживающих предыдущие вхождения и копирующих то, что за ними следовало. |
