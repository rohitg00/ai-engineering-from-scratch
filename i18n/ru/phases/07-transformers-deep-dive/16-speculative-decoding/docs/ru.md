# Спекулятивное декодирование — черновик, проверка, повтор

> Авторегрессионное декодирование последовательно. Каждый токен ждёт предыдущий. Спекулятивное декодирование разрывает эту цепочку: дешёвая модель предлагает черновик из N токенов, а дорогая модель за один прямой проход проверяет все N. Если черновик оказался верным, вы заплатили за один большой прямой проход ради N сгенерированных токенов.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 07 (каузальная языковая модель GPT), этап 7 · 12 (KV-кеш и Flash Attention)
**Время:** ~60 минут

## Проблема

Сэмплирование одного токена с помощью большой языковой модели (LLM) на 70B параметров занимает ~30 мс на H100. Черновая модель на 3B занимает ~3 мс. Если позволить 3B-модели сгенерировать черновик из 5 токенов вперёд, а затем один раз запустить 70B-модель, чтобы проверить все 5, итог — `5×3 + 30 = 45 ms` на до 5 принятых токенов, против `5×30 = 150 ms` при линейной генерации. В этом вся суть спекулятивного декодирования: обменять немного дополнительной памяти GPU (черновая модель) на снижение задержки декодирования в 2–4 раза.

Приём должен сохранять распределение. Спекулятивное сэмплирование, предложенное Leviathan et al. (2023) и одновременно Chen et al., гарантирует, что итоговая последовательность **распределена идентично** тому, что произвела бы большая модель самостоятельно. Никакого компромисса в качестве. Просто быстрее.

В сфере выполнения вывода (инференс) в 2026 году доминируют четыре семейства пар «черновик — верификатор»:

1. **Ванильный спекулятивный подход (Leviathan 2023).** Отдельная черновая модель (например, Llama 3 1B) + верификатор (например, Llama 3 70B).
2. **Medusa (Cai 2024).** Несколько голов декодирования на верификаторе параллельно предсказывают позиции `t+1..t+k`. Отдельная черновая модель не нужна.
3. **Семейство EAGLE (Li 2024, 2025).** Лёгкий черновик, переиспользующий скрытые состояния верификатора; доля принятия выше, чем у ванильного варианта; типично 3–4×.
4. **Опережающее декодирование (Fu 2024).** Итерация Якоби; черновая модель вообще не нужна. Самоспекуляция. Нишевый подход, но не требует зависимостей.

Каждый продакшен-стек инференса в 2026 году поставляется со спекулятивным декодированием по умолчанию. vLLM, TensorRT-LLM, SGLang и llama.cpp — все поддерживают как минимум ванильный вариант + EAGLE-2.

## Концепция

### Базовый алгоритм

Пусть есть верификатор `M_q` и более дешёвый черновик `M_p`:

1. Пусть `x_1..x_k` — уже декодированный префикс.
2. **Черновик**: используйте `M_p`, чтобы авторегрессионно предложить `d_{k+1}, d_{k+2}, ..., d_{k+N}` с черновыми вероятностями `p_1..p_N`.
3. **Параллельная верификация**: запустите `M_q` один раз на `x_1..x_k, d_{k+1}, ..., d_{k+N}`, получив вероятности верификатора `q_1..q_{N+1}` для позиций `k+1..k+N+1`.
4. **Принимайте/отклоняйте каждый черновой токен слева направо**: для каждого `i` принимайте с вероятностью `min(1, q_i(d_i) / p_i(d_i))`.
5. При первом отклонении в позиции `j`: сэмплируйте `t_j` из нормализованного «остаточного» распределения `(q_j - p_j)_+`. Все черновые токены после `j` отбрасываются.
6. Если приняты все `N`: сэмплируйте один дополнительный токен `t_{N+1}` из `q_{N+1}` (бесплатный бонусный токен).

Приём с остаточным распределением — это математическая идея, благодаря которой итоговое распределение в точности совпадает с тем, как если бы `M_q` сэмплировала с нуля.

### Что определяет ускорение

Пусть `α` — ожидаемая доля принятия на черновой токен. Пусть `c` — отношение стоимости черновика к стоимости верификатора. На каждом шаге:

- Наивная генерация делает 1 вызов большой модели на токен.
- Спекулятивный подход делает 1 вызов большой модели на `(1 - α^{N+1}) / (1 - α) ≈ 1/(1-α)` токенов при высоком `α`.

Типичное эмпирическое правило при `α = 0.75` и `N = 5`: в 3 раза меньше вызовов большой модели. При этом выполняются 5 дешёвых вызовов черновой модели. Общее время выполнения падает примерно в 2.5 раза.

**От чего зависит α:**

- Насколько хорошо черновик аппроксимирует верификатор. Та же семья моделей / те же обучающие данные значительно повышают α.
- Стратегия декодирования. Жадный черновик против жадного верификатора: высокий α. Сэмплирование с температурой: сложнее совпасть; доля принятия падает.
- Тип задачи. Код и структурированный вывод принимаются чаще (предсказуемы); свободное творческое письмо — реже.

### Medusa — черновики без черновой модели

Medusa заменяет черновую модель дополнительными выходными головами на верификаторе. В позиции `t`:

```
shared trunk → hidden h_t
    ├── head_0: predict token at t+1  (standard LM head)
    ├── head_1: predict token at t+2
    ├── head_2: predict token at t+3
    ├── head_3: predict token at t+4
```

Каждая голова выдаёт собственные логиты. При инференсе вы сэмплируете из каждой головы, чтобы получить кандидатную последовательность, а затем верифицируете её за один прямой проход с помощью схемы древовидного внимания (tree attention), которая рассматривает все варианты продолжения одновременно.

Плюсы: нет второй модели. Минусы: добавляет обучаемые параметры; требует этапа дообучения с учителем (~1B токенов); доля принятия немного ниже, чем у ванильного спекулятивного подхода с хорошим черновиком.

### EAGLE — черновик лучше за счёт переиспользования скрытых состояний

EAGLE-1/2/3 (Li et al., 2024–2025) превращает черновую модель в крошечный трансформер (обычно 1 слой), который принимает на вход скрытые состояния последнего слоя верификатора. Поскольку черновик видит признаковое представление верификатора, его предсказания сильно коррелируют с выходным распределением верификатора. Доля принятия вырастает с ~0.6 (ванильный вариант) до 0.85+.

EAGLE-3 (2025) добавила древовидный поиск по вариантам продолжения. vLLM и SGLang используют EAGLE-2/3 как путь спекуляции по умолчанию для Llama 3/4 и Qwen 3.

### Танец с KV-кешем

Верификация подаёт `N` черновых токенов в верификатор за один прямой проход. Это расширяет KV-кеш верификатора на `N` записей. Если часть черновиков отклонена, кеш нужно откатить до длины принятого префикса.

Продакшен-реализации (`--speculative-model` в vLLM, LookaheadDecoder в TensorRT-LLM) решают это с помощью временных KV-буферов. Сначала запись, коммит — при принятии. Концептуально это не сложно, но возни много.

## Постройте это

См. `code/main.py`. Мы реализуем базовый алгоритм спекулятивного сэмплирования (шаг отклонения + остаточное распределение), включающий:

- «Большую модель» — детерминированную функцию softmax над вручную заданным распределением (чтобы можно было аналитически проверить математику принятия).
- «Черновую модель» — возмущение большой модели.
- Цикл принятия/отклонения, который даёт то же маргинальное распределение, что и прямое сэмплирование.

### Шаг 1: шаг отклонения

```python
def accept_or_reject(q_prob, p_prob, draft_token, u):
    ratio = q_prob / p_prob if p_prob > 0 else float("inf")
    return u < min(1.0, ratio)
```

`u` — равномерное случайное число. `q_prob` — вероятность верификатора для чернового токена. `p_prob` — вероятность черновой модели. Теорема Leviathan гласит, что это решение по Бернулли в сочетании с сэмплированием из остаточного распределения при отклонении в точности сохраняет распределение верификатора.

### Шаг 2: остаточное распределение

```python
def residual_dist(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    return [r / s for r in raw]
```

Вычтите `p` из `q` поэлементно, обнулите отрицательные значения, перенормируйте. При любом отклонении сэмплируйте из этого распределения.

### Шаг 3: один спекулятивный шаг

```python
def spec_step(prefix, q_model, p_model, N, rng):
    drafts = []
    p_probs = []
    ctx = list(prefix)
    for _ in range(N):
        p_dist = p_model(ctx)
        d = sample(p_dist, rng)
        drafts.append(d)
        p_probs.append(p_dist[d])
        ctx.append(d)

    q_dists = [q_model(prefix + drafts[:i]) for i in range(N + 1)]

    for i, d in enumerate(drafts):
        u = rng.random()
        q_prob = q_dists[i][d]
        p_prob = p_probs[i]
        if u < min(1.0, q_prob / p_prob if p_prob > 0 else float("inf")):
            prefix = prefix + [d]
        else:
            res = residual_dist(q_dists[i], p_model(prefix))
            prefix = prefix + [sample(res, rng)]
            return prefix
    prefix = prefix + [sample(q_dists[N], rng)]
    return prefix
```

Пять принято → один бонус → шесть токенов получено за один проход верификатора.

### Шаг 4: измерение доли принятия

Запустите 10 000 спекулятивных шагов при разных уровнях качества черновика. Постройте график зависимости доли принятия от KL-дивергенции между распределениями черновика и верификатора. Вы должны увидеть чёткую монотонную зависимость.

### Шаг 5: проверка эквивалентности распределений

Эмпирически: гистограмма токенов, полученных спекулятивным циклом, должна совпадать с гистограммой, полученной прямым сэмплированием из верификатора. Это теорема Leviathan на практике. Критерий хи-квадрат подтверждает совпадение в пределах ошибки выборки.

## Применение

Продакшен:

```bash
# vLLM with EAGLE
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-model /models/llama-3.1-eagle-70b \
    --speculative-draft-tensor-parallel-size 1 \
    --num-speculative-tokens 5

# vLLM with vanilla draft model
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-model meta-llama/Llama-3.2-1B-Instruct \
    --num-speculative-tokens 5
```

У TensorRT-LLM самый быстрый путь Medusa по состоянию на середину 2026 года. `faster-whisper` оборачивает спекулятивное декодирование для Whisper-large небольшим черновиком.

**Выбор черновика:**

| Стратегия | Когда выбирать | Ускорение |
|----------|--------------|---------|
| Ванильный черновик (семейство Llama 1B/3B) | Быстрый прототип, без обучения | 1.8–2.3× |
| Головы Medusa | Можно дообучить верификатор | 2–3× |
| EAGLE-2 / 3 | Продакшен, максимальная скорость | 3–4× |
| Опережающее декодирование | Без черновика, без обучения, без лишних параметров | 1.3–1.6× |

**Когда НЕ стоит использовать спекулятивное декодирование:**

- Генерация одной последовательности из 1–5 токенов. Накладные расходы доминируют.
- Крайне творческое сэмплирование / сэмплирование с высокой температурой (α падает).
- Развёртывания с ограниченной памятью (черновая модель добавляет расход VRAM).

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Черновая модель | «Дешёвая модель» | Модель меньшего размера, предлагающая кандидатные токены; обычно в 10–50 раз дешевле верификатора. |
| Верификатор | «Большая модель» | Целевая модель, чьё распределение мы сохраняем; запускается один раз за спекулятивный шаг. |
| Доля принятия (α) | «Как часто черновик угадывает» | Вероятность на токен того, что верификатор примет черновой токен. Типично 0.7–0.9. |
| Остаточное распределение | «Резервный вариант при отклонении» | Нормализованное `(q - p)_+`; сэмплирование из него при отклонении сохраняет распределение верификатора. |
| Бонусный токен | «Бесплатный токен» | Когда приняты все N черновых токенов, из распределения верификатора для следующего шага сэмплируется ещё один. |
| Medusa | «Спекуляция без черновика» | Несколько LM-голов на верификаторе параллельно предсказывают позиции t+1..t+k. |
| EAGLE | «Черновик на скрытых состояниях» | Крошечный трансформер-черновик, обусловленный скрытыми состояниями последнего слоя верификатора. |
| Опережающее декодирование | «Итерация Якоби» | Самоспекуляция с помощью итерации неподвижной точки; без черновой модели. |
| Древовидное внимание | «Верификация многих кандидатов сразу» | Ветвящаяся верификация, одновременно рассматривающая несколько вариантов продолжения черновика. |
| Откат KV-кеша | «Отмена отклонённых черновиков» | Временный KV-буфер; коммит при принятии, сброс при отклонении. |
