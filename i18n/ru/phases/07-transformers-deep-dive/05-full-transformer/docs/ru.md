# Полный трансформер — энкодер + декодер

> Внимание — звезда. Всё остальное — остаточные связи, нормализация, сеть прямого распространения и перекрёстное внимание — это строительные леса, позволяющие собирать глубокие стеки.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 02 (механизм самовнимания), этап 7 · 03 (многоголовое внимание), этап 7 · 04 (позиционное кодирование)
**Время:** ~75 минут

## Проблема

Один слой внимания — это экстрактор признаков, а не модель. Одного матричного умножения на слой недостаточно для языка. Нужна глубина — а глубина ломается без правильной обвязки.

Статья Vaswani 2017 года упаковала шесть архитектурных решений, превративших один слой внимания в блок, который можно складывать в стек. Каждый трансформер с тех пор — только энкодер (BERT), только декодер (GPT), энкодер-декодер (T5) — наследует один и тот же скелет. К 2026 году блоки были доработаны (RMSNorm, SwiGLU, предварительная нормализация, RoPE), но скелет остался тем же.

Этот урок — скелет. Следующие уроки его специализируют — 06 для энкодеров, 07 для декодеров, 08 для энкодер-декодерных моделей.

## Концепция

![Внутреннее устройство соединённых блоков энкодера и декодера](../assets/full-transformer.svg)

### Шесть компонентов

1. **Эмбеддинг + позиционный сигнал.** Токены → векторы. Позиция внедряется через RoPE (современный подход) или синусоидальное кодирование (классический).
2. **Самовнимание (self-attention).** Каждая позиция обращает внимание на все остальные. В декодерах маскируется.
3. **Сеть прямого распространения (FFN).** Применяемый к каждой позиции двухслойный MLP: `W_2 · activation(W_1 · x)`. Коэффициент расширения по умолчанию — 4×.
4. **Остаточная связь.** `x + sublayer(x)`. Без неё градиенты затухают уже после ~6 слоёв.
5. **Нормализация слоя.** `LayerNorm` или `RMSNorm` (современный подход). Стабилизирует остаточный поток.
6. **Перекрёстное внимание (cross-attention, только в декодере).** Запросы приходят из декодера, ключи и значения — из выхода энкодера.

Проследите, как вектор проходит через один блок: внимание перемешивает информацию между позициями, остаточная связь переносит её дальше, FFN трансформирует её, а нормализация удерживает поток стабильным.

### Блок энкодера (используется в BERT, энкодере T5)

```
x → LN → MHA(self) → + → LN → FFN → + → out
                     ^              ^
                     |              |
                     └── residual ──┘
```

Энкодер двунаправленный. Маскирования нет. Все позиции видят все позиции.

### Блок декодера (используется в GPT, декодере T5)

```
x → LN → MHA(masked self) → + → LN → MHA(cross to encoder) → + → LN → FFN → + → out
```

В декодере три подслоя на блок. Средний — перекрёстное внимание — единственное место, где информация течёт от энкодера к декодеру. В чисто декодерной архитектуре (GPT) перекрёстное внимание отсутствует, и остаются только маскированное самовнимание и FFN.

### Предварительная нормализация против последующей

Оригинальная статья: `x + sublayer(LN(x))` против `LN(x + sublayer(x))`. Последующая нормализация (post-norm) потеряла популярность около 2019 года — с ней сложнее обучать глубокие модели без тщательно настроенного прогрева. Предварительная нормализация (pre-norm, `LN` *перед* подслоем) — стандарт 2026 года: Llama, Qwen, GPT-3+, Mistral используют именно её.

### Модернизированный блок 2026 года

Vaswani 2017 поставляла LayerNorm + ReLU. Современные стеки заменили и то, и другое. Как на самом деле выглядят продакшн-блоки:

| Компонент | 2017 | 2026 |
|-----------|------|------|
| Нормализация | LayerNorm | RMSNorm |
| Функция активации FFN | ReLU | SwiGLU |
| Расширение FFN | 4× | 2.6× (SwiGLU использует три матрицы, общее число параметров совпадает) |
| Позиция | Абсолютное синусоидальное кодирование | RoPE |
| Внимание | Полное MHA | GQA (или MLA) |
| Смещения | Да | Нет |

RMSNorm отбрасывает центрирование по среднему из LayerNorm (одним вычитанием меньше), что экономит вычисления и эмпирически как минимум так же стабильно. SwiGLU (`Swish(W1 x) ⊙ W3 x`) стабильно превосходит FFN на ReLU/GELU примерно на 0.5 пункта перплексии в статьях Llama, PaLM и Qwen.

### Количество параметров

Для одного блока с `d_model = d` и расширением FFN `r`:

- MHA: `4 · d²` (проекции Q, K, V, O)
- FFN (SwiGLU): `3 · d · (r · d)` ≈ `3rd²`
- Норма: пренебрежимо мало

При `d = 4096, r = 2.6, layers = 32` (примерно как в Llama 3 8B), итого: `32 · (4·4096² + 3·2.6·4096²) ≈ 32 · (16 + 32) M = ~1.5B parameters per layer × 32 ≈ 7B` (плюс эмбеддинги и голова). Совпадает с опубликованными значениями.

## Построение

### Шаг 1: строительные блоки

Используя крохотный класс `Matrix` из урока 03 (скопированный в этот файл для независимости):

- `layer_norm(x, eps=1e-5)` — вычесть среднее, разделить на стандартное отклонение.
- `rms_norm(x, eps=1e-6)` — разделить на RMS. Без вычитания среднего.
- `gelu(x)` и `silu(x) * W3 x` (SwiGLU).
- `ffn_swiglu(x, W1, W2, W3)`.
- `encoder_block(x, params)` и `decoder_block(x, enc_out, params)`.

См. `code/main.py` для полной реализации.

### Шаг 2: собираем 2-слойный энкодер и 2-слойный декодер

Соберите их в стек. Передайте выход энкодера в каждый слой перекрёстного внимания декодера. Добавьте финальный LN перед выходной проекцией.

```python
def encode(tokens, params):
    x = embed(tokens, params.emb) + sinusoidal(len(tokens), params.d)
    for block in params.encoder_blocks:
        x = encoder_block(x, block)
    return x

def decode(target_tokens, encoder_out, params):
    x = embed(target_tokens, params.emb) + sinusoidal(len(target_tokens), params.d)
    for block in params.decoder_blocks:
        x = decoder_block(x, encoder_out, block)
    return x
```

### Шаг 3: прямой проход на игрушечном примере

Пропустите через модель источник из 6 токенов и цель из 5 токенов. Убедитесь, что форма выхода `(5, vocab)`. Без обучения — этот урок про архитектуру, а не про функцию потерь.

### Шаг 4: замена на RMSNorm + SwiGLU

Замените LayerNorm и FFN на ReLU на RMSNorm и SwiGLU. Убедитесь, что формы по-прежнему совпадают. Это модернизация 2026 года одной заменой функции.

## Применение

Эталонные реализации в PyTorch/TF: `nn.TransformerEncoderLayer`, `nn.TransformerDecoderLayer`. Но большая часть продакшн-кода в 2026 году пишет свой собственный блок, потому что:

- Flash Attention вызывается внутри внимания, а не через `nn.MultiheadAttention`.
- GQA / MLA отсутствуют в эталонной реализации стандартной библиотеки.
- RoPE, RMSNorm, SwiGLU не являются вариантами по умолчанию в PyTorch.

В HF `transformers` есть чистые эталонные блоки, которые стоит прочитать: `modeling_llama.py` — канонический блок чисто декодерной архитектуры 2026 года. Это около 500 строк, и стоит пройтись по нему хотя бы раз.

**Энкодер против декодера против энкодер-декодера — что выбрать:**

| Задача | Выбор | Пример |
|------|------|---------|
| Классификация, эмбеддинги, ответы на вопросы по тексту | Только энкодер | BERT, DeBERTa, ModernBERT |
| Генерация текста, чат, код, рассуждения | Только декодер | GPT, Llama, Claude, Qwen |
| Структурированный ввод → структурированный вывод (перевод, суммаризация) | Энкодер-декодер | T5, BART, Whisper |

Чисто декодерные модели стали доминировать в языковых задачах, поскольку проще всего масштабируются и поддерживают как понимание, так и генерацию. Энкодер-декодер по-прежнему лучше подходит, когда вход явно представляет собой отдельную «исходную последовательность» (перевод, распознавание речи, структурированные задачи).

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Блок (block) | «Один слой трансформера» | Стек из нормализации + внимания + нормализации + FFN, обёрнутый в остаточные связи. |
| Остаточная связь (residual) | «Обходное соединение» | Выход `x + f(x)`; обеспечивает прохождение градиента через глубокие стеки. |
| Предварительная нормализация (pre-norm) | «Нормализовать до, а не после» | Современный подход: `x + sublayer(LN(x))`. Позволяет обучать глубже без гимнастики с прогревом. |
| RMSNorm | «LayerNorm без среднего» | Деление на RMS; на одну операцию меньше, та же эмпирическая стабильность. |
| SwiGLU | «FFN, на который все перешли» | `Swish(W1 x) ⊙ W3 x → W2`. Превосходит ReLU/GELU по перплексии языковой модели. |
| Перекрёстное внимание (cross-attention) | «Как декодер видит энкодер» | MHA с Q из декодера, K/V из выходов энкодера. |
| Расширение FFN (FFN expansion) | «Насколько широк средний MLP» | Отношение размера скрытого слоя к d_model, обычно 4 (LayerNorm) или 2.6 (SwiGLU). |
| Без смещений (bias-free) | «Отбросить члены +b» | Современные стеки опускают смещения в линейных слоях; небольшое улучшение перплексии, меньшая модель. |
