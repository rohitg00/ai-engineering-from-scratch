# KV-кеш, Flash Attention и оптимизация инференса

> Обучение параллельно и упирается в FLOPs. Выполнение вывода (инференс) последовательно и упирается в память. Разное узкое место — разные приёмы.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 02 (Самовнимание), Этап 7 · 05 (Полный трансформер), Этап 7 · 07 (GPT)
**Время:** ~75 минут

## Проблема

Наивный авторегрессионный декодировщик выполняет `O(N²)` работы для генерации `N` токенов: на каждом шаге он пересчитывает внимание по всему префиксу. Для ответа в 4K токенов это 16 млн операций внимания, большинство из которых избыточны. Каждое скрытое состояние токена префикса детерминировано, как только оно вычислено, — нужно лишь прогнать запрос нового токена против кешированных ключей и значений всего, что было раньше.

Вдобавок само внимание перемещает много данных. Стандартное внимание материализует матрицу оценок N×N, выход функции softmax N×d, финальный выход N×d — слишком много чтений и записей в HBM. При N≥2K внимание упирается в память раньше, чем в FLOPs. Классические ядра внимания недоиспользуют современные GPU в 4–10 раз.

Две оптимизации, обе от Dao и др., подтолкнули топовый инференс от «медленно» к «быстро»:

1. **KV-кеш.** Хранить векторы K и V каждого токена префикса. Внимание для каждого нового токена — это один запрос к кешированным ключам. Инференс снижается с `O(N²)` до `O(N)` на шаг генерации.
2. **Flash Attention.** Разбить вычисление внимания на блоки (тайлинг), чтобы полная матрица N×N никогда не попадала в HBM. Весь softmax и матричное умножение выполняются в SRAM. Ускорение по времени в 2–4× на A100; в 5–10× на H100 с FP8.

К 2026 году оба приёма стали повсеместными. Каждый продакшен-стек для инференса (vLLM, TensorRT-LLM, SGLang, llama.cpp) считает их само собой разумеющимися. Каждая топовая модель поставляется с включённым Flash Attention.

### Математика KV-кеша

На слой декодировщика, на токен, на голову:

```
bytes_per_token_per_layer = 2 * d_head * dtype_size
                          ^
                          K and V
```

Для модели 7B с 32 слоями, 32 головами, d_head=128, fp16:

```
per token per layer = 2 * 128 * 2 = 512 bytes
per token (32 layers) = 16 KB
per 32K context = 512 MB
```

Для Llama 3 70B (80 слоёв, d_head=128, GQA с 8 KV-головами):

```
per token per layer = 2 * 8 * 128 * 2 = 4096 bytes (4 KB)
per 32K context = 10.4 GB
```

Именно из-за этих 10 ГБ Llama 3 70B при контексте 128K требует почти всю 40-гигабайтную A100 только под KV-кеш при размере пакета 1.

**GQA — это выигрыш для KV-кеша.** MHA с 64 головами потребовала бы 32 ГБ. MLA сжимает ещё сильнее.

### Flash Attention — приём с тайлингом

Стандартное внимание:

```
S = Q @ K^T          (HBM read, N×N, HBM write)
P = softmax(S)       (HBM read, HBM write)
O = P @ V            (HBM read, HBM write)
```

Три обращения туда-обратно к HBM. На H100 пропускная способность HBM — 3 ТБ/с, SRAM — 30 ТБ/с. Каждое обращение к HBM — это замедление на порядок по сравнению с тем, чтобы держать всё на кристалле.

Flash Attention:

```
for each block of Q (tile size ~128 × 128):
    load Q_tile into SRAM
    for each block of K, V:
        load K_tile, V_tile into SRAM
        compute S_tile = Q_tile @ K_tile^T     (SRAM)
        running softmax aggregation             (SRAM)
        accumulate into O_tile                  (SRAM)
    write O_tile to HBM
```

Одно обращение к HBM на тайл. Общий объём занимаемой памяти падает с `O(N²)` до `O(N)`. Обратный проход пересчитывает часть значений прямого прохода вместо того, чтобы их хранить, — ещё один выигрыш по памяти.

**Численный приём.** Потоковый алгоритм softmax поддерживает пару `(max, sum)` по тайлам, так что финальная нормализация точна. Это не приближение — Flash Attention вычисляет результат, побитно идентичный стандартному вниманию (с поправкой на неассоциативность fp16).

**Эволюция версий:**

| Версия | Год | Ключевое изменение | Ускорение на эталонном оборудовании |
|---------|------|-----------|-------------------------------|
| Flash 1 | 2022 | Тайлинговое ядро на SRAM | 2× на A100 |
| Flash 2 | 2023 | Более эффективный параллелизм, приоритетная обработка каузальных блоков | 3× на A100 |
| Flash 3 | 2024 | Асинхронность Hopper, FP8 | 1.5–2× на H100 (~740 TFLOPs FP16) |
| Flash 4 | 2026 | 5-стадийный конвейер Blackwell, программный exp2 | В первую очередь для инференса (изначально только прямой проход) |

На старте Flash 4 поддерживает только прямой проход. Обучение по-прежнему использует Flash 3. Поддержка GQA и последовательностей переменной длины в Flash 4 ожидается позже (середина 2026 года).

### Спекулятивное декодирование — ещё один способ снизить задержку

Дешёвая модель предлагает N токенов. Большая модель параллельно проверяет все N. Если проверка принимает k токенов, вы платите за один прямой проход большой модели ради k генераций. Типичное k=3–5 на коде и прозе.

Стандартные подходы 2026 года:
- **EAGLE 2 / Medusa.** Встроенные черновые головы, использующие общие с верификатором скрытые состояния. Ускорение в 2–3× без потери качества.
- **Спекулятивное декодирование с черновой моделью.** Ускорение в 2–4× на потребительском оборудовании.
- **Опережающее декодирование.** Итерации Якоби; черновая модель не нужна. Нишевый, но «бесплатный» приём.

### Непрерывная пакетная обработка

Классический пакетный инференс: дождаться завершения самой медленной последовательности и только потом начать новый пакет. Это впустую тратит GPU, когда короткие ответы завершаются раньше.

Непрерывная пакетная обработка (впервые появилась в Orca, теперь есть в vLLM, TensorRT-LLM, SGLang): новые запросы добавляются в пакет сразу же, как только завершаются старые. Прирост пропускной способности в 5–10× для типичных чат-нагрузок.

### PagedAttention — KV-кеш как виртуальная память

Главная возможность vLLM. KV-кеш выделяется блоками по 16 токенов; таблица страниц отображает логические позиции на физические блоки. Это позволяет разделять KV между параллельными сэмплами (лучевой поиск, параллельное сэмплирование), «горячо» подменять префиксы для кеширования промптов и дефрагментировать память. Прирост пропускной способности в 4× по сравнению с наивным смежным выделением памяти.

## Постройте это

См. `code/main.py`. Мы реализуем:

1. Наивный инкрементный декодировщик `O(N²)`.
2. Декодировщик `O(N)` с KV-кешем.
3. Тайлинговый softmax, имитирующий алгоритм текущего максимума из Flash Attention.

### Шаг 1: KV-кеш

```python
class KVCache:
    def __init__(self, n_layers, n_heads, d_head):
        self.K = [[[] for _ in range(n_heads)] for _ in range(n_layers)]
        self.V = [[[] for _ in range(n_heads)] for _ in range(n_layers)]

    def append(self, layer, head, k, v):
        self.K[layer][head].append(k)
        self.V[layer][head].append(v)

    def read(self, layer, head):
        return self.K[layer][head], self.V[layer][head]
```

Просто: храним растущие по мере поступления токенов векторы K, V в списках по слоям и головам.

### Шаг 2: тайлинговый softmax

```python
def tiled_softmax_dot(q, K, V, tile=4):
    """Flash-attention-style softmax(qK^T)V with running max/sum."""
    m = float("-inf")
    s = 0.0
    out = [0.0] * len(V[0])
    for start in range(0, len(K), tile):
        k_block = K[start:start + tile]
        v_block = V[start:start + tile]
        scores = [sum(qi * ki for qi, ki in zip(q, k)) for k in k_block]
        new_m = max(m, *scores)
        exp_old = math.exp(m - new_m) if m != float("-inf") else 0.0
        exp_new = [math.exp(sc - new_m) for sc in scores]
        s = s * exp_old + sum(exp_new)
        for j in range(len(out)):
            out[j] = out[j] * exp_old + sum(e * v[j] for e, v in zip(exp_new, v_block))
        m = new_m
    return [o / s for o in out]
```

Результат побитно идентичен `softmax(qK) V`, вычисленному за один проход, но в любой момент времени рабочий набор — это блок `tile × d_head`, а не полный `N × d_head`.

### Шаг 3: сравнение наивного и кешированного декодирования при генерации 100 токенов

Подсчитайте операции внимания. Наивный: `O(N²)` = 5050. С кешем: `O(N)` = 100. Код выводит оба значения.

## Применение

```python
# HuggingFace transformers auto-enables KV cache on decoder-only generate().
from transformers import AutoModelForCausalLM
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.2-3B",
    attn_implementation="flash_attention_2",  # use FA3 if Hopper
    torch_dtype="bfloat16",
)
# generate() uses KV cache automatically
```

vLLM в продакшене:

```bash
pip install vllm
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --tensor-parallel-size 4 \
    --max-model-len 32768 \
    --enable-prefix-caching \
    --kv-cache-dtype fp8
```

Кеширование префиксов между запросами — большой выигрыш 2026 года: один и тот же системный промпт, несколько примеров или длинный контекстный документ переиспользуют KV между вызовами. Для агентных нагрузок с повторяющимися промптами инструментов кеширование префиксов регулярно даёт прирост пропускной способности в 5×.

## Ключевые термины

| Термин | Что говорят | Что это значит на самом деле |
|------|-----------------|-----------------------|
| KV-кеш | «Приём, который ускоряет декодирование» | Сохранённые K и V каждого токена префикса; новые запросы обращаются к ним вместо пересчёта. |
| HBM | «Основная память GPU» | Память с высокой пропускной способностью; 80 ГБ на H100, 192 ГБ на B200. Пропускная способность ~3 ТБ/с. |
| SRAM | «Память на кристалле» | Быстрая память на каждый SM, ~256 КБ на SM на H100. Пропускная способность ~30 ТБ/с. |
| Flash Attention | «Тайлинговое ядро внимания» | Вычисляет внимание, не материализуя N×N в HBM. |
| Непрерывная пакетная обработка | «Пакетная обработка без ожидания» | Завершённые последовательности заменяются новыми, не дожидаясь завершения всего пакета. |
| PagedAttention | «Главная возможность vLLM» | KV-кеш выделяется фиксированными блоками с таблицей страниц; устраняет фрагментацию. |
| Кеширование префикса | «Переиспользование длинных промптов» | Кеширование KV для общего префикса между запросами; существенное снижение затрат для агентов. |
| Спекулятивное декодирование | «Черновик + проверка» | Дешёвая черновая модель предлагает токены; большая модель проверяет k за один проход. |
