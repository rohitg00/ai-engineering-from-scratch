# GPT — каузальное языковое моделирование

> BERT видит обе стороны. GPT видит только прошлое. Треугольная маска — одна строка кода с самыми далеко идущими последствиями для современного ИИ.

**Тип:** Build
**Языки:** Python
**Требования:** этап 7 · 02 (самовнимание), этап 7 · 05 (полный трансформер), этап 7 · 06 (BERT)
**Время:** ~75 минут

## Проблема

Языковая модель отвечает на один вопрос: даны первые `t-1` токенов, каково распределение вероятностей для токена `t`? Обучение на этом сигнале — предсказании следующего токена — даёт модель, способную генерировать произвольный текст токен за токеном.

Чтобы обучить её сквозным образом на всей последовательности параллельно, нужно, чтобы предсказание каждой позиции зависело только от более ранних позиций. Иначе модель тривиально жульничает, подглядывая в ответ.

Каузальная маска решает это. Это единая верхнетреугольная матрица значений `-inf`, добавляемая к оценкам внимания перед функцией softmax. После softmax эти позиции становятся 0. Каждая позиция может обращать внимание только на себя и более ранние позиции. И поскольку маска применяется один раз ко всей последовательности, вы получаете N параллельных предсказаний следующего токена за один прямой проход.

GPT-1 (2018), GPT-2 (2019), GPT-3 (2020), GPT-4 (2023), GPT-5 (2025), Claude, Llama, Qwen, Mistral, DeepSeek, Kimi — все они являются каузальными трансформерами только с декодером с одним и тем же базовым циклом. Их отличают качество данных, масштаб и архитектурные усовершенствования, а также постобучение (SFT, RLHF, DPO и их преемники).

## Концепция

![Каузальная маска создаёт треугольную матрицу внимания](../assets/causal-attention.svg)

### Маска

Дана последовательность длины `N`, построим матрицу `N × N`:

```
M[i, j] = 0       if j <= i
M[i, j] = -inf    if j > i
```

Добавьте `M` к исходным оценкам внимания перед softmax. `exp(-inf) = 0`, поэтому замаскированные позиции вносят нулевой вес. Каждая строка матрицы внимания — это распределение вероятностей только по предыдущим позициям.

Затраты на реализацию: один вызов `torch.tril()`. Время вычисления: наносекунды. Влияние на область: всё.

### Откуда берётся треугольник

Маску обычно представляют как заплатку, приделанную к механизму внимания. Но если провести вывод в обратном направлении, загадка исчезает: внимание — третий этап усовершенствования среднего по префиксу, а треугольник — это границы цикла при вычислении такого среднего, записанные в виде матрицы.

**Этап 1 — среднее по префиксу.** Простейшее каузальное представление последовательности: позиция `i` становится средним позиций `0…i`. В виде цикла это `out[i] = X[:i+1].mean(0)`. То же вычисление выполняется одним умножением матриц. Возьмите нижнетреугольную матрицу из единиц, разделите каждую строку на число единиц в ней и умножьте:

```python
import numpy as np

A = np.tril(np.ones((n, n)))
A = A / A.sum(axis=1, keepdims=True)
out = A @ X
```

Строка `i` матрицы `A` имеет вид `[1/(i+1), …, 1/(i+1), 0, …, 0]`. Нули над диагональю и обеспечивают каузальность. Будущие позиции не были замаскированы — их изначально не было в сумме.

**Этап 2 — обучаемые веса.** При равномерном усреднении все предыдущие токены считаются одинаково значимыми. Замените единицы обучаемой матрицей оценок `S`. Теперь сумма элементов строки не обязательно равна единице, поэтому вместо деления на их число нормализуйте каждую строку с помощью softmax. Softmax никогда не возвращает точный ноль, а значит, нарушает каузальность — если только оценки будущих позиций не подаются как `-inf`, поскольку `exp(-inf) = 0`:

```python
def softmax(x, axis):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

S = S + np.triu(np.full((n, n), -np.inf), k=1)
A = softmax(S, axis=1)
out = A @ X
```

Тот же треугольник, та же стохастическая по строкам матрица, то же одно умножение матриц. Маска `-inf` — не новый механизм. Это нулевые элементы из этапа 1, перенесённые во входную область softmax.

**Этап 3 — веса, зависящие от содержимого.** На этапе 2 матрица `S` после обучения неизменна: позиция 7 всегда придаёт позиции 3 один и тот же вес независимо от токенов. Сделаем оценки зависимыми от самих токенов: `S = Q @ K.T / sqrt(d_k)`. Всё остальное остаётся прежним. Маска, softmax, умножение матриц — без изменений.

Три этапа, один инвариант: нижнетреугольная стохастическая по строкам матрица, умноженная на последовательность. Равномерное среднее, обучаемые статические веса, веса, зависящие от содержимого. Маску не добавляли к вниманию. Она сохранилась от операции усреднения.

### Параллельное обучение, последовательное выполнение вывода (инференс)

Обучение: прямой проход по всей последовательности `(N, d_model)` один раз, вычисление N значений кросс-энтропийных потерь (по одной на позицию), суммирование, обратное распространение ошибки. Параллельно вдоль последовательности. Именно поэтому обучение GPT масштабируется — вы обрабатываете 1 млн токенов в пакете за один проход GPU.

Инференс: генерация токен за токеном. Подайте `[t1, t2, t3]`, получите `t4`. Подайте `[t1, t2, t3, t4]`, получите `t5`. Подайте `[t1, t2, t3, t4, t5]`, получите `t6`. KV-кеш (урок 12) сохраняет скрытые состояния `t1…tn`, чтобы не пересчитывать их на каждом шаге. Но последовательная глубина при инференсе равна длине вывода. Это авторегрессионный налог и причина, по которой декодирование — узкое место задержки любой большой языковой модели (LLM).

### Функция потерь — сдвиг на единицу

Даны токены `[t1, t2, t3, t4]`:

- Вход: `[t1, t2, t3]`
- Цели: `[t2, t3, t4]`

Для каждой позиции `i` вычислите `-log P(target_i | inputs[:i+1])`. Просуммируйте. Это кросс-энтропия для всей последовательности.

Каждая известная вам трансформерная LM обучается на этой функции потерь. Предварительное обучение, дообучение, SFT — та же функция потерь, другие данные.

### Стратегии декодирования

После обучения выбор сэмплирования имеет значение больше, чем кажется.

| Метод | Принцип работы | Когда применять |
|--------|--------------|-------------|
| Жадное декодирование | Выбирать argmax на каждом шаге | Детерминированные задачи, автодополнение кода |
| Температура | Разделить логиты на T и выполнить сэмплирование | Творческие задачи; чем выше T, тем больше разнообразие |
| Top-k | Сэмплировать только из top-k токенов | Убирает хвосты с низкой вероятностью |
| Top-p (ядерное сэмплирование) | Сэмплировать из наименьшего множества с суммарной вероятностью ≥ p | Стандарт с 2020 года; адаптируется к форме распределения |
| Min-p | Оставить токены с `p > min_p * max_p` | С 2024 года; лучше отсекает длинные хвосты, чем top-p |
| Спекулятивное декодирование | Модель-черновик предлагает N токенов, большая модель проверяет | Снижение задержки в 2–3× при том же качестве |

В 2026 году min-p с температурой 0.7 — разумная конфигурация по умолчанию для моделей с открытыми весами. Спекулятивное декодирование — обязательный элемент любого продакшн-стека инференса.

### Что заставило «рецепт GPT» работать

1. **Только декодер.** Никаких накладных расходов на энкодер. Один проход внимания + FFN на слой.
2. **Масштабирование.** 124M → 1.5B → 175B → триллионы. Законы масштабирования Chinchilla (урок 13) показывают, как тратить вычисления.
3. **Обучение в контексте (in-context learning).** Появилось в районе 6B–13B. Модель может следовать нескольким примерам (few-shot) без дообучения.
4. **RLHF.** Постобучение на человеческих предпочтениях превратило исходные модели, полученные в результате предварительного обучения, в чат-ассистентов.
5. **Предварительная нормализация (pre-norm) + RoPE + SwiGLU.** Стабильное обучение при масштабировании.

Базовая архитектура почти не изменилась со времён GPT-2. Всё интересное происходило в данных, масштабе и постобучении.

## Создаём

### Шаг 1: каузальная маска

См. `code/main.py`. Одна строка:

```python
def causal_mask(n):
    return [[0.0 if j <= i else float("-inf") for j in range(n)] for i in range(n)]
```

Добавьте её к оценкам внимания перед softmax. Это весь механизм.

### Шаг 2: 2-слойная модель в духе GPT

Составьте два блока декодера (маскированное самовнимание + FFN, без перекрёстного внимания). Добавьте векторное представление (эмбеддинг) токенов, позиционное кодирование и обратное преобразование эмбеддингов (unembedding), связанное с матрицей эмбеддингов токенов, — это стандартный приём со времён GPT-2.

### Шаг 3: предсказание следующего токена, сквозной проход

На игрушечном словаре из 20 токенов выдайте логиты на каждой позиции. Вычислите кросс-энтропийные потери относительно цели, сдвинутой на единицу. Без градиента — это проверка прямого прохода на здравый смысл.

### Шаг 4: сэмплирование

Реализуйте жадное декодирование, сэмплирование с температурой, top-k, top-p и min-p. Запустите каждый метод на фиксированном промпте и сравните результаты. Функция сэмплирования — 10 строк.

## Применяем

PyTorch, идиома 2026 года:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")

prompt = "Attention is all you need because"
inputs = tok(prompt, return_tensors="pt")
out = model.generate(
    **inputs,
    max_new_tokens=64,
    temperature=0.7,
    top_p=0.9,
    do_sample=True,
)
print(tok.decode(out[0]))
```

Под капотом `generate()` выполняет прямой проход, извлекает логиты последней позиции, сэмплирует следующий токен, добавляет его и повторяет. Каждый продакшн-стек инференса LLM (vLLM, TensorRT-LLM, llama.cpp, Ollama, MLX) реализует тот же цикл с интенсивной оптимизацией: пакетное предварительное заполнение (prefill), непрерывная пакетная обработка, страничная организация KV-кеша и спекулятивное декодирование.

**GPT против BERT, по одной строке на каждый:** GPT предсказывает `P(x_t | x_{<t})`. BERT предсказывает `P(x_masked | x_unmasked)`. Функция потерь определяет, способна ли модель генерировать.

## Ключевые термины

| Термин | Как его называют | Что он означает на самом деле |
|------|-----------------|-----------------------|
| Каузальная маска | «Треугольник» | Верхнетреугольная матрица `-inf`, добавляемая к оценкам внимания, так что позиция `i` видит только позиции `≤ i`. |
| Предсказание следующего токена | «Функция потерь» | Кросс-энтропия распределения модели относительно истинного следующего токена на каждой позиции. |
| Авторегрессионная генерация | «Генерировать по одному токену за раз» | Подавать выход обратно как вход; параллелизм возможен только при обучении, но не при генерации. |
| Логиты | «Оценки до softmax» | Необработанный выход головы LM перед softmax; сэмплирование выполняется на основе этих значений. |
| Температура | «Регулятор творчества» | Разделить логиты на T; T→0 соответствует жадному декодированию, T→∞ — равномерному распределению. |
| Top-p | «Ядерное сэмплирование» | Обрезать распределение до наименьшего множества с суммой ≥p; сэмплировать из оставшегося. |
| Min-p | «Лучше, чем top-p» | Оставить токены, где `p ≥ min_p × max_p`; порог адаптируется к остроте распределения. |
| Спекулятивное декодирование | «Черновик + проверка» | Дешёвая модель предлагает N токенов; большая модель проверяет их параллельно. |
| Принудительное обучение (teacher forcing) | «Приём обучения» | Во время обучения подаётся истинный предыдущий токен, а не предсказание модели. Стандарт для любой seq2seq LM. |
