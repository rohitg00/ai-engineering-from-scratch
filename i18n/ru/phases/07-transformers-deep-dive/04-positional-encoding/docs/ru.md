# Позиционное кодирование — синусоидальное, RoPE, ALiBi

> Внимание инвариантно к перестановкам. «Кот сидел на коврике» и «коврике на сидел кот» дают один и тот же результат без позиционного сигнала. Три алгоритма это исправляют — каждый по-своему трактует понятие «позиция».

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 02 (Самовнимание), этап 7 · 03 (Многоголовое внимание)
**Время:** ~45 минут

## Проблема

Масштабированное скалярное внимание не учитывает порядок. Матрица внимания `softmax(Q K^T / √d) V` вычисляется на основе попарного сходства. Перемешайте строки `X` — и строки результата перемешаются точно так же. Позиция внутри механизма внимания нигде не учитывается.

Это не баг для модели «мешка слов». Но для языка, кода, аудио, видео — всего, где порядок несёт смысл, — это фатально.

Решение — так или иначе внедрить позицию в векторные представления (эмбеддинги). Есть три поколения подходов:

1. **Абсолютное синусоидальное** (Vaswani 2017). Добавить `sin/cos` от позиции к эмбеддингу. Просто, без обучаемых параметров, плохо экстраполируется за пределы обученных длин.
2. **RoPE — Rotary Position Embeddings** (Su 2021). Повернуть векторы Q и K на угол, пропорциональный позиции. Кодирует *относительную* позицию прямо в скалярном произведении. Доминирует в 2026 году.
3. **ALiBi — Attention with Linear Biases** (Press 2022). Полностью отказаться от эмбеддингов; добавить к оценкам внимания линейный штраф для каждой головы на основе расстояния. Отличная экстраполяция длины.

По состоянию на 2026 год практически каждая передовая открытая модель использует RoPE: Llama 2/3/4, Qwen 2/3, Mistral, Mixtral, DeepSeek-V3, Kimi. Небольшое число моделей для длинного контекста используют ALiBi или его современные варианты. Абсолютное синусоидальное кодирование стало историей.

## Концепция

![Абсолютное синусоидальное кодирование, вращения RoPE и смещение ALiBi на основе расстояния](../assets/positional-encoding.svg)

### Абсолютное синусоидальное

Заранее вычислите фиксированную матрицу `PE` формы `(max_len, d_model)`:

```
PE[pos, 2i]   = sin(pos / 10000^(2i / d_model))
PE[pos, 2i+1] = cos(pos / 10000^(2i / d_model))
```

Затем `X' = X + PE[:N]` перед вниманием. Каждая размерность — это синусоида на своей частоте. Модель учится читать позицию по паттерну фазы. Не работает за пределами `max_len`: ничто не сообщило модели, что происходит на позиции 2048, если она видела только позиции 0–2047.

### RoPE

Поворачивайте векторы Q и K (не эмбеддинги). Для пары размерностей `(2i, 2i+1)`:

```
[q'_2i    ]   [ cos(pos·θ_i)  -sin(pos·θ_i) ] [q_2i   ]
[q'_2i+1  ] = [ sin(pos·θ_i)   cos(pos·θ_i) ] [q_2i+1 ]

θ_i = base^(-2i / d_head),  base = 10000 by default
```

Примените то же вращение к ключам с позицией `pos_k`. Скалярное произведение `q'_m · k'_n` становится функцией только `(m - n)`. То есть: **оценка внимания зависит только от относительного расстояния**, хотя вращение и задавалось абсолютными позициями. Красивый трюк.

Расширение RoPE: `base` можно масштабировать (NTK-aware, YaRN, LongRoPE), чтобы экстраполировать на более длинные контексты без повторного обучения. Именно так Llama 3 расширила контекст с 8K до 128K.

### ALiBi

Откажитесь от трюка с эмбеддингами. Смещайте оценки внимания напрямую:

```
attn_score[i, j] = (q_i · k_j) / √d  -  m_h · |i - j|
```

Где `m_h` — специфичный для головы наклон (например, `1 / 2^(8·h/H)`). Более близкие токены получают усиление; далёкие — штраф. Никаких затрат во время обучения. В статье показано, что экстраполяция длины превосходит синусоидальное кодирование и не уступает RoPE на исходной обученной длине.

### Что выбрать в 2026 году

| Вариант | Экстраполяция | Затраты на обучение | Где используется |
|---------|---------------|---------------|---------|
| Абсолютное синусоидальное | низкая | отсутствуют | исходный трансформер, ранние версии BERT |
| Обучаемое абсолютное | отсутствует | незначительные | GPT-2, GPT-3 |
| RoPE | высокая при масштабировании | отсутствуют | Llama 2/3/4, Qwen 2/3, Mistral, DeepSeek-V3, Kimi |
| RoPE + YaRN | отличная | этап дообучения | Qwen2-1M, Llama 3.1 128K |
| ALiBi | отличная | отсутствуют | BLOOM, MPT, Baichuan |

RoPE победил, потому что встраивается во внимание без изменения архитектуры, кодирует относительную позицию, а его гиперпараметр `base` даёт чистую ручку регулировки для дообучения на длинном контексте.

## Построение

### Шаг 1: синусоидальное кодирование

См. `code/main.py`. Вычисление в 4 строки:

```python
def sinusoidal(N, d):
    pe = [[0.0] * d for _ in range(N)]
    for pos in range(N):
        for i in range(d // 2):
            theta = pos / (10000 ** (2 * i / d))
            pe[pos][2 * i]     = math.sin(theta)
            pe[pos][2 * i + 1] = math.cos(theta)
    return pe
```

Добавьте это к матрице эмбеддингов перед первым слоем внимания.

### Шаг 2: RoPE применительно к Q, K

RoPE действует на месте на Q и K. Для каждой пары измерений:

```python
def apply_rope(x, pos, base=10000):
    d = len(x)
    out = list(x)
    for i in range(d // 2):
        theta = pos / (base ** (2 * i / d))
        c, s = math.cos(theta), math.sin(theta)
        a, b = x[2 * i], x[2 * i + 1]
        out[2 * i]     = a * c - b * s
        out[2 * i + 1] = a * s + b * c
    return out
```

Критически важно: примените одну и ту же функцию к Q на позиции `m` и к K на позиции `n`. Их скалярное произведение получит множитель `cos((m-n)·θ_i)` на каждой паре координат. Внимание бесплатно учится относительной позиции.

### Шаг 3: наклоны и смещение ALiBi

```python
def alibi_bias(n_heads, seq_len):
    # slope_h = 2 ** (-8 * h / n_heads) for h = 1..n_heads
    slopes = [2 ** (-8 * (h + 1) / n_heads) for h in range(n_heads)]
    bias = []
    for m in slopes:
        row = [[-m * abs(i - j) for j in range(seq_len)] for i in range(seq_len)]
        bias.append(row)
    return bias  # add to attention scores before softmax
```

Добавьте `bias[h]` к матрице оценок внимания `(seq_len, seq_len)` головы `h`, затем примените функцию softmax.

### Шаг 4: проверка свойства относительного расстояния у RoPE

Возьмите два случайных вектора `a, b`. Поверните их на `(pos_a, pos_b)`. Затем на `(pos_a + k, pos_b + k)`. Оба скалярных произведения должны совпасть с точностью до ошибки округления. Именно в этом свойстве весь смысл RoPE — оно инвариантно к абсолютному сдвигу, важен только относительный разрыв.

## Применение

PyTorch 2.5+ поставляется с утилитами RoPE в `torch.nn.functional`. Большая часть продакшн-кода использует `flash_attn` или `xformers`, где RoPE применяется внутри ядра внимания.

```python
from transformers import AutoModel
model = AutoModel.from_pretrained("meta-llama/Llama-3.2-3B")
# model.config.rope_scaling → {"type": "yarn", "factor": 32.0, "original_max_position_embeddings": 8192}
```

**Трюки для длинного контекста в 2026 году:**

- **NTK-aware интерполяция.** Пересчитать `base` в `base * (scale_factor)^(d/(d-2))` при расширении с 4K до 16K+.
- **YaRN.** Более умная интерполяция, сохраняющая энтропию внимания на длинных контекстах. Используется в Llama 3.1 128K.
- **LongRoPE.** Метод Microsoft 2024 года, использующий эволюционный поиск для подбора масштабных коэффициентов для каждой размерности. Используется в Phi-3-Long.
- **Позиционная интерполяция + дообучение.** Просто сжать позиции на коэффициент расширения и дообучить на 1–5 млрд токенов. На удивление эффективно.

## Упражнения

1. **Лёгкое.** Постройте тепловую карту синусоидальной матрицы `PE` для `max_len=512, d=128`. Подтвердите паттерн «полосы становятся шире по мере роста индекса измерения».
2. **Среднее.** Реализуйте масштабирование RoPE в стиле NTK-aware. Обучите крохотную LM на последовательностях длиной 256, затем протестируйте на длине 1024 с масштабированием и без него. Измерьте перплексию.
3. **Сложное.** Реализуйте ALiBi и RoPE в одном модуле внимания. Обучите 4-слойный трансформер на задаче копирования с последовательностями длиной 512. Экстраполируйте до 2048 во время теста. Сравните деградацию.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Позиционное кодирование | «Сообщает вниманию о порядке» | Любой сигнал, добавляемый к эмбеддингам или механизму внимания и кодирующий позицию. |
| Синусоидальное кодирование | «Первоначальный вариант» | `sin/cos` на геометрических частотах, добавленные к эмбеддингам; не поддерживает экстраполяцию. |
| RoPE | «Ротационные эмбеддинги» | Поворот Q, K на угол, зависящий от позиции; скалярное произведение кодирует относительное расстояние. |
| ALiBi | «Трюк с линейным смещением» | Добавление `-m·\|i-j\|` к оценкам внимания; эмбеддинги не нужны, отличная экстраполяция. |
| base | «Регулятор RoPE» | Масштабирующий коэффициент частоты в RoPE; его увеличение расширяет контекст на этапе выполнения вывода (инференс). |
| NTK-aware | «Трюк масштабирования RoPE» | Пересчёт `base`, чтобы высокочастотные измерения не сжимались при расширении контекста. |
| YaRN | «Продвинутый вариант» | Интерполяция+экстраполяция для каждого измерения, сохраняющая энтропию внимания. |
| Экстраполяция | «Работает за пределами обученной длины» | Может ли схема позиционирования давать корректный результат за пределами `max_len`, увиденного при обучении? |
