# Смесь экспертов (MoE)

> Плотный трансформер на 70 млрд параметров активирует каждый параметр для каждого токена. MoE на 671 млрд параметров активирует лишь 37 млрд на токен — и превосходит его на каждом бенчмарке. Разреженность — самая важная идея масштабирования этого десятилетия.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 7 · 05 (Полный трансформер), этап 7 · 07 (GPT)
**Время:** ~45 минут

## Проблема

Число FLOPs плотного трансформера при инференсе равно числу его параметров (умноженному на 2 для прямого прохода). Масштабируйте плотную модель — и каждый токен платит по полному счёту. К 2024 году передовые модели упёрлись в вычислительную стену: чтобы стать заметно умнее, требовалось экспоненциально больше FLOPs на токен.

Архитектура смеси экспертов (MoE) разрывает эту связь. Замените каждый FFN на `E` независимых экспертов и маршрутизатор, который выбирает `k` экспертов на токен. Общее число параметров = `E × FFN_size`. Активные параметры на токен = `k × FFN_size`. Типичная конфигурация 2026 года: `E=256`, `k=8`. Объём хранения масштабируется с `E`, вычисления — с `k`.

Передовые модели 2026 года почти все построены на MoE: DeepSeek-V3 (671 млрд всего / 37 млрд активных), Mixtral 8×22B, Qwen2.5-MoE, Llama 4, Kimi K2, gpt-oss. В независимом рейтинге Artificial Analysis все топ-10 моделей с открытым исходным кодом — это MoE.

## Концепция

![Слой MoE: маршрутизатор выбирает k из E экспертов для каждого токена](../assets/moe.svg)

### Замена FFN

Блок плотного трансформера:

```
h = x + attn(norm(x))
h = h + FFN(norm(h))
```

Блок MoE:

```
h = x + attn(norm(x))
scores = router(norm(h))              # (N_tokens, E)
top_k = argmax_k(scores)              # pick k of E per token
h = h + sum_{e in top_k}(
        gate(scores[e]) * Expert_e(norm(h))
    )
```

Каждый эксперт — независимый FFN (как правило, SwiGLU). Маршрутизатор — это один линейный слой. Каждый токен выбирает собственные `k` экспертов и получает смесь их выходов, взвешенную функцией гейтирования.

### Проблема балансировки нагрузки

Если маршрутизатор пропускает 90% токенов через эксперта 3, остальные эксперты голодают. Опробованы три способа исправить это:

1. **Вспомогательная функция потерь балансировки нагрузки** (Switch Transformer, Mixtral). Добавляет штраф, пропорциональный дисперсии использования экспертов. Работает, но добавляет гиперпараметр и второй сигнал градиента.
2. **Ёмкость эксперта и отбрасывание токенов** (ранний Switch). Каждый эксперт обрабатывает не более `C × N/E` токенов; токены сверх лимита пропускают слой. Ухудшает качество.
3. **Балансировка без вспомогательной функции потерь** (DeepSeek-V3). Добавляет обучаемое смещение для каждого эксперта, которое сдвигает top-k-выбор маршрутизатора. Смещение обновляется вне обучающей функции потерь. Никакого штрафа на основную цель обучения. Главный прорыв 2024 года.

Подход DeepSeek-V3: после каждого шага обучения для каждого эксперта проверяется, выше или ниже целевого значения его использование. Смещение сдвигается на `±γ`. Для выбора используется `scores + bias`. Вероятности экспертов, используемые для гейтирования, — это исходные `scores` без изменений. Это разделяет маршрутизацию и гейтирование.

### Общие эксперты

DeepSeek-V2/V3 также делит экспертов на *общих* и *маршрутизируемых*. Каждый токен проходит через всех общих экспертов. Маршрутизируемые эксперты выбираются через top-k. Общие эксперты фиксируют общие знания; маршрутизируемые — специализируются. V3 использует 1 общего эксперта плюс top-8 из 256 маршрутизируемых.

### Мелкозернистые эксперты

Классический MoE (GShard, Switch): каждый эксперт по ширине равен полному FFN. `E` небольшое (8–64), `k` небольшое (1–2).

Современный мелкозернистый MoE (DeepSeek-V3, Qwen-MoE): каждый эксперт уже (1/8 от размера FFN). `E` большое (256+), `k` больше (8+). То же общее число параметров, но число комбинаций растёт гораздо быстрее. `C(256, 8) = 400 trillion` возможных «экспертов» на токен. Качество растёт, задержка остаётся неизменной.

### Профиль стоимости

На токен, на слой:

| Конфигурация | Активных параметров на токен | Всего параметров |
|--------|-----------------------|--------------|
| Mixtral 8×22B | ~39 млрд | 141 млрд |
| Llama 3 70B (плотная) | 70 млрд | 70 млрд |
| DeepSeek-V3 | 37 млрд | 671 млрд |
| Kimi K2 (MoE) | ~32 млрд | 1 трлн |

DeepSeek-V3 превосходит Llama 3 70B (плотную) почти на каждом бенчмарке, выполняя при этом **меньше активных FLOPs на токен**. Больше параметров = больше знаний. Больше активных FLOPs = больше вычислений на токен. MoE разделяет эти две величины.

### Ловушка: память

Все эксперты находятся на GPU независимо от того, какие из них сработают. Модели на 671 млрд параметров требуется ~1,3 ТБ видеопамяти для весов в fp16. Развёртывание передового MoE требует экспертного параллелизма — разбиения экспертов по GPU и маршрутизации токенов по сети. Задержка определяется в первую очередь обменом «все со всеми», а не матричным умножением.

## Постройте это

См. `code/main.py`. Компактный слой MoE, реализованный только на стандартной библиотеке Python, со следующими элементами:

- `n_experts=8` экспертов, подобных SwiGLU (по одному линейному слою каждый, для наглядности)
- маршрутизация top-k=2
- веса гейтирования, нормализованные через softmax
- балансировка без вспомогательной функции потерь через смещение для каждого эксперта

### Шаг 1: маршрутизатор

```python
def route(hidden, W_router, top_k, bias):
    scores = [sum(h * w for h, w in zip(hidden, W_router[e])) for e in range(len(W_router))]
    biased = [s + b for s, b in zip(scores, bias)]
    top_idx = sorted(range(len(biased)), key=lambda i: -biased[i])[:top_k]
    # softmax over ORIGINAL scores of the chosen experts
    chosen = [scores[i] for i in top_idx]
    m = max(chosen)
    exps = [math.exp(c - m) for c in chosen]
    s = sum(exps)
    gates = [e / s for e in exps]
    return top_idx, gates
```

Смещение влияет на выбор, но не на вес гейтирования. В этом и состоит трюк DeepSeek-V3 — смещение устраняет дисбаланс нагрузки, не влияя на предсказания модели.

### Шаг 2: пропускаем 100 токенов через маршрутизатор

Отслеживаем, как часто срабатывает каждый эксперт. Без смещения использование перекошено. С циклом обновления смещения (`-γ` для перегруженных экспертов, `+γ` для недогруженных) использование сходится к равномерному распределению за несколько итераций.

### Шаг 3: сравнение числа параметров

Выводим «плотный эквивалент» конфигурации MoE. Конфигурация в духе DeepSeek-V3: 256 маршрутизируемых + 1 общий эксперт, 8 активных, d_model=7168. Общее число параметров впечатляет. Число активных параметров составляет седьмую часть от плотной Llama 3 70B.

## Применение

Загрузка через HuggingFace:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("mistralai/Mixtral-8x22B-v0.1")
```

Продакшн-инференс 2026 года: vLLM поддерживает маршрутизацию MoE нативно. SGLang предлагает самый быстрый путь экспертного параллелизма. Оба автоматически обрабатывают top-k-выбор и экспертный параллелизм.

**Когда выбирать MoE:**
- Вам нужно передовое качество при меньшей стоимости инференса на токен.
- У вас есть видеопамять / инфраструктура для экспертного параллелизма.
- Ваша нагрузка требует много токенов (чат, код), а не много контекста (длинные документы).

**Когда НЕ выбирать MoE:**
- Развёртывание на периферийных устройствах — вы платите за полный объём хранения ради любого активного FLOP.
- Обслуживание, критичное к задержке, для одного пользователя — маршрутизация экспертов добавляет накладные расходы.
- Маленькие модели (<7B) — преимущество MoE в качестве проявляется только выше определённого порога вычислений (~6 млрд активных параметров).

## Ключевые термины

| Термин | Как говорят | Что это значит на самом деле |
|------|-----------------|-----------------------|
| Эксперт | «Один FFN среди многих» | Независимая нейросеть прямого распространения; параметры, выделенные под разреженный срез вычислений FFN. |
| Маршрутизатор | «Гейт» | Крошечный линейный слой, оценивающий каждый токен относительно каждого эксперта; отбор top-k. |
| Маршрутизация top-k | «k активных экспертов на токен» | Вычисление FFN для каждого токена проходит ровно через k экспертов, взвешенных функцией гейтирования. |
| Вспомогательная функция потерь | «Штраф за балансировку нагрузки» | Дополнительный член функции потерь, штрафующий перекошенное использование экспертов. |
| Без вспомогательной функции потерь | «Трюк DeepSeek-V3» | Балансировка через смещение для каждого эксперта, влияющее только на выбор маршрутизатора; без дополнительного градиента. |
| Общий эксперт | «Всегда включён» | Дополнительный эксперт, через которого проходит каждый токен; фиксирует общие знания. |
| Экспертный параллелизм | «Шардирование по экспертам» | Распределение разных экспертов по разным GPU; маршрутизация токенов по сети. |
| Разреженность | «Активные параметры < общего числа параметров» | Отношение `k × expert_size / (E × expert_size)`; 37/671 ≈ 5,5% для DeepSeek-V3. |
