# Transfusion: авторегрессионный текст + диффузионное изображение в одном трансформере

> Chameleon и Emu3 ставят всё на дискретные токены. Это работает, но узкое место квантования заметно — качество изображений выходит на плато ниже уровня непрерывной диффузии. Transfusion (Meta, Zhou et al., август 2024) делает противоположную ставку: оставить изображения непрерывными, полностью отказаться от VQ-VAE и обучить один трансформер с двумя функциями потерь. Текстовые токены получают предсказание следующего токена. Патчи изображений получают функцию потерь сопоставления потоков (flow matching) / диффузии. Обе задачи оптимизируют одни и те же веса. Архитектура, лежащая в основе Stable Diffusion 3 (MMDiT), — близкий родственник. Этот урок разбирает тезис Transfusion, строит игрушечный тренер с двумя функциями потерь и прослеживает маску внимания, позволяющую одному трансформеру выполнять обе задачи.

**Тип:** Build
**Языки:** Python (стандартная библиотека, тренер с двумя функциями потерь на игрушечной задаче масштаба MNIST)
**Предварительные требования:** Этап 12 · 11 (Chameleon), этап 8 (генеративный ИИ)
**Время:** ~180 минут

## Цели обучения

- Собрать трансформер, работающий с двумя функциями потерь (предсказание следующего токена на текстовых токенах, диффузионный MSE на патчах изображений) на одной базовой архитектуре.
- Объяснять, почему двунаправленное внимание между патчами изображения в сочетании с каузальным вниманием по текстовым токенам — правильный выбор маски.
- Сравнивать подход в стиле Transfusion (непрерывные изображения, диффузионная функция потерь) с подходом в стиле Chameleon (дискретные изображения, предсказание следующего токена) по вычислениям, качеству и сложности кода.
- Называть вклад MMDiT: модально-специфичные веса в каждом блоке, совместное внимание в остаточном потоке.

## Проблема

Спор о дискретных против непрерывных токенов изображений старше самих LLM. Непрерывные представления (сырые пиксели, латенты VAE) сохраняют детали. Дискретные токены (индексы VQ) вписываются в нативный словарь трансформера, но теряют детали на этапе квантования.

Chameleon / Emu3 пошли по дискретному пути: одна функция потерь, одна архитектура, но точность изображений упирается в качество токенизатора.

Диффузионные модели пошли по непрерывному пути: исключительное качество изображений, но отдельная от LLM модель, сложная инженерия шумового расписания и отсутствие чистой интеграции с генерацией текста.

Transfusion спрашивает: можно ли получить и то, и другое? Оставить изображения непрерывными, всё же обучить одну модель, использовать две функции потерь, сшитые в один шаг градиента.

## Концепция

### Архитектура с двумя функциями потерь

Один декодерный трансформер обрабатывает последовательность, содержащую:

- Текстовые токены (дискретные, из BPE-словаря).
- Патчи изображения (непрерывные, блоки пикселей 16x16, спроецированные в скрытую размерность через линейный эмбеддинг — так же, как входной слой энкодера ViT).
- Теги `<image>` и `</image>`, отмечающие, где находятся непрерывные патчи.

Прямой проход выполняется один раз. Функция потерь выбирает одну из двух голов для каждого токена:

- Для текстовых токенов: стандартная кросс-энтропия на голове логитов словаря.
- Для патчей изображения: диффузионная функция потерь на непрерывных патчах — предсказать шум, добавленный к каждому патчу.

Градиент проходит через общее тело трансформера. Обе функции потерь одновременно улучшают общие веса.

### Маска внимания: каузальный текст + двунаправленное изображение

Текстовые токены обязаны быть каузальными — нельзя позволить текстовому токену обращаться к будущему тексту, иначе нарушится принудительное обучение (teacher forcing). Патчи изображения, однако, представляют один снимок; в пределах одного блока изображения они должны обращаться друг к другу двунаправленно.

Маска:

```
M[i, j] = 1 if:
  (i is text and j is text and j <= i)   # causal for text
  OR (i is image and j is image and same_image_block(i, j))   # bidirectional within image
  OR (i is text and j is image and j < i_image_end)   # text attends to previous images
  OR (i is image and j is text and j < i_image_start)   # image attends to preceding text
```

Реализуется как блочно-треугольная маска на обучении и на инференсе.

### Диффузионная функция потерь внутри трансформера

Диффузионная функция потерь стандартна: добавить шум к патчу изображения, попросить модель предсказать этот шум (или, что эквивалентно, чистый патч). Версия Transfusion использует сопоставление потоков — предсказывает поле скорости от зашумлённых данных к чистым.

Во время обучения:
1. Для каждого патча изображения x0 сэмплируется случайный шаг времени t.
2. Сэмплируется шум ε, вычисляется xt = (1-t) * x0 + t * ε (линейная интерполяция для сопоставления потоков).
3. Трансформер предсказывает v_theta(xt, t); функция потерь = MSE(v_theta(xt, t), ε - x0).
4. Обратное распространение вместе с функциями потерь предсказания следующего токена для текста из той же последовательности.

На инференсе генерация выглядит так:
- Текстовые токены: стандартное авторегрессионное сэмплирование.
- Патчи изображения: цикл диффузионного сэмплирования (обычно 10-30 шагов), обусловленный предшествующими текстовыми токенами.

### MMDiT: вариант Stable Diffusion 3

Stable Diffusion 3 (Esser et al., март 2024) представила MMDiT (Multimodal Diffusion Transformer) примерно в то же время, что и Transfusion. Архитектуры — родственные.

Ключевые отличия MMDiT:

- Модально-специфичные веса в каждом блоке. У каждого блока трансформера отдельные веса Q, K, V и MLP для текстовых токенов и для патчей изображения. Внимание совместное (межмодальное); всё остальное — модально-специфичное.
- Обучение выпрямленному потоку (rectified flow). Конкретный вариант сопоставления потоков с известным сэмплированием и более простой математикой, чем у DDPM.
- Масштаб. MMDiT — базовая архитектура SD3 (варианты на 2 и 8 млрд параметров). Статья Transfusion масштабируется до 7 млрд.

Оба сходятся к одной и той же основной идее: один трансформер выполняет предсказание следующего токена на тексте и диффузию на непрерывных представлениях изображения.

### Почему это превосходит подход в стиле Chameleon

Разрыв в качестве между непрерывной диффузией и дискретным предсказанием следующего токена в генерации изображений измерим. Статья Transfusion сообщает:

- При 7 млрд параметров превосходит модель в стиле Chameleon того же размера по FID на 3-5 баллов.
- Обучение токенизатора не требуется — энкодер изображения проще (линейная проекция в скрытое состояние, как входной слой ViT).
- Инференс может распараллелить удаление шума по патчам изображения, в отличие от авторегрессионных токенов изображения.

Недостаток: Transfusion — модель с двумя функциями потерь, из-за чего динамика обучения сложнее. Веса функций потерь нужно подбирать. Несоответствие расписаний между предсказанием следующего токена и диффузией может привести к доминированию одной из голов.

### Что развивается дальше

Janus-Pro (Урок 12.15) уточняет идею Transfusion, разделяя визуальный энкодер для понимания и для генерации — SigLIP для одного, VQ для другого — при общем теле трансформера. Show-o (Урок 12.14) заменяет диффузию на дискретную диффузию (маскированное предсказание). Семейство унифицированной генерации быстро ветвится после Transfusion.

VLM 2026 года, умеющие выводить изображения — Gemini 3 Pro, GPT-5, путь генерации изображений Claude Opus 4.7, — почти наверняка используют тот или иной вариант из этого семейства. Детали проприетарны.

## Применяем

`code/main.py` строит игрушечный Transfusion на крошечной задаче в духе MNIST:

- Текстовые подписи — короткие последовательности целых чисел, описывающие цифру (0-9).
- Изображения — сетки байтов 4x4.
- Пара линейных проекций с общими весами играет роль трансформера; функция потерь предсказания следующего токена на тексте, MSE-функция потерь на зашумлённых патчах.
- Цикл обучения чередует две функции потерь, маска внимания задана явно.
- Генерация производит текстовую подпись и изображение 4x4 за один прямой проход.

Трансформер игрушечный. Реальные артефакты — это разводка двух функций потерь, построение маски внимания и цикл инференса.

## Публикуем

Этот урок производит `outputs/skill-two-loss-trainer-designer.md`. По заданной новой задаче мультимодального обучения (текст + изображение, текст + аудио, текст + видео) он проектирует расписание с двумя функциями потерь (веса функций потерь, форма маски, общие против модально-специфичных блоков) и отмечает риски реализации.

## Упражнения

1. Модель в стиле Transfusion обучается на 70% текстовых токенов и 30% патчей изображения. Диффузионная функция потерь на изображении примерно в 10 раз больше по величине, чем функция потерь предсказания следующего токена на тексте. Какие веса функций потерь их сбалансируют?

2. Реализуйте блочно-треугольную маску для последовательности: `[T, T, <image>, P, P, P, P, </image>, T]`. Отметьте каждую запись 0 или 1.

3. У MMDiT модально-специфичные веса QKV. Какие накладные расходы по числу параметров это добавляет относительно полностью общего трансформера Transfusion? При 7 млрд параметров это того стоит?

4. Генерация: по текстовому промпту модель выполняет предсказание следующего токена для 50 токенов, затем встречает `<image>`, затем выполняет диффузию на 256 патчах за 20 шагов удаления шума. Сколько всего прямых проходов?

5. Прочитайте раздел 3 статьи SD3. Опишите выпрямленный поток и объясните, почему он сходится за меньшее число шагов инференса, чем DDPM.

## Ключевые термины

| Термин | Как это обычно называют | Что это означает на самом деле |
|------|-----------------|------------------------|
| Обучение с двумя функциями потерь | «NTP + диффузия» | Один трансформер оптимизирует одновременно кросс-энтропию на текстовых токенах и MSE на непрерывных патчах изображения за один шаг градиента |
| Сопоставление потоков | «Выпрямленный поток» | Вариант диффузии, предсказывающий поле скорости от шума к чистым данным; математика проще, чем у DDPM |
| MMDiT | «Мультимодальный DiT» | Архитектура Stable Diffusion 3: совместное внимание, модально-специфичные MLP и нормализации |
| Блочно-треугольная маска | «Каузальный текст + двунаправленное изображение» | Маска внимания, каузальная по тексту, но двунаправленная внутри областей изображения |
| Непрерывное представление изображения | «Без VQ» | Патчи изображения как вещественнозначные векторы, а не целочисленные индексы кодовой книги |
| Предсказание скорости | «v-параметризация» | Выход сети — поле скорости между шумом и данными, а не сам шум |
