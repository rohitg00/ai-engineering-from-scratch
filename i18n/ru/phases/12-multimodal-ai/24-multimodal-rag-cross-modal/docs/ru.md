# Мультимодальный RAG и кросс-модальный поиск

> Зрение-нативный RAG для документов — лишь один срез. Продакшен-мультимодальный RAG охватывает больше — поиск по тексту, изображениям, аудио и видео для рабочих процессов вроде планирования поездок («найди мне тихий веганский бранч с естественным освещением»), медицинской триажной сортировки («какая травма соответствует этому фото + этим заметкам»), электронной коммерции («наряды, похожие на это селфи, моего размера») и выездного обслуживания («диагностируй этот звук двигателя плюс фото детали»). Три обзора 2025 года — Abootorabi et al., Mei et al., Zhao et al. — систематизировали подзадачи: кросс-модальный поиск, слияние результатов поиска, привязка генерации к источникам (grounding), мультимодальное оценивание. Этот урок разбирает обзоры и проектирует продакшен-конвейер.

**Тип:** Build
**Языки:** Python (stdlib, кросс-модальный поисковик со слиянием + генератор с привязкой к источникам)
**Предварительные требования:** Фаза 12 · 23 (ColPali), Фаза 11 (основы RAG)
**Время:** ~180 минут

## Цели обучения

- Проектировать кросс-модальный поиск: текст → изображение, изображение → текст, аудио → видео и так далее.
- Сравнивать три стратегии слияния: слияние по оценкам, слияние на основе внимания, слияние MoE.
- Объяснять привязку генерации к источникам: как выглядит «указание источников», когда источники — смесь модальностей.
- Называть три канонических обзора мультимодального RAG 2025 года и их таксономию подзадач.

## Проблема

Одномодальный RAG — решённый паттерн: превратить запрос в эмбеддинг, превратить фрагменты в эмбеддинги, найти релевантные, поместить в LLM. Мультимодальный RAG требует:

1. Несколько поисковых голов (каждой модальности нужны эмбеддинги в совместимом пространстве).
2. Слияния результатов поиска между модальностями.
3. Привязки генерации к источникам разных модальностей.
4. Метрик оценивания, покрывающих кросс-модальный сигнал.

Все обзоры 2025 года приходят к одной и той же таксономии.

## Концепция

### Кросс-модальный поиск

Найти документы модальности B по запросу модальности A. Три паттерна:

1. Общее пространство эмбеддингов. CLIP и CLAP создают эмбеддинги текст+изображение / текст+аудио в общем пространстве. Косинусное сходство между модальностями работает напрямую. Ограничено парами, на которых обучен CLIP.

2. Энкодер для каждой модальности + перевод. Текстовый энкодер + энкодер изображений + небольшой модуль-переводчик, отображающий между пространствами. Sen2Sen (Gupta et al.) и другие решения 2024 года. Гибко, но добавляет сложность.

3. VLM как энкодер. Использовать скрытые состояния VLM как представление для поиска. Подходит любая модальность, которую поддерживает VLM. Выше качество, дороже.

Выбор: CLIP / SigLIP 2 для текст+изображение; CLAP для текст+аудио; скрытые состояния VLM для кросс-модального поиска на переднем крае качества.

### Стратегии слияния

Вы нашли 10 результатов: 5 изображений, 3 текстовых фрагмента, 2 аудиоклипа. Как их объединить?

Слияние по оценкам (самое дешёвое). У каждой модальности свой поисковик, каждый возвращает оценки. Нормализуйте оценки внутри модальности, затем суммируйте. Просто и часто работает.

Слияние на основе внимания. Конкатенируйте все найденные элементы, пусть небольшая сеть внимания взвесит их. Требует обучения.

Слияние MoE. Управляющая сеть (gating network) направляет к экспертам, специфичным для модальности. Разные типы запросов маршрутизируются по-разному — визуальный вопрос повышает вес изображений.

Вариант по умолчанию в продакшене: слияние по оценкам с небольшим смещением в сторону доминирующей модальности запроса. Переходите на MoE, если A/B-тестирование показывает явный выигрыш в вашем домене.

### Привязка генерации к источникам

LLM должна указывать, какой найденный элемент обосновывает каждое утверждение. Для мультимодальных источников:

- Текстовый источник: стандартная ссылка `[1]`.
- Источник-изображение: `[img 3]` с короткой подписью.
- Аудио: `[audio 2 at 0:34]`.

Обучайте генератор на данных, учитывающих привязку к источникам: каждое утверждение в целевом ответе помечено индексом источника. На инференсе модель естественным образом выдаёт ссылки.

### Обзоры 2025 года

Abootorabi et al. (arXiv:2502.08826, «Ask in Any Modality»): таксономия мультимодального RAG. Охватывает поиск, слияние, генерацию. Самое широкое покрытие.

Mei et al. (arXiv:2504.08748, «A Survey of Multimodal RAG»): фокусируется на бенчмарках подзадач и режимах отказа. Полезен для проектирования оценивания.

Zhao et al. (arXiv:2503.18016): обзор с фокусом на зрении. Силён в освещении работ семейства ColPali.

Чтение всех трёх даёт представление о состоянии дел на весну 2025 года. Большинство подзадач всё ещё остаются открытыми.

### MuRAG — основополагающая статья

MuRAG (Chen et al., 2022) была первым мультимодальным RAG. Находила изображение + текст в мультимодальной базе знаний, генерировала ответы. Показала осуществимость ещё до волны VLM. Современные системы (REACT, VisRAG, M3DocRAG) строятся на её основе.

### Пример продакшен-планировщика поездок

Запрос: «найди мне тихий веганский бранч с естественным освещением».

Конвейер:

1. Разложить запрос. «тихий» → ключевое слово аудио/отзыва; «веганский бранч» → пункт меню; «естественное освещение» → признак изображения.
2. Искать по каждой модальности:
   - Текстовый поиск по отзывам: «веганский бранч, тихая атмосфера».
   - Поиск по фотографиям ресторана: «естественное освещение, воздушная атмосфера».
   - Поиск по аудио в клипах фонового звука: «низкая громкость, без музыки».
3. Слить оценки. У каждого ресторана есть составная оценка.
4. Топ-k ресторанов → генератор VLM со всеми свидетельствами → ответ со ссылками на источники.

Это выходит далеко за рамки текстового RAG. Каждая модальность добавляет сигнал, который упускает один только текст.

### Агентный мультимодальный RAG

Многошаговый (multi-hop): если первый поиск не возвращает ответов с высокой уверенностью, LLM переформулирует запрос и ищет снова. Здесь применимы паттерны агентного RAG из Фазы 14. Примеры:

- Найти начальный топ-10 → LLM запрашивает «слишком шумно, отфильтровать до <40 дБ» → повторный поиск.
- Найти изображения → LLM замечает, что на одном есть меню → найти текст меню → ответ.

Добавляет сложность, но справляется с запросами, которые не под силу однократному поиску.

### Оценивание

Кросс-модальное оценивание всё ещё незрелая область. Распространённые прокси-метрики:

- Полнота@k по каждой модальности.
- Точность слитого топ-k.
- Сквозная удовлетворённость по оценке людей.
- Специфичные для задачи (завершённые бронирования, совершённые покупки).

Единого бенчмарка, охватывающего все модальности, не существует. Большинство статей оценивают модели на задачах, специфичных для домена.

## Применяем

`code/main.py`:

- Три имитационных поисковика (текст, изображение, аудио), работающих на общем корпусе ресторанов.
- Слияние по оценкам, объединяющее оценки модальностей с настраиваемыми весами.
- Заглушка генератора, выдающая финальный ответ со ссылками на источники.
- Простой агентный цикл, переформулирующий запрос при низкой уверенности.

1. Предложите мультимодальный RAG для медицинской триажной сортировки: запрос = фото травмы + текстовые симптомы. Какие модальности что ищут в какой базе знаний?

2. Слияние по оценкам — это простая взвешенная сумма. Какой режим отказа у него есть, которого избегает слияние MoE?

5. Агентный многошаговый RAG платит задержкой за каждый цикл обращения. При какой сложности запроса выигрыш в точности оправдывает задержку?

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|------------------------|
| Кросс-модальный поиск | «Запрос в одной модальности, поиск в другой» | Текстовый запрос находит изображения; запрос-изображение находит текст; требует общего пространства или переводчика |
| Слияние по оценкам | «Объединить оценки» | Взвешенная сумма оценок поиска по каждой модальности; простейшее слияние |
| Слияние MoE | «Эксперты, маршрутизируемые по модальности» | Управляющая сеть выбирает, каким модальным оценкам доверять для каждого запроса |
| Генерация с привязкой к источникам | «Указывай источники» | Каждое утверждение в ответе помечено индексом источника |
| MuRAG | «Первый мультимодальный RAG» | Статья 2022 года, заложившая паттерн мультимодального RAG |
| Агентный многошаговый поиск | «Переформулировать и повторить» | LLM повторно запрашивает поисковики, когда уверенность первого прохода низка |
