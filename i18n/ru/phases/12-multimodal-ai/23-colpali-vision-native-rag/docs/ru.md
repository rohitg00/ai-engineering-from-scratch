# ColPali и визуально-ориентированный RAG для документов

> Традиционный RAG разбирает PDF на текст, делит его на фрагменты, вычисляет эмбеддинги фрагментов и сохраняет векторы. На каждом шаге теряется часть сигнала: OCR теряет данные диаграмм, разбиение на фрагменты ломает строки таблиц, текстовые эмбеддинги игнорируют иллюстрации. ColPali (Faysse et al., июль 2024) задал более простой вопрос: зачем вообще извлекать текст? Эмбеддинг страницы вычисляется напрямую через PaliGemma, для поиска используется свойственное ColBERT позднее взаимодействие (late interaction), сохраняющее весь сигнал разметки, иллюстраций, шрифтов и форматирования, который несёт документ. Опубликованные бенчмарки показывают: сквозная точность на 20-40% выше, чем у text-RAG, на визуально насыщенных документах. ColQwen2, ColSmol и VisRAG расширили этот паттерн. Этот урок разбирает концепцию визуально-ориентированного RAG и строит миниатюрный индексатор в духе ColPali.

**Тип:** Build
**Языки:** Python (стандартная библиотека, мультивекторный индексатор + оценщик MaxSim)
**Предварительные требования:** этап 11 (инженерия LLM — основы RAG), этап 12 · 05 (LLaVA)
**Время:** ~180 минут

## Цели обучения

- Объяснять разницу между поиском на основе двухбашенного энкодера (bi-encoder; один вектор на документ) и поиском с поздним взаимодействием (много векторов на документ).
- Описывать операцию MaxSim в ColBERT и то, как ColPali обобщает её с текстовых токенов на патчи изображений.
- Строить миниатюрный индексатор в духе ColPali: страница → эмбеддинги патчей → MaxSim по эмбеддингам токенов запроса → top-k страниц.
- Сравнивать связку ColPali + генератор Qwen2.5-VL с text-RAG + GPT-4 на примере счетов-фактур и финансовых отчётов.

## Проблема

text-RAG на PDF-документах отбрасывает большую часть документа. Рост выручки за третий квартал в финансовом отчёте обычно показан на диаграмме; результаты медицинского отчёта — в аннотированных изображениях; блок подписи в юридическом контракте — это факт разметки страницы, а не текстовый факт.

Конвейер text-RAG:

1. PDF → текст через OCR / pdftotext.
2. Текст → фрагменты по 300-500 токенов.
3. Фрагмент → эмбеддинг двухбашенного энкодера (один вектор).
4. Запрос пользователя → эмбеддинг → косинусное сходство → top-k фрагментов.
5. Фрагменты + запрос → LLM.

Пять шагов с потерей сигнала. Диаграммы не захватываются. Таблицы разбиваются между фрагментами. Многоколоночная разметка сплющивается. Аннотации к иллюстрациям исчезают.

Решение ColPali: пропустить OCR и вычислять эмбеддинг изображения страницы напрямую. Для поиска используется свойственное ColBERT позднее взаимодействие, чтобы модель могла обращать внимание на мелкозернистые патчи в момент запроса.

## Концепция

### ColBERT (2020)

ColBERT (Khattab & Zaharia, arXiv:2004.12832) — метод текстового поиска. Вместо одного вектора на документ он производит один вектор на токен. В момент запроса:

- Токены запроса получают собственные эмбеддинги (N_q векторов).
- Токены документа получают эмбеддинги (N_d векторов, обычно кешируются).
- Оценка = сумма по токенам запроса максимума по токенам документа косинусного сходства: Σ_i max_j cos(q_i, d_j).

Это операция MaxSim. Каждый токен запроса «выбирает» наиболее подходящий ему токен документа. Итоговая оценка — сумма этих выборов.

Плюсы: высокая полнота, учитывает семантику на уровне отдельных термов. Минусы: N_d векторов на документ, дорогое хранение.

### ColPali

ColPali (Faysse et al., arXiv:2407.01449) применяет паттерн ColBERT к изображениям.

- Каждая страница кодируется PaliGemma (ViT + языковая модель) в эмбеддинги патчей: N_p векторов на страницу.
- Каждый пользовательский запрос (текст) кодируется в эмбеддинги токенов запроса: N_q векторов.
- Оценка = Σ_i max_j cos(q_i, p_j), то есть MaxSim между текстовыми токенами запроса и патчами изображения страницы.
- Извлекаются top-k страниц по суммарной оценке.

На этапе загрузки документа: вычисляется эмбеддинг каждой страницы через PaliGemma, сохраняются все эмбеддинги патчей. В момент запроса: вычисляется эмбеддинг токенов запроса, MaxSim считается относительно всех сохранённых эмбеддингов страниц, возвращаются top-k страниц.

Плюсы: по сквозной точности метод превосходит text-RAG на 20-40% на визуально насыщенных документах. Каждый вектор патча захватывает локальную разметку и содержимое.

Минусы: N_p патчей × 4-байтные числа с плавающей точкой × D-мерные векторы на страницу — хранилище растёт быстро. Смягчается квантованием PQ / OPQ.

### ColQwen2 и ColSmol

ColQwen2 (illuin-tech, 2024-2025) заменяет PaliGemma на Qwen2-VL. Более сильный базовый энкодер — более качественный поиск.

ColSmol — уменьшенный вариант для локального использования или работы на периферийных устройствах. Средство поиска ColSmol с ~1 млрд параметров работает на потребительском GPU.

### VisRAG

VisRAG (Yu et al., arXiv:2410.10594) — другой вариант: вместо MaxSim по патчам VLM сводит каждую страницу в единый вектор с помощью агрегации (pooling), а поиск выполняется как у двухбашенного энкодера. Индексирование быстрее, хранилище меньше, полнота ниже.

Компромисс качество/стоимость: ColPali — для качества, VisRAG — для масштаба.

### M3DocRAG

M3DocRAG (Cho et al., arXiv:2411.04952) расширяет мультимодальный поиск до рассуждения по нескольким страницам и нескольким документам. Извлекает страницы из разных документов и собирает из них многостраничный контекст для VLM.

### ViDoRe — бенчмарк

Сопутствующий бенчмарк ColPali. Visual Document Retrieval Evaluation (оценка визуального поиска по документам). Задачи включают финансовые отчёты, научные статьи, административные документы, медицинские записи, руководства. Метрика: nDCG@5.

ColPali-v1 набирает ~80% nDCG@5 на ViDoRe; text-RAG на тех же документах — ~50-60%.

### Полный конвейер RAG

Для визуально-ориентированного RAG:

1. Загрузка: PDF → изображения страниц → кодирование PaliGemma → сохранение всех эмбеддингов патчей.
2. Запрос: текст пользователя → эмбеддинги токенов запроса → MaxSim относительно всех проиндексированных страниц → top-k страниц.
3. Генерация: изображения top-k страниц + запрос → VLM (Qwen2.5-VL или Claude) → ответ.

Нигде нет OCR. Иллюстрации, диаграммы, шрифты, разметка — всё это участвует в формировании ответа.

### Расчёт хранилища

Финансовый отчёт на 50 страниц с 729 патчами на странице и 128-мерными эмбеддингами:

- ColPali: 50 * 729 * 128 * 4 байта = ~18 МБ в исходном виде, ~4 МБ после PQ.
- text-RAG: 50 фрагментов * 768 измерений * 4 байта = ~150 кБ.

ColPali требует примерно в 30 раз больше хранилища на документ. При масштабировании OPQ / PQ снижает это соотношение до ~5-10x, что обычно приемлемо.

### Когда text-RAG всё ещё выигрывает

- Чисто текстовые документы без сигнала разметки (статьи wiki, логи чатов). text-RAG проще и дешевле по хранилищу.
- Архивы на многие миллионы страниц, где стоимость определяется хранилищем.
- Строгие нормативные требования, обязывающие иметь извлекаемый OCR-текст наряду с поиском.

Для всего остального в 2026 году — финансовых отчётов, научных статей, юридических контрактов, медицинских записей, UX-документации — побеждает визуально-ориентированный RAG.

## Применяем

`code/main.py`:

- Игрушечный энкодер патчей: отображает «страницу» (небольшую сетку векторов признаков) в массив эмбеддингов патчей.
- Скорер MaxSim: вычисляет оценку в стиле ColBERT между набором эмбеддингов токенов запроса и набором патчей страницы.
- Индексирует 5 игрушечных страниц, выполняет 3 запроса, возвращает top-k с оценками.

## Упражнения

1. Годовой отчёт на 200 страниц с 729 патчами на странице, 128-мерными эмбеддингами, 4-байтными числами с плавающей точкой. Вычислите исходный объём хранилища и объём после PQ-сжатия (8x).

2. MaxSim — это Σ_i max_j cos(q_i, p_j). Что эта сумма захватывает такого, чего не захватывает простое среднее сходство?

3. ColPali индексирует страницы как наборы патчей. Что изменится, если вместо этого индексировать на уровне слов (как это делает ColBERT)? Какие здесь компромиссы?

4. Спроектируйте полный конвейер для корпуса на 1 млн страниц с бюджетом задержки 500 мс на запрос. Выберите ColQwen2 / VisRAG и обоснуйте выбор.

5. Прочитайте M3DocRAG (arXiv:2411.04952). Опишите паттерн внимания между несколькими страницами и то, чем он отличается от поиска ColPali по одной странице.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|------------------------|
| Позднее взаимодействие | «В стиле ColBERT» | Поиск с эмбеддингами на уровне токена или патча + MaxSim, а не с единым вектором документа |
| MaxSim | «Максимум по патчам» | Для каждого токена запроса выбирается токен документа с наибольшим сходством; суммируется по запросу |
| Двухбашенный энкодер | «Единый вектор» | Один вектор на документ; быстрее, но теряет детализацию |
| Мультивекторное представление | «Много векторов на документ» | Хранение N_p векторов на документ / страницу; стоимость хранилища растёт, но полнота улучшается |
| Эмбеддинг патча | «Признак страницы» | Один вектор на патч изображения от энкодера VLM, кешируется для каждой страницы |
| ViDoRe | «Бенчмарк визуальных документов» | Набор бенчмарков ColPali для визуального поиска по документам |
| Квантование PQ | «Продуктовое квантование» | Сжатие, сохраняющее сходство векторов при уменьшении объёма хранилища примерно в 8 раз |
