# LLaVA-OneVision: одно изображение, несколько изображений, видео — в одной модели

> До LLaVA-OneVision (Li et al., август 2024) мир открытых VLM состоял из отдельных линий: LLaVA-1.5 для одиночных изображений, модели для нескольких изображений вроде Mantis и VILA, видеомодели вроде Video-LLaVA и Video-LLaMA. Каждая выигрывала на своём бенчмарке и проваливалась на остальных. LLaVA-OneVision утверждала, что единый куррикулум может обучить одну модель доминировать во всех трёх сценариях и что эффекты эмерджентного переноса задач (навыки с одиночными изображениями переносятся на видео, рассуждение по нескольким изображениям переносится на одиночное изображение) превосходят сумму специализированных моделей. Рецепт обманчиво прост: бюджет визуальных токенов, остающийся постоянным во всех сценариях, плюс явный куррикулум, движущийся от одиночного изображения к OneVision (несколько изображений), а затем к видео. Этот урок разбирает бюджет, куррикулум и эмерджентное поведение.

**Тип:** Build
**Языки:** Python (stdlib, решатель бюджета токенов + планировщик куррикулума)
**Предварительные требования:** Фаза 12 · 05 (LLaVA), Фаза 12 · 06 (произвольное разрешение)
**Время:** ~180 минут

## Цели обучения

- Проектировать бюджет визуальных токенов, остающийся постоянным для одиночных изображений, нескольких изображений и видео.
- Упорядочивать куррикулум обучения, переносящий навыки от одиночного изображения к видео без катастрофического забывания.
- Объяснять, почему одна модель превосходит специализированные модели при том же количестве параметров, если куррикулум выстроен правильно.
- Называть три эмерджентные способности, о которых сообщает LLaVA-OneVision: рассуждение с нескольких камер, промптинг с набором меток, агент по скриншотам iPhone.

## Проблема

Одно изображение, несколько изображений и видео нагружают модель по-разному.

Одиночное изображение требует токенов высокого разрешения (AnyRes, ~2880 визуальных токенов), чтобы улавливать OCR и мелкие детали. Бюджет на пример: одно изображение, 2880 токенов.

Несколько изображений требуют нескольких изображений умеренного разрешения (~576 токенов каждое), чтобы рассуждение между изображениями умещалось в контекст. Бюджет на пример: 4-8 изображений по 576 токенов каждое, 2300-4600 токенов.

Видео требует множества кадров низкого разрешения (~196 токенов на кадр после пулинга), чтобы улавливать временную динамику. Бюджет на пример: 8-32 кадра по 196 токенов каждый, 1600-6200 токенов.

Если вы обучаете отдельные модели, вы выбираете один бюджет. Если вы обучаете одну модель, нужно, чтобы бюджет разумно масштабировался между сценариями, не раздувая контекст.

До OneVision ответ по умолчанию был «обучить один сценарий, игнорировать остальные». Video-LLaVA дооснастила видео поверх модели для изображений дополнительными этапами обучения. LLaVA-NeXT добавила поддержку нескольких изображений с помощью тайлинга. Ни одна из них не обрабатывала все три сценария аккуратно.

## Концепция

### Бюджет токенов OneVision

LLaVA-OneVision выбирает единый бюджет визуальных токенов примерно в 3000-4000 токенов на пример, распределяемый по-разному в зависимости от сценария:

- Одиночное изображение: AnyRes-9 (тайлы 3x3 + миниатюра), каждый тайл на 384 с 729 патчами, агрессивный билинейный пулинг 2x2 → 182 на тайл. Итого: 9 * 182 + 182 = 1820 токенов. Или AnyRes-4 при 729 на тайл = 2916 + 729.
- Несколько изображений: каждое изображение при умеренном разрешении (384, без тайлинга), 729 токенов без пулинга. Бюджет для 6 изображений → 4374 токена.
- Видео: 32 кадра при разрешении 384 с агрессивным билинейным пулингом 3x3 → 81 токен на кадр. Итого: 32 * 81 = 2592 токена.

Распределение поддерживает примерно постоянное общее число токенов. Большая языковая модель (LLM) никогда не видит пакет, раздувающий её контекст. Энкодер выдаёт разную геометрию в зависимости от сценария, но LLM потребляет один и тот же бюджет.

### Трёхэтапный куррикулум

LLaVA-OneVision обучается в три этапа:

1. SFT на одиночных изображениях (этап SI). Все данные — одиночное изображение плюс текст. Обучение на входе AnyRes высокого разрешения. Это учит восприятию, OCR и тонкому пониманию. Используются данные LLaVA-NeXT плюс специфичные для OneVision данные с одиночными изображениями.
2. SFT OneVision (этап OV). Смесь одиночных изображений + нескольких изображений + видео (равномерно сэмплированные кадры). Обучение на едином бюджете токенов. Это учит модель обрабатывать пакеты неоднородной формы. Без сброса весов — продолжение с этапа SI.
3. Перенос задач (этап TT). Продолжение с целевой смесью задач, обычно с большим упором на несколько изображений или видео в зависимости от продукта. Опциональное дообучение для развёртывания.

Критично: порядок куррикулума имеет значение. Обучение сначала на видео или сначала на нескольких изображениях даёт худшую производительность на изображениях, чем обучение сначала на одиночном изображении, даже при тех же данных. Статья явно абляционирует это.

### Почему куррикулум работает

Обучение на одиночных изображениях строит перцептивную базу. Токены патчей несут тонкие визуальные признаки; LLM учится интегрировать их с текстом. Несколько изображений и видео вносят структурные сложности (какое изображение какое, что произошло первым), которые трудно освоить без прочной перцептивной базы.

Если обучать все сценарии совместно с нуля, модель недообучается восприятию (ограниченное количество данных с одиночными изображениями на пакет) и переобучается структуре (много данных с несколькими изображениями / видео). Результат: модель, следующая паттернам рассуждения между изображениями, но визуально поверхностная.

Упорядочивание куррикулума даёт силу восприятия с этапа SI, затем композиционное/временно́е рассуждение с этапа OV, не теряя ни того, ни другого.

### Эмерджентные межсценарные навыки

Статья LLaVA-OneVision сообщает о трёх эмерджентных способностях:

1. Рассуждение с нескольких камер. Обучена на нескольких изображениях + видео по отдельности; во время выполнения вывода (инференс) её просят рассуждать о сцене вождения с нескольких камер. Модель корректно интегрирует ракурсы, хотя никогда не видела точно такой формат при обучении.
2. Промптинг с набором меток. Пользователь аннотирует объекты на изображении пронумерованными метками; модель рассуждает о том, «что делает метка 3 относительно метки 7». Обучена ни на метках, ни на аннотации; научилась из комбинации пространственной локализации и ссылок между несколькими изображениями.
3. Агент по скриншотам iPhone. Пользователь предоставляет скриншот экрана iPhone и просит спланировать следующий клик. Обучена на скриншотах UI, видео рабочих процессов пользователя и парах «до/после» из нескольких изображений. Обобщается на сценарий использования агента.

Модель не обучали непосредственно этим задачам; они возникают благодаря композиционной структуре куррикулума.

### Пулинг визуальных токенов

Бюджет токенов требует пулинга. OneVision использует билинейную интерполяцию на 2D-сетке патчей: 24x24 = 576 патчей становится 12x12 = 144 (коэффициент 2x) или 8x8 = 64 (коэффициент 3x). Пулинг выполняется в пространстве сетки патчей, а не в пространстве токенов, чтобы сохранить локальность.

Выбор коэффициента пулинга для каждого сценария — сам по себе гиперпараметр. Меньше пулинга = больше токенов = более богатое представление. Больше пулинга = меньше токенов = помещается больше кадров / изображений.

### LLaVA-OneVision-1.5

Продолжение 2025 года (LLaVA-OneVision-1.5, arXiv 2509.23661) «полностью открыто» в плане обучающих данных, весов модели и кода. На некоторых бенчмарках оно сокращает разрыв с проприетарными моделями и демократизирует рецепт. Тот же куррикулум, больше данных, лучшая базовая LLM. Без изменений архитектуры.

### Сравнение с Qwen2.5-VL

Qwen2.5-VL (Урок 12.09) делает другой выбор. Она использует M-RoPE и динамический FPS вместо фиксированного пулинга. Её бюджет масштабируется с входом — минутное видео использует больше токенов, чем пятисекундное. LLaVA-OneVision фиксирует бюджет и масштабирует пулинг. Оба подхода работают; они меняют настраиваемость на предсказуемость.

## Применяем

`code/main.py` — это планировщик куррикулума и бюджета для VLM в стиле OneVision. Учитывая бюджет токенов на пример и целевую смесь сценариев (скажем, 40% одиночное изображение, 30% несколько изображений, 30% видео), он:

- Распределяет разрешение, коэффициент пулинга и количество кадров по сценариям.
- Проверяет, что каждый сценарий укладывается в общий бюджет.
- Сообщает ожидаемое количество токенов, FLOPs LLM и какие сценарии недополучают токены.
- Выводит поэтапное расписание обучения.

Используйте его для планирования дообучения OneVision или для проверки стоимости запроса при развёртывании VLM.

## Публикуем

Этот урок производит `outputs/skill-onevision-budget-planner.md`. Учитывая целевое распределение задач и бюджет на пример, он выдаёт коэффициент AnyRes, пулинг на кадр, количество кадров видео и веса этапов куррикулума. Используйте этот навык всякий раз, когда обучаете или дообучаете унифицированную VLM для нескольких сценариев.

## Упражнения

1. Ваш продукт поддерживает 80% одиночных изображений, 10% нескольких изображений (2-4 изображения), 10% видео (8-16 кадров). Спроектируйте бюджет токенов. Куда бы вы направили дополнительный бюджет, сэкономленный за счёт отказа от интенсивной работы с несколькими изображениями?

2. Прочитайте раздел 4.3 LLaVA-OneVision (эмерджентные способности). Предложите четвёртый эмерджентный навык, который куррикулум, вероятно, раскрыл бы, но который статья не сообщает.

3. Поменяйте порядок куррикулума — обучайте сначала на нескольких изображениях, затем на одиночном изображении, затем на видео. Предскажите, какие бенчмарки ухудшатся и почему.

4. Статья сообщает о видеобенчмарках, обученных всего на 8 кадрах на пример. Обобщается ли это на 30-секундные видео при инференсе? Что ломается первым — бюджет токенов или временно́е рассуждение?

5. Билинейный пулинг патчей 24x24 до 12x12 — это уменьшение в 4 раза по каждой размерности. Реализуйте пулинг на stdlib Python и проверьте, что среднее по каждому блоку 2x2 совпадает с билинейным выходом.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|-----------------|------------------------|
| Сценарий OneVision | «Одиночное изображение, несколько изображений или видео» | Одна из трёх форм входа, обрабатываемых унифицированной VLM; бюджет остаётся постоянным между ними |
| Бюджет токенов | «Сколько токенов на пример» | Общее количество визуальных токенов, которые LLM видит на пример при обучении/инференсе, обычно 3000-4000 |
| Куррикулум | «Порядок обучения» | Порядок этапов (одиночное изображение → несколько изображений → видео), выбранный для эмерджентного переноса |
| Билинейный пулинг | «Сжатие токенов» | Применение билинейной интерполяции к сетке патчей (2D) для уменьшения числа токенов с сохранением локальности |
| Эмерджентный навык | «Не обучалась, но всё равно работает» | Способность, проявляющаяся при инференсе без соответствующих обучающих данных, за счёт композиции куррикулума |
| AnyRes-k | «Настройка с k тайлами» | k подтайлов фиксированного разрешения плюс одна миниатюра, обычно k ∈ {4, 9} |
| Перенос задач | «Обобщение между сценариями» | Навыки, изученные на одиночном изображении, применяются к видео (и наоборот) через общий бэкбон |
