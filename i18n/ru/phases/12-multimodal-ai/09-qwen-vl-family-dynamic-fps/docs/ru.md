# Семейство Qwen-VL и видео с динамическим FPS

> Семейство Qwen-VL — Qwen-VL (2023), Qwen2-VL (2024), Qwen2.5-VL (2025), Qwen3-VL (2025) — самая влиятельная линия открытых визуально-языковых моделей в 2026 году. Каждое поколение делало одну решающую архитектурную ставку, которую остальная открытая экосистема копировала в течение двенадцати месяцев: нативное динамическое разрешение через M-RoPE, сэмплирование с динамическим FPS с абсолютным выравниванием по времени, оконное внимание в ViT и структурированные форматы вывода для агентов. К Qwen3-VL рецепт стабилизировался: энкодер ViT с 2D-RoPE и нативным соотношением сторон на входе, MLP-проектор в большую языковую базу Qwen3 и этапы обучения, делающие OCR, локализацию (grounding) и агентное поведение целями первого класса. Этот урок читает семейство хронологически, чтобы вы понимали, почему каждый рычаг находится там, где он есть.

**Тип:** Learn
**Языки:** Python (стандартная библиотека, энкодер M-RoPE + сэмплер с динамическим FPS)
**Предварительные требования:** Этап 12 · 06 (patch-n'-pack)
**Время:** ~120 минут

## Цели обучения

- Вычислять трёхосевые вращения M-RoPE (временну́ю, по высоте, по ширине) и объяснять, почему нужны все три.
- Выбирать стратегию сэмплирования с динамическим FPS для видео и рассуждать о компромиссе между токенами в секунду и точностью обнаружения событий.
- Называть по порядку четыре обновления поколений Qwen-VL и что каждое из них дало.
- Собирать формат вывода JSON-агента в стиле Qwen2.5-VL и разбирать структурированные вызовы инструментов из ответа VLM.

## Проблема

Qwen-VL вышла в августе 2023 года как прямой ответ на LLaVA-1.5 и BLIP-2. Разрыв, на который нацелилась команда Qwen, был тройным: разрешение, видео и структурированный вывод.

Разрешение: LLaVA-1.5 работала при 336x336. Хорошо для фотографий, бесполезно для счёта-фактуры на китайском языке или скриншота плотной электронной таблицы. Первое новшество Qwen-VL — 448x448 и вывод координат ограничивающих рамок для локализации объектов, позволяющий модели указывать на них.

Видео: Video-LLaMA складывала покадровые энкодеры и подавала их в LLM. Это работало для коротких клипов, но не для многоминутных видео, где сигнал — именно временна́я ось. Команда Qwen хотела единый энкодер, понимающий время.

Структурированный вывод: LLaVA выдавала свободный текст. Агенту нужен JSON. Qwen-VL обучалась на явных форматах вывода JSON, включая координаты ограничивающих рамок как текст.

Каждое поколение Qwen-VL расширяет одну из этих трёх осей.

## Концепция

### Qwen-VL (август 2023)

Первое поколение: OpenCLIP ViT-bigG/14 в качестве энкодера (2.5B параметров), совместимый с LLama Q-Former (один шаг с 256 запросами), база Qwen-7B. Вклад:

- Разрешение 448x448 (на тот момент SOTA для открытой VLM).
- Локализация (grounding): обучена на парах изображение-текст с явным выводом координатных токенов. «Кот находится на <box>(112, 204), (280, 344)</box>».
- Многоязычное обучение на китайском + английском с самого начала.

Бенчмарки на тот момент: конкурентоспособна с GPT-4V на английском, доминирует на китайском. Реальным заголовком было именно обучение с супервизией по локализации.

### Qwen2-VL (сентябрь 2024) — M-RoPE и нативное разрешение

Qwen2-VL заменила стек с фиксированным разрешением + Q-Former на нативно динамический по разрешению ViT-энкодер. Ключевые изменения:

- Нативное динамическое разрешение. ViT принимает любые HxW, кратные 28 (патч 14 с 2x пространственным слиянием). Изображение 1120x672 (40x24 слитых патча) выдаёт 960 визуальных токенов. Без ресайза, без тайлинга, без миниатюры.
- M-RoPE (мультимодальный RoPE). Каждый токен несёт 3D-позицию (t, h, w) вместо 1D. Для изображений t=0, для видео t = индекс кадра. RoPE вращает векторы запроса/ключа с частотой для каждой оси. Без таблицы позиционных эмбеддингов.
- MLP-проектор. Отказ от Q-Former; использование 2-слойного MLP на слитых токенах патчей.
- Видео с динамическим FPS. Видео сэмплируется на 1-2 FPS по умолчанию, но модель принимает произвольное количество кадров.

Результат: Qwen2-VL-7B сравнялась с GPT-4o на нескольких мультимодальных бенчмарках и превзошла её на DocVQA (94.5 против 88.4). Решающим шагом стало именно изменение архитектуры.

### Qwen2.5-VL (февраль 2025) — динамический FPS + абсолютное время

Главный сдвиг Qwen2.5-VL — видео. Динамический FPS — это не просто «сэмплировать больше кадров при необходимости». Статья формализовала:

- Токены абсолютного времени. Вместо позиционных индексов (кадр 0, 1, 2...) используются реальные временны́е метки. «В 0:04 кот прыгает». Модель видит токены `<time>0.04</time>`, чередующиеся с токенами кадров.
- Динамический FPS. Сэмплирование на 1 FPS для медленной съёмки, 4+ FPS для действия. Пользователь или тренер выбирает; M-RoPE адаптируется.
- Оконное внимание в ViT. Пространственное внимание оконное (локальное внутри блоков) для пропускной способности; глобальное внимание каждые несколько слоёв.
- Явный формат вывода JSON. Обучена на данных с вызовами инструментов: «{\"tool\": \"click\", \"coords\": [380, 220]}». Готова к работе агентом из коробки.
- Масштабирование MRoPE-v2. Позиции масштабируются с максимальным размером входа, чтобы 10-минутное видео не выходило за пределы диапазона частот.

Бенчмарки: Qwen2.5-VL-72B превосходит GPT-4o на большинстве видеобенчмарков, сравнима с Gemini 2.0 на документах и устанавливает SOTA среди открытых моделей для локализации в GUI (ScreenSpot: точность 84% против 38% у GPT-4o).

### Qwen3-VL (ноябрь 2025)

Qwen3-VL — инкрементальное обновление, которое консолидирует, а не изобретает заново: более крупный бэкбон LLM (Qwen3-72B), расширенные обучающие данные, улучшенный OCR, более сильное рассуждение через «режим мышления» Qwen3. ViT и M-RoPE остаются прежними. Статья фокусируется на данных и улучшениях обучения, а не на архитектуре.

Вывод из этой линии: к 2025 году архитектура Qwen-VL стабилизировалась. Дополнительные поколения масштабируют вычисления и данные, а не примитивы.

### M-RoPE математически

Классический RoPE вращает запрос `q` размерности `d` на позицию `m`, используя парные координаты:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE разбивает скрытую размерность на три полосы. Пусть `d = 96`. Назначаем 32 измерения временно́й полосе, 32 — высоте, 32 — ширине. Каждая полоса вращается по своей собственной осевой позиции. Патч в позиции (t=5, h=10, w=20) получает вращения `R_t(5)`, `R_h(10)`, `R_w(20)`, применённые к трём его полосам.

Текстовые токены используют `t = text_index, h = 0, w = 0` (или нормализованный выбор), сохраняя совместимость. Видеокадры используют `t = frame_time, h = row, w = col`. Одиночные изображения используют `t = 0`.

Преимущество: одно позиционное кодирование обрабатывает текст, изображение и видео без ветвления кода или разных таблиц позиций.

### Логика сэмплирования с динамическим FPS

Учитывая видео длительностью `T` секунд и целевой бюджет токенов `B`:

1. Вычислить максимальный FPS, который можно себе позволить: `fps_max = B / (T * tokens_per_frame)`.
2. Выбрать целевой FPS из `{1, 2, 4, 8}`, удовлетворяющий `fps <= fps_max`.
3. Если движение интенсивное (эвристика по оптическому потоку или явный запрос пользователя), выбрать более высокий FPS. Если движение слабое — более низкий.
4. Сэмплировать равномерно на выбранном FPS; вставлять токены `<time>t</time>` между кадрами.

Qwen2.5-VL обучает эту логику неявно; на инференсе пользователь управляет ею через параметр `fps`. 60-секундная последовательность действий на 4 FPS с 81 токеном на кадр = 19440 токенов, что укладывается в контекст 32k.

### Структурированный вывод для агента

Обучение агента Qwen2.5-VL явно нацелено на структурированные вызовы инструментов:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

Разбор детерминирован: JSON.parse применяется к выводу модели. Сравните со свободным текстом «щёлкнуть в точке (1024, 512)», требующим регулярных выражений и обработки неоднозначности. Этот сдвиг — причина, по которой оценки Qwen2.5-VL на ScreenSpot выросли с 55% у Qwen2-VL до 84%.


## Применяем

`code/main.py` реализует:

- Вычисление позиций M-RoPE для упакованной последовательности, смешивающей текст, патчи изображений и видеокадры.
- Сэмплер с динамическим FPS: учитывая (длительность, бюджет, уровень движения), выбирает FPS и выдаёт временны́е метки кадров.
- Игрушечный парсер JSON-вывода Qwen2.5-VL, обрабатывающий ответы с вызовами инструментов с полями координат.

Запустите его, а затем почувствуйте разницу, когда замените фиксированный FPS на динамический FPS для пятиминутного видео.

## Упражнения

1. Вычислите вращения M-RoPE для патча в позиции (t=3, h=5, w=7) со скрытой размерностью 48 (16 на полосу, базовое theta 10000). Покажите углы вращения для первых трёх пар в каждой полосе.

2. 10-минутная запись с камеры видеонаблюдения на 1 FPS даёт сколько кадров? При разрешении 384 с 3x пулингом — сколько токенов всего? Справляется ли контекст Qwen2.5-VL по умолчанию в 32k?

3. Выберите FPS для 30-секундного теннисного розыгрыша, 30-секундного демо рецепта и 30-секундной записи UI-агента. Обоснуйте каждый выбор логикой динамического FPS.

4. Qwen2.5-VL полностью отказывается от Q-Former. Почему простой MLP работает в 2025 году, но не в 2023-м? (Подсказка: масштаб данных и качество энкодера.)

5. Разберите три выхода JSON-вызовов инструментов Qwen2.5-VL в словари Python. Что ломается на некорректном JSON и какую стратегию восстановления рекомендует руководство Qwen с практическими примерами?

## Ключевые термины

| Термин | Как его обычно называют | Что он означает на самом деле |
|------|-----------------|------------------------|
| M-RoPE | «Мультимодальный RoPE» | 3D вращающееся позиционное кодирование с временно́й полосой, полосой высоты и полосой ширины в скрытой размерности |
| Динамический FPS | «Умное сэмплирование» | Частота сэмплирования кадров, выбираемая для каждого видео на основе движения, длительности и бюджета токенов |
| Токен абсолютного времени | «Токен временно́й метки» | Токен `<time>t</time>`, чередующийся в последовательности, чтобы модель видела реальные секунды, а не индекс кадра |
| Оконное внимание | «Локальное внимание» | Пространственное самовнимание, ограниченное небольшими окнами ради скорости; глобальное внимание добавляется периодически |
| Структурированный вывод для агента | «Режим JSON» | Супервизия на обучающих данных, приучающая VLM выдавать пригодный для разбора JSON с координатами и именами инструментов |
| min_pixels / max_pixels | «Границы разрешения» | Настройки Qwen2.5-VL для каждого запроса, ограничивающие общее число пикселей и, следовательно, количество токенов |
| Локализация (grounding) | «Указать на объект» | Вывод координат ограничивающих рамок в виде текстовых токенов; используется начиная с Qwen-VL v1 |
