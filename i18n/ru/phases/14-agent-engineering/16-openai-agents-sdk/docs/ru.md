# OpenAI Agents SDK: передача полномочий, защитные ограничения, трассировка

> OpenAI Agents SDK — это лёгкий мультиагентный фреймворк, построенный поверх Responses API. Пять примитивов: Agent, Handoff, Guardrail, Session, Tracing. Передача полномочий (handoff) — это инструменты с именем `transfer_to_<agent>`. Защитные ограничения (guardrail) срабатывают на входе или на выходе. Трассировка включена по умолчанию.

**Тип:** Learn + Build
**Языки:** Python (stdlib)
**Предварительные требования:** Фаза 14 · 01 (Цикл агента), Фаза 14 · 06 (Использование инструментов)
**Время:** ~75 минут

## Цели обучения

- Назвать пять примитивов OpenAI Agents SDK.
- Объяснить передачу полномочий (handoff): почему она моделируется как инструмент, какое имя видит модель и как передаётся контекст.
- Различать входные, выходные и инструментальные защитные ограничения (guardrail); объяснить разницу между `run_in_parallel` и блокирующим режимом.
- Реализовать рантайм на стандартной библиотеке с передачей полномочий, защитными ограничениями и трассировкой в стиле спанов.

## Проблема

Агенты, которые не умеют аккуратно делегировать задачи, в итоге запихивают всё в один промпт. Агенты без защитных ограничений выдают персональные данные, контент, нарушающий политику, или зацикливаются навсегда. SDK от OpenAI формализует три примитива, которые делают мультиагентную работу управляемой.

## Концепция

### Пять примитивов

1. **Agent.** LLM + инструкции + инструменты + передача полномочий.
2. **Handoff.** Делегирование другому агенту. Представляется модели как инструмент с именем `transfer_to_<agent_name>`.
3. **Guardrail.** Проверка входа (только у первого агента), выхода (только у последнего агента) или вызова инструмента (для каждого функционального инструмента).
4. **Session.** Автоматическая история разговора между ходами.
5. **Tracing.** Встроенные спаны для генераций LLM, вызовов инструментов, передач полномочий, защитных ограничений.

### Передача полномочий как инструмент

Модель видит `transfer_to_billing_agent` в списке своих инструментов. Вызов этого инструмента сигнализирует рантайму:

1. Скопировать контекст разговора (или свернуть его через бета-функцию `nest_handoff_history`).
2. Инициализировать целевого агента его инструкциями.
3. Продолжить выполнение с целевым агентом.

Это паттерн супервизора (Урок 13 / Урок 28), доведённый до продукта.

### Защитные ограничения

Три разновидности:

- **Входные защитные ограничения.** Работают на входе первого агента. Отклоняют небезопасные или выходящие за рамки запросы до любого вызова LLM.
- **Выходные защитные ограничения.** Работают на выходе последнего агента. Ловят утечки персональных данных, нарушения политики, некорректно сформированные ответы.
- **Инструментальные защитные ограничения.** Работают для каждого функционального инструмента. Проверяют аргументы, права доступа, аудируют выполнение.

Режим:

- **Параллельный** (по умолчанию). LLM защитного ограничения работает параллельно с основной LLM. Меньшая хвостовая задержка. Если защитное ограничение сработало, работа основной LLM отбрасывается (трата токенов).
- **Блокирующий** (`run_in_parallel=False`). LLM защитного ограничения работает первой. Если оно сработало, токены на основной вызов не тратятся.

Срабатывание генерирует исключения `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered`.

### Трассировка

Включена по умолчанию. Каждая генерация LLM, вызов инструмента, передача полномочий и защитное ограничение создают спан. `OPENAI_AGENTS_DISABLE_TRACING=1` отключает это поведение. `add_trace_processor(processor)` направляет спаны в ваш собственный бэкенд параллельно с бэкендом OpenAI.

### Сессии

`Session` хранит историю разговора в бэкенде (SQLite, Redis, кастомный). `Runner.run(agent, input, session=session)` автоматически загружает и дополняет историю.

### Где этот паттерн даёт сбой

- **Дрейф передачи полномочий.** Агент A передаёт полномочия агенту B, который передаёт их обратно агенту A. Добавьте счётчик переходов.
- **Обход защитных ограничений.** Инструментальные защитные ограничения срабатывают только на функциональных инструментах; встроенные инструменты (чтение файлов, веб-запросы) нуждаются в отдельной политике.
- **Избыточная трассировка.** Чувствительный контент в спанах. Сочетайте с правилами захвата контента OTel GenAI (Урок 23) — храните данные снаружи, ссылайтесь по идентификатору.

```figure
ae-agent-handoff
```

## Реализация

`code/main.py` воспроизводит структуру SDK средствами стандартной библиотеки:

- `Agent`, `FunctionTool`, `Handoff` (как функциональный инструмент с семантикой передачи полномочий).
- `Runner` с входными, выходными и инструментальными защитными ограничениями, диспетчеризацией передачи полномочий и счётчиком переходов.
- Простой эмиттер спанов для демонстрации формы трассировки.
- Агент-диспетчер, который передаёт полномочия агенту по биллингу или поддержке в зависимости от запроса пользователя; на одном входе срабатывает защитное ограничение.

Запустите:

```
python3 code/main.py
```

Трассировка показывает две успешные передачи полномочий, одно срабатывание входного защитного ограничения и дерево спанов, повторяющее то, что выдаёт настоящий SDK.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Агент | «LLM + инструкции» | Тип Agent в SDK; владеет инструментами и механизмами передачи полномочий |
| Передача полномочий | «Передача» | Инструмент, который модель вызывает, чтобы делегировать задачу другому агенту |
| Защитное ограничение | «Проверка политики» | Проверка входа, выхода или вызова инструмента |
| Сигнальное срабатывание | «Срабатывание защитного ограничения» | Исключение, возникающее, когда защитное ограничение отклоняет данные |
| Сессия | «Хранилище истории» | Память разговора, сохраняемая между запусками |
| Трассировка | «Спаны» | Встроенная наблюдаемость для LLM, инструментов, передачи полномочий и защитных ограничений |
| Блокирующее защитное ограничение | «Последовательная проверка» | Защитное ограничение выполняется первым; при срабатывании токены не тратятся |
| Параллельное защитное ограничение | «Параллельная проверка» | Защитное ограничение выполняется параллельно; задержка ниже, но при срабатывании токены тратятся впустую |
