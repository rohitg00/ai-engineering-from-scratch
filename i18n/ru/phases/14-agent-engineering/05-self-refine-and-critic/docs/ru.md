# Self-Refine и CRITIC: итеративное улучшение вывода

> Self-Refine (Madaan et al., 2023) использует одну большую языковую модель (LLM) в трёх ролях — генератора, критика и редактора — в цикле. Средний прирост: +20 абсолютных пунктов на 7 задачах. CRITIC (Gou et al., 2023) усиливает этап обратной связи, направляя проверку через внешние инструменты. В 2026 году этот паттерн входит в каждый фреймворк как «оценщик — оптимизатор» (evaluator-optimizer) у Anthropic или цикл защитных ограничений (guardrail) в OpenAI Agents SDK.

**Тип:** Build
**Языки:** Python (stdlib)
**Предварительные требования:** Этап 14 · 01 (Цикл агента), этап 14 · 03 (Reflexion)
**Время:** ~60 минут

## Проблема

Агент выдаёт почти правильный ответ. Может, в строке кода синтаксическая ошибка. Может, сводка слишком длинная. Может, план упускает граничный случай. Хочется, чтобы агент раскритиковал собственный вывод, а затем исправил его.

Self-Refine показывает, что это работает с одной моделью, без обучающих данных, без RL. Но есть загвоздка: LLM плохо справляются с самопроверкой сложных фактов. CRITIC называет решение — направить шаг проверки через внешние инструменты (поиск, интерпретатор кода, калькулятор, запуск тестов).

Вместе эти две статьи определяют стандарт 2026 года для итеративного улучшения: сгенерировать, проверить (по возможности внешне), доработать, остановиться, когда верификатор проходит.

## Концепция

### Self-Refine (Madaan et al., NeurIPS 2023)

Одна LLM, три роли:

```
generate(task)            -> output_0
feedback(task, output_0)  -> critique_0
refine(task, output_0, critique_0, history) -> output_1
feedback(task, output_1)  -> critique_1
refine(task, output_1, critique_1, history) -> output_2
...
stop when feedback says "no issues" or budget exhausted.
```

Ключевая деталь: `refine` видит полную историю — все предыдущие выводы и критику — поэтому не повторяет ошибок. В статье проведена абляция: убрав историю, качество резко падает.

Главный результат: +20 абсолютных пунктов улучшения в среднем по 7 задачам (математика, код, акронимы, диалог), включая GPT-4. Без обучения, без внешних инструментов, одна модель.

### CRITIC (Gou et al., arXiv:2305.11738, v4, февраль 2024)

Слабость Self-Refine: на этапе обратной связи LLM оценивает саму себя. Для фактических утверждений это ненадёжно (галлюцинация часто выглядит убедительно для той же модели, которая её породила). CRITIC заменяет `feedback(task, output)` на `verify(task, output, tools)`, где `tools` включает:

- Поисковую систему для фактических утверждений.
- Интерпретатор кода для проверки корректности кода.
- Калькулятор для арифметики.
- Доменные верификаторы (юнит-тесты, проверка типов, линтеры).

Верификатор формирует структурированную критику, опирающуюся на результаты инструментов. Затем редактор формирует результат с учётом этой критики.

Главный результат: CRITIC превосходит Self-Refine на фактических задачах, потому что критика опирается на факты. На задачах без внешних верификаторов (творческое письмо, форматирование) CRITIC сводится к Self-Refine.

### Условие остановки

Два распространённых варианта:

1. **Верификатор проходит.** Внешний тест возвращает успех. Предпочтителен, когда доступен (юнит-тесты, проверка типов, утверждение защитного ограничения).
2. **Обратная связь не выдана.** Модель говорит «вывод в порядке». Дешевле, но ненадёжно; сочетайте с ограничением на максимум итераций.

Стандарт 2026 года: комбинировать их. «Останов, если верификатор проходит ИЛИ модель говорит «в порядке» И итераций >= 2 ИЛИ итераций >= max_iterations».

### Оценщик — оптимизатор (Evaluator-Optimizer; Anthropic, 2024)

В посте Anthropic от декабря 2024 года это названо одним из пяти паттернов рабочих процессов. Две роли:

- Оценщик: оценивает вывод и формирует критику.
- Оптимизатор: дорабатывает вывод с учётом критики.

Цикл продолжается, пока оценщик не примет результат. Это Self-Refine/CRITIC в формулировке Anthropic. Критически важная инженерная деталь, которую добавляет Anthropic: промпты оценщика и оптимизатора должны существенно различаться, чтобы модель не просто «штамповала одобрение».

### Защитные ограничения вывода в OpenAI Agents SDK

OpenAI Agents SDK реализует этот паттерн в виде защитных ограничений вывода (output guardrails). Защитное ограничение — это валидатор, который запускается на финальном выводе агента. Если оно срабатывает (выбрасывает `OutputGuardrailTripwireTriggered`), вывод отклоняется, и агент может повторить попытку. Защитные ограничения могут вызывать инструменты (в стиле CRITIC) или быть чистыми функциями (в стиле Self-Refine).

### Подводные камни 2026 года

- **Циклы «штамповки одобрения».** Одна и та же модель, выполняющая генерацию и критику с одинаковым стилем промпта, сходится к «выглядит нормально». Используйте структурно разные промпты или меньшую дешёвую модель для критики.
- **Чрезмерная доработка.** Каждый проход доработки добавляет задержку и токены. Закладывайте бюджет 1–3 прохода; после этого эскалируйте до проверки человеком.
- **CRITIC на тривиальных задачах.** Если внешнего верификатора нет, CRITIC вырождается в Self-Refine; не платите задержкой за верификатор-заглушку.

```figure
self-refine
```

## Реализация

`code/main.py` реализует Self-Refine и CRITIC на игрушечной задаче: составить короткий маркированный список по теме. Верификатор проверяет формат (3 пункта, каждый короче 60 символов). CRITIC добавляет внешний «проверщик фактов», штрафующий за известные галлюцинации.

Компоненты:

- `generate` — сценарный генератор.
- `feedback` — самокритика в стиле LLM.
- `verify_external` — опирающийся на факты верификатор в стиле CRITIC.
- `refine` — переписывает вывод с учётом истории.
- Условие остановки — верификатор проходит или достигнут максимум в 4 итерации.

Запустите:

```
python3 code/main.py
```

Сравните запуски Self-Refine и CRITIC. CRITIC ловит фактическую ошибку, которую пропустил Self-Refine, потому что внешний верификатор опирается на факты, которых нет у самокритики.

## Применение

«Оценщик — оптимизатор» в Anthropic — это тот же паттерн на языке, близком Claude. Защитные ограничения вывода в OpenAI Agents SDK имеют форму CRITIC и могут вызывать инструменты. LangGraph предоставляет узел рефлексии, устроенный по принципу Self-Refine. Gemini 2.5 Computer Use от Google добавляет пошаговый оценщик безопасности — вариант CRITIC: каждое действие проверяется перед фиксацией.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Self-Refine | «LLM, которая исправляет сама себя» | Цикл «генерация → обратная связь → доработка» в одной модели с сохранением истории |
| CRITIC | «Проверка с опорой на инструменты» | Замена обратной связи внешним верификатором: поиском, выполнением кода, калькулятором или тестами |
| Оценщик — оптимизатор (Evaluator-Optimizer) | «Паттерн рабочего процесса Anthropic» | Две роли: оценщик выставляет оценку, а оптимизатор вносит изменения; цикл повторяется до сходимости |
| Защитное ограничение вывода (output guardrail) | «Проверка постфактум» | Валидатор OpenAI Agents SDK, который запускается после того, как агент сформировал вывод |
| Этап проверки | «Этап критики» | Ключевое решение: опираться на внешние данные или на самооценку модели |
| История доработки | «Что модель уже пробовала» | Предыдущие выводы и критика добавляются в начало промпта доработки; без них качество резко падает |
| Цикл формального одобрения | «Ошибка самосогласия» | При том же промпте критик отвечает «всё хорошо»; исправляется структурно отличающимися промптами |
| Условие остановки | «Проверка сходимости» | Верификатор проходит проверку ИЛИ обратной связи нет И достигнут предел итераций; одного условия всегда недостаточно |
