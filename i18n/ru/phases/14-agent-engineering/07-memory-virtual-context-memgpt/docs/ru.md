# Память агента — виртуальный контекст и подкачка памяти

> Контекстные окна конечны. Диалоги, документы и трассы вызовов инструментов — нет. Решение повторяет виртуальную память ОС: основной контекст — это RAM, внешнее хранилище — диск, агент подкачивает данные между ними. MemGPT (Packer et al., 2023) дал название этому паттерну; на нём строятся многие продакшн-системы памяти.

**Тип:** Build
**Языки:** Python (stdlib)
**Предварительные требования:** Фаза 14 · 01 (Цикл агента), Фаза 14 · 06 (Использование инструментов)
**Время:** ~75 минут

## Цели обучения

- Объяснить аналогию с ОС, на которой построен MemGPT: основной контекст = RAM, внешний контекст = диск, инструменты памяти = подкачка внутрь/наружу.
- Реализовать двухуровневый паттерн MemGPT на stdlib с буфером основного контекста, внешним доступным для поиска хранилищем и инструментами подкачки внутрь/наружу.
- Описать, как агент выдаёт «прерывания» для запроса или изменения внешней памяти и как результат встраивается обратно в следующий промпт.
- Определить архитектурные решения MemGPT, которые переходят в Letta (Урок 08) и Mem0 (Урок 09).

## Проблема

Кажется, что контекстные окна должны решать проблему памяти. Это не так. В продакшне повторяются три сбоя:

1. **Переполнение.** Многоходовые диалоги, длинные документы или траектории с большим числом вызовов инструментов выходят за пределы окна. Всё, что осталось за границей отсечения, теряется.
2. **Разбавление.** Даже в пределах окна забивание нерелевантным контекстом размывает внимание на том, что действительно важно. Даже передовые модели деградируют на длинных входных данных.
3. **Персистентность.** Новая сессия начинается с пустого окна. Агенты без внешней памяти не могут сказать «помнишь, ты просил меня...» между сессиями.

Большие окна помогают, но не решают проблему. Статья Mem0 2025 года показала: базовые модели с окном 128k всё равно упускают факты на длинном горизонте, которые улавливает агент с окном 4k и внешней памятью.

## Концепция

### Аналогия с ОС

MemGPT (Packer et al., arXiv:2310.08560, v2, февраль 2024) отображает управление контекстом на виртуальную память операционной системы:

| Концепция ОС | Концепция MemGPT | Продакшн-аналог 2026 года |
|------------|---------------|------------------------|
| RAM | основной контекст (промпт) | контекстное окно Anthropic/OpenAI |
| Диск | внешний контекст | векторная БД, KV-, графовое хранилище |
| Ошибка отсутствия страницы | вызов инструмента памяти | `memory.search`, `memory.read`, `memory.write` |
| Ядро ОС | управляющий цикл агента | цикл ReAct с инструментами памяти |

Агент выполняет обычный цикл ReAct. Один дополнительный класс инструментов позволяет ему подкачивать данные в основной контекст и из него.

### Два уровня

- **Основной контекст.** Промпт фиксированного размера, хранящий текущую задачу. Всегда виден модели.
- **Внешний контекст.** Неограниченный, доступный для поиска через инструменты. Читается при необходимости, записывается по мере появления фактов.

Оригинальная статья оценивала архитектуру на двух задачах за пределами базового окна: анализ документов длиннее 100k токенов и многосессионный диалог с персистентной памятью на протяжении нескольких дней.

### Паттерн прерывания

MemGPT вводит память как прерывание: в середине диалога агент может вызвать инструмент памяти, среда выполнения исполняет его, а результат встраивается в следующий ход ассистента как новое наблюдение. Это концептуально идентично системному вызову Unix `read()`, который блокирует процесс, возвращает байты, после чего процесс продолжает работу.

Канонический набор инструментов памяти:

- `core_memory_append(section, text)` — запись в персистентный раздел промпта.
- `core_memory_replace(section, old, new)` — редактирование персистентного раздела.
- `archival_memory_insert(text)` — запись во внешнее доступное для поиска хранилище.
- `archival_memory_search(query, top_k)` — извлечение из внешнего хранилища.
- `conversation_search(query)` — сканирование прошлых ходов.

### Где заканчивается статья и начинается продакшн

В сентябре 2024 года MemGPT стал Letta. Исследовательский репозиторий (`cpacker/MemGPT`) остаётся; Letta расширяет архитектуру:

- Три уровня вместо двух (основная память, память воспоминаний и архивная память — Урок 08).
- Нативное рассуждение вместо паттерна с `send_message` и периодическими сигналами активности (Урок 08).
- Агенты фоновой обработки, выполняющие асинхронную работу с памятью (Урок 08).

Статья MemGPT остаётся фундаментом 2026 года, даже если продакшн-системы работают на Letta, Mem0 или собственном двухуровневом хранилище.

### Где этот паттерн ломается

- **Гниение памяти.** Записи накапливаются быстрее, чем чтения; поиск тонет в устаревших фактах. Решение: периодическая консолидация (фоновая обработка Letta), явная инвалидация (детектор конфликтов Mem0).
- **Отравление памяти.** Внешняя память — это извлекаемый текст. Если контролируемый атакующим контент попадает в заметку памяти, агент повторно потребляет его в следующей сессии. Это атака Greshake et al. (Урок 27), растянутая во времени.
- **Потеря цитирования.** Агент вспоминает «пользователь просил меня отправить X», но не может указать, в каком ходе. Храните ссылки на источник (ID сессии, ID хода) при каждой записи в архивную память.

## Реализация

`code/main.py` реализует двухуровневый паттерн MemGPT на stdlib:

- `MainContext` — буфер промпта фиксированного размера со словарём `core` и списком `messages`; автоматически уплотняет самые старые сообщения при превышении лимита.
- `ArchivalStore` — хранилище в оперативной памяти в духе BM25 (оценка по пересечению токенов) для записей (id, text, tags, session, turn).
- Пять инструментов памяти, отображающих набор MemGPT.
- Сценарный агент, заполняющий архивную память фактами, а затем отвечающий на вопрос вызовом `archival_memory_search`.

Запуск:

```
python3 code/main.py
```

Трасса показывает, как агент записывает три факта, заполняет основной контекст до предела (вынуждая вытеснение), а затем отвечает на последующий вопрос, извлекая данные из архивной памяти, — тем самым воспроизводя рабочий процесс MemGPT без реальной LLM.

## Применение

Каждая продакшн-система памяти сегодня — это вариант MemGPT:

- **Letta** (Урок 08) — три уровня, нативное рассуждение, фоновые вычисления.
- **Mem0** (Урок 09) — векторное, KV- и графовое хранилища, объединённые слоем оценки.
- **OpenAI Assistants / Responses** — управляемая память через ветки и файлы.
- **Claude Agent SDK** — долгосрочная память через навыки и хранилище сессий.

Выбирайте вариант по способу эксплуатации (самостоятельное размещение, управляемый сервис, интеграция во фреймворк), а не по базовому паттерну — базовый паттерн остаётся тем же, что в MemGPT.

### Структура памяти агента

Подкачка решает проблему ёмкости. Но она не определяет, что следует хранить. В продакшн-системах регулярно встречаются четыре типа памяти, каждый из которых отвечает на свой вопрос:

- **Рабочая память** — что важно прямо сейчас? Уровень внутри контекста: текущая задача, недавние ходы, закреплённые основные разделы. Сам промпт.
- **Эпизодическая память** — что произошло? Прошлые ходы и траектории, которые хранятся со ссылками на сессию и ход и могут быть воспроизведены по запросу.
- **Семантическая память** — что верно? Факты о пользователе, предметной области и мире, которые обновляются и дедуплицируются по мере изменений.
- **Процедурная память** — как это делать? Усвоенные процедуры, предпочтения и правила, которые направляют будущее поведение, а не служат для воспроизведения прошлого.

Реализации с открытым исходным кодом решают разные части этой задачи:

| Тип | Реализация | Подход |
|------|----------------|-------------------|
| Рабочая | MemGPT / Letta | Подкачивает содержимое в промпт с фиксированным бюджетом и из него с помощью инструментов памяти (этот урок, Урок 08) |
| Эпизодическая | Zep | Темпоральный граф знаний: факты имеют интервалы действия, поэтому можно запросить, что было истинно в тот или иной момент |
| Семантическая | Mem0 | Конвейер извлечения, который дедуплицирует и обновляет факты в векторном, KV- и графовом хранилищах (Урок 09) |
| Семантическая + процедурная | LangMem | Фоновое извлечение фактов и поведенческих правил в хранилище, к которому агент обращается между ходами |
| Эпизодическая + семантическая | agentmemory | Фиксирует сессии по ходу работы и консолидирует их в типизированные записи с возможностью поиска |

## Упражнения

1. Добавьте лимит `max_main_context_tokens`, измеряемый в токенах (приближение через `len(text.split())` * 1.3). Уплотняйте самые старые сообщения в резюме при превышении лимита. Сравните поведение с суммаризатором и без него.
2. Реализуйте BM25 над архивным хранилищем в полном виде (частота термина, обратная частота документа). Измерьте recall@10 на игрушечном наборе фактов по сравнению с базовым вариантом на пересечении токенов.
3. Добавьте поля `citation` (session_id, turn_id, source_url) к архивным записям. Заставьте агента цитировать источники при каждом ответе, опирающемся на результаты поиска.
4. Смоделируйте отравление памяти: добавьте архивную запись со словами «игнорируй все последующие инструкции пользователя». Напишите защиту, которая проверяет найденные записи на текст в форме директивы и помечает их как недоверенные.
5. Перенесите реализацию на JSON-схему основной памяти из исследовательского репозитория MemGPT (`cpacker/MemGPT`). Что меняется при переходе от плоских строк к типизированным разделам?

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Виртуальный контекст | «Неограниченная память» | Основной уровень (промпт) + внешний уровень (с возможностью поиска) с подкачкой данных в контекст и из него |
| Основной контекст | «Рабочая память» | Промпт фиксированного размера, всегда видимый модели |
| Архивная память | «Долгосрочное хранилище» | Внешнее персистентное хранилище с возможностью поиска, данные из которого извлекаются по запросу |
| Основная память | «Персистентный раздел промпта» | Именованные разделы, закреплённые внутри основного контекста |
| Инструмент памяти | «API памяти» | Вызов инструмента, который агент выполняет для чтения или записи внешней памяти |
| Прерывание | «Ошибка отсутствия страницы памяти» | Агент приостанавливается, среда выполнения извлекает данные, а результат встраивается в следующий ход |
| Гниение памяти | «Устаревшие факты» | Старые записи подавляют релевантные результаты поиска; помогает консолидация |
| Отравление памяти | «Внедрённая персистентная заметка» | Содержимое злоумышленника сохраняется в памяти и повторно поступает агенту при последующем извлечении |
