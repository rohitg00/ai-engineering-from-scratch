# Паттерны оркестрации: Supervisor, Swarm, Hierarchical

> Четыре паттерна оркестрации повторяются во фреймворках 2026 года: supervisor-worker, swarm / peer-to-peer, hierarchical, debate. Рекомендация Anthropic: «Дело в том, чтобы построить систему, подходящую именно под ваши задачи». Начинайте с простого; добавляйте топологию только тогда, когда одного агента и пяти паттернов рабочих процессов недостаточно.

**Тип:** Learn + Build**Языки:** Python (stdlib)**Предварительные требования:** Фаза 14 · 12 (паттерны рабочих процессов), Фаза 14 · 25 (мультиагентные дебаты)**Время:** ~60 минут
## Цели обучения

- Назвать четыре повторяющихся паттерна оркестрации и определить, для каких случаев подходит каждый.
- Описать рекомендацию LangChain 2026 года: Tool-call-based supervision против supervisor-библиотек.
- Объяснить правило Anthropic «постройте подходящую систему» и то, как оно определяет выбор топологии.
- Реализовать все четыре паттерна на stdlib поверх общей сценарной LLM (scripted LLM).

## Проблема

Команды хватаются за «мультиагентность», ещё не успев в ней по-настоящему нуждаться. Четыре паттерна повторяются во фреймворках; как только вы научитесь их называть, вы сможете выбрать подходящий — или вовсе обойтись без топологии.

## Концепция

### Supervisor-worker

- Центральная LLM-маршрутизатор направляет задачи специализированным агентам.
- Принимает решение: вернуться к себе, передать специалисту (handoff) или завершить работу.
- Специалисты не общаются друг с другом напрямую; вся маршрутизация проходит через supervisor.

Фреймворки: LangGraph `create_supervisor`, Anthropic orchestrator-workers, CrewAI Hierarchical Process.

**Рекомендация LangChain в 2026 году:** реализуйте supervision через прямые вызовы инструментов, а не через `create_supervisor`. Это даёт более точный контроль над проектированием контекста — вы сами решаете, что именно видит каждый специалист.

### Swarm / peer-to-peer

- Агенты передают задачи друг другу напрямую через общий набор инструментов.
- Центрального маршрутизатора нет.
- Задержка ниже, чем у Supervisor (меньше промежуточных переходов).
- Сложнее рассуждать о поведении системы (нет единой точки контроля).

Фреймворки: топология swarm в LangGraph, передача полномочий (handoffs) в OpenAI Agents SDK (когда любой агент может передать задачу любому другому).

### Hierarchical

- Supervisor, управляющие суб-Supervisor, которые управляют воркерами.
- Реализуется как вложенные подграфы в LangGraph; вложенные crews в CrewAI.
- Масштабируется на большие популяции агентов ценой операционной сложности.

Когда это нужно: когда бюджета контекста одного supervisor не хватает, чтобы вместить описания всех специалистов.

### Debate

- Параллельные инициаторы + итеративная взаимная критика (урок 25).
- По сути это не оркестрация, а скорее верификация, но во фреймворках это фигурирует как один из вариантов топологии.

### Автономные команды против детерминированных потоков

CrewAI формализует два режима развёртывания:

- **Flow** — для детерминированной событийно-ориентированной автоматизации (рекомендуемая отправная точка для production).
- **Crew** — для автономного ролевого взаимодействия.

Это ортогонально четырём паттернам выше, но соотносится с топологией: Flow обычно соответствует Supervisor или Hierarchical; Crew обычно соответствует Supervisor с LLM-маршрутизатором.

### Рекомендация Anthropic

«Успех в сфере LLM не в том, чтобы построить самую изощрённую систему. Он в том, чтобы построить систему, подходящую именно под ваши задачи».

Порядок принятия решения:

1. Один агент + паттерны рабочих процессов (урок 12) — начните отсюда.
2. Supervisor-worker — когда у вас 2–4 специалиста.
3. Swarm — когда задержка важнее ясности рассуждений.
4. Hierarchical — только когда не хватает бюджета контекста supervisor.
5. Debate — когда точность важнее стоимости.

### Где этот паттерн ломается

- **Мышление «сначала топология».** «Нам нужна мультиагентность» — раньше, чем определена задача, которую мультиагентность должна решить.
- **Прыгающие передачи в Swarm.** A -> B -> A -> B. Используйте счётчики переходов (hop counter).
- **Фальшивая иерархия.** Три уровня, потому что «enterprise»; а по факту — две команды. Сводите к реальной структуре.

## Реализация

`code/main.py` реализует все четыре паттерна на stdlib поверх сценарной LLM:

- `Supervisor` — центральный маршрутизатор.
- `Swarm` — peer-to-peer с прямыми передачами.
- `Hierarchical` — супервизоры над супервизорами.
- `Debate` — параллельные инициаторы + критика.

Каждый паттерн обрабатывает одну и ту же задачу с тремя интентами (refund / bug / sales). Форма трасс различается.

Запустите:

```
python3 code/main.py
```

Вывод: трасса по каждому паттерну + количество операций. У Supervisor — самая чистая трасса; у Swarm — самая короткая; у Hierarchical — самая глубокая; у Debate — самая дорогая.

## Применение

- **LangGraph** — для Supervisor и Hierarchical (вложенных подграфов).
- **OpenAI Agents SDK** — для передачи полномочий в виде инструментов (handoffs-as-tools), по форме близкого к Supervisor.
- **CrewAI Flow** — для детерминированного production.
- **Собственное решение** — для Debate или когда нужен точный контроль.

## Упражнения

1. Преобразуйте Supervisor-worker в Swarm, убрав маршрутизатор. Что ломается? Что становится лучше?
2. Добавьте в Swarm счётчик переходов: отказывайте после 3 передач. Ловит ли он прыгающие передачи вида A->B->A?
3. Постройте двухуровневую Hierarchical-систему для домена из 12 специалистов. Где бюджет контекста перестаёт справляться без вложенности?
4. Профилируйте все четыре паттерна на нагрузке, приближённой к production. Какой паттерн выигрывает по какой метрике (задержка, стоимость, точность, отлаживаемость)?
5. Прочитайте статью Anthropic «Building Effective Agents». Сопоставьте каждый ваш production-процесс с одним из четырёх паттернов. Есть ли такие, что не сопоставляются однозначно?

## Ключевые термины

| Термин | Как это называют | Что это означает на самом деле |
|------|----------------|------------------------|
| Supervisor-worker | «Маршрутизатор + специалисты» | Центральная LLM направляет задачи специалистам; они не общаются друг с другом напрямую |
| Swarm | «Одноранговая сеть» | Прямая передача задач через общие инструменты; центрального маршрутизатора нет |
| Hierarchical | «Супервизоры над супервизорами» | Вложенные подграфы для больших популяций агентов |
| Debate | «Инициатор + критика» | Параллельные инициаторы и взаимная критика (урок 25) |
| Управление через вызовы инструментов | «Супервизор без библиотеки» | Супервизор реализуется через прямые вызовы инструментов, что позволяет контролировать контекст |
| Crew | «Автономная команда» | Режим ролевого взаимодействия в CrewAI |
| Flow | «Детерминированный рабочий процесс» | Событийно-ориентированный production-режим в CrewAI |
