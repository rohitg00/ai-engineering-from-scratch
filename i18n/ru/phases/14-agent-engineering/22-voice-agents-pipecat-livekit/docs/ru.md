# Голосовые агенты: Pipecat и LiveKit

> Голосовые агенты — полноценная продакшен-категория в 2026 году. Pipecat даёт вам конвейер на Python, основанный на фреймах (VAD → STT → LLM → TTS → транспорт). LiveKit Agents связывает модели ИИ с пользователями через WebRTC. Продакшен-цели по сквозной задержке для премиальных стеков — 450–600 мс.

**Тип:** Learn
**Языки:** Python (stdlib)
**Предварительные требования:** Этап 14 · 01 (Цикл агента), этап 14 · 12 (Паттерны рабочих процессов)
**Время:** ~60 минут

## Цели обучения

- Опишите основанный на фреймах конвейер Pipecat: DOWNSTREAM (источник→приёмник) и UPSTREAM (управление).
- Назовите канонические этапы голосового конвейера и какие транспорты поддерживает Pipecat.
- Объясните два класса голосовых агентов LiveKit Agents (MultimodalAgent, VoicePipelineAgent) и когда какой подходит.
- Обобщите продакшен-ожидания по задержке в 2026 году и то, как они определяют архитектурные решения.

## Проблема

Голосовые агенты — это не текстовый цикл с прикрученным TTS. Бюджеты задержки безжалостны (~600 мс), частичное аудио — норма по умолчанию, определение конца хода выполняет отдельная модель, а транспорты варьируются от телефонии по SIP до WebRTC. Либо вы строите конвейер на фреймах (Pipecat), либо опираетесь на платформу (LiveKit).

## Концепция

### Pipecat (pipecat-ai/pipecat)

- Фреймворк для конвейеров на Python, основанный на фреймах.
- Цепочка `Frame` → `FrameProcessor`.
- Два направления потока:
  - **DOWNSTREAM** — источник → приёмник (аудио на входе, TTS на выходе).
  - **UPSTREAM** — обратная связь и управление (отмена, метрики, перебивание пользователем).
- `PipelineTask` управляет жизненным циклом с помощью событий (`on_pipeline_started`, `on_pipeline_finished`, `on_idle_timeout`) и наблюдателей для метрик/трассировки/RTVI.

Типичный конвейер:

```
VAD (Silero) → STT → LLM (context alternates user/assistant) → TTS → transport
```

Транспорты: Daily, LiveKit, SmallWebRTCTransport, FastAPI WebSocket, WhatsApp.

Pipecat Flows добавляет структурированные диалоги (конечные автоматы). Pipecat Cloud — управляемый рантайм.

### LiveKit Agents (livekit/agents)

- Связывает модели ИИ с пользователями через WebRTC.
- Ключевые концепции: `Agent`, `AgentSession`, `entrypoint`, `AgentServer`.
- Два класса голосовых агентов:
  - **MultimodalAgent** — прямое аудио через OpenAI Realtime или аналог.
  - **VoicePipelineAgent** — каскад STT → LLM → TTS; даёт контроль на уровне текста.
- Семантическое определение конца хода через модель-трансформер.
- Нативная интеграция с MCP.
- Телефония через SIP.
- 50+ моделей без ключей API через LiveKit Inference; ещё 200+ через плагины.

### Коммерческие платформы

Vapi (~450–600 мс на оптимизированном премиальном стеке) и Retell (~600 мс сквозь весь путь на 180 тестовых звонках) строятся поверх этого. Выбирайте платформу, если хотите управляемый голосовой стек без команды WebRTC.

### Где этот паттерн даёт сбой

- **Нет обработки перебивания.** Пользователь перебивает — агент продолжает говорить. Для этого нужны UPSTREAM-фреймы отмены в Pipecat или аналогичный механизм в LiveKit.
- **Игнорируется уверенность STT.** Транскрипты с низкой уверенностью передаются в LLM как истина в последней инстанции. Фильтруйте по уверенности или запрашивайте подтверждение.
- **Обрыв TTS на середине фразы.** Когда конвейер отменяет высказывание на середине, TTS должен об этом узнать или обрезать аудио.
- **Игнорируется бюджет задержки.** Каждый компонент добавляет 50–200 мс. Просуммируйте вашу цепочку до релиза.

### Типичные задержки 2026 года

- VAD: 20–60 мс
- Частичный STT: 100–250 мс
- Первый токен LLM: 150–400 мс
- Первое аудио TTS: 100–200 мс
- RTT транспорта: 30–80 мс

Сквозная задержка 450–600 мс — это премиум. 800–1200 мс — обычное дело. Всё, что больше 1500 мс, ощущается как поломка.

## Реализация

`code/main.py` — игрушечный конвейер на фреймах с:

- типами `Frame` (audio, transcript, text, tts_audio, control);
- интерфейсом `Processor` с `process(frame)`;
- пятиэтапным конвейером (VAD → STT → LLM → TTS → транспорт) в виде сценарных процессоров;
- UPSTREAM-фреймом отмены для демонстрации перебивания.

Запустите:

```
python3 code/main.py
```

Трассировка показывает нормальный поток и отмену при перебивании, которая останавливает TTS на середине высказывания.

## Применение

- **Pipecat** для полного контроля — собственные процессоры, ориентация на Python, подключаемые провайдеры.
- **LiveKit Agents** для развёртываний с приоритетом WebRTC и телефонии.
- **Vapi / Retell** для хостинговых голосовых агентов без команды WebRTC.
- **OpenAI Realtime / Gemini Live** для прямого аудио на входе/выходе (MultimodalAgent).

## Ключевые термины

| Термин | Как обычно говорят | Что это означает |
|------|----------------|------------------------|
| Frame | «Событие» | Типизированная единица данных в конвейере (аудио, транскрипт, текст, управление) |
| Processor | «Этап конвейера» | Обработчик с process(frame) |
| DOWNSTREAM | «Прямой поток» | От источника к приёмнику: аудио на входе, речь на выходе |
| UPSTREAM | «Поток обратной связи» | Управление: отмена, метрики, перебивание |
| VAD | «Обнаружение голосовой активности» | Определяет, когда пользователь говорит |
| Семантическое определение конца хода | «Умное определение конца хода» | Решение модели о том, что пользователь закончил говорить |
| MultimodalAgent | «Агент с прямой обработкой аудио» | Аудио на входе и выходе, без промежуточного текста |
| VoicePipelineAgent | «Каскадный агент» | STT + LLM + TTS; управление на уровне текста |
