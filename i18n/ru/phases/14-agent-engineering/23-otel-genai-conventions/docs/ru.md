# Семантические соглашения OpenTelemetry GenAI

> Рабочая группа GenAI SIG проекта OpenTelemetry (созданная в апреле 2024 года) определяет стандартную схему телеметрии агентов. Названия спанов, атрибуты и правила захвата контента унифицируются между поставщиками, поэтому трассировки агентов имеют один и тот же смысл в Datadog, Grafana, Jaeger и Honeycomb.

**Тип:** Learn + Build
**Языки:** Python (стандартная библиотека)
**Предварительные требования:** Этап 14 · 13 (LangGraph), этап 14 · 24 (Платформы наблюдаемости)
**Время:** ~60 минут

## Цели обучения

- Назвать категории спанов GenAI: модель/клиент, агент, инструмент.
- Различать спаны `invoke_agent` видов CLIENT и INTERNAL и объяснять, когда применяется каждый из них.
- Перечислить верхнеуровневые атрибуты GenAI: имя провайдера, модель запроса, идентификатор источника данных.
- Объяснить контракт захвата контента: явное включение, `OTEL_SEMCONV_STABILITY_OPT_IN` и рекомендацию использовать внешние ссылки.

## Проблема

Каждый поставщик придумывает собственные названия спанов. В итоге команды эксплуатации строят отдельные дашборды для каждого фреймворка. GenAI SIG проекта OpenTelemetry решает эту проблему, определяя единый стандарт, на который ориентируется вся экосистема.

## Концепция

### Категории спанов

1. **Спаны модели/клиента.** Охватывают непосредственные вызовы LLM. Их создают SDK провайдеров (Anthropic, OpenAI, Bedrock) и адаптеры моделей во фреймворках.
2. **Спаны агента.** `create_agent` (при создании агента) и `invoke_agent` (при его запуске).
3. **Спаны инструментов.** По одному на каждый вызов инструмента; связаны со спаном агента отношением «родитель — потомок».

### Именование спана агента

- Имя спана: `invoke_agent {gen_ai.agent.name}`, если агенту присвоено имя; иначе — `invoke_agent`.
- Вид спана:
  - **CLIENT** — для удалённых сервисов агентов (OpenAI Assistants API, Bedrock Agents).
  - **INTERNAL** — для внутрипроцессных агентных фреймворков (LangChain, CrewAI, локальный ReAct).

### Ключевые атрибуты

- `gen_ai.provider.name` — `anthropic`, `openai`, `aws.bedrock`, `google.vertex`.
- `gen_ai.request.model` — идентификатор модели.
- `gen_ai.response.model` — фактически выбранная модель (может отличаться от запрошенной из-за маршрутизации).
- `gen_ai.agent.name` — идентификатор агента.
- `gen_ai.operation.name` — `chat`, `completion`, `invoke_agent`, `tool_call`.
- `gen_ai.data_source.id` — для RAG: какой корпус или хранилище использовались.

Для Anthropic, Azure AI Inference, AWS Bedrock и OpenAI существуют отдельные технологические соглашения.

### Захват контента

Правило по умолчанию: инструментации НЕ СЛЕДУЕТ захватывать входные и выходные данные без явного разрешения. Захват можно явно включить для следующих атрибутов:

- `gen_ai.system_instructions`
- `gen_ai.input.messages`
- `gen_ai.output.messages`

Рекомендуемый подход для промышленной эксплуатации: храните контент во внешнем хранилище (S3 или вашем хранилище журналов), а в спанах записывайте ссылки на него (идентификаторы-указатели, а не сам текст). Так защита от отравления контента из Урока 27 встраивается в наблюдаемость.

### Стабильность

По состоянию на март 2026 года большинство соглашений остаются экспериментальными. Чтобы явно включить стабильную предварительную версию, задайте:

```
OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental
```

Datadog v1.37+ напрямую преобразует атрибуты GenAI в собственную схему LLM Observability. Другие системы (Grafana, Honeycomb, Jaeger) поддерживают исходные атрибуты.

### Где этот подход даёт сбой

- **Захват полных промптов в спанах.** PII, секреты и данные клиентов попадают в трассировки, доступные команде эксплуатации. Храните их во внешнем хранилище.
- **Отсутствие `gen_ai.provider.name`.** Дашборды для нескольких провайдеров перестают работать, если не указана принадлежность данных.
- **Спаны без родительских связей.** Спаны инструментов остаются без родителя. Всегда передавайте контекст.
- **Не задан явный выбор версии соглашений.** При обновлении системы хранения телеметрии ваши атрибуты могут быть переименованы.

## Реализация

`code/main.py` реализует эмиттер спанов на стандартной библиотеке Python в соответствии с соглашениями GenAI:

- `Span` со схемой атрибутов GenAI.
- `Tracer` с `start_span` и вложенными контекстами.
- Сценарий запуска агента, который создаёт спаны `create_agent`, `invoke_agent` (INTERNAL), отдельные спаны для каждого инструмента и спаны `chat` для вызовов LLM.
- Режим захвата контента, который хранит промпты во внешнем хранилище и записывает их идентификаторы в спаны.

Запустите:

```
python3 code/main.py
```

Результат: дерево спанов со всеми обязательными атрибутами GenAI и «внешнее хранилище» с явно включёнными ссылками на контент.

## Применение

- **Datadog LLM Observability** (v1.37+) напрямую преобразует атрибуты.
- **Langfuse / Phoenix / Opik** (Урок 24) — автоматически инструментируют экосистему.
- **Jaeger / Honeycomb / Grafana Tempo** — исходные трассировки OTel; стройте дашборды на основе атрибутов GenAI.
- **Самостоятельное размещение** — запустите OTel Collector с процессором GenAI.

## Поставка

`outputs/skill-otel-genai.md` подключает спаны OTel GenAI к существующему агенту, используя настройки захвата контента по умолчанию и хранение внешних ссылок.

## Упражнения

1. Инструментируйте свой цикл ReAct из Урока 01 с помощью `invoke_agent` (INTERNAL) и отдельных спанов для каждого инструмента. Отправьте данные в экземпляр Jaeger.
2. Добавьте захват контента в режиме «только ссылки»: сохраняйте промпты в SQLite, а в атрибутах спанов — только идентификаторы строк.
3. Прочитайте спецификацию `gen_ai.data_source.id`. Подключите этот атрибут к поиску Mem0 из Урока 09.
4. Установите `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` и убедитесь, что коллектор не переименовывает ваши атрибуты.
5. Постройте дашборд «Какие ошибки инструментов коррелируют с какими моделями», используя только атрибуты GenAI.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| GenAI SIG | «Группа OpenTelemetry по GenAI» | Рабочая группа OTel, определяющая схему |
| invoke_agent | «Спан агента» | Имя спана, представляющего запуск агента |
| Спан CLIENT | «Удалённый вызов» | Спан вызова удалённого сервиса агентов |
| Спан INTERNAL | «Внутри процесса» | Спан внутрипроцессного запуска агента |
| gen_ai.provider.name | «Провайдер» | anthropic / openai / aws.bedrock / google.vertex |
| gen_ai.data_source.id | «Источник RAG» | Корпус или хранилище, в котором найден результат поиска |
| Захват контента | «Журналирование промптов» | Явно включаемый захват сообщений; в промышленной среде храните их во внешнем хранилище |
| Явный выбор версии соглашений | «Режим предварительной версии» | Переменная окружения, фиксирующая экспериментальные соглашения |
