# Модель акторов для агентов — асинхронные сообщения и типизированные среды выполнения

> Агенты как акторы: асинхронный обмен сообщениями, событийно-управляемые обработчики, изоляция сбоев, естественная конкурентность. AutoGen v0.4 (Microsoft Research, январь 2025) перестроил оркестрацию агентов вокруг этой модели; сейчас фреймворк находится в режиме поддержки, а его преемником для промышленного применения стал Microsoft Agent Framework (публичное превью, октябрь 2025).

**Тип:** Learn + Build**Языки:** Python (stdlib)**Предварительные требования:** Фаза 14 · 01 (цикл агента), Фаза 14 · 12 (паттерны рабочих процессов)**Время:** ~75 минут
## Цели обучения

- Описать модель акторов: агенты как акторы, сообщения как единственный способ межпроцессного взаимодействия (IPC), изоляция сбоев на уровне каждого актора.
- Назвать три уровня API AutoGen v0.4 — Core, AgentChat, Extensions — и для чего нужен каждый из них.
- Объяснить, почему разделение доставки сообщений и их обработки даёт изоляцию сбоев и естественную конкурентность.
- Реализовать среду выполнения акторов на Python (только stdlib) и перенести на неё процесс код-ревью с двумя агентами.

## Проблема

Большинство агентных фреймворков синхронны: один агент производит, другой потребляет — всё в рамках стека вызовов. Сбои обрушивают весь стек. Конкурентность добавляется задним числом. Распределённость требует переписывания.

Ответ AutoGen v0.4 — модель акторов. Каждый агент — это актор (actor) с приватным почтовым ящиком. Сообщения — единственный способ взаимодействия. Среда выполнения (runtime) отделяет доставку от обработки. Сбои изолируются в пределах одного актора. Конкурентность встроена по умолчанию. Распределённость — это просто другой транспорт.

## Концепция

### Акторы

У актора есть:

- приватное состояние (никогда не изменяется напрямую извне);
- почтовый ящик (очередь сообщений);
- обработчик: `receive(message) -> effects`, где эффектом может быть «ответить», «отправить сообщение другому актору», «породить новый актор», «обновить состояние», «остановить себя».

Два актора не могут разделять память. Они могут только обмениваться сообщениями.

### Три уровня API

В AutoGen v0.4 интерфейс разделён на три уровня:

1. **Core.** Низкоуровневый фреймворк акторов. `AgentRuntime`, `Agent`, `Message`, `Topic`. Асинхронный обмен сообщениями, событийная модель.
2. **AgentChat.** Высокоуровневый API, ориентированный на задачи (замена ConversableAgent из v0.2). `AssistantAgent`, `UserProxyAgent`, `RoundRobinGroupChat`, `SelectorGroupChat`.
3. **Extensions.** Интеграции — OpenAI, Anthropic, Azure, инструменты, память.

### Почему важно разделение

В модели v0.2 вызов `agent_a.chat(agent_b)` синхронно блокирует agent_a, пока agent_b не вернёт результат. В v0.4 вызов `send(agent_b, msg)` помещает сообщение в почтовый ящик agent_b и сразу возвращает управление. Среда выполнения доставит сообщение позже. Три следствия:

- **Изоляция сбоев.** Падение агента B не обрушивает агента A — среда выполнения перехватывает сбой в обработчике B и решает, что делать (записать в лог, повторить, отправить в dead-letter).
- **Естественная конкурентность.** Одновременно в полёте может находиться множество сообщений; акторы обрабатывают свой почтовый ящик конкурентно.
- **Готовность к распределению.** Абстракция «почтовый ящик + транспорт» одна и та же независимо от того, находится ли актор в том же процессе или на другом хосте.

### Топологии

- **RoundRobinGroupChat.** Агенты ходят по очереди в фиксированной ротации.
- **SelectorGroupChat.** Агент-селектор выбирает, кто ходит следующим, на основе контекста разговора.
- **Magentic-One.** Эталонная мультиагентная команда для веб-браузинга, выполнения кода и работы с файлами. Построена на AgentChat.

### Наблюдаемость

Поддержка OpenTelemetry встроена. Каждое сообщение порождает span; вызовы инструментов несут атрибуты `gen_ai.*` согласно семантическим соглашениям OTel GenAI 2026 года (Урок 23).

### Статус: режим поддержки

Начало 2026 года: AutoGen v0.7.x стабилен для исследований и прототипирования. Microsoft переключила активную разработку на Microsoft Agent Framework — преемника AutoGen для промышленного применения (публичное превью с 1 октября 2025 года; релиз 1.0 GA был запланирован на конец первого квартала 2026 года). Паттерны AutoGen переносятся без проблем — модель акторов остаётся устойчивой идеей.

## Реализация

`code/main.py` реализует среду выполнения акторов на stdlib:

- `Message` — типизированный payload с полями `sender`, `recipient`, `topic`, `body`.
- `Actor` — абстрактный класс с `receive(message, runtime)`.
- `Runtime` — цикл событий с общей очередью, доставкой и изоляцией сбоев.
- Демонстрация с двумя акторами: `ReviewerAgent` рецензирует код, `ChecklistAgent` прогоняет чек-лист; они обмениваются сообщениями до достижения консенсуса.

Запустите:

```
python3 code/main.py
```

Трассировка показывает доставку сообщений, смоделированный сбой в одном акторе, который не обрушивает другой, и схождение к общему вердикту.

## Практика

- **AutoGen v0.4/v0.7** (режим поддержки) — стабилен для исследований, прототипирования, мультиагентных паттернов.
- **Microsoft Agent Framework** — преемник для промышленного применения (публичное превью, октябрь 2025); те же идеи модели акторов в обновлённом API.
- **LangGraph swarm topology** (Урок 13) — похожий паттерн через передачу управления с использованием общих инструментов.
- **Custom actor runtime** — собственная среда выполнения, когда нужен специфический транспорт (NATS, RabbitMQ, gRPC).

## Упражнения

1. Добавьте очередь dead-letter: когда обработчик выбрасывает исключение, откладывайте проблемное сообщение для проверки человеком. Как часто DLQ срабатывает в вашем игрушечном примере?
2. Реализуйте `SelectorGroupChat`: актор-селектор выбирает, кто обрабатывает следующее сообщение, на основе состояния разговора.
3. Добавьте распределённый транспорт: замените внутрипроцессную очередь на сервер JSON-по-HTTP, чтобы акторы могли работать в отдельных процессах.
4. Подключите OTel span на каждое сообщение (или заглушку no-op). Эмитируйте `gen_ai.agent.name`, `gen_ai.operation.name` согласно Уроку 23.
5. Прочитайте пост об архитектуре AutoGen v0.4. Перенесите свой игрушечный пример на реальный API `autogen_core`. Что вы пропустили из того, что важно в продакшене?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| Actor | «Агент» | Приватное состояние + почтовый ящик + обработчик; без общей памяти |
| Message | «Событие» | Типизированный payload; единственный способ взаимодействия акторов |
| Inbox | «Почтовый ящик» (Mailbox) | Очередь ожидающих сообщений для каждого актора |
| Runtime | «Хост агентов» | Цикл событий, который маршрутизирует сообщения и изолирует сбои |
| Topic | «Канал» | Именованный маршрут publish-subscribe между акторами |
| Fault isolation | «Пусть падает» (Let it crash) | Сбой одного актора не обрушивает остальные |
| RoundRobinGroupChat | «Команда с фиксированной ротацией» | Агенты ходят по очереди в заданном порядке |
| SelectorGroupChat | «Команда с маршрутизацией по контексту» | Селектор выбирает, кто ходит следующим |
| Magentic-One | «Эталонная команда» | Мультиагентная группа для веба, кода и файлов |
