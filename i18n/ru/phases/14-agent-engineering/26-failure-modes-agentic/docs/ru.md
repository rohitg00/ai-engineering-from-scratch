# Типы сбоев: почему агенты ломаются

> MASFT (Berkeley, 2025) каталогизирует 14 типов сбоев мультиагентных систем в 3 категориях. Таксономия Microsoft показывает, как существующие сбои ИИ усиливаются в агентных средах. Отраслевые полевые данные сходятся на пяти повторяющихся типах сбоев: галлюцинированные действия, разрастание объёма задачи, каскадные ошибки, потеря контекста, неправильное использование инструментов.

**Тип:** Learn + Build
**Языки:** Python (стандартная библиотека)
**Предварительные требования:** Этап 14 · 05 (Self-Refine и CRITIC), Этап 14 · 24 (Наблюдаемость)
**Время:** ~60 минут

## Цели обучения

- Назвать три категории сбоев MASFT и минимум по четыре конкретных типа в каждой.
- Объяснить, почему агентные сбои усиливают существующие типы сбоев ИИ (предвзятость, галлюцинации).
- Описать пять типов сбоев, регулярно встречающихся в индустрии, и способы их смягчения.
- Реализовать детектор на стандартной библиотеке, который размечает трассы агента метками типов сбоев.

## Проблема

Команды поставляют агентов, которые работают на 90% трасс. 10% сбоев — не случайный шум: они укладываются в небольшое число повторяющихся категорий. Как только вы можете их назвать, вы можете отслеживать их и исправлять.

## Концепция

### MASFT (Berkeley, arXiv:2503.13657)

Таксономия сбоев мультиагентных систем. 14 типов сбоев, сгруппированных в 3 категории. Межаннотаторская каппа Коэна 0,88 — категории надёжно различимы.

Основной тезис: сбои — это фундаментальные недостатки архитектуры мультиагентных систем, а не ограничения LLM, которые можно исправить более качественными базовыми моделями.

### Таксономия Microsoft типов сбоев в агентных системах ИИ

- Существующие сбои ИИ (предвзятость, галлюцинации, утечка данных) усиливаются в агентных средах.
- Новые сбои возникают из автономности: непреднамеренные действия в масштабе, неправильное использование инструментов, дрейф целей.
- Этот аналитический документ — реестр рисков для агентных продуктов.

### Characterizing Faults in Agentic AI (arXiv:2603.06847)

- Сбои возникают из оркестрации, эволюции внутреннего состояния и взаимодействия со средой.
- Это не просто «плохой код» или «плохой вывод модели».

### LLM Agent Hallucinations Survey (arXiv:2509.18970)

Два основных проявления:

1. **Отклонение от следования инструкциям (Instruction-following Deviation)** — агент не следует системному промпту.
2. **Неправильное использование долгосрочного контекста (Long-range Contextual Misuse)** — агент забывает или неверно применяет контекст из более ранних шагов.

Ошибки подзадач (Sub-intention errors): пропуск (пропущенный шаг), избыточность (повторённый шаг), нарушение порядка (шаги в неверном порядке).

### Пять типов сбоев, регулярно встречающихся в индустрии

Полевые исследования Arize, Galileo, NimbleBrain за 2024–2026 годы сходятся на следующем:

1. **Галлюцинированные действия (Hallucinated actions).** Агент вызывает несуществующий инструмент или выдумывает аргументы.
2. **Разрастание объёма задачи (Scope creep).** Агент расширяет задачу за пределы запроса пользователя (создаёт лишние PR, отправляет лишние письма).
3. **Каскадные ошибки (Cascading errors).** Один неверный вызов запускает цепочку последствий. Галлюцинация фантомного SKU запускает четыре вызова API — инцидент, затрагивающий несколько систем.
4. **Потеря контекста (Context loss).** В долгих задачах теряются ограничения, заданные на ранних шагах.
5. **Неправильное использование инструментов (Tool misuse).** Вызывает нужный инструмент с неверными аргументами либо вообще не тот инструмент.

Каскадирование — самое опасное. Агенты не могут отличить «я не справился» от «задача невыполнима» и часто галлюцинируют сообщение об успехе при ошибках 400, чтобы закрыть цикл.

### Смягчение: проверочные барьеры на каждом шаге

Автоматизированные проверочные барьеры на каждом шаге цепочки рассуждений, сверяющие фактическую обоснованность с состоянием среды. Конкретно:

- Классификатор безопасности на каждом шаге (Урок 21).
- Валидация аргументов вызова инструмента (Урок 06).
- Перекрёстная проверка полученного контента на соответствие известным фактам (Урок 05, CRITIC).
- Обнаружение галлюцинации успеха повторной проверкой состояния (файл действительно создан?).

### Где мониторинг сбоев даёт сбой

- **Разметка только крашей.** Большинство сбоев агента дают вывод, который выглядит валидным. Нужны проверки на уровне содержимого.
- **Отсутствие базовой линии.** Для обнаружения дрейфа нужен последний известный исправный результат; без него нельзя сказать «становится хуже».
- **Избыточные оповещения.** Каждый сбой порождает пейджинг. Группируйте и ограничивайте частоту.

```figure
failure-cascade
```

## Реализация

`code/main.py` реализует теггер типов сбоев на стандартной библиотеке:

- Синтетический набор трасс, охватывающий пять типов сбоев.
- Функции-детекторы для каждого типа (сигнатурные паттерны в вызовах инструментов, выводах и повторяющихся действиях).
- Теггер, размечающий каждую трассу и выводящий распределение по типам сбоев.

Запустите:

```
python3 code/main.py
```

Вывод: метки для каждой трассы + агрегированное распределение — дешёвое воспроизведение того, что показывает кластеризация трасс в Phoenix.

## Применение

- **Phoenix** для кластеризации дрейфа в продакшене (Урок 24).
- **Langfuse** для воспроизведения сессий и аннотирования.
- **Собственное решение** для доменных сигнатур, которые ваша платформа наблюдаемости не может обнаружить.

## Поставка

`outputs/skill-failure-detector.md` генерирует детекторы типов сбоев, адаптированные под ваш домен и подключённые к хранилищу трасс.

## Упражнения

1. Добавьте детектор «галлюцинации успеха»: агент возвращает успех, но целевое состояние не изменилось.
2. Разметьте 100 реальных трасс из продукта, который вы создали. Какой тип сбоя преобладает? Сколько стоит его исправление?
3. Реализуйте метрику «радиус каскада»: при сбое на шаге N сколько последующих шагов он затронул?
4. Изучите 14 типов сбоев MASFT. Выберите три, применимых к вашему продукту. Напишите детекторы.
5. Подключите один детектор к CI-задаче: проваливайте сборку, если >=5% трасс размечены каким-либо типом сбоя.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| MASFT | «Таксономия сбоев мультиагентных систем» | Разработанная в Berkeley классификация из 14 типов сбоев |
| Каскадная ошибка | «Волнообразный сбой» | Одна ранняя ошибка распространяется на N шагов |
| Потеря контекста | «Забыл ограничение» | На длинном горизонте агент упускает факты из ранних шагов |
| Неправильное использование инструмента | «Не тот инструмент или не те аргументы» | Допустимый вызов, но неверное применение |
| Галлюцинация успеха | «Поддельное завершение» | Агент заявляет об успехе при ошибке 400, хотя состояние не изменилось |
| Разрастание объёма задачи | «Выход за рамки» | Агент делает больше, чем его просили |
| Отклонение от следования инструкциям | «Непослушание» | Агент игнорирует системный промпт или ограничение пользователя |
| Ошибки подзадач | «Ошибки в плане» | Пропуски, избыточность и нарушения порядка при выполнении плана |
