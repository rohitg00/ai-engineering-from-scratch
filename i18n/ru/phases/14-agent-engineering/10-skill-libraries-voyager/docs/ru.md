# Библиотеки навыков и обучение на протяжении всей жизни (Voyager)

> Voyager (Wang et al., TMLR 2024) рассматривает исполняемый код как навык. Навыки именованы, доступны для поиска, компонуемы и уточняются на основе обратной связи от среды. Это эталонная архитектура для навыков Claude Agent SDK, skillkit и паттерна библиотек навыков 2026 года.

**Тип:** Build
**Языки:** Python (stdlib)
**Предварительные требования:** Фаза 14 · 07 (MemGPT), Фаза 14 · 08 (Letta Blocks)
**Время:** ~75 минут

## Цели обучения

- Назвать три компонента Voyager — автоматический учебный план, библиотеку навыков, механизм итеративного промптинга — и роль каждого из них.
- Объяснить, почему в Voyager пространство действий — это код, а не примитивные команды.
- Реализовать библиотеку навыков на stdlib с регистрацией, поиском, композицией и уточнением, управляемым сбоями.
- Спроецировать паттерн Voyager на навыки Claude Agent SDK 2026 года и экосистему skillkit.

## Проблема

Агенты, которые заново выстраивают каждую способность с нуля в каждой сессии, делают три вещи неправильно:

1. **Тратят токены впустую.** Каждая задача заново вызывает то же самое рассуждение.
2. **Теряют прогресс.** Коррекция, усвоенная в сессии A, не переносится в сессию B.
3. **Проваливаются на долгосрочной композиции.** Сложные задачи требуют иерархий способностей; одноразовые промпты не могут их выразить.

Ответ Voyager: рассматривать каждую переиспользуемую способность как именованный фрагмент кода, хранящийся в библиотеке, доступный для поиска по сходству, компонуемый с другими навыками и уточняемый по обратной связи от выполнения.

## Концепция

### Три компонента

Voyager (arXiv:2305.16291) строит агента вокруг:

1. **Автоматического учебного плана.** Движимый любопытством предлагающий модуль выбирает следующую задачу на основе текущего набора навыков агента и состояния среды. Исследование идёт снизу вверх.
2. **Библиотеки навыков.** Каждый навык — это исполняемый код. Новые навыки добавляются, когда задача выполняется успешно. Поиск навыков выполняется по сходству запроса и описания.
3. **Механизма итеративного промптинга.** При сбое агент получает ошибки выполнения, обратную связь от среды и результат самопроверки, после чего уточняет навык.

Оценка на Minecraft (Wang et al., 2024): в 3.3x больше уникальных предметов, в 8.5x быстрее каменные инструменты, в 6.4x быстрее железные инструменты, в 2.3x дальше перемещение по карте по сравнению с базовыми решениями. Цифры специфичны для Minecraft, но паттерн переносится.

### Пространство действий = код

Большинство агентов выдают примитивные команды. Voyager выдаёт функции JavaScript. Навык выглядит так:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

Собран из под-навыков. Хранится с ключом по описанию и эмбеддингу. Находится как программа, а не как промпт.

Это и есть навык Claude Agent SDK 2026 года: именованный, доступный для поиска фрагмент кода плюс инструкции, которые агент загружает по требованию.

### Поиск навыков

Новая задача «сделать алмазную кирку». Агент:

1. Формирует эмбеддинг описания задачи.
2. Запрашивает у библиотеки навыков top-k наиболее похожих навыков.
3. Находит `craftIronPickaxe`, `mineDiamond`, `placeCraftingTable` и другие.
4. Составляет новый навык из найденных примитивов и новой логики.

Это тот же паттерн, что реализуют ресурсы MCP (Фаза 13) и навыки Agent SDK: поиск в совокупности знаний и кода, ограниченный текущей задачей.

### Итеративное уточнение

Цикл обратной связи Voyager:

1. Агент пишет навык.
2. Навык выполняется в среде.
3. Возвращается один из трёх сигналов: `success`, `error` (с трассировкой стека), `self-verification failure`.
4. Агент переписывает навык, используя сигнал как контекст.
5. Цикл повторяется до успеха или максимального числа раундов.

Это Self-Refine (Урок 05), применённый к генерации кода с верификацией, привязанной к среде. CRITIC (Урок 05) — тот же паттерн, где верификатором выступают внешние инструменты.

### Учебный план и исследование

Модуль учебного плана Voyager предлагает задачи вроде «построить укрытие у озера» на основе того, что у агента уже есть и чего он ещё не делал. Предлагающий модуль использует состояние среды и инвентарь навыков, чтобы выбрать задачу чуть выше текущей способности — оптимальную точку для исследования.

Для продакшен-агентов это превращается в оператор «чего не хватает»: учитывая текущую библиотеку навыков и домен, какие навыки мы ещё не покрываем? Команды обычно реализуют это вручную как обзор учебного плана.

### Где этот паттерн ломается

- **Загнивание библиотеки навыков.** Один и тот же навык добавлен 10 раз с чуть отличающимися описаниями. Добавьте дедупликацию при записи; поиск должен возвращать только один.
- **Дрейф составных навыков.** Родительский навык зависит от дочернего, который был уточнён. Версионируйте навыки; родитель, закреплённый за v1, не должен магическим образом подхватить v3.
- **Качество поиска.** Векторный поиск по описаниям навыков работает всё хуже, когда библиотека вырастает за пределы нескольких сотен. Дополните его фильтрами по тегам и жёсткими ограничениями («только навыки с `category=tooling`»).

```figure
voyager-skills
```

## Реализация

`code/main.py` реализует библиотеку навыков на stdlib:

- `Skill` — имя, описание, код (в виде строки), версия, теги, зависимости.
- `SkillLibrary` — регистрация, поиск (пересечение токенов), композиция (топологическая сортировка зависимостей) и уточнение (повышение версии при обновлении).
- Сценарный агент, который регистрирует три примитивных навыка, компонует четвёртый, сталкивается со сбоем и уточняет его.

Запустите:

```
python3 code/main.py
```

Трассировка показывает записи в библиотеку, поиск, композицию, неудачное выполнение и уточнение до v2 — цикл Voyager от начала до конца.

## Применение

- **Навыки Claude Agent SDK** (Anthropic) — эталон 2026 года: у каждого навыка есть описание, код и инструкции; он загружается по требованию во время сессии агента.
- **skillkit** (npm: skillkit) — межагентное управление навыками для 32+ ИИ-агентов для кодирования.
- **Пользовательские библиотеки навыков** — специфичные для домена (SQL-навыки для агентов данных, Terraform-навыки для инфраструктурных агентов). Паттерн Voyager масштабируется вниз.
- **`tools` в OpenAI Agents SDK** — на нижнем уровне сложности; каждый инструмент — это облегчённый навык.

## Упражнения

1. Добавьте детектор циклических зависимостей в `compose()`. Что происходит, когда навык A зависит от B, который зависит от A? Ошибка или предупреждение?
2. Реализуйте закрепление версий для каждого навыка. Когда родительский навык компонует дочерний `crafting@1`, уточнение до `crafting@2` не должно молча обновлять родителя.
3. Замените поиск по пересечению токенов на эмбеддинги sentence-transformers (или реализацию BM25 на stdlib). Измерьте retrieval@5 на игрушечной библиотеке из 50 навыков.
4. Добавьте агента «учебного плана»: учитывая текущую библиотеку и описание домена, предложить 5 недостающих навыков. Вызывать его еженедельно.
5. Прочитайте документацию Anthropic по навыкам Claude Agent SDK. Перенесите игрушечную библиотеку на схему навыков SDK. Что меняется в возможности их обнаружения?

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Навык | «Переиспользуемая способность» | Именованный фрагмент кода с описанием, доступный для поиска по сходству |
| Библиотека навыков | «Память агента о том, как выполнять задачи» | Постоянное хранилище навыков с возможностью поиска и композиции |
| Учебный план | «Модуль, предлагающий задачи» | Генератор целей снизу вверх, ориентирующийся на пробелы в текущих способностях |
| Композиция | «Ориентированный ациклический граф навыков» | Навыки вызывают другие навыки; при выполнении они сортируются топологически |
| Итеративное уточнение | «Самокорректирующийся цикл» | Обратная связь от среды, ошибки и самопроверка учитываются в следующей версии |
| Пространство действий в виде кода | «Программно заданные действия» | Для длительного во времени поведения генерируются функции, а не примитивные команды |
| Дедупликация при записи | «Схлопывание навыков» | Описания почти одинаковых навыков сводятся к одному каноническому навыку |
