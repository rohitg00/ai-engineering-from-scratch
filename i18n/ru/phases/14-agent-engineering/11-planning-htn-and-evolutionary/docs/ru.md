# Планирование с помощью HTN и эволюционного поиска

> Символьное планирование справляется со случаями, когда план доказуемо корректен. Эволюционный поиск кода справляется со случаями, когда функция приспособленности проверяема программно (machine-checkable). ChatHTN (2025) и AlphaEvolve (2025) показывают, что каждый из этих подходов раскрывает в паре с LLM.

**Тип:** Build**Языки:** Python (stdlib)**Предварительные требования:** Фаза 14 · 02 (ReWOO и Plan-and-Execute)**Время:** ~75 минут
## Цели обучения

- Объяснить иерархические сети задач (Hierarchical Task Networks): задачи, методы, операторы, предусловия, эффекты.
- Описать гибридный цикл ChatHTN — символьный поиск с откатом к LLM для декомпозиции.
- Объяснить эволюционный цикл AlphaEvolve и почему он работает только с программной функцией оценки.
- Реализовать игрушечный HTN-планировщик и игрушечный эволюционный поиск на stdlib.

## Проблема

ReWOO (урок 02), Plan-and-Execute и ReAct покрывают большинство сценариев агентного планирования. Есть два случая, которые они покрывают плохо:

1. **Планы с доказуемой корректностью.** Составление расписаний, прокладка маршрутов полётов, комплаенс-процессы — план должен быть корректен по построению. Бегло составленный LLM-план, который иногда галлюцинирует шаг, неприемлем.
2. **Оптимизации с проверяемой программно функцией приспособленности.** Умножение матриц, эвристики планирования, проходы компилятора — цель здесь не «корректный план», а «наилучший план».

HTN-планирование и AlphaEvolve решают эти две разные задачи. Оба подхода используют LLM как усилитель, а не как замену.

## Концепция

### Иерархические сети задач

HTN — это:

- **Задачи (tasks)** — составные (подлежащие декомпозиции) и примитивные (непосредственно исполняемые).
- **Методы (methods)** — способы разложить составную задачу на подзадачи, с предусловиями.
- **Операторы (operators)** — примитивные действия с предусловиями и эффектами.
- **Состояние (state)** — набор фактов.

Планирование: по заданной целевой задаче и начальному состоянию найти декомпозицию до примитивных операторов, предусловия которых выполняются последовательно.

HTN старше LLM и по-прежнему остаётся эталоном для доказуемо корректных планов.

### ChatHTN (Gopalakrishnan et al., 2025)

ChatHTN (arXiv:2505.11814) чередует символьный HTN с запросами к LLM:

1. Попытаться декомпозировать текущую составную задачу существующими методами.
2. Если ни один метод не подходит, спросить LLM: «как бы вы разложили `task` в состоянии `s`?»
3. Перевести ответ LLM в кандидатов-подзадач.
4. Проверить соответствие схеме операторов; отклонить недопустимые декомпозиции.
5. Рекурсивно повторить.

Центральное утверждение статьи: каждый сгенерированный план доказуемо корректен, потому что предложения LLM входят только как кандидаты декомпозиции, а не как прямые правки плана. Символьный уровень отвечает за корректность; LLM лишь расширяет библиотеку методов.

Онлайновое обучение методов (OpenReview `gwYEDY9j2x`, продолжение 2025 года) добавляет обучающийся компонент, который обобщает декомпозиции, сгенерированные LLM, посредством регрессии — сокращая частоту запросов к LLM до 75%.

### AlphaEvolve (Novikov et al., 2025)

AlphaEvolve (arXiv:2506.13131, DeepMind, июнь 2025) — совершенно другой зверь: эволюционный поиск кода, оркестрируемый ансамблем Gemini 2.0 Flash/Pro.

Цикл:

1. Начать с программы-затравки и программной функции оценки (возвращающей значение приспособленности).
2. Ансамбль LLM предлагает мутации.
3. Прогнать мутации через функцию оценки.
4. Оставить лучшие; снова мутировать.

Опубликованные результаты:

- Первое за 56 лет улучшение над алгоритмом Штрассена для умножения комплексных матриц 4x4 (48 скалярных умножений).
- 0,7% высвобожденных вычислительных мощностей Google благодаря эвристике планирования Borg.
- Ускорение FlashAttention на 32% на передовой рабочей нагрузке.

Жёсткое ограничение: функция приспособленности должна быть проверяема программно. Эволюционный поиск по текстовым ответам не сходится.

### Когда что использовать

| Класс задачи | Что использовать | Почему |
|---------------|-----|-----|
| Планирование с жёсткими ограничениями | HTN + ChatHTN | Доказуемая корректность |
| Оптимизация компилятора | AlphaEvolve | Проверяемая программно функция приспособленности |
| Многошаговое выполнение задач | ReAct / ReWOO | LLM в цикле, без формальных гарантий |
| Улучшение кода с тестами | AlphaEvolve | Тесты выступают оценщиком |
| Автоматизация, ограниченная политикой | HTN | Предусловия кодируют политику |

### Где этот паттерн ломается

- **HTN без операторов.** Без схем предусловий и эффектов утверждение о корректности рушится. Требование ChatHTN «LLM предлагает декомпозицию» работает только если схема отклоняет недопустимые ходы.
- **AlphaEvolve без настоящей функции оценки.** «Спросить у LLM, стал ли код лучше» — это не функция приспособленности. Оценщик должен быть детерминированным и быстрым.
- **Избыточная инженерия.** Большинству агентных задач не нужен ни один из этих подходов. Сначала обращайтесь к ReAct или ReWOO.

## Реализация

`code/main.py` реализует два игрушечных примера:

- HTN-планировщик на stdlib с операторами, методами, предусловиями, эффектами и `LLMFallback`, который включается, когда ни один метод не подходит составной задаче. «LLM» здесь — сценарный декомпозер, чтобы планировщик работал офлайн.
- Эволюционный поиск на stdlib по арифметическим программам: выращивание выражений, чей результат минимизирует `|f(x) - target|` на тестовом наборе. Оценщик детерминирован.

Запустите:

```
python3 code/main.py
```

Трассировка показывает, как HTN-планировщик декомпозирует составную задачу (с промежуточным откатом к LLM в середине плана) и как эволюционный цикл сходится к целевому выражению.

## Практика

- **HTN-планировщики** — `pyhop`, `SHOP3` или ваш собственный, для применения доменной политики.
- **ChatHTN** — исследовательский код; паттерн (символьный слой + откат к LLM) переносится без изменений на любой HTN-планировщик.
- **AlphaEvolve** — статья DeepMind; паттерн (ансамбль + оценщик) воспроизводим. Появляются OpenEvolve и похожие форки с открытым исходным кодом.
- **Агентные фреймворки** — ни один пока не поставляет готовую поддержку HTN или AlphaEvolve. Реализуйте это как субагента или фоновый воркер.

## Поставка

## Упражнения

1. Расширьте HTN-планировщик откатом (backtracking): когда постусловие оператора не выполняется во время выполнения, откатитесь и попробуйте следующий метод.
2. Добавьте кеш LLM-методов в ChatHTN: когда LLM декомпозирует задачу `T` в шаблоне состояния `P`, сохраняйте результат. При следующем вызове сначала проверяйте библиотеку методов.
3. Замените оценщик эволюционного поиска на настоящий набор тестов. Эволюционируйте функцию сортировки, проходящую 20 тестовых случаев; сообщите число поколений до сходимости.
4. Изучите заметки о дизайне оценщика AlphaEvolve. Спроектируйте оценщик для интересующей вас области (оптимизация SQL-запросов, минимизация набора тестов, YAML для развёртывания).
5. Скомбинируйте: используйте HTN для декомпозиции составной задачи на подзадачи, а затем эволюционный поиск — для примитивного оператора каждой подзадачи. Где это раскрывается лучше всего, а где становится избыточной инженерией?

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| HTN | «Иерархический планировщик» | Декомпозиция задач с операторами, предусловиями, эффектами |
| Method | «Правило декомпозиции» | Способ разбить составную задачу на подзадачи |
| Operator | «Примитивное действие» | Конкретный шаг с предусловием и эффектом |
| ChatHTN | «LLM + HTN» | Символьный планировщик обращается к LLM, когда ни один метод не подходит |
| AlphaEvolve | «Эволюционный поиск кода» | Ансамбль LLM мутирует код; детерминированный оценщик отбирает лучшее |
| Fitness function | «Оценщик» | Детерминированная, проверяемая программно оценка результатов |
| Online method learning | «Кешированная декомпозиция LLM» | Сохранение и обобщение планов LLM для снижения стоимости запросов |
