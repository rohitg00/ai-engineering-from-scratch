# Блоки памяти и вычисления во время сна

> Дискретные функциональные блоки памяти, которые модель может редактировать напрямую, и агент для вычислений во время сна (sleep-time agent), который асинхронно консолидирует память, пока основной агент простаивает. Эти две идеи позволяют масштабировать память за пределы одного диалога.

**Тип:** Build
**Языки:** Python (stdlib)
**Предварительные требования:** Фаза 14 · 07 (MemGPT)
**Время:** ~75 минут

## Цели обучения

- Назвать три уровня памяти, которые использует Letta (core, recall, archival), и роль каждого.
- Объяснить паттерн блока памяти: блок Human, блок Persona и пользовательские блоки как объекты первого класса с типами.
- Описать, что такое вычисления во время сна (sleep-time compute), почему они находятся вне критического пути и почему для них можно использовать более сильную модель, чем для основного агента.
- Реализовать сценарный цикл из двух агентов, где основной агент отвечает пользователю, а агент для вычислений во время сна консолидирует блоки между ходами.

## Проблема

MemGPT (Урок 07) решил проблему управления потоком виртуальной памяти. Возникли три проблемы эксплуатации:

1. **Задержка.** Каждая операция с памятью находится на критическом пути. Если агенту приходится сокращать, суммаризировать или согласовывать данные, пока пользователь ждёт, хвостовая задержка резко растёт.
2. **Гниение памяти.** Записи накапливаются. Опровергнутые факты остаются. Извлечение тонет в устаревшем содержимом.
3. **Потеря структуры.** Плоское хранилище archival не способно выразить «блок Human всегда в промпте; блок Persona всегда в промпте; блок Task меняется от сессии к сессии».

Letta (letta.com) — название платформы, которое исходный проект MemGPT принял в 2024 году; паттерн из статьи сохранил название MemGPT, а переработка Letta V1 2026 года стала более поздним, отдельным этапом. Блоки памяти делают структуру явной; вычисления во время сна выносят консолидацию за пределы критического пути.

## Концепция

### Три уровня

| Уровень | Область видимости | Где хранится | Кем записывается |
|------|-------|----------------|------------|
| Core | Всегда видим | Внутри основного промпта | Вызов инструмента агентом + переписывание во время сна |
| Recall | История диалога | Извлекаемо | Автоматическое логирование ходов |
| Archival | Произвольные факты | Векторное + KV + графовое | Вызов инструмента агентом + приём данных во время сна |

Core — это core из MemGPT. Recall — буфер диалога с его вытесненным хвостом. Archival — внешнее хранилище. Такое разделение убирает перегруженность двухуровневой схемы MemGPT.

### Блоки памяти

Блок — типизированный, персистентный, редактируемый раздел уровня core. Оригинальная статья MemGPT определила два таких блока:

- **Блок Human** — факты о пользователе (имя, роль, предпочтения, цели).
- **Блок Persona** — самоописание агента (идентичность, тон, ограничения).

Letta обобщает это до произвольных пользовательских блоков: блок `Task` для текущей цели, блок `Project` для фактов о кодовой базе, блок `Safety` для жёстких ограничений. У каждого блока есть `id`, `label`, `value`, `limit` (лимит символов), `description` (чтобы модель знала, когда его редактировать).

Блоки редактируются через набор инструментов:

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — сжать блок, приближающийся к своему лимиту.

### Вычисления во время сна

Добавление 2025 года в Letta: запускать второго агента в фоне, вне критического пути. Агенты для вычислений во время сна обрабатывают транскрипты диалога и контекст кодовой базы, записывают `learned_context` в общие блоки и консолидируют или инвалидируют записи archival.

Из этого вытекают следующие свойства:

- **Нет издержек по задержке.** Основные ответы не ждут операций с памятью.
- **Допустима более сильная модель.** Агент для вычислений во время сна может использовать более дорогую и медленную модель, поскольку его работа не ограничена требованиями к задержке.
- **Естественное окно консолидации.** Дедупликация, суммаризация, инвалидация опровергнутых фактов происходят, пока пользователь не ждёт.

Форма повторяет то, как работают люди: вы выполняете задачу, «спите на ней», и долгосрочная память устаканивается за ночь.

### Нативное рассуждение

Letta V1 (`letta_v1_agent`, 2026) отказывается от `send_message`/heartbeat и встроенных токенов `Thought:` в пользу нативного рассуждения. Responses API (OpenAI) и Messages API с расширенным мышлением (extended thinking) от Anthropic выдают рассуждение по отдельному каналу, передаваемому между ходами (в рабочей среде он шифруется при передаче между провайдерами). Управляющий цикл по-прежнему ReAct. Трасса размышлений теперь структурна, а не оформлена как часть промпта.

### Где этот паттерн ломается

- **Раздутие блока.** Бесконечный `block_append` быстро упирается в лимит. Подключите суммаризатор блока перед записью, которая превышает лимит.
- **Незаметный дрейф.** Агент для вычислений во время сна переписывает блок, а основной агент этого не замечает. Версионируйте блоки и показывайте различия в трассе.
- **Отравленная консолидация.** Агент для вычислений во время сна переносит в core содержимое, на которое может повлиять атакующий. Урок 27 применим и к интерфейсу вычислений во время сна.

## Реализация

`code/main.py` реализует:

- `Block` — идентификатор, метка, значение, лимит и описание.
- `BlockStore` — CRUD + вспомогательный метод `near_limit(label)`.
- Два сценарных агента — `PrimaryAgent` отвечает за ход, `SleepTimeAgent` консолидирует данные между ходами.
- Трассу, показывающую трёхходовый диалог с записями в блоки, а также проход вычислений во время сна, который суммаризирует блок и инвалидирует устаревший факт.

Запуск:

```
python3 code/main.py
```

Транскрипт показывает разделение: основные ходы быстрые и производят «сырые» записи; проход вычислений во время сна уплотняет и очищает их.

## Применение

- **Letta** (letta.com) для эталонной реализации. Самостоятельное развёртывание или управляемое облако.
- **Навыки (skills) Claude Agent SDK** как знания в форме блоков: навык — это именованный, версионированный, извлекаемый блок инструкций, который агент загружает по требованию.
- **Собственные реализации** для команд, которым нужен контроль над бэкендом хранения. Используйте контракт API Letta, чтобы позже можно было мигрировать.

`outputs/skill-memory-blocks.md` генерирует систему блоков в духе Letta с хуками для вычислений во время сна в любой среде выполнения, включая правила безопасности и подключение цитирования.

## Упражнения

1. Добавьте инструмент `block_summarize`, заменяющий значение блока сгенерированным моделью резюме, когда `near_limit` возвращает true. Какой пороговый триггер минимизирует и количество вызовов суммаризации, и переполнение блоков?
2. Реализуйте дедупликацию записей archival во время сна: две записи, текст которых совпадает по токенам более чем на 90%, объединяются в одну. Делайте это только во время прохода вычислений во время сна, но никогда на критическом пути.
3. Версионируйте блоки. При каждой записи сохраняйте старое значение и дифф. Реализуйте `block_history(label)`, чтобы операторы могли отлаживать «почему агент забыл X».
4. Считайте агентов для вычислений во время сна недоверенными авторами. Когда они изменяют блок Persona или Safety, требуйте проверку вторым агентом перед фиксацией.
5. Перенесите пример на API Letta (`letta_v1_agent`). Что меняется в схеме блоков и как нативное рассуждение изменяет форму трассы?

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|----------------|------------------------|
| Блок памяти | «Редактируемый раздел промпта» | Типизированный, персистентный сегмент памяти core, редактируемый LLM |
| Блок Human | «Память о пользователе» | Факты о пользователе, постоянно закреплённые в core |
| Блок Persona | «Идентичность агента» | Самоописание, тон и ограничения, постоянно закреплённые в core |
| Вычисления во время сна | «Асинхронная работа с памятью» | Консолидация вне критического пути, выполняемая вторым агентом |
| Core / Recall / Archival | «Уровни» | Трёхуровневая структура памяти: всегда видимая / диалоговая / внешняя |
| Лимит блока | «Ограничение» | Лимит символов для каждого блока, вынуждающий выполнять суммаризацию |
| Нативное рассуждение | «Канал рассуждений» | Вывод рассуждений на уровне провайдера, а не `Thought:` на уровне промпта |
| Усвоенный контекст | «Результат работы во время сна» | Факты, которые агент для вычислений во время сна записывает в общие блоки |
