# Отслеживание состояния диалога

> «Мне нужен недорогой ресторан на севере… хотя нет, пусть будет со средними ценами… и добавьте итальянскую кухню». Три реплики, три обновления состояния. DST поддерживает синхронизацию словаря слот-значение, чтобы бронирование работало.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 5 · 17 (Чат-боты), Этап 5 · 20 (Структурированный вывод)
**Время:** ~75 минут

## Проблема

В диалоговой системе, ориентированной на выполнение задач, цель пользователя кодируется как набор пар слот-значение: `{cuisine: italian, area: north, price: moderate}`. Каждая реплика пользователя может добавить, изменить или удалить слот. Система должна прочитать весь разговор и правильно вывести текущее состояние.

Ошибитесь в одном-единственном слоте — и система забронирует не тот ресторан, запланирует не тот рейс или спишет деньги не с той карты. DST — это шарнир между тем, что сказал пользователь, и тем, что выполняет бэкенд.

Почему это всё ещё важно в 2026 году, несмотря на развитие больших языковых моделей (LLM):

- В сферах с жёсткими регуляторными требованиями (банкинг, здравоохранение, бронирование авиабилетов) нужны детерминированные значения слотов, а не свободная генерация.
- Агентам, использующим инструменты, всё ещё нужно уточнять значения слотов перед вызовом API.
- Многоходовая коррекция сложнее, чем кажется: «Хотя нет, перенесите на четверг».

Современный конвейер: классические концепции DST + LLM-экстракторы + защитные ограничения структурированного вывода.

## Концепция

![DST: история диалога → состояние в виде пар слот-значение](../assets/dst.svg)

**Структура задачи.** Схема определяет домены (ресторан, отель, такси) и их слоты (cuisine, area, price, people). Каждый слот может быть пустым, заполненным значением из закрытого множества (price: {cheap, moderate, expensive}) или значением в свободной форме (name: «Медный чайник»).

**Две формулировки DST.**

- **Классификация.** Для каждой пары (слот, кандидат-значение) предсказывается да/нет. Работает для слотов с закрытым словарём. Стандарт до 2020 года.
- **Генерация.** Учитывая диалог, генерируются значения слотов как свободный текст. Работает для слотов с открытым словарём. Современный стандарт по умолчанию.

**Метрика.** Совместная точность цели (JGA) — доля реплик, где *каждый* слот верен. Всё или ничего. В 2026 году лучший результат в таблице лидеров MultiWOZ 2.4 составляет около 83%.

**Архитектуры.**

1. **На основе правил (регулярные выражения слотов + ключевые слова).** Сильная базовая линия для узких доменов. Поддаётся отладке.
2. **TripPy / BERT-DST.** Генерация на основе копирования с кодированием BERT. Стандарт до эпохи LLM.
3. **LDST (LLaMA + LoRA).** LLM, дообученная на инструкциях, с промптингом по доменам и слотам. Достигает качества уровня ChatGPT на MultiWOZ 2.4.
4. **Без онтологии (2024–26).** Схема пропускается; имена и значения слотов генерируются напрямую. Работает с открытыми доменами.
5. **Промпт + структурированный вывод (2024–26).** LLM со схемой Pydantic и ограниченным декодированием. 5 строк кода, готово для продакшена.

### Классические режимы сбоя

- **Кореференция между репликами.** «Остановимся на первом варианте». Нужно определить, какой вариант имеется в виду.
- **Перезапись или добавление.** Пользователь говорит: «Добавьте итальянскую кухню». Заменить cuisine или добавить ещё одно значение?
- **Неявные подтверждения.** «Хорошо, отлично» — означает ли это согласие на предложенное бронирование?
- **Коррекция.** «Вообще-то перенесите на 19:00». Нужно обновить время, не сбрасывая другие слоты.
- **Кореференция к предыдущей реплике системы.** «Да, этот». Какой именно вариант имеется в виду?

## Постройте это

### Шаг 1: экстрактор слотов на основе правил

См. `code/main.py`. Регулярные выражения + словари синонимов покрывают 70% канонических реплик в узких доменах:

```python
CUISINE_SYNONYMS = {
    "italian": ["italian", "pasta", "pizza", "italy"],
    "chinese": ["chinese", "chow mein", "noodles"],
}


def extract_cuisine(utterance):
    for canonical, synonyms in CUISINE_SYNONYMS.items():
        if any(syn in utterance.lower() for syn in synonyms):
            return canonical
    return None
```

Хрупко за пределами канонического словаря. Работает для детерминированных подтверждений слотов.

### Шаг 2: цикл обновления состояния

```python
def update_state(state, utterance):
    new_state = dict(state)
    for slot, extractor in SLOT_EXTRACTORS.items():
        value = extractor(utterance)
        if value is not None:
            new_state[slot] = value
    for slot in NEGATION_CLEARS:
        if is_negated(utterance, slot):
            new_state[slot] = None
    return new_state
```

Три инварианта:

- Никогда не сбрасывайте слот, которого пользователь не касался.
- Явное отрицание («кухня не важна») должно очищать слот.
- Коррекция пользователя («вообще-то…») должна перезаписывать, а не добавлять.

### Шаг 3: LLM-управляемый DST со структурированным выводом

```python
from pydantic import BaseModel
from typing import Literal, Optional
import instructor

class RestaurantState(BaseModel):
    cuisine: Optional[Literal["italian", "chinese", "indian", "thai", "any"]] = None
    area: Optional[Literal["north", "south", "east", "west", "center"]] = None
    price: Optional[Literal["cheap", "moderate", "expensive"]] = None
    people: Optional[int] = None
    day: Optional[str] = None


def llm_dst(history, llm):
    prompt = f"""You track the slot values of a restaurant booking across turns.
Dialogue so far:
{render(history)}

Update the state based on the latest user turn. Output only the JSON state."""
    return llm(prompt, response_model=RestaurantState)
```

Instructor + Pydantic гарантируют валидный объект состояния. Никаких регулярных выражений, никаких несоответствий схеме, никаких галлюцинированных слотов.

### Шаг 4: оценка JGA

```python
def joint_goal_accuracy(predicted_states, gold_states):
    correct = sum(1 for p, g in zip(predicted_states, gold_states) if p == g)
    return correct / len(predicted_states)
```

Калибровка: в какой доле реплик система правильно определяет ВСЕ слоты? Для MultiWOZ 2.4 топовые системы 2026 года: 80–83%. Ваша внутридоменная система должна превзойти это на своём узком словаре, иначе базовая линия на LLM обгонит вас.

### Шаг 5: обработка коррекции

```python
CORRECTION_CUES = {"actually", "no wait", "on second thought", "change that to"}


def is_correction(utterance):
    return any(cue in utterance.lower() for cue in CORRECTION_CUES)
```

При обнаружении коррекции перезаписывайте последний обновлённый слот, а не добавляйте новый. Трудно сделать правильно без помощи LLM. Современный паттерн: всегда давать LLM регенерировать всё состояние из истории целиком, а не обновлять инкрементально — это естественным образом обрабатывает коррекции.

## Ловушки

- **Стоимость полной регенерации истории.** Если давать LLM регенерировать состояние на каждой реплике, это стоит O(n²) токенов суммарно. Ограничивайте историю или суммаризируйте старые реплики.
- **Дрейф схемы.** Добавление новых слотов постфактум ломает старые обучающие данные. Версионируйте схему.
- **Чувствительность к регистру.** «Итальянская» против «итальянская» против «ИТАЛЬЯНСКАЯ» — нормализуйте везде.
- **Неявное наследование.** Если пользователь ранее указал «на 4 человек», новый запрос на другое время не должен сбрасывать people. Всегда передавайте полную историю.
- **Свободная форма против закрытого множества.** Имена, время и адреса нуждаются в слотах свободной формы; cuisine и area — закрытые. Смешивайте оба типа в схеме.

## Применение

Стек 2026 года:

| Ситуация | Подход |
|-----------|----------|
| Узкий домен (один-два интента) | На основе правил + регулярные выражения |
| Широкий домен, есть размеченные данные | LDST (LLaMA + LoRA на данных в стиле MultiWOZ) |
| Широкий домен, нет меток, готово для продакшена | LLM + Instructor + схема Pydantic |
| Голосовой / речевой | ASR + нормализатор + LLM-DST |
| Мультидоменный поток бронирования | LLM под управлением схемы с моделями Pydantic для каждого домена |
| Сферы с жёсткими регуляторными требованиями | Основной — на основе правил, LLM как резервный вариант с подтверждающим потоком |

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| DST | Отслеживание состояния диалога | Поддержание словаря слот-значение синхронизированным на протяжении диалога. |
| Слот | Единица намерения пользователя | Именованный параметр, нужный бэкенду (cuisine, date). |
| Домен | Область задачи | Ресторан, отель, такси — наборы слотов. |
| JGA | Совместная точность цели | Доля реплик, где каждый слот верен. Всё или ничего. |
| MultiWOZ | Бенчмарк | Мультидоменный набор данных WOZ; стандарт оценки DST. |
| DST без онтологии | Без схемы | Прямая генерация имён и значений слотов, без фиксированного списка. |
| Коррекция | «Вообще-то…» | Реплика, которая перезаписывает ранее заполненный слот. |
