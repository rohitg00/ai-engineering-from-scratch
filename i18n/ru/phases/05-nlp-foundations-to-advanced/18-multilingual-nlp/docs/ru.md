# Многоязычный NLP

> Одна модель, 100+ языков, ноль обучающих данных для большинства из них. Кросс-языковой перенос — практическое чудо 2020-х.

**Тип:** Learn
**Языки:** Python
**Предварительные требования:** Фаза 5 · 04 (GloVe, FastText, Subword), Фаза 5 · 11 (машинный перевод)
**Время:** ~45 минут

## Проблема

У английского языка миллиарды размеченных примеров. У урду — тысячи. У майтхили — почти ноль. Любая практическая NLP-система, обслуживающая глобальную аудиторию, должна работать на длинном хвосте языков, для которых не существует обучающих данных под конкретную задачу.

Многоязычные модели решают это, обучая одну модель одновременно на многих языках. Общее представление позволяет модели переносить навыки, полученные на высокоресурсных языках, на низкоресурсные. Дообучите модель на английском анализе тональности — и она даёт удивительно хорошие предсказания тональности на урду прямо «из коробки». Это перенос между языками без примеров (zero-shot cross-lingual transfer), и он изменил то, как NLP поставляется в мир.

Этот урок называет компромиссы, канонические модели и одно решение, на котором спотыкаются команды, новые в многоязычной работе: выбор исходного языка для переноса.

## Концепция

![Кросс-языковой перенос через общее многоязычное пространство эмбеддингов](../assets/multilingual.svg)

**Общий словарь.** Многоязычные модели используют токенизатор SentencePiece или WordPiece, обученный на тексте всех целевых языков. Словарь общий: одна и та же субсловная единица представляет одну и ту же морфему в родственных языках. `anti-` в английском и итальянском получает один и тот же токен.

**Общее представление.** Трансформер, предобученный на маскированном языковом моделировании на многих языках, учится тому, что семантически схожие предложения на разных языках порождают похожие скрытые состояния. mBERT, XLM-R и NLLB — все демонстрируют это. Эмбеддинги слова «cat» в английском кластеризуются рядом с «chat» во французском и «gato» в испанском, и то же самое происходит с эмбеддингами целых предложений.

**Перенос без примеров (zero-shot).** Дообучите модель на размеченных данных на одном языке (обычно английском). На этапе вывода запускайте её на любом другом языке, который поддерживает модель. Метки на целевом языке не нужны. Результаты сильны для типологически родственных языков и слабее для далёких.

**Дообучение с малым числом примеров (few-shot).** Добавьте 100-500 размеченных примеров на целевом языке. Точность подскакивает до 95-98% от базовой линии на английском для задач классификации. Это самый экономически эффективный рычаг в многоязычном NLP.

## Модели

| Модель | Год | Покрытие | Примечания |
|-------|------|----------|-------|
| mBERT | 2018 | 104 языка | Обучена на Wikipedia. Первая практичная многоязычная LM. Слабая на низкоресурсных языках. |
| XLM-R | 2019 | 100 языков | Обучена на CommonCrawl (намного больше, чем Wikipedia). Задаёт кросс-языковую базовую линию. Base 270M, Large 550M. |
| XLM-V | 2023 | 100 языков | XLM-R со словарём в 1 млн токенов (против 250 тыс.). Лучше на низкоресурсных языках. |
| mT5 | 2020 | 101 язык | Архитектура T5 для многоязычной генерации. |
| NLLB-200 | 2022 | 200 языков | Модель перевода от Meta; включает 55 низкоресурсных языков. |
| BLOOM | 2022 | 46 языков + 13 языков программирования | Открытая LLM на 176B параметров, обученная многоязычно. |
| Aya-23 | 2024 | 23 языка | Многоязычная LLM от Cohere. Сильна на арабском, хинди, суахили. |

Выбирайте по сценарию использования. Классификация хорошо работает с XLM-R-base как разумным выбором по умолчанию. Задачи генерации требуют mT5 или NLLB в зависимости от того, перевод это или открытая генерация. Работа в стиле LLM сочетается с Aya-23 или Claude при явном многоязычном промптинге.

## Решение об исходном языке (исследования 2026 года)

Большинство команд по умолчанию выбирают английский в качестве исходного языка для дообучения. Недавние исследования (2026) показывают, что это часто неверно.

Языковое сходство предсказывает качество переноса лучше, чем сырой размер корпуса. Для славянских целевых языков немецкий или русский часто превосходят английский. Для индийских целевых языков хинди часто превосходит английский. Метрика сходства **qWALS** (2026, на основе признаков World Atlas of Language Structures) количественно измеряет это. **LANGRANK** (Lin et al., ACL 2019) — отдельный, более ранний метод, который ранжирует кандидатов на роль исходного языка по комбинации лингвистического сходства, размера корпуса и генетического родства.

Практическое правило: если у вашего целевого языка есть типологически близкий высокоресурсный родственник, попробуйте сначала дообучить на нём, затем сравните с дообучением на английском.

## Создаём

### Шаг 1: классификация без примеров между языками

```python
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch

tok = AutoTokenizer.from_pretrained("joeddav/xlm-roberta-large-xnli")
model = AutoModelForSequenceClassification.from_pretrained("joeddav/xlm-roberta-large-xnli")


def classify(text, candidate_labels, hypothesis_template="This text is about {}."):
    scores = {}
    for label in candidate_labels:
        hypothesis = hypothesis_template.format(label)
        inputs = tok(text, hypothesis, return_tensors="pt", truncation=True)
        with torch.no_grad():
            logits = model(**inputs).logits[0]
        entail_score = torch.softmax(logits, dim=-1)[2].item()
        scores[label] = entail_score
    return dict(sorted(scores.items(), key=lambda x: -x[1]))


print(classify("I love this product!", ["positive", "negative", "neutral"]))
print(classify("मुझे यह उत्पाद पसंद है!", ["positive", "negative", "neutral"]))
print(classify("J'adore ce produit !", ["positive", "negative", "neutral"]))
```

Одна модель, три языка, один и тот же API. XLM-R, обученный на данных NLI, хорошо переносится на классификацию через приём с энтейлментом (entailment).

### Шаг 2: многоязычное пространство эмбеддингов

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")

pairs = [
    ("The cat is sleeping.", "Le chat dort."),
    ("The cat is sleeping.", "El gato está durmiendo."),
    ("The cat is sleeping.", "Die Katze schläft."),
    ("The cat is sleeping.", "The dog is barking."),
]

for eng, other in pairs:
    emb_eng = model.encode([eng], normalize_embeddings=True)[0]
    emb_other = model.encode([other], normalize_embeddings=True)[0]
    sim = float(np.dot(emb_eng, emb_other))
    print(f"  {eng!r} <-> {other!r}: cos={sim:.3f}")
```

Переводы оказываются близко в пространстве эмбеддингов. Другое английское предложение оказывается дальше. Именно это делает возможными кросс-языковой поиск, кластеризацию и сравнение сходства.

### Шаг 3: стратегия дообучения с малым числом примеров

```python
from transformers import TrainingArguments, Trainer
from datasets import Dataset


def few_shot_finetune(base_model, base_tokenizer, examples):
    ds = Dataset.from_list(examples)

    def tokenize_fn(ex):
        out = base_tokenizer(ex["text"], truncation=True, max_length=128)
        out["labels"] = ex["label"]
        return out

    ds = ds.map(tokenize_fn)
    args = TrainingArguments(
        output_dir="out",
        per_device_train_batch_size=8,
        num_train_epochs=5,
        learning_rate=2e-5,
        save_strategy="no",
    )
    trainer = Trainer(model=base_model, args=args, train_dataset=ds)
    trainer.train()
    return base_model
```

Для 100-500 примеров на целевом языке `num_train_epochs=5` и `learning_rate=2e-5` — безопасные значения по умолчанию. Более высокая скорость обучения приводит к разрушению многоязычного выравнивания, и в итоге получается англоязычная модель.

## Оценивание, которое реально работает

- **Точность по каждому языку на отложенных наборах.** Не агрегированная. Агрегат скрывает длинный хвост.
- **Сравнение с одноязычной базовой линией.** Для языков с достаточным количеством данных одноязычная модель, обученная с нуля, иногда превосходит многоязычную. Проверьте.
- **Тесты на уровне сущностей.** Именованные сущности на целевом языке. Многоязычные модели часто имеют слабую токенизацию для письменностей, далёких от латиницы.
- **Кросс-языковая согласованность.** Один и тот же смысл на двух языках должен давать одно и то же предсказание. Измерьте разрыв.

## Применяем

Стек 2026 года:

| Задача | Рекомендация |
|-----|-------------|
| Классификация, 100 языков | Дообученная XLM-R-base (~270M) |
| Классификация без примеров | `joeddav/xlm-roberta-large-xnli` |
| Многоязычные эмбеддинги предложений | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| Перевод, 200 языков | `facebook/nllb-200-distilled-600M` (см. урок 11) |
| Генеративный многоязычный | Claude, GPT-4, Aya-23, mT5-XXL |
| NLP для низкоресурсных языков | XLM-V или дообучение под конкретную область на родственном высокоресурсном языке |

Всегда закладывайте бюджет на дообучение на целевом языке, если важна производительность. Перенос без примеров — это отправная точка, а не окончательный ответ.

### Налог токенизации (что идёт не так для низкоресурсных языков)

Многоязычные модели используют один токенизатор для всех своих языков. Этот словарь обучен на корпусе, в котором доминируют английский, французский, испанский, китайский, немецкий. Для любого языка вне доминирующего набора незаметно накапливаются три «налога»:

- **Налог на «плодовитость» (fertility tax).** Текст на низкоресурсном языке токенизируется в гораздо больше токенов на слово, чем английский. Предложению на хинди может понадобиться в 3-5 раз больше токенов, чем эквивалентному предложению на английском. Эти 3-5 раз съедают ваше контекстное окно, эффективность обучения и задержку.
- **Налог на восстановление вариантов.** Каждая опечатка, вариант диакритики, несовпадение нормализации Unicode или вариация регистра становится холодным стартом — не связанной ни с чем последовательностью в пространстве эмбеддингов. Модель не может выучить орфографические соответствия, которые носитель языка считает очевидными.
- **Налог на утечку ёмкости.** Первые два налога поглощают позиции контекста, глубину слоёв и измерения эмбеддингов. То, что остаётся для собственно рассуждения, систематически меньше того, что получает высокоресурсный язык от той же модели.

Практический симптом: ваша модель обучается на хинди нормально, кривая потерь выглядит правильно, перплексия на валидации выглядит разумной, а продакшен-выводы едва заметно неверны. Морфология рушится в середине предложения. Редкие словоформы остаются невосстановимыми. **Вы не можете масштабированием данных компенсировать сломанный токенизатор.**

Смягчение: выберите токенизатор с хорошим покрытием для вашего целевого языка (словарь XLM-V из 1 млн токенов — прямое решение); проверьте «плодовитость» токенизации на отложенном целевом тексте перед обучением; используйте резервный переход на байтовый уровень (SentencePiece `byte_fallback=True`, байтовый BPE в стиле GPT-2) для по-настоящему длиннохвостых письменностей, чтобы ничего никогда не оказывалось вне словаря (OOV).

version: 1.0.0
phase: 5
lesson: 18
tags: [nlp, multilingual, cross-lingual]
---

Given requirements (target languages, task type, available labeled data per language), output:

1. Source language for fine-tuning. Default English; check LANGRANK or qWALS if target language has a typologically close high-resource language.
2. Base model. XLM-R (classification), mT5 (generation), NLLB (translation), Aya-23 (generative LLM).
3. Few-shot budget. Start with 100-500 target-language examples if available. Zero-shot only if labeling is infeasible.

Refuse to ship a multilingual model without per-language evaluation — aggregate metrics hide long-tail failures. ```

## Упражнения

1. **Лёгкое.** Запустите конвейер классификации без примеров на 10 предложениях для каждого языка среди английского, французского, хинди и арабского. Сообщите точность для каждого. Вы должны увидеть сильные результаты для французского, приличные для хинди, переменчивые для арабского.
2. **Среднее.** Используйте `paraphrase-multilingual-MiniLM-L12-v2`, чтобы построить кросс-языковой ретривер по небольшому многоязычному корпусу. Задайте запрос на английском, извлекайте документы на любом языке. Измерьте recall@5.
3. **Сложное.** Сравните дообучение с исходным языком английский и исходным языком хинди для задачи классификации на хинди. Используйте 500 примеров на целевом языке для дообучения с малым числом примеров в обоих режимах. Сообщите, какой исходный язык даёт лучшую точность на хинди и насколько. Это тезис LANGRANK в миниатюре.

## Ключевые термины

| Термин | Как говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Многоязычная модель | Одна модель, много языков | Общий словарь и параметры для всех языков. |
| Кросс-языковой перенос | Обучение на одном языке, запуск на другом | Дообучение на исходном языке, оценка на целевом без меток на целевом языке. |
| Zero-shot (без примеров) | Нет меток на целевом языке | Перенос без дообучения на целевом языке. |
| Few-shot (с малым числом примеров) | Немного меток на целевом языке | 100-500 примеров на целевом языке, используемых для дообучения. |
| mBERT | Первая многоязычная LM | 104-язычный BERT, предобученный на Wikipedia. |
| XLM-R | Стандартная кросс-языковая базовая линия | 100-язычная RoBERTa, предобученная на CommonCrawl. |
| NLLB | 200-язычный MT от Meta | No Language Left Behind. Включает 55 низкоресурсных языков. |
