# Системы вопросно-ответного взаимодействия

> Три системы сформировали современный QA. Экстрактивная находила фрагменты. Поиск с дополнением заземлял их в документах. Генеративная производила ответы. Каждый современный ИИ-ассистент — это смесь всех трёх.

**Тип:** Практика
**Языки:** Python
**Предпосылки:** Фаза 5 · 11 (Machine Translation), Фаза 5 · 10 (Attention Mechanism)
**Время:** ~75 минут

## Проблема

Пользователь вводит «Когда вышел первый iPhone?» и ожидает «29 июня 2007 года». Не «История Apple длинная и разнообразная». Не «2007» в изоляции без предложения. Прямой, обоснованный, верный ответ.

Три архитектуры доминировали в QA последнее десятилетие.

- **Экстрактивный QA.** Дан вопрос и отрывок, о котором известно, что он содержит ответ; найдите начальный и конечный индексы фрагмента ответа в отрывке. SQuAD — канонический бенчмарк.
- **QA открытого домена.** Отрывок не дан. Сначала найдите релевантный отрывок, затем извлеките или сгенерируйте ответ. Это основа каждого RAG-пайплайна сегодня.
- **Генеративный / QA закрытой книги.** Большая языковая модель отвечает из своей параметрической памяти. Без поиска. Быстрее всего при инференсе, наименее надёжна в фактах.

Тренд 2026 года — гибридный: найти несколько лучших отрывков, затем промптить генеративную модель ответить, опираясь на эти отрывки. Это и есть RAG, и урок 14 подробно разбирает поисковую половину. Этот урок строит половину, отвечающую за QA.

## Концепция

![Архитектуры QA: экстрактивная, с дополнением поиском, генеративная](../assets/qa.svg)

**Экстрактивная.** Закодируйте вопрос и отрывок вместе трансформером (семейство BERT). Обучите две головы, предсказывающие индексы начального и конечного токенов ответа. Функция потерь — кросс-энтропия по допустимым позициям. Вывод — фрагмент из отрывка. Никогда не галлюцинирует (по построению), никогда не обрабатывает вопросы, на которые отрывок не может ответить (по построению).

**С дополнением поиском (RAG).** Два этапа. Сначала ретривер находит топ-`k` отрывков из корпуса. Затем ридер (экстрактивный или генеративный) производит ответ, используя эти отрывки. Разделение ретривер-ридер позволяет обучать и оценивать каждый компонент независимо. Современный RAG часто добавляет реранкер между ними.

**Генеративная.** Декодер-only LLM (GPT, Claude, Llama) отвечает из обученных весов. Без этапа поиска. Отлично справляется с общеизвестными фактами, катастрофически — с редкими или недавними. Частота галлюцинаций обратно коррелирует с частотой факта в данных предобучения.

## Реализация

### Шаг 1: экстрактивный QA с предобученной моделью

```python
from transformers import pipeline

qa = pipeline("question-answering", model="deepset/roberta-base-squad2")

passage = (
    "Apple Inc. released the first iPhone on June 29, 2007. "
    "The device was announced by Steve Jobs at Macworld in January 2007."
)
question = "When was the first iPhone released?"

answer = qa(question=question, context=passage)
print(answer)
```

```python
{'score': 0.98, 'start': 57, 'end': 70, 'answer': 'June 29, 2007'}
```

`deepset/roberta-base-squad2` обучена на SQuAD 2.0, который включает вопросы без ответа. По умолчанию пайплайн `question-answering` возвращает фрагмент с наивысшей оценкой, даже когда побеждает нулевая оценка модели — он *не* возвращает пустой ответ автоматически. Чтобы получить явное поведение «нет ответа», передайте `handle_impossible_answer=True` при вызове пайплайна: тогда пайплайн вернёт пустой ответ только когда нулевая оценка превышает оценку каждого фрагмента. В любом случае всегда проверяйте поле `score`.

### Шаг 2: пайплайн с дополнением поиском (набросок)

```python
from sentence_transformers import SentenceTransformer
import numpy as np

encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

corpus = [
    "Apple Inc. released the first iPhone on June 29, 2007.",
    "Macworld 2007 featured the iPhone announcement by Steve Jobs.",
    "Android launched in 2008 as Google's mobile operating system.",
    "The first iPod was released in 2001.",
]
corpus_embeddings = encoder.encode(corpus, normalize_embeddings=True)


def retrieve(question, top_k=2):
    q_emb = encoder.encode([question], normalize_embeddings=True)
    sims = (corpus_embeddings @ q_emb.T).squeeze()
    order = np.argsort(-sims)[:top_k]
    return [corpus[i] for i in order]


def answer(question):
    passages = retrieve(question, top_k=2)
    combined = " ".join(passages)
    return qa(question=question, context=combined)


print(answer("When was the first iPhone released?"))
```

Двухэтапный пайплайн. Плотный ретривер (Sentence-BERT) находит релевантные отрывки по семантическому сходству. Экстрактивный ридер (RoBERTa-SQuAD) извлекает фрагмент ответа из объединённых верхних отрывков. Работает на небольших корпусах. Для корпуса из миллиона документов используйте FAISS или векторную базу данных.

### Шаг 3: генеративный подход с RAG

```python
def rag_generate(question, llm):
    passages = retrieve(question, top_k=3)
    prompt = f"""Context:
{chr(10).join('- ' + p for p in passages)}

Question: {question}

Answer using only the context above. If the context does not contain the answer, say "I don't know."
"""
    return llm(prompt)
```

Паттерн промпта имеет значение. Явное указание модели опираться на контекст и отвечать «не знаю», когда контекста недостаточно, снижает частоту галлюцинаций на 40–60% по сравнению с наивным промптингом. Более сложные паттерны добавляют цитаты, оценки уверенности и структурированное извлечение.

### Шаг 4: оценивание, отражающее реальный мир

SQuAD использует **точное совпадение (Exact Match, EM)** и **F1 на уровне токенов**. EM — это строгое совпадение после нормализации (нижний регистр, удаление пунктуации, удаление артиклей) — либо предсказание совпадает точно, либо оценка равна 0. F1 вычисляется по перекрытию токенов между предсказанием и эталоном и даёт частичный зачёт. Обе метрики недооценивают перефразирование: «June 29, 2007» против «June 29th, 2007» обычно получает 0 по EM (порядковое числительное ломает нормализацию), но всё же зарабатывает существенный F1 за счёт пересекающихся токенов.

Для продакшен-QA:

- **Точность ответа** (оценка LLM или человеком, поскольку метрики не улавливают семантическую эквивалентность).
- **Точность цитирования.** Действительно ли процитированный отрывок подтверждает ответ? Тривиально проверить автоматически сопоставлением строк между сгенерированными цитатами и найденными отрывками.
- **Калибровка отказа.** Когда ответа нет в найденных отрывках, корректно ли система говорит «не знаю»? Измеряйте частоту ложной уверенности.
- **Полнота поиска.** Прежде чем оценивать ридер, измерьте, попадает ли верный отрывок в топ-`k` у ретривера. Ридер не может исправить отсутствующий отрывок.

### RAGAS: фреймворк оценивания для продакшена 2026 года

`RAGAS` создан специально для RAG-систем и является вариантом по умолчанию для продакшена в 2026 году. Он оценивает четыре измерения без необходимости в эталонных ответах:

- **Достоверность (Faithfulness).** Исходит ли каждое утверждение в ответе из найденного контекста? Измеряется через NLI-выводимость (entailment). Ваша основная метрика галлюцинаций.
- **Релевантность ответа.** Отвечает ли ответ на вопрос? Измеряется генерацией гипотетических вопросов из ответа и сравнением с реальным вопросом.
- **Точность контекста.** Какая доля найденных фрагментов действительно была релевантной? Низкая точность означает шум в промпте.
- **Полнота контекста.** Содержал ли найденный набор всю необходимую информацию? Низкая полнота означает, что ридер не может справиться.

Оценивание без эталона позволяет оценивать на реальном продакшен-трафике без размеченных эталонных ответов. Наложите поверх LLM как судью для открытых вопросов, где метрики точного совпадения бесполезны.

`pip install ragas`. Подключите свой ретривер и ридер. Получите четыре скаляра на запрос. Настройте оповещение о регрессиях.

## Применение

Стек 2026 года.

| Сценарий использования | Рекомендация |
|---------|-------------|
| Дан отрывок, найти фрагмент ответа | `deepset/roberta-base-squad2` |
| По фиксированному корпусу, закрытая книга неприемлема | RAG: плотный ретривер + LLM-ридер |
| В реальном времени по хранилищу документов | RAG с гибридным (BM25 + плотный) ретривером + реранкер (урок 14) |
| Диалоговый QA (уточняющие вопросы) | LLM с историей диалога + RAG на каждом ходе |
| Высокая фактическая точность, регулируемые домены | Экстрактивный подход по авторитетному корпусу; никогда не только генеративный |

Экстрактивный QA не в моде в 2026 году, потому что RAG с LLM покрывает больше случаев. Он всё ещё используется в контекстах, где требуется дословное цитирование: юридические исследования, регуляторное соответствие, инструменты аудита.

## Упражнения

1. **Лёгкое.** Настройте экстрактивный пайплайн SQuAD выше на 10 отрывках из Википедии. Вручную составьте 10 вопросов. Измерьте, как часто ответ верен. Вы должны увидеть 7–9 верных, если отрывки и вопросы чистые.
2. **Среднее.** Добавьте классификатор отказа. Когда верхняя оценка поиска ниже порога (скажем, 0.3 по косинусу), верните «не знаю» вместо вызова ридера. Настройте порог на отложенном наборе.
3. **Сложное.** Постройте RAG-пайплайн по корпусу из 10 000 документов по вашему выбору. Реализуйте гибридный поиск (BM25 + плотный) с RRF-слиянием (см. урок 14). Измерьте точность ответа с гибридным этапом и без него. Задокументируйте, какие типы вопросов выигрывают больше всего.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Экстрактивный QA | Найти фрагмент ответа | Предсказать начальный и конечный индексы ответа внутри данного отрывка. |
| QA открытого домена | QA по корпусу | Отрывок не дан; нужно сначала найти, затем ответить. |
| RAG | Сначала найти, потом сгенерировать | Генерация с дополнением поиском. Пайплайн ретривер + ридер. |
| SQuAD | Канонический бенчмарк | Stanford Question Answering Dataset. Метрики EM + F1. |
| Галлюцинация | Выдуманный ответ | Вывод ридера, не подтверждённый найденным контекстом. |
| Калибровка отказа | Знать, когда промолчать | Система корректно говорит «не знаю», когда не может ответить. |
