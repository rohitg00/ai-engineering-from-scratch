# Автоматическое реферирование текста

> Экстрактивные системы сообщают, что сказано в документе. Абстрактивные системы сообщают, что имел в виду автор. Разные задачи, разные подводные камни.

**Тип:** Практика
**Языки:** Python
**Предпосылки:** Фаза 5 · 02 (BoW + TF-IDF), Фаза 5 · 11 (Machine Translation)
**Время:** ~75 минут

## Проблема

В вашу ленту попадает новостная статья на 2000 слов. Вам нужны 120 слов, которые её передадут. Можно либо выбрать три самых важных предложения из статьи (экстрактивный подход), либо переписать содержание своими словами (абстрактивный подход). Оба называются реферированием. Это совершенно разные задачи.

Экстрактивное реферирование — это задача ранжирования. Оцените каждое предложение, верните верхние `k`. Вывод всегда грамматически корректен, потому что он взят дословно. Риск — упустить содержание, распределённое по всей статье.

Абстрактивное реферирование — это задача генерации. Трансформер производит новый текст, обусловленный входом. Вывод беглый и сжатый, но может галлюцинировать факты, которых не было в источнике. Риск — уверенная фабрикация.

Этот урок строит оба подхода вместе с режимом отказа, за который каждый отвечает.

## Концепция

![Экстрактивный TextRank против абстрактивного трансформера](../assets/summarization.svg)

**Экстрактивный.** Рассматривайте статью как граф, где узлы — предложения, а рёбра — сходства. Запустите PageRank (или что-то похожее) по графу, чтобы оценить предложения по тому, насколько они связаны со всем остальным. Предложения с наивысшей оценкой становятся рефератом. Каноническая реализация — **TextRank** (Михалча и Тарау, 2004).

**Абстрактивный.** Дообучите трансформерный энкодер-декодер (BART, T5, Pegasus) на парах документ-реферат. При инференсе модель читает документ и генерирует реферат токен за токеном через cross-attention. Pegasus, в частности, использует цель предобучения с пропуском предложений (gap-sentence pretraining), что делает его отличным для реферирования без большого дообучения.

Оценивание с помощью **ROUGE** (Recall-Oriented Understudy for Gisting Evaluation). ROUGE-1 и ROUGE-2 оценивают перекрытие униграмм и биграмм. ROUGE-L оценивает наибольшую общую подпоследовательность. Чем выше, тем лучше, но 40 ROUGE-L — «хорошо», а 50 — «исключительно». Каждая статья приводит все три метрики. Используйте пакет `rouge-score`.

## Реализация

### Шаг 1: TextRank (экстрактивный)

```python
import math
import re
from collections import Counter


def sentence_split(text):
    return re.split(r"(?<=[.!?])\s+", text.strip())


def similarity(s1, s2):
    w1 = Counter(s1.lower().split())
    w2 = Counter(s2.lower().split())
    intersection = sum((w1 & w2).values())
    denom = math.log(len(w1) + 1) + math.log(len(w2) + 1)
    if denom == 0:
        return 0.0
    return intersection / denom


def textrank(text, top_k=3, damping=0.85, iterations=50, epsilon=1e-4):
    sentences = sentence_split(text)
    n = len(sentences)
    if n <= top_k:
        return sentences

    sim = [[0.0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                sim[i][j] = similarity(sentences[i], sentences[j])

    scores = [1.0] * n
    for _ in range(iterations):
        new_scores = [1 - damping] * n
        for i in range(n):
            total_out = sum(sim[i]) or 1e-9
            for j in range(n):
                if sim[i][j] > 0:
                    new_scores[j] += damping * sim[i][j] / total_out * scores[i]
        if max(abs(s - ns) for s, ns in zip(scores, new_scores)) < epsilon:
            scores = new_scores
            break
        scores = new_scores

    ranked = sorted(range(n), key=lambda k: scores[k], reverse=True)[:top_k]
    ranked.sort()
    return [sentences[i] for i in ranked]
```

Стоит назвать две вещи. Функция сходства использует лог-нормализованное перекрытие слов — это оригинальный вариант TextRank. Косинус TF-IDF векторов тоже работает. Коэффициент затухания 0.85 и число итераций — стандартные значения PageRank по умолчанию.

### Шаг 2: абстрактивное реферирование с BART

```python
from transformers import pipeline

summarizer = pipeline("summarization", model="facebook/bart-large-cnn")

article = """(long news article text)"""

summary = summarizer(article, max_length=120, min_length=60, do_sample=False)
print(summary[0]["summary_text"])
```

BART-large-CNN дообучен на корпусе CNN/DailyMail. Он выдаёт рефераты в стиле новостей «из коробки». Для других доменов (научные статьи, диалоги, юридические тексты) используйте соответствующий чекпоинт Pegasus или дообучите на своих целевых данных.

### Шаг 3: оценивание с ROUGE

```python
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(["rouge1", "rouge2", "rougeL"], use_stemmer=True)
scores = scorer.score(reference_summary, generated_summary)
print({k: round(v.fmeasure, 3) for k, v in scores.items()})
```

Всегда используйте стемминг. Без него «running» и «run» считаются разными словами, и ROUGE недооценивает совпадения.

### За пределами ROUGE (оценивание реферирования в 2026 году)

ROUGE была доминирующей метрикой реферирования двадцать лет, и в 2026 году её одной уже недостаточно. Масштабный метаанализ статей по NLG показал:

- **BERTScore** (сходство контекстных эмбеддингов) набрала позиции к 2023 году и теперь приводится наряду с ROUGE в большинстве статей по реферированию.
- **BARTScore** рассматривает оценивание как генерацию: оценивает реферат по тому, насколько правдоподобным его считает предобученная BART при заданном источнике.
- **MoverScore** (расстояние Земляного Экскаватора (Earth Mover's Distance) над контекстными эмбеддингами) заняла первое место в бенчмарках реферирования 2025 года, потому что лучше улавливает семантическое перекрытие, чем ROUGE.
- **FactCC** и **QA-based faithfulness** были распространены в 2021–2023 годах, сейчас их часто заменяет **G-Eval** (цепочка промптов на базе GPT-4, оценивающая связность, согласованность, беглость, релевантность с помощью цепочки рассуждений).
- **G-Eval** и похожие подходы «LLM как судья» совпадают с человеческой оценкой примерно в 80% случаев при хорошо продуманных рубриках.

Рекомендация для продакшена: приводите ROUGE-L для сравнения с прошлыми результатами, BERTScore для семантического перекрытия, G-Eval для связности и фактической точности. Калибруйте на 50–100 рефератах с человеческой разметкой.

### Шаг 4: проблема фактической точности

Абстрактивные рефераты склонны к галлюцинациям. Экстрактивные рефераты несут гораздо более низкий риск галлюцинаций, потому что вывод взят дословно из источника, хотя они всё же могут вводить в заблуждение, если предложения источника вырваны из контекста, устарели или процитированы не по порядку. Это главная причина, по которой продакшен-системы всё ещё предпочитают экстрактивные методы для контента, близкого к комплаенсу.

Типы галлюцинаций, которые стоит назвать:

- **Подмена сущности.** Источник говорит «John Smith». Реферат говорит «John Brown».
- **Дрейф числа.** Источник говорит «25 000». Реферат говорит «25 миллионов».
- **Переворот полярности.** Источник говорит «отклонил предложение». Реферат говорит «принял предложение».
- **Изобретение факта.** Источник не упоминает CEO. Реферат утверждает, что CEO одобрил.

Работающие подходы к оцениванию:

- **FactCC.** Бинарный классификатор, обученный на выводимости (entailment) между предложением источника и предложением реферата. Предсказывает фактическое/нефактическое.
- **Фактическая точность на основе QA.** Задайте модели QA вопросы, ответы на которые есть в источнике. Если реферат подтверждает другие ответы — отметьте.
- **F1 на уровне сущностей.** Сравните именованные сущности в источнике и реферате. Сущности, присутствующие только в реферате, подозрительны.

Для всего, что видит пользователь и где важна фактическая точность (новости, медицина, юриспруденция, финансы), экстрактивный подход — более безопасный выбор по умолчанию. Абстрактивному нужна проверка фактической точности в цикле.

## Применение

Стек 2026 года:

| Сценарий использования | Рекомендация |
|---------|-------------|
| Новости, реферат из 3–5 предложений, английский | `facebook/bart-large-cnn` |
| Научные статьи | `google/pegasus-pubmed` или настроенная T5 |
| Многодокументное, длинноформатное | Любая LLM с контекстом 32k+, через промпт |
| Реферирование диалогов | `philschmid/bart-large-cnn-samsum` |
| Экстрактивное, низкий риск галлюцинаций по построению | TextRank или LSA / LexRank из `sumy` |

LLM с длинным контекстом в 2026 году часто превосходят специализированные модели, когда вычислительные ресурсы не ограничены. Компромисс — стоимость и воспроизводимость; специализированные модели дают более стабильный вывод.

Сохраните как `outputs/skill-summary-picker.md`:

```markdown
---
name: summary-picker
description: Pick extractive or abstractive, named library, factuality check.
version: 1.0.0
phase: 5
lesson: 12
tags: [nlp, summarization]
---

Given a task (document type, compliance requirement, length, compute budget), output:

1. Approach. Extractive or abstractive. Explain in one sentence why.
2. Starting model / library. Name it. `sumy.TextRankSummarizer`, `facebook/bart-large-cnn`, `google/pegasus-pubmed`, or an LLM prompt.
3. Evaluation plan. ROUGE-1, ROUGE-2, ROUGE-L (use rouge-score with stemming). Plus factuality check if abstractive.
4. One failure mode to probe. Entity swap is the most common in abstractive news summarization; flag samples where source entities do not appear in summary.

Refuse abstractive summarization for medical, legal, financial, or regulated content without a factuality gate. Flag input over the model's context window as needing chunked map-reduce summarization (not just truncation).
```

## Упражнения

1. **Лёгкое.** Запустите TextRank на 5 новостных статьях. Сравните топ-3 предложения с эталонным рефератом. Измерьте ROUGE-L. Вы должны увидеть 30–45 ROUGE-L на статьях в стиле CNN/DailyMail.
2. **Среднее.** Реализуйте фактическую точность на уровне сущностей: извлеките именованные сущности из источника и реферата (spaCy), вычислите полноту сущностей источника в реферате и точность сущностей реферата относительно источника. Высокая точность и низкая полнота означают безопасно, но кратко; низкая точность означает галлюцинированные сущности.
3. **Сложное.** Сравните BART-large-CNN с LLM (Claude или GPT-4) на 50 статьях CNN/DailyMail. Приведите ROUGE-L, фактическую точность (по F1 сущностей) и стоимость на реферат. Задокументируйте, где выигрывает каждый вариант.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Экстрактивный | Выбор предложений | Возврат предложений дословно из источника. Никогда не галлюцинирует. |
| Абстрактивный | Переписывание | Генерация нового текста, обусловленного источником. Может галлюцинировать. |
| ROUGE | Метрика реферата | Перекрытие n-грамм / LCS между выводом системы и эталоном. |
| TextRank | Экстрактивный на основе графа | PageRank по графу сходства предложений. |
| Фактическая точность | Правильно ли это | Подтверждены ли утверждения реферата источником. |
| Галлюцинация | Выдуманное содержание | Содержание в реферате, не подтверждённое источником. |
