# Механизм внимания — прорыв

> Декодер перестаёт щуриться на сжатую сводку и начинает смотреть на весь источник целиком. Всё, что будет дальше, — это внимание плюс инженерия.

**Тип:** Практика
**Языки:** Python
**Предпосылки:** Фаза 5 · 09 (Sequence-to-Sequence Models)
**Время:** ~45 минут

## Проблема

Урок 09 закончился размеренной неудачей. GRU-энкодер-декодер, обученный на игрушечной задаче копирования, идёт от 89% точности при длине 5 до почти случайного угадывания при длине 80. Причина структурная, а не баг обучения: вся информация, которую энкодер собрал, должна поместиться в одно скрытое состояние фиксированного размера, и декодер больше ничего не видит.

Бахданау, Чо и Бенджио опубликовали трёхстрочное решение в 2014 году. Вместо того чтобы давать декодеру только финальное состояние энкодера, сохраните все состояния энкодера. На каждом шаге декодера вычисляйте взвешенное среднее состояний энкодера, где веса отвечают на вопрос «насколько декодеру нужно смотреть на позицию энкодера `i` прямо сейчас?». Это взвешенное среднее и есть контекст, и оно меняется на каждом шаге декодера.

Это вся идея целиком. Трансформеры её расширили. Self-attention применило её к одной последовательности. Multi-head attention запустило её параллельно. Но версия 2014 года уже пробила бутылочное горлышко, и как только она у вас есть, переход к трансформерам — это инженерия, а не новая концепция.

## Концепция

![Внимание Бахданау: декодер запрашивает все состояния энкодера](../assets/attention.svg)

На каждом шаге декодера `t`:

1. Используйте предыдущее скрытое состояние декодера `s_{t-1}` как **запрос (query)**.
2. Сопоставьте его с каждым скрытым состоянием энкодера `h_1, ..., h_T`. Один скаляр на каждую позицию энкодера.
3. Примените softmax к оценкам, чтобы получить веса внимания `α_{t,1}, ..., α_{t,T}`, сумма которых равна 1.
4. Вектор контекста `c_t = Σ α_{t,i} * h_i`. Взвешенное среднее состояний энкодера.
5. Декодер берёт `c_t` вместе с предыдущим выходным токеном и выдаёт следующий токен.

Суть именно во взвешенном среднем. Когда декодеру нужно перевести «Je» как «I», он присваивает высокий вес состоянию энкодера на «Je» и низкий — остальным. Когда нужно «not», высокий вес получает «pas». Вектор контекста пересобирается на каждом шаге.

## Размерности (то, на чём спотыкаются все)

Именно здесь любая реализация внимания ломается в первый раз. Читайте медленно.

| Объект | Размерность | Примечания |
|-------|-------|-------|
| Скрытые состояния энкодера `H` | `(T_enc, d_h)` | Для BiLSTM `d_h = 2 * d_hidden` |
| Скрытое состояние декодера `s_{t-1}` | `(d_s,)` | Один вектор |
| Оценка внимания `e_{t,i}` | скаляр | По одной на позицию энкодера |
| Вес внимания `α_{t,i}` | скаляр | После softmax по всем `i` |
| Вектор контекста `c_t` | `(d_h,)` | Та же размерность, что и состояние энкодера |

**Оценка Бахданау (аддитивная).** `e_{t,i} = v_α^T * tanh(W_a * s_{t-1} + U_a * h_i)`.

- `s_{t-1}` имеет размерность `(d_s,)`, `h_i` — `(d_h,)`.
- `W_a` имеет размерность `(d_attn, d_s)`. `U_a` — `(d_attn, d_h)`.
- Их сумма внутри tanh имеет размерность `(d_attn,)`.
- `v_α` имеет размерность `(d_attn,)`. Скалярное произведение с `v_α` сворачивается в скаляр. **Именно это и делает `v_α`.** Никакой магии — это проекция, превращающая вектор размерности внимания в скалярную оценку.

**Оценка Луонга (мультипликативная).** Три варианта:

- `dot`: `e_{t,i} = s_t^T * h_i`. Требует `d_s == d_h`. Жёсткое ограничение. Пропустите, если ваш энкодер двунаправленный.
- `general`: `e_{t,i} = s_t^T * W * h_i` с `W` размерности `(d_s, d_h)`. Снимает ограничение на равенство размерностей.
- `concat`: по сути форма Бахданау. Используется редко, поскольку первые два варианта дешевле.

**Одна ловушка Бахданау / Луонга, которую стоит назвать явно.** Бахданау использует `s_{t-1}` (состояние декодера *до* генерации текущего слова). Луонг использует `s_t` (состояние *после*). Их путаница даёт тонко неверные градиенты, которые крайне трудно отладить. Выберите одну статью и придерживайтесь её соглашения.

## Реализация

### Шаг 1: аддитивное внимание (Бахданау)

```python
import numpy as np


def additive_attention(decoder_state, encoder_states, W_a, U_a, v_a):
    projected_dec = W_a @ decoder_state
    projected_enc = encoder_states @ U_a.T
    combined = np.tanh(projected_enc + projected_dec)
    scores = combined @ v_a
    weights = softmax(scores)
    context = weights @ encoder_states
    return context, weights


def softmax(x):
    x = x - np.max(x)
    e = np.exp(x)
    return e / e.sum()
```

Сверьте размерности с таблицей выше. `encoder_states` имеет размерность `(T_enc, d_h)`. `projected_enc` — `(T_enc, d_attn)`. `projected_dec` — `(d_attn,)` и участвует в broadcasting. `combined` — `(T_enc, d_attn)`. `scores` — `(T_enc,)`. `weights` — `(T_enc,)`. `context` — `(d_h,)`. Готово.

### Шаг 2: dot и general Луонга

```python
def dot_attention(decoder_state, encoder_states):
    scores = encoder_states @ decoder_state
    weights = softmax(scores)
    return weights @ encoder_states, weights


def general_attention(decoder_state, encoder_states, W):
    projected = W.T @ decoder_state
    scores = encoder_states @ projected
    weights = softmax(scores)
    return weights @ encoder_states, weights
```

По три строки каждый. Именно поэтому статья Луонга произвела впечатление. Та же точность на большинстве задач, но намного меньше кода.

### Шаг 3: разобранный числовой пример

Даны три состояния энкодера (условно «cat», «sat», «mat») и состояние декодера, которое сильнее всего согласуется с первым; распределение внимания концентрируется на позиции 0. Если состояние декодера смещается к согласованию с последним, внимание переходит на позицию 2. Вектор контекста следует за этим сдвигом.

```python
H = np.array([
    [1.0, 0.0, 0.2],
    [0.5, 0.5, 0.1],
    [0.1, 0.9, 0.3],
])

s_close_to_cat = np.array([0.9, 0.1, 0.2])
ctx, w = dot_attention(s_close_to_cat, H)
print("weights:", w.round(3))
```

```
weights: [0.464 0.305 0.231]
```

Побеждает первая строка. Теперь сдвиньте состояние декодера ближе к третьему состоянию энкодера и понаблюдайте, как смещаются веса. Вот и всё. Внимание — это явное выравнивание.

### Шаг 4: почему это мост к трансформерам

Переведите язык выше на термины Q/K/V:

- **Query (запрос)** = состояние декодера `s_{t-1}`
- **Key (ключ)** = состояния энкодера (то, с чем сопоставляем)
- **Value (значение)** = состояния энкодера (то, что взвешиваем и суммируем)

В классическом внимании ключи и значения — одно и то же. Self-attention их разделяет: можно запрашивать последовательность саму относительно себя, с разными обученными проекциями для K и V. Multi-head attention запускает это параллельно с разными обученными проекциями. Трансформеры стекируют весь этот этап много раз и отказываются от RNN.

Математика та же. Размерности те же. Педагогический переход от внимания Бахданау к масштабированному скалярному произведению (scaled dot-product attention) — это в основном вопрос нотации.

## Применение

PyTorch и TensorFlow поставляют внимание «из коробки».

```python
import torch
import torch.nn as nn

mha = nn.MultiheadAttention(embed_dim=128, num_heads=8, batch_first=True)
query = torch.randn(2, 5, 128)
key = torch.randn(2, 10, 128)
value = torch.randn(2, 10, 128)

output, weights = mha(query, key, value)
print(output.shape, weights.shape)
```

```
torch.Size([2, 5, 128]) torch.Size([2, 5, 10])
```

Это слой внимания трансформера. Пакет query из 5 позиций, пакет key/value из 10 позиций, размерность 128 каждая, 8 голов. `output` — это новые запросы, дополненные контекстом. `weights` — это матрица выравнивания 5×10, которую можно визуализировать.

### Когда классическое внимание всё ещё важно

- Педагогика. Однослойная, одноголовая, RNN-версия делает каждую концепцию видимой.
- Задачи над последовательностями на устройстве, где трансформеры не помещаются.
- Любая статья 2014–2017 годов. Вы неправильно её прочитаете, не зная соглашения Бахданау.
- Тонкий анализ выравнивания в машинном переводе. Сырые веса внимания остаются инструментом интерпретации даже на трансформерных моделях, и чтение их требует понимания, что они собой представляют.

### Ловушка «веса внимания как объяснение»

Веса внимания выглядят интерпретируемыми. Это веса, сумма которых по позициям равна единице; их можно построить на графике; высокое значение означает «смотрел сюда». Рецензенты их обожают.

Они не настолько интерпретируемы, как кажется. Джейн и Уоллес (2019) показали, что распределения внимания можно переставлять и заменять произвольными альтернативами без изменения предсказаний модели для некоторых задач. Никогда не приводите веса внимания как доказательство рассуждения без абляции или контрфактической проверки.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Внимание (Attention) | Смотреть на вещи | Взвешенное среднее последовательности значений, веса вычисляются из сходства запроса и ключа. |
| Query, Key, Value | QKV | Три проекции: Q спрашивает, K — то, с чем сопоставляют, V — то, что возвращают. |
| Аддитивное внимание | Бахданау | Оценка через прямой проход: `v^T tanh(W q + U k)`. |
| Мультипликативное внимание | Луонг dot / general | Оценка — это `q^T k` или `q^T W k`. Дешевле, та же точность на большинстве задач. |
| Матрица выравнивания | Красивая картинка | Веса внимания в виде сетки `(T_dec, T_enc)`. Читайте её, чтобы увидеть, на что смотрела модель. |
