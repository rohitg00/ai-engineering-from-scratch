# Связывание сущностей и разрешение неоднозначности

> NER нашёл «Paris». Связывание сущностей определяет, что имеется в виду: Париж во Франции, Paris Hilton, город Paris в Техасе или Парис, троянский царевич? Без связывания ваш граф знаний остаётся неоднозначным.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** этап 5 · 06 (NER), этап 5 · 24 (разрешение кореференции)
**Время:** ~60 минут

## Проблема

В предложении сказано: «Jordan одержал победу над прессой». Ваш NER присваивает «Jordan» метку PERSON. Хорошо. Но *какой* именно Jordan?

- Michael Jordan (баскетболист)?
- Michael B. Jordan (актёр)?
- Michael I. Jordan (профессор машинного обучения из Беркли — да, эта путаница действительно встречается в статьях по машинному обучению)?
- Jordan (страна)?
- Jordan (еврейское имя)?

Связывание сущностей (entity linking, EL) сопоставляет каждое упоминание с уникальной записью в базе знаний: Wikidata, Wikipedia, DBpedia или вашей доменной базе знаний. Две подзадачи:

1. **Генерация кандидатов.** Учитывая «Jordan», какие записи базы знаний правдоподобны?
2. **Разрешение неоднозначности.** С учётом контекста, какой кандидат правильный?

Оба шага обучаемы. Оба измеряются бенчмарками. Комбинированный конвейер стабилен уже десятилетие — меняется качество дизамбигуатора.

## Концепция

![Конвейер связывания сущностей: упоминание → кандидаты → сущность после разрешения неоднозначности](../assets/entity-linking.svg)

**Генерация кандидатов.** По поверхностной форме упоминания («Jordan») найдите кандидатов в индексе псевдонимов. Словари псевдонимов Wikipedia охватывают большинство именованных сущностей: «JFK» → John F. Kennedy, Jacqueline Kennedy, аэропорт JFK, «JFK» (фильм). Типичный индекс возвращает 10–30 кандидатов на упоминание.

**Разрешение неоднозначности: три подхода.**

1. **Приор (априорная вероятность) + контекст (Milne & Witten, 2008).** `P(entity | mention) × context-similarity(entity, text)`. Работает хорошо, быстро, без обучения.
2. **На основе эмбеддингов (ESS / REL / Blink).** Кодируется упоминание + контекст. Кодируется описание каждого кандидата. Выбирается максимальное косинусное сходство. Стандарт 2020–2024 годов.
3. **Генеративный (GENRE, 2021; на основе LLM, 2023+).** Декодирование канонического имени сущности токен за токеном. Ограничение согласно префиксному дереву (trie) допустимых имён сущностей гарантирует, что результат будет допустимым идентификатором базы знаний.

**Сквозные системы и конвейеры.** Современные модели (ELQ, BLINK, ExtEnD, GENRE) выполняют NER + генерацию кандидатов + разрешение неоднозначности за один проход. Конвейерные системы всё ещё доминируют в продакшене, потому что позволяют заменять компоненты.

### Два измерения

- **Полнота генерации кандидатов.** Доля эталонных упоминаний, для которых правильная запись базы знаний присутствует в списке кандидатов. Нижняя граница для всего конвейера.
- **Точность / F1 разрешения неоднозначности.** При правильных кандидатах — как часто топ-1 верен.

Всегда сообщайте оба значения. Система с 99% точностью разрешения неоднозначности при 80% полноте кандидатов — это конвейер с эффективностью 80%.

### Шаг 2: разрешение неоднозначности на основе контекста

```python
def disambiguate(mention, context, alias_index, entity_desc):
    candidates = alias_index.get(mention.lower(), [])
    if not candidates:
        return None, 0.0
    context_words = set(tokenize(context))
    best, best_score = None, -1
    for entity_id in candidates:
        desc_words = set(tokenize(entity_desc[entity_id]))
        union = len(context_words | desc_words)
        score = len(context_words & desc_words) / union if union else 0.0
        if score > best_score:
            best, best_score = entity_id, score
    return best, best_score
```

Пересечение Жаккара — это игрушечный пример. Замените его на косинусное сходство эмбеддингов (см. `code/main.py`, шаг 2, для версии с трансформером).

### Шаг 3: подход на основе эмбеддингов (в стиле BLINK)

```python
from sentence_transformers import SentenceTransformer
encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

def embed_mention(text, mention_span):
    start, end = mention_span
    marked = f"{text[:start]} [MENTION] {text[start:end]} [/MENTION] {text[end:]}"
    return encoder.encode([marked], normalize_embeddings=True)[0]

def embed_entity(entity_id, description):
    return encoder.encode([f"{entity_id}: {description}"], normalize_embeddings=True)[0]
```

Во время индексации каждая сущность базы знаний кодируется один раз. Во время запроса упоминание + контекст кодируются один раз, вычисляется скалярное произведение с пулом кандидатов, выбирается максимум.

### Шаг 4: генеративное связывание сущностей (концепция)

GENRE декодирует заголовок сущности в Wikipedia посимвольно. Ограниченное декодирование (см. урок 20) гарантирует, что могут быть выведены только валидные заголовки. Тесная интеграция с префиксным деревом (trie), опирающимся на базу знаний. Современный потомок — REL-GEN и EL с промптингом LLM и структурированным выводом.

```python
prompt = f"""Text: {text}
Mention: {mention}
List the best Wikipedia title for this mention.
Respond with JSON: {{"title": "..."}}"""
```

В сочетании с белым списком (Outlines `choice`) это самый простой конвейер EL для внедрения в 2026 году.

### Шаг 5: оценка на AIDA-CoNLL

AIDA-CoNLL — стандартный бенчмарк для EL: 1393 статьи Reuters, 34 тыс. упоминаний, сущности Wikipedia. Сообщайте точность в рамках базы знаний (`P@1`) и долю обнаружения NIL вне базы знаний.

## Ловушки

- **Обработка NIL.** Некоторые упоминания отсутствуют в базе знаний (новые сущности, малоизвестные люди). Системы должны предсказывать NIL вместо угадывания неправильной сущности. Измеряется отдельно.
- **Ошибки границ упоминания.** Вышестоящий NER пропускает частичные спаны («Bank of America» помечен только как «Bank»). Полнота EL падает.
- **Смещение к популярности.** Обученные системы слишком часто предсказывают популярные сущности. Упоминание «Michael I. Jordan» в статье по машинному обучению часто связывается с баскетболистом Michael Jordan.
- **Кросс-языковое EL.** Отображение упоминаний в китайском тексте на английские сущности Wikipedia. Требует многоязычного энкодера или этапа перевода.
- **Устаревание базы знаний.** Новые компании, события и люди отсутствуют в прошлогоднем дампе Wikipedia. Рабочим конвейерам нужен цикл обновления.

## Применение

Стек 2026 года:

| Ситуация | Выбор |
|-----------|------|
| Английский язык общего назначения + Wikipedia | BLINK или REL |
| Кросс-языковой сценарий, база знаний = Wikipedia | mGENRE |
| LLM-дружественный, мало упоминаний в день | Промпт для Claude/GPT-4 со списком кандидатов и ограниченным JSON |
| Доменная база знаний (медицина, право) | Кастомный BERT с поиском по базе знаний + дообучение на доменном наборе в стиле AIDA |
| Крайне низкая задержка | Только точное совпадение по приору (базовая линия Milne-Witten) |
| Передовые исследовательские решения | GENRE / ExtEnD / генеративное LLM-EL |

Рабочий шаблон, применяемый в 2026 году: NER → разрешение кореференции → EL для каждого упоминания → схлопывание каждого кластера в одну каноническую сущность. Результат: один идентификатор базы знаний на сущность в документе, а не один на упоминание.

```markdown
Given a use case (domain KB, language, volume, latency budget), output:

2. Candidate generator. Alias-index, embedding, or hybrid. Target mention recall @ K.

```

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
