# Оценивание длинного контекста — NIAH, RULER, LongBench, MRCR

> Gemini 3 Pro заявляет контекст в 10M токенов. При 1M токенов результат MRCR с 8 иголками падает до 26.3%. Заявленное ≠ пригодное для использования. Оценивание длинного контекста показывает реальную ёмкость модели, на которую вы полагаетесь в продакшене.

**Тип:** Learn
**Языки:** Python
**Предварительные требования:** Этап 5 · 13 (Ответы на вопросы), этап 5 · 23 (Стратегии разбиения на фрагменты)
**Время:** ~60 минут

## Проблема

У вас есть контракт на 200 страниц. Модель заявляет контекст в 1M токенов. Вы вставляете контракт целиком и спрашиваете: «Каково условие расторжения договора?» Модель отвечает — но отвечает по первой странице, потому что условие о расторжении находится на глубине 120k токенов, за пределами того, куда модель реально обращает внимание.

Это разрыв ёмкости контекста 2026 года. Спецификации говорят 1M или 10M. Реальность говорит, что пригодны 60-70% этого объёма, и «пригодность» зависит от задачи.

- **Поиск (одна иголка в стоге сена):** почти идеально вплоть до заявленного максимума на топовых моделях.
- **Многошаговые задачи / агрегация:** резко деградируют после ~128k на большинстве моделей.
- **Рассуждение по разрозненным фактам:** первая задача, которая проваливается.

Оценивание длинного контекста измеряет эти оси. Этот урок называет бенчмарки, что каждый из них на самом деле измеряет, и как построить кастомный тест-иголку для вашего домена.

## Концепция

![Базовый тест NIAH, многозадачный RULER и комплексный LongBench](../assets/long-context-eval.svg)

**Needle-in-a-Haystack (NIAH, 2023).** Разместите факт («волшебное слово — ананас») на контролируемой глубине в длинном контексте. Попросите модель найти его. Прогоните развёртку по глубине × длине. Оригинальный бенчмарк длинного контекста. Топовые модели сейчас насыщают этот тест; он необходим, но недостаточен в качестве базовой линии.

**RULER (Nvidia, 2024).** 13 типов задач в 4 категориях: поиск (одиночный / мульти-ключ / мульти-значение), многошаговая трассировка (отслеживание переменных), агрегация (частота общих слов), QA. Настраиваемая длина контекста (от 4k до 128k+). Выявляет модели, которые насыщают NIAH, но проваливаются на многошаговых задачах. В релизе 2024 года только половина из 17 моделей, заявлявших контекст 32k+, сохраняли качество на длине 32k.

**LongBench v2 (2024).** 503 вопроса с выбором ответа, контексты объёмом 8k-2M слов, шесть категорий задач: QA по одному документу, QA по нескольким документам, длинное обучение в контексте, длинный диалог, репозиторий кода, длинные структурированные данные. Продакшен-бенчмарк для реального поведения на длинном контексте.

**MRCR (Multi-Round Coreference Resolution).** Многоходовая кореференция в масштабе. Варианты с 8, 24 и 100 иголками. Показывает, сколько фактов модель может удерживать одновременно, прежде чем внимание деградирует.

**NoLiMa.** «Нелексическая иголка». Иголка и запрос не имеют буквального пересечения; поиск требует одного шага семантического рассуждения. Сложнее, чем NIAH.

**HELMET.** Конкатенирует множество документов, задаёт вопрос по любому из них. Проверяет избирательное внимание.

**BABILong.** Встраивает цепочки рассуждений bAbI внутрь нерелевантных стогов сена. Проверяет рассуждение-в-стоге-сена, а не только поиск.

### Что на самом деле нужно сообщать

- **Заявленное контекстное окно.** Число из спецификации.
- **Эффективная длина поиска.** Прохождение NIAH при некотором пороге (например, 90%).
- **Эффективная длина рассуждения.** Прохождение многошаговой задачи или агрегации при этом пороге.
- **Кривая деградации.** Точность в зависимости от длины контекста, построенная для каждого типа задачи.

Два числа для вашей спецификации: эффективная длина для поиска и эффективная длина для рассуждения. Обычно эффективная длина для рассуждения составляет 25-50% от заявленного окна.

## Постройте это

### Шаг 1: кастомный NIAH для вашего домена

См. `code/main.py`. Скелет:

```python
def build_haystack(filler_text, needle, depth_ratio, total_tokens):
    if not (0.0 <= depth_ratio <= 1.0):
        raise ValueError(f"depth_ratio must be in [0, 1], got {depth_ratio}")
    if total_tokens <= 0:
        raise ValueError(f"total_tokens must be positive, got {total_tokens}")

    filler_tokens = tokenize(filler_text)
    needle_tokens = tokenize(needle)
    if not filler_tokens:
        raise ValueError("filler_text produced no tokens")

    # Repeat filler until long enough to fill the haystack body.
    body_len = max(total_tokens - len(needle_tokens), 0)
    while len(filler_tokens) < body_len:
        filler_tokens = filler_tokens + filler_tokens
    filler_tokens = filler_tokens[:body_len]

    insert_at = min(int(body_len * depth_ratio), body_len)
    haystack = filler_tokens[:insert_at] + needle_tokens + filler_tokens[insert_at:]
    return " ".join(haystack)


def score_niah(model, haystack, question, expected):
    answer = model.complete(f"Context: {haystack}\nQ: {question}\nA:", max_tokens=50)
    return 1 if expected.lower() in answer.lower() else 0
```

Прогоните развёртку по `depth_ratio` ∈ {0, 0.25, 0.5, 0.75, 1.0} × `total_tokens` ∈ {1k, 4k, 16k, 64k}. Постройте тепловую карту. Это и есть карточка NIAH для вашей целевой модели.

### Шаг 2: вариант с несколькими иголками

```python
def build_multi_needle(filler, needles, total_tokens):
    depths = [0.1, 0.4, 0.7]
    chunks = [filler[:int(total_tokens * 0.1)]]
    for depth, needle in zip(depths, needles):
        chunks.append(needle)
        next_chunk = filler[int(total_tokens * depth): int(total_tokens * (depth + 0.3))]
        chunks.append(next_chunk)
    return " ".join(chunks)
```

Вопросы вроде «Каковы три волшебных слова?» требуют извлечения всех трёх. Успех с одной иголкой не предсказывает успех с несколькими.

### Шаг 3: многошаговая трассировка переменных (в стиле RULER)

```python
haystack = """X1 = 42. ... (filler) ... X2 = X1 + 10. ... (filler) ... X3 = X2 * 2."""
question = "What is X3?"
```

Ответ требует цепочки из трёх присваиваний. Топовые модели на 128k часто показывают здесь лишь 50-70% точности.

### Шаг 4: LongBench v2 на вашем стеке

```python
from datasets import load_dataset
longbench = load_dataset("THUDM/LongBench-v2")

def eval_model_on_longbench(model, subset="single-doc-qa"):
    tasks = [x for x in longbench["test"] if x["task"] == subset]
    correct = 0
    for x in tasks:
        answer = model.complete(x["context"] + "\n\nQ: " + x["question"], max_tokens=20)
        if normalize(answer) == normalize(x["answer"]):
            correct += 1
    return correct / len(tasks)
```

Сообщайте точность по каждой категории. Агрегированные оценки скрывают большие различия на уровне задач.

## Ловушки

- **Оценивание только по NIAH.** Прохождение NIAH на 1M токенов ничего не говорит о многошаговых задачах. Всегда запускайте RULER или кастомный многошаговый тест.
- **Равномерная выборка глубины.** Многие реализации тестируют только depth=0.5. Тестируйте depth=0, 0.25, 0.5, 0.75, 1.0 — эффект «потери в середине» реален.
- **Лексическое пересечение с наполнителем.** Если иголка разделяет ключевые слова с наполнителем, поиск становится тривиальным. Используйте неперекрывающиеся иголки в стиле NoLiMa.
- **Игнорирование задержки.** Предварительная обработка (prefill) промптов на 1M токенов занимает 30-120 секунд. Измеряйте время до первого токена наряду с точностью.
- **Числа, о которых заявляют вендоры.** OpenAI, Google, Anthropic — все публикуют собственные оценки. Всегда перепроверяйте независимо для своего сценария использования.

## Применение

Стек 2026 года:

| Ситуация | Бенчмарк |
|-----------|-----------|
| Быстрая проверка на вменяемость | Кастомный NIAH на 3 глубинах × 3 длинах |
| Выбор модели для продакшена | RULER (13 задач) на вашей целевой длине |
| Качество реального QA | Подмножество single-doc-QA из LongBench v2 |
| Многошаговое рассуждение | BABILong или кастомная трассировка переменных |
| Диалог / беседа | MRCR с 8 иголками на вашей целевой длине |
| Регрессия при обновлении модели | Фиксированный внутренний харнес NIAH + RULER, запускаемый на каждой новой модели |

Правило для продакшена: никогда не доверяйте контекстному окну, пока у вас нет NIAH + хотя бы одной задачи на рассуждение на нужной вам длине.

## Упражнения

1. **Лёгкое.** Постройте NIAH с 3 глубинами (0.25, 0.5, 0.75) × 3 длинами (1k, 4k, 16k). Запустите на любой модели. Постройте тепловую карту 3×3 для доли успеха.
2. **Среднее.** Добавьте вариант с 3 иголками. Измерьте извлечение всех трёх на каждой длине. Сравните с долей успеха для одной иголки на той же длине.
3. **Сложное.** Постройте задачу трассировки переменных (X1 → X2 → X3, 3 шага), встроенную в 64k наполнителя. Измерьте точность на 3 топовых моделях. Сообщите эффективную длину рассуждения для каждой модели.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| NIAH | Иголка в стоге сена | Поместите факт в наполнитель, попросите модель найти его. |
| RULER | NIAH на стероидах | 13 типов задач в категориях поиск / многошаговость / агрегация / QA. |
| Эффективный контекст | Реальная ёмкость | Длина, при которой точность всё ещё держится выше порога. |
| Потеря в середине | Смещение по глубине | Модели недостаточно обращают внимание на содержимое в середине длинных входов. |
| Несколько иголок | Много фактов одновременно | Несколько закладок; проверяет жонглирование вниманием, а не только поиск. |
| MRCR | Многораундовая кореференция | Кореференция с 8, 24 или 100 иголками; выявляет насыщение внимания. |
| NoLiMa | Нелексическая иголка | Иголка и запрос не имеют общих буквальных токенов; требует рассуждения. |
