# Roots и elicitation — определение области действия и ввод пользователя на лету

> Жёстко закодированные пути ломаются в тот момент, когда пользователь открывает другой проект. Предзаполненные аргументы инструментов ломаются, когда пользователь недостаточно точно формулирует запрос. Roots ограничивают сервер набором URI, контролируемым пользователем; elicitation приостанавливает вызов инструмента на середине, чтобы спросить у пользователя структурированный ввод через форму или URL. Два примитива клиента, два исправления для типичных отказов MCP. SEP-1036 (elicitation в режиме URL, 25.11.2025) экспериментален вплоть до первой половины 2026 года — проверяйте версии SDK, прежде чем на него полагаться.

**Тип:** Build**Языки:** Python (stdlib, roots + elicitation demo)**Предварительные требования:** Фаза 13 · 07 (MCP server)**Время:** ~45 минут
## Цели обучения

- Объявлять `roots` и реагировать на `notifications/roots/list_changed`.
- Ограничивать файловые операции сервера URI внутри объявленного набора roots.
- Использовать `elicitation/create`, чтобы запросить у пользователя подтверждение или структурированный ввод в середине вызова инструмента.
- Выбирать между elicitation в режиме формы и в режиме URL (второй экспериментален; отмечен риск устаревания).

## Проблема

Два конкретных отказа, с которыми сталкивается в продакшене MCP-сервер заметок.

**Ошибочное предположение о пути.** Сервер написан в расчёте на `~/notes`. Пользователь на другой машине с заметками в `~/Documents/Notes` получает вызов инструмента, который тихо проваливается (файл не найден) или, того хуже, записывает не в то место.

**Отсутствующий аргумент, который знал бы пользователь.** Пользователь просит «удали старую заметку про отчёт TPS». Модель вызывает `notes_delete(title: "TPS report")`, но есть три подходящие заметки за 2023, 2024 и 2025 годы. Инструмент не может угадать. Провалиться с «неоднозначно» — раздражает; выполнить для всех трёх — катастрофично.

Roots исправляют первую проблему: клиент объявляет при `initialize` набор URI, к которым серверу разрешено обращаться. Elicitation исправляет вторую: сервер приостанавливает вызов инструмента и отправляет `elicitation/create`, чтобы попросить пользователя выбрать нужную.

## Концепция

### Roots

Клиент объявляет список roots при `initialize`:

```json
{
  "capabilities": {"roots": {"listChanged": true}}
}
```

Затем сервер может вызвать `roots/list`:

```json
{"roots": [{"uri": "file:///Users/alice/Documents/Notes", "name": "Notes"}]}
```

Серверы ОБЯЗАНЫ рассматривать roots как границу: любое чтение или запись файла за пределами набора roots отклоняется. Это не принудительно обеспечивается клиентом (сервер по-прежнему остаётся кодом, которому доверился пользователь), но серверы, соответствующие спецификации, это соблюдают.

Когда пользователь добавляет или удаляет root, клиент отправляет `notifications/roots/list_changed`. Сервер заново вызывает `roots/list` и обновляет свою границу.

### Почему roots — это примитив клиента

Roots объявляются клиентом, потому что они представляют модель согласия пользователя. Пользователь сказал Claude Desktop: «дай этому серверу заметок доступ к этим двум каталогам». Сервер не может расширить эту область действия.

### Elicitation: режим формы по умолчанию

`elicitation/create` принимает схему формы плюс промпт на естественном языке:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Delete 'TPS report'? Multiple notes match; pick one.",
    "requestedSchema": {
      "type": "object",
      "properties": {
        "note_id": {
          "type": "string",
          "enum": ["note-3", "note-7", "note-14"]
        },
        "confirm": {"type": "boolean"}
      },
      "required": ["note_id", "confirm"]
    }
  }
}
```

Клиент рендерит форму, собирает ответ пользователя, возвращает:

```json
{
  "action": "accept",
  "content": {"note_id": "note-14", "confirm": true}
}
```

Три возможных действия: `accept` (пользователь заполнил), `decline` (пользователь закрыл её), `cancel` (пользователь прервал весь вызов инструмента).

Схемы формы плоские — вложенные объекты не поддерживаются в v1. SDK, как правило, отклоняют всё сложнее одного уровня.

### Elicitation: режим URL (SEP-1036, экспериментально)

Новое в 25.11.2025. Вместо схемы сервер отправляет URL:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Sign in to GitHub",
    "url": "https://github.com/login/oauth/authorize?client_id=..."
  }
}
```

Клиент открывает URL в браузере, ждёт завершения, возвращает результат, когда пользователь вернулся. Полезно для OAuth-потоков, авторизации платежей и подписания документов, где формы недостаточно.

Примечание о риске устаревания: форма ответа SEP-1036 всё ещё устаканивается; одни SDK возвращают callback-URL, другие — токен завершения. Прочитайте примечания к релизу вашего SDK, прежде чем использовать режим URL в продакшене.

### Когда elicitation — правильный инструмент

- Подтверждение пользователем перед деструктивными действиями (destructive hint + elicitation).
- Разрешение неоднозначности (выбор одного из N совпадений).
- Первоначальная настройка (API-ключи, каталоги, настройки).
- Потоки в стиле OAuth (режим URL).

### Когда elicitation — неправильный инструмент

- Заполнение обязательных аргументов инструмента, о которых модель могла бы спросить в тексте. Используйте обычный повторный запрос, а не диалог elicitation.
- Высокочастотные вызовы. Elicitation прерывает диалог; не запускайте его внутри цикла.
- Всё, что сервер мог бы проверить постфактум. Проверьте, верните ошибку, дайте модели спросить пользователя в тексте.

### Мост human-in-the-loop

Elicitation вместе с sampling обеспечивают модель «human-in-the-loop» MCP. Агентный цикл сервера может приостанавливаться либо для ввода пользователя (elicitation), либо для рассуждения модели (sampling). Phase 13 · 11 разбирала sampling; этот урок разбирает elicitation. Соедините их вместе для полного контроля в середине цикла.

```figure
t3-roots-boundary
```

## Практика

`code/main.py` расширяет сервер заметок следующим:

- Ответ `roots/list`, который сервер повторно запрашивает после уведомлений об изменении списка roots.
- Инструмент `notes_delete`, который использует `elicitation/create` для разрешения неоднозначности, когда совпадает несколько заметок.
- Инструмент `notes_setup`, который использует elicitation в режиме URL для открытия страницы первоначальной настройки (симулированной).
- Проверку границы, которая отклоняет операции над URI за пределами объявленных roots.

Демонстрация прогоняет три сценария: счастливый путь (одно совпадение), разрешение неоднозначности (три совпадения, срабатывает elicitation), запись за пределами root (отклоняется).

## Поставка

Этот урок производит `outputs/skill-elicitation-form-designer.md`. Учитывая инструмент, которому может понадобиться подтверждение пользователя или разрешение неоднозначности, навык проектирует схему формы elicitation и шаблон сообщения.

1. Запустите `code/main.py`. Запустите путь разрешения неоднозначности; убедитесь, что симулированный ответ пользователя маршрутизируется обратно в инструмент.

3. Реализуйте elicitation в режиме URL для первоначального потока OAuth. Отметьте риск устаревания и добавьте проверку версии SDK.

4. Расширьте обработку `roots/list`: когда приходит уведомление, сервер должен атомарно перечитать и пересканировать открытые файловые дескрипторы, которые теперь могут оказаться за пределами области действия.

5. Прочитайте обсуждение issue по SEP-1036 на GitHub. Определите один открытый вопрос, который влияет на то, как серверам следует обрабатывать callback'и режима URL.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| Root | «Граница согласия» | URI, к которому клиент разрешил серверу обращаться |
| `roots/list` | «Сервер запрашивает область действия» | Клиент возвращает текущий набор roots |
| `notifications/roots/list_changed` | «Пользователь изменил область действия» | Клиент сигнализирует, что набор roots изменился |
| Elicitation | «Спросить пользователя в середине вызова» | Инициированный сервером запрос структурированного ввода пользователя |
| `elicitation/create` | «Тот самый метод» | JSON-RPC-метод для запросов elicitation |
| Form mode | «Форма на основе схемы» | Плоская JSON Schema, отображаемая как форма в UI клиента |
| URL mode | «Редирект в браузер» | SEP-1036, экспериментально; открывает URL и ждёт |
| `accept` / `decline` / `cancel` | «Исходы ответа пользователя» | Три ветки, которые обрабатывает сервер |
| Disambiguation | «Выбрать одно» | Типичный сценарий использования elicitation, когда у инструмента N кандидатов |
| Flat form | «Только свойства верхнего уровня» | Схемы elicitation не могут быть вложенными |
