# Создание сервера MCP — SDK для Python и TypeScript

> Большинство туториалов по MCP показывают только hello-world на stdio. Настоящий сервер выставляет инструменты, ресурсы и промпты вместе, обрабатывает согласование возможностей, формирует структурированные ошибки и работает одинаково независимо от SDK. Этот урок собирает сервер заметок целиком: транспорт stdio на stdlib, диспетчеризацию JSON-RPC, три серверных примитива и стиль в виде чистых функций, который переносится либо в FastMCP из Python SDK, либо в TypeScript SDK, когда вы перерастёте базовый вариант.

**Тип:** Build**Языки:** Python (stdlib, stdio MCP server)**Предварительные требования:** Фаза 13 · 06 (MCP fundamentals)**Время:** ~75 минут
## Цели обучения

- Реализовать методы `initialize`, `tools/list`, `tools/call`, `resources/list`, `resources/read`, `prompts/list` и `prompts/get`.
- Написать диспетчерский цикл, который читает сообщения JSON-RPC из stdin и пишет ответы в stdout.
- Формировать структурированные ответы об ошибках согласно спецификации JSON-RPC 2.0 и дополнительным кодам MCP.
- Перевести реализацию на stdlib в FastMCP (Python SDK) или TypeScript SDK без переписывания логики инструментов.

## Проблема

Прежде чем использовать удалённый транспорт (Фаза 13 · 09) или слой авторизации (Фаза 13 · 16), нужен чистый локальный сервер. Локальный означает stdio: сервер порождается клиентом как дочерний процесс, сообщения идут по stdin/stdout с разделением по строкам.

Спецификация 2025-11-25 предписывает, что сообщения stdio кодируются как JSON-объекты с явным разделителем `\n`. Никакого SSE здесь; SSE был старым удалённым режимом и будет удалён к середине 2026 года (сервер Rovo MCP от Atlassian отказался от него 30 июня 2026 года; Keboola — 1 апреля 2026 года). Для stdio весь формат передачи данных — это один JSON-объект на строку.

Сервер заметок — удачная форма для урока, потому что он задействует все три серверных примитива. Инструменты выполняют мутации (`notes_create`). Ресурсы выставляют данные (`notes://{id}`). Промпты поставляют шаблоны (`review_note`). Форма этого урока обобщается на любую предметную область.

## Концепция

### Диспетчерский цикл

```
loop:
  line = stdin.readline()
  msg = json.loads(line)
  if has id:
    handle request -> write response
  else:
    handle notification -> no response
```

Три правила:

- Не печатать в stdout ничего, что не является конвертом JSON-RPC. Отладочные логи идут в stderr.
- Каждый запрос ДОЛЖЕН сопровождаться ответом с тем же `id`.
- На уведомления НЕЛЬЗЯ отвечать.

### Реализация `initialize`

```python
def initialize(params):
    return {
        "protocolVersion": "2025-11-25",
        "capabilities": {
            "tools": {"listChanged": True},
            "resources": {"listChanged": True, "subscribe": False},
            "prompts": {"listChanged": False},
        },
        "serverInfo": {"name": "notes", "version": "1.0.0"},
    }
```

Объявляйте только то, что поддерживаете. Клиент полагается на набор возможностей, чтобы включать или отключать функции.

### Реализация `tools/list` и `tools/call`

`tools/list` возвращает `{tools: [...]}`, где у каждой записи есть `name`, `description`, `inputSchema`. `tools/call` принимает `{name, arguments}` и возвращает `{content: [blocks], isError: bool}`.

Блоки контента типизированы. Самые распространённые:

```json
{"type": "text", "text": "Found 2 notes"}
{"type": "resource", "resource": {"uri": "notes://14", "text": "..."}}
{"type": "image", "data": "<base64>", "mimeType": "image/png"}
```

Ошибки инструментов бывают двух видов. Ошибки уровня протокола (неизвестный метод, некорректные параметры) — это ошибки JSON-RPC. Ошибки уровня инструмента (вызов корректен, но инструмент не справился) возвращаются как `{content: [...], isError: true}`. Это позволяет модели увидеть сбой прямо в своём контексте.

### Реализация ресурсов

Ресурсы по замыслу доступны только для чтения. `resources/list` возвращает манифест; `resources/read` возвращает содержимое. URI могут быть `file://...`, `http://...` или пользовательской схемой вроде `notes://`.

Когда стоит выставлять данные как ресурс, а не как инструмент:

- Модель не «вызывает» его; клиент может внедрить его в контекст по запросу пользователя.
- Подписки позволяют серверу проталкивать обновления при изменении ресурса (Phase 13 · 10).
- Phase 13 · 14 расширяет это схемой `ui://` для интерактивных ресурсов.

### Реализация промптов

Промпты — это шаблоны с именованными аргументами. Хост показывает их как слэш-команды. Промпт `review_note` может принимать аргумент `note_id` и производить многосообщенческий шаблон промпта, который клиент передаёт своей модели.

### Тонкости транспорта stdio

- JSON с разделением по строкам. Без фреймирования с префиксом длины.
- Не буферизовать. `sys.stdout.flush()` после каждой записи.
- Клиент управляет временем жизни. Когда stdin закрывается (EOF), выходить чисто.
- Не обрабатывать SIGPIPE молча; логировать и завершать работу.

### Аннотации

Каждый инструмент может нести `annotations`, описывающие свойства безопасности:

- `readOnlyHint: true` — чистое чтение, безопасно повторять.
- `destructiveHint: true` — необратимые побочные эффекты; клиент должен запросить подтверждение.
- `idempotentHint: true` — одинаковые входные данные дают одинаковые результаты.
- `openWorldHint: true` — взаимодействует с внешними системами.

Клиент использует это для выбора UX (диалоги подтверждения, индикаторы статуса) и маршрутизации (Phase 13 · 17).

### Путь перехода на SDK

Сервер на stdlib в `code/main.py` — около 180 строк. FastMCP (Python) сворачивает ту же логику в декораторный стиль:

```python
from fastmcp import FastMCP
app = FastMCP("notes")

@app.tool()
def notes_search(query: str, limit: int = 10) -> list[dict]:
    ...
```

У TypeScript SDK эквивалентная форма. Переход на SDK — это подстановка «как есть», когда вы будете готовы; концепции (возможности, диспетчеризация, блоки контента) остаются теми же.

```figure
t3-dispatch-loop
```

## Практика

`code/main.py` — полноценный сервер заметок MCP поверх stdio, только на stdlib. Он обрабатывает `initialize`, `tools/list`, `tools/call` для трёх инструментов (`notes_list`, `notes_search`, `notes_create`), `resources/list` и `resources/read` для каждой заметки, а также промпт `review_note`. Управлять им можно, передавая сообщения JSON-RPC по конвейеру:

```
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | python main.py
```

На что смотреть:

- Диспетчер — это `dict[str, Callable]` с ключом по имени метода.
- Каждый исполнитель инструмента возвращает список блоков контента, а не просто строку.
- `isError: true` устанавливается, когда исполнитель выбрасывает исключение.

## Упражнения

1. Запустите `code/main.py` и управляйте им, вручную формируя сообщения JSON-RPC. Задействуйте `notes_create`, затем `resources/read`, чтобы получить новую заметку.

2. Добавьте инструмент `notes_delete` с `annotations: {destructiveHint: true}`. Убедитесь, что клиент показал бы диалог подтверждения (для этого нужен реальный хост; подойдёт Claude Desktop).

3. Реализуйте `resources/subscribe`, чтобы сервер проталкивал `notifications/resources/updated` при каждом изменении заметки. Добавьте задачу keepalive.

4. Перенесите сервер на FastMCP. Файл на Python должен сократиться до менее чем 80 строк. Поведение на уровне передачи данных должно остаться идентичным; проверьте тем же тестовым набором JSON-RPC.

5. Прочитайте раздел `server/tools` спецификации и найдите одно поле определения инструмента, не реализованное в сервере этого урока. (Подсказка: их несколько; выберите одно и добавьте его.)

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| MCP server | «Штука, которая выставляет инструменты» | Процесс, говорящий на JSON-RPC поверх MCP по stdio или HTTP |
| stdio transport | «Модель дочернего процесса» | Сервер порождается клиентом; общение через stdin/stdout |
| Dispatcher | «Маршрутизатор методов» | Соответствие имени метода JSON-RPC функции-обработчику |
| Content block | «Кусок результата инструмента» | Типизированный элемент в массиве `content` ответа инструмента |
| `isError` | «Ошибка уровня инструмента» | Сигнализирует, что инструмент не справился; отличается от ошибки JSON-RPC |
| Annotations | «Подсказки безопасности» | Флаги readOnly / destructive / idempotent / openWorld |
| FastMCP | «Python SDK» | Декораторный фреймворк более высокого уровня поверх протокола MCP |
| Resource URI | «Адресуемые данные» | `file://`, `db://` или пользовательская схема, идентифицирующая ресурс |
| Prompt template | «Заготовка слэш-команды» | Шаблон от сервера со слотами для аргументов, предназначенный для UI хостов |
| Capability declaration | «Переключатель функции» | Флаги по каждому примитиву, объявляемые в `initialize` |
