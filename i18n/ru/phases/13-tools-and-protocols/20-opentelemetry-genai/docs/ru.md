# OpenTelemetry GenAI — трассировка вызовов инструментов от начала до конца

> Агент вызывает пять инструментов, три MCP-сервера и двух суб-агентов. Нужна единая трассировка для всего этого. Семантические соглашения OpenTelemetry GenAI (стабильные атрибуты в v1.37 и выше) — стандарт 2026 года, нативно поддерживаемый Datadog, Langfuse, Arize Phoenix, OpenLLMetry и AgentOps. В этом уроке называются обязательные атрибуты, разбирается иерархия спанов (агент → LLM → инструмент), и поставляется эмиттер спанов на stdlib, который можно подключить к любому экспортёру OTel.

**Тип:** Build**Языки:** Python (stdlib, OTel span emitter)**Предварительные требования:** Фаза 13 · 07 (MCP server), Фаза 13 · 08 (MCP client)**Время:** ~75 минут
## Цели обучения

- Назвать обязательные атрибуты OTel GenAI для спана LLM и спана выполнения инструмента.
- Построить иерархию трассировки, охватывающую цикл агента, вызов LLM, вызов инструмента и диспетчеризацию MCP-клиента.
- Решить, какое содержимое захватывать (опционально), а какое — редактировать/скрывать (по умолчанию).
- Отправлять спаны в локальный коллектор (Jaeger, Langfuse) без переписывания кода инструментов.

## Проблема

Отладка из февраля 2026 года: пользователь сообщает: «мой агент иногда отвечает 30 секунд, а иногда — 3 секунды». Трассировок нет. Логи показывают вызов LLM, но не диспетчеризацию инструмента, не обмен с MCP-сервером, не суб-агента. Вы гадаете. В итоге выясняется: один MCP-сервер иногда подвисает на холодном старте.

Без сквозной трассировки это не найти. OTel GenAI решает эту проблему.

Соглашения сложились в 2025–2026 годах в рамках группы семантических соглашений OpenTelemetry. Они определяют стабильные имена атрибутов, чтобы Datadog, Langfuse, Phoenix, OpenLLMetry и AgentOps одинаково разбирали одни и те же спаны. Инструментируйте один раз — поставляйте в любой бэкенд.

## Концепция

### Иерархия спанов

```
agent.invoke_agent  (top, INTERNAL span)
 ├── llm.chat       (CLIENT span)
 ├── tool.execute   (INTERNAL)
 │    └── mcp.call  (CLIENT span)
 ├── llm.chat       (CLIENT span)
 └── subagent.invoke (INTERNAL)
```

Всё это вложено под одним trace id. Span id связывают отношения родитель-потомок.

### Обязательные атрибуты

По семантическим соглашениям 2025–2026:

- `gen_ai.operation.name` — `"chat"`, `"text_completion"`, `"embeddings"`, `"execute_tool"`, `"invoke_agent"`.
- `gen_ai.provider.name` — `"openai"`, `"anthropic"`, `"google"`, `"azure_openai"`.
- `gen_ai.request.model` — строка запрошенной модели (например, `"gpt-4o-2024-08-06"`).
- `gen_ai.response.model` — модель, фактически обслужившая запрос.
- `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens`.
- `gen_ai.response.id` — идентификатор ответа провайдера для сопоставления.

Для спанов инструментов:

- `gen_ai.tool.name` — идентификатор инструмента.
- `gen_ai.tool.call.id` — идентификатор конкретного вызова.
- `gen_ai.tool.description` — описание инструмента (опционально).

Для спанов агентов:

- `gen_ai.agent.name` / `gen_ai.agent.id` / `gen_ai.agent.description`.

### Виды спанов

- `SpanKind.CLIENT` для вызовов, пересекающих границу процесса (провайдер LLM, MCP-сервер).
- `SpanKind.INTERNAL` для собственных шагов цикла агента и выполнения инструмента.

### Опциональный захват содержимого

По умолчанию спаны несут метрики и тайминги — не промпты и не завершения. Большие полезные нагрузки и персональные данные (PII) по умолчанию отключены. Установите `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` и специальные переменные окружения для захвата содержимого, чтобы включить его. Тщательно проверяйте перед включением в продакшене.

### События на спанах

Токен-уровневые события можно добавлять как события спана:

- `gen_ai.content.prompt` — входные сообщения.
- `gen_ai.content.completion` — выходные сообщения.
- `gen_ai.content.tool_call` — вызов инструмента, как он был зафиксирован.

События упорядочены по времени внутри спана для детального воспроизведения.

### Экспортёры

Спаны OTel экспортируются в:

- **Jaeger / Tempo.** Открытый код, on-prem.
- **Langfuse.** Специализирован на наблюдаемости LLM; визуализирует использование токенов.
- **Arize Phoenix.** Оценивание + трассировка вместе.
- **Datadog.** Коммерческий; нативно разбирает атрибуты `gen_ai.*`.
- **Honeycomb.** Колоночно-ориентированный; удобен для запросов.

Все говорят на OTLP — проводном формате. Вашему коду это безразлично.

### Распространение через MCP

Когда MCP-клиент вызывает сервер, внедрите заголовок W3C traceparent в запрос. Streamable HTTP поддерживает стандартные заголовки. Stdio не переносит HTTP-заголовки нативно; дорожная карта спецификации на 2026 год обсуждает добавление поля `_meta.traceparent` в вызовы JSON-RPC.

Пока это не реализовано: включайте traceparent в `_meta` каждого запроса вручную. Сервер логирует trace id.

### Метрики

Наряду со спанами семантические соглашения GenAI определяют метрики:

- `gen_ai.client.token.usage` — гистограмма.
- `gen_ai.client.operation.duration` — гистограмма.
- `gen_ai.tool.execution.duration` — гистограмма.

Используйте их для дашбордов, которым не нужна детализация по каждому вызову.

### Слой AgentOps

AgentOps (основана в 2024 году) специализируется на наблюдаемости GenAI. Она оборачивает популярные фреймворки (LangGraph, Pydantic AI, CrewAI), автоматически генерируя спаны OTel. Полезна, если ваш стек использует поддерживаемый фреймворк; в остальных случаях используйте ручную инструментацию.

```figure
t3-span-waterfall
```

## Практика

`code/main.py` выводит в stdout спаны в форме OTel (в формате, похожем на OTLP-JSON) для агента, который вызывает LLM, диспетчеризует два инструмента и делает один обмен с MCP-сервером. Реального экспортёра нет — урок фокусируется на форме спанов и наборе атрибутов. Вставьте вывод в OTLP-совместимый просмотрщик или просто прочитайте его.

На что смотреть:

- Trace id общий для всех спанов.
- Связи родитель-потомок закодированы через `parentSpanId`.
- Обязательные атрибуты `gen_ai.*` заполнены.
- Захват содержимого по умолчанию выключен; один сценарий включает его через переменную окружения.

## Поставка

Этот урок производит `outputs/skill-otel-genai-instrumentation.md`. По кодовой базе агента навык производит план инструментации: где добавить спаны, какие атрибуты заполнить и на какие экспортёры ориентироваться.

## Упражнения

1. Запустите `code/main.py`. Посчитайте спаны и определите, какие из них CLIENT, а какие INTERNAL.

2. Включите захват содержимого (переменная окружения) и убедитесь, что появляются события `gen_ai.content.prompt` и `gen_ai.content.completion`. Отметьте последствия для персональных данных (PII).

3. Добавьте метрику выполнения инструмента `gen_ai.tool.execution.duration` и отправляйте её как образец гистограммы на каждый вызов.

4. Распространите traceparent из родительского спана агента в поле `_meta.traceparent` запроса MCP. Убедитесь, что MCP-сервер увидит тот же trace id.

5. Прочитайте спецификацию семантических соглашений OTel GenAI. Найдите один атрибут, перечисленный в спецификации, который код этого урока НЕ генерирует. Добавьте его.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|----------------|------------------------|
| OTel | «OpenTelemetry» | Открытый стандарт для трассировок, метрик и логов |
| GenAI semconv | «Семантические соглашения GenAI» | Стабильные имена атрибутов для спанов LLM / инструментов / агентов |
| `gen_ai.*` | «Пространство имён атрибутов» | Все атрибуты GenAI используют этот префикс |
| Span | «Измеряемая операция» | Единица работы с началом, концом и атрибутами |
| Trace | «Межспановое родство» | Дерево спанов, разделяющих один trace id |
| SpanKind | «CLIENT / SERVER / INTERNAL» | Подсказки о направлении спана |
| OTLP | «OpenTelemetry Line Protocol» | Проводной формат для экспортёров |
| Opt-in content | «Захват промптов / завершений» | Выключено по умолчанию; включается переменной окружения |
| traceparent | «Заголовок W3C» | Распространяет контекст трассировки между сервисами |
| Exporter | «Специфичный для бэкенда отправитель» | Компонент, отправляющий спаны в Jaeger / Datadog / и т. д. |
