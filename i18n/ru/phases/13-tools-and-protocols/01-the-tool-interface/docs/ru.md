# Интерфейс инструмента — зачем агентам структурированный ввод-вывод

> Языковая модель производит токены. Программа совершает действия. Разрыв между этими двумя вещами закрывает интерфейс инструмента: контракт, который позволяет модели запросить действие, а хосту — выполнить его. Каждый стек 2026 года — вызов функций в OpenAI, Anthropic и Gemini; `tools/call` в MCP; части задач в A2A — это своя кодировка одного и того же цикла из четырёх шагов. Этот урок называет этот цикл и показывает минимальный набор механизмов, чтобы его запустить.

**Тип:** Learn
**Языки:** Python (стандартная библиотека, без LLM)
**Предварительные требования:** Фаза 11 (API завершений LLM)
**Время:** ~45 минут

## Цели обучения

- Объяснять, почему LLM, способная только генерировать текст, не может самостоятельно совершать действия в реальном мире.
- Изображать цикл вызова инструмента из четырёх шагов (описать → решить → выполнить → наблюдать) и называть, кто отвечает за каждый шаг.
- Записывать описание инструмента как три части: имя, JSON Schema для входных данных и детерминированную функцию-исполнитель.
- Различать чистые (pure) и вызывающие побочные эффекты (consequential) инструменты и объяснять, почему это разделение важно для безопасности.

## Проблема

LLM выдаёт распределение вероятностей для следующего токена. Это вся поверхность её вывода. Если спросить чат-модель «какая сейчас погода в Бангалоре», она может написать правдоподобное предложение, но не может дозвониться до API погоды. Предложение может оказаться верным по совпадению или устаревшим на три дня.

Закрытие этого разрыва — назначение интерфейса инструмента. Хост-программа — ваша среда выполнения агента, Claude Desktop, ChatGPT, Cursor или собственный скрипт — объявляет модели список доступных инструментов. Когда модель решает, что нужно действие, она выдаёт структурированную полезную нагрузку с именем инструмента и его аргументами. Хост разбирает эту нагрузку, реально запускает инструмент и возвращает результат обратно в модель. Цикл продолжается, пока модель не решит, что больше вызовов не требуется.

Первая версия этого контракта появилась в июне 2023 года как параметр «functions» у OpenAI. Anthropic последовала за ним блоками `tool_use` в Claude 2.1. Gemini добавила `functionDeclarations` несколько месяцев спустя. Теперь каждый провайдер выставляет одну и ту же форму: на входе — список инструментов, типизированный JSON Schema, на выходе — JSON-нагрузка вызова инструмента. Model Context Protocol (ноябрь 2024) обобщил контракт так, что один реестр инструментов обслуживает любую модель. A2A (апрель 2026, версия 1.0) наложил тот же примитив для делегирования между агентами.

Цикл из четырёх шагов — это инвариант, лежащий в основе всего перечисленного. Всё остальное в Фазе 13 — развитие этой идеи.

## Концепция

### Шаг первый: описать

Хост объявляет каждый инструмент тремя полями.

- **Имя.** Стабильный, машиночитаемый идентификатор. `get_weather`, а не «штука с погодой».
- **Описание.** Краткий абзац на естественном языке. «Использовать, когда пользователь спрашивает о текущих условиях для конкретного города. Не использовать для исторических данных».
- **Схема входных данных.** Объект JSON Schema (редакция 2020-12), описывающий аргументы инструмента.

Модель получает этот список. Современные провайдеры сериализуют эти объявления в системный промпт по собственному шаблону, поэтому вызывающая сторона имеет дело только со структурированной формой.

### Шаг второй: решить

Учитывая сообщение пользователя и доступные инструменты, модель выбирает одно из трёх поведений.

1. **Ответить напрямую** текстом. Без вызова инструмента.
2. **Вызвать один или несколько инструментов.** Выдать структурированные объекты вызова. При `parallel_tool_calls: true` (включено по умолчанию у OpenAI и Gemini, включается опционально у Anthropic) модель может выдать несколько вызовов за один ход.
3. **Отказаться.** Строгий режим структурированного вывода может выдать типизированный блок `refusal` вместо вызова.

Полезная нагрузка вызова инструмента имеет три стабильных поля: идентификатор вызова `id`, имя инструмента `name` и объект аргументов `arguments` в формате JSON. Идентификатор существует, чтобы хост мог сопоставить более поздний результат с конкретным вызовом — это важно, когда параллельные вызовы возвращаются не по порядку.

### Шаг третий: выполнить

Хост получает вызов, проверяет аргументы по объявленной схеме и запускает исполнитель. Некорректные аргументы означают, что модель галлюцинировала поле или использовала неверный тип — очень распространённый режим отказа на слабых моделях. Продакшен-хосты в ответ на некорректные аргументы делают одно из трёх: быстро завершаются с ошибкой и показывают её модели, чинят JSON ограниченным парсером или повторяют запрос к модели, включив ошибку валидации в промпт.

Сам исполнитель — обычный код. Python, TypeScript, команда оболочки, запрос к базе данных. Он производит результат, обычно строку, но это может быть любое значение JSON или структурированный блок содержимого (текст, изображение или ссылка на ресурс в MCP). Результат должен быть сериализуемым.

### Шаг четвёртый: наблюдать

Хост добавляет результат инструмента в разговор (как сообщение с ролью `tool` и соответствующим `id`) и повторно вызывает модель. Теперь у модели есть вывод инструмента в контексте, и она может выдать итоговый ответ или запросить ещё вызовы. Это продолжается, пока модель не перестанет выдавать вызовы или пока хост не упрётся в предохранитель по числу итераций.

### Разделение по доверию

Инструменты бывают двух видов, важных для безопасности.

- **Чистые (pure).** Только чтение, детерминированные, без побочных эффектов. `get_weather`, `search_docs`, `get_current_time`. Безопасно вызывать спекулятивно.
- **С последствиями (consequential).** Изменяют состояние, тратят деньги, затрагивают данные пользователя. `send_email`, `delete_file`, `execute_trade`. Должны быть под контролем.

«Правило двух» (Rule of Two) Meta для безопасности агентов 2026 года гласит: в одном ходе можно сочетать не более двух из следующего: недоверенный ввод, чувствительные данные, действие с последствиями. Интерфейс инструмента — это место, где вы обеспечиваете соблюдение этого правила: отклоняя вызовы, требуя подтверждения пользователя или повышая области доступа (scope). Полную главу по безопасности см. в Фазе 13 · 15, а политики разрешений на уровне агента — в Фазе 14 · 09.

### Где живёт цикл

| Контекст | Кто описывает | Кто принимает решение | Кто выполняет |
|---------|---------------|-------------|--------------|
| Однооходовый вызов функций (OpenAI/Anthropic/Gemini) | Разработчик приложения | LLM | Разработчик приложения |
| MCP | MCP-сервер | LLM через MCP-клиент | MCP-сервер |
| A2A | Издатель Agent Card | Вызывающий агент | Вызываемый агент |
| Веб-браузер (агент с вызовом функций) | Расширение браузера / WebMCP | LLM | Среда выполнения браузера |

Везде одни и те же четыре шага. Меняются названия столбцов, структура — нет.

### Почему не просто попросить модель выдать JSON?

«Попросить модель ответить в JSON» — это паттерн, использовавшийся до появления вызова функций. Он не срабатывает примерно в 5–15 процентах случаев на топовых моделях и значительно чаще на моделях поменьше. Режимы отказа включают отсутствующие фигурные скобки, лишние запятые, галлюцинированные поля и неверные типы. После этого нужен проход починки JSON, повтор запроса или ограниченный декодер.

Нативный вызов функций лучше по трём причинам. Во-первых, провайдер обучает модель сквозным образом на точную форму вызова, поэтому доля валидного JSON поднимается до 98–99 процентов в строгом режиме. Во-вторых, полезная нагрузка вызова размещается в собственном слоте протокола, а не внутри свободного текста — поэтому вызов инструмента никогда не просачивается в ответ, видимый пользователю. В-третьих, провайдеры обеспечивают соответствие схеме через ограниченное декодирование (строгий режим OpenAI, `tool_use` у Anthropic, `responseSchema` у Gemini). Гарантируется, что вывод пройдёт валидацию.

### Предохранители

Цикл завершается, когда модель перестаёт выдавать вызовы или хост упирается в максимальное число ходов. Продакшен-хосты устанавливают его в диапазоне от 5 до 20 ходов. Сверх этого вы почти наверняка находитесь в цикле, из которого модель не может выйти. Claude Code по умолчанию ставит 20; OpenAI Assistants — 10; агентный режим Cursor — 25.

Альтернатива — неограниченные циклы — раз в полгода всплывает в разборах инцидентов вида «агент потратил $400 на вызовы API за ночь». Не выпускайте продукт без такого ограничения.

## Применяем

`code/main.py` запускает цикл из четырёх шагов без LLM. Фиктивная функция принятия решения имитирует модель, сопоставляя сообщение пользователя с шаблонами; исполнитель, валидатор схемы и обвязка шага наблюдения — настоящие. Запустите его, чтобы увидеть полную хореографию запросов и ответов с выводом промежуточного состояния, а затем замените фиктивную функцию принятия решения на любого реального провайдера в одном из следующих уроков.

На что обратить внимание:

- Реестр инструментов хранит три поля на инструмент: имя, описание, схему и ссылку на исполнитель.
- Валидатор — это минимальное подмножество JSON Schema (типы, required, enum, min/max), написанное только на stdlib. Фаза 13 · 04 поставляет более полный.
- Цикл ограничивает число итераций пятью. Продакшен-агентам нужен именно такой предохранитель.

## Публикуем

Этот урок производит `outputs/skill-tool-interface-reviewer.md`. Получив черновик определения инструмента (имя + описание + схема + план исполнителя), скилл проверяет его пригодность для цикла: стабильно ли машиночитаемое имя, является ли описание полным брифом по использованию, корректно ли схема использует JSON Schema 2020-12, и явно ли указана классификация «чистый / с последствиями».

## Упражнения

1. Добавьте четвёртый инструмент в `code/main.py` под названием `get_stock_price(ticker)`. Напишите его описание как «Использовать, когда пользователь спрашивает текущую цену акции по тикеру. Не использовать для исторических цен или обзоров рынка». Запустите обвязку и убедитесь, что фиктивная функция принятия решения направляет запросы, упоминающие тикеры, к новому инструменту.

2. Сломайте валидатор схемы. Передайте вызов, у которого в объекте `arguments` отсутствует обязательное поле, и убедитесь, что хост отклоняет его до выполнения. Затем передайте вызов с лишним неизвестным полем. Решите: должен ли хост отклонять его или игнорировать? Обоснуйте выбор аргументом безопасности.

3. Классифицируйте каждый инструмент в обвязке как чистый или с последствиями. Добавьте флаг `consequential: true` к записям реестра, которым он нужен, и измените цикл так, чтобы он печатал строку «запросить подтверждение пользователя», когда выбран инструмент с последствиями. Это форма шлюза подтверждения, который нужен каждому продакшен-хосту.

4. Нарисуйте на бумаге цикл из четырёх шагов, заполнив приведённую выше таблицу столбцов провайдеров для вашего любимого клиента (Claude Desktop, Cursor, ChatGPT или собственный стек). Сверьтесь со специфичным для MCP вариантом в Фазе 13 · 06.

5. Прочитайте руководство OpenAI по вызову функций от начала до конца. Найдите единственное поле, которое присутствует в запросе, но не входит в цикл из четырёх шагов в том виде, как он представлен здесь. Объясните, что оно добавляет и почему оно скорее удобно, чем необходимо.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Инструмент | «Штука, которую может вызвать модель» | Тройка из имени + входных данных, типизированных JSON Schema, + функции-исполнителя |
| Вызов функций | «Нативное использование инструментов» | Поддержка на уровне API провайдера для выдачи структурированных вызовов инструментов вместо прозы |
| Вызов инструмента | «Запрос модели на действие» | JSON-нагрузка с полями `id`, `name`, `arguments`, выданная моделью |
| Результат инструмента | «То, что вернул инструмент» | Вывод исполнителя, обёрнутый в сообщение с ролью `tool` и совпадающим идентификатором |
| Параллельные вызовы инструментов | «Много вызовов сразу» | Несколько объектов вызова за один ход модели, независимых и упорядочиваемых по идентификатору |
| Строгий режим | «Гарантированный JSON» | Ограниченное декодирование, заставляющее вывод модели проходить валидацию по объявленной схеме |
| Чистый инструмент | «Инструмент только для чтения» | Без побочных эффектов; безопасно перезапускать |
| Инструмент с последствиями | «Инструмент действия» | Изменяет внешнее состояние; требует шлюза, аудита или подтверждения пользователя |
| Цикл из четырёх шагов | «Цикл вызова инструмента» | описать → решить → выполнить → наблюдать |
| Хост | «Среда выполнения агента» | Программа, которая хранит реестр инструментов, вызывает модель и запускает исполнитель |
