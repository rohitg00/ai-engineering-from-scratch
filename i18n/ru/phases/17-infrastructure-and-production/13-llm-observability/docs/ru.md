# Выбор стека наблюдаемости для больших языковых моделей (LLM)

> Рынок наблюдаемости 2026 года делится на две категории. Платформы для разработки (LangSmith, Langfuse, Comet Opik) объединяют мониторинг с оцениванием, управлением промптами и воспроизведением сессий. Шлюзы и инструменты инструментирования (Helicone, SigNoz, OpenLLMetry, Phoenix) сосредоточены на телеметрии. Langfuse имеет ядро под лицензией MIT и хорошо сбалансирован как продукт с открытым исходным кодом (50K событий в месяц в бесплатном облаке). Phoenix изначально построен на OpenTelemetry и распространяется по Elastic License 2.0 — отлично подходит для визуализации дрейфа и генерации с дополнением поиском (RAG), но не является постоянным продакшен-бэкендом. Arize AX использует интеграцию с Iceberg/Parquet без копирования и заявляет о стоимости в 100 раз ниже монолитной наблюдаемости. LangSmith лидирует для LangChain/LangGraph, $39 за пользователя в месяц, самостоятельное развёртывание доступно только в тарифе Enterprise. Helicone работает через прокси, настройка занимает 15-30 минут, 100K запросов в месяц бесплатно, но глубина трассировки агентов у него меньше. Типичный продакшен-паттерн: шлюз (Helicone/Portkey) + платформа оценивания (Phoenix/TruLens), связанные через OpenTelemetry.

**Тип:** Learn
**Языки:** Python (stdlib, игрушечный симулятор сэмплирования трасс)
**Предварительные требования:** этап 17 · 08 («Метрики инференса»), этап 14 («Инженерия агентов»)
**Время:** ~60 минут

## Цели обучения

- Отличать платформы для разработки (объединяющие оценивание + промпты + сессии) от шлюзов и инструментов телеметрии (только трассы + метрики).
- Сопоставить шесть основных инструментов (Langfuse, LangSmith, Phoenix, Arize AX, Helicone, Opik) с их лицензированием, ценообразованием и оптимальными сценариями использования.
- Объяснить паттерн склейки через OpenTelemetry, который позволяет сочетать шлюз с отдельной платформой оценивания.
- Назвать ключевое ценовое отличие 2026 года (подход Arize AX без копирования в сравнении с монолитной загрузкой данных) и указать примерный множитель в 100 раз.

## Проблема

Вы выкатили функцию на LLM. Она работает. Но у вас нет видимости в сбои промптов, циклы вызовов инструментов, регрессии задержки, скачки затрат или долю попаданий в кеш промптов. Вы ищете в Google «наблюдаемость LLM» и получаете восемь инструментов, каждый из которых утверждает, что решает одну и ту же задачу, по трём разным ценам.

На самом деле они решают разные задачи. LangSmith отвечает на вопрос «почему упал этот запуск LangGraph?». Phoenix отвечает на вопрос «дрейфует ли мой RAG-конвейер?». Helicone отвечает на вопрос «какое приложение сжигает токены?». Langfuse отвечает на вопрос «могу ли я развернуть всё это у себя?». Разные инструменты — разная аудитория.

Выбор идёт по четырём осям: стек (LangChain? прямое использование SDK? несколько провайдеров?), приемлемые лицензии (только MIT? Elastic допустима? коммерческая лицензия подходит?), бюджет (бесплатный план? $100 в месяц? $1000 в месяц?) и самостоятельное развёртывание (обязательно? желательно? исключено?).

## Концепция

### Две категории

**Платформы для разработки** объединяют наблюдаемость с оцениванием, управлением промптами, версионированием наборов данных и воспроизведением сессий. Вы запускаете эксперименты, смотрите, какой промпт сработал, и проверяете новый промпт на регрессию по набору данных против прежних победителей. LangSmith, Langfuse, Comet Opik.

**Шлюзы и инструменты телеметрии** инструментируют вызовы инференса — промпт, ответ, токены, задержку, модель, стоимость. Helicone, SigNoz, OpenLLMetry, Phoenix. Минималистичны. Можно сочетать с отдельным инструментом оценивания через OpenTelemetry.

### Langfuse — баланс открытого исходного кода

- Ядро под лицензией Apache / MIT; самостоятельное развёртывание через Docker.
- Бесплатный план в облаке: 50K событий в месяц. Платный: $29 в месяц для команды.
- Оценивание, управление промптами, трассы, наборы данных. Достойное покрытие всех четырёх функций платформы для разработки.
- Оптимально: вам нужны возможности уровня LangSmith, но требуется самостоятельное развёртывание или лицензия с открытым исходным кодом.

### Phoenix (Arize) — телеметрия прежде всего, изначально на OpenTelemetry

- Elastic License 2.0; самостоятельное развёртывание тривиально.
- Отлично справляется с визуализацией RAG и дрейфа. Диаграммы рассеяния пространства векторных представлений (эмбеддингов) поставляются как полноценная функция.
- Не предназначен для использования в качестве постоянного продакшен-бэкенда — в первую очередь это наблюдаемость на этапе разработки.
- Оптимально: разработка RAG-конвейера, отладка дрейфа, работа в паре с отдельным шлюзом для продакшена.

### Arize AX — ставка на масштаб

- Коммерческий. Интеграция с озером данных без копирования через Iceberg/Parquet.
- Заявляет о цене примерно в 100 раз ниже монолитной наблюдаемости (уровня Datadog) при масштабе. Логика простая: вы храните трассы в собственном Parquet на S3; Arize читает их напрямую.
- Оптимально: >10M трасс в день, уже есть озеро данных, нужны специализированные дашборды для LLM без цен уровня Datadog.

### LangSmith — прежде всего LangChain/LangGraph

- Коммерческий, $39 за пользователя в месяц. Самостоятельное развёртывание только в тарифе Enterprise.
- Лучший в своём классе для стеков LangChain и LangGraph. Если вы не используете ни то, ни другое, он менее привлекателен.
- Оптимально: команда, привязанная к LangChain и готовая платить.

### Helicone — минимально жизнеспособный вариант на основе прокси

- Настройка за 15-30 минут — достаточно заменить `OPENAI_API_BASE` на прокси Helicone.
- Лицензия MIT; 100K запросов в месяц бесплатно, платный тариф от $20 в месяц.
- Включает переключение при сбоях, кеширование, ограничение частоты запросов — также работает как шлюз.
- Меньше глубины по трассам агентов и многошаговым процессам.
- Оптимально: быстрый старт, приложение на одном стеке, нужны шлюз и наблюдаемость в одном месте.

### Opik (Comet) — платформа для разработки с открытым исходным кодом

- Apache 2.0, полностью с открытым исходным кодом.
- Набор функций похож на Langfuse, но с наследием Comet.
- Оптимально: ML-команды, уже использующие Comet и желающие получить наблюдаемость LLM в той же панели.

### SigNoz — полноценный APM с упором на OpenTelemetry

- Apache 2.0. Обрабатывает общий APM и LLM через OpenTelemetry.
- Оптимально: единая наблюдаемость по сервисам и вызовам LLM.

### Клей: OpenTelemetry + семантические соглашения GenAI

В конце 2025 года OpenTelemetry опубликовал семантические соглашения GenAI (`gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`). Инструменты, которые потребляют OTel, могут взаимодействовать друг с другом. Формируется следующий продакшен-паттерн:

1. Отправлять OTel с соглашениями GenAI на каждом вызове LLM.
2. Направлять в шлюз (Helicone / Portkey) для повседневной работы.
3. Параллельно отправлять данные на платформу оценивания (Phoenix / Langfuse) для отслеживания регрессий.
4. Архивировать данные в озере данных (Iceberg) для долгосрочного анализа через Arize AX или DuckDB.

### Ловушка: инструментирование не на том уровне

Инструментирование внутри вашего агентного фреймворка (например, добавление трасс LangSmith) привязывает вас к этому фреймворку. Инструментирование на уровне HTTP/OpenAI-SDK (через OpenLLMetry или ваш шлюз) переносимо.

### Сэмплирование — нельзя хранить всё

При >1M запросов в день полное хранение трасс стоит дороже, чем сами вызовы LLM. Сэмплируйте по правилам: 100% ошибок, 100% дорогих запросов, 5% успешных запросов. Агрегаты храните всегда, а необработанные данные — для длинного хвоста.

### Числа, которые стоит запомнить

- Бесплатное облако Langfuse: 50K событий в месяц.
- LangSmith: $39 за пользователя в месяц.
- Helicone бесплатно: 100K запросов в месяц.
- Заявление Arize AX: примерно в 100 раз дешевле монолитных решений при масштабе.
- Соглашения OpenTelemetry GenAI: выпущены в 2025, широко приняты в 2026.

## Упражнения

1. Ваша команда работает на LangChain и хочет наблюдаемость с открытым исходным кодом и самостоятельным развёртыванием. Выберите Langfuse или Opik и обоснуйте выбор.
2. При 5M трасс в день и цене Datadog $150K в месяц вычислите точку безубыточности для Arize AX.
3. Спроектируйте набор атрибутов OpenTelemetry GenAI, который стандарт вашей организации должен предписывать для каждого вызова LLM.
4. Обоснуйте, достаточно ли одного Phoenix для продакшена. Когда его недостаточно?
5. Helicone добавляет 20 мс накладных расходов на прокси. Приемлемо ли это при P99 TTFT 300 мс? А если SLA составляет 100 мс?

## Ключевые термины

| Термин | Как его называют | Что он означает на самом деле |
|--------|------------------|-------------------------------|
| OpenLLMetry | «OTel для LLM» | Инструментирование LLM с открытым исходным кодом на базе OpenTelemetry |
| Соглашения GenAI | «атрибуты OTel» | Стандартные имена атрибутов OTel для вызовов LLM |
| LangSmith | «наблюдаемость LangChain» | Коммерческая платформа, интегрированная с экосистемой LangChain |
| Langfuse | «LangSmith с открытым исходным кодом» | Продукт с открытым исходным кодом под лицензией MIT и похожим набором функций |
| Phoenix | «инструмент Arize для разработки» | Платформа разработки и оценивания, изначально построенная на OpenTelemetry |
| Arize AX | «наблюдаемость в большом масштабе» | Коммерческая наблюдаемость Iceberg/Parquet без копирования данных |
| Helicone | «наблюдаемость через прокси» | HTTP-прокси, который собирает телеметрию LLM и предоставляет функции шлюза |
| Opik | «Comet для LLM» | Платформа разработки с открытым исходным кодом от Comet под лицензией Apache 2.0 |
| Воспроизведение сессии | «повторный запуск трассы» | Воспроизведение полной сессии агента вместе с вызовами инструментов |
| Оценивание | «офлайн-тест» | Запуск модели или промпта-кандидата на размеченном наборе данных |
