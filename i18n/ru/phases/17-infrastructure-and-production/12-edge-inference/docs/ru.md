# Инференс на периферии — Apple Neural Engine, Qualcomm Hexagon, WebGPU/WebLLM, Jetson

> Главное ограничение на периферии — не вычисления, а пропускная способность памяти. Мобильная DRAM держится на уровне 50-90 GB/s; датацентровая HBM3 выдаёт 2-3 TB/s — разрыв в 30-50x. Декодирование ограничено пропускной способностью памяти, поэтому этот разрыв оказывается решающим. В 2026 году ландшафт делится на четыре направления. Apple M4/A18 Neural Engine достигает пика в 38 TOPS с унифицированной памятью (без копирования между CPU и NPU). Qualcomm Snapdragon X Elite / 8 Gen 4 Hexagon выдаёт 45 TOPS. WebGPU + WebLLM запускает Llama 3.1 8B (Q4) на скорости ~41 tok/s на M3 Max (примерно 70-80% от нативной производительности); 17.6k звёзд на GitHub, OpenAI-совместимый API, ~70-75% покрытия мобильных устройств. NVIDIA Jetson Orin Nano Super (8GB) вмещает Llama 3.2 3B / Phi-3; AGX Orin запускает gpt-oss-20b через vLLM на скорости ~40 tok/s; Jetson T4000 (JetPack 7.1) вдвое быстрее AGX Orin. TensorRT Edge-LLM поддерживает EAGLE-3, NVFP4, предварительное заполнение фрагментами — это было показано на CES 2026 компаниями Bosch, ThunderSoft и MediaTek.

## Проблема

Клиент хочет чат-бот на устройстве: голосовой в первую очередь, приватный по умолчанию, работающий офлайн. На MacBook Pro M3 Max Llama 3.1 8B Q4 работает на скорости ~55 tok/s — нормально. На iPhone 16 Pro та же модель выдаёт 3 tok/s — уже не нормально. На среднебюджетном Android со Snapdragon 8 Gen 3 — 7 tok/s. В браузере через WebGPU на Chrome Android v121+ — 4-8 tok/s в зависимости от устройства.

Такой разброс пропускной способности — не проблема переноса. Это произведение разрыва в пропускной способности памяти, формата квантования и того, доступен ли NPU из пользовательского пространства. Инференс на периферии в 2026 году — это четыре разные задачи с четырьмя разными решениями.

## Концепция

### Пропускная способность памяти — реальный потолок

Декодирование считывает полный набор весов на каждый токен. Одна модель 7B в Q4 весит 3.5 GB. Чтение 3.5 GB на скорости 50 GB/s занимает 70 мс — теоретический потолок ~14 tok/s. При 90 GB/s (высокопроизводительная мобильная DRAM) потолок поднимается до ~25 tok/s. Никакие вычислительные мощности не помогут превысить этот предел.

Датацентровая HBM3 на скорости 3 TB/s считывает те же 3.5 GB за 1.2 мс — потолок составляет 830 tok/s. Та же модель, те же веса. Другая подсистема памяти.

### Apple Neural Engine (M4 / A18)

- До 38 TOPS. Унифицированная память (CPU и ANE используют один и тот же пул) — без затрат на копирование.
- Доступ через Core ML и скомпилированные модели `.mlmodel`, либо через Metal Performance Shaders (MPS) из PyTorch.
- Бэкенд Llama.cpp для Metal использует MPS, а не ANE напрямую; для нативного ANE требуется конвертация в Core ML.
- Лучший практический путь для iOS-приложений в 2026 году: Core ML с весами INT4 + активациями FP16.

### Qualcomm Hexagon (Snapdragon X Elite / 8 Gen 4)

- До 45 TOPS. Интегрирован с CPU и GPU в составе SoC, но имеет отдельный домен памяти.
- QNN (Qualcomm Neural Network) SDK и AI Hub обеспечивают конвертацию из PyTorch/ONNX.
- Шаблоны чата, Llama 3.2, Phi-3 — всё это поставляется как полноценные артефакты на AI Hub.

### NPU от Intel и AMD (Lunar Lake, Ryzen AI 300)

- 40-50 TOPS. Программная поддержка отстаёт от Apple/Qualcomm; OpenVINO развивается, но остаётся нишевым решением.
- Лучше всего подходит для приложений-помощников на Windows ARM; нативно на десктопах AMD/Intel для сценариев с локальной обработкой по умолчанию.

### WebGPU + WebLLM

- Запуск моделей в браузере через вычислительные шейдеры WebGPU; без установки.
- Llama 3.1 8B Q4 на скорости ~41 tok/s на M3 Max — примерно 70-80% от нативной производительности на том же бэкенде.
- 17.6k звёзд на GitHub у WebLLM; OpenAI-совместимый JS API; лицензия Apache 2.0.
- Покрытие в 2026 году: Chrome Android v121+, общедоступная версия Safari iOS 26, Firefox Android всё ещё догоняет. В целом ~70-75% покрытия мобильных устройств.

### Семейство NVIDIA Jetson

- Orin Nano Super (8GB): вмещает Llama 3.2 3B, Phi-3 с хорошей скоростью tok/s.
- AGX Orin: запускает gpt-oss-20b через vLLM на скорости ~40 tok/s.
- Thor / T4000 (JetPack 7.1): производительность вдвое выше AGX Orin, поддерживаются EAGLE-3 и NVFP4.
- TensorRT Edge-LLM (2026) поддерживает спекулятивное декодирование EAGLE-3, веса NVFP4, предварительное заполнение фрагментами — датацентровые оптимизации, перенесённые на периферию.

### Выбор формата квантования для каждой платформы

| Целевая платформа | Формат | Примечания |
|--------|--------|-------|
| Apple ANE | Веса INT4 + активации FP16 | Путь конвертации через Core ML |
| Qualcomm Hexagon | QNN INT8 / INT4 | Конвертеры AI Hub |
| WebGPU / WebLLM | Q4 MLC (q4f16_1) | Используйте `mlc_llm convert_weight` + скомпилированный `.wasm`; GGUF не поддерживается |
| Jetson Orin Nano | Q4 GGUF или TRT-LLM INT4 | Ограничено пропускной способностью памяти |
| Jetson AGX / Thor | NVFP4 + FP8 KV | Путь через Edge-LLM |

### Ловушка длинного контекста на периферии

Контекст в 128K у Llama 3.1 — это датацентровая функция. На телефоне с 8 GB RAM: модель 4 GB + 2 GB KV-кеша для 32K токенов + накладные расходы ОС = OOM. Развёртывания на периферии удерживают контекст в диапазоне 4K-8K, если только не принято агрессивное квантование KV (Q4 KV).

### Голос — ключевой сценарий использования

Голосовые агенты чувствительны к задержке: время до первого токена должно быть < 500 мс. Локальный инференс полностью устраняет сетевую задержку. В сочетании с распознаванием речи (варианты Whisper Turbo работают на периферии) периферийный инференс превращается в голосовой цикл продакшен-качества.

### Числа, которые стоит запомнить

- Apple M4 / A18 ANE: 38 TOPS.
- Qualcomm Hexagon SD X Elite: 45 TOPS.
- WebLLM на M3 Max: ~41 tok/s на Llama 3.1 8B Q4.
- AGX Orin: ~40 tok/s на gpt-oss-20b через vLLM.
- Разрыв в пропускной способности памяти между датацентром и периферией: 30-50x.
- Покрытие WebGPU на мобильных устройствах: ~70-75% (Firefox Android отстаёт).

## Применение

`code/main.py` вычисляет теоретические потолки пропускной способности декодирования на основе расчётов, ограниченных пропускной способностью памяти, для разных периферийных платформ. Сравнивает их с наблюдаемыми бенчмарками и показывает, где узким местом становится пропускная способность памяти, а не вычисления.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| ANE | «Apple Neural Engine» | Встроенный NPU в устройствах серий M и A; унифицированная память |
| Hexagon | «NPU Qualcomm» | NPU в Snapdragon; доступ через QNN SDK |
| WebGPU | «GPU в браузере» | Стандартизированный W3C браузерный API для GPU; Chrome/Safari в 2026 году |
| WebLLM | «браузерная среда выполнения LLM» | Проект MLC-LLM; Apache 2.0; OpenAI-совместимый JS API |
| Jetson | «периферийная платформа NVIDIA» | Семейство Orin Nano / AGX / Thor / T4000 |
| TRT Edge-LLM | «TensorRT для периферии» | Перенос TensorRT-LLM на периферию в 2026 году; EAGLE-3 + NVFP4 |
| Унифицированная память | «общий пул» | CPU и NPU обращаются к одной и той же RAM; без затрат на копирование |
| Ограничение пропускной способностью памяти | «ограничено памятью» | Скорость декодирования определяется объёмом весов, считываемым за секунду |
| Core ML | «конвертация для Apple» | Фреймворк Apple для моделей, нативно работающих на ANE |
| QNN | «стек Qualcomm» | Qualcomm Neural Network SDK |
