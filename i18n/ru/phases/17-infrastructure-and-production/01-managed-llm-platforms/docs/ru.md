# Управляемые LLM-платформы — Bedrock, Vertex AI, Azure OpenAI

> Три гиперскейлера (hyperscaler) — три разные стратегии. AWS Bedrock — это маркетплейс моделей: Claude, Llama, Titan, Stability, Cohere за одним API. Azure OpenAI — эксклюзивное партнёрство с OpenAI плюс Provisioned Throughput Units (PTU) для выделенной мощности. Vertex AI — платформа, ориентированная прежде всего на Gemini, с лучшей поддержкой длинного контекста и мультимодальности. В 2026 году Artificial Analysis измеряет медианную задержку Azure OpenAI на уровне ~50 мс, а Bedrock — на уровне ~75 мс на эквивалентах Llama 3.1 405B — PTU объясняют этот разрыв, потому что выделенная мощность превосходит общую мощность по требованию (on-demand). Правило принятия решения — не «что быстрее», а «какой каталог моделей и какая поверхность FinOps подходят моему продукту». Этот урок учит выбирать, опираясь на явно выписанные компромиссы, а не на интуицию.

**Тип:** Обучение
**Языки:** Python (стандартная библиотека, учебный компаратор стоимости и задержки)
**Предварительные требования:** Этап 11 (инженерия LLM), этап 13 (инструменты и протоколы)
**Время:** ~60 минут

## Цели обучения

- Назовите три стратегии платформ (маркетплейс, эксклюзивность, ориентация прежде всего на Gemini) и сопоставьте каждую со сценарием использования в продукте.
- Объясните, что дают Provisioned Throughput Units (PTU) в Azure OpenAI и почему Bedrock по требованию (on-demand) обычно показывает задержку примерно на 25 мс выше на масштабе 405B.
- Изобразите поверхность атрибуции FinOps для каждой платформы (Bedrock Application Inference Profiles против модели «проект на команду» в Vertex против областей Azure + резервирований PTU).
- Сформулируйте политику «минимум два провайдера» и объясните, почему привязка к одному поставщику (vendor lock-in) — дорогая ошибка в 2026 году.

## Проблема

Вы выбрали Claude 3.7 Sonnet для своего продукта. Теперь его нужно обслуживать. Можно вызывать Anthropic API напрямую, можно — через AWS Bedrock, а можно — через шлюз (gateway). Прямой API проще всего; Bedrock добавляет BAA, VPC-эндпоинты, IAM и атрибуцию через CloudWatch. Шлюз добавляет аварийное переключение (failover), единый биллинг и ограничение частоты запросов между провайдерами.

Более глубокий вопрос — это каталог. Если вам нужны Claude, Llama и Gemini в одном продукте, вы не купите их всех в одном месте — разве что этим местом одновременно являются Bedrock, Vertex и Azure OpenAI. Гиперскейлеры не взаимозаменяемы: каждый сделал свою ставку на то, кто владеет модельным слоем.

Этот урок сопоставляет три ставки, разрыв в задержке, разрыв в FinOps и риск привязки к поставщику.

## Концепция

### Три стратегии

**AWS Bedrock** — маркетплейс. Claude (Anthropic), Llama (Meta), Titan (собственная модель AWS), Stability (изображения), Cohere (эмбеддинги), Mistral, плюс подкаталоги изображений и эмбеддингов. Один API, одна поверхность IAM, один экспорт в CloudWatch. Ставка Bedrock в том, что клиентам важнее вариативность выбора, чем единственная модель.

**Azure OpenAI** — эксклюзивное партнёрство. Вы получаете GPT-4 / 4o / 5 / серию o, DALL·E, Whisper и дообучение моделей OpenAI в дата-центрах Azure. В каталоге «Azure OpenAI Service» нет моделей не от OpenAI — они относятся к Azure AI Foundry (отдельному продукту). Ставка Azure в том, что OpenAI останется на переднем крае, а клиентам нужен корпоративный контроль именно над этими отношениями.

**Vertex AI** — сначала Gemini, всё остальное — потом. Gemini 1.5 / 2.0 / 2.5 Flash и Pro, плюс Model Garden (сторонние модели). Ставка Vertex — мультимодальность и длинный контекст: контекст Gemini на 1 млн токенов — это отличительная черта.

### Разрыв в задержке на масштабе

Artificial Analysis непрерывно проводит бенчмарки. На эквивалентных развёртываниях Llama 3.1 405B (общая мощность по требованию) медианная задержка до первого токена у Azure OpenAI — около 50 мс; у Bedrock — около 75 мс. Этот разрыв — не провал AWS, а разница в модели ёмкости. Azure продаёт PTU (Provisioned Throughput Units), которые резервируют GPU-мощность для вашего арендатора (tenant). У Bedrock есть эквивалент (Provisioned Throughput), но он стоит от ~$21 в час за единицу, и большинство клиентов остаются на общей мощности по требованию.

Общая мощность по требованию конкурирует с трафиком всех остальных клиентов. Выделенная мощность — нет. Если ваш SLA по продукту требует TTFT < 100 мс на P99, вы либо покупаете PTU в Azure, либо покупаете Bedrock Provisioned Throughput, либо принимаете стандартный разброс задержки.

### Экономика Provisioned Throughput

Azure PTU: зарезервированный блок вычислений для инференса. Экономия до ~70% по сравнению с оплатой по требованию для предсказуемых нагрузок. Стоимость фиксирована по часам независимо от трафика — вы платите за резерв, даже когда он простаивает. Точка безубыточности обычно достигается примерно при 40-60% устойчивой загрузки.

Bedrock Provisioned Throughput: $21-$50 в час в зависимости от модели и региона. Похожая математика: точка безубыточности — примерно половина от пиковой загрузки. Требуется месячное обязательство.

Выделенная мощность Vertex продаётся по SKU для каждой модели Gemini; цена зависит от модели и региона и рекламируется публично в меньшей степени.

### Поверхность FinOps — главное отличие

**Bedrock Application Inference Profiles** — самая чистая атрибуция затрат в маркетплейсе. Вы помечаете профиль тегами `team`, `product`, `feature`, направляете через него все вызовы моделей, а CloudWatch разбивает затраты по профилям без постобработки. Добавлено в 2025 году, всё ещё самый детальный нативный механизм среди гиперскейлеров.

**Vertex** строит атрибуцию по схеме «проект на команду» плюс метки везде. Вы моделируете каждую команду как отдельный проект GCP, расставляете метки на всех ресурсах и используете BigQuery Billing Export + DataStudio для сводных отчётов. Работы больше, но BigQuery даёт произвольные SQL-запросы к данным о затратах.

**Azure** опирается на области подписок и групп ресурсов плюс теги, а резервирования PTU выступают полноценным объектом учёта затрат. Теги наследуются от групп ресурсов, а не от запросов, поэтому атрибуция на уровне запроса требует пользовательских метрик Application Insights или шлюза, который проставляет заголовки.

Закономерность: у Bedrock самая чистая нативная атрибуция, Vertex — самый гибкий вариант через BigQuery, Azure — самый непрозрачный, если не настроить инструментирование.

### Привязка к поставщику — риск 2026 года

Обязательства перед единственным гиперскейлером были нормальны, пока доминировала одна модель. В 2026 году передний край смещается ежемесячно: один квартал — Claude 3.7, следующий — Gemini 2.5, ещё через квартал — GPT-5. Привязка к одной платформе отрезает вас от двух третей переднего края.

Паттерн, который берут на вооружение работающие команды: минимум два провайдера для любого продуктово-критичного вызова LLM. Bedrock плюс Azure OpenAI — распространённая пара: Claude из одного, GPT из другого, аварийное переключение между ними, один и тот же шлюз. Рост затрат незначителен, потому что шлюз маршрутизирует оптимально; выигрыш в доступности при сбоях (как инцидент Azure OpenAI в январе 2025 года, отключение региона AWS us-east-1) — решающий.

### Резидентность данных, BAA и регулируемые отрасли

Bedrock: BAA в большинстве регионов; VPC-эндпоинты; защитные ограничения (guardrails). Частый выбор по умолчанию в финтехе.
Azure OpenAI: HIPAA, SOC 2, ISO 27001; резидентность данных в ЕС; выбор по умолчанию для регулируемых корпоративных заказчиков.
Vertex: HIPAA, GDPR, резидентность данных по регионам; стек комплаенса Google Cloud.

Все три платформы закрывают базовый чек-лист требований. Различия — в политиках хранения данных, в том, как обрабатываются логи, и в том, читает ли ваш трафик мониторинг злоупотреблений (abuse monitoring) (по умолчанию включён у большинства; для корпоративных клиентов доступен отказ).

### Цифры, которые нужно запомнить

- Медианный TTFT Azure OpenAI на эквивалентах Llama 3.1 405B: ~50 мс (с PTU).
- Медианный TTFT Bedrock по требованию: ~75 мс.
- Bedrock Provisioned Throughput: $21-$50/час за единицу.
- Точка безубыточности Azure PTU: ~40-60% устойчивой загрузки.
- Экономия PTU по сравнению с оплатой по требованию при высокой загрузке: до 70%.

`code/main.py` сравнивает три платформы на синтетической нагрузке — моделирует экономику оплаты по требованию и PTU, разброс TTFT и точность атрибуции затрат. Запустите его, чтобы увидеть, где PTU окупаются, а где широта модельного каталога маркетплейса перевешивает разрыв в TTFT.

## Поставка

Этот урок производит `outputs/skill-managed-platform-picker.md`. По профилю нагрузки (нужные модели, SLA по TTFT, дневной объём, требования комплаенса) он рекомендует основную платформу, резервный вариант и план инструментирования FinOps.

## Ключевые термины

| Термин | Как его обычно называют | Что он означает на самом деле |
|------|----------------|------------------------|
| Bedrock | «LLM-сервис AWS» | Маркетплейс моделей Claude, Llama, Titan, Mistral и Cohere |
| Azure OpenAI | «ChatGPT от Azure» | Эксклюзивные модели OpenAI в дата-центрах Azure с корпоративными средствами управления |
| Vertex AI | «LLM от Google» | Платформа, ориентированная прежде всего на Gemini, с Model Garden для сторонних моделей |
| PTU | «выделенная мощность» | Provisioned Throughput Unit — зарезервированные GPU для инференса с почасовой оплатой |
| Application Inference Profile | «теги Bedrock» | Нативный для CloudWatch профиль затрат и использования с тегами для отдельного продукта |
| Model Garden | «каталог Vertex» | Раздел сторонних моделей в Vertex AI, отдельный от Gemini |
| Минимум два провайдера | «резервирование LLM» | Политика, согласно которой каждый критичный путь LLM работает как минимум через двух гиперскейлеров |
| BAA | «документы для HIPAA» | Соглашение с деловым партнёром (Business Associate Agreement), необходимое для работы с PHI; его предоставляют все три платформы |
| Мониторинг злоупотреблений | «наблюдатель за логами» | Проверка безопасности промптов и выводов на стороне провайдера; корпоративные клиенты могут от неё отказаться |
