# Метрики инференса — TTFT, TPOT, ITL, Goodput, P99

> Четыре метрики определяют, работает ли инференс-развёртывание. TTFT — это prefill плюс очередь плюс сеть. TPOT (эквивалентно ITL) — это ограниченная пропускной способностью памяти (memory-bound) стоимость декодирования на токен. Сквозная задержка (end-to-end latency) — это TTFT плюс TPOT, умноженный на длину вывода. Пропускная способность — это токены в секунду, агрегированные по всему флоту. Но для продукта важна именно Goodput (полезная пропускная способность) — доля запросов, уложившихся сразу во все SLO. Высокая пропускная способность при низкой Goodput означает, что вы обрабатываете токены, которые никогда не доходят до пользователей вовремя. Референсные цифры для Llama-3.1-8B-Instruct на TRT-LLM в 2026 году: средний TTFT 162 ms, средний TPOT 7.33 ms, средний E2E 1,093 ms. Всегда указывайте P50, P90, P99 — никогда не только среднее. И остерегайтесь ловушки измерений: GenAI-Perf исключает TTFT из расчёта ITL, LLMPerf включает его; два инструмента расходятся в оценке TPOT для одного и того же прогона.

## Проблема

"Наша пропускная способность — 15,000 токенов в секунду." И что? Если у 40% запросов сквозная задержка превысила 2 секунды, пользователи покинули сессию. Одна лишь пропускная способность не говорит о том, работает ли продукт.

У инференса несколько осей задержки, и каждая отказывает по-своему. Prefill compute-bound и масштабируется с длиной промпта. Decode memory-bound и масштабируется с размером пакета. Задержка в очереди — операционная проблема. Сеть — проблема физического расстояния. Для каждой нужна отдельная метрика, нужны перцентили, и нужна единая композитная метрика, отвечающая на вопрос "получил ли пользователь то, что ожидал" — это и есть Goodput.

## Концепция

### TTFT — время до первого токена

`TTFT = queue_time + network_request + prefill_time`

Prefill доминирует, когда промпты длинные. На Llama-3.3-70B FP8 на H100 промпт в 32k занимает ~800 ms чистого prefill. Время в очереди — это поведение планировщика под нагрузкой. Сетевой запрос — это время в проводе, включая TLS. TTFT — это задержка, которую видит пользователь до того, как что-либо начнёт стримиться обратно.

### TPOT / ITL — задержка между токенами

Много имён для одной величины. `TPOT` (time per output token), `ITL` (inter-token latency), `decode latency per token` — всё одно и то же. Это время между последовательными стримящимися токенами после первого.

`TPOT = (decode_forward_time + scheduler_overhead) / tokens_produced`

На том же стеке Llama-3.3-70B H100 с chunked prefill средний TPOT ~7 ms. Без chunked prefill, во время долгого prefill соседней последовательности, TPOT может подскакивать до 50 ms. Следите за P99, а не за средним.

### Задержка E2E

`E2E = TTFT + TPOT * output_tokens + network_response`

Для длинных выводов (>500 токенов) E2E доминируется TPOT. Для коротких выводов с длинными промптами E2E доминируется TTFT. Указывайте E2E с учётом (conditioned) длины вывода.

### Пропускная способность

`throughput = total_output_tokens / elapsed_time`

Агрегированная метрика. Показывает эффективность флота. Не показывает здоровье отдельного запроса.

### Goodput — метрика, которая реально важна

`goodput = fraction of requests meeting (TTFT <= a) AND (TPOT <= b) AND (E2E <= c)`

SLO — это многокритериальное (multi-constraint) условие. Запрос считается "хорошим" только если выполнены все условия. Goodput — это доля таких запросов. Высокая пропускная способность при Goodput 60% — это провал. Более низкая пропускная способность при Goodput 99% — это цель.

В 2026 году Goodput — это метрика, используемая в заявках MLPerf Inference v6.0 и во внутреннем отслеживании SLA у провайдеров AI-платформ.

### Почему среднее — неверная статистика

Распределения задержки LLM смещены вправо (right-skewed). Пакет декодирования с одним соседом с долгим prefill может выдать 500 токенов с TPOT ~7 ms и 20 токенов с TPOT ~60 ms. Средний TPOT — 9 ms. P99 TPOT — 65 ms. Пользователи регулярно попадают на P99 — вот почему они уходят.

Всегда указывайте тройку (P50, P90, P99). Для пользовательского опыта оптимизируют именно P99.

### Референсные цифры — Llama-3.1-8B-Instruct на TRT-LLM, 2026

- средний TTFT: 162 ms
- средний TPOT: 7.33 ms
- средний E2E: 1,093 ms
- P99 TPOT: варьируется 10-25 ms в зависимости от конфигурации chunked prefill.

Это опубликованные референсные точки NVIDIA. Они меняются с размером модели (для 70B были бы в 3-5 раз выше), оборудованием (H100 против B200 ~3x) и нагрузкой.

### Ловушка измерений

Два самых используемых бенчмарк-инструмента 2026 года расходятся в оценке TPOT для одного и того же прогона:

- **NVIDIA GenAI-Perf**: исключает TTFT из расчёта ITL. ITL начинается со второго токена.
- **LLMPerf**: включает TTFT. ITL начинается с первого токена.

Для запроса с TTFT 500 ms и 100 выходными токенами за 700 ms общего декодирования GenAI-Perf сообщает `ITL = 700/99 = 7.07 ms`, LLMPerf сообщает `ITL = 1200/100 = 12.00 ms`. Выбор инструмента меняет число.

Всегда указывайте, какой инструмент использовался. Всегда публикуйте определение.

### Построение SLO

Разумный потребительский SLO для чат-модели 70B в 2026 году:

- TTFT P99 <= 800 ms.
- TPOT P99 <= 25 ms.
- E2E P99 <= 3 s для выводов <300 токенов.
- Целевая Goodput >= 99%.

Корпоративные SLO ужесточают TTFT (200-400 ms) и ослабляют E2E. Смысл в том, чтобы зафиксировать их письменно, измерять все три и отслеживать Goodput как единую композитную метрику.

### Как измерять

- Запускайте реальный трафик или реалистичный синтетический (LLMPerf с `--mean-input-tokens 800 --stddev-input-tokens 300 --mean-output-tokens 150`).
- Ориентируйтесь на 2x от пиковой конкурентности для прогона бенчмарка.
- Проведите 30-50 итераций, вычислите перцентили по объединённой выборке.
- Публикуйте с именем инструмента, версией инструмента, моделью, оборудованием, конкурентностью, распределением промптов.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|--------|--------------------|-------------------------------|
| TTFT | «время до первого токена» | Очередь + сеть + prefill; при длинных промптах основную часть составляет prefill |
| TPOT | «время на выходной токен» | Ограниченная пропускной способностью памяти стоимость декодирования на токен после первого |
| ITL | «задержка между токенами» | То же, что TPOT, в большинстве инструментов (но не во всех — см. GenAI-Perf) |
| E2E | «от начала до конца» | TTFT + TPOT * output_len; плюс сеть на стороне ответа |
| Пропускная способность | «tok/s» | Эффективность флота; бесполезна без перцентилей задержки |
| Goodput | «доля запросов, выполнивших SLO» | Доля запросов, одновременно удовлетворяющих всем ограничениям SLO |
| P99 | «хвост» | Наихудшая задержка в 1 случае из 100; метрика пользовательского опыта |
| Многокритериальный SLO | «совместное условие» | Логическое И для всех трёх ограничений задержки; запрос не проходит, если нарушено хотя бы одно из них |
| GenAI-Perf и LLMPerf | «ловушка инструментов» | Инструменты расходятся в том, включается ли TTFT в ITL |
