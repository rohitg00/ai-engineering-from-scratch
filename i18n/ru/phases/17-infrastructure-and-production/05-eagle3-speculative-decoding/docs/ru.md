# EAGLE-3 Speculative Decoding в продакшене

> Спекулятивное декодирование (speculative decoding) сочетает быструю черновую модель (draft model) с целевой моделью. Черновая модель предлагает K токенов; целевая модель проверяет их за один forward-проход; принятые токены достаются бесплатно. В 2026 году EAGLE-3 — это продакшен-вариант: он обучает черновую голову (draft head) на скрытых состояниях целевой модели, а не на сырых токенах, поднимая коэффициент принятия (acceptance rate) alpha в диапазон 0.6-0.8 на общем чате. Правильный вопрос — не «насколько быстра черновая модель», а «чему равен alpha на моём трафике?» Если alpha падает ниже ~0.55, спекулятивное декодирование при высокой конкурентности даёт чистый отрицательный эффект, потому что каждый отклонённый черновой токен стоит второго forward-прохода целевой модели. Этот урок учит сначала измерять alpha, а уже потом включать флаг.

**Тип:** Learn**Языки:** Python (stdlib, игрушечный симулятор коэффициента принятия)**Предварительные требования:** Фаза 17 · 04 (Serving Engine Internals), Фаза 10 · 18 (Multi-Token Prediction)**Время:** ~60 минут

## Проблема

Декодирование ограничено пропускной способностью памяти (memory-bound). На H100, выполняющем Llama 3.3 70B FP8, каждый декодированный токен читает ~140 ГБ/с весов и выдаёт один токен. Во время декодирования вычислительные мощности GPU почти простаивают — узкое место не в пропускной способности матричных умножений, а в пропускной способности HBM.

Спекулятивное декодирование использует этот разрыв. Черновая модель генерирует K кандидатных токенов, после чего целевая модель проверяет все K за один forward-проход. Каждый проверенный токен фактически достаётся бесплатно (амортизируется в пакетный forward-проход размера K, который целевой модели пришлось бы выполнить в любом случае).

Классический подход с черновой моделью использует меньшую модель того же семейства (Llama 3.2 1B в роли черновой модели для Llama 3.3 70B). Он работает, но коэффициент принятия посредственный — распределение меньшей модели расходится с целевым. EAGLE, затем EAGLE-2, затем EAGLE-3 обучают лёгкую черновую голову напрямую на внутренних состояниях целевой модели, поэтому распределение черновой модели гораздо точнее отслеживает целевое. Именно поэтому alpha растёт с 0.4 у классической черновой модели до 0.6-0.8 у EAGLE-3.

Подвох: EAGLE-3 опционален в vLLM 2026 года. `speculative_config` нужно задать явно. Без флага — без ускорения. Команды, которые включают его, не измерив alpha на реальном трафике, часто видят ухудшение хвостовой задержки (tail latency), а не улучшение.

## Концепция

### Что реально даёт спекулятивное декодирование

Без спекулятивного декодирования стоимость одного токена — это один forward-проход целевой модели. При спекулятивном декодировании с длиной черновой последовательности K и коэффициентом принятия alpha ожидаемое число токенов на forward-проход целевой модели равно `1 + K * alpha`. Ускорение равно `(1 + K * alpha) / (1 + epsilon)`, где epsilon — накладные расходы на черновой прогон плюс проверку. Для K=5, alpha=0.7: `(1 + 5*0.7) / (1 + 0.1) = 4.5 / 1.1 = 4.1x`. Реальные цифры группируются в районе 2-3x, потому что alpha на продакшен-трафике редко бывает настолько высоким, а epsilon растёт при увеличении размера пакета.

### Почему alpha — единственная метрика, которая имеет значение

Отклонённые токены не исчезают бесследно — они вынуждают выполнить второй forward-проход целевой модели для первого отклонённого токена. На нагрузке, где alpha падает до 0.4, вы платите за накладные расходы черновой модели, плюс проверку, плюс повторную попытку. При высокой конкурентности (скажем, 256 одновременных запросов) пакет декодирования уже достаточно велик, так что разрыв по пропускной способности памяти между «только целевая модель» и «целевая модель с проверкой» сокращается. Ниже alpha 0.55 на большинстве оборудования 2026 года спекулятивное декодирование даёт чистый отрицательный эффект.

Alpha меняется в зависимости от нагрузки. На трафике в стиле ShareGPT (общий чат) EAGLE-3, обученный на ShareGPT, достигает 0.6-0.8. На трафике из специализированных доменов (код, медицина, юриспруденция) черновая голова, обученная на общих данных, падает до 0.4-0.6. Обучение доменно-специфичной черновой головы восстанавливает alpha — это лёгкая и быстрая задача обучения по сравнению с дообучением целевой модели.

### Поколения EAGLE вкратце

- **Классическая черновая модель**: небольшая модель того же семейства. Alpha 0.3-0.5. Инфраструктура простая — загружены две модели, черновая модель выполняет K forward-проходов на один forward-проход целевой модели.
- **EAGLE-1 (2024)**: единственная черновая голова, обученная на скрытых состояниях целевой модели (последний слой). Alpha ~0.5-0.6. Небольшие накладные расходы по параметрам сверх целевой модели.
- **EAGLE-2 (2025)**: адаптивная длина черновой последовательности и древовидные черновые прогоны (проверка нескольких ветвей за один проход целевой модели). Alpha ~0.6-0.7. Более сложный планировщик черновых прогонов.
- **EAGLE-3 (2025-2026)**: черновая голова, обученная на нескольких слоях целевой модели (не только последнем), лучшее согласование (alignment). Alpha ~0.6-0.8 на общем чате.

### Продакшен-рецепт 2026 года

1. Разверните целевую модель в чистом виде. Измерьте базовые TTFT, ITL, пропускную способность при целевой конкурентности.
2. Включите черновой прогон EAGLE-3 через `speculative_config` в vLLM. Повторно запустите бенчмарк.
3. Логируйте коэффициент принятия alpha. vLLM V1 сообщает это как `spec_decode_metrics.accepted_tokens_per_request`. Разделите на запрошенную длину черновой последовательности, чтобы получить alpha.
4. Если alpha < 0.55 на распределении продакшен-трафика, отключите спекулятивное декодирование или обучите доменно-специфичную черновую модель EAGLE-3.
5. При продакшен-конкурентности повторите запуск. Убедитесь, что P99 ITL не ухудшился.

### Продакшен-ловушка: хвост P99

Средний ITL снижается со спекулятивным декодированием. P99 может ухудшиться, если не настроить систему. Отклонённые черновые прогоны запускают двухпроходную последовательность (черновой прогон + неудачная проверка + повторная попытка). При полном заполнении пакета эти два прохода выполняются последовательно. Следите за P99 ITL, а не за P50.

### Где EAGLE-3 уже развёрнут

Google развернул спекулятивное декодирование в AI Overviews в 2025 году (то же качество, более быстрый ответ). vLLM V1 предоставляет `speculative_config` как документированный интерфейс; GPU-спекулятивное декодирование на N-граммах в V1 — это вариант, совместимый с chunked prefill. SGLang поддерживает EAGLE-3 как рекомендуемый черновой путь для нагрузок с интенсивным использованием общих префиксов (prefix-heavy).

### Математика точки безубыточности в одну строку

Ожидаемое ускорение: `S(alpha, K) = (1 + K*alpha) / (1 + verify_overhead)`. Решая уравнение `S = 1` относительно alpha, получаем: `alpha_breakeven = verify_overhead / K`. Для типичного verify_overhead ~0.15 и K=5: `alpha_breakeven = 0.03`. Но это чистая математика декодирования. При высокой конкурентности накладные расходы на проверку растут, а пакет декодирования уже амортизирует чтения памяти между последовательностями, поэтому на практике эффективный alpha_breakeven поднимается до ~0.45-0.55.

### Когда не стоит использовать спекулятивное декодирование

- Офлайн-генерация с пакетом размера 1, где задержка не важна. Используйте чистую целевую модель.
- Очень короткие выходные последовательности (менее 50 токенов). Накладные расходы черновой модели и стоимость проверки доминируют.
- Специализированные домены без доменно-обученной черновой головы. Alpha слишком низкий.
- vLLM v0.18.0 плюс спекулятивное декодирование с черновой моделью плюс `--enable-chunked-prefill`. Эта комбинация не компилируется. Документированное исключение — GPU-спекулятивное декодирование на N-граммах в V1.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| Спекулятивное декодирование | «черновой прогон плюс проверка» | Дешёвая модель предлагает K токенов, а целевая проверяет все K за один forward-проход |
| Коэффициент принятия alpha | «доля принятых черновых токенов» | Доля черновых токенов, принятых целевой моделью; единственная метрика, которая имеет значение |
| Длина черновой последовательности K | «черновой K» | Число токенов, предлагаемых черновой моделью на каждый forward-проход целевой модели; обычно 4-8 |
| Накладные расходы на проверку epsilon | «накладные расходы спекулятивного декодирования» | Дополнительная стоимость проверки и повторной попытки по сравнению с обычным forward-проходом целевой модели; растёт вместе с пакетом |
| EAGLE-3 | «новейший EAGLE» | Вариант 2025-2026 годов; черновая голова обучается на нескольких слоях целевой модели; alpha 0.6-0.8 на общем чате |
| `speculative_config` | «конфигурация спекулятивного декодирования vLLM» | Явно включаемая возможность в vLLM V1; без включения нет ускорения |
| Спекулятивное декодирование на N-граммах | «черновой прогон на N-граммах» | Черновой прогон на GPU с поиском N-грамм в промпте; совместим с chunked prefill |
| Точка безубыточности alpha | «нейтральный alpha» | Значение alpha, при котором спекулятивное декодирование не даёт ускорения; следите за ним при продакшен-конкурентности |
| Два прохода при отклонении чернового прогона | «стоимость повторной попытки» | Два forward-прохода целевой модели при отклонении черновых токенов; увеличивают хвост P99 |
