# API пакетной обработки — скидка 50% как отраслевой стандарт

> Каждый крупный провайдер предлагает асинхронный API пакетной обработки со скидкой 50% и временем обработки около 24 часов. OpenAI, Anthropic, Google и большинство инференс-платформ (пакетный тариф Fireworks, пакетная обработка Together) реализуют один и тот же паттерн. Если сочетать пакетную обработку с кешированием промптов, стоимость ночных конвейеров падает до ~10% от стоимости синхронной обработки без кеша. Правило предельно простое: если задача не интерактивна — её следует обрабатывать в пакетном режиме. Конвейеры генерации контента, классификация документов, извлечение данных, генерация отчётов, массовая разметка, тегирование каталогов — всё, что допускает задержку в 24 часа, это деньги, оставленные на столе, пока работа не перейдёт на пакетную обработку. Продакшен-паттерн 2026 года — сортировать (triage) каждую новую LLM-нагрузку по трём дорожкам: интерактивная (синхронный вызов с кешированием), полуинтерактивная (асинхронная очередь с резервным вариантом), пакетная (ночная обработка, с накоплением кешированного ввода). Нагрузки, которые притворяются интерактивными, но на деле допускают задержку в минуты, тратят впустую больше всего.

**Тип:** Изучение
**Языки:** Python (стандартная библиотека, учебный симулятор стоимости пакетной и синхронной обработки)
**Предварительные требования:** Этап 17 · 14 (кеширование промптов и семантическое кеширование)
**Время:** ~45 минут

## Цели обучения

- Назовите три API пакетной обработки провайдеров (OpenAI, Anthropic, Google) и общие гарантии: скидку 50% и время обработки 24 часа.
- Рассчитайте стоимость сочетания пакетной обработки и кешированного ввода (cached-input) для ночной нагрузки классификации и сравните её с базовым уровнем синхронной обработки без кеша.
- Отсортируйте (triage) нагрузку по категориям интерактивная / полуинтерактивная / пакетная и обоснуйте выбор дорожки.
- Назовите две ловушки: частичная интерактивность (пользователь ожидает результат быстрее, чем за 24 часа) и расхождение схемы вывода (output-schema drift) (формат пакетного файла различается у каждого провайдера).

## Проблема

Ваша команда поставляет ночной конвейер генерации отчётов. 50 000 документов, для каждого нужно составить резюме, сгруппировать резюме по кластерам и подготовить черновик отчёта для руководства. При синхронном запуске это занимает 4 часа и стоит $2,000 за ночь. Вы узнаёте об API пакетной обработки.

Пакетная обработка даёт скидку 50%. Вы также включаете кеширование промптов (prompt caching) для системного промпта (общего для всех 50k вызовов). При сложении обеих скидок счёт падает до $180 за ночь — ~9% от базового уровня. Тот же конвейер, три изменения конфигурации.

Пакетная обработка — это самый дешёвый рычаг в наборе инструментов управления стоимостью LLM, которым никто не пользуется. Причина в основном организационная: команды думают «реальное время», хотя на деле SLA — это «к утру». Этот урок о том, как не оставлять 90% счёта на столе.

## Концепция

### Три API пакетной обработки

**OpenAI Batch API**: загрузка JSONL-файла со списком запросов. Обещанное время обработки — 24 часа (на практике обычно ~2-8 часов). Скидка 50% на входные и выходные токены. Конечная точка `/v1/batches`. Ввод, подходящий для кеширования, дополнительно получает тарификацию кешированного ввода (cached-input pricing).

**Anthropic Message Batches**: загрузка JSONL. Время обработки — 24 часа. Скидка 50%. Поддерживает `cache_control` — записи в кеш явные, чтения происходят автоматически внутри пакета.

**Google Vertex AI Batch Prediction**: ввод через BigQuery или GCS. Аналогичная скидка 50% для Gemini. Интегрируется с конвейерами Vertex.

### Смысл: асинхронно — не значит медленно

Пакетная обработка — это «обещаю вернуть результат в течение 24 часов», а не «это займёт 24 часа». Типичное значение P50 — 2-6 часов. Провайдер планирует выполнение вашего пакета в периоды низкой нагрузки, когда GPU-мощности недозагружены.

### Сложение с кешированием

Суммаризация 50k документов с одним и тем же системным промптом на 4K токенов:

- Синхронно без кеша: 50000 × ($input × 4000 + $output × 200) по полным тарифам.
- Синхронно с кешем: системный промпт кешируется после первой записи; для оставшихся 49999 вызовов ввод дешевле в 10 раз.
- Пакетная обработка с кешем: всё вышеперечисленное плюс скидка 50% на чтение и запись.

Итог сложения: пакетная обработка + кеш = ~10% от счёта синхронной обработки без кеша. Любая нагрузка, которая выполняется ночью и использует общий системный промпт, должна применять этот подход.

### Сортировка нагрузок (triage)

**Интерактивная** — пользователь ждёт ответа. Важен TTFT. Синхронный вызов с кешированием промптов. Нельзя перевести на пакетную обработку.

**Полуинтерактивная** — пользователь отправляет задачу и возвращается за результатом через несколько минут. Асинхронная очередь с резервным вариантом (fallback) на синхронный вызов, если пакетная обработка недоступна. Пример — индексирование RAG умеренного объёма.

**Пакетная** — пользователь ожидает результат «к утру» или «через час». Конвейеры контента, классификация в масштабе, офлайн-анализ. Всегда используйте пакетную обработку и сочетайте её с кешированием.

Частая ошибка: классифицировать всё как интерактивное только потому, что конвейер работает в продакшене. Продакшен — это не спецификация задержки, спецификация задержки — это SLA.

### Ловушка частичной интерактивности

Некоторые функции выглядят интерактивными, но допускают задержку в 5-10 минут. Пример: ночной отчёт о состоянии клиента с кнопкой «обновить». Пользователь нажимает «обновить»; ожидание в 10 минут вполне приемлемо. Команда реализует это как синхронный вызов. 50 одновременных обновлений обходятся в 10 раз дороже, чем пакетная обработка с доставкой по электронной почте.

Вопрос, который стоит задать: «Что для этого пользователя значат 24 часа?» Если ответ «он бы не заметил разницы» — переводите на пакетную обработку.

### Ловушка схемы вывода

Форматы пакетных файлов различаются у каждого провайдера:

- OpenAI: JSONL, один запрос на строку.
- Anthropic: JSONL, одно сообщение на строку; формат ответа встроен.
- Vertex: таблица BigQuery или префикс GCS с TFRecord.

Написание «единого клиента пакетной обработки» для нескольких провайдеров означает адаптерный код под каждого из них. Шлюзы, которые рекламируют мультипровайдерную пакетную обработку (Portkey, некоторые тарифы LiteLLM), всё равно лишь тонко оборачивают сырой формат.

### Цифры, которые стоит запомнить

- Скидка на пакетную обработку у всех провайдеров: фиксированные 50% на ввод и вывод.
- SLA по времени обработки: гарантия 24 часа, типичное значение P50 — 2-6 часов.
- Пакетная обработка в сочетании с кешированным вводом: ~10% от стоимости синхронной обработки без кеша.
- Правило сортировки нагрузок: если задержка 24h приемлема — всегда используйте пакетную обработку.

1. Запустите `code/main.py`. Для конвейера на 100k документов с системным промптом на 3K токенов и выводом на 500 токенов рассчитайте экономию от полного сочетания пакетной обработки и кеширования по сравнению с базовым синхронным вариантом.

3. Пользователь жалуется, что его отчёт готовился 3 часа. Это была ошибка отнесения к пакетной обработке или действительно интерактивная задача? Сформулируйте критерий принятия решения.

5. Рассчитайте точку безубыточности: при какой длине общего префикса (shared prefix) сочетание пакетной обработки и кеширования становится дешевле, чем ночной запуск на собственном зарезервированном GPU?

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|----------------|------------------------|
| API пакетной обработки | «скидка за асинхронную обработку» | Скидка 50% при обработке в течение 24 часов |
| JSONL | «пакетный формат» | Один JSON-запрос на строку; стандарт OpenAI и Anthropic |
| Message Batches | «пакетная обработка Anthropic» | Название API пакетной обработки Anthropic |
| Пакетное прогнозирование | «пакетная обработка Vertex» | API пакетной обработки Vertex AI |

| Сортировка нагрузок | «выбор степени интерактивности» | Выбор маршрута: интерактивная, полуинтерактивная или пакетная обработка |
