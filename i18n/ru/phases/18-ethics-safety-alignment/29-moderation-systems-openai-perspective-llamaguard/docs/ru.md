# Системы модерации — OpenAI, Perspective, Llama Guard

> Системы модерации, работающие в продакшене, реализуют на практике политики безопасности, определённые в уроках 12–16. OpenAI Moderation API: `omni-moderation-latest` (2024), построенный на GPT-4o, классифицирует текст и изображения за один вызов; на 42% точнее на многоязычном тестовом наборе, чем предыдущая версия; схема ответа возвращает 13 булевых категорий — harassment, harassment/threatening, hate, hate/threatening, illicit, illicit/violent, self-harm, self-harm/intent, self-harm/instructions, sexual, sexual/minors, violence, violence/graphic; бесплатен для большинства разработчиков. Многоуровневые схемы: модерация входа (до генерации), модерация выхода (после генерации), специализированная модерация (доменные правила). Асинхронные параллельные вызовы скрывают задержку; при срабатывании флага показываются заполняющие ответы. Llama Guard 3/4 (урок 16): 14 категорий опасностей MLCommons, злоупотребление интерпретатором кода (Code Interpreter Abuse), 8 языков (v3), поддержка нескольких изображений (v4). Perspective API (Google Jigsaw): оценка токсичности, появившаяся до волны LLM-модераторов; в основном одномерная оценка токсичности с вариантами для крайней токсичности, оскорблений и ненормативной лексики; базовый ориентир для исследований в области модерации контента. Устаревание: Azure Content Moderator объявлен устаревшим в феврале 2024 года, выводится из эксплуатации в феврале 2027 года, заменяется на Azure AI Content Safety.

## Проблема

Уроки 12–16 описывают атаки и инструментарий защиты. Урок 29 посвящён развёрнутым системам модерации, которые реализуют эти средства защиты на том рубеже, где пользователи взаимодействуют с продуктом. Трёхуровневый паттерн — конфигурация по умолчанию в 2026 году.

## Концепция

### OpenAI Moderation API

`omni-moderation-latest` (2024). Построен на GPT-4o. Классифицирует текст и изображения за один вызов. Бесплатен для большинства разработчиков.

Категории (13 булевых значений в схеме ответа):
- harassment, harassment/threatening
- hate, hate/threatening
- self-harm, self-harm/intent, self-harm/instructions
- sexual, sexual/minors
- violence, violence/graphic
- illicit, illicit/violent

Поддержка мультимодальности распространяется на `violence`, `self-harm` и `sexual`, но не на `sexual/minors`; остальные категории работают только с текстом.

В учебном каркасе кода `code/main.py` мы сворачиваем подкатегории `/threatening`, `/intent`, `/instructions` и `/graphic` в родительские категории верхнего уровня для упрощения изложения. В продакшен-коде следует использовать полную схему из 13 категорий.

На 42% точнее на многоязычном тестовом наборе, чем конечная точка модерации предыдущего поколения. Оценки по каждой категории; приложения сами задают пороги.

### Llama Guard 3/4

Рассматривается в уроке 16. 14 категорий опасностей MLCommons (организованы иначе, чем 13 булевых значений в схеме ответа OpenAI). Поддерживает 8 языков (v3). Llama Guard 4 (апрель 2025) изначально мультимодальна, 12B параметров.

Таксономии OpenAI и Llama Guard пересекаются, но расходятся. У OpenAI есть широкая категория «противоправная деятельность»; у Llama Guard отдельно выделены «насильственные преступления» и «ненасильственные преступления». Выбор при развёртывании делается исходя из соответствия таксономии политике.

### Perspective API (Google Jigsaw)

Система оценки токсичности, появившаяся до волны LLM-модераторов (до 2020 года). Категории: TOXICITY, SEVERE_TOXICITY, INSULT, PROFANITY, THREAT, IDENTITY_ATTACK. Основная одномерная оценка (TOXICITY) с вариантами по подизмерениям.

Широко используется как базовый ориентир в исследованиях модерации контента, поскольку API стабилен, задокументирован и накопил годы калибровочных данных. Для современных сценариев, связанных с LLM, обычно лучше подходят Llama Guard или OpenAI Moderation.

### Трёхуровневый паттерн

1. **Модерация входа.** Классифицирует промпт пользователя до генерации. Отклоняет при срабатывании флага. Задержка: один вызов классификатора.
2. **Модерация выхода.** Классифицирует вывод модели перед доставкой. Заменяет отказом при срабатывании флага. Задержка: один вызов классификатора после генерации.
3. **Специализированная модерация.** Правила предметной области (регулярные выражения, списки разрешений, бизнес-политика). Выполняется либо на входе, либо на выходе.

Три уровня по замыслу последовательны: модерация входа должна завершиться до генерации, а модерация выхода выполняется после неё. Параллелизм применяется внутри одного уровня — одновременный запуск нескольких классификаторов (например, OpenAI Moderation + Llama Guard + Perspective) на одном и том же тексте скрывает задержку каждого отдельного классификатора. В качестве необязательной оптимизации, пока завершается модерация входа и откладывается стриминг первого токена, может показываться заполняющий ответ («один момент, проверяю…»). Поведение при срабатывании флага настраивается: отказ, очистка, эскалация к проверке человеком.

### Типичные недостатки

- **Только вход.** Не улавливает галлюцинации в выводе (атаки с кодированием из уроков 12–14 обходят классификаторы входа).
- **Только выход.** Позволяет любому входу достичь модели; увеличивает стоимость; раскрывает атакующему внутренние рассуждения модели.
- **Только специализированная.** Не устойчива для всех категорий; регулярные выражения хрупки.

Многоуровневая модерация используется по умолчанию. Принцип «пояс и подтяжки».

### Устаревание Azure

Azure Content Moderator: объявлен устаревшим в феврале 2024 года, выводится из эксплуатации в феврале 2027 года. Заменяется на Azure AI Content Safety — решение на основе LLM, интегрированное с Azure OpenAI. Для развёртываний на Azure это практический проект миграции, рассчитанный на 2024–2027 годы.

## Применение

`code/main.py` строит каркас трёхуровневой модерации: модератор входа (ключевые слова + оценка по категории), модератор выхода (тот же классификатор применяется к выходу), специализированный модератор (доменные правила). Вы можете пропускать через него входные данные и наблюдать, какой уровень что перехватывает.

## Поставка

Результат этого урока — `outputs/skill-moderation-stack.md`. Для заданного развёртывания он рекомендует конфигурацию стека модерации: какой классификатор использовать на входе, какой на выходе, какие специализированные правила и какой судья для пограничных случаев.

## Упражнения

1. Запустите `code/main.py`. Пропустите безобидный, пограничный и вредоносный ввод через все три уровня. Укажите, какой уровень срабатывает для каждого случая.

2. Расширьте каркас оценкой токсичности в стиле Perspective API для конкретной категории. Сравните поведение её порога с оценкой по категории.

3. Изучите документацию OpenAI Moderation API и список категорий Llama Guard 3. Сопоставьте каждую категорию OpenAI с ближайшими категориями Llama Guard. Определите три категории, которые не сопоставляются однозначно.

4. Спроектируйте стек модерации для развёртывания ассистента по программированию (например, GitHub Copilot). Определите наиболее и наименее релевантные категории и предложите специализированные правила.

5. Azure Content Moderator выводится из эксплуатации в феврале 2027 года. Спланируйте миграцию на Azure AI Content Safety. Определите элемент миграции с наивысшим риском.

## Ключевые термины

| Термин | Как его обычно называют | Что он означает на самом деле |
|------|-----------------|------------------------|
| OpenAI Moderation | «omni-moderation-latest» | Основанный на GPT-4o текстовый классификатор по 13 категориям с частичной поддержкой мультимодальности |
| Perspective API | «оценка токсичности от Google Jigsaw» | Базовая система оценки токсичности, созданная до эпохи LLM |
| Llama Guard | «14 категорий MLCommons» | Классификатор опасностей от Meta (v3: текстовая модель 8B, 8 языков; v4: мультимодальная модель 12B) |
| Модерация входа | «фильтр до генерации» | Классификатор промпта пользователя, запускаемый до вызова модели |
| Модерация выхода | «фильтр после генерации» | Классификатор вывода модели, запускаемый перед его доставкой |
| Специализированная модерация | «правила предметной области» | Правила для конкретного развёртывания (регулярные выражения, списки разрешений, политика) |
| Многоуровневая модерация | «все три уровня» | Стандартная схема развёртывания в продакшене |
