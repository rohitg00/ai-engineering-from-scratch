# Глубокие Q-сети (DQN)

> 2013: Mnih обучил одну сеть Q-обучения на сырых пикселях и обошёл все классические RL-агенты в семи играх Atari. 2015: расширение до 49 игр, публикация в Nature, начало эры глубокого RL. DQN — это Q-обучение плюс три трюка, делающие аппроксимацию функций стабильной.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 3 · 03 (обратное распространение ошибки), Фаза 9 · 04 (Q-обучение, SARSA)
**Время:** ~75 минут

## Проблема

Табличному Q-обучению нужно отдельное Q-значение для каждой пары (состояние, действие). У шахматной доски ~10⁴³ состояний. Кадр Atari — это 210×160×3 = 100 800 признаков. Табличный RL умирает уже на тысячах состояний, не говоря о миллиардах.

Решение очевидно задним числом: заменить Q-таблицу нейронной сетью, `Q(s, a; θ)`. Но «очевидное задним числом» заняло десятилетия. Наивная аппроксимация функций с Q-обучением расходится под действием «смертельной триады» — аппроксимация функций + бутстрапинг + обучение вне политики. Mnih и др. (2013, 2015) выявили три инженерных трюка, стабилизирующих обучение:

1. **Воспроизведение опыта (experience replay)** декоррелирует переходы.
2. **Целевая сеть** замораживает бутстрапированную цель.
3. **Обрезка вознаграждения** нормализует величины градиентов.

DQN на Atari стал первым случаем, когда единая архитектура с единым набором гиперпараметров решила десятки задач управления по сырым пикселям. Всё «глубокое RL», построенное с тех пор, — DDQN, Rainbow, Dueling, Distributional, R2D2, Agent57 — надстроено поверх этой базы из трёх трюков.

## Концепция

![Цикл обучения DQN: среда, буфер воспроизведения, онлайн-сеть, целевая сеть, TD-потеря Беллмана](../assets/dqn.svg)

**Целевая функция.** DQN минимизирует одношаговую TD-потерю на нейронной Q-функции:

`L(θ) = E_{(s,a,r,s')~D} [ (r + γ max_{a'} Q(s', a'; θ^-) - Q(s, a; θ))² ]`

`θ` — онлайн-сеть, обновляемая на каждом шаге градиентным спуском. `θ^-` — целевая сеть, периодически копируемая из `θ` (каждые ~10 000 шагов). `D` — буфер воспроизведения прошлых переходов.

**Три трюка, в порядке важности:**

**Воспроизведение опыта.** Кольцевой буфер из `~10⁶` переходов. Каждый шаг обучения сэмплирует минипакет равномерно случайно. Это разрывает временную корреляцию (последовательные кадры почти идентичны), позволяет сети многократно учиться на редких вознаграждающих переходах и декоррелирует последовательные обновления градиента. Без него TD-обучение на основе текущей политики с нейросетью расходится на Atari.

**Целевая сеть.** Использование одной и той же сети `Q(·; θ)` в обеих частях уравнения Беллмана заставляет цель сдвигаться при каждом обновлении — «погоня за собственным хвостом». Решение: держать вторую сеть `Q(·; θ^-)` с замороженными весами. Каждые `C` шагов копировать `θ → θ^-`. Это стабилизирует цель регрессии на протяжении тысяч шагов градиента подряд. Мягкие обновления `θ^- ← τ θ + (1-τ) θ^-` (используются в DDPG, SAC) — более плавный вариант.

**Обрезка вознаграждения.** Величины вознаграждений в Atari варьируются от 1 до 1000+. Обрезка до `{-1, 0, +1}` не даёт какой-либо одной игре доминировать в градиенте. Неверна, когда важна величина вознаграждения; хороша для Atari, где важен только знак.

**Double DQN.** Хасселт (2016) исправляет максимизационное смещение: онлайн-сеть *выбирает* действие, целевая сеть его *оценивает*.

`target = r + γ Q(s', argmax_{a'} Q(s', a'; θ); θ^-)`

Замена, не требующая других изменений и стабильно работающая лучше. Используйте её по умолчанию.

**Другие улучшения (Rainbow, 2017):** приоритизированное воспроизведение (сэмплировать переходы с высокой TD-ошибкой чаще), дуэльная архитектура (отдельные головы для `V(s)` и преимущества), шумные сети (выученное исследование), n-шаговые отдачи, дистрибутивное Q-обучение (C51/QR-DQN), многошаговый бутстрапинг. Каждый добавляет несколько процентов; прирост примерно аддитивен.

## Реализация

Код здесь использует только stdlib, без numpy — мы применяем самодельный MLP с одним скрытым слоем на крошечном непрерывном GridWorld, так что каждый шаг обучения выполняется за микросекунды. Алгоритм идентичен DQN на Atari в масштабе.

### Шаг 1: буфер воспроизведения

```python
class ReplayBuffer:
    def __init__(self, capacity):
        self.buf = []
        self.capacity = capacity
    def push(self, s, a, r, s_next, done):
        if len(self.buf) == self.capacity:
            self.buf.pop(0)
        self.buf.append((s, a, r, s_next, done))
    def sample(self, batch, rng):
        return rng.sample(self.buf, batch)
```

Ёмкость ~50 000 для Atari; для нашей игрушечной среды хватает 5000.

### Шаг 2: крошечная Q-сеть (ручной MLP)

```python
class QNet:
    def __init__(self, n_in, n_hidden, n_actions, rng):
        self.W1 = [[rng.gauss(0, 0.3) for _ in range(n_in)] for _ in range(n_hidden)]
        self.b1 = [0.0] * n_hidden
        self.W2 = [[rng.gauss(0, 0.3) for _ in range(n_hidden)] for _ in range(n_actions)]
        self.b2 = [0.0] * n_actions
    def forward(self, x):
        h = [max(0.0, sum(w * xi for w, xi in zip(row, x)) + b) for row, b in zip(self.W1, self.b1)]
        q = [sum(w * hi for w, hi in zip(row, h)) + b for row, b in zip(self.W2, self.b2)]
        return q, h
```

Прямой проход: линейный слой → ReLU → линейный слой. Это вся сеть целиком.

### Шаг 3: обновление DQN

```python
def train_step(online, target, batch, gamma, lr):
    grads = zeros_like(online)
    for s, a, r, s_next, done in batch:
        q, h = online.forward(s)
        if done:
            y = r
        else:
            q_next, _ = target.forward(s_next)
            y = r + gamma * max(q_next)
        td_error = q[a] - y
        accumulate_grads(grads, online, s, h, a, td_error)
    apply_sgd(online, grads, lr / len(batch))
```

Форма — это Q-обучение из Урока 04 с двумя отличиями: (а) мы делаем обратное распространение через дифференцируемую `Q(·; θ)` вместо индексации таблицы, (б) цель использует `Q(·; θ^-)`.

### Шаг 4: внешний цикл

Для каждого эпизода: действовать ε-жадно на `Q(·; θ)`, помещать переходы в буфер, сэмплировать минипакет, делать шаг градиента, периодически синхронизировать `θ^- ← θ`. Паттерн:

```python
for episode in range(N):
    s = env.reset()
    while not done:
        a = epsilon_greedy(online, s, epsilon)
        s_next, r, done = env.step(s, a)
        buffer.push(s, a, r, s_next, done)
        if len(buffer) >= batch:
            train_step(online, target, buffer.sample(batch), gamma, lr)
        if steps % sync_every == 0:
            target = copy(online)
        s = s_next
```

На нашем крошечном GridWorld с 16-мерным унитарно закодированным состоянием агент выучивает близкую к оптимальной политику примерно за 500 эпизодов. На Atari масштабируйте это до 200 млн кадров и добавьте CNN-экстрактор признаков.

## Подводные камни

- **Смертельная триада.** Аппроксимация функций + обучение вне политики + бутстрапинг могут привести к расходимости. DQN смягчает это целевой сетью + воспроизведением; не убирайте ни то, ни другое.
- **Исследование.** ε должна затухать, обычно от 1.0 до 0.01 за первые ~10% обучения. Без достаточного раннего исследования Q-сеть сходится в локальный бассейн.
- **Переоценка.** `max` по зашумлённой Q смещён вверх. Всегда используйте Double DQN в продакшене.
- **Масштаб вознаграждения.** Обрезайте или нормализуйте вознаграждения; величина градиента пропорциональна величине вознаграждения.
- **Холодный старт буфера воспроизведения.** Не начинайте обучение, пока в буфере не накопится несколько тысяч переходов. Ранние градиенты на ~20 сэмплах переобучаются.
- **Частота синхронизации цели.** Слишком часто ≈ отсутствие целевой сети; слишком редко ≈ устаревшие цели. DQN на Atari использует 10 000 шагов среды. Эмпирическое правило: синхронизировать примерно каждую 1/100 горизонта обучения.
- **Предобработка наблюдений.** DQN на Atari стекирует 4 кадра, чтобы сделать состояние марковским. Любой среде с информацией о скорости нужно стекирование кадров или рекуррентное состояние.

## Применение

В 2026 году DQN редко бывает передовым решением, но остаётся эталонным алгоритмом обучения вне политики:

| Задача | Предпочтительный метод | Почему не DQN? |
|------|------------------|--------------|
| Дискретные действия в стиле Atari | Rainbow DQN или Muesli | Тот же фреймворк, больше трюков. |
| Непрерывное управление | SAC / TD3 (Фаза 9 · 07) | У DQN нет сети политики. |
| На основе своей политики / высокая пропускная способность | PPO (Фаза 9 · 08) | Без буфера воспроизведения; проще масштабировать. |
| Офлайн-RL | CQL / IQL / Decision Transformer | Консервативные Q-цели, без взрывов бутстрапинга. |
| Большие дискретные пространства действий (рекомендации) | DQN с эмбеддингом действий или IMPALA | Подходит; важны детали оформления. |
| RL для LLM | PPO / GRPO | На уровне последовательности, а не шага; другая функция потерь. |

Уроки переносятся и дальше. Воспроизведение и целевые сети встречаются в SAC, TD3, DDPG, SAC-X, буфере самоигры AlphaZero и в каждом методе офлайн-RL. Обрезка вознаграждения живёт дальше в виде нормализации преимущества в PPO. Эта архитектура — чертёж.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| DQN | «Глубокое Q-обучение» | Q-обучение с нейронной Q-функцией, буфером воспроизведения и целевой сетью. |
| Воспроизведение опыта | «Перемешанные переходы» | Кольцевой буфер, из которого равномерно сэмплируют на каждом шаге градиента; декоррелирует данные. |
| Целевая сеть | «Замороженный бутстрап» | Периодическая копия Q, используемая в цели Беллмана; стабилизирует обучение. |
| Смертельная триада | «Почему RL расходится» | Аппроксимация функций + бутстрапинг + обучение вне политики = отсутствие гарантии сходимости. |
| Double DQN | «Исправление максимизационного смещения» | Онлайн-сеть выбирает действие, целевая сеть его оценивает. |
| Дуэльная DQN | «Головы V и A» | Разложение Q = V + A - mean(A); тот же выход, лучший поток градиента. |
| Rainbow | «Все трюки сразу» | DDQN + PER + дуэльная архитектура + n-шаг + шумные сети + дистрибутивное Q-обучение в одном. |
| PER | «Приоритизированное воспроизведение» | Сэмплирование переходов пропорционально величине TD-ошибки. |
