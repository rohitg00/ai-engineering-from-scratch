# Проксимальная оптимизация политики (PPO)

> A2C выбрасывает каждый прогон после одного обновления. PPO оборачивает градиент политики в усечённое отношение важности (importance ratio), позволяя делать 10+ эпох на одних и тех же данных без взрыва политики. Schulman et al. (2017). По-прежнему алгоритм градиента политики по умолчанию в 2026 году.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** этап 9 · 06 (REINFORCE), этап 9 · 07 (актор–критик)
**Время:** ~75 минут

## Проблема

A2C (урок 07) работает по данным текущей политики (on-policy): градиент `E_{π_θ}[A · ∇ log π_θ]` требует данных, сэмплированных из *текущей* `π_θ`. Сделайте одно обновление — и `π_θ` изменится; использованные данные уже не соответствуют текущей политике (off-policy). Переиспользуйте их — и градиент будет смещён.

Прогоны дороги. На Atari один прогон по 8 средам × 128 шагов — это 1024 перехода и дюжина секунд времени среды. Выбрасывать это после одного шага градиента расточительно.

Trust Region Policy Optimization (TRPO, Schulman 2015) стал первым решением: ограничить каждое обновление так, чтобы KL-дивергенция между старой и новой политикой оставалась ниже `δ`. Теоретически чисто, но требует решения методом сопряжённых градиентов на каждое обновление. Никто не запускает TRPO в 2026 году.

PPO (Schulman et al. 2017) заменяет жёсткое ограничение доверительной области простой усечённой целевой функцией. Одна дополнительная строка кода. Десять эпох на прогон. Никаких сопряжённых градиентов. Достаточно хорошие теоретические гарантии. Спустя девять лет это по-прежнему алгоритм градиента политики по умолчанию — от MuJoCo до RLHF.

## Концепция

![Усечённая суррогатная целевая функция PPO: отсечение отношения на уровне 1 ± ε](../assets/ppo.svg)

**Отношение важности.**

`r_t(θ) = π_θ(a_t | s_t) / π_{θ_old}(a_t | s_t)`

Это отношение правдоподобия новой политики к политике, собравшей данные. `r_t = 1` означает отсутствие изменений. `r_t = 2` означает, что новая политика вдвое более склонна выбрать `a_t`, чем старая.

**Усечённая суррогатная функция.**

`L^{CLIP}(θ) = E_t [ min( r_t(θ) A_t, clip(r_t(θ), 1-ε, 1+ε) A_t ) ]`

Два случая:

- Если преимущество `A_t > 0` и отношение пытается вырасти выше `1 + ε`, отсечение делает градиент плоским — не толкайте хорошее действие дальше, чем на `+ε` выше старой вероятности.
- Если преимущество `A_t < 0` и отношение пытается вырасти выше `1 - ε` (то есть мы бы сделали плохое действие более вероятным по сравнению с его усечённым снижением), отсечение ограничивает градиент сверху — не толкайте плохое действие ниже `-ε`.

`min` обрабатывает противоположное направление: если отношение сдвинулось в *выгодную* сторону, градиент всё равно передаётся (на стороне, которая была бы вам во вред, отсечения нет).

Типичное значение `ε = 0.2`. Постройте целевую функцию как функцию от `r_t`: кусочно-линейная функция с плоской «крышей» на «хорошей стороне» и плоским «полом» на «плохой стороне».

**Полная функция потерь PPO.**

`L(θ, φ) = L^{CLIP}(θ) - c_v · (V_φ(s_t) - V_t^{target})² + c_e · H(π_θ(·|s_t))`

Та же структура «актор–критик», что у A2C. Три коэффициента, обычно `c_v = 0.5`, `c_e = 0.01`, `ε = 0.2`.

**Цикл обучения.**

1. Соберите `N × T` переходов по `N` параллельным средам за `T` шагов каждая.
2. Вычислите преимущества (GAE), зафиксируйте их как константы.
3. Зафиксируйте `π_{θ_old}` как снимок текущей `π_θ`.
4. На `K` эпохах, для каждого минибатча `(s, a, A, V_target, log π_old(a|s))`:
   - Вычислите `r_t(θ) = exp(log π_θ(a|s) - log π_old(a|s))`.
   - Примените `L^{CLIP}` + потерю ценности + энтропию.
   - Сделайте шаг градиента.
5. Отбросьте прогон. Вернитесь к шагу 1.

`K = 10` и минибатчи по 64 — стандартный набор гиперпараметров. PPO устойчив: точные числа редко имеют значение в пределах ±50%.

**Вариант с KL-штрафом.** Оригинальная статья предлагала альтернативу с адаптивным KL-штрафом: `L = L^{PG} - β · KL(π_θ || π_old)`, где `β` подстраивается по наблюдаемому KL. Версия с отсечением стала доминирующей; KL-вариант сохраняется в RLHF (где KL к референсной политике — это отдельное ограничение, которое всё равно всегда нужно).

## Реализация

### Шаг 1: зафиксировать `log π_old(a | s)` во время прогона

```python
for step in range(T):
    probs = softmax(logits(theta, state_features(s)))
    a = sample(probs, rng)
    s_next, r, done = env.step(s, a)
    buffer.append({
        "s": s, "a": a, "r": r, "done": done,
        "v_old": value(w, state_features(s)),
        "log_pi_old": log(probs[a] + 1e-12),
    })
    s = s_next
```

Снимок делается один раз, во время прогона. Он не меняется в течение эпох обновления.

### Шаг 2: вычислить GAE-преимущества (урок 07)

Так же, как в A2C. Нормализуйте по батчу.

### Шаг 3: обновление с усечённой суррогатной функцией

```python
for _ in range(K_EPOCHS):
    for mb in minibatches(buffer, size=64):
        for rec in mb:
            x = state_features(rec["s"])
            probs = softmax(logits(theta, x))
            logp = log(probs[rec["a"]] + 1e-12)
            ratio = exp(logp - rec["log_pi_old"])
            adv = rec["advantage"]
            surrogate = min(
                ratio * adv,
                clamp(ratio, 1 - EPS, 1 + EPS) * adv,
            )
            # backprop -surrogate, add value loss, subtract entropy
            grad_logpi = onehot(rec["a"]) - probs
            if (adv > 0 and ratio >= 1 + EPS) or (adv < 0 and ratio <= 1 - EPS):
                pg_grad = 0.0  # clipped
            else:
                pg_grad = ratio * adv
            for i in range(N_ACTIONS):
                for j in range(N_FEAT):
                    theta[i][j] += LR * pg_grad * grad_logpi[i] * x[j]
```

Паттерн «усечено → нулевой градиент» — это сердце PPO. Если новая политика уже сместилась слишком далеко в выгодную сторону, обновление останавливается.

### Шаг 4: ценность и энтропия

Добавьте стандартный MSE для цели критика и бонус энтропии для актора — так же, как в A2C.

### Шаг 5: диагностика

Три вещи, за которыми нужно следить на каждом обновлении:

- **Средний KL** `E[log π_old - log π_θ]`. Должен оставаться в `[0, 0.02]`. Если проскакивает `0.1`, уменьшите `K_EPOCHS` или `LR`.
- **Доля отсечения (clip fraction)** — доля сэмплов, чьё отношение лежит вне `[1-ε, 1+ε]`. Должна быть `~0.1-0.3`. Если `~0`, отсечение никогда не срабатывает → увеличьте `LR` или `K_EPOCHS`. Если `~0.5+`, вы переобучаетесь на прогоне → уменьшите их.
- **Объяснённая дисперсия** `1 - Var(V_target - V_pred) / Var(V_target)`. Метрика качества критика. Должна расти к 1 по мере обучения критика.

## Подводные камни

- **Неверно подобранный коэффициент отсечения.** `ε = 0.2` — фактический стандарт. `0.1` делает обновления слишком робкими; `0.3+` провоцирует нестабильность.
- **Слишком много эпох.** `K > 20` регулярно дестабилизирует обучение, потому что политика уходит далеко от `π_old`. Ограничивайте число эпох, особенно для крупных сетей.
- **Отсутствие нормализации вознаграждения.** Большие масштабы вознаграждения «съедают» диапазон отсечения. Нормализуйте вознаграждения (скользящее стандартное отклонение) перед вычислением преимуществ.
- **Забытая нормализация преимущества.** Нормализация к нулевому среднему и единичной дисперсии по батчу — стандарт. Пропуск этого шага ломает PPO на большинстве бенчмарков.
- **Не затухающая скорость обучения.** PPO выигрывает от линейного затухания LR до нуля. Постоянная LR часто хуже.
- **Ошибки в арифметике отношения важности.** Всегда `exp(log_new - log_old)` для численной устойчивости, а не `new / old`.
- **Неверный знак градиента.** Максимизация суррогата = *минимизация* `-L^{CLIP}`. Перевёрнутый знак — самая частая ошибка в PPO.

## Применение

PPO — алгоритм RL по умолчанию в 2026 году для удивительно широкого круга задач:

| Сценарий применения | Вариант PPO |
|----------|-------------|
| MuJoCo / управление роботами | PPO с гауссовской политикой, GAE(0.95) |
| Atari / игры с дискретными действиями | PPO с категориальной политикой и последовательными прогонами по 128 шагов |
| RLHF для LLM | PPO с KL-штрафом относительно референсной модели; вознаграждение от модели вознаграждения в конце ответа |
| Крупномасштабные игровые агенты | IMPALA + PPO (AlphaStar, OpenAI Five) |
| LLM для решения задач | GRPO (урок 12) — вариант PPO без критика |
| Данные только о предпочтениях | DPO — аналитическое сведение PPO+KL, без сэмплирования во время обучения |

*Форма* функции потерь PPO — усечённый суррогат + ценность + энтропия — это каркас для DPO, GRPO и почти любого пайплайна RLHF.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Отношение важности | «r_t(θ)» | `π_θ(a\|s) / π_old(a\|s)`; отклонение от политики, которая собрала данные. |
| Усечённая суррогатная функция | «Главный приём PPO» | `min(r·A, clip(r, 1-ε, 1+ε)·A)`; после границы отсечения с выгодной стороны градиент становится плоским. |
| Доверительная область | «Замысел TRPO / PPO» | Ограничение KL для каждого обновления, гарантирующее монотонное улучшение. |
| KL-штраф | «Мягкая доверительная область» | Альтернативный вариант PPO: `L - β · KL(π_θ \|\| π_old)`. Значение `β` адаптивно. |
| Доля отсечения | «Как часто срабатывает отсечение» | Диагностическая метрика — должна составлять 0.1-0.3; выход за этот диапазон означает неверную настройку. |
| Многоэпоховое обучение | «Переиспользование данных» | K эпох на каждом прогоне; ценой дисперсии достигается более высокая эффективность по выборкам. |
| Почти по текущей политике | «В основном по текущей политике» | Формально PPO работает по данным текущей политики, но при K>1 безопасно использует на последующих эпохах данные от немного отличающейся политики. |
| PPO-KL | «Другой PPO» | Вариант с KL-штрафом; применяется в RLHF, где KL относительно референсной политики уже служит ограничением. |
