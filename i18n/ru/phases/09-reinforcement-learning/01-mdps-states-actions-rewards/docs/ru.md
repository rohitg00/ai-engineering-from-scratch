# MDP, состояния, действия и вознаграждения

> Марковский процесс принятия решений (MDP) — это пять вещей: состояния, действия, переходы, вознаграждения, дисконт. Всё в обучении с подкреплением (RL) — Q-обучение, PPO, DPO, GRPO — оптимизирует именно эту структуру. Выучите её один раз — и остальная часть обучения с подкреплением достанется вам бесплатно.

**Тип:** Learn**Языки:** Python**Предварительные требования:** Фаза 1 · 06 (Probability & Distributions), Фаза 2 · 01 (ML Taxonomy)**Время:** ~45 минут
## Проблема

Вы пишете шахматного бота. Или планировщик запасов. Или торгового агента. Или цикл PPO, обучающий модель рассуждениям. Четыре разные области — и один удивительный факт: все четыре сводятся к одному и тому же математическому объекту.

Обучение с учителем даёт вам пары `(x, y)` и просит подобрать функцию. Обучение с подкреплением не даёт меток — только поток состояний, совершённых действий и скалярное вознаграждение. Выиграл ли ход партию? Сэкономило ли решение о пополнении запасов деньги? Принесла ли сделка прибыль? Привёл ли токен, только что сгенерированный LLM, к более высокому вознаграждению от судьи?

Вы не сможете учиться на этом потоке, пока не формализуете его. «Что я увидел», «что я сделал», «что произошло дальше», «насколько это было хорошо» — каждое из этих понятий должно стать объектом, с которым можно рассуждать формально. Эта формализация и есть MDP. Каждый алгоритм RL в этой фазе, включая циклы RLHF и GRPO в конце, оптимизирует именно эту структуру.

## Концепция

![Марковский процесс принятия решений: состояния, действия, переходы, вознаграждения, дисконт](../assets/mdp.svg)

**Пять объектов.**

- **Состояния** `S`. Всё, что нужно агенту для принятия решения. В GridWorld — это клетка. В шахматах — доска. В LLM — контекстное окно плюс любая память.
- **Действия** `A`. Варианты выбора. Сходить вверх/вниз/влево/вправо. Сделать ход. Сгенерировать токен.
- **Переходы** `P(s' | s, a)`. При состоянии `s` и действии `a` — распределение над следующим состоянием. Детерминированные в шахматах, стохастические в управлении запасами, почти детерминированные при декодировании LLM.
- **Вознаграждения** `R(s, a, s')`. Скалярный сигнал. Победа = +1, поражение = -1. Выручка минус затраты. Слагаемое отношения логарифмов правдоподобия в GRPO.
- **Дисконт** `γ ∈ [0, 1)`. Насколько будущее вознаграждение весит по сравнению с настоящим. `γ = 0.99` даёт горизонт около 100 шагов; `γ = 0.9` — около 10.

**Марковское свойство** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`. Будущее зависит только от текущего состояния. Если это не так, представление состояния неполно — это сбой не метода, а состояния.

**Политики и отдачи.** Политика `π(a | s)` отображает состояния в распределения действий. Отдача `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …` — это дисконтированная сумма будущих вознаграждений. Ценность `V^π(s) = E[G_t | s_t = s]` — ожидаемая отдача при старте из `s` под политикой `π`. Q-ценность `Q^π(s, a) = E[G_t | s_t = s, a_t = a]` — ожидаемая отдача при старте с конкретного действия. Каждый алгоритм RL оценивает одну из этих двух величин, а затем соответствующим образом улучшает `π`.

**Уравнения Беллмана.** Уравнения неподвижной точки, на которых строится всё содержимое этой фазы:

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

Они разбивают ожидаемую отдачу на «вознаграждение этого шага» плюс «дисконтированную ценность того, куда вы попадёте». Рекурсивно. Каждый алгоритм Фазы 9 либо итерирует это уравнение до сходимости (динамическое программирование), либо сэмплирует из него (метод Монте-Карло), либо бутстрапирует на один шаг (временная разница).

## Реализация

### Шаг 1: крошечный детерминированный MDP

GridWorld 4×4. Агент стартует в левом верхнем углу, терминальное состояние — в правом нижнем, вознаграждение -1 за шаг, действия `{up, down, left, right}`. См. `code/main.py`.

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

Пять строк. Это вся среда целиком. Детерминированные переходы, постоянный штраф за шаг, поглощающее терминальное состояние.

### Шаг 2: прогон политики

Политика — это функция из состояния в распределение действий. Простейший вариант: равномерно случайная.

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

Запустите случайную политику 1000 раз. Средняя отдача составляет примерно от -60 до -80 для этой доски 4×4. Оптимальная отдача равна -6 (прямой путь по диагонали вниз-вправо). Сокращение этого разрыва — вот в чём вся суть Фазы 9.

### Шаг 3: точное вычисление `V^π` через уравнение Беллмана

Для небольших MDP уравнение Беллмана — это линейная система. Перечислите состояния, примените математическое ожидание, итерируйте, пока значения не перестанут меняться.

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

Это итеративное оценивание политики. Это первый алгоритм у Sutton & Barto и теоретический фундамент для каждого последующего метода RL.

### Шаг 4: `γ` — гиперпараметр с физическим смыслом

Эффективный горизонт приблизительно равен `1 / (1 - γ)`. `γ = 0.9` → 10 шагов. `γ = 0.99` → 100 шагов. `γ = 0.999` → 1000 шагов.

Слишком низкое значение — и агент действует близоруко. Слишком высокое — и присвоение заслуг (credit assignment) становится зашумлённым, потому что многие ранние шаги делят ответственность за далёкое будущее вознаграждение. RLHF для LLM обычно использует `γ = 1`, потому что эпизоды короткие и ограниченные. Задачи управления используют `0.95–0.99`. Стратегические игры с длинным горизонтом используют `0.999`.

## Подводные камни

- **Немарковское состояние.** Если для решения нужны последние три наблюдения, «состояние» — это не просто текущее наблюдение. Решение: стекирование кадров (DQN на Atari стекирует 4) или рекуррентное состояние (LSTM/GRU по наблюдениям).
- **Разреженные вознаграждения.** Вознаграждение только за победу делает обучение почти невозможным в больших пространствах состояний. Формируйте вознаграждение (промежуточный сигнал) или запускайте обучение через имитацию (Фаза 9 · 09).
- **Взлом вознаграждения (reward hacking).** Оптимизация суррогатного вознаграждения часто порождает патологическое поведение. Агент OpenAI в гонках на лодках вечно крутился по кругу, собирая бонусы, вместо того чтобы финишировать. Всегда определяйте вознаграждение через целевой результат, а не через суррогат.
- **Неверно заданный дисконт.** `γ = 1` в задаче с бесконечным горизонтом делает любую ценность бесконечной. Всегда ограничивайте либо конечным горизонтом, либо `γ < 1`.
- **Масштаб вознаграждения.** Вознаграждения {+100, -100} и {+1, -1} дают идентичные оптимальные политики, но сильно разные величины градиентов. Нормализуйте примерно к `[-1, 1]`, прежде чем подавать в PPO/DQN.

## Применение

Стек 2026 года сводит любой RL-пайплайн к MDP ещё до того, как написана хоть одна строка кода:

| Situation | State | Action | Reward | γ |
|-----------|-------|--------|--------|---|
| Управление (локомоция, манипуляция) | Углы и скорости суставов | Непрерывные крутящие моменты | Специфичное для задачи, формированное | 0.99 |
| Игры (шахматы, го, покер) | Доска + история | Допустимый ход | Победа=+1 / поражение=-1 | 1.0 (конечный) |
| Запасы / ценообразование | Запасы + спрос | Объём заказа | Выручка - затраты | 0.95 |
| RLHF для LLM | Токены контекста | Следующий токен | Оценка модели вознаграждения в конце | 1.0 (эпизод ~200 токенов) |
| GRPO для рассуждений | Промпт + частичный ответ | Следующий токен | Верификатор 0/1 в конце | 1.0 |

Выпишите все пять компонентов кортежа прежде, чем писать хоть один цикл обучения. Большинство отчётов о багах вида «RL не работает» сводится к формулировке MDP, сломанной ещё на бумаге.

## Ключевые термины

| Term | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| MDP | «Постановка задачи RL» | Кортеж `(S, A, P, R, γ)`, удовлетворяющий марковскому свойству. |
| State | «То, что видит агент» | Достаточная статистика для будущей динамики в рамках выбранного класса политик. |
| Policy | «Поведение агента» | Условное распределение `π(a \| s)` или детерминированное отображение `s → a`. |
| Return | «Суммарное вознаграждение» | Дисконтированная сумма `Σ γ^t r_t` начиная с текущего шага. |
| Value | «Насколько хорошо состояние» | Ожидаемая отдача под политикой `π`, начиная из `s`. |
| Q-value | «Насколько хорошо действие» | Ожидаемая отдача под политикой `π`, начиная из `s` с первым действием `a`. |
| Bellman equation | «Рекурсия динамического программирования» | Разложение ценности / Q в неподвижной точке на вознаграждение за один шаг плюс дисконтированную ценность следующего состояния. |
| Discount `γ` | «Будущее против настоящего» | Геометрический вес далёкого будущего вознаграждения; эффективный горизонт `~1/(1-γ)`. |
