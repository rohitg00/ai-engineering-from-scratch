# Методы Монте-Карло — обучение по полным эпизодам

> Динамическому программированию нужна модель. Методу Монте-Карло не нужно ничего, кроме эпизодов. Запустите политику, посмотрите на отдачи, усредните их. Простейшая идея в RL — и та, что открывает дорогу ко всему последующему.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 9 · 01 (MDP), Фаза 9 · 02 (динамическое программирование)
**Время:** ~75 минут

## Проблема

Динамическое программирование элегантно, но предполагает, что вы можете запросить `P(s' | s, a)` для каждого состояния и действия. Почти ничто в реальном мире так не устроено. Робот не может аналитически вычислить распределение по пикселям камеры после приложения момента к суставу. Алгоритм ценообразования не может проинтегрировать по всем возможным реакциям клиента. LLM не может перечислить все возможные продолжения после токена.

Вам нужен метод, которому требуется лишь возможность *сэмплировать* из среды. Запустите политику. Получите траекторию `s_0, a_0, r_1, s_1, a_1, r_2, …, s_T`. Используйте её для оценки ценностей. Это и есть метод Монте-Карло.

Сдвиг от DP к MC философски важен: мы переходим от *известной модели + точного бэкапа* к *сэмплированным прогонам + усреднённой отдаче*. Дисперсия растёт, но применимость взрывается. Каждый алгоритм RL после этого урока — TD, Q-обучение, REINFORCE, PPO, GRPO — это, по сути, оценщик Монте-Карло, иногда с надстроенным бутстрапингом.

## Концепция

![Монте-Карло: прогон, вычисление отдач, усреднение; первое посещение против каждого посещения](../assets/monte-carlo.svg)

**Основная идея одной строкой:** `V^π(s) = E_π[G_t | s_t = s] ≈ (1/N) Σ_i G^{(i)}(s)`, где `G^{(i)}(s)` — наблюдаемые отдачи после посещений `s` под политикой `π`.

**MC с первым посещением против MC с каждым посещением.** Пусть эпизод посещает состояние `s` несколько раз; MC с первым посещением учитывает только отдачу от первого визита, MC с каждым посещением учитывает все визиты. Оба несмещены в пределе. Первый проще анализировать (независимые одинаково распределённые сэмплы). Второй использует больше данных на эпизод и на практике обычно сходится быстрее.

**Инкрементное среднее.** Вместо хранения всех отдач обновляйте скользящее среднее:

`V_n(s) = V_{n-1}(s) + (1/n) [G_n - V_{n-1}(s)]`

Перегруппируем: `V_new = V_old + α · (target - V_old)`, где `α = 1/n`. Замените `1/n` на постоянный шаг `α ∈ (0, 1)` — и получите нестационарный оценщик MC, отслеживающий изменения `π`. Этот переход и есть весь путь от MC к TD и к каждому современному алгоритму RL.

**Теперь исследование — это проблема.** DP касалось каждого состояния перечислением. MC видит только те состояния, которые посещает политика. Если `π` детерминирована, целые области пространства состояний никогда не сэмплируются, и их оценки ценности навсегда остаются нулевыми. Три решения, в историческом порядке:

1. **Исследующие старты (exploring starts).** Начинать каждый эпизод со случайной пары (s, a). Гарантирует покрытие; на практике нереалистично (нельзя «сбросить» робота в произвольное состояние).
2. **ε-жадность.** Действовать жадно относительно текущего Q, но с вероятностью `ε` выбирать случайное действие. Все пары состояние-действие асимптотически будут сэмплированы.
3. **Внеполитический MC (off-policy).** Собирать данные под поведенческой политикой `μ`, обучаться о целевой политике `π` через выборку по значимости (importance sampling). Высокая дисперсия, но это мост к методам с буфером воспроизведения, таким как DQN.

**Управление методом Монте-Карло.** Оценка → улучшение → оценка, как в итерации по политике, но оценка основана на сэмплировании:

1. Запустить `π`, получить эпизод.
2. Обновить `Q(s, a)` по наблюдаемым отдачам.
3. Сделать `π` ε-жадной относительно `Q`.
4. Повторить.

Сходится к `Q*` и `π*` с вероятностью 1 при мягких условиях (каждая пара посещается бесконечно часто, `α` удовлетворяет условию Роббинса-Монро).

## Реализация

### Шаг 1: прогон → список (s, a, r)

```python
def rollout(env, policy, max_steps=200):
    trajectory = []
    s = env.reset()
    for _ in range(max_steps):
        a = policy(s)
        s_next, r, done = env.step(s, a)
        trajectory.append((s, a, r))
        s = s_next
        if done:
            break
    return trajectory
```

Никакой модели — только `env.reset()` и `env.step(s, a)`. Тот же интерфейс, что и у среды gym, но в упрощённом виде.

### Шаг 2: вычисление отдач (обратный проход)

```python
def returns_from(trajectory, gamma):
    returns = []
    G = 0.0
    for _, _, r in reversed(trajectory):
        G = r + gamma * G
        returns.append(G)
    return list(reversed(returns))
```

Один проход, `O(T)`. Обратная рекуррентность `G_t = r_{t+1} + γ G_{t+1}` избавляет от повторного суммирования.

### Шаг 3: оценивание политики методом MC с первым посещением

```python
def mc_policy_evaluation(env, policy, episodes, gamma=0.99):
    V = defaultdict(float)
    counts = defaultdict(int)
    for _ in range(episodes):
        trajectory = rollout(env, policy)
        returns = returns_from(trajectory, gamma)
        seen = set()
        for t, ((s, _, _), G) in enumerate(zip(trajectory, returns)):
            if s in seen:
                continue
            seen.add(s)
            counts[s] += 1
            V[s] += (G - V[s]) / counts[s]
    return V
```

Три строки делают всю работу: отметить состояние как посещённое при первом визите, увеличить счётчик, обновить скользящее среднее.

### Шаг 4: ε-жадное управление MC (на основе своей политики)

```python
def mc_control(env, episodes, gamma=0.99, epsilon=0.1):
    Q = defaultdict(lambda: {a: 0.0 for a in ACTIONS})
    counts = defaultdict(lambda: {a: 0 for a in ACTIONS})

    def policy(s):
        if random() < epsilon:
            return choice(ACTIONS)
        return max(Q[s], key=Q[s].get)

    for _ in range(episodes):
        trajectory = rollout(env, policy)
        returns = returns_from(trajectory, gamma)
        seen = set()
        for (s, a, _), G in zip(trajectory, returns):
            if (s, a) in seen:
                continue
            seen.add((s, a))
            counts[s][a] += 1
            Q[s][a] += (G - Q[s][a]) / counts[s][a]
    return Q, policy
```

### Шаг 5: сравнение с золотым стандартом DP

Ваша MC-оценка `V^π` должна сходиться с результатом DP из Урока 02 по мере того, как число эпизодов → ∞. На практике: 50 000 эпизодов на GridWorld 4×4 приближают вас к ответу DP с точностью до `~0.1`.

## Подводные камни

- **Бесконечные эпизоды.** MC требует, чтобы эпизоды *завершались*. Если ваша политика может зациклиться навсегда, ограничьте `max_steps` и считайте достижение лимита неявным провалом. GridWorld со случайной политикой регулярно упирается в таймаут — это нормально, просто убедитесь, что вы правильно это учитываете.
- **Дисперсия.** MC использует полные отдачи. На длинных эпизодах дисперсия огромна — одно невезучее вознаграждение в конце сдвигает `V(s_0)` на ту же величину. Методы TD (Урок 04) сокращают её за счёт бутстрапинга.
- **Покрытие состояний.** Жадный MC на свежем Q с ничьими будет всегда пробовать только одно действие. Вы *обязаны* исследовать (ε-жадность, исследующие старты, UCB).
- **Нестационарные политики.** Если `π` меняется (как при управлении MC), старые отдачи получены от другой политики. MC с постоянным α справляется с этим; MC с усреднением по сэмплам — нет.
- **Внеполитическая выборка по значимости.** Веса `π(a|s)/μ(a|s)` перемножаются вдоль траектории. Дисперсия взрывается с ростом горизонта. Ограничивайте пооперационной взвешенной IS или переходите на TD.

## Применение

Роль методов Монте-Карло в 2026 году:

| Сценарий применения | Почему MC |
|----------|--------|
| Игры с коротким горизонтом (блэкджек, покер) | Эпизоды естественно завершаются; отдачи чистые. |
| Офлайн-оценивание залогированной политики | Усреднение дисконтированных отдач по сохранённым траекториям. |
| Поиск по дереву методом Монте-Карло (AlphaZero) | MC-прогоны из листьев дерева направляют выбор. |
| Оценивание RL для LLM | Вычисление среднего вознаграждения по сэмплированным завершениям для данной политики. |
| Оценка базовой линии в PPO | Целевое значение преимущества `A_t = G_t - V(s_t)` использует MC-отдачу `G_t`. |
| Преподавание RL | Простейший алгоритм, который действительно работает — убирает бутстрапинг, обнажая ядро идеи. |

Современные алгоритмы глубокого RL (PPO, SAC) интерполируют между чистым MC (полные отдачи) и чистым TD (одношаговый бутстрапинг) через `n`-шаговые отдачи или GAE. Оба крайних случая — экземпляры одного и того же оценщика.

## Ключевые термины

| Термин | Что говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Метод Монте-Карло | «Случайное сэмплирование» | Оценка математических ожиданий усреднением по независимым одинаково распределённым сэмплам из распределения. |
| Отдача `G_t` | «Будущее вознаграждение» | Сумма дисконтированных вознаграждений от шага `t` до конца эпизода: `Σ_{k≥0} γ^k r_{t+k+1}`. |
| MC с первым посещением | «Считать каждое состояние один раз» | Только первый визит в эпизоде вносит вклад в оценку ценности. |
| MC с каждым посещением | «Использовать все визиты» | Каждый визит вносит вклад; немного смещённая оценка, но более эффективна по данным. |
| ε-жадная стратегия | «Шум исследования» | Выбирать жадное действие с вероятностью `1-ε`; случайное действие с вероятностью `ε`. |
| Выборка по значимости | «Коррекция сэмплирования из неверного распределения» | Перевзвешивание отдач произведениями `π(a\|s)/μ(a\|s)` для оценки `V^π` по данным `μ`. |
| Обучение на основе своей политики | «Учиться на собственных данных» | Целевая политика = поведенческая политика. Обычный MC, PPO, SARSA. |
| Обучение вне политики | «Учиться на чужих данных» | Целевая политика ≠ поведенческая политика. MC с выборкой по значимости, Q-обучение, DQN. |
