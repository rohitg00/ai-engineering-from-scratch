# Динамическое программирование — итерация по политике и итерация по ценности

> Динамическое программирование — это RL с читерством. Вы уже знаете функции переходов и вознаграждений; остаётся лишь итерировать уравнение Беллмана, пока `V` или `π` не перестанут меняться. Это эталон, к которому стремится приблизиться каждый метод, основанный на сэмплировании.

**Тип:** Build**Языки:** Python**Предварительные требования:** Фаза 9 · 01 (MDPs)**Время:** ~75 минут
## Проблема

У вас есть MDP с известной моделью: вы можете запросить `P(s' | s, a)` и `R(s, a, s')` для любой пары состояние-действие. Менеджер запасов знает распределение спроса. В настольной игре переходы детерминированы. GridWorld — это четыре строки Python. У вас есть *модель*.

Безмодельный RL (Q-обучение, PPO, REINFORCE) был придуман для случая, когда модели нет — можно только сэмплировать из среды. Но когда модель есть, существуют более быстрые и качественные методы: динамическое программирование. Беллман разработал их в 1957 году. Они по-прежнему определяют правильность: когда говорят «оптимальная политика для этого MDP», имеют в виду политику, которую вернуло бы DP.

Они нужны вам и в 2026 году по трём причинам. Во-первых, каждая табличная среда в исследованиях RL (GridWorld, FrozenLake, CliffWalking) решается через DP, чтобы получить эталонную политику. Во-вторых, точные значения позволяют *отлаживать* методы сэмплирования: если оценка Q-обучения для `V*(s_0)` расходится с ответом DP на 30%, значит, в вашем Q-обучении есть баг. В-третьих, современные методы офлайн-RL и планирования (MCTS, поиск AlphaZero, RL на основе модели в Фазе 9 · 10) — все они итерируют бэкап Беллмана по выученной или заданной модели.

## Концепция

![Итерация по политике и итерация по ценности бок о бок](../assets/dp.svg)

**Два алгоритма, оба — итерация неподвижной точки над уравнением Беллмана.**

**Итерация по политике.** Чередует два шага, пока политика не перестанет меняться.

1. *Оценивание:* при данной политике `π` вычислить `V^π`, многократно применяя `V(s) ← Σ_a π(a|s) Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`, пока не наступит сходимость.
2. *Улучшение:* при данном `V^π` сделать `π` жадной относительно `V^π`: `π(s) ← argmax_a Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`.

Сходимость гарантирована, потому что (а) каждый шаг улучшения либо оставляет `π` неизменной, либо строго увеличивает `V^π` для некоторого состояния, (б) пространство детерминированных политик конечно. Обычно сходится за ~5–20 внешних итераций даже для больших пространств состояний.

**Итерация по ценности.** Объединяет оценивание и улучшение в один проход. Применяет уравнение *оптимальности* Беллмана:

`V(s) ← max_a Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`

Повторяйте, пока `max_s |V_{new}(s) - V(s)| < ε`. В конце извлеките политику, взяв жадное действие. Строго быстрее на одной итерации — нет внутреннего цикла оценивания, — но обычно требует больше итераций для сходимости.

**Обобщённая итерация по политике (GPI).** Объединяющая рамка. Функция ценности и политика заперты в двустороннем цикле улучшения; любой метод, который продвигает и то, и другое к взаимной согласованности (асинхронная итерация по ценности, модифицированная итерация по политике, Q-обучение, актор-критик, PPO), — это экземпляр GPI.

**Почему важно `γ < 1`.** Оператор Беллмана — это `γ`-сжатие в sup-норме: `||T V - T V'||_∞ ≤ γ ||V - V'||_∞`. Сжатие подразумевает единственную неподвижную точку и геометрическую сходимость. Откажитесь от `γ < 1`, и вы потеряете эту гарантию — понадобится конечный горизонт или поглощающее терминальное состояние.

## Реализация

### Шаг 1: постройте модель MDP для GridWorld

Используйте тот же GridWorld 4×4 из Урока 01. Добавим стохастический вариант: с вероятностью `0.1` агент соскальзывает в случайное перпендикулярное направление.

```python
SLIP = 0.1

def transitions(state, action):
    if state == TERMINAL:
        return [(state, 0.0, 1.0)]
    outcomes = []
    for direction, prob in action_probs(action):
        outcomes.append((apply_move(state, direction), -1.0, prob))
    return outcomes
```

`transitions(s, a)` возвращает список `(s', r, p)`. Это вся модель целиком.

### Шаг 2: оценивание политики

При данной политике `π(s) = {action: prob}` итерируйте уравнение Беллмана, пока `V` не перестанет меняться:

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = sum(pi_a * sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a))
                   for a, pi_a in policy(s).items())
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

### Шаг 3: улучшение политики

Замените `π` жадной политикой относительно `V`. Если `π` не изменилась — вернитесь: мы в оптимуме.

```python
def policy_improvement(V, gamma=0.99):
    new_policy = {}
    for s in states():
        best_a = max(
            ACTIONS,
            key=lambda a: sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a)),
        )
        new_policy[s] = best_a
    return new_policy
```

### Шаг 4: соберите всё вместе

```python
def policy_iteration(gamma=0.99):
    policy = {s: "up" for s in states()}   # arbitrary start
    for _ in range(100):
        V = policy_evaluation(lambda s: {policy[s]: 1.0}, gamma)
        new_policy = policy_improvement(V, gamma)
        if new_policy == policy:
            return V, policy
        policy = new_policy
```

Типичная сходимость на 4×4: 4–6 внешних итераций. На выходе `V*(0,0) ≈ -6` и политика, строго уменьшающая число шагов.

### Шаг 5: итерация по ценности (версия в один цикл)

```python
def value_iteration(gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = max(sum(p * (r + gamma * V[s_prime])
                       for s_prime, r, p in transitions(s, a))
                   for a in ACTIONS)
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            break
    policy = policy_improvement(V, gamma)
    return V, policy
```

Та же неподвижная точка, меньше строк кода.

## Подводные камни

- **Забыть обработать терминалы.** Если применить Беллмана к поглощающему состоянию, он всё равно подберёт «лучшее действие», которое ничего не меняет. Защититесь проверкой `if s == terminal: V[s] = 0`.
- **Sup-норма против сходимости по L2.** Используйте `max |V_new - V|`, а не среднее. Теоретическая гарантия дана именно для sup-нормы.
- **Обновление на месте против синхронного.** Обновление `V[s]` на месте (Гаусс-Зейдель) сходится быстрее, чем отдельный словарь `V_new` (Якоби). В продакшен-коде используют обновление на месте.
- **Ничьи в политике.** Если у двух действий одинаковое Q-значение, `argmax` может по-разному разрешать ничью на каждой итерации, из-за чего проверка «политика стабильна» начинает колебаться. Используйте стабильное разрешение ничьи (первое действие в фиксированном порядке).
- **Взрыв пространства состояний.** DP работает за `O(|S| · |A|)` на проход. Работает до ~10⁷ состояний. Дальше нужна аппроксимация функций (Фаза 9 · 05 и далее).

## Применение

В 2026 году DP — это эталон правильности и внутренний цикл планировщиков:

| Use case | Method |
|----------|--------|
| Точное решение небольшого табличного MDP | Итерация по ценности (проще) или итерация по политике (меньше внешних шагов) |
| Проверка реализации Q-обучения / PPO | Сравнение с DP-оптимальным V* на игрушечной среде |
| RL на основе модели (Фаза 9 · 10) | Бэкап Беллмана по выученной модели переходов |
| Планирование в AlphaZero / MuZero | Monte Carlo Tree Search = асинхронный бэкап Беллмана |
| Офлайн-RL (CQL, IQL) | Консервативная Q-итерация — DP со штрафом за действия вне распределения |

Каждый раз, когда кто-то говорит «оптимальная функция ценности», имеется в виду «неподвижная точка DP». Когда вы видите `V*` или `Q*` в статье, представляйте себе этот цикл.

## Ключевые термины

| Term | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Policy iteration | «Алгоритм DP» | Чередование оценивания (`V^π`) и улучшения (жадная `π` относительно `V^π`) до тех пор, пока политика не перестанет меняться. |
| Value iteration | «Более быстрый DP» | Бэкап оптимальности Беллмана, применённый за один проход; сходится к `V*` геометрически. |
| Bellman operator | «Рекурсия» | `(T V)(s) = max_a Σ P (r + γ V(s'))`; `γ`-сжатие в sup-норме. |
| Contraction | «Почему DP сходится» | Любой оператор `T` с `\|\|T x - T y\|\| ≤ γ \|\|x - y\|\|` имеет единственную неподвижную точку. |
| GPI | «Всё есть DP» | Обобщённая итерация по политике: любой метод, продвигающий `V` и `π` к взаимной согласованности. |
| Synchronous update | «В стиле Якоби» | Использовать старое `V` на протяжении всего прохода; чисто анализируется, но медленнее. |
| In-place update | «В стиле Гаусса-Зейделя» | Использовать `V` по мере его обновления; на практике сходится быстрее. |
