# Актор-критик — A2C и A3C

> REINFORCE зашумлён. Добавьте критика, выучивающего `V̂(s)`, вычтите его из отдачи — и вы получите преимущество (advantage) с тем же математическим ожиданием, но существенно меньшей дисперсией. Это и есть архитектура «актор-критик» (actor-critic). A2C выполняет её синхронно; A3C — распределённо по потокам. Оба служат концептуальной моделью для каждого современного метода глубокого RL.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Этап 9 · 04 (TD-обучение), этап 9 · 06 (REINFORCE)
**Время:** ~75 минут

## Проблема

Ванильный REINFORCE работает, но его дисперсия ужасна. Отдачи Монте-Карло `G_t` могут различаться между эпизодами в 10 раз. Умножение этого шума на `∇ log π` и усреднение даёт оценку градиента, которой требуются тысячи эпизодов, чтобы сдвинуть политику на то же расстояние, на которое DQN сдвигает её за куда меньшее число обновлений.

Дисперсия возникает из-за использования сырых отдач. Если вычесть базовую линию `b(s_t)` — любую функцию состояния, включая выученное значение, — математическое ожидание не изменится, а дисперсия упадёт. Лучшая практически достижимая базовая линия — `V̂(s_t)`. Теперь величина, умножаемая на `∇ log π`, — это *преимущество* (advantage):

`A(s, a) = G - V̂(s)`

Действие хорошее, если оно дало отдачу выше средней; плохое — если ниже. REINFORCE с выученным критиком — это архитектура *«актор-критик»*. Критик даёт актору низкодисперсного учителя. Это модель для каждого метода на основе глубокой политики после 2015 года (A2C, A3C, PPO, SAC, IMPALA).

## Концепция

![Актор-критик: сеть политики и сеть ценности, TD-невязка в качестве преимущества](../assets/actor-critic.svg)

**Две сети, одна общая функция потерь:**

- **Актор** `π_θ(a | s)`: политика. Из неё сэмплируют для выбора действия. Обучается градиентом политики.
- **Критик** `V_φ(s)`: оценивает ожидаемую отдачу из состояния. Обучается минимизировать `(V_φ(s) - target)²`.

**Преимущество.** Две стандартные формы:

- *MC-преимущество:* `A_t = G_t - V_φ(s_t)`. Несмещённое, дисперсия выше.
- *TD-преимущество:* `A_t = r_{t+1} + γ V_φ(s_{t+1}) - V_φ(s_t)`. Смещённое (использует `V_φ`), дисперсия существенно ниже. Также называется *TD-невязкой* `δ_t`.

**n-шаговое преимущество.** Интерполяция между двумя формами:

`A_t^{(n)} = r_{t+1} + γ r_{t+2} + … + γ^{n-1} r_{t+n} + γ^n V_φ(s_{t+n}) - V_φ(s_t)`

`n = 1` — чистый TD. `n = ∞` — MC. Большинство реализаций используют `n = 5` для Atari, `n = 2048` для PPO на MuJoCo.

**Обобщённая оценка преимущества (GAE).** Schulman et al. (2016) предложили экспоненциально взвешенное усреднение по всем n-шаговым преимуществам:

`A_t^{GAE} = Σ_{l=0}^{∞} (γλ)^l δ_{t+l}`

где `λ ∈ [0, 1]`. `λ = 0` — это TD (низкая дисперсия, высокое смещение). `λ = 1` — это MC (высокая дисперсия, без смещения). `λ = 0.95` — значение по умолчанию в 2026 году: подстраивайте, пока баланс смещения и дисперсии не станет таким, как нужно.

**A2C: синхронный актор-критик с преимуществом.** Соберите `T` шагов по `N` параллельным средам. Вычислите преимущества для каждого шага. Обновите актора и критика на объединённом пакете. Повторите. Более простой и масштабируемый собрат A3C.

**A3C: асинхронный актор-критик с преимуществом.** Mnih et al. (2016). Запустите `N` рабочих потоков, каждый со своей средой. Каждый рабочий поток вычисляет градиенты локально на собственном прогоне, затем асинхронно применяет их к общему серверу параметров. Буфер воспроизведения не нужен — рабочие потоки декоррелируются, проходя разные траектории. A3C доказал, что можно обучать на CPU в большом масштабе. В 2026 году доминирует A2C на GPU (параллельные среды, объединённые в пакеты), потому что GPU нужны большие пакеты.

**Совокупная функция потерь.**

`L(θ, φ) = -E[ A_t · log π_θ(a_t | s_t) ]  +  c_v · E[(V_φ(s_t) - G_t)²]  -  c_e · E[H(π_θ(·|s_t))]`

Три слагаемых: потеря градиента политики, регрессия ценности, бонус энтропии. `c_v ~ 0.5`, `c_e ~ 0.01` — канонические стартовые значения.

## Реализация

### Шаг 1: критик

Линейный критик `V_φ(s) = w · features(s)`, обновляемый по MSE:

```python
def critic_update(w, x, target, lr):
    v_hat = dot(w, x)
    err = target - v_hat
    for j in range(len(w)):
        w[j] += lr * err * x[j]
    return v_hat
```

На табличной среде критик сходится за несколько сотен эпизодов. На Atari замените линейного критика на общий CNN-ствол с головой ценности.

### Шаг 2: n-шаговое преимущество

Дан прогон длины `T` и бутстрап-оценка финального `V(s_T)`:

```python
def compute_advantages(rewards, values, gamma=0.99, lam=0.95, last_value=0.0):
    advantages = [0.0] * len(rewards)
    gae = 0.0
    for t in reversed(range(len(rewards))):
        next_v = values[t + 1] if t + 1 < len(values) else last_value
        delta = rewards[t] + gamma * next_v - values[t]
        gae = delta + gamma * lam * gae
        advantages[t] = gae
    returns = [a + v for a, v in zip(advantages, values)]
    return advantages, returns
```

`returns` — цель для критика. `advantages` — то, на что умножается `∇ log π`.

### Шаг 3: совместное обновление

```python
for step_i, (x, a, _r, probs) in enumerate(traj):
    adv = advantages[step_i]
    target_v = returns[step_i]

    # critic
    critic_update(w, x, target_v, lr_v)

    # actor
    for i in range(N_ACTIONS):
        grad_logpi = (1.0 if i == a else 0.0) - probs[i]
        for j in range(N_FEAT):
            theta[i][j] += lr_a * adv * grad_logpi * x[j]
```

Обучение по текущей политике: один прогон на обновление и отдельные скорости обучения для актора и критика.

### Шаг 4: параллелизация (A3C против A2C)

- **A3C:** поднимите `N` потоков. Каждый ведёт собственную среду и собственный прямой проход. Периодически отправляйте обновления градиентов на общий мастер. Без блокировок на мастере — гонки допустимы, они лишь добавляют шум.
- **A2C:** запустите `N` экземпляров среды в одном процессе, соберите наблюдения в батч `[N, obs_dim]`, батчированный прямой и обратный проход. Выше утилизация GPU, детерминированно, проще рассуждать. Стандарт по умолчанию в 2026 году.

Наш игрушечный код однопоточный для ясности; переписать его на батчированный A2C — три строки на numpy.

## Подводные камни

- **Смещение критика до градиента актора.** Если критик случайный, его базовая линия неинформативна, и вы обучаетесь на чистом шуме. Прогрейте критика несколько сотен шагов перед включением градиента политики, либо используйте медленную скорость обучения для актора.
- **Нормализация преимущества.** Нормализуйте преимущества к нулевому среднему и единичному стандартному отклонению по пакету. Это значительно стабилизирует обучение почти без дополнительных затрат.
- **Общий ствол.** На изображениях используйте общий экстрактор признаков для актора и критика с отдельными головами. Общие признаки «подпитываются» обеими функциями потерь.
- **Контракт обучения по текущей политике.** A2C переиспользует данные ровно для одного обновления. Больше — и градиент смещён (PPO добавляет коррекцию с помощью выборки по значимости).
- **Коллапс энтропии.** Без `c_e > 0` политика становится почти детерминированной за несколько сотен обновлений и перестаёт исследовать.
- **Масштаб вознаграждения.** Величина преимущества зависит от масштаба вознаграждения. Нормализуйте вознаграждения (например, делением на скользящее стандартное отклонение) для согласованных масштабов градиента между задачами.

## Применение

A2C/A3C редко становятся финальным выбором в 2026 году, но это архитектура, которую уточняет всё последующее:

| Метод | Связь с A2C |
|--------|----------------|
| PPO | A2C + ограниченное отношение значимости для многоэпоховых обновлений |
| IMPALA | A3C + V-trace-коррекция для обучения вне политики |
| SAC (этап 9 · 07) | A2C вне политики с критиком мягкой ценности (следующий урок) |
| GRPO (этап 9 · 12) | A2C без критика — преимущество относительно группы |
| DPO | A2C, свёрнутый в функцию потерь для ранжирования предпочтений, без сэмплирования |
| AlphaStar / OpenAI Five | A2C с обучением в лиге и предварительным обучением через имитацию |

Если в статье 2026 года встречается слово «преимущество», думайте об архитектуре «актор-критик».

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Актор | «Сеть политики» | `π_θ(a\|s)`, обновляемая градиентом политики. |
| Критик | «Сеть ценности» | `V_φ(s)`, обновляемая MSE-регрессией к отдачам или TD-целям. |
| Преимущество | «Насколько действие лучше среднего» | `A(s, a) = Q(s, a) - V(s)` или оценки этой величины. Множитель для `∇ log π`. |
| TD-невязка | «δ» | `δ_t = r + γ V(s') - V(s)`; одношаговая оценка преимущества. |
| GAE | «Регулятор интерполяции» | Экспоненциально взвешенная сумма n-шаговых преимуществ с параметром `λ`. |
| A2C | «Синхронный актор-критик» | Обработка сред пакетами; один шаг градиента на прогон. |
| A3C | «Асинхронный актор-критик» | Рабочие потоки отправляют градиенты на общий сервер параметров. Исходный метод из оригинальной статьи; в 2026 году применяется реже. |
| Бутстрап | «Использовать функцию ценности на горизонте» | Обрезать прогон и добавить `γ^n V(s_{t+n})`, чтобы замкнуть сумму. |
