# Градиент политики — REINFORCE с нуля

> Хватит оценивать ценность. Параметризуйте политику напрямую, вычислите градиент ожидаемой отдачи, шагните вверх по склону. Уильямс (1992) уместил это в одну теорему. Именно поэтому существуют PPO, GRPO и каждый RL-цикл для LLM.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** фаза 3 · 03 (обратное распространение ошибки), фаза 9 · 03 (метод Монте-Карло), фаза 9 · 04 (обучение с временны́ми различиями)
**Время:** ~75 минут

## Проблема

Q-learning и DQN параметризуют функцию *ценности*. Действия выбираются через `argmax Q`. Это нормально для дискретных действий и дискретных состояний. Но это ломается, когда действия непрерывны (по какому 10-мерному крутящему моменту брать `argmax`?) или когда нужна стохастическая политика (`argmax` по построению детерминирован).

Градиенты политики параметризуют вместо этого саму *политику*. `π_θ(a | s)` — нейросеть, выдающая распределение по действиям. Чтобы действовать, из него сэмплируют. Вычисляется градиент ожидаемой отдачи по `θ`. Шаг вверх по склону. Никакого `argmax`. Никакой рекурсии Беллмана. Просто градиентный подъём по `J(θ) = E_{π_θ}[G]`.

Теорема REINFORCE (Уильямс, 1992) утверждает, что этот градиент вычислим: `∇J(θ) = E_π[ G · ∇_θ log π_θ(a | s) ]`. Прогоните эпизод. Вычислите отдачу. Умножьте на `∇ log π_θ(a | s)` на каждом шаге. Усредните. Градиентный подъём. Готово.

Каждый алгоритм LLM-RL 2026 года — PPO, DPO, GRPO — это уточнение REINFORCE. Понимание его «на кончиках пальцев» — необходимое условие для остальной части этой фазы, а также для фазы 10 · 07 (реализация RLHF) и фазы 10 · 08 (DPO).

## Концепция

![Градиент политики: softmax-политика, градиент логарифма π и обновление, взвешенное по отдаче](../assets/policy-gradient.svg)

**Теорема о градиенте политики.** Для любой политики `π_θ`, параметризованной `θ`:

`∇J(θ) = E_{τ ~ π_θ}[ Σ_{t=0}^{T} G_t · ∇_θ log π_θ(a_t | s_t) ]`

где `G_t = Σ_{k=t}^{T} γ^{k-t} r_{k+1}` — дисконтированная отдача начиная с шага `t`. Математическое ожидание берётся по полным траекториям `τ`, сэмплированным из `π_θ`.

**Доказательство короткое.** Продифференцируйте `J(θ) = Σ_τ P(τ; θ) G(τ)` под знаком ожидания. Используйте `∇P(τ; θ) = P(τ; θ) ∇ log P(τ; θ)` (трюк с логарифмической производной). Разложите `log P(τ; θ) = Σ log π_θ(a_t | s_t) + environment terms that do not depend on θ`. Члены среды исчезают. Две строки алгебры дают теорему.

**Приёмы снижения дисперсии.** У ванильного REINFORCE убийственная дисперсия — отдачи зашумлены, `∇ log π` зашумлен, их произведение зашумлено вдвойне. Два стандартных исправления:

1. **Вычитание базовой линии.** Замените `G_t` на `G_t - b(s_t)` для любой базовой линии `b(s_t)`, не зависящей от `a_t`. Это несмещённая замена, потому что `E[b(s_t) · ∇ log π(a_t | s_t)] = 0`. Типичный выбор: `b(s_t) = V̂(s_t)`, выучиваемая критиком → метод «актор-критик» (actor-critic, урок 07).
2. **Отдача с текущего шага (reward-to-go).** Замените `Σ_t G_t · ∇ log π_θ(a_t | s_t)` на `Σ_t G_t^{from t} · ∇ log π_θ(a_t | s_t)`. Для данного действия важны только будущие отдачи — прошлые вознаграждения вносят шум с нулевым средним.

В сочетании получается:

`∇J ≈ (1/N) Σ_{i=1}^{N} Σ_{t=0}^{T_i} [ G_t^{(i)} - V̂(s_t^{(i)}) ] · ∇_θ log π_θ(a_t^{(i)} | s_t^{(i)})`

это REINFORCE с базовой линией — прямой предшественник A2C (урок 07) и PPO (урок 08).

**Softmax-параметризация политики.** Для дискретных действий стандартный выбор:

`π_θ(a | s) = exp(f_θ(s, a)) / Σ_{a'} exp(f_θ(s, a'))`

где `f_θ` — любая нейросеть, выдающая оценку для каждого действия. Градиент имеет чистую форму:

`∇_θ log π_θ(a | s) = ∇_θ f_θ(s, a) - Σ_{a'} π_θ(a' | s) ∇_θ f_θ(s, a')`

то есть оценка выбранного действия минус его ожидаемое значение под текущей политикой.

**Гауссова политика для непрерывных действий.** `π_θ(a | s) = N(μ_θ(s), σ_θ(s))`. `∇ log N(a; μ, σ)` имеет замкнутую форму. Это всё, что нужно SAC из фазы 9 · 07.

## Реализация

### Шаг 1: softmax-сеть политики

```python
def policy_logits(theta, state_features):
    return [dot(theta[a], state_features) for a in range(N_ACTIONS)]

def softmax(logits):
    m = max(logits)
    exps = [exp(l - m) for l in logits]
    Z = sum(exps)
    return [e / Z for e in exps]
```

Используйте линейную политику (по одному вектору весов на действие) для табличной среды. Для Atari замените её на CNN, оставив softmax-голову.

### Шаг 2: сэмплирование и логарифм вероятности

```python
def sample_action(probs, rng):
    x = rng.random()
    cum = 0
    for a, p in enumerate(probs):
        cum += p
        if x <= cum:
            return a
    return len(probs) - 1

def log_prob(probs, a):
    return log(probs[a] + 1e-12)
```

### Шаг 3: прогон эпизода с записью логарифмов вероятностей

```python
def rollout(theta, env, rng, gamma):
    trajectory = []
    s = env.reset()
    while not done:
        logits = policy_logits(theta, s)
        probs = softmax(logits)
        a = sample_action(probs, rng)
        s_next, r, done = env.step(s, a)
        trajectory.append((s, a, r, probs))
        s = s_next
    return trajectory
```

### Шаг 4: обновление REINFORCE

```python
def reinforce_step(theta, trajectory, gamma, lr, baseline=0.0):
    returns = compute_returns(trajectory, gamma)
    for (s, a, _, probs), G in zip(trajectory, returns):
        advantage = G - baseline
        grad_log_pi_a = [-p for p in probs]
        grad_log_pi_a[a] += 1.0
        for i in range(N_ACTIONS):
            for j in range(len(s)):
                theta[i][j] += lr * advantage * grad_log_pi_a[i] * s[j]
```

Градиент `∇ log π(a|s) = e_a - π(·|s)` (унитарный вектор `a` минус вероятности) — это основа градиентов политики с softmax. Доведите его до автоматизма.

### Шаг 5: базовые линии

Скользящего среднего `G` за последние эпизоды достаточно для снижения дисперсии, чтобы запустить 4×4 GridWorld; сходимость занимает ~500 эпизодов. Замените базовую линию на выученную `V̂(s)` — и получите метод «актор-критик».

## Подводные камни

- **Взрывающиеся градиенты.** Отдачи могут быть огромными. Всегда нормализуйте `G` до `~N(0, 1)` по батчу перед умножением на `∇ log π`.
- **Коллапс энтропии.** Политика слишком рано сходится к почти детерминированному действию, перестаёт исследовать и застревает. Исправление: добавьте бонус энтропии `β · H(π(·|s))` к целевой функции.
- **Высокая дисперсия.** Ванильному REINFORCE нужны тысячи эпизодов. Стандартное исправление — базовая линия-критик (урок 07) или доверительная область TRPO/PPO (урок 08).
- **Неэффективность по выборкам.** Обучение по текущей политике (on-policy) означает, что после каждого обновления вы выбрасываете все переходы. Коррекции для обучения по сторонней политике (off-policy) с помощью выборки по значимости (importance sampling) позволяют снова использовать данные ценой повышенной дисперсии (отношение PPO — это усечённый вес выборки по значимости).
- **Нестационарные градиенты.** Тот же градиент, вычисленный 100 эпизодов назад, использует старую `π`. Поэтому методы обучения по текущей политике обновляются каждые несколько прогонов.
- **Определение вклада действий (credit assignment).** Без отдачи с текущего шага прошлые вознаграждения вносят шум. Всегда используйте отдачу с текущего шага.

## Применение

В 2026 году REINFORCE редко запускают напрямую, но его формула градиента встречается повсюду:

| Сценарий применения | Производный метод |
|----------|---------------|
| Управление с непрерывными действиями | PPO / SAC с гауссовой политикой |
| RLHF для LLM | PPO со штрафом KL, работающий с политикой на уровне токенов |
| Рассуждения LLM (DeepSeek) | GRPO — REINFORCE с базовой линией относительно группы, без критика |
| Многоагентные системы | REINFORCE с централизованным критиком (MADDPG, COMA) |
| Робототехника с дискретными действиями | A2C, A3C, PPO |
| Задачи только с предпочтениями | DPO — REINFORCE, переписанный как функция потерь правдоподобия предпочтений, без сэмплирования |

Когда в тренировочном скрипте 2026 года встречается `loss = -advantage * log_prob`, это REINFORCE с базовой линией. Целые статьи (DPO, GRPO, RLOO) — это приёмы снижения дисперсии поверх одной этой строки.

## Ключевые термины

| Термин | Как обычно говорят | Что это означает на самом деле |
|------|-----------------|-----------------------|
| Градиент политики | «Обучать политику напрямую» | `∇J(θ) = E[G · ∇ log π_θ(a\|s)]`; выводится с помощью трюка с логарифмической производной. |
| REINFORCE | «Первоначальный алгоритм градиента политики» | Уильямс (1992); отдачи Монте-Карло умножаются на градиент логарифма политики. |
| Трюк с логарифмической производной | «Оценка на основе функции правдоподобия» | `∇P(τ;θ) = P(τ;θ) · ∇ log P(τ;θ)`; позволяет вычислять градиенты математических ожиданий. |
| Базовая линия | «Снижение дисперсии» | Любая величина `b(s)`, вычитаемая из `G`; несмещённость сохраняется, поскольку `E[b · ∇ log π] = 0`. |
| Отдача с текущего шага | «Учитываются только будущие отдачи» | `G_t^{from t}` вместо полной отдачи `G_0`; это корректная оценка с меньшей дисперсией. |
| Бонус энтропии | «Поощрять исследование» | Слагаемое `+β · H(π(·\|s))` не даёт политике коллапсировать. |
| Обучение по текущей политике | «Обучаться на только что полученных данных» | Математическое ожидание градиента берётся по текущей политике, поэтому старые данные нельзя использовать напрямую. |
| Преимущество | «Насколько результат лучше среднего» | `A(s, a) = G(s, a) - V(s)`; знаковая величина, на которую умножает REINFORCE с базовой линией. |
