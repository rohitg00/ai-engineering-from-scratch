# RL для игр — AlphaZero, MuZero и эра LLM-рассуждений

> 1992: TD-Gammon обыграл чемпионов среди людей в нарды с помощью чистого TD. 2016: AlphaGo обыграл Ли Седоля. 2017: AlphaZero доминировал в шахматах, сёги и го с нуля. 2024: DeepSeek-R1 доказал, что тот же рецепт, с заменой PPO на GRPO, работает для рассуждений. Игры — это бенчмарк, который двигает каждый прорыв в этой фазе.

**Тип:** Build
**Языки:** Python
**Предварительные требования:** Фаза 9 · 05 (DQN), Фаза 9 · 08 (PPO), Фаза 9 · 09 (RLHF), Фаза 9 · 10 (MARL)
**Время:** ~120 минут

## Проблема

В играх есть всё, что нужно RL. Чистое вознаграждение (победа/поражение). Бесконечные эпизоды (сбросы через self-play). Идеальная симуляция (игра *и есть* симулятор). Дискретные или небольшие непрерывные пространства действий. Мультиагентная структура, вынуждающая к устойчивости против антагонистов.

И именно на играх проверялся каждый крупный прорыв RL. TD-Gammon (нарды, 1992). Atari-DQN (2013). AlphaGo (2016). AlphaZero (2017). OpenAI Five (Dota 2, 2019). AlphaStar (StarCraft II, 2019). MuZero (выученная модель, 2019). AlphaTensor (умножение матриц, 2022). AlphaDev (алгоритмы сортировки, 2023). DeepSeek-R1 (математические рассуждения, 2025) — последняя демонстрация того, что техники игрового RL работают и на тексте.

Этот итоговый урок обозревает три знаковые архитектуры — AlphaZero, MuZero и GRPO — через единую объединяющую призму: **self-play + поиск + улучшение политики**. Каждая последующая обобщает предыдущую; GRPO, в частности, — это рецепт AlphaZero, применённый к рассуждениям LLM, где токены выступают действиями, а математическая верификация — сигналом победы.

## Концепция

![AlphaZero ↔ MuZero ↔ GRPO: один и тот же цикл, разные среды](../assets/rl-games.svg)

**Объединяющий цикл.**

```
while True:
    trajectory = self_play(current_policy, search)     # play game against self
    policy_target = search.improved_policy(trajectory) # search improves raw policy
    policy_net.update(policy_target, value_target)     # supervised on search output
```

**AlphaZero (2017).** Silver и соавт. Дана игра (шахматы, сёги, го) с известными правилами:

- Сеть политики и ценности: одна башня `f_θ(s) → (p, v)`. `p` — априорное распределение над допустимыми ходами. `v` — ожидаемый исход игры.
- Поиск по дереву Монте-Карло (MCTS): на каждом ходу разворачивается дерево возможных продолжений. Используются `(p, v)` в качестве априорного распределения + bootstrap. Узлы выбираются по UCB (PUCT): `a* = argmax Q(s, a) + c · p(a|s) · √N(s) / (1 + N(s, a))`.
- Self-play: игры агент против агента. На ходу `t` распределение посещений MCTS `π_t` становится целью обучения политики.
- Функция потерь: `L = (v - z)² - π · log p + c · ||θ||²`. `z` — исход игры (+1 / 0 / -1).

Ноль человеческих знаний. Ноль эвристик, заданных вручную. Единый рецепт, освоивший шахматы, сёги и го после нескольких десятков миллионов партий self-play на каждую игру.

**MuZero (2019).** Schrittwieser и соавт. Убирает требование о том, что правила известны.

- Вместо фиксированной среды обучается *латентная модель динамики* `(h, g, f)`:
  - `h(s)`: кодирует наблюдение в латентное состояние.
  - `g(s_latent, a)`: предсказывает следующее латентное состояние + вознаграждение.
  - `f(s_latent)`: предсказывает априорную политику + ценность.
- MCTS выполняется в *выученном латентном пространстве*. Тот же поиск, тот же цикл обучения.
- Работает на го, шахматах, сёги *и* на Atari — один алгоритм, никакого знания правил.

**Stochastic MuZero (2022).** Добавляет стохастическую динамику и узлы случайности; расширяется на игры класса нард.

**Muesli, Gumbel MuZero (2022–2024).** Улучшения эффективности использования выборки и детерминированного поиска.

**GRPO (2024–2025).** Рецепт DeepSeek-R1. Тот же цикл в форме AlphaZero, применённый к рассуждениям языковой модели:

- «Игра»: ответ на задачу по математике / программированию / рассуждению. «Победа» = верификатор (тест проходит, числовой ответ совпадает) возвращает 1.
- Политика: LLM. Действия: токены. Состояние: промпт + ответ-на-текущий-момент.
- Нет критика (в стиле PPO, V_φ). Вместо этого для каждого промпта сэмплируется `G` завершений от политики. Для каждого вычисляется вознаграждение. Используется **групповое относительное преимущество** `A_i = (r_i - mean_r) / std_r` в качестве сигнала для обновления в стиле REINFORCE.
- KL-штраф к референсной политике для предотвращения дрейфа (как в RLHF).
- Полная функция потерь:

  `L_GRPO(θ) = -E_{q, {o_i}} [ (1/G) Σ_i A_i · log π_θ(o_i | q) ] + β · KL(π_θ || π_ref)`

Нет модели вознаграждения, нет критика, нет MCTS. Групповая относительная базовая линия заменяет все три. Соответствует или превосходит качество PPO-RLHF на бенчмарках рассуждений при небольшой доле вычислений.

**Рецепт R1 целиком.** DeepSeek-R1 (DeepSeek 2025) — это две модели в одной статье:

- **R1-Zero.** Начните с базовой модели DeepSeek-V3. Без SFT. Примените GRPO напрямую с двумя компонентами вознаграждения: *вознаграждение за точность* (основанное на правилах — совпал ли итоговый ответ с правильным числом / прошёл ли код модульные тесты) и *вознаграждение за формат* (обернул ли ответ цепочку рассуждений в теги `<think>…</think>`). За тысячи шагов средняя длина ответа вырастает со ~100 до ~10 000 токенов, а результаты на математических бенчмарках приближаются к уровню o1-preview. Модель учится рассуждать с нуля. Недостаток: её цепочки рассуждений зачастую нечитаемы, смешивают языки и лишены стилистической отточенности.
- **R1.** Исправляет проблемы читаемости R1-Zero четырёхэтапным конвейером:
  1. **Холодный старт SFT.** Соберите несколько тысяч длинных демонстраций цепочек рассуждений с чистым форматированием. Дообучите базовую модель с учителем на них. Это даёт читаемую отправную точку.
  2. **GRPO, ориентированный на рассуждения.** Примените GRPO с вознаграждениями за точность и формат плюс вознаграждение за *языковую согласованность*, чтобы предотвратить переключение между языками.
  3. **Отбраковочная выборка (rejection sampling) + SFT, раунд 2.** Сэмплируйте ~600 тыс. траекторий рассуждений из контрольной точки RL, оставьте только те, у которых верный итоговый ответ и читаемая цепочка рассуждений, и объедините с ~200 тыс. примеров SFT без рассуждений (письмо, ответы на вопросы, самопознание). Снова дообучите базовую модель.
  4. **GRPO полного спектра.** Ещё один раунд RL, охватывающий и рассуждения (вознаграждения на основе правил), и общее согласование (вознаграждения на основе предпочтений полезности/безвредности).

Результат соответствует o1 на AIME и MATH-500 с открытыми весами и достаточно мал для дистилляции. Та же статья также выпускает шесть дистиллированных плотных моделей (от Qwen-1.5B до Llama-70B) путём SFT на трассах рассуждений R1 — без RL на стороне ученика. Дистилляция сильного RL-учителя стабильно превосходит RL с нуля в масштабе ученика.

**Почему GRPO вместо PPO для рассуждений.** Три причины из статьи DeepSeekMath (февраль 2024): (1) не нужно обучать сеть ценности, что вдвое сокращает память; (2) групповая базовая линия естественным образом справляется с разреженным вознаграждением в конце траектории, характерным для задач рассуждения; (3) нормализация по промпту делает преимущества сопоставимыми между задачами сильно разной сложности, чего единый критик PPO сделать не может.

**Поиск и без поиска.** Игры разделились на два направления:

- *Игры с полной информацией и длинным горизонтом* (го, шахматы): по-прежнему на основе поиска. Доминируют AlphaZero / MuZero.
- *Рассуждения LLM*: MCTS пока не используется в продакшене; GRPO на полных прогонах, best-of-N для инференс-вычислений. Модели вознаграждения за процесс (PRM) намекают на возвращение поиска на уровне шагов.

## Реализация

Код в `code/main.py` реализует **GRPO в миниатюре** — бандит с несколькими группами сэмплов. Алгоритм тот же, что и на LLM; отличаются только политика и среда — они проще. Он учит *функции потерь* и *групповому относительному преимуществу*, которые являются инновацией 2025 года.

### Шаг 1: крошечная среда с верификатором

```python
QUESTIONS = [
    {"prompt": "q1", "correct": 3},
    {"prompt": "q2", "correct": 1},
]

def verify(prompt_idx, answer_token):
    return 1.0 if answer_token == QUESTIONS[prompt_idx]["correct"] else 0.0
```

В настоящем GRPO верификатор запускает модульные тесты или проверяет математическое равенство.

### Шаг 2: политика — softmax по K токенам ответа на промпт

```python
def policy_probs(theta, p_idx):
    return softmax(theta[p_idx])
```

Эквивалентно выходу последнего слоя LLM, обусловленного промптом.

### Шаг 3: групповое сэмплирование и групповое относительное преимущество

```python
def grpo_step(theta, p_idx, G=8, beta=0.01, lr=0.1, rng=None):
    probs = policy_probs(theta, p_idx)
    samples = [sample(probs, rng) for _ in range(G)]
    rewards = [verify(p_idx, s) for s in samples]
    mean_r = sum(rewards) / G
    std_r = stddev(rewards) + 1e-8
    advs = [(r - mean_r) / std_r for r in rewards]

    for a, A in zip(samples, advs):
        grad = onehot(a) - probs
        for i in range(len(probs)):
            theta[p_idx][i] += lr * A * grad[i]
    # KL penalty: pull theta toward reference
    for i in range(len(probs)):
        theta[p_idx][i] -= beta * (theta[p_idx][i] - reference[p_idx][i])
```

Групповое относительное преимущество — приём DeepSeek 2024 года. Критик не нужен. «Базовая линия» — это среднее по группе, а нормализация использует стандартное отклонение по группе.

### Шаг 4: сравнение с базовым REINFORCE (без функции ценности)

Та же постановка, те же вычисления, обычный REINFORCE. GRPO сходится быстрее и стабильнее.

### Шаг 5: наблюдение за энтропией и KL

Те же диагностики, что и в RLHF: средний KL к референсу, энтропия политики, вознаграждение во времени. Как только они стабилизируются, обучение завершено.

## Подводные камни

- **Взлом вознаграждения через обман верификатора.** GRPO наследует риск RLHF: если верификатор неверен или его можно эксплуатировать, LLM найдёт эксплойт. Важны надёжные верификаторы (несколько тестовых случаев, формальные доказательства).
- **Слишком маленький размер группы.** Дисперсия групповой базовой линии ведёт себя как `1/√G`. Ниже `G = 4` сигнал преимущества зашумлён; стандартный выбор — `G = 8`–`64`.
- **Смещение по длине.** Завершения LLM разной длины имеют разные логарифмы вероятностей. Нормализуйте по числу токенов, либо используйте логарифм вероятности на уровне последовательности, либо обрезайте до максимальной длины.
- **Циклы чистого self-play.** Обучение в стиле AlphaZero может застрять в циклах доминирования в играх с ненулевой суммой. Смягчается разнообразными пулами соперников (лига, урок 10).
- **Несоответствие поиска и политики.** AlphaZero обучает политику имитировать выход поиска. Если сеть политики слишком мала, чтобы представить распределение поиска, обучение застревает.
- **Порог вычислений.** MuZero / AlphaZero требуют огромных вычислений. Одна аблация часто занимает сотни GPU-часов. Существуют миниатюрные демонстрации (например, AlphaZero на «Четыре в ряд») для обучения.
- **Покрытие верификатором.** Модульные тесты, проходящие для решения с ошибкой, закрепляют эту ошибку. Проектируйте верификаторы, отлавливающие граничные случаи.

## Применение

Ландшафт игрового RL 2026 года по доменам:

| Домен | Доминирующий метод |
|--------|-------------------|
| Настольные игры для двух игроков с нулевой суммой (го, шахматы, сёги) | AlphaZero / MuZero / KataGo |
| Карточные игры с неполной информацией (покер) | CFR + глубокое обучение (DeepStack, Libratus, Pluribus) |
| Atari / игры с пиксельными наблюдениями | Muesli / MuZero / IMPALA-PPO |
| Масштабные многопользовательские стратегии (Dota, StarCraft) | PPO + self-play + лига (OpenAI Five, AlphaStar) |
| Математические рассуждения и программирование с помощью LLM | GRPO (DeepSeek-R1, Qwen-RL, открытые репликации) |
| Согласование LLM | DPO / RLHF-PPO (не GRPO: верификатор оценивает предпочтения, а не проверяемый результат) |
| Робототехника | PPO + DR (не игровой RL, но использует те же инструменты градиента политики) |
| Комбинаторные задачи | Варианты AlphaZero (AlphaTensor, AlphaDev) |

*Рецепт* — self-play, улучшение с помощью поиска, дистилляция политики — охватывает текст, пиксели и физическое управление. GRPO — самый молодой представитель; впереди появятся новые.

## Ключевые термины

| Термин | Как обычно говорят | Что это на самом деле означает |
|--------|--------------------|--------------------------------|
| MCTS | «Поиск по дереву с обученной сетью» | Поиск по дереву Монте-Карло; выбор по UCB1/PUCT с выученными априорными оценками `(p, v)`. |
| AlphaZero | «Self-play + MCTS» | Сеть политики и ценности, обученная воспроизводить распределение посещений MCTS и исход игры. |
| MuZero | «AlphaZero с выученной моделью» | Тот же цикл, но в латентном пространстве с выученной динамикой. |
| GRPO | «PPO без критика» | Групповая относительная оптимизация политики (Group Relative Policy Optimization); REINFORCE с базовой линией в виде среднего по группе и KL. |
| PUCT | «UCB из AlphaZero» | `Q + c · p · √N / (1 + N_a)` — уравновешивает оценку ценности и априорную оценку. |
| Self-play | «Агент против своей прошлой версии» | Стандартный подход для игр с нулевой суммой; даёт симметричный обучающий сигнал. |
| Игра в лиге | «Self-play на основе популяции» | В качестве соперников сэмплируются прошлые и текущие версии агентов, а также эксплуататоры. |
| Вознаграждение верификатора | «Проверяемый RL» | Вознаграждение поступает от детерминированного средства проверки (тесты пройдены, ответ совпадает). |
| Вознаграждение за процесс | «PRM» | Оценивает каждый шаг рассуждения, а не только итоговый ответ. |

- [Qwen Team (2024). Qwen2.5-Math — GRPO replication](https://github.com/QwenLM/Qwen2.5-Math) — открытая репликация рецепта R1 в нескольких масштабах.
- [Sutton & Barto (2018). Ch. 17 — Frontiers of Reinforcement Learning](http://incompleteideas.net/book/RLbook2020.pdf) — изложение self-play, поиска и «спроектированного вознаграждения» в учебнике, которое R1 воплощает в масштабе LLM.
