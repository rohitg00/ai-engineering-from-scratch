# Кеширование промптов и кеширование контекста

> Ваш системный промпт занимает 4,000 токенов. Контекст RAG — 20,000 токенов. Вы отправляете оба с каждым запросом. И платите за оба — каждый раз. Кеширование промптов (prompt caching) позволяет провайдеру держать этот префикс тёплым на своей стороне и выставлять счёт за повторное использование по ставке 10% от обычной. При правильном использовании оно снижает стоимость инференса на 50–90% и задержку до первого токена — на 40–85%.

**Тип:** Build**Языки:** Python**Предварительные требования:** Фаза 11 · 01 (Prompt Engineering), Фаза 11 · 05 (Context Engineering), Фаза 11 · 11 (Caching and Cost)**Время:** ~60 минут
## Проблема

Агент для написания кода отправляет Claude один и тот же системный промпт на 15,000 токенов на каждом ходу разговора. Двадцать ходов по $3/M входных токенов — это $0.90 только на входных данных — ещё до учёта собственных сообщений пользователя. Умножьте это на 10,000 разговоров в день, и счёт достигает $9,000/day за текст, который никогда не меняется.

Сократить промпт без ущерба для качества нельзя. Не отправлять его тоже нельзя — модели он нужен на каждом ходу. Единственный выход — перестать платить полную цену за префикс, который провайдер уже видел.

Этот выход — кеширование промптов. Anthropic выпустила его в августе 2024 года (с вариантом расширенного TTL на 1 час в 2025 году), OpenAI автоматизировала его позже в том же году, Google выпустила явное кеширование контекста (context caching) вместе с Gemini 1.5, и теперь все три провайдера предлагают его как полноценную функцию своих топовых моделей.

## Концепция

![Кеширование промптов: запись один раз, дешёвое чтение](../assets/prompt-caching.svg)

**Механика.** Когда префикс запроса совпадает с префиксом недавнего запроса, провайдер отдаёт KV-кеш из предыдущего запуска вместо повторного кодирования токенов. В первый раз вы платите небольшую надбавку за запись, а затем каждый раз получаете значительную скидку за чтение.

**Три варианта провайдеров в 2026 году.**

| Провайдер | Стиль API | Скидка при попадании | Надбавка за запись | TTL по умолчанию | Минимум для кеширования |
|---------|-----------|--------------|---------------|-------------|---------------|
| Anthropic | Явные маркеры `cache_control` на блоках содержимого | Скидка 90% на входные токены | Надбавка 25% | 5 мин (можно продлить до 1 часа) | 1,024 токена (Sonnet/Opus), 2,048 (Haiku) |
| OpenAI | Автоматическое обнаружение префикса | Скидка 50% на входные токены | нет | До 1 часа (по мере возможности) | 1,024 токена |
| Google (Gemini) | Явный API `CachedContent` | Тарификация по хранению; чтение по ~25% от обычной ставки | Плата за хранение за токен·час | Задаётся пользователем (по умолчанию 1 час) | 4,096 токенов (Flash), 32,768 (Pro) |

**Инвариант.** Все три провайдера кешируют только префиксы. Если между запросами различается хотя бы один токен, всё, что идёт после первого различающегося токена, становится промахом. Располагайте *стабильные* части сверху, а *переменные* — снизу.

### Раскладка, удобная для кеширования

```
[system prompt]          <-- cache this
[tool definitions]       <-- cache this
[few-shot examples]      <-- cache this
[retrieved documents]    <-- cache if reused, else don't
[conversation history]   <-- cache up to last turn
[current user message]   <-- never cache (different every time)
```

Нарушьте порядок — поставьте сообщение пользователя выше системного промпта, перемешайте динамические результаты поиска с примерами с несколькими примерами (few-shot) — и кеш никогда не сработает.

### Расчёт точки безубыточности

Надбавка Anthropic в 25% за запись означает, что закешированный блок должен быть прочитан минимум дважды, чтобы кеширование окупилось. При 1 записи и 1 чтении средняя стоимость запроса составляет 0.675x (экономия 32%); при 1 записи и 10 чтениях — 0.205x (экономия 80%). Эмпирическое правило: кешируйте всё, что вы рассчитываете использовать повторно не менее 3 раз в пределах TTL.

## Соберите это

### Шаг 1: Кеширование промптов Anthropic с явными маркерами

```python
import anthropic

client = anthropic.Anthropic()

SYSTEM = [
    {
        "type": "text",
        "text": "You are a senior Python reviewer. Follow the rubric exactly.\n\n" + RUBRIC_15K_TOKENS,
        "cache_control": {"type": "ephemeral"},
    }
]

def review(code: str):
    return client.messages.create(
        model="claude-opus-4-7",
        max_tokens=1024,
        system=SYSTEM,
        messages=[{"role": "user", "content": code}],
    )
```

Маркер `cache_control` указывает Anthropic хранить блок в течение 5 минут. Повторное использование в пределах этого окна даёт попадание; после истечения срока — снова запись.

**Поля usage в ответе:**

```python
response = review(code_a)
response.usage
# InputTokensUsage(
#     input_tokens=120,
#     cache_creation_input_tokens=15023,   # paid at 1.25x
#     cache_read_input_tokens=0,
#     output_tokens=340,
# )

response_b = review(code_b)
response_b.usage
# cache_creation_input_tokens=0
# cache_read_input_tokens=15023           # paid at 0.1x
```

Проверяйте оба поля в CI — если `cache_read_input_tokens` во всех запросах остаётся нулевым, значит ключи вашего кеша расходятся.

### Шаг 2: Расширенный TTL на один час

Для длительных пакетных заданий 5-минутный TTL по умолчанию истекает между заданиями. Задайте `ttl`:

```python
{"type": "text", "text": RUBRIC, "cache_control": {"type": "ephemeral", "ttl": "1h"}}
```

TTL на 1 час стоит в 2 раза больше по надбавке за запись (50% сверх базовой ставки вместо 25%), но быстро окупается на любом пакетном задании, использующем префикс повторно более 5 раз.

### Шаг 3: Автоматическое кеширование OpenAI

У OpenAI настраивать нечего. Любой префикс длиннее 1,024 токенов, совпадающий с недавним запросом, автоматически получает скидку 50%.

```python
from openai import OpenAI
client = OpenAI()

resp = client.chat.completions.create(
    model="gpt-5",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},   # long and stable
        {"role": "user", "content": user_msg},
    ],
)
resp.usage.prompt_tokens_details.cached_tokens  # the discounted portion
```

Действует то же правило раскладки, удобной для кеширования. Есть два фактора, которые убивают кеш OpenAI, но не убивают кеш Anthropic: изменение поля `user` (используется как компонент ключа кеша) и изменение порядка инструментов.

### Шаг 4: Явное кеширование контекста Gemini

Gemini рассматривает кеш как полноценный объект, который вы создаёте и именуете:

```python
from google import genai
from google.genai import types

client = genai.Client()

cache = client.caches.create(
    model="gemini-3-pro",
    config=types.CreateCachedContentConfig(
        display_name="rubric-v3",
        system_instruction=RUBRIC,
        contents=[FEW_SHOT_EXAMPLES],
        ttl="3600s",
    ),
)

resp = client.models.generate_content(
    model="gemini-3-pro",
    contents=["Review this code:\n" + code],
    config=types.GenerateContentConfig(cached_content=cache.name),
)
```

Gemini взимает плату за хранение за токен·час на всё время жизни кеша, а чтение стоит ~25% от обычной ставки на входные токены. Это подходящий вариант, когда один и тот же гигантский промпт повторно используется в разных сессиях на протяжении нескольких дней.

### Шаг 5: Измерение частоты попаданий в продакшене

Смотрите `code/main.py` — симулятор-«бухгалтер» для трёх провайдеров, который отслеживает количество записей/чтений/промахов и рассчитывает смешанную стоимость на 1K запросов. Разрешайте деплой только при достижении целевой частоты попаданий — в большинстве продакшен-конфигураций Anthropic доля чтений после прогрева должна превышать 80%.

## Ошибки, которые всё ещё случаются в 2026 году

- **Динамические метки времени сверху.** `"Current time: 2026-04-22 15:30:02"` в начале системного промпта. Каждый запрос становится промахом. Переносите метки времени ниже точки разрыва кеша.
- **Изменение порядка инструментов.** Сериализуйте инструменты в стабильном порядке — перетасовка словаря между деплоями ломает каждое попадание.
- **Почти-дубликаты в свободном тексте.** «You are helpful.» против «You are a helpful assistant.» — разница в один байт означает полный промах.
- **Слишком маленькие блоки.** Anthropic требует минимум 1,024 токена (2,048 для Haiku). Более мелкие блоки молча не кешируются.
- **Слепые дашборды затрат.** Разделяйте «входные токены» на закешированные и незакешированные. Иначе падение трафика будет выглядеть как выигрыш от кеша.

## Используйте это

Стек кеширования 2026 года:

| Ситуация | Выбор |
|-----------|------|
| Агент со стабильным системным промптом 10k+ токенов, много ходов | Anthropic `cache_control` с TTL 5 минут |
| Пакетное задание, использующее префикс повторно 30+ минут | Anthropic с `ttl: "1h"` |
| Serverless-эндпоинты на GPT-5, без собственной инфраструктуры | Автоматическое кеширование OpenAI (достаточно сделать префикс стабильным и длинным) |
| Многодневное повторное использование гигантского корпуса кода/документов | Явный `CachedContent` Gemini |
| Резервный переход между провайдерами | Держите раскладку кешируемого префикса одинаковой у всех провайдеров, чтобы попадание срабатывало везде |

Сочетайте с семантическим кешированием (Phase 11 · 11) на уровне сообщений пользователя: кеширование промптов обрабатывает повторное использование, *идентичное на уровне токенов*, а семантическое кеширование — повторное использование, *идентичное по смыслу*.

## Упражнения

1. **Лёгкий.** Возьмите разговор из 10 ходов с системным промптом на 5,000 токенов для Claude. Запустите его сначала без `cache_control`, затем с ним. Сообщите счёт по входным токенам для каждого варианта.
2. **Средний.** Напишите тестовый харнесс, который по шаблону промпта и логу запросов вычисляет ожидаемую частоту попаданий и экономию в долларах для каждого провайдера (Anthropic 5m, Anthropic 1h, OpenAI automatic, Gemini explicit).
3. **Сложный.** Постройте оптимизатор раскладки: по промпту и списку полей с пометкой `stable=True/False` перепишите промпт так, чтобы разместить единственную точку разрыва кеша в максимально удобной для кеширования позиции без потери информации. Проверьте на реальном эндпоинте Anthropic.

## Ключевые термины

| Термин | Что говорят люди | Что это на самом деле означает |
|------|-----------------|-----------------------|
| Кеширование промптов | «Делает длинные промпты дешёвыми» | Повторное использование KV-кеша на стороне провайдера для совпадающих префиксов; скидка 50-90% на повторяющиеся входные токены. |
| `cache_control` | «Маркер Anthropic» | Атрибут блока содержимого, объявляющий «всё до этого места можно кешировать»; `{"type": "ephemeral"}`. |
| Запись в кеш | «Оплата надбавки» | Первый запрос, заполняющий кеш; тарифицируется по ставке ~1.25x у Anthropic, бесплатно у OpenAI. |
| Чтение из кеша | «Скидка» | Последующие запросы, совпадающие с префиксом; тарифицируются по ставке 10% (Anthropic), 50% (OpenAI), ~25% (Gemini). |
| TTL | «Сколько он живёт» | Число секунд, в течение которых кеш остаётся тёплым; у Anthropic по умолчанию 5 мин (можно продлить до 1 часа), у OpenAI — до 1 часа по мере возможности, у Gemini задаётся пользователем. |
| Расширенный TTL | «Часовой кеш Anthropic» | `{"type": "ephemeral", "ttl": "1h"}`; надбавка за запись в 2 раза выше, но окупается при пакетном повторном использовании. |
| Совпадение префикса | «Почему мой кеш промахнулся» | Кеш срабатывает, только если каждый токен от начала до точки разрыва побайтово идентичен. |
| Кеширование контекста (Gemini) | «Явный вариант» | Именованный, тарифицируемый по хранению объект кеша от Google; лучше всего подходит для многодневного повторного использования крупных корпусов. |
