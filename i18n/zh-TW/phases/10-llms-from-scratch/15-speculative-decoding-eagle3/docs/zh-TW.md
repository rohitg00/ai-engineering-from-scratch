# 推測解碼與 EAGLE-3

> 第 7 階段第 16 課從數學上證明了這一點：Leviathan 拒絕取樣法則（rejection sampling）能嚴格保留驗證模型的分布。本課則從訓練架構與工程實踐的角度出發，深入解析 2026 年生產級推測解碼技術。EAGLE-3 將草稿模型從廉價的粗略近似，轉化為在驗證模型自身隱藏狀態上訓練的專用微型網路，並引入了訓練期測試迴圈以對齊訓練與推論分布。其成果為：端到端加速達 3 倍至 6.5 倍、對話任務上每 token 接受率（acceptance rate）超過 0.9，且在分布上毫無品質損耗。2026 年的每個正式環境推論堆疊皆將其設為預設標配。

## The Problem｜問題

在 H100 上對 70B 模型執行自回歸解碼，生成速度大約只有每秒 35 個 token。此時 GPU 遠遠未達飽和狀態。記憶體頻寬是無法逾越的上限：每個 token 都需要從 HBM 讀取 70B 的權重、執行單步算術運算，並輸出一個浮點數。運算單元絕大部分時間都在無所事事地空轉。

推測解碼（Speculative decoding）將此轉化為一個真正可解的吞吐量問題。一個廉價的草稿模型在 `N` 次小型前向傳遞中預測出 `N` 個 token。驗證模型隨後在前綴加上這 `N` 個候選 token 上僅執行一次前向傳遞。如果驗證模型在位置 `i` 的機率分布與草稿模型相符（在我們稍後嚴格定義的統計意義下），我們就接受它；若不符，我們予以拒絕並從殘差分布中抽樣進行修正。大模型單次前向傳遞就能一口氣產出高達 `N+1` 個被接受的 token，而非僅僅一個。

真正關鍵的定理來自 Leviathan、Kalman 與 Matias（ICML 2023）：最終的輸出分布與直接從驗證模型進行抽樣完全相同。不是近似相同，而是**數學上百分之百嚴格一致**。這正是推測解碼在正式環境中被廣泛接納的核心原因——它是純粹的延遲最佳化，不帶任何品質妥協。

第 7 階段第 16 課為你奠定了數學基礎。本課為你交付完整的訓練與推論堆疊。一個高質量的草稿模型相較於粗糙的草稿模型加速效果可達廉價草稿模型的 2 倍。EAGLE、EAGLE-2 與 EAGLE-3（Li 等人，2024–2025 年）將「草稿 = 同家族的小型模型」這一粗糙概念打磨成了精密的工程科學。2026 年的正式環境推論伺服器預設皆採用 EAGLE-3。

## The Concept｜核心概念

### 不變的核心：Leviathan 拒絕取樣

令 `p(t)` 為草稿模型在給定前綴下對下一個 token 的機率分布，`q(t)` 為驗證模型的機率分布。從草稿中抽樣一個 token `d ~ p`。以 `min(1, q(d) / p(d))` 的機率接受它。若拒絕，則從殘差分布 `(q - p)_+ / ||(q - p)_+||_1` 中抽樣。所得樣本的機率分布嚴格遵循 `q`。無論 `p` 多麼拙劣，這個結論始終成立——情況越差，拒絕的頻率越高，但最終輸出依然精確無誤。

透過在 `prefix + d_1 + ... + d_N` 上執行單次驗證模型前向傳遞，將 `N` 次此類呼叫串聯在一起。驗證模型同時回傳 `q_1, q_2, ..., q_{N+1}`。從左到右依次檢驗。一旦在位置 `j` 發生首次拒絕，從 `residual(q_j, p_j)` 中抽樣並立即停止。若全部通過驗證，則從 `q_{N+1}` 中免費額外抽樣一個 token。

### 決定加速比的關鍵因素

令 `α` 為每個草稿 token 的預期接受率。令 `c = cost(draft) / cost(verifier)` 為成本比例。每次驗證模型前向傳遞所能產出的預期接受 token 數為：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每個被接受 token 所花費的預期總實際耗時為 `(N * c + 1) / E[accepted]`。針對 `N` 對此式求極小值即可求得最佳甜蜜點。在 `α = 0.8, c = 0.05` 下：最佳 `N` 約為 5 到 7，加速比達 3.2 倍。在 `α = 0.95, c = 0.02` 下：最佳 `N` 約為 8 到 10，加速比直逼 5 倍。

單一最大的槓桿就是 `α`。在固定 `N = 5` 下，從 `α = 0.6`（樸素草稿）拉升至 `α = 0.9`（EAGLE-3），每次驗證呼叫產出的預期接受 token 數將從 2.2 個躍升至 4.1 個。相同的驗證模型，吞吐量直接翻倍。

### 兩年技術演進

**樸素推測解碼（Leviathan，2023 年）。** 草稿模型是同家族中獨立訓練的小型 LLM。組裝容易，`α ≈ 0.6`，加速比頂多在 2 倍左右。

**EAGLE-1（Li 等人，2024 年）。** 草稿模型是一個微型的 transformer——通常只有一到兩層——以驗證模型最後一層的隱藏狀態作為輸入，直接預測下一個 token。由於草稿模型看見了驗證模型的特徵表示，其機率分布與驗證模型大幅貼近。`α` 爬升至 0.7 到 0.8。

**EAGLE-2（Li 等人，2024 年）。** 引入了動態草稿樹：不再單純預測單一條包含 `N` 個 token 的序列，而是提出一棵候選的小樹，在單次驗證傳遞中透過樹狀注意力（tree attention）為每個候選打分，並沿著機率最高的路徑前進。草稿長度實現了每步動態自適應。獲選路徑上的 per-token `α` 突破 0.85。

**EAGLE-3（Li 等人，2025 年，NeurIPS）。** 又帶來了兩項突破。首先，徹底拋棄特徵預測損失——EAGLE-1/2 訓練草稿模型去匹配驗證模型的隱藏狀態，這限制了資料規模帶來的助益。EAGLE-3 直接針對 token 預測進行訓練。其次，訓練期測試（Training-time test，TTT）：在草稿模型訓練期間，將其自身的先前預測作為後續步驟的輸入餵回，完全模擬推論時的操作方式。這使訓練分布與測試分布保持一致，消除了誤差累積。實測加速比：在對話任務上高達 6.5 倍，在 H100 上的 SGLang 批次 64 下吞吐量提升 38%。

### KV 快取回滾機制

驗證操作在單次傳遞中將驗證模型的 KV 快取向後延伸了 `N` 個條目。如果拒絕發生在位置 `j`，位置 `j-1` 之後的快取內容便不再正確。兩種常見工程實作：寫入臨時暫存緩衝區並在接受時正式寫入（vLLM、TensorRT-LLM），或者維護實體 KV 快取與邏輯長度，拒絕時截斷邏輯長度。無論哪種方式，回滾成本僅為每層、每頭的 KV 位元組量，相較於前向傳遞成本可忽略不計。

對於 EAGLE-2 的樹狀搜尋，驗證模型採用符合樹拓撲結構的非因果遮罩執行注意力運算。工程細節雖然繁瑣，但底層只是呼叫帶有自訂遮罩的標準 FlashAttention。

## Build It｜動手實作

完整實作請參閱 `code/main.py`。這裡包含了完整的 Leviathan 推測解碼迴圈的所有環節：N-token 草稿、驗證模型並行傳遞、逐位置拒絕、殘差抽樣、額外贈送 token、KV 回滾，以及輸出分布與直接從 `q` 抽樣完全吻合的實證檢驗。

### 步驟 1：拒絕法則

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步驟 2：殘差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步驟 3：完整的推測步驟

`spec_step` 函數從 `p` 中產生 `N` 個 token 的草稿，接著在單次並行 `q` 評估中驗證它們。它對每個草稿 token 套用拒絕法則，並在首次拒絕時從殘差分布中抽樣修正。如果全部接受，則從 `q_{N+1}` 中產出額外贈送 token。

### 步驟 4：KV 回滾記錄簿

模擬器追蹤每個 worker 的邏輯 `kv_length`。當接受 `k` 個草稿時，`kv_length += k`。當在位置 `j` 發生拒絕時，雖然實體快取已經寫過了位置 `j`，但邏輯長度會被重設為 `prefix_length + j + 1`——即修正 token 的下一個位置。後續讀取會自動截斷至該邏輯長度。

### 步驟 5：Leviathan 定理檢驗

執行 50,000 次推測步驟。統計被接受 token 的經驗分布，並與直接從 `q` 進行的 50,000 次直接抽樣進行比較。卡方統計量（chi-square statistic）應遠低於臨界值，在實務中驗證該定理的正確性。

### 步驟 6：加速比對照 α

透過以不同幅度擾動 `p` 偏離 `q` 來掃描草稿品質。測量 `α`，並繪製每次驗證呼叫的預期 token 數作為 `α` 與 `N` 的函數曲線。程式碼會印出一張表格，展示 EAGLE-3 等級的草稿品質（`α ≈ 0.9`）如何釋放出每次驗證呼叫產出 4 到 5 個 token 的潛力。

## Use It｜實際應用

在生產級 `vllm serve` 中啟用 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

根據 EAGLE-3 論文，在 H100 上的 SGLang 批次 64 下，EAGLE-3 推測解碼相較於批次 64 的樸素解碼能帶來約 1.38 倍的額外吞吐量。

何時應採用推測解碼：

- 任何對話型互動負載，其中 p50 延遲的重要性高於單純的峰值吞吐量。
- 程式碼生成與結構化輸出（JSON、SQL）。`α` 接受率往往高於 0.9，因為目標分布具有高度可預測性。
- 長篇文本生成（數千個 token）。分攤後的加速效能將持續帶來回報。

何時不應採用：

- 極小型模型（< 3B）。草稿模型相較於驗證模型便宜不了多少。
- 小型批次為 1 的 CPU 部署環境。草稿模型的記憶體開銷可能得不償失。
- 溫度極高的發散性創意抽樣，此時 `α` 接受率會劇烈跌落。

## Key Terms｜關鍵術語

| 術語 | 常見說法 | 實際意義 |
|------|----------------|------------------------|
| Leviathan 法則 | 「min(1, q 除以 p)」 | 伯努利接受／拒絕法則，機率為 `min(1, q(d)/p(d))`，拒絕時從殘差分布抽樣可嚴格保留驗證模型分布 |
| 殘差分布（Residual distribution） | 「q 減 p 取正並正規化」 | `(q - p)_+` 在零處截斷並重新歸一化——拒絕時應抽樣的正確分布 |
| 接受率 α | 「草稿猜對的頻率」 | 拒絕法則下每個 token 的預期伯努利成功機率；支配了所有加速比數學公式 |
| EAGLE-1 | 「隱藏狀態草稿」 | 以驗證模型最後一層隱藏狀態為條件的微型 transformer 草稿模型（Li 等人，2024 年） |
| EAGLE-2 | 「動態草稿樹」 | EAGLE-1 加上候選接續樹，在單次驗證傳遞中以樹狀注意力評分 |
| EAGLE-3 | 「訓練期測試」 | 捨棄特徵預測損失，在訓練期間直接將自身輸出餵回進行 token 預測訓練 |
| 訓練期測試（TTT） | 「暴露偏差修復方案」 | 在訓練期間以自回歸方式執行草稿模型，使訓練與測試輸入分布一致——排程抽樣的直接對應物 |
| KV 回滾（KV rollback） | 「撤銷被拒絕的草稿」 | 在拒絕後將驗證模型的 KV 快取重設回被接受前綴長度的記錄機制 |
| 額外贈送 token（Bonus token） | 「免費多送的一個」 | 當全部 `N` 個草稿皆被接受時，從 `q_{N+1}` 中額外抽樣一個 token，無任何額外驗證開銷 |
| 樹狀注意力（Tree attention） | 「一次驗證多個候選」 | 符合草稿樹拓撲結構的非因果遮罩注意力；在單次前向傳遞中為樹中每個節點計算 `q_i` |
