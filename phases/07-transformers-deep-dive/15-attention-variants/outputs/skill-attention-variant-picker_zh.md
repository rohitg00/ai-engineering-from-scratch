# 注意力变体选择器

帮助开发者选择并论证新Transformer（或要扩展到更长上下文的现有Transformer）的注意力拓扑。

## 需收集的输入

1. **目标上下文长度**——训练时和推理时的长度（通常不同——许多模型在16K训练，在推理时扩展）。
2. **检索需求**——1到5级：1 = 纯聊天，5 = 大海捞针 / RAG / 带有长仓库上下文的代码。
3. **推理内存预算**——每请求KV缓存容差（每层每token的字节数是合适的单位）。
4. **训练成本容忍度**——从头训练SWA很便宜；将微分注意力改造到预训练模型中很昂贵。
5. **硬件目标**——Hopper+有完整的FlashAttention-3，Ada有FA2，旧GPU受掩码限制。

## 决策规则

- **上下文 ≤ 16K 且检索 ≤ 3**：使用FlashAttention的完整注意力。不要过早优化。
- **上下文 16–128K 且检索 ≤ 3**：混合SWA + 全局层，比例为5:1，窗口1024（Gemma 3形状）。保持检索可行性同时压缩KV。
- **上下文 > 128K**：完整SWA，每4–6层加一个全局层，加上位置插值/YaRN缩放（第4课）。
- **检索 = 5 且训练预算允许**：考虑仅在最上面4层使用微分注意力（KV翻倍减半，大部分消除注意力崩溃的收益）。
- **你正在交付公共API**：优先选择稳定的模式（完整、SWA、Gemma-3混合）。跳过原生稀疏/DIFF，除非你有内核工程师。
- **你不能改变基座模型**：SWA可以通过推理时的掩码进行改造；微分注意力和稀疏注意力不行。

## 始终标记

- 7B以下的纯SWA模型通常在推理基准上可测量地表现较差。建议不要使用。
- 窗口大小 < 512几乎从不是正确的。使用更大的窗口或不同的拓扑结构。
- 论文中关于微分注意力的报告是在小模型（3–7B）上做的。截至2026年初，大规模证据仍然薄弱。
- 每种变体都与RoPE / YaRN缩放（第4课）相互作用。明确说明位置方案。

## 输出格式

返回：

1. **推荐**——一个命名的拓扑结构（例如"Gemma-3混合，W=1024，SWA:全局 = 5:1"）。
2. **理由**——将每个输入映射到上述决策规则。
3. **KV缓存估算**——在目标上下文下，以每层每token字节数和批次为1时的GB数。
4. **迁移路径**——如果基座模型已经训练好，如何进行改造。
5. **已知风险**——哪些基准测试/工作负载可能退化。
