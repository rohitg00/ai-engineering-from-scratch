# MIO 與任意對任意的串流多模態模型

> GPT-4o 出貨了一項多數開放模型複製不來的產品：一個能聽見語音、看見影片，並即時說話回應的代理程式。到 2024 年底，開放生態系給出的答案是 MIO（Wang 等人，2024 年 9 月）。MIO 把文字、影像、語音與音樂都分詞，在交錯的序列上訓練單一個因果 Transformer，並能從任一模態生成到任一模態。AnyGPT（Zhan 等人，2024 年 2 月）是那個概念驗證；MIO 是規模擴大版；Unified-IO 2（Allen AI，2023 年 12 月）則是帶視覺 + 動作接地的表親。這一課會讀任意對任意這套模式 —— 四個分詞器、一個 Transformer，以及對串流友善的解碼。

**類型：** 學習
**程式語言：** Python (stdlib, four-modality token allocator + streaming decode loop)
**先修單元：** 階段 12 · 11（Chameleon）、階段 6（語音與音訊）
**時間：** 約 120 分鐘

## 學習目標

- 設計一份共享詞彙表，讓文字、影像、語音與音樂詞元共存而不衝突。
- 在壓縮與重建的取捨上，比較 SEED-Tokenizer（影像）與 SpeechTokenizer 的殘差 VQ（語音）。
- 說明那套逐步堆出任意對任意生成能力的四階段課程。
- 說出三種開放的任意對任意配方及其主要取捨：MIO、AnyGPT、Unified-IO 2。

## 問題所在

統一多模態模型講起來容易，但要做到規模化很難。一路到 2024 年，多數「任意對任意」系統都是管線式的：視覺模型 → 文字表徵 → 語音模型 → 音訊。每一次轉手都流失資訊、增加延遲，也讓訓練更複雜。GPT-4o 的展示影片秀出了一個能在一秒內回應的單一模型替代方案；開放系統落後了好幾個月。

工程上的挑戰是：

- 每個模態都得有分詞器，壓縮得夠無損以支撐重建，而且產出詞元的速率要讓 Transformer 吃得下。
- 單一份詞彙表得替文字（32k 以上）、影像（8k 以上）、語音（4k 以上）、音樂（8k 以上）配置空間。最少五萬多個項目。
- 訓練資料必須涵蓋每一種輸入—輸出配對（文字→影像、影像→語音、語音→影像等），否則模型就得靠組合硬湊。
- 推論時輸出詞元的串流速度，得快到足以撐起對話級延遲（首個音訊位元組的時間 <500ms）。

## 核心概念

### 四種模態，四個分詞器

MIO 的分詞器堆疊：

- 文字：標準 BPE，詞彙表約 32000。
- 影像：SEED-Tokenizer（2023），一個離散影像分詞器，碼本有 8192 個項目，每張影像吐出 32 個詞元。
- 語音：SpeechTokenizer 的殘差 VQ（2023），把 16kHz 波形編碼成 8 個階層式碼本；第一層是粗略的內容，後續各層再加上韻律與說話者身分。MIO 保留內容層加上前三個音色層，每層 1024 個碼，所以共 4096 個語音 ID。
- 音樂：類似的殘差 VQ（Meta 的 MusicGen／Encodec 家族），4 到 8 個碼本。MIO 本身並沒有附音樂分詞器（它的第四種模態是影片，以影格的形式走影像分詞器）；本課的玩具範例加上音樂，是為了示範新模態怎麼佔下一段 ID 範圍。

每個模態都產出整數詞元。這些詞元在共享詞彙表中佔據互不相交的 ID 區間：

```
text:   0..31999
image:  32000..40191  (8192 image tokens)
speech: 40192..44287  (4 codebooks x 1024 speech tokens)
music:  44288..52479  (8192 music tokens, the toy's extension)
sep:    52480..52485  (<image>, <speech>, <music>, </...>)
```

總計：約 52k 的詞彙表。輸入嵌入與輸出投影橫跨全部。

### 串流解碼

語音生成用的是殘差 VQ。Transformer 預測基礎層（第 0 層）的語音詞元；一個平行解碼的殘差量化器再預測後續各層。每個第 0 層詞元，在 16kHz 下大約是 50ms 的音訊。

串流的樣態是：

1. 使用者對著麥克風說話；即時音訊分詞器每 50ms 吐出語音詞元。
2. MIO 邊到邊吃（提示詞預填 + 增量前向）。
3. 輸出詞元一邊生成一邊串流出去；一個平行的語音解碼器以約 50 到 150ms 的延遲把它們轉成音訊樣本。
4. 首個音訊位元組的時間：MIO 論文沒有回報延遲數字。依下方的延遲預算，這種設計最好也只能做到約 300ms，對照 GPT-4o 的約 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）與 Moshi（arXiv:2410.00037）是互補的串流語音 LLM 設計。Moshi 尤其厲害，在單張 GPU 上達成 160ms 的來回延遲。

### 四階段課程

MIO 的訓練課程：

1. 第 1 階段 —— 對齊。大規模的模態配對語料：文字—影像、文字—語音、文字—音樂。每種配對使用自己那段詞彙表區間。這是在訓練那份共享詞彙表。
2. 第 2 階段 —— 交錯。多模態交錯的文件（帶影像與影片的部落格、帶逐字稿的 podcast 等）。這是在訓練跨模態的脈絡。
3. 第 3 階段 —— 語音強化。額外的音訊資料，在不流失文字能力的前提下把語音品質拉上來。
4. 第 4 階段 —— SFT。跨模態的指令微調：VQA、字幕、旁白、語音對語音的對話。

少了任一階段，就會有特定能力退化：跳過第 2 階段，模型就失去跨模態脈絡；跳過第 3 階段，語音就很差。

### 視覺思維鏈

MIO 引入了視覺思維鏈：模型把中間的影像詞元當成一個推理步驟吐出來。面對「這隻貓是在爬樹嗎？」，模型會：

1. 吐出 `<image>` 詞元，把那個場景繪製出來（來自輸入影像或一張草圖）。
2. 吐出分析那張草圖的文字。
3. 吐出最終答案。

那張繪製出來的中間影像充當一塊草稿紙。空間推理任務的基準分數因此提升。這個想法對應的是文字推理裡的思維鏈。

### 任意對任意的競爭者

- AnyGPT（arXiv:2402.12226）：4 種模態（文字、影像、語音、音樂），設計相似。
- Unified-IO 2（arXiv:2312.17172）：加上了視覺動作輸出、深度、法向量。任務更多樣，但規模較小。
- NExT-GPT（arXiv:2309.05519）：LLM + 各模態專屬的擴散解碼器。不是單一模型的路線。
- CoDi（arXiv:2305.11846）：可組合的擴散；透過共享潛在空間做到任意對任意。

MIO 是最貼近純詞元式任意對任意的一個。AnyGPT 則是它概念上的祖先。

### 延遲預算

對一個對話式產品來說，每個元件的延遲都要緊：

- 麥克風到音訊詞元：約 50ms。
- 預填（音訊詞元 + 歷史）：在一個 8B 模型上約 100ms。
- 首個輸出詞元：約 50ms。
- 平行殘差 VQ + 語音解碼器：約 100 到 150ms。

首個音訊位元組的總時間：最少約 300ms。GPT-4o 宣稱約 250ms。Moshi 宣稱 160ms。MIO 與 AnyGPT 都沒有公布實測數字，所以把這份預算當成估計，而不是評測結果。

### 任意對任意為什麼依然困難

即便到了 2026 年，開放的任意對任意模型在兩根軸上仍落後於封閉模型：

- 語音品質。殘差 VQ 分詞器是有損的；相較於 ElevenLabs 等級的嗓音，對話語音聽起來很機械。
- 跨模態推理。要模型「唱出你所看到的」，失敗率仍然高於純視覺任務。

這些都是開放的研究問題。Qwen3-Omni（見單元 12.20）是 2025 年最先進的開放嘗試。

## 框架應用

`code/main.py`：

- 定義四模態的詞彙表配置並印出來。
- 把一串多模態輸入（文字、影像、音訊片段、音樂）送過分詞器路由器。
- 模擬一次文字轉語音回應的串流解碼，並計數延遲。
- 給定編碼器、預填與解碼器的延遲，算出預期的首個音訊位元組時間。

## 產出交付

這一課產出 `outputs/skill-any-to-any-pipeline-auditor.md`。給定一份對話式產品規格（輸入哪些模態、輸出哪些模態、延遲目標），它會稽核 MIO 家族的設計選擇，並算出延遲預算。

## 練習

1. 你的產品接受語音輸入並回傳語音輸出。端到端的延遲預算目標是多少？列出會花掉時間的各個元件。

2. SpeechTokenizer 的殘差 VQ 用了 8 個碼本。提出為什麼殘差各層必須平行解碼（而非循序），以及這能省下多少延遲。

3. 你的詞彙表有 32k 文字 + 8k 影像 + 4k 語音。再加上 8k 音樂與約 10 個分隔符。在隱藏維度 4096 之下，嵌入矩陣的參數成本是多少？

4. 視覺思維鏈會吐出一張中間影像。哪類問題會因此受益？哪類問題會被那些額外詞元拖累？

5. 讀 Moshi（arXiv:2410.00037）。描述它的「內心獨白」技巧，並與 MIO 的視覺思維鏈做比較。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| 任意對任意 | 「多模態進出」 | 單一模型能在任意方向上接收與吐出文字、影像、語音與音樂 |
| 殘差 VQ | 「語音分詞器堆疊」 | 多碼本的分詞方式，每一層都補上資訊；基礎層是內容，後續各層是韻律 |
| SEED-Tokenizer | 「影像編碼」 | MIO 使用的離散影像分詞器，碼本有 8192 個項目，每張影像 32 個詞元 |
| 視覺思維鏈 | 「視覺草稿紙」 | 模型在給出最終答案之前，先生成一張中間影像當作推理步驟 |
| 首個音訊位元組時間 | 「TTFAB」 | 從使用者出聲到第一個音訊輸出之間的延遲；要有對話感就得 <500ms |
| 四階段課程 | 「訓練配方」 | 對齊 -> 交錯 -> 語音強化 -> SFT，依此順序 |
