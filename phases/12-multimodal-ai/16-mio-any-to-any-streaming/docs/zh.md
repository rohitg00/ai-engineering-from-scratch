# MIO 与任意到任意流式多模态模型

> GPT-4o 推出了一款大多数开源模型无法复制的产品：一个能听、能看、能实时回话的智能体。截至 2024 年底，开源生态系统的答案是 MIO（Wang 等人，2024 年 9 月）。MIO 将文本、图像、语音和音乐进行分词，用一个因果 Transformer 训练交错的序列，并能够生成任意模态到任意模态的输出。AnyGPT（Zhan 等人，2024 年 2 月）是概念验证；MIO 是规模化版本；Unified-IO 2（Allen AI，2023 年 12 月）是增加了视觉 + 动作接地（grounding）的同类模型。本课讲解任意到任意（any-to-any）的模式——四个分词器，一个 Transformer，以及适合流式传输的解码方式。

**类型：** 学习
**语言：** Python（标准库，四模态 token 分配器 + 流式解码循环）
**前置知识：** 阶段 12 · 11（Chameleon），阶段 6（语音和音频）
**时间：** ~120 分钟

## 学习目标

- 设计一个共享词汇表，容纳文本、图像、语音和音乐的 token 且不发生冲突。
- 比较 SEED-Tokenizer（图像）和 SpeechTokenizer 残差向量量化（residual-VQ）（语音）在压缩与重建之间的权衡。
- 解释构建任意到任意生成的四阶段课程（curriculum）。
- 列出三种开源任意到任意方案及其主要权衡：MIO、AnyGPT、Unified-IO 2。

## 问题

统一的多模态模型说起来容易，大规模构建起来却很难。直到 2024 年，大多数"任意到任意"系统都是流水线式的：视觉模型 → 文本表示 → 语音模型 → 音频。每一跳都会损失信息、增加延迟并使训练复杂化。GPT-4o 的演示视频展示了一种亚秒级响应的单模型替代方案；开源系统落后了数月。

工程挑战如下：

- 必须为每种模态提供分词器，以足够无损的方式压缩以便重建，并产生 Transformer 能够消费的 token 速率。
- 单个词汇表必须为文本（32k+）、图像（16k+）、语音（4k+）和音乐（8k+）分配空间。至少四万个条目。
- 训练数据必须覆盖每一种输入-输出对（文本→图像、图像→语音、语音→图像等），否则模型必须能够组合生成。
- 推理必须以足够快的速度流式输出 token，以满足对话延迟（首个音频字节时间 <500ms）。

## 概念

### 四种模态的四个分词器

MIO 的分词器堆栈：

- 文本：标准 BPE，词汇量约 32000。
- 图像：SEED-Tokenizer（2023）——带有离散码本的量化 VAE，4096 个条目，每张图像 32×32 个 token。
- 语音：SpeechTokenizer 残差向量量化（2023）——将 16kHz 波形编码为 8 个分层码本；第一层是粗粒度内容，后续层增加韵律和说话人身份信息。
- 音乐：类似的残差向量量化（Meta 的 MusicGen/Encodec 系列），4-8 个码本。

每种模态产生整数 token。这些 token 在共享词汇表中获得互不重叠的 ID 范围：

```
文本：   0..31999
图像：   32000..36095  （4096 个图像 token）
语音：   36096..40191  （4096 个语音基础 token，加上残差层）
音乐：   40192..48383  （8192 个音乐 token）
分隔符： 48384..48390  （<image>、<speech>、<music>、</...> 等）
```

总计：约 48k 词汇量。输入嵌入和输出投影均覆盖整个范围。

### 流式解码

语音生成使用残差向量量化。Transformer 预测基础（第 0 层）语音 token；并行解码的残差量化器预测后续各层。每个第 0 层 token 大约对应 16kHz 下的 50ms 音频。

流式模式如下：

1. 用户对着麦克风说话；实时音频分词器每 50ms 发出语音 token。
2. MIO 在 token 到达时消费它们（提示预填充 + 增量前向计算）。
3. 输出 token 在生成时流式输出；并行语音解码器将其转换为音频样本，延迟约 50-150ms。
4. 首个音频字节时间：MIO 论文中约为 300-500ms，接近 GPT-4o 的约 250ms。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）和 Moshi（arXiv:2410.00037）是互补的流式语音-LLM 设计。其中 Moshi 在单 GPU 上实现了 160ms 的往返延迟。

### 四阶段课程

MIO 的训练课程：

1. 阶段 1——对齐（Alignment）。大规模模态对语料：文本-图像、文本-语音、文本-音乐。每对使用其自身的 token 词汇段。训练共享词汇表。
2. 阶段 2——交错（Interleaved）。多模态交错文档（带有图像和视频的博客、带有转录本的播客等）。训练跨模态上下文理解。
3. 阶段 3——语音增强（Speech-enhanced）。额外的音频数据，在不损失文本能力的前提下提升语音质量。
4. 阶段 4——监督微调（SFT）。跨模态的指令微调：VQA、图像描述、旁白、语音到语音对话。

缺少某个阶段会降低特定能力：跳过阶段 2 会导致模型失去跨模态上下文理解；跳过阶段 3 会导致语音质量不佳。

### 视觉思维链

MIO 引入了视觉思维链（chain-of-visual-thought）：模型将中间图像 token 作为推理步骤发出。对于"猫在爬树吗？"这个问题，模型：

1. 发出 `<image>` token，渲染场景（来自输入图像或草图）。
2. 发出分析草图的文本。
3. 发出最终答案。

渲染的中间图像充当草稿本（scratchpad）。基准测试在空间推理任务上有所提升。这一想法类似于文本推理中的思维链（chain-of-thought）。

### 任意到任意领域的竞争者

- **AnyGPT**（arXiv:2402.12226）：4 种模态（文本、图像、语音、音乐），类似设计。
- **Unified-IO 2**（arXiv:2312.17172）：增加视觉动作输出、深度图、法线图。任务多样性更高，规模较小。
- **NExT-GPT**（arXiv:2309.05519）：LLM + 模态特定扩散解码器。非单模型方法。
- **CoDi**（arXiv:2305.11846）：可组合扩散；通过共享潜在空间实现任意到任意。

MIO 最接近纯 token 的任意到任意方法。AnyGPT 是其概念上的前身。

### 延迟预算

对于对话式产品，每个组件的延迟都很重要：

- 麦克风到音频 token：约 50ms。
- 预填充（音频 token + 历史）：8B 模型上约 100ms。
- 第一个输出 token：约 50ms。
- 并行残差向量量化 + 语音解码器：约 100-150ms。

总首个音频字节时间：最低约 300ms。GPT-4o 声称约 250ms。Moshi 声称 160ms。根据公开基准，MIO/AnyGPT 在 400-600ms 范围内。

### 为什么任意到任意仍然困难

即使在 2026 年，开源的任意到任意模型在两个维度上仍落后于闭源模型：

- **语音质量。** 残差向量量化分词器是有损的；与 ElevenLabs 级别的语音相比，对话语音听起来仍显机械。
- **跨模态推理。** 要求模型"为你所见之物唱出来"时，失败率仍高于纯视觉任务。

这些都是开放的研究问题。Qwen3-Omni（课程 12.20）是 2025 年最先进的开源尝试。

## 使用它

`code/main.py`：

- 定义四种模态的词汇分配并打印。
- 将一系列多模态输入（文本、图像、音频片段、音乐）通过分词器路由器进行路由。
- 模拟文本到语音响应的流式解码并计算延迟。
- 根据编码器、预填充和解码器延迟计算预期的首个音频字节时间。

## 练习

1. 你的产品接受语音输入并返回语音输出。端到端延迟预算目标是多少？列出消耗时间的各个组件。

2. SpeechTokenizer 残差向量量化使用 8 个码本。请说明为什么需要并行解码残差层（而非顺序解码），以及它能带来多少延迟节省。

3. 你的词汇表有 32k 文本 + 4k 图像 + 4k 语音。增加 8k 音乐和约 10 个分隔符。在隐藏维度为 4096 时，嵌入矩阵的参数成本是多少？

4. 视觉思维链会发出一个中间图像。哪些类型的问题会从中受益？哪些类型会因为额外的 token 而受到损害？

5. 阅读 Moshi（arXiv:2410.00037）。描述其"内心独白"（inner monologue）技术，并与 MIO 的视觉思维链进行比较。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| 任意到任意（Any-to-any） | "多模态输入/输出" | 单个模型，能够以任意方向接受和生成文本、图像、语音和音乐 |
| 残差向量量化（Residual-VQ） | "语音分词器堆栈" | 多层码本分词，每层增加信息；基础层是内容，后续层是韵律 |
| SEED-Tokenizer | "图像编码" | MIO 使用的离散图像分词器，具有 4096 个条目的码本 |
| 视觉思维链（Chain-of-visual-thought） | "视觉草稿本" | 模型在给出最终答案之前，生成中间图像作为推理步骤 |
| 首个音频字节时间（Time-to-first-audio-byte） | "TTFAB" | 从用户语音到首次音频输出的延迟；<500ms 以获得对话感 |
| 四阶段课程（Four-stage curriculum） | "训练配方" | 对齐 -> 交错 -> 语音增强 -> SFT，按此顺序进行 |
