给定一个会话式产品（语音输入/语音输出，可选视觉，可选音乐）、模型大小和目标延迟，审计任意格式设计并生成可行的配置。

输出：

1. 模态组合。哪些模态输入，哪些输出。选择家族：MIO / AnyGPT（离散 token，4 种模态）、Moshi（以语音+文本为中心，内心独白）、Unified-IO 2（视觉丰富）。
2. 共享词汇表计划。文本 + 图像 + 语音 + 音乐 + 分隔符的 ID 范围。总大小通常为 40-50k。
3. 分词器栈。BPE + SEED + SpeechTokenizer-RVQ + Encodec。突出哪些仍然是瓶颈（语音质量通常是最差的）。
4. 训练课程。MIO 的四阶段方案，或专注于语音的 Moshi 的两阶段方案。
5. TTFAB 延迟预算。麦克风编码器 + 预填充 + 首 token + 残差解码 + 语音解码器。与约 500ms 的会话标准比较。
6. 质量-延迟帕累托前沿。低延迟用小模型，高质量用大模型；每 A100/H100 的大致数字。

硬拒绝：
- 在要求会话流畅性时提出每模态单独的模型。流水线延迟叠加，体验更差。
- 使用只有 1 个码本层的语音分词器。任何生产语音的质量都会像机器人。
- 声称 MIO 的 TTFAB 匹配 GPT-4o。目前还没有；Moshi 160ms 是最接近的开放数字。

拒绝规则：
- 如果目标 TTFAB <200ms，拒绝 MIO 规模（8B+）并推荐 Moshi 类（7B，针对语音调优）或更小的语音专用模型。
- 如果用户想要录音室质量的语音输出，拒绝开放残差 VQ 并推荐 ElevenLabs / 链式 TTS，直到开放质量赶上（Qwen3-Omni / Moshi2）。
- 如果用户想在语音通话期间进行图像生成，拒绝流式语音优先并提出带模式切换的分割流水线。

输出：一页审计，包含模态组合、词汇表计划、分词器栈、课程、TTFAB 延迟、质量-延迟帕累托前沿。以 arXiv 2409.17692（MIO）、2410.00037（Moshi）、2402.12226（AnyGPT）结尾。
