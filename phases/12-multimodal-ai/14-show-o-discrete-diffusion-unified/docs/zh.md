# Show-o 与离散扩散统一模型

> Transfusion 混合了连续表示和离散表示。Show-o（Xie 等人，2024 年 8 月）走了另一条路：文本 token 使用因果式下一个 token 预测，图像 token 使用受 MaskGIT 启发的掩码离散扩散。两者共处于一个带有混合注意力掩码的 Transformer 中。其结果是在单个骨干网络、每种模态一个分词器、同一个损失公式（将下一个 token 预测扩展为掩码预测）上统一了 VQA、文生图、图像修复和多模态生成。本课程讲解 Show-o 的设计——为什么掩码离散扩散是一种并行的、少步数图像生成器——并与 Transfusion 和 Emu3 进行对比。

**类型：** 学习
**语言：** Python（标准库，掩码离散扩散采样器）
**前置要求：** 阶段 12 · 13（Transfusion）
**时间：** 约 120 分钟

## 学习目标

- 解释掩码离散扩散：其调度机制均匀地掩码 token，然后让 Transformer 恢复它们。
- 在速度和质量上比较并行图像解码（Show-o、MaskGIT）与自回归图像解码（Chameleon、Emu3）。
- 说出 Show-o 在一个检查点中处理的三个任务：T2I、VQA、图像修复。
- 选择一个掩码调度（余弦、线性、截断）并分析其对样本质量的影响。

## 问题

Transfusion 的双损失训练虽然有效，但动态调整较为棘手——连续扩散损失与离散 NTP 损失处于不同的数值量级。平衡损失权重需要进行超参数搜索。该架构高效但复杂。

Show-o 的回答：让两种模态都保持离散（像 Chameleon 一样），但通过掩码离散扩散并行生成图像，而不是串行生成。训练目标变为单一的掩码 token 预测，自然地泛化了下一个 token 预测。

## 核心概念

### 掩码离散扩散（MaskGIT）

原始的 Chang 等人（2022）MaskGIT 技巧非常优雅。从一幅完全掩码的图像开始（每个 token 都是特殊的 `<MASK>` id）。在每一步中，并行预测所有被掩码的 token，然后保留置信度最高的 K 个预测，重新掩码其余部分。经过约 8-16 次迭代后，所有 token 都被填充完毕。每步取消掩码的 token 数量的调度需要调优——余弦调度效果很好。

训练很简单：从 [0, 1] 均匀采样一个掩码比例，将其应用于图像的 VQ token，训练 Transformer 恢复被掩码的 token。这正是 BERT 对文本所做的，但规模扩大到图像生成。

### Show-o：一个 Transformer，混合掩码

Show-o 将 MaskGIT 放入一个因果语言模型 Transformer 中。注意力掩码如下：

- **文本 token：** 因果掩码（标准 LLM）。
- **图像 token：** 图像块内全双向掩码（使得被掩码的 token 在预测时能看到所有其他图像 token）。
- **文生图：** 文本关注先前的图像，图像关注先前的文本。

训练在以下三种模式间交替：
1. 对文本序列进行标准 NTP。
2. T2I 样本：文本 → 图像，使用掩码图像 token，损失为掩码 token 预测。
3. VQA 样本：图像 → 文本，使用掩码文本 token（实际上就是 NTP）。

统一的损失是关于 `<MASK>` token 的交叉熵，这既覆盖了文本 NTP（只有最后一个 token 被"掩码"），也覆盖了图像掩码扩散（随机子集被掩码）。

### 并行采样

Show-o 在大约 16 步内生成一幅图像，而不是约 1000 步（每个 token 自回归）或约 20 步（扩散）。在每一步中，并行预测所有被掩码的 token；保留置信度最高的 K 个；重复。

比较：
- **Chameleon / Emu3**（token 自回归）：N 个 token 的前向传播，通常每幅图像 1024-4096 次。
- **Transfusion**（连续扩散）：约 20 步，每一步是一次完整的 Transformer 前向传播。
- **Show-o**（掩码离散扩散）：约 16 步，每一步是一次完整的 Transformer 前向传播。

在相似规模的模型下，Show-o 比 Chameleon 更快，步数大致与 Transfusion 相当，但每步成本更低（离散词表 logits 与连续 MSE 损失相比）。

### 单个检查点中的任务

Show-o 在推理时支持四种任务，通过提示格式选择：

- **文本生成：** 标准自回归文本输出。
- **VQA：** 图像输入，文本输出。
- **T2I：** 文本输入，通过掩码离散扩散输出图像。
- **图像修复：** 输入部分 token 被掩码的图像，填充缺失部分。

图像修复能力来自于掩码预测训练的天然副产品。掩码 VQ token 网格的某个区域，输入剩余部分加上文本提示，预测被掩码的 token。

### 掩码调度

每步取消掩码的 token 数量的调度决定了生成质量。Show-o 推荐余弦调度：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

在第 0 步，所有 token 被掩码（比例 1.0）。在第 T 步，没有 token 被掩码。余弦调度将质量集中在中段比例上，此时预测的信息量最大。线性调度也可以工作，但会更快地进入平台期。

### Show-o2

Show-o2（2025 年后续工作，arXiv 2506.15564）扩展了 Show-o：更大的 LLM 基座、更好的分词器、改进的掩码调度。架构模式相同。

### Show-o 的定位

在 2026 年的分类中：

- **离散 token + NTP：** Chameleon、Emu3。简单但推理速度慢。
- **离散 token + 掩码扩散：** Show-o、MaskGIT、LlamaGen、Muse。并行采样，仍受分词器信息损失影响。
- **连续 + 扩散：** Transfusion、MMDiT、DiT。质量最高，训练更复杂。
- **连续 + VLM 中的流匹配：** JanusFlow、InternVL-U。最新。

根据任务选择：当你想要一个兼具 T2I + 图像修复 + VQA 且速度合理的开放模型时，选择 Show-o；当质量是首要考量且你能承受双损失框架的复杂性时，选择 Transfusion。

## 使用

`code/main.py` 模拟了 Show-o 的采样：

- 一个包含 16 个 VQ token 的玩具网格。
- 一个模拟的"Transformer"，根据提示和当前未掩码的 token 预测 logits。
- 使用余弦调度在 8 步内进行并行掩码采样。

运行它，观察掩码逐步消失的过程。

## 练习

1. 掩码离散扩散用约 16 步采样。为什么不是 1 步？如果在第 0 步就取消所有掩码，会出什么问题？

2. 图像修复对于掩码扩散来说是免费的。提出一个产品用例（真实或假设），其中 Show-o 的图像修复优于专用模型。

3. 余弦调度与线性调度：对于 T=8，追踪每步未掩码的 token 数量。哪个更均衡？

4. 一幅 512x512 的 Show-o 图像是 1024 个 token。在词表大小 K=16384 的情况下，模型生成 1024 * log2(16384) = 14,336 比特（约 1.75 KiB）的数据。Stable Diffusion 输出 512x512x24 比特 = 6,291,456 比特（约 768 KiB）的原始像素。压缩比是多少？这种压缩换来了什么质量优势？

5. 阅读 LlamaGen（arXiv:2406.06525）。LlamaGen 的类别条件自回归图像模型与 Show-o 的掩码方法有何不同？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| 掩码离散扩散 | "MaskGIT 风格" | 训练模型预测被掩码的 token；推理时，迭代式地取消掩码置信度最高的预测 |
| 余弦调度 | "取消掩码调度" | 推理步骤中掩码比例的衰减；使置信度增长集中在中段范围 |
| 并行解码 | "所有 token 同时" | 每一步在一次前向传播中预测整个被掩码 token 序列，然后保留 Top-K |
| 混合注意力 | "因果 + 双向" | 文本 token 上使用因果掩码，图像块内部使用双向掩码 |
| 图像修复 | "填充生成" | 以部分 token 被掩码的图像为条件，预测缺失的 token；来自训练目标的天然副产品 |
| 提交率 | "每步 Top-K" | 每次迭代中声明"已完成"的 token 数量；控制推理速度与质量的权衡 |
