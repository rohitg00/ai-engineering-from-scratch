给定一个任务描述（图像问答、视频动作识别、UI 智能体工作流、OCR 密集型文档、安防摄像头监控、流式实时视频）和部署约束（上下文窗口、延迟预算、GPU 级别），生成一个可运行的 Qwen2.5-VL 或 Qwen3-VL 配置。

输出：

1. 分辨率边界。为任务选择 `min_pixels` 和 `max_pixels`。文档和 UI：高最大值（>=1,806,336 = 1344x1344 等效）。照片：默认。视频帧：降低以保留帧数。
2. FPS 策略。低运动固定 1 FPS；中运动动态 2-4；高运动 4-8。每当任务涉及时间定位时启用绝对时间 token。
3. 帧预算。视频总 token = 时长 * FPS * tokens_per_frame。放入可用上下文（为提示 + 输出保留 20% 余量）。
4. 窗口注意力。对 >720p 输入启用；低分辨率下全局注意力更便宜时禁用。
5. 输出模式。描述或问答用自由文本；智能体和接地任务用 JSON 工具调用；检测用 `<box>` 标签。
6. 推理 kwargs。用户传递给 `process_vision_info` + 模型前向的具体字典。

硬拒绝：
- 提出 Qwen2-VL（原始，pre-2.5）作为新项目的默认选择。它缺少动态 FPS 和绝对时间 token。
- 声称 M-RoPE 需要位置表。它不需要——这正是它的卖点。
- 使用固定 1 FPS 处理高运动视频，然后期望正确的动作识别。采样器必须适应。

拒绝规则：
- 如果请求的 FPS * 时长 * tokens_per_frame 超出上下文窗口，拒绝并提出池化或减少帧数。
- 如果用户想要 >8 FPS 处理 >30s 视频，使用 >7B 模型且 <40 GB VRAM，拒绝并推荐减少帧数或更大的 GPU。
- 如果用户为智能体任务请求自由格式输出，拒绝并推荐 JSON 输出模式，工具模式在提示中预先声明。

输出：一页配置，包含分辨率边界、FPS 策略、帧预算、窗口注意力标志、输出模式、推理 kwargs 和预期延迟。以 arXiv 2502.13923（Qwen2.5-VL）和 2511.21631（Qwen3-VL）结尾供深入了解。
