# Qwen-VL 家族與動態 FPS 影片

> Qwen-VL 家族 —— Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）—— 是 2026 年最具影響力的開放視覺—語言模型血脈。每一代都押下了一個決定性的架構賭注，而開放生態系的其他人在十二個月內就抄了過去：靠 M-RoPE 實現的原生動態解析度、搭配絕對時間對齊的動態 FPS 取樣、ViT 裡的視窗注意力，以及結構化的代理程式輸出格式。到了 Qwen3-VL，這份配方已經穩定下來：一個吃原生長寬比輸入的 2D-RoPE-ViT 編碼器、一個接進大型 Qwen3 語言基礎模型的 MLP 投影器，以及把 OCR、接地與代理程式行為當成一級目標來強調的訓練階段。這一課會按時間順序讀完這個家族，好讓你明白每一個旋鈕為什麼會擺在它現在的位置。

**類型：** 學習
**程式語言：** Python (stdlib, M-RoPE encoder + dynamic-FPS sampler)
**先修單元：** 階段 12 · 06（patch-n'-pack）
**時間：** 約 120 分鐘

## 學習目標

- 算出 M-RoPE 的三軸旋轉（時間、高、寬），並說明為什麼三者都不可少。
- 為一段影片挑一種動態 FPS 取樣策略，並推敲每秒詞元數與事件偵測準確率之間的權衡。
- 依序說出 Qwen-VL 的四次世代升級，以及各自解鎖了什麼。
- 接上一個 Qwen2.5-VL 風格的 JSON 代理程式輸出格式，並從 VLM 回應中解析出結構化的工具呼叫。

## 問題所在

Qwen-VL 在 2023 年 8 月出貨，是對 LLaVA-1.5 與 BLIP-2 的直接回應。Qwen 團隊瞄準的落差有三塊：解析度、影片與結構化輸出。

解析度：LLaVA-1.5 跑在 336x336。用來看照片沒問題，但對一張中文發票或一張密集的試算表截圖就毫無用處。Qwen-VL 的第一項創新是 448x448 與帶接地的邊界框輸出，讓模型能指出東西在哪。

影片：Video-LLaMA 把逐畫格編碼器疊起來再餵給 LLM。這對短片段可行，但對數分鐘的影片就不行了 —— 那裡時間軸才是訊號。Qwen 團隊想要一個懂時間的單一編碼器。

結構化輸出：LLaVA 吐的是自由形式的文字。代理程式需要的是 JSON。Qwen-VL 是在明確的 JSON 輸出格式上訓練的，其中連邊界框座標都以文字形式表示。

Qwen-VL 的每一代，都在延伸這三根軸中的某一根。

## 核心概念

### Qwen-VL（2023 年 8 月）

第一代：以 OpenCLIP ViT-bigG/14 為編碼器（25 億參數）、一個相容 LLama 的 Q-Former（單步，256 個 query）、Qwen-7B 為基礎。貢獻是：

- 448x448 解析度（在當時是開放 VLM 的 SOTA）。
- 接地：在帶有明確座標詞元輸出的影像—文字配對上訓練。「The cat is at <box>(112, 204), (280, 344)</box>」。
- 從一開始就做中英雙語的多語言訓練。

當時的基準表現：英文上與 GPT-4V 有得拼，中文上則佔絕對優勢。而真正的頭條是那套接地監督。

### Qwen2-VL（2024 年 9 月）—— M-RoPE 與原生解析度

Qwen2-VL 把「固定解析度 + Q-Former」的那套堆疊，換成一個原生動態解析度的 ViT 編碼器。關鍵改動：

- 原生動態解析度。ViT 接受任何能被 28 整除的 HxW（patch 14 搭配 2 倍的空間合併）。一張 1120x672 的影像（合併後 40x24 個 patch）產出 960 個視覺詞元。不縮放、不鋪排、不用縮圖。
- M-RoPE（多模態 RoPE）。每個詞元帶的是三維位置 (t, h, w)，而不是一維。影像的 t=0，影片的 t = 畫格索引。RoPE 依每根軸各自的頻率去旋轉 query／key 向量。不需要位置嵌入表。
- MLP 投影器。捨棄 Q-Former；在合併後的 patch 詞元上用一個兩層 MLP。
- 動態 FPS 的影片。影片預設以 1 到 2 FPS 取樣，但模型接受任意畫格數。

結果：Qwen2-VL-7B 在數個多模態基準上追平 GPT-4o，並在 DocVQA 上勝過它（94.5 對 88.4）。架構的改動就是那一著決定性的棋。

### Qwen2.5-VL（2025 年 2 月）—— 動態 FPS + 絕對時間

Qwen2.5-VL 最大的轉變在影片。動態 FPS 不只是「需要時就多取幾格」。論文把它形式化為：

- 絕對時間詞元。不用位置索引（畫格 0、1、2……），改用實際的時間戳。「在 0:04 時，貓跳了起來。」模型看到的是與畫格詞元交錯的 `<time>0.04</time>` 詞元。
- 動態 FPS。慢速素材用 1 FPS 取樣，動作場面用 4 FPS 以上。由使用者或訓練者決定；M-RoPE 會跟著調適。
- ViT 中的視窗注意力。空間注意力做成視窗式（在區塊內局部運算）以提升吞吐量；每隔幾層再做一次全域注意力。
- 明確的 JSON 輸出格式。在工具呼叫資料上訓練：「{\"tool\": \"click\", \"coords\": [380, 220]}」。開箱即用於代理程式。
- MRoPE-v2 縮放。位置會隨最大輸入尺寸縮放，好讓一段 10 分鐘的影片不會把頻率範圍用光。

基準表現：Qwen2.5-VL-72B 在多數影片基準上勝過 GPT-4o，在文件上追平 Gemini 2.0，並在 GUI 接地上創下開放模型的 SOTA（ScreenSpot：84% 準確率，GPT-4o 為 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一次鞏固而非重新發明的漸進升級：更大的 LLM 骨幹（Qwen3-72B）、擴充的訓練資料、更好的 OCR，以及透過 Qwen3「思考模式」而更強的推理。ViT 與 M-RoPE 都留著。論文的重點放在資料與訓練的改進，而非架構。

這條血脈的重點是：到了 2025 年，Qwen-VL 的架構已經穩定下來。後續世代擴展的是計算與資料，不是基本單位。

### M-RoPE 的數學

古典的 RoPE 用成對的座標，把一個維度為 `d` 的 query `q` 依位置 `m` 旋轉：

```math
\begin{aligned}
q_{\text{rot}}[2i] &= q[2i] \cos(m \theta_i) - q[2i+1] \sin(m \theta_i) \\
q_{\text{rot}}[2i+1] &= q[2i] \sin(m \theta_i) + q[2i+1] \cos(m \theta_i) \\
\theta_i &= 10000^{-2i/d}
\end{aligned}
```

M-RoPE 把隱藏維度切成三個頻帶。假設 `d = 96`。指派 32 維給時間、32 維給高、32 維給寬。每個頻帶依它自己那根軸的位置去旋轉。一個位在 (t=5, h=10, w=20) 的 patch，其三個頻帶會分別套用 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文字詞元用的是 `t = text_index, h = 0, w = 0`（或某種正規化的選擇），以維持相容性。影片畫格用 `t = frame_time, h = row, w = col`。單張影像用 `t = 0`。

好處是：單一套位置編碼就能處理文字、影像與影片，不需要分支的程式碼，也不需要不同的位置表。

### 動態 FPS 的取樣邏輯

給定一段長度 `T` 秒的影片與一個目標詞元預算 `B`：

1. 算出你負擔得起的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 從 `{1, 2, 4, 8}` 中挑一個滿足 `fps <= fps_max` 的目標 FPS。
3. 若動態量大（用光流啟發式判斷，或使用者明確要求），就挑更高的 FPS。動態量小就挑低的。
4. 以選定的 FPS 均勻取樣；在畫格之間插入 `<time>t</time>` 詞元。

Qwen2.5-VL 是隱式地訓練這套邏輯；推論時使用者透過 `fps` 參數控制。一段 60 秒的動作序列以 4 FPS、每畫格 81 個詞元計算 = 19440 個詞元，在 32k 的脈絡下應付得來。

### 結構化的代理程式輸出

Qwen2.5-VL 的代理程式訓練明確瞄準結構化的工具呼叫：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是確定性的：對模型輸出跑 JSON.parse。相比之下，自由形式的「click at (1024, 512)」需要正規表示式，還得處理歧義。正是這個轉變，讓 Qwen2.5-VL 的 ScreenSpot 分數從 Qwen2-VL 的 55% 跳到 84%。

## 框架應用

`code/main.py` 實作了：

- 對一條混合文字、影像 patch 與影片畫格的打包序列，計算 M-RoPE 位置。
- 動態 FPS 取樣器：給定 (時長, 預算, 動態量)，挑出 FPS 並吐出畫格時間戳。
- 一個玩具版的 Qwen2.5-VL JSON 輸出解析器，能處理帶座標欄位的工具呼叫回應。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|-----------------|------------------------|
| M-RoPE | 「多模態 RoPE」 | 三維旋轉位置嵌入，在隱藏維度中分出時間、高、寬三個頻帶 |
| 動態 FPS | 「聰明取樣」 | 依動態量、時長與詞元預算，為每段影片各自挑選的畫格取樣率 |
| 絕對時間詞元 | 「時間戳詞元」 | 交錯在序列中的 `<time>t</time>`，讓模型看到的是實際秒數而非畫格索引 |
| 視窗注意力 | 「局部注意力」 | 為了速度而限制在小視窗內的空間自注意力；再週期性地補上全域注意力 |
| 結構化代理程式輸出 | 「JSON 模式」 | 用訓練資料監督，教會 VLM 吐出帶座標與工具名稱、可被解析的 JSON |
| min_pixels／max_pixels | 「解析度上下界」 | Qwen2.5-VL 的逐請求控制項，用來限制總像素數，也因此限制了詞元數 |
| 接地 | 「指出它在哪」 | 把邊界框座標當成文字詞元輸出；從 Qwen-VL v1 起就在用 |
