# Qwen-VL 系列与 Dynamic-FPS 视频

> Qwen-VL 系列——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是截至 2026 年最具影响力的开源视觉语言模型系列。每一代都做出了一项决定性的架构赌注，而开源生态圈在十二个月内悉数效仿：基于 M-RoPE 的原生动态分辨率、带绝对时间对齐的动态 FPS 采样、ViT 中的窗口注意力以及结构化智能体输出格式。到 Qwen3-VL，配方已经稳固：一个支持原生宽高比输入的 2D-RoPE-ViT 编码器、一个将特征映射到大规模 Qwen3 语言基座的 MLP 投影器，以及将 OCR、定位和智能体行为作为一等目标进行训练的阶段。本文按时间顺序通读该系列，帮助读者理解每一个设计决策的由来。

**类型：** 学习
**语言：** Python（标准库，M-RoPE 编码器 + 动态 FPS 采样器）
**前置知识：** 阶段 12 · 06（patch-n'-pack）
**时长：** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三轴旋转（时间、高度、宽度），并解释为何三者缺一不可。
- 为视频选取动态 FPS 采样策略，并权衡每秒 token 数与事件检测准确率。
- 按顺序说出 Qwen-VL 四代升级及其各自带来的能力。
- 搭建 Qwen2.5-VL 风格的 JSON 智能体输出格式，并从 VLM 响应中解析结构化工具调用。

## 问题背景

Qwen-VL 于 2023 年 8 月发布，直接对标 LLaVA-1.5 和 BLIP-2。Qwen 团队瞄准的差距主要有三个维度：分辨率、视频和结构化输出。

**分辨率：** LLaVA-1.5 运行在 336x336 分辨率上。这对照片来说尚可，但对于中文发票或密集的电子表格截图则毫无用处。Qwen-VL 的首个创新是 448x448 分辨率以及带定位的边界框输出，让模型能够"指向"物体。

**视频：** Video-LLaMA 堆叠了逐帧编码器并将其馈送到 LLM。这适用于短视频片段，而对于时间轴本身就是信号的多分钟视频则力不从心。Qwen 团队希望有一个能理解时间的单一编码器。

**结构化输出：** LLaVA 输出自由文本。而智能体需要 JSON。Qwen-VL 针对明确的 JSON 输出格式（包括以文本形式输出的边界框坐标）进行了训练。

每一代 Qwen-VL 都在这三个维度之一上进行了延伸。

## 核心概念

### Qwen-VL（2023 年 8 月）

第一代：编码器采用 OpenCLIP ViT-bigG/14（25 亿参数），兼容 LLaMA 的 Q-Former（单步，256 个查询），基座为 Qwen-7B。贡献如下：

- 448x448 分辨率（当时开源 VLM 的最佳水平）。
- 定位能力：在带有显式坐标 token 输出的图像-文本对上训练。"猫在 \<box\>(112, 204), (280, 344)\</box\>"。
- 从一开始就支持中文和英文的多语言训练。

当时的基准：在英文上与 GPT-4V 不相上下，在中文上占据主导地位。定位监督才是真正的亮点。

### Qwen2-VL（2024 年 9月）—— M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率的 ViT 编码器取代了固定分辨率 + Q-Former 的组合。关键变化：

- **原生动态分辨率。** ViT 接受任意能被 28 整除的 H×W（patch 大小为 14，2×2 空间合并）。1120×672 的图像（40×24 合并后的 patch）产生 960 个视觉 token。无需缩放、无需分块、无需缩略图。
- **M-RoPE（多模态 RoPE）。** 每个 token 携带三维位置 (t, h, w) 而非一维位置。图像中 t=0，视频中 t=帧索引。RoPE 按每个轴各自的频率旋转 query/key 向量。无需位置嵌入表。
- **MLP 投影器。** 去掉 Q-Former；在合并后的 patch token 上使用两层 MLP。
- **动态 FPS 视频。** 默认以 1-2 FPS 采样视频，但模型可接受任意数量的帧。

结果：Qwen2-VL-7B 在多个多模态基准上与 GPT-4o 持平，并在 DocVQA 上以 94.5 比 88.4 击败了它。架构变更才是决定性的一步。

### Qwen2.5-VL（2025 年 2 月）—— 动态 FPS + 绝对时间

Qwen2.5-VL 的重大转变在于视频。动态 FPS 不仅仅是"在需要时采样更多帧"。其论文将其形式化为：

- **绝对时间 token。** 不使用位置索引（第 0 帧、第 1 帧、第 2 帧……），而是使用实际时间戳。"在 0:04，猫跳了起来。"模型看到的是 `<time>0.04</time>` token 与帧 token 交错排列。
- **动态 FPS。** 对缓慢的素材以 1 FPS 采样，对动作场景以 4+ FPS 采样。由用户或训练者选择；M-RoPE 自适应调整。
- **ViT 中的窗口注意力。** 空间注意力被限定在窗口内（块内局部注意力）以提高吞吐量；每若干层加入一次全局注意力。
- **显式 JSON 输出格式。** 在工具调用数据上训练："{\"tool\": \"click\", \"coords\": [380, 220]}"。开箱即用，面向智能体。
- **MRoPE-v2 缩放。** 位置随最大输入大小缩放，使得 10 分钟的视频不会超出频率范围。

基准：Qwen2.5-VL-72B 在大多数视频基准上超越 GPT-4o，在文档类任务上与 Gemini 2.0 持平，并在 GUI 定位上创下开源模型最佳水平（ScreenSpot：准确率 84%，而 GPT-4o 为 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是一次增量升级，旨在巩固而非重构：更大的 LLM 基座（Qwen3-72B）、扩充的训练数据、改进的 OCR、通过 Qwen3"思考模式"实现的更强推理能力。ViT 和 M-RoPE 保持不变。论文侧重于数据和训练方法的改进，而非架构创新。

该系列的经验总结：到 2025 年，Qwen-VL 的架构已经稳定。后续的代际升级扩展的是算力和数据，而非基本原语。

### M-RoPE 的数学原理

经典 RoPE 使用配对坐标将维度为 `d` 的 query 向量 `q` 按位置 `m` 进行旋转：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分成三个频带。设 `d = 96`，将 32 维分配给时间，32 维分配给高度，32 维分配给宽度。每个频带按其自身的轴位置进行旋转。位于 (t=5, h=10, w=20) 的 patch 会对其三个频带分别施加旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t = text_index, h = 0, w = 0`（或归一化后的选择），保持兼容性。视频帧使用 `t = frame_time, h = row, w = col`。单张图像使用 `t = 0`。

其优势在于：一种位置编码即可同时处理文本、图像和视频，无需分支代码或不同的位置表。

### 动态 FPS 采样逻辑

给定一段时长为 `T` 秒的视频和目标 token 预算 `B`：

1. 计算能承受的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选取满足 `fps <= fps_max` 的目标 FPS。
3. 如果运动幅度大（通过光流启发式方法或用户明确指定），选择更高的 FPS；如果运动幅度小，选择更低的 FPS。
4. 以所选 FPS 均匀采样，在帧之间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式地训练了这一逻辑；推理时用户通过 `fps` 参数进行控制。一个 60 秒的动作序列以 4 FPS 采样，每帧 81 个 token，总计 19440 个 token，在 32k 上下文中完全可控。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练明确针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：对模型输出执行 `JSON.parse`。相比之下，自由形式的"click at (1024, 512)"需要正则表达式并处理歧义。这一转变正是 Qwen2.5-VL 的 ScreenSpot 得分从 Qwen2-VL 的 55% 跃升至 84% 的原因。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| M-RoPE | "多模态 RoPE" | 三维旋转位置嵌入，在隐藏维度中划分时间、高度和宽度频带 |
| 动态 FPS | "智能采样" | 根据运动幅度、时长和 token 预算为每个视频选择的帧采样率 |
| 绝对时间 token | "时间戳 token" | 在序列中交错插入的 `<time>t</time>`，使模型看到实际秒数而非帧索引 |
| 窗口注意力 | "局部注意力" | 将空间自注意力限制在小窗口内以提高速度；周期性加入全局注意力 |
| 结构化智能体输出 | "JSON 模式" | 通过训练数据监督，教会 VLM 输出包含坐标和工具名称的可解析 JSON |
| min_pixels / max_pixels | "分辨率边界" | 按请求控制 Qwen2.5-VL 总像素数进而控制 token 数的参数 |
| 定位（Grounding） | "指向它" | 以文本 token 形式输出边界框坐标；自 Qwen-VL v1 起即已使用 |
