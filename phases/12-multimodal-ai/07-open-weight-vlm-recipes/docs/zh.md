# 开源权重 VLM 配方：真正重要的东西

> 2024-2026 年的开源权重 VLM 文献是一片消融实验表格的森林。Apple 的 MM1 测试了图像编码器、连接器和数据混合的 13 种组合。Allen AI 的 Molmo 证明了详细的人工标注描述优于 GPT-4V 蒸馏。Cambrian-1 进行了 20+ 种编码器对比。Idefics2 正式定义了五轴设计空间。Prismatic VLMs 在受控基准上比较了 27 种训练配方。在所有这些噪声中，有一小部分结论在论文间保持一致：图像编码器比连接器架构更重要，数据混合比两者都更重要，而详细的人工标注描述优于蒸馏合成数据。本课程解读了这些表格，让你不必亲自研读。

**类型：** 学习 + 实验
**语言：** Python（标准库，消融表格解析器 + 配方选择器）
**前置条件：** 阶段 12 · 05（LLaVA 基线）
**时长：** ≈180 分钟

## 学习目标

- 说出 VLM 的五轴设计空间：图像编码器、连接器、LLM、数据混合、分辨率调度。
- 读懂 MM1 / Idefics2 / Cambrian-1 的消融表格，并预测哪个旋钮会影响某个给定基准。
- 在给定计算预算和任务组合的情况下，为新 VLM 选择配方（编码器、连接器、数据、分辨率）。
- 解释为什么在相同 token 数量下，详细的人工标注描述优于 GPT-4V 蒸馏。

## 问题

数以百计的开源权重 VLM 已经存在。"好"与"最先进"之间的差距大多不在架构上，而在数据、分辨率调度和编码器选择上。当你的模型表现不佳时，知道先转动哪个旋钮，可以帮你避免一个价值 500 万 GPU 小时的错误。

2023 年的浪潮（LLaVA-1.5、InstructBLIP、MiniGPT-4）基于描述对预训练 + LLaVA-Instruct-150k。不错的基线。MMMU 最高约 35%。

2024 年的浪潮（MM1、Idefics2、Molmo、Cambrian-1、Prismatic VLMs）进行了详尽的消融实验。结果令人惊讶且实用。

## 核心概念

### 五轴设计空间

Idefics2（Laurençon 等人，2024）命名了这些轴：

1. **图像编码器。** CLIP ViT-L/14、SigLIP SO400m/14、DINOv2 ViT-g/14、InternViT-6B。编码器在 patch 尺寸、分辨率和预训练目标上有所不同。
2. **连接器。** MLP（2-4 层）、Q-Former（32 查询 + 交叉注意力）、Perceiver Resampler（64 查询）、C-Abstractor（卷积 + 双线性池化）。
3. **语言模型。** Llama-3 8B / 70B、Mistral 7B、Phi-3、Gemma-2、Qwen2.5。LLM 的大小是主要的参数量成本。
4. **训练数据。** 描述对（CC3M、LAION）、交错数据（OBELICS、MMC4）、指令数据（LLaVA-Instruct、ShareGPT4V、PixMo、Cauldron）。
5. **分辨率调度。** 固定 224/336/448、AnyRes、原生动态。训练期间逐步提高或保持不变。

每一个生产级 VLM 都在每个轴上做出了选择。MMMU 分数的大部分差异由轴 1、4 和 5 解释——而不是你选择了哪个连接器。

### 轴 1：编码器 > 连接器

MM1 第 3.2 节表明：从 CLIP ViT-L/14 切换到 SigLIP SO400m/14 在 MMMU 上增加了 3 个以上的百分点。将连接器从 MLP 切换到 Perceiver Resampler 增加了不到 1 个百分点。Idefics2 复现了相同的结论：SigLIP > CLIP，Q-Former ≈ MLP ≈ Perceiver（在相同 token 数量下）。

Cambrian-1 的"Cambrian 视觉编码器对决"（Tong 等人，2024）在视觉中心基准（CV-Bench）上测试了 20+ 种编码器。排行榜顶端是 DINOv2 和 SigLIP 的混合；CLIP 处于中游；ImageBind 和 ViT-MAE 排名较低。从 CLIP ViT-L 到 DINOv2 ViT-g/14 在 CV-Bench 上的差距约为 5-7 个百分点。

2026 年开源 VLM 的默认编码器是 SigLIP 2 SO400m/14（用于语义 + 密集特征），有时会与 DINOv2 ViT-g/14 的特征拼接（Cambrian 的"空间视觉聚合器"就是这样做）。

### 轴 2：连接器设计影响不大

MM1、Idefics2、Prismatic 和 MM-Interleaved 都得出了相同的结论：在固定视觉 token 数量下，连接器架构几乎无关紧要。在相同的 token 预算下，对均值池化 patch 使用 2 层 MLP 的性能与使用 32 查询 Q-Former 的差距在 1 个百分点以内。

真正重要的是 token 数量。更多的视觉 token = 更多的 LLM 计算 = 更好的性能（达到某个点后边际收益递减）。每张图像 64 个 token 对 OCR 来说太少。576-1024 个 token 是大多数开源 VLM 的最佳区间。2048+ 个 token 仅对文档和图表有帮助。

Q-Former 与 MLP 之争是成本问题而非质量问题：Q-Former 不论图像分辨率如何，都将 token 数限制在 32-64；而 MLP 会输出所有 patch 的 token。对于高分辨率输入，Q-Former 节省了 LLM 上下文；对于低分辨率输入，差异只是噪声。

### 轴 3：LLM 大小决定天花板

将 LLM 从 7B 翻倍到 13B，在每篇 VLM 论文的 MMMU 上都稳定增加 2-4 个百分点。到 70B 时，大多数基准趋于饱和。VLM 的多模态推理天花板就是 LLM 的文本推理天花板——视觉编码器只能为它提供输入，而不能替它推理。

这就是为什么 Qwen2.5-VL-72B 和 Claude Opus 4.7 能碾压 MMMU-Pro 和 ScreenSpot-Pro：语言大脑足够大。一个 7B 的 VLM 无法通过巧妙设计连接器来替代一个 70B 的 VLM。

### 轴 4：数据——详细的人工标注描述优于蒸馏

Molmo + PixMo（Deitke 等人，2024）是 2024 年每个人都应该读的结果。Allen AI 让标注人员用 1-3 分钟的密集语音转文字描述来描述图像，获得了 712K 张密集标注的图像。训练数据中完全没有 GPT-4V 蒸馏。

Molmo-72B 在 11/11 个基准上击败了 Llama-3.2-90B-Vision。差异不在架构——而在描述质量。详细的人工标注描述每张图像包含的信息量是简短网络描述的 5-10 倍，并且在事实准确性上优于 GPT-4V 蒸馏（后者会产生幻觉）。

ShareGPT4V（Chen 等人，2023）和 Cauldron（Idefics2）遵循了相同的策略，使用了人工 + GPT-4V 描述的混合。趋势很明确：对于 2026 年的前沿模型，描述密度 > 描述数量 > 蒸馏便利性。

### 轴 5：分辨率及其调度

Idefics2 的消融实验：384 -> 448 增加 1-2 个百分点。448 -> 980 带图像分割（AnyRes）在 OCR 基准上再增加 3-5 个百分点。固定分辨率训练在中精度水平趋于平台期；分辨率逐步提升（从 224 开始，在 448 或原生分辨率结束）训练更快且最终精度更高。

Cambrian-1 进行了分辨率与 token 的权衡实验：在固定计算量下，你可以选择低分辨率下更多 token，或高分辨率下更少 token。高分辨率对 OCR 更优；低分辨率多 token 对通用场景理解更优。

2026 年的生产配方：第一阶段在 384 固定分辨率下训练，第二阶段使用动态分辨率（最高 1280）处理 OCR 密集型任务。

### Prismatic 的受控对比

Prismatic VLMs（Karamcheti 等人，2024）是一篇控制了所有轴的论文。相同的 13B LLM、相同的指令数据、相同的评估——每次只变化一个轴。结果如下：

- 每张图像的视觉 token 数量解释了约 60% 的方差。
- 编码器选择解释了约 20%。
- 连接器架构解释了约 5%。
- 其他所有因素（数据混合、调度器、学习率）解释了剩下的约 15%。

这是一个粗略的分解，但它是文献中关于"我应该先消融什么"这个问题最清晰的答案。

### 2026 年的选择指南

基于已有证据，2026 年新项目的默认开源 VLM 配方：

- **编码器：** SigLIP 2 SO400m/14，原生分辨率配合 NaFlex，如果需要分割/接地能力，则与 DINOv2 ViT-g/14 的密集特征拼接。
- **连接器：** 在 patch token 上使用 2 层 MLP。除非 token 受限，否则跳过 Q-Former。
- **LLM：** Qwen2.5 / Llama-3.1 / Gemma 2，追求成本用 7B，追求质量用 70B，根据目标延迟选择。
- **数据：** PixMo + ShareGPT4V + Cauldron，辅以任务特定的指令数据。
- **分辨率：** 动态（长边最小 256，最大 1280 像素）。
- **调度：** 第一阶段对齐（仅投影器），第二阶段全参数微调，第三阶段任务特定微调。

以上每一个默认选择都可以追溯到本课程末尾引用的论文中的实测消融实验。

## 动手实践

`code/main.py` 是一个消融表格解析器和配方选择器。它编码了 MM1 和 Idefics2 的消融表格（精简版），让你可以查询：

- "给定预算 X 和任务 Y，哪种配方最优？"
- "如果我在 7B Llama 上把 SigLIP 换成 CLIP，MMMU 的预期变化是多少？"
- "要获得 80% 置信度的答案，我应该先消融哪个轴？"

输出是一个排序后的配方列表，包含预期的基准变化 delta 以及"优先消融"建议。

## 交付物

本课程产出 `outputs/skill-vlm-recipe-picker.md`。给定目标任务组合、计算预算和延迟目标，它会输出一份完整配方（编码器、连接器、LLM、数据混合、分辨率调度），并附上支持每个选择的消融实验引用。避免工程师在每个新 VLM 项目开始时重复 Idefics2 的消融表格。

## 练习

1. 阅读 MM1 第 3.2 节。给定 50M 图像的预算和固定的 2B LLM，哪种编码器最优？如果换成 13B LLM，答案会改变吗？为什么？

2. Cambrian-1 发现，拼接 DINOv2 + SigLIP 在视觉中心基准上优于两者单独使用，但在 MMMU 上没有增加信号。预测哪些基准会提升，哪些保持不变。

3. 你的目标是在 2B LLM 上运行一个移动端 UI 智能体。选择编码器、连接器、分辨率和数据混合。用具体的消融表格证明每个选择的合理性。

4. Molmo 发布了 4B 和 72B 模型。4B 版本与闭源 7B VLM 竞争力相当；72B 版本在 11/11 个基准上击败了 Llama-3.2-90B-Vision。这揭示了 LLM 大小平台期假说的什么问题？

5. 设计一个消融表格，在 7B VLM 上分离数据混合质量与编码器质量的影响。最少需要多少次训练运行？提出四个轴的设置方案。

## 关键术语

| 术语 | 人们常说的意思 | 实际含义 |
|------|----------------|----------|
| 消融 (Ablation) | "转动一个旋钮" | 进行多次训练，每次仅在设计空间的一个轴上改变，其他所有条件保持不变 |
| 连接器 (Connector) | "桥接" / "投影器" | 将视觉编码器输出映射到 LLM token 空间的可训练模块（MLP、Q-Former、Perceiver） |
| 详细人工标注描述 (Detailed human caption) | "密集描述" | 多句人工编写的描述（通常 80-300 个 token），比网络替代文本更丰富 |
| 蒸馏 (Distillation) | "GPT-4V 描述" | 由更强的闭源 VLM 生成的训练数据；方便但容易继承幻觉 |
| AnyRes / 动态分辨率 (Dynamic res) | "高分辨率路径" | 通过分块或 M-RoPE 策略输入大于编码器原生分辨率的图像 |
| 分辨率逐步提升 (Resolution ramp) | "课程学习" | 从低分辨率开始并逐步提高的训练调度，加速对齐学习 |
| 视觉中心基准 (Vision-centric bench) | "CV-Bench / BLINK" | 侧重于细粒度视觉感知而非语言密集型推理的评估 |
| PixMo | "Molmo 的数据" | Allen AI 的 712K 张密集标注图像数据集；人工语音转录为密集描述 |
