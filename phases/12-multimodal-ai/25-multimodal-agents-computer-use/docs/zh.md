# 多模态智能体与计算机操控（顶点项目）

> 2026年的前沿产品是一个多模态智能体，它能够读取屏幕截图、点击按钮、导航网页UI、填写表单，并端到端完成工作流程。SeeClick 和 CogAgent（2024）证明了GUI定位基础能力。Ferret-UI 增加了移动端支持。ChartAgent 引入了图表方面的视觉工具使用。VisualWebArena 和 AgentVista（2026）是前沿模型追赶的基准——即使是 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的困难任务上也仅得 ~30%。本顶点项目汇集了第12阶段的所有线索：感知（高分辨率VLM）、推理（带工具使用的LLM）、定位（坐标输出）、长程记忆和评估。

**类型：** 顶点项目
**语言：** Python（stdlib，动作模式 + 智能体循环框架）
**前置要求：** 第12阶段·05（LLaVA），第12阶段·09（Qwen-VL JSON），第14阶段（智能体工程）
**时间：** ~240分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建一个VLM能够以JSON形式输出的GUI定位输出模式（点击坐标、输入文本、滚动、拖拽）。
- 比较纯截图智能体、无障碍树智能体与混合智能体。
- 在小型 VisualWebArena 子集上设置多模态智能体基准评估。

## 问题

一个预订网站工作流："帮我找一张4月15日去东京的航班，靠过道座位，预算低于800美元，完成预订。"

多模态智能体需要：

1. 截取浏览器截图。
2. 将截图 + URL + 目标解析为计划。
3. 输出结构化动作：点击（在x,y处）、输入"Tokyo"（在元素E处）、向下滚动、选择（单选按钮）。
4. 将动作应用于浏览器。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一次多模态VLM调用。VLM输出必须是可解析的JSON。错误会跨步骤累积，因此恢复能力至关重要。

## 核心概念

### GUI定位——基础能力

GUI定位是指：给定一张截图和一条自然语言指令，输出要点击的（x, y）坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是首个大规模开放成果：在合成+真实GUI数据上微调VLM，以纯文本标记形式输出坐标。有效。

CogAgent（arXiv:2312.08914）增加了1120x1120高分辨率编码以支持密集UI。得分：网页导航约84%。

Ferret-UI（arXiv:2404.05719）专注于移动端UI，集成了iOS无障碍数据。

输出格式通常为JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "搜索按钮"}
```

`element_desc` 有助于恢复：如果坐标在截图之间发生偏移，语义提示可让系统重新定位。

### 动作模式

典型的动作模式包含6-10种动作类型：

- `click`（点击）：(x, y)
- `type`（输入）：(text, x?, y?)
- `scroll`（滚动）：(direction, amount)
- `drag`（拖拽）：(x0, y0, x1, y1)
- `select`（选择）：(option_index)
- `hover`（悬停）：(x, y)
- `navigate`（导航）：(url)
- `wait`（等待）：(ms)
- `done`（完成）：(success, explanation)

智能体每一步输出一个动作。浏览器封装器执行该动作并返回新状态。

### 纯截图 vs 无障碍树

两种输入模式：

- **纯截图**：完整图像，无结构信息。通用性最强，适用于任何应用。
- **无障碍树**：结构化DOM / iOS无障碍信息。定位更可靠，适用于树可用的场景。
- **混合模式**：两者并用，以树作为原子操作的可靠定位器，以截图提供语义上下文。

生产级智能体在可能的情况下使用混合模式。浏览器自动化（Selenium + 无障碍）始终拥有树；桌面应用有时具备。

### 长程记忆

一个20步的工作流会产生20张截图。VLM的上下文会迅速填满。三种压缩策略：

- **摘要链**：每5步后总结已发生内容，丢弃旧截图。
- **跳帧**：保留第一张、最后一张和每第三张截图。
- **工具记录日志**：执行动作，记录文本日志描述已完成的操作；不重新查看旧截图。

Claude的计算机操控API使用日志模式。更简单，更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）引入了面向图表理解的视觉工具使用：裁剪、缩放、OCR、调用外部检测。智能体可以输出"裁剪到区域（100, 200, 300, 400）然后调用OCR"作为工具调用。工具返回文本；VLM继续推理。

这种模式具有通用性：标记提示、区域标注和外部检测工具都适用于相同的"输出工具调用，接收结构化响应"模式。

### 2026年的基准测试

- **ScreenSpot-Pro**：约1k张网页截图上的GUI定位。开源SOTA Qwen2.5-VL-72B ~85%。前沿模型 ~90%。
- **VisualWebArena**：端到端网页任务（购物、论坛、分类信息）。开源SOTA ~20%。Gemini 3 Pro ~27%。
- **AgentVista**（arXiv:2602.23166）：最难的2026基准测试。跨12个领域的真实工作流。前沿模型得分27-40%；开源模型10-20%。
- **WebArena / WebShop**：较旧的基准测试；已被前沿模型饱和。

### 为何仍然困难

智能体性能瓶颈：

1. **精细尺度的视觉定位**："点击那个小×"在移动端分辨率下经常失败。
2. **长程规划**：10步之后，智能体开始偏离目标。
3. **错误恢复**：当点击失败（点错按钮）时，检测并恢复的训练数据很少。
4. **跨页面上下文**：在标签页之间跳转或处理长表单时丢失状态。

研究方向：记忆架构、显式重新规划、多模态验证（动作成功的截图匹配）。

### 顶点项目构建任务

顶点项目任务：构建一个计算机操控智能体，它能够：

1. 读取预订网站模拟页面的HTML + 截图。
2. 规划多步序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出符合动作模式的JSON动作。
4. 在固定10任务子集上评估。

课程提供脚手架代码，便于扩展到真实浏览器。

## 如何使用

`code/main.py` 是顶点项目脚手架：

- 动作模式JSON定义（10种动作）。
- 将模拟浏览器状态作为字典。
- 智能体循环框架：接收状态，输出动作，执行，循环。
- 10任务迷你基准测试（合成页面）以衡量端到端成功率。
- 动作失败时的错误恢复钩子。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------|----------|
| GUI定位 | "点击坐标" | 模型为截图上的指令目标输出(x,y)坐标 |
| 动作模式 | "工具定义" | 有效动作（点击、输入、滚动、拖拽）的JSON描述 |
| 无障碍树 | "结构化DOM" | 来自浏览器/iOS API的机器可读UI层级结构 |
| 混合智能体 | "截图+树" | 同时使用图像和结构化信息，比单独使用任一方式更可靠 |
| 视觉工具使用 | "缩放/裁剪/检测" | 智能体在规划过程中调用外部视觉工具（OCR、检测） |
| 摘要链 | "记忆压缩" | 定期用文本摘要替代长截图历史 |
| VisualWebArena | "端到端网页基准" | 2024年端到端网页任务基准 |
| AgentVista | "2026高难度基准" | 12领域真实工作流；即使Gemini 3 Pro也仅得~30% |
