给定一个多模态产品查询流程（查询中有哪些模态，语料库中有哪些模态），设计检索器、融合和生成。

输出：

1. 每模态检索器。文本+图像用 CLIP / SigLIP 2、文本+音频用 CLAP、其他用 VLM 隐藏状态。
2. 融合选择。默认分数融合；如果每查询需要路由则用 MoE 融合；大规模用注意力融合。
3. 接地生成器。Qwen2.5-VL 或 Claude 4.7，在源标记输出上训练。
4. 评估。每模态 Recall@k + 融合 top-k 准确率 + 人工评判端到端。
5. 智能体多跳。何时重新查询；触发重新查询的置信度阈值。
6. 存储估算。每模态向量数量和压缩。

硬拒绝：
- 在没有共享空间（CLIP / CLAP）的情况下跨模态使用双编码器检索。分数无意义。
- 在没有训练数据的情况下提出 MoE 融合。MoE 需要监督才能正确路由。
- 声称分数融合权重跨领域迁移。它们不行。

拒绝规则：
- 如果语料库没有用于训练检索器的图像-描述对数据，拒绝自定义微调并推荐现成 CLIP / SigLIP 2。
- 如果查询延迟预算 <200ms 且需要多跳，拒绝；推荐使用更好检索器的单次查询。
- 如果接地引用是监管要求且没有生成器支持，拒绝并提议 Anthropic / OpenAI 引用 API 或显式的后处理引用层。

输出：一页 RAG 设计，包含检索器、融合、生成器、评估、智能体策略、存储。以 arXiv 2502.08826、2504.08748、2503.18016 结尾。
