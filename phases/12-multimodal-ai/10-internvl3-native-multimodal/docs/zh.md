# InternVL3：原生多模态预训练

> InternVL3 之前的所有开源 VLM 都遵循相同的三步配方：拿一个经过数万亿文本 token 训练的文本 LLM，在其上螺栓固定一个视觉编码器，然后微调连接处。这种方法有效，但存在对齐债务——文本 LLM 将其全部预训练预算都花在了纯文本上，天生不理解视觉 token。当你事后添加视觉能力时，LLM 必须在不忘却文本能力的前提下重新学习如何将视觉输入与文本推理关联起来。InternVL3（Zhu 等人，2025 年 4 月）拒绝了这种事后修补的方式：一次预训练，从第一步开始就将文本和多模态交错进行。结果是 78B 参数的开源模型在 MMMU-Pro 上匹敌 Gemini 2.5 Pro。本课解读原生预训练的合理性以及做出这一改变后带来的变化。

**类型：** 学习
**语言：** Python（标准库，训练语料混合器）
**前置知识：** 阶段 12·05，阶段 12·07（配方）
**时间：** ~120 分钟

## 学习目标

- 解释事后 VLM 训练为何积累对齐债务，列举三种可测量的症状（灾难性遗忘、答案漂移、视觉-文本不一致）。
- 描述 InternVL3 的原生预训练语料混合比例，以及文本：交错：图文配对的比例为何重要。
- 比较 V2PE（可变视觉位置编码）与 Qwen2-VL 的 M-RoPE。
- 说出 Visual Resolution Router（ViR）和 Decoupled Vision-Language（DvD）部署优化方法。

## 问题所在

事后 VLM 训练是默认做法。LLaVA、BLIP-2、Qwen-VL、Idefics——所有这些模型都拿一个已经预训练好的 LLM（Llama、Vicuna、Qwen、Mistral）并添加视觉能力。训练阶段通常如下所示：

1. 冻结 LLM + 冻结视觉编码器 + 可训练投影器，在图文配对数据上训练以对齐嵌入。
2. 解冻 LLM，在指令数据（LLaVA-Instruct、ShareGPT4V）上训练。
3. 可选的特定任务微调。

对齐债务表现出三种症状：

- **灾难性遗忘。** 事后 VLM 忘记了纯文本技能。GSM8K 分数下降 5-10 分。HellaSwag 分数下降。纯文本智能体出现性能倒退。
- **答案漂移。** 同一视觉问题因措辞细微不同而得到不同答案。视觉编码器与 LLM 之间的连接比 LLM 自身的 token 连接更弱。
- **视觉-文本不一致。** VLM 能正确描述图像，然后回答一个与其自身描述相矛盾的问题。视觉 token 无法像文本 token 那样参与 LLM 的内部一致性检查。

这些症状有充分的文献记录。MM1.5 第 4 节对其进行了量化。LLaVA-OneVision 的消融实验也暗示了它们的存在。原生预训练就是答案。

## 核心概念

### 原生多模态预训练

InternVL3 从零开始在一个从第一步起就是原生多模态的语料上训练。混合比例为：

- 40% 纯文本数据（FineWeb、Proof-Pile-2 等）
- 35% 交错图文数据（OBELICS、MMC4 风格）
- 20% 配对图文数据
- 5% 视频-文本数据

视觉 token、文本 token 和跨模态交互从第一个梯度步骤开始就参与相同的损失函数。无需对齐预训练，无需投影器冻结阶段，无需从灾难性遗忘中恢复。

基座模型的训练是单阶段的。随后是指令微调，但基座模型已经将视觉 token 视为一等公民。

### V2PE（可变视觉位置编码）

Qwen2-VL 使用具有固定轴分配的 M-RoPE。InternVL3 引入了 V2PE：位置编码根据模态类型（文本、图像、视频）变化，采用可学习的缩放。实际中：

- 文本 token 获得 1D 位置（文本索引）。
- 图像块获得 2D 位置（行、列）。
- 视频帧获得 3D 位置（时间、行、列）。

三者共享相同的 RoPE 频率基，但每个频带的隐藏维度分配是学习得到的参数，而非固定的分割。可以在预训练期间自由权衡时间频率与空间频率的分辨率。

V2PE 的消融实验声称：在相同计算量下，比 M-RoPE 在视频基准上高出 1-2 个点。算不上革命，但更简洁。

### Visual Resolution Router（ViR）

部署优化。并非所有图像都需要全分辨率编码。一张只有一个物体的低细节照片，以 1280px 原生分辨率编码会浪费 token。ViR 是一个小型分类器，在编码之前预测回答问题所需的最低分辨率。

路由分为三个等级：低分辨率（256 token）、中分辨率（576）、高分辨率（2048+）。在生产流量中，60% 的查询只需要低或中分辨率。净效果：在同等质量下吞吐量提升 2-3 倍。

### Decoupled Vision-Language 部署（DvD）

当服务一个大 VLM 时，视觉编码器每张图像运行一次，但 LLM 为每个输出 token 自回归运行。两个组件有不同的瓶颈（视觉 = 卷积 + 注意力机制的 GPU 显存带宽；LLM = KV 缓存）。DvD 将它们拆分到不同的 GPU 上，之间通过流式传输连接。

对于一个 8B + 400M 编码器模型，DvD 的每节点吞吐量大约是共置部署的两倍。

### 单阶段与多阶段质量

InternVL3 的主要基准声称：78B 参数，在 MMMU-Pro 上匹敌 Gemini 2.5 Pro。38B 参数，匹敌 GPT-4o。8B 参数，领跑开源 8B 排行榜。所有这些都是基于单阶段预训练 + 指令微调配方。

对齐债务假说是可测量的：InternVL3-8B 每单位视觉基准增益所损失的文本基准分数（MMLU、GSM8K）少于 Qwen2.5-VL-7B。该模型更像通才，因为训练是一体的，而不是分两步的。

### InternVL3.5 与 InternVL-U

InternVL3.5（2025 年 8 月）扩展了该配方。相同的原生预训练方法，更多数据，更多参数。MMMU 的改进是增量式的。

InternVL-U（2026 年）增加了统一生成——在同一个骨干网络上通过 MMDiT 头部实现图像输出。"U"代表"理解+生成"，追寻 Transfusion 风格的统一模型（第 12.13 课）。同一个原生预训练骨干网络同时支持理解和生成头部。

### 原生预训练的权衡

原生预训练并非没有代价：

- **计算成本。** 从头训练一个新的 VLM 的成本与训练一个文本 LLM 相同——数百万 GPU 小时。事后适配复用了现有的 LLM 权重，节省了大部分成本。
- **数据。** 大规模的交错图文语料很稀缺。OBELICS 有 1.41 亿文档；MMC4 有 5.71 亿。纯文本数据则有 15 万亿 token。多模态预训练数据的稀缺是一个硬约束。
- **基座 LLM 复用。** 原生预训练放弃了后续替换新 LLM 的可能性。事后方法只需重新训练适配器即可将 Llama-3.1 换成 Llama-4。

InternVL3 押注的是：对齐债务比复用损失更严重。基准测试支持这一主张。生产成本阻止了未来实验室廉价复制。事后 VLM 将继续存在，因为对大多数项目来说它们仍然更便宜。

## 使用它

`code/main.py` 是一个训练语料混合器和 ViR 路由器模拟器。它能：

- 接收目标语料混合比例（%文本、%交错、%图文配对、%视频）并计算每种模态的期望步数。
- 在一批查询上模拟 ViR 路由（分布：50% 低细节、30% 中细节、20% 高细节）并报告平均 token 数。
- 根据编码器与 LLM 的 FLOPs 报告 DvD 吞吐量估计。
- 并排展示事后与原生预训练在参数、计算量、数据和预期对齐债务症状方面的对比。

本课产出 `outputs/skill-native-vs-posthoc-auditor.md`。给定一个拟议的 VLM 训练计划，它会审计应该采用原生还是事后方法，标记对齐债务风险，并推荐语料混合比例。在你评估一个新的开源 VLM 项目并需要选择训练策略时使用它。

## 练习

1. 估算 InternVL3-8B（原生预训练）与 LLaVA-OneVision-7B（事后）之间的计算量差值。GPU 小时数比例大致是多少？差距的原因是什么？

2. InternVL3 报告了 40% 文本 / 35% 交错 / 20% 图文配对 / 5% 视频。如果你的目标任务以视频为主，提出一个新的比例，并论证为什么基座模型仍然需要大量的文本和图文配对数据。

3. 阅读 MM1.5 第 4 节关于遗忘的内容。说出事后训练表现出最大退化的确切基准。退化程度有多大？

4. ViR 将 60% 的流量路由到低分辨率编码。哪些类型的查询会被它错误路由（在需要高分辨率时发送到低分辨率）？提出三种路由器失效模式。

5. DvD 将视觉和 LLM 拆分到不同的 GPU 上。在哪种流量模式下 DvD 反而会损害吞吐量而不是提升？

## 关键术语

| 术语 | 表面意思 | 实际含义 |
|------|---------|---------|
| 原生多模态预训练 | "从零开始一起训练" | 文本 + 图像 + 视频 token 从第一步起参与损失函数，而非事后螺栓固定 |
| 对齐债务 | "事后惩罚" | 因将视觉螺栓固定到冻结 LLM 上而导致的文本技能和答案一致性的可测量退化 |
| V2PE | "可变视觉位置编码" | 每种模态可学习的位置编码分配；InternVL3 对 M-RoPE 的继任方案 |
| ViR | "分辨率路由器" | 在编码之前为每个查询选择所需最低分辨率的小型分类器，节省推理 token |
| DvD | "解耦部署" | 视觉编码器在一张 GPU 上，LLM 在另一张上，通过流式传输交接；对大型 VLM 吞吐量翻倍 |
| InternVL-U | "统一理解+生成" | 2026 年的后续工作，在原生预训练骨干网络上添加图像生成头部 |
| 交错语料 | "OBELICS / MMC4" | 包含文本和图像、按自然阅读顺序排列的文档；原生预训练的原材料 |
