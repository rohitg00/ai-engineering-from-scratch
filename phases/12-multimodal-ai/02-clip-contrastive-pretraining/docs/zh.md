# CLIP 与对比式视觉-语言预训练

> OpenAI 的 CLIP（2021）证明了一个足以驱动未来五年的核心理念：仅使用嘈杂的网络图像-文本配对数据和对比损失函数，在同一个向量空间中对齐图像编码器和文本编码器。零监督标签。4 亿对数据。由此产生的嵌入空间能够进行零样本分类、图像-文本检索，并且作为视觉骨干接入每一个 2026 年的 VLM。SigLIP 2（2025）用 sigmoid 替代了 softmax，以更低的成本超越了 CLIP。本课程从 InfoNCE 讲到 sigmoid 逐对损失，并用标准库 Python 构建训练步骤。

**类型：** 构建
**语言：** Python（标准库，InfoNCE + sigmoid 损失实现）
**前置知识：** 阶段 12 · 01（ViT 分块），阶段 7（Transformer）
**时间：** 约 180 分钟

## 学习目标

- 从互信息推导 InfoNCE 损失，并实现数值稳定的向量化版本。
- 解释为什么 sigmoid 逐对损失（SigLIP）可以扩展到 32768+ 的批量大小，而无需 softmax 所需的 all-gather 通信开销。
- 通过构建文本模板（`a photo of a {class}`）并取余弦相似度的 argmax，运行零样本 ImageNet 分类。
- 说出 CLIP / SigLIP 预训练提供的四个杠杆：批量大小、温度、提示模板、数据质量。

## 问题背景

在 CLIP 之前，视觉领域是监督学习的天下。收集带标签的数据集（ImageNet：120 万张图片，1000 个类别），训练 CNN，然后发布。标签成本高昂，标签偏向于标注者能达成一致的内容，而且标签无法迁移到新任务——除非微调。

互联网上的图像-文本描述数据提供了超过十亿对宽松标注的数据，而且分文不取。一张金毛犬的照片，配以替代文本"我的狗 Max 在公园里"，本身就携带监督信号——文本描述了图像。问题是：你能把它变成有用的训练数据吗？

CLIP 的答案是：将图像-文本配对视为一个匹配任务。给定一个包含 N 张图片和 N 个描述的批次，学习将每张图片与其对应的描述匹配起来，对抗 N-1 个干扰项。监督信号就是"这两个属于一起；那 N-1 个不属于。"没有类别标签。没有人工标注。只有一个对比损失。

由此产生的嵌入空间能做的事情远超过 CLIP 训练时的目标。ImageNet 零样本分类之所以可行，是因为"一只猫的照片"嵌入到了从未被明确标注为"猫"的猫图片附近。这就是催生了所有 2026 年 VLM 的那场赌注。

## 核心概念

### 双编码器

CLIP 有两个塔：

- 图像编码器 `f`：ViT 或 ResNet，每张图像输出一个 D 维向量。
- 文本编码器 `g`：小型 Transformer，每个描述输出一个 D 维向量。

两个塔都将输出归一化为单位长度。相似度是 `cos(f(x), g(y)) = f(x)^T g(y)`，因为二者都是单位范数。

对于包含 N 对（图像，描述）的批次，构建形状为 `(N, N)` 的相似度矩阵 `S`：

```
S[i, j] = cos(f(x_i), g(y_j)) / tau
```

其中 `tau` 是一个可学习的温度参数（CLIP 初始化为 0.07；在对数空间中学习）。

### InfoNCE 损失

CLIP 使用对称的交叉熵，分别在行和列上计算：

```
loss_i2t = CE(S, labels=identity)     # 每张图像的正样本是其对应的描述
loss_t2i = CE(S^T, labels=identity)   # 每个描述的正样本是其对应的图像
loss = (loss_i2t + loss_t2i) / 2
```

这就是 InfoNCE。CE 中的 softmax 迫使每张图像与其描述匹配的程度超过批次中所有其他描述。负样本就是批次中所有其他项目。批次越大 = 负样本越多 = 信号越强。CLIP 以 32k 的批量大小进行训练；规模至关重要。

### 温度

`tau` 控制 softmax 的尖锐程度。温度低 → 分布尖锐，具有难负样本挖掘效果。温度高 → 分布平滑，所有样本都有贡献。CLIP 学习 `log(1/tau)`，并做裁剪以防止崩溃。SigLIP 2 固定了初始 tau，并使用可学习的偏置来代替。

### 为什么 sigmoid 扩展性更好（SigLIP）

Softmax 需要整个相似度矩阵保持同步。在分布式训练中，你必须将每个嵌入 all-gather 到所有副本，然后计算 softmax。这在通信上是世界大小（world size）的二次方复杂度。

SigLIP 用逐元素 sigmoid 替代了 softmax：对于每一对 `(i, j)`，损失是"这两个是匹配对吗？"的二分类问题。正类标签位于对角线，其余都是负类。损失为：

```
L = -1/N sum over (i, j) [ y_ij log sigmoid(S[i,j]) + (1-y_ij) log sigmoid(-S[i,j]) ]
```

`y_ij = 1` 当 `i == j`，否则为 0。每一对的损失是独立的。不需要 all-gather。每个 GPU 计算自己的局部块并求和。SigLIP 2 可以低成本地扩展到 32k–512k 的批量大小，而 CLIP 需要成比例地增加通信量。

### 零样本分类

给定 N 个类别名称，为每个类别构建文本模板：

```
"a photo of a {class}"
```

用文本编码器嵌入每个模板。用图像编码器嵌入你的图像。余弦相似度的 argmax = 预测类别。不需要在目标类别上进行训练。

提示模板很重要。CLIP 原论文对每个类别使用了 80 个模板（普通、艺术、照片、绘画等）并平均了嵌入结果。ImageNet 提高了 3 个点。现代用法通常只选择一个或两个模板。

### 线性探测与微调

零样本是一个基线。线性探测（在冻结的 CLIP 特征之上为你的目标类别训练一个线性层）在领域内任务上优于零样本。全参数微调在领域内优于线性探测，但可能损害零样本迁移能力。三种模式，三种权衡。

### SigLIP 2：NaFlex 与密集特征

SigLIP 2（2025）新增：

- NaFlex：单一模型处理可变的长宽比和分辨率。
- 更好的密集特征，用于分割和深度估计，目标是在 VLM 中作为冻结的骨干网络使用。
- 多语言：在 100 多种语言上训练，而 CLIP 仅支持英语。
- 10 亿参数规模，而 CLIP 的上限是 4 亿。

在 2026 年的开源 VLM 中，SigLIP 2 SO400m/14 是默认的视觉骨干。CLIP 仍然是纯图像-文本检索的默认选择，特别是当 LAION-2B 训练分布与你的查询模式匹配时。

### ALIGN、BASIC、OpenCLIP、EVA-CLIP

ALIGN（Google，2021）：与 CLIP 相同的思路，18 亿对规模，90% 为噪声数据。证明了噪声数据可以规模化。OpenCLIP（LAION）：在 LAION-400M / 2B 上对 CLIP 的开源复现，多种规模，是首选的开源检查点。EVA-CLIP：从掩码图像建模初始化；是 VLM 的强大骨干。BASIC：Google 的 CLIP+ALIGN 混合体。都属于同一家族，只是数据和调优不同。

### 零样本的天花板

CLIP 类模型在 ImageNet 零样本上大约止步于 76% 准确率（CLIP-G、OpenCLIP-G）。要超越这一水平，需要更大的数据量（SigLIP 2 达到 80%+）或架构上的改变（监督头、更多参数）。该基准正在趋于饱和；真正的价值在于下游 VLM 所使用的嵌入空间。

## 关键术语

| 术语 | 通常说法 | 实际含义 |
|------|----------|----------|
| InfoNCE | 对比损失 | 批次相似度矩阵上的交叉熵；每个项目的正样本是其配对项，负样本是其他所有项 |
| Sigmoid 损失 | SigLIP 损失 | 逐对的二分类交叉熵；无 softmax，无 all-gather，在分布式训练中成本低廉 |
| 温度 | tau | 在 softmax/sigmoid 之前缩放 logits 的标量；控制分布的尖锐程度 |
| 零样本 | 无微调分类 | 使用文本提示构建类别嵌入，通过余弦相似度进行分类；不在目标类别上训练 |
| 提示模板 | a photo of a ... | 围绕类别名称的文本脚手架；影响零样本准确率 1–5 个点 |
| 双编码器 | 双塔 | 一个图像编码器 + 一个文本编码器，输出在共享的 D 维空间中 |
| 难负样本 | 困难的干扰项 | 与正样本足够相似，以至于模型需要努力才能将其区分的负样本 |
| 线性探测 | 冻结 + 一层 | 仅在冻结特征之上训练一个线性分类器；衡量特征质量 |
| NaFlex | 原生灵活分辨率 | SigLIP 2 的能力，可在不调整大小的情况下处理任意长宽比和分辨率的图像 |
| 温度缩放 | 对数参数化的 tau | CLIP 对 `log(1/tau)` 进行参数化，使梯度行为稳定；进行裁剪以防止 tau 趋近于零而崩溃 |
