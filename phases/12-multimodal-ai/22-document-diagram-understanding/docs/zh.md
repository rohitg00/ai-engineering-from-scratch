# 文档与图表理解

> 文档不是照片。PDF、科学论文、发票或手写表单具有布局、表格、图表、脚注、页眉和语义结构，这些是纯图像理解无法捕捉的。前 VLM 时代的架构是一条流水线：Tesseract OCR + LayoutLMv3 + 表格提取启发式规则。VLM 浪潮则用无 OCR 模型替代了这一切——Donut（2022）、Nougat（2023）、DocLLM（2023）——这些模型直接输出结构化标记。到 2026 年，前沿方案不过是"将页面图像以 2576px 原生分辨率输入 Claude Opus 4.7"，结构化标记输出便自然产生。本节课将解读文档 AI 的三个时代演进。

**类型：** 构建
**语言：** Python（标准库，布局感知的文档解析器骨架）
**前置知识：** 阶段 12 · 05（LLaVA）、阶段 5（NLP）
**时间：** 约 180 分钟

## 学习目标

- 解释文档 AI 的三个时代：OCR 流水线、无 OCR、VLM 原生。
- 描述 LayoutLMv3 的三个输入流：文本、布局（边界框）、图像块，以及统一掩码机制。
- 比较 Donut（无 OCR，图像→标记）、Nougat（科学论文→LaTeX）、DocLLM（布局感知生成式）、PaliGemma 2（VLM 原生）。
- 为新任务（发票、科学论文、手写表单、中文收据）选择合适的文档模型。

## 问题

"理解这份 PDF" 比想象中困难得多。信息分布在：

- 文本内容（90% 的信号）。
- 布局（页眉、脚注、侧边栏、双栏格式）。
- 表格（行、列、合并单元格）。
- 图形和图表。
- 手写批注。
- 字体和排版（标题与正文）。

原始 OCR 提取了文本却丢失了其他一切。一个需要处理发票的系统必须知道"总计：￥1,245"来自右下角，而不是脚注。

## 概念

### 时代 1 — OCR 流水线（2021 年前）

经典架构：

1. PDF → 每页图像。
2. Tesseract（或商业 OCR）提取文本及每个词的边界框。
3. 布局分析器识别区块（页眉、表格、段落）。
4. 表格结构识别器解析表格。
5. 领域规则 + 正则表达式提取字段。

适用于清晰的印刷文本。在手写、倾斜扫描件、复杂表格、非英文脚本上表现不佳。每种失败模式都需要自定义异常处理路径。

### TrOCR（2021）

TrOCR（Li 等，arXiv:2109.10282）用基于合成+真实文本图像训练的 Transformer 编码器-解码器取代了 Tesseract 的经典 CNN-CTC。在手写和多语言文本上取得了显著提升。但仍是一个流水线（检测器 → TrOCR → 布局），不过 OCR 步骤得到了巨大改善。

### 时代 2 — 无 OCR（2022-2023）

最早的无 OCR 模型主张：完全跳过检测，直接将图像像素映射为结构化输出。

Donut（Kim 等，arXiv:2111.15664）：
- 编码器-解码器 Transformer，编码器为 Swin-B。
- 输出：表单理解为 JSON，摘要为 Markdown，或任意特定任务的模式。
- 无需 OCR、无需布局、无需检测。

Nougat（Blecher 等，arXiv:2308.13418）：
- 专门针对科学论文训练。
- 输出为 LaTeX / Markdown。
- 能处理公式、多栏布局、图形。
- 每个 arXiv 解析器都在调用的模型。

这些是专才，而非通才。Donut 处理科学论文会失败；Nougat 处理发票会失败。

### LayoutLMv3（2022）

另一条技术路线。LayoutLMv3（Huang 等，arXiv:2204.08387）保留了 OCR 但增加了布局理解：

- 三个输入流：OCR 文本令牌、每个令牌的二维边界框、图像块。
- 跨三种模态的掩码训练目标（掩码文本、掩码图像块、掩码布局）。
- 下游任务：分类、实体提取、表格问答。

LayoutLMv3 是基于 OCR 的文档理解的巅峰。在表单和发票上表现强劲。需要上游 OCR。标准化文档基准上，前 VLM 时代的最佳准确率。

### DocLLM（2023）

DocLLM（Wang 等，arXiv:2401.00908）是 LayoutLM 的生成式兄弟。根据布局令牌条件生成自由形式的回答。更适合文档问答；但仍依赖 OCR 输入。

### 时代 3 — VLM 原生（2024+）

2024 年，VLM 变得足够强大，可以完全替代整个流水线。将全页图像以高分辨率输入 VLM，提出问题，获得答案。

- LLaVA-NeXT 336-tile AnyRes 适用于小型文档。
- Qwen2.5-VL 动态分辨率原生支持 2048+ 像素。
- Claude Opus 4.7 支持 2576px 文档。
- PaliGemma 2（2025 年 4 月）专门针对文档 + 手写进行训练。

VLM 原生与 OCR 流水线之间的差距正在迅速缩小。到 2026 年，VLM 原生在以下方面胜出：

- 场景文字（手写 + 印刷，混合脚本）。
- 带合并单元格的复杂表格。
- 嵌入文本中的数学公式。
- 带文字标注的图形。

OCR 流水线仍在以下方面胜出：

- 大规模纯扫描工作负载，每页延迟至关重要。
- 流水线可靠性（确定性失败 vs VLM 幻觉）。
- 需要可审计 OCR 输出的监管环境。

### Claude 4.7 / GPT-5 前沿

在 2576 像素原生输入下，前沿 VLM 的文档理解准确率接近人类水平。2026 年初的基准数据：

- DocVQA：Claude 4.7 ~95.1，PaliGemma 2 ~88.4，Nougat ~77.3，流水线 LayoutLMv3 ~83。
- ChartQA：Claude 4.7 ~92.2，GPT-4V ~78。
- VisualMRC：Claude 4.7 ~94。

闭源模型的差距主要体现在分辨率和基础 LLM 规模上。7B 的开源模型落后几个百分点，但正在追赶。

### 数学公式与 LaTeX 输出

科学论文需要为公式提供精确的 LaTeX 输出。Nougat 正是在此基础上训练的。使用 LaTeX 目标训练过的 VLM（Qwen2.5-VL-Math、Nougat 衍生模型）能生成可用的 LaTeX。没有显式 LaTeX 训练的 VLM 会产生可读但不精确的转录结果。

对于 2026 年的科学论文流水线：先用 Nougat 处理 PDF，再对疑难页面使用 VLM。

### 手写

仍然是最难的子任务。印刷 + 手写混合（医生处方、填写表单）是 OCR 流水线在成本上仍优于 VLM 的领域。纯手写 VLM 正在改进（Claude 4.7、PaliGemma 2）。

### 2026 年方案

对于一个新的文档 AI 项目：

- 大规模纯印刷发票：LayoutLMv3 + 规则，成本高效。
- 混合文档（科学论文 + 手写 + 表单）：VLM 原生（PaliGemma 2 或 Qwen2.5-VL）。
- 完整的 arXiv 数据摄入：Nougat 处理数学，VLM 处理图形。
- 监管场景：OCR 流水线 + VLM 验证器交叉校验。

## 使用

`code/main.py`：

- 一个玩具级布局感知分词器：给定（文本，边界框）对，生成 LayoutLMv3 风格的输入。
- 一个 Donut 风格的任务模式生成器：表单的 JSON 模板。
- 每页令牌预算在 OCR 流水线、Donut、Nougat 和 VLM 原生之间的对比。

## 产出

本节课生成 `outputs/skill-document-ai-stack-picker.md`。给定一个文档 AI 项目（领域、规模、质量、监管），在 OCR 流水线、无 OCR 专才和 VLM 原生之间做出选择。

## 练习

1. 你的项目每天处理 1000 万张发票。哪种架构能在不损失准确率的前提下最大化降低每页成本？

2. 为什么 LayoutLMv3 在表单问答上优于纯 CLIP-VLM，但在场景文字上表现不及？边界框输入流放弃了什么？

3. Nougat 生成 LaTeX。提出一个测试场景，其中 VLM 原生输出在 LaTeX 精度上优于 Nougat，以及另一个 Nougat 胜出的场景。

4. 阅读 PaliGemma 2 论文（Google，2024）。与 PaliGemma 1 相比，关键的训练数据新增是什么提升了文档准确率？

5. 设计一个监管安全的混合方案：OCR 流水线为主，VLM 为辅助交叉校验。如何解决两者不一致的情况？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| OCR 流水线 | "Tesseract 风格" | 分阶段架构：检测 -> OCR -> 布局 -> 规则；确定性，脆弱 |
| 无 OCR | "Donut 风格" | 图像到输出的 Transformer，跳过显式 OCR；单模型 |
| 布局感知 | "LayoutLM" | 输入包含每个令牌的边界框坐标；跨模态统一掩码 |
| VLM 原生 | "前沿 VLM" | 直接将页面图像以高分辨率输入 Claude/GPT/Qwen VLM；无流水线 |
| DocVQA | "文档基准" | 文档 VQA 标准；引用最多的指标 |
| 标记输出 | "LaTeX / MD" | 结构化输出格式，而非自由形式文本；支持下游自动化 |
