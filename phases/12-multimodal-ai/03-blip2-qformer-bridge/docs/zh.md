# 从 CLIP 到 BLIP-2 — Q-Former 作为模态桥接器

> CLIP 可以对齐图像和文本，但无法生成描述、回答问题或进行对话。BLIP-2（Salesforce, 2023）用一个轻量可训练的桥接器解决了这个问题：32 个可学习的查询向量通过交叉注意力关注冻结的 ViT 特征，然后直接插入冻结 LLM 的输入流中。188M 参数的桥接器连接了一个 11B LLM 和一个 ViT-g/14。直到 2026 年的所有基于适配器的 VLM——MiniGPT-4、InstructBLIP、LLaVA 的衍生系列——都是它的后代。本课将解读 Q-Former 的架构，解释其两阶段训练，并构建一个将视觉 token 馈入冻结文本解码器的玩具版本。

**类型：** 构建
**语言：** Python（标准库，交叉注意力 + 可学习查询演示）
**前置知识：** 阶段 12 · 02（CLIP），阶段 7（Transformer）
**时间：** ~180 分钟

## 学习目标

- 解释为什么在冻结的视觉编码器和冻结的 LLM 之间使用可训练瓶颈比端到端微调在成本和稳定性上更优。
- 实现一个交叉注意力模块，其中一组固定的可学习查询关注外部的图像特征。
- 梳理 BLIP-2 的两阶段预训练：表示学习（ITC + ITM + ITG）然后是生成学习（基于冻结解码器的 LM 损失）。
- 比较 Q-Former 与 LLaVA 中使用的更简单的 MLP 投影器，并论证何时选择哪种方案。

## 问题

你有一个冻结的 ViT，每张图像产生 256 个维度为 1408 的 patch token。你有一个冻结的 7B LLM，它期望维度为 4096 的 token 嵌入。显而易见的桥接——一个从 1408 到 4096 的线性层——是可行的，但将所有 256 个 patch token 送入 LLM 的上下文意味着每张图像额外消耗 256 个 token。在一个 32 张图像的批次中，仅视觉模态就消耗了 8192 个 token。

BLIP-2 的问题是：能否将 256 个 token 的图像表示压缩为更少的 token（比如 32 个），同时保留足够的信息让 LLM 能够描述图像、回答问题和推理？而且，能否在不触及冻结骨干网络的情况下训练这个桥接器，使训练成本仅局限于桥接器的参数？

答案是：Q-Former。32 个可学习的"查询"向量交叉关注 ViT 的 patch token，生成一个 32 个 token 的视觉摘要供 LLM 使用。总共 188M 参数。在接触 LLM 之前，使用对比、匹配和生成目标进行训练。

## 概念

### 可学习查询

Q-Former 的核心技巧：不是让 LLM 的文本 token 关注图像 patch，而是引入一组新的 32 个可学习查询向量 `Q`，让*它们*去关注图像 patch。这些查询是模型的参数——它们在训练过程中被学习，且对于每张图像都使用相同的 32 个查询。

经过交叉注意力后，每个查询都持有图像的一个压缩摘要——"描述主要物体"、"描述背景"、"数一数物体数量"等。查询并非严格按语义标签特化；它们学习任何能使下游损失下降的编码方式。

### 架构

Q-Former 是一个小型 Transformer（12 层，~100M 参数），包含两条路径：

1. 查询路径：32 个查询向量依次经过自注意力（查询之间）、对冻结 ViT patch token 的交叉注意力，然后是 FFN。
2. 文本路径：一个类似 BERT 的文本编码器，与查询路径共享自注意力和 FFN 的权重。文本路径禁用交叉注意力。

训练时两条路径同时运行。查询和文本通过共享的自注意力交互，这意味着查询可以在需要时根据文本条件进行调节（ITM、ITG）。在推理时用于 VLM 衔接，仅查询路径运行，生成 32 个视觉 token。

### 两阶段训练

BLIP-2 分两个阶段进行预训练：

阶段 1：表示学习（无 LLM）。三种损失：
- ITC（图像-文本对比）：CLIP 风格的对比损失，在池化后的查询 token 与文本 CLS token 之间计算。
- ITM（图像-文本匹配）：二元分类器——这对图像-文本是否匹配？采用难负例挖掘。
- ITG（基于图像文本生成）：基于查询条件生成文本的因果 LM 头。迫使查询编码可生成文本的内容。

仅有 Q-Former 参与训练。ViT 冻结。LLM 不参与。

阶段 2：生成学习。挂载一个冻结的 LLM（OPT-2.7B 或 Flan-T5-XL 等）。通过一个小型线性层将 32 个查询输出投影到 LLM 的嵌入维度。将它们前置到文本提示之前。仅在线性投影和 Q-Former 上，针对拼接后的提示 + 图像 + 描述序列计算 LM 损失。

阶段 2 之后，Q-Former + 投影构成完整的视觉适配器。推理时：图像 → ViT → Q-Former → 线性投影 → 前置到文本 → 冻结的 LLM 生成输出。

### 参数经济学

BLIP-2 使用 ViT-g/14（1.1B，冻结）+ OPT-6.7B（6.7B，冻结）+ Q-Former（188M，训练）= 共计 8B，训练 188M。Q-Former 仅占完整参数量的 ~2.4%。训练成本反映了这一点：几天时间在数块 A100 上完成，而端到端训练则需要数周。

质量：BLIP-2 在零样本 VQA 上匹配或超越了 Flamingo-80B，而模型大小仅为后者的 1/50。桥接器确实奏效。

### InstructBLIP 与指令感知的 Q-Former

InstructBLIP（2023）为 Q-Former 增加了一个额外输入：指令文本本身。在交叉注意力时，查询现在可以同时访问图像 patch 和指令。查询可以按指令进行特化（"数一数汽车数量"、"描述一下氛围"），而不是学习单一的固定摘要。在保留任务上取得了基准提升。

### MiniGPT-4 与仅投影器方法

MiniGPT-4 保留了 Q-Former，但仅训练输出端的线性投影，同时冻结其他所有部分。成本低，但代价是质量——查询是 BLIP-2 的，不是你自己的。适合快速迭代，但不是最优架构。

### LLaVA 为何选择更简单的方案

LLaVA（2023，课程 12.05）将 Q-Former 替换为一个简单的 2 层 MLP，将每个 ViT patch token 投影到 LLM 空间——对于 24×24 的网格，每张图像产生 576 个 token，全部馈入 LLM。压缩效果更差，但让 LLM 能够直接关注原始 patch。在当时这存在争议；到 2023 年底它成为主流，因为视觉指令数据（LLaVA-Instruct-150k）证明 MLP 可以训练到保留足够的信号。权衡：LLaVA 的上下文填充更快，但它能自然地扩展到多图像和视频场景。

到 2026 年，这个领域已经分化：在 token 预算受限的场景下（长视频、多张图像），Q-Former 仍然存活；在注重每个 token 的原始质量的场景下，MLP 投影器占据主导。

### 门控交叉注意力：Flamingo，先驱者

Flamingo（课程 12.04）早于 BLIP-2，使用了相同的交叉注意力思想，但应用于每一个冻结的 LLM 层，而不是作为一个单一的桥接器。BLIP-2 证明了只需在输入层进行压缩也能有效工作。Gemini 和 Idefics 结合了两种方式：交错输入 token 加上可选的用于上下文少样本学习的门控交叉注意力。

### 2026 年的后代

- Q-Former：BLIP-2、InstructBLIP、MiniGPT-4，以及大多数出于 token 预算考虑的视频语言模型。
- Perceiver 重采样器：Flamingo 的变体（课程 12.04）；Idefics 系列、Eagle、OmniMAE。
- MLP 投影器：LLaVA、LLaVA-NeXT、LLaVA-OneVision、Cambrian-1。
- 注意力池化：VILA、PaliGemma。

所有四种方法都有效。决定性的问题在于你的约束是 token 预算还是每 token 的质量。

## 使用它

`code/main.py` 构建了一个标准库风格的 Q-Former 交叉注意力：

1. 模拟 256 个图像 patch token（维度 128）。
2. 实例化 32 个可学习查询（维度 128）。
3. 运行缩放点积交叉注意力（Q 来自查询，K/V 来自 patch）。
4. 通过线性层投影到 LLM 维度（512）。
5. 输出 32 个 LLM 可用的视觉 token。

所有计算使用纯 Python 实现（向量上的嵌套循环）。玩具但形状正确。注意力权重矩阵会被打印出来，让你可以看到每个查询从哪些 patch 中提取了信息。

## 练习

1. 在 PyTorch 中实现交叉注意力模块。验证：使用 32 个查询和 256 个键/值时，注意力权重矩阵为 32 × 256，且 softmax 后每行之和为 1。

2. 在 BLIP-2 阶段 1，Q-Former 同时运行三种损失：ITC、ITM、ITG。用伪代码为每种损失写出前向签名。哪一种需要文本编码器路径处于激活状态？

3. 比较参数数量：Q-Former（12 层，768 隐藏维度）与一个 2 层 MLP 投影器（1408 → 4096，两层）。在多大的 LLM 规模下，188M 的 Q-Former 成本能在训练效率上获得回报？

4. 阅读 BLIP-2 论文（arXiv:2301.12597）第 3.2 节关于 Q-Former 初始化方式的内容。解释为什么从 BERT-base 初始化（而非随机）能加速收敛。

5. 对于一个以 1 FPS 采样到 60 帧的 10 分钟视频，计算每帧的 token 成本：（Q-Former → 32 token/帧）vs（MLP 投影器 → 576 token/帧）。哪种方案能容纳在 128k token 的 LLM 上下文窗口中？

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| Q-Former | "查询 Transformer" | 小型 Transformer，带有 32 个可学习查询向量，对冻结的 ViT 特征进行交叉注意力 |
| 可学习查询 | "视觉的软提示" | 一组固定的参数，作为交叉注意力的查询方；每个模型学习，所有输入共享 |
| 交叉注意力 | "查询来自这里，键/值来自那里" | 查询、键和值来自不同源的注意力机制；查询如何从 ViT patch 中提取信息 |
| ITC | "图像-文本对比" | CLIP 风格的损失，在 Q-Former 池化后的查询与文本 CLS 之间计算 |
| ITM | "图像-文本匹配" | 对难负例挖掘出的对进行二元分类；迫使查询区分细粒度不匹配 |
| ITG | "基于图像文本生成" | 因果 LM 损失，文本在查询条件下生成；迫使查询编码可解码为文本的内容 |
| 两阶段预训练 | "表示学习然后是生成学习" | 阶段 1 单独训练 Q-Former（ITC/ITM/ITG）；阶段 2 挂载冻结的 LLM，仅训练投影层 + Q-Former |
| 冻结骨干网络 | "不做微调" | 视觉编码器和 LLM 的权重固定；仅桥接器参与训练 |
| 投影头 | "线性层映射到 LLM 维度" | 将 Q-Former 输出映射到 LLM 嵌入维度的最终线性层 |
| Perceiver 重采样器 | "Flamingo 的版本" | 类似的可学习查询交叉注意力，Flamingo 在每一层使用，而非作为单一桥接器 |
