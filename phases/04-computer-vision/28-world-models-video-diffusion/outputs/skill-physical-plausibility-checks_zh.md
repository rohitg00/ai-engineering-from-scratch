# 物理合理性检查

生成的视频的生产部署需要自动护栏。人工审查无法扩展；物理检查能捕获经典的失败模式。

## 使用时机

- 任何从文本或图像提示生成视频的产品。
- 在视频生成 API 端点上自动化 QA。
- 监控视频模型在微调或基础模型更新后的质量漂移。

## 输入

- `video`：张量 `(T, H, W, 3)` 或 mp4 路径。
- 可选的参考信息：预期的物体数量、初始场景描述。

## 检查项

### 1. 物体恒存性
使用 SAM 3.1 Object Multiplex 跨帧跟踪每个检测。当稳定轨迹消失 <=3 帧后重新出现时标记——模型暂时丢失了物体。当物体在帧中心附近（非边缘）消失时硬失败；在边缘处软失败。

### 2. 运动平滑度
连续帧之间的光流应该大致连续。突发的逐像素流尖峰表示瞬移。使用 RAFT 计算光流；标记第 99 百分位流量幅度超过中位数 10 倍以上的帧。

### 3. 重力 / 支撑
对于检测为固体的物体（食物、球、工具），检查其垂直位置在没有抬升动作的情况下是否非递增。标记向上漂移，除非在物体附近检测到"抓取的手"。

### 4. 身份一致性
对于人物或角色，跨帧使用人脸识别嵌入。对于持续的身份，5 帧窗口内的余弦相似度应保持 > 0.8。低于阈值表示角色变形。

### 5. 手和肢体
运行姿态估计器（第 21 课）。标记手部可见手指 > 5 或 < 4 的帧；手臂长度在帧间翻倍的帧；肢体穿过身体表面的帧。

### 6. 文本渲染（如果提示要求文本）
如果用户提示包含引号内的字符串，对生成的帧进行 OCR 并计算相对于请求字符串的 CER。标记 > 20% CER。

## 报告

```
[plausibility]
  video frames:           <T>
  permanence violations:  <N>
  smoothness violations:  <N>
  gravity violations:     <N>
  identity drift:         <N 个 5 帧窗口>
  limb anomalies:         <N>
  OCR CER vs requested:   <浮点数>

[verdict]
  ship（发布） | hold（暂缓） | reject（拒绝）

[samples for review]
  每种失败发生的帧范围
```

## 规则

- 不要在任何单个检查上硬拦截；聚合分数并在异常总数超过阈值时将视频暂缓审查。
- 身份漂移和恒存性违规权重最高——用户最先注意到它们。
- 随时间记录每个检查的失败率；上升趋势通常意味着基础模型已更新或提示分布已漂移。
- 绝不要删除标记的视频；保留它用于模型调试和事后分析。
- 对于敏感内容（人物、儿童、公众人物），无论分数如何，每个视频都需要人工审查。
