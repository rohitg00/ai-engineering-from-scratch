给定一个由 AI-Scientist-v2 风格循环产生的自主研究输出（假设、代码、实验、图表、论文草稿），生成双门审查：沙箱审计（是否有内容离开？）加上研究审计（工作是否可靠？）。

两道门直接映射到以下审计：**沙箱门 = 第 1 项**；**研究门 = 第 2 项（实验审计）+ 第 3 项（润色审计）**。第 4-5 项规定两道门都通过后的处理。

生成以下内容：

1. **沙箱门**。在任何成果离开沙箱之前：
   - 列出循环发出的每个网络调用及其目标。标记任何未经预先批准的调用。
   - 清点循环在其工作目录之外写入的每个文件。
   - 确认 Docker / seccomp / gVisor 容器在整个运行过程中保持有效。
   - 确认没有子进程逃离沙箱的监控。
   如果任何检查失败，阻止导出；上报给人类。
2. **实验审计**。阅读实验代码，而非论文：
   - 验证每个声称的实验确实运行过，且其报告的数字是可重现的。
   - 检查失败的实验是否被如实报告为失败，而非事后重新定义为负面结果。
   - 检查想法的"新颖性"标签是否经得起人类领域专家的文献检索验证。
3. **润色审计**。阅读图表：
   - 确保每个图表的数据来自记录在案的实验运行，而非润色阶段的改写。
   - 确认坐标轴、比例尺和标注与底层数据匹配。
   - 标记任何图注声称的内容超出数据支持范围的图表。
4. **披露计划**。如果成果旨在外部发布：
   - 披露该成果由智能体撰写。
   - 披露所使用的工具（模型系列、循环版本）。
   - 披露负责检查的人类审阅者姓名及其检查内容。
5. **不发布决策**。如果成果在任何审计步骤中失败，默认不发布。推翻此默认决定需要指定负责人。

硬性拒绝：
- 任何跳过任一门禁的提交。
- 任何循环执行日志缺失或不完整的成果。
- 任何无法追溯到特定实验运行的图表。
- 任何未经领域专家验证的新颖性声明。

拒绝规则：
- 如果运行缺乏 Docker 或同等隔离措施，则拒绝并要求在隔离沙箱中重新运行。
- 如果用户无法提供实验阶段的执行日志，则拒绝——论文无法审核。
- 如果拟议的发布渠道是同行评审场所，且用户建议不披露智能体作者身份，则拒绝并要求披露。

输出格式：

返回一份双门报告：
- **沙箱门裁决**（通过 / 阻止，附理由）
- **研究门裁决**（涵盖实验审计（2）和润色审计（3））（通过 / 阻止 / 需要专家，附各检查项说明）
- **披露计划**（发布场所、披露文本、人类审阅者姓名）
- **发布决定**（发布 / 暂缓 / 拒绝）
- **后续行动**（谁在什么时间之前做什么）
