# AI Scientist v2 — 工作坊级自主研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、论文撰写、投稿。它是首个在 ICLR 2025 工作坊上通过同行评审的自主生成论文系统。独立评估（Beel 等人）发现 42% 的实验因编码错误失败，文献综述频繁将已有概念误标为新颖。Sakana 自己的文档警告该代码库会执行 LLM 编写的代码，并建议使用 Docker 隔离。这幅图景的两面都值得关注。

**类型：** 学习
**语言：** Python（标准库，研究循环状态机玩具）
**前置要求：** 阶段 15 · 03（AlphaEvolve），阶段 15 · 04（DGM）
**时间：** 约 60 分钟

## 问题

研究是一项开放式任务。不同于 AlphaEvolve 的算法搜索或 DGM 的基准受限自修改，研究结果并不具有机器可检验的正确性标准。论文由审稿人评判，而非单元测试。这使得闭环更难实现——而一旦实现则更有价值，因为研究正是复合进步的源泉。

AI Scientist v1（Sakana, 2024）通过从人类撰写的模板出发来实现闭环。LLM 在固定的脚手架内填充实验内容。AI Scientist v2（Yamada 等人, 2025）通过使用智能体树搜索结合视觉-语言模型评判循环，消除了模板需求。该系统生成想法、实施实验、制作图表、撰写论文，并根据审稿人反馈进行迭代。

同行评审结果：一篇 v2 生成的论文在 ICLR 2025 工作坊上被接收（已公开披露）。独立评估结果：该系统远未达到可靠。两者皆为事实。

## 概念

### 架构

1. **想法生成。** LLM 基于主题和先前文献提出研究想法。v1 使用模板；v2 在假设空间中进行智能体搜索。
2. **新颖性检查。** 文献检索步骤检查该想法是否已被发表。Beel 等人的评估发现该步骤存在误标——已有方法频繁被归类为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败会反馈到重试循环中。根据 Beel 等人的测量，42% 的实验在此阶段因编码错误失败。
5. **图表生成。** 视觉-语言模型读取生成的图表并改写得更加清晰。这是 v2 的关键技术新增。
6. **论文撰写。** LLM 起草论文，并与内部审稿人进行迭代。
7. **可选：投稿。** 论文提交至某个学术场所。

### 工作坊接收结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 工作坊的同行评审。作者向程序委员会披露了论文的起源。这一接收是一个数据点，而非声称该系统"做研究"的许可证。

重要背景：工作坊论文的门槛低于主会议论文。同行评审充满噪声；在任何一天，只有一小部分投稿会被接收。一次成功是概念验证，而非可靠性声明。Nature 2026 的论文记录了端到端循环，并且本身由人类研究人员共同撰写；它并非"该系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误失败（错误的导入、形状不匹配、未定义的变量）。重试循环捕获了部分错误，但未全部捕获。
- **新颖性误标。** 文献检索步骤频繁将已有概念标记为新颖。这是研究领域的幻觉。
- **呈现质量差距。** 视觉-语言图表评判生成了达到出版质量的视觉内容，掩盖了底层实验的缺陷。

最后一点对本阶段最为重要。一个能产出令人信服的输出却没有进行令人信服的研究的系统，比一个明显失败的系统更危险，而非更安全。评估必须触及底层声明，不能止步于图表。

### 沙箱逃逸风险

Sakana 自己的仓库 README 警告：

> 鉴于本软件执行 LLM 生成的代码的性质，我们无法保证安全性。存在危险包、不受控的网络访问以及生成意外进程的风险。请自行承担使用风险，并考虑使用 Docker 隔离。

这是自主性在未验证领域中的操作形态。LLM 编写代码；代码运行；代码可以做进程被允许做的任何事情。如果没有严格限制文件系统、网络和进程操作的沙箱，任何自主研究智能体都可以泄露数据、消耗算力或重写自身。

AlphaEvolve 的沙箱故事更为简单，因为其评估器是紧缩的。AI Scientist v2 的循环以开放式目标运行开放式代码。这就是为什么它需要更强的隔离（最低 Docker；推荐 seccomp/gVisor）以及在每一项产出离开系统前进行人工审查。

### v2 在前沿堆栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准测试 | 受限于评估器严格程度 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、误标、抛光掩盖缺陷 |

v2 在这三者中拥有最弱的自动评估器、最广泛的输出表面，以及通往公开产物的最短路径。操作控制（沙箱、审查、披露）承担了大部分安全工作。

## 使用

`code/main.py` 将 v2 循环模拟为一个状态机：想法 → 新颖性检查 → 实验 → 图表 → 论文撰写 → 审稿 → 接收或迭代。每个状态都有取自 Beel 等人发现的可配置失败概率。运行该模拟器 N 次循环并统计：

- 有多少想法到达投稿阶段。
- 有多少投稿存在经过抛光后的论文所隐藏的关键实验缺陷。
- 重试预算如何在质量与产出之间权衡。

## 交付

`outputs/skill-ai-scientist-sandbox-review.md` 是一个双门审查询问清单，适用于任何由研究循环智能体生成且即将离开沙箱的产出。

## 练习

1. 使用默认参数运行 `code/main.py`。多少比例的循环运行产生了"干净"的论文？多少比例产生的论文存在被图表评判抛光过的实验失败缺陷？

2. 默认参数已使用 Beel 等人的 42%/25%。分别使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 和 `--experiment-failure 0.60 --novelty-mislabel 0.40` 重新运行。两次运行之间，抛光但有缺陷的论文占比如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的内容。列出你在多日自主运行中会施加的两项额外限制（超越 Docker 之外）。

4. 阅读 Beel 等人论文第 4 节关于呈现质量差距的内容。设计一个额外的评估器，用于捕获看起来抛光但在实验上有缺陷的论文。

5. 提出一种针对研究智能体产出的人工审查协议，该协议应比"让一位博士阅读每篇论文"更具可扩展性。识别瓶颈并围绕它进行设计。

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究智能体" | 在固定脚手架中填充实验内容 |
| AI Scientist v2 | "无模板研究智能体" | 使用 VLM 图表评判的智能体树搜索 |
| 智能体树搜索 | "分支式研究智能体" | 并行扩展多个实验计划；通过内部评判器剪枝 |
| 视觉-语言评判 | "VLM 抛光图表" | 多模态模型读取图表并改写得更加清晰 |
| 文献检索 | "新颖性检查" | 搜索已有工作以确认想法的新颖性——已知存在误标 |
| 抛光掩盖 | "漂亮的论文，破碎的研究" | 呈现质量超过实验质量；隐藏缺陷 |
| 沙箱逃逸 | "LLM 代码突破限制" | 智能体执行的代码做了循环设计者未预期的事情 |
