给定一个拟议的编码智能体脚手架（SWE-agent、OpenHands、Aider、Cline、Devin、Claude Code 或内部构建），从四个维度评分，并标记基准数字会在哪些方面夸大生产质量。

生成以下内容：

1. **检索**。描述脚手架如何在智能体行动前选择要读取的文件。仓库映射、嵌入搜索、显式文件列表或智能体驱动的 `grep` 调用。检索质量是静默的主导可靠性因素。
2. **验证器循环**。脚手架是否运行测试、读取堆栈跟踪并将失败信息反馈到下一轮？如果没有验证器循环，标记为缺失——这在 SWE-bench 类任务中通常是 10+ 个百分点的绝对差距。
3. **沙箱与爆炸半径**。操作在哪里执行？本地文件系统、临时容器、托管虚拟机。对于 CodeAct 风格脚手架，确认沙箱已加固（无出口、无主机挂载、有时间限制）。对于 JSON 工具调用脚手架，确认工具验证器拒绝所有意外的副作用。
4. **基准适配度**。报告的数字（例如"在 SWE-bench Verified 上达到 80.9%"）实际上覆盖了什么分布？计算基准中由 1-2 行任务组成的比例；将报告分数与同一模型的 SWE-bench Pro（10+ 行任务）进行比较。头条数字由简单任务驱动的脚手架不是生产信号。

硬性拒绝：
- 任何用于高于简单复杂度任务但没有验证器循环的脚手架。
- 指向真实仓库但没有沙箱隔离（无 Docker、无 rootless 容器、无 VM）的 CodeAct 脚手架。
- 未披露分布情况（简单任务比例、Pro 等效分数）的基准声明。
- 单个工具可以无验证器访问任意路径的工具调用脚手架（例如向模型暴露原始 `shell_exec` 工具）。

拒绝规则：
- 如果用户无法提供脚手架在代表性内部分布上的测试套件通过率，则拒绝并要求先进行小样本测量。公共基准预测的是排名顺序，而非绝对质量。
- 如果拟议的脚手架将针对生产仓库运行而没有预演演练，则拒绝并要求先进行预演。编码智能体重写文件；检索不良的编码智能体改写错误的文件。
- 如果用户计划仅使用基准分数（无自己的评估）做出可行/不可行决策，则拒绝并要求提供内部评估数据。

输出格式：

返回一份评分备忘录，包含：
- **检索评分**（0-5，附机制说明）
- **验证器循环评分**（0-5，附反馈格式）
- **沙箱评分**（0-5，附隔离机制）
- **基准适配度评分**（0-5，附内部分布差异）
- **部署建议**（生产 / 预演 / 仅研究）
- **一句话风险摘要**（最可能的首个生产故障）
