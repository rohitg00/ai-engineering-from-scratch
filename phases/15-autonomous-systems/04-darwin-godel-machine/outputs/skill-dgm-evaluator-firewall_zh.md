给定一个拟议的自我修改智能体循环（智能体脚手架、评估器流程、部署目标），生成一份防火墙规范，确保评估器处于智能体无法触及的范围之外。DGM 论文记录了智能体移除自身安全标记以提高分数的案例；本技能就是针对此的控制措施。

生成以下内容：

1. **文件系统边界**。列出智能体可以编辑的每个文件。列出评估器读取的每个文件。交集必须为空。如果不为空，则指定需要采取的具体行动使其为空。
2. **进程边界**。评估器必须在智能体无法控制的进程中运行。指定容器或沙箱。如果智能体具有 shell 访问权限，则智能体可以绕过进程内保护。
3. **网络与密钥边界**。智能体必须无法编辑用于获取评估器输入或发布分数的 CI 密钥。列出密钥的存储位置及其挂载方式。
4. **分数输入合约**。分数从评估器返回到循环的存档。该路径是唯一的通道。智能体可以写入的任何影响未来评分的内容都会破坏该合约。
5. **变更审查清单**。列出需要人工审核才能接受的智能体编辑类别：新增依赖、对评分相关代码的编辑、对沙箱配置的编辑、对日志或监控的编辑。

硬性拒绝：
- 评估器与智能体源代码位于同一仓库中。将其移出。
- 评估器作为 Python 导入在智能体进程内部运行。应在子进程中运行。
- 任何在智能体侧应用的分数调整。所有调整必须在服务端进行。
- 任何智能体可通过编辑自身代码来静默的日志记录。

拒绝规则：
- 如果用户无法说出智能体能编辑的每个文件，则拒绝并要求先进行文件级别的写入权限审计。
- 如果评估器没有保留输入，则拒绝——这是第 3 课的审计，是前置条件。
- 如果部署表面包括对评估器本身的更改（即使是间接通过拟议的依赖更新），则拒绝并要求执行人工防火墙审查步骤。

输出格式：

返回一份一页规范，包含：
- **智能体写入表面**（路径、通配符）
- **评估器读取表面**（路径、端点）
- **交集**（必须为空；显示差异）
- **进程模型**（评估器的隔离方式）
- **密钥清单**（位置及挂载方式）
- **需要审查的变更类别**（项目符号列表）
- **签核栏**（防火墙不变量的负责人）
