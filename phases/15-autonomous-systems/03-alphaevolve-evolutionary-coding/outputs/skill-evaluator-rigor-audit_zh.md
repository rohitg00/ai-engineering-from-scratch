给定一个拟议的进化编码循环（生成器 LLM、程序数据库、评估器），审计评估器。评估器是架构核心；生成器是可替换的。本技能判断该循环是否有可能产生真正的成果，还是只会产生奖励黑客式的垃圾。

生成以下内容：

1. **评估器分解**。命名评估器报告的每个信号：正确性、性能、资源、其他。对每个信号说明 (a) 如何测量、(b) 能被多容易地欺骗、(c) 保留输入规则应是什么样。
2. **虚构表面**。列出 LLM 在该领域中最可能出现的三种虚构：声称的复杂度类别、声称的边缘情况正确性、未经验证的声称性能。说明每个评估器信号能捕捉哪些。
3. **奖励黑客表面**。列出该循环可能在不执行预期任务的情况下最大化分数的三种方式（通过测试的捷径、代理指标游戏、输入记忆化）。说明每种方式的缓解措施。
4. **确定性与可重现性**。要求评估器输出在容差范围内是确定性的。标记任何运行间分数波动超过总体方差的评估器。
5. **部署检查**。如果胜出的变体将被推送到生产环境，则需要一次单独的预部署审查，检查评估器未涵盖的内容（安全性、成本、人工审查）。搜索过程并未验证部署就绪性。

硬性拒绝：
- 任何评估器是 LLM 裁判而没有机器可检查的真实依据的循环。LLM 裁判可以被欺骗。
- 任何只报告单一标量分数而没有分解的评估器。标量分数会放大奖励黑客行为。
- 仅使用训练集的评估器。保留输入是不可谈判的。

拒绝规则：
- 如果用户无法用两段话描述评估器，则拒绝并要求先提供评估器规范。没有规范评估器的循环还未准备好投入算力。
- 如果领域是不可验证的（创意写作、开放式科学假设、长篇研究），则拒绝并推荐采用人工审查的混合流程而非封闭循环。
- 如果拟议的部署表面是不可逆的（生产基础设施变更、已发布产品中的算法替换），则拒绝封闭式部署。要求分阶段推出和人工签核。

输出格式：

返回一份一页备忘录，包含：
- **循环摘要**（生成器、评估器、目标领域）
- **评估器评分**（严谨度 1-5 及理由）
- **虚构表面**（前 3 个，含评估器覆盖情况）
- **奖励黑客表面**（前 3 个，含缓解措施）
- **确定性与可重现性**（分数方差与总体方差对比；种子控制；通过/失败）
- **部署就绪性**（允许封闭循环推送 y/n；所需的预部署审查：安全、成本、人工）
- **建议**（继续 / 收紧评估器 / 选择不同领域）
