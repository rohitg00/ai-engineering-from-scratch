# 提示模式选择指南

在构建基于 LLM 的功能时，在编写提示之前选择提示模式。模式决定结构。内容填充其中。

## 模式决策矩阵

| 任务类型 | 主要模式 | 次要模式 | 温度 | 需要少样本？ |
|-----------|----------------|-------------------|-------------|-----------------|
| 数据提取 | 模板填充 | 少样本 | 0.0 | 是（2-3 示例） |
| 分类 | 少样本 | 护栏 | 0.0 | 是（3-5 示例） |
| 摘要 | 角色 + 模板 | 受众适配 | 0.3 | 否 |
| 代码生成 | 角色 | 思维链 | 0.0 | 可选 |
| 创意写作 | 角色 | 批评 | 0.7-1.0 | 否 |
| 多步推理 | 思维链 | 分解 | 0.3 | 可选 |
| 问答 | 角色 + 护栏 | 边界 | 0.3 | 否 |
| 提示生成 | 元提示 | 批评 | 0.7 | 是（1-2 示例） |
| 内容审核 | 护栏 + 边界 | 少样本 | 0.0 | 是（5+ 示例） |
| 翻译/适配 | 受众适配 | 少样本 | 0.3 | 是（2-3 示例） |

## 何时使用每种模式

**角色模式**：对每个提示作为基线使用。唯一的问题是角色要多具体。对于通用任务，宽泛的角色就够了。对于领域特定任务，角色应命名领域、资历级别和上下文。

**少样本模式**：当输出格式比内容更重要时使用。如果模型需要产生特定的 JSON 形状、CSV 格式或分类标签，示例比指令更有效。经验法则：简单格式用 2-3 个示例，复杂或模糊格式用 5+ 个示例。

**思维链模式**：用于数学、逻辑、多步分析以及任何模型需要"展示其工作"的任务。在推理任务上提高准确率 10-40%（Wei 等人，2022）。不要用于简单的事实查找或提取——它会浪费 token。

**模板填充模式**：用于每个输出必须具有相同形状的结构化提取。与 temperature=0.0 和缺失字段的显式"不适用"处理搭配效果最佳。

**批评模式**：当质量比速度更重要时使用。模型生成、批评和改进。大致使 token 成本翻倍但显著提高准确性和完整性。最适合高风险输出（报告、建议、面向公众的内容）。

**护栏模式**：用于任何面向用户的系统。始终包含：范围边界、超出范围请求的拒绝行为以及显式的"我不知道"处理。与应用端的输入验证结合使用。

**元提示模式**：用于为新任务生成提示。无需从头编写提示，而是描述任务让模型编写提示。然后测试和迭代。在初始提示开发上节省时间。

**分解模式**：用于受益于分治策略的复杂问题。模型将问题分解为部分，解决每个部分，然后组合。对具有 3-7 个子问题的任务最有效。

**受众适配模式**：当相同内容需要服务不同受众时使用。显式指定受众——不要依赖模型从上下文中猜测。

**边界模式**：用于绝对不能回答某些类型问题的生产系统。比护栏更强，因为它定义了硬范围及确切的拒绝消息。对合规敏感领域至关重要。

## 跨模型兼容性

模式按在 GPT-4o、Claude 3.5 Sonnet、Gemini 1.5 Pro 和 Llama 3 上一致工作的程度排序：

| 模式 | 跨模型一致性 | 备注 |
|---------|------------------------|-------|
| 少样本 | 非常高 | 示例跨所有模型迁移良好 |
| 模板填充 | 非常高 | 显式结构几乎不留下发散空间 |
| 思维链 | 高 | 所有主流模型支持"逐步思考" |
| 角色 | 高 | 各处生效但不同模型对不同角色具体级别有不同反应 |
| 护栏 | 中等 | Claude 最严格遵循护栏；GPT-4o 在长对话中有时漂移 |
| 批评 | 中等 | 自我批评质量因模型而异显著 |
| 元提示 | 中等 | GPT-4o 和 Claude 产生不同提示风格 |
| 边界 | 中低 | 拒绝行为各异；需按模型测试 |

## 常见错误

1. **对一切使用思维链**：CoT 增加 token 和延迟。仅在需要推理步骤时才使用。
2. **约束太多**：超过 5-7 个约束时模型开始忽略一些。优先选择 3 个最重要的。
3. **矛盾的角色 + 约束**："你是一位创意作家"+"永远不要使用比喻"会混淆模型。
4. **无温度规范**：在需要确定性输出时将温度保持在默认值（通常为 1.0）。
5. **跨模型复制粘贴提示**：始终测试。为 GPT-4o 调优的提示在 Claude 上可能表现不佳，反之亦然。
6. **忽略系统消息**：将所有内容放入用户消息而非使用系统消息放置持久规则。
7. **过度依赖负向约束**："不要做 X、Y、Z、A、B、C"不如"只做 W"有效。正向框架给模型明确目标。

## 可靠性目标

| 用例 | 模式组合 | 预期准确率 | Token 成本 |
|----------|-------------------|-------------------|------------|
| 生产提取 | 模板 + 少样本 | 95%+ | 低（500-1K） |
| 面向用户的问答 | 角色 + 护栏 + 边界 | 90%+ | 中（1-2K） |
| 代码生成 | 角色 + 思维链 | 85%+ | 中（1-3K） |
| 内容生成 | 角色 + 批评 | 质量 90%+ | 高（2-4K，两遍） |
| 分类 | 少样本 + 护栏 | 95%+ | 低（300-800） |
| 复杂分析 | 分解 + 思维链 | 85%+ | 高（3-5K） |
