# 嵌入模式

每个嵌入工作流遵循此契约：

```
文本 -> 嵌入(文本) -> 向量（浮点数数组）
相似度(向量_a, 向量_b) -> 分数（浮点数）
```

嵌入模型和相似度度量是唯一重要的两个决策。其他一切都是管道。

## 何时使用嵌入

- 跨文档的语义搜索（找含义，而非关键词）
- 相似项聚类（支持工单、产品评论、缺陷报告）
- 通过最近邻分类（通过与标注示例的相似度为新项打标签）
- 推荐系统（找与用户喜欢的内容相似的项）
- 去重（使用相似度阈值找近似重复内容）

## 何时不使用嵌入

- 精确关键词匹配（使用全文搜索）
- 结构化查询（使用 SQL、过滤器）
- 手工标注更快的小型数据集（<100 项）
- 可解释性比准确率更重要的任务（嵌入是不透明的）

## 模型选择

根据约束条件选择：

- **需要 API，最佳价值**：OpenAI text-embedding-3-small（1536d，$0.02/1M token）
- **需要最大准确率**：Voyage-3（1024d，$0.06/1M token，最高 MTEB）
- **需要本地/私有**：BGE-M3（1024d，免费，多语言，建议 GPU）
- **需要快速本地原型**：all-MiniLM-L6-v2（384d，免费，可在 CPU 上运行）
- **需要多语言**：Cohere embed-v3（1024d）或 BGE-M3（两者多语言能力强）

规则：永远不要在索引和查询之间混合使用嵌入模型。来自不同模型的向量存在于不兼容的空间中。

## 分块规则

1. 每块目标 256-512 token，50 token 重叠
2. 尽可能避免在句子中间拆分
3. 为每个块包含元数据（源文件、章节标题、位置）
4. 对于结构化文档（Markdown、HTML），首先在标题边界处拆分
5. 通过搜索已知答案并检查检索结果来测试分块质量

## 相似度度量选择

- **余弦相似度**：默认选择，处理变长文本，归一化
- **点积**：当向量已是单位归一化时使用（OpenAI 模型如此），稍快
- **欧几里得距离**：用于聚类，当绝对位置重要时

当向量归一化时，三者给出相同的排序。选择仅对非归一化向量重要。

## 存储优化

三个压缩级别，可叠加：

1. **Matryoshka 截断**：减少维度（1536 -> 256 = 6 倍节省，准确率损失 3-5%）
2. **Float16 量化**：每维度存储减半（2 倍节省，准确率损失 <1%）
3. **二值量化**：每维度 1 比特（32 倍节省，准确率损失 5-10%，与重新评分配合使用）

生产模式：对整个语料库进行二值搜索，用 float32 向量对 top-1000 重新评分。

## 检索-然后-重排序

两阶段流水线实现最佳准确率：

1. 双编码器检索 top-100 候选（快速，使用预计算嵌入）
2. 交叉编码器重排序到 top-10（慢速，处理每个查询-文档对）

这比单阶段检索在精度指标上提高 10-15%。当准确率比延迟更重要时使用。

## 常见错误

- 索引和查询使用不同的嵌入模型
- 嵌入整个文档而不是分块（嵌入变成所有内容的平均值）
- 在余弦相似度之前未归一化向量（大多数模型预归一化，但需验证）
- 忽略分块重叠（在边界处拆分的句子会丢失上下文）
- 仅存储向量而不存储原始文本（检索需要两者）
- 模型更改时未重新嵌入（旧向量不兼容）
- 仅根据准确率选择维度（存储和延迟随维度线性增长）

## 调试嵌入

如果搜索结果差：

1. 验证查询嵌入非零（空或空白输入产生零向量）
2. 手动检查已知相关文档的相似度分数
3. 尝试重新表述查询以匹配文档词汇
4. 检查分块边界，确保相关内容未跨块拆分
5. 跨指标（余弦、点积、欧几里得）比较 top-k 结果以发现归一化问题
6. 使用简单匹配查询测试（从文档中复制一句话）以确认流水线工作

## 生产参数

- 块大小：256-512 token
- 块重叠：50 token（块大小的 10-20%）
- Top-k 检索：直接使用 5-10，重排序用 50-100
- 相似度阈值：余弦值 0.7+（低于此值结果通常不相关）
- 批量嵌入：每次 API 调用处理 100-500 个文本以获得吞吐量
- 索引重建：模型更改或文档显著更新时重新嵌入
