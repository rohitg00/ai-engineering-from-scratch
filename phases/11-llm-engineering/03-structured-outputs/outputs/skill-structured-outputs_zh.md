# 结构化输出策略

在构建需要结构化数据的 LLM 应用时，应用此决策框架。

## 何时使用每种方法

**基于提示（"返回 JSON"）：** 仅原型开发。对内部工具可接受，偶尔的解析失败可以容忍。添加 try/except 和重试。绝不在生产流水线中使用。

**JSON 模式（API 标志）：** 需要保证有效的 JSON 但模式简单或灵活。在应用端验证形状时有效。可用：OpenAI、Anthropic（通过工具使用）、Google。

**模式模式（约束解码）：** 每个输出必须匹配特定模式的生产系统。零解析失败。零模式违规。默认用于任何生产提取或分类任务。可用：OpenAI 结构化输出、Outlines、Guidance。

**函数调用 / 工具使用：** 模型需要选择调用哪个函数，而不仅仅是填充参数。有多个模式且模型选择适当的模式。在集成到现有工具/函数基础设施时也使用。

**Instructor 库：** 想要 Pydantic 验证并在任何提供者上自动重试。适合 Python 项目的最佳开发体验。封装 OpenAI、Anthropic、Google 和开源模型。

## 提供者特定指导

**OpenAI：** 使用 `response_format` 带 `json_schema` 类型。约束解码内置。Pydantic 模型直接工作。最可靠的结构化输出实现。

**Anthropic：** 使用工具使用进行结构化输出。用所需模式定义一个工具。模型返回匹配模式的工具调用参数。可靠但需要工具使用 API 模式。

**开源模型（vLLM、Ollama）：** 使用 Outlines 或 Guidance 进行约束解码。这些库将 JSON Schema 编译为有限状态机，在生成期间屏蔽无效 token。需要本地运行推理。

## 模式设计指南

1. 尽可能保持模式扁平。超过 2 层的嵌套对象增加提取错误。
2. 对分类字段使用枚举。不要依赖模型发明正确的字符串。
3. 将模糊字段设为必填并显式支持 null，而非设为可选。迫使模型做出决定。
4. 为模式属性添加描述。模型将这些视为指令。
5. 除非必要，避免联合类型（oneOf/anyOf）。它们增加解码复杂度。
6. 对数字设置最小值/最大值。捕捉幻觉出的极端值。
7. 对数组使用 minItems/maxItems 以防止空或无限输出。

## 常见失败模式及修复

- **模型将 JSON 包裹在 markdown 围栏中**：从基于提示切换到 JSON 模式或模式模式
- **模式有效但事实错误**：在提取后添加 LLM 作为评判的验证步骤
- **枚举值不一致**：切换到约束解码或添加后处理标准化
- **缺少可选字段**：设为必填或在应用代码中添加默认值
- **提取非常慢**：约束解码增加 5-15% 延迟，如对延迟敏感则降低模式复杂度
- **带有不同项的大型数组**：分块输入并按块提取，然后合并结果

## 可靠性阶梯

| 方法 | 解析成功率 | 模式匹配率 | 设置工作量 |
|----------|-------------|-------------|-------------|
| 基于提示 | ~90% | ~80% | 1 分钟 |
| JSON 模式 | 100% | ~90% | 5 分钟 |
| 模式模式 | 100% | ~99% | 15 分钟 |
| 约束解码 | 100% | 100% | 30 分钟 |
| Instructor + 重试 | 100% | ~99.5% | 10 分钟 |
