# 推理技术选择指南

当需要 LLM 进行推理时，在编写提示之前选择技术。技术决定推理架构。提示填充内容。

## 快速决策树

1. 任务是简单的事实查找或单步分类？
   - 是：使用**零样本**。CoT 增加成本而无准确率增益。
   - 否：继续。

2. 任务是否需要多步推理（数学、逻辑、规划）？
   - 是：使用**思维链**。继续第 3 步。
   - 否：如果格式重要使用**少样本**，否则使用零样本。

3. 单个推理错误可接受吗？
   - 是：使用**少样本 CoT**（单样本，温度 0.0）。
   - 否：使用**自一致性**（N=5，温度 0.7）。继续第 4 步。

4. 问题是具有许多可能路径的搜索/规划问题吗？
   - 是：使用**思维树**。
   - 否：自一致性已足够。

5. 任务是否需要外部信息或计算？
   - 是：使用**ReAct**（推理 + 工具调用）。
   - 否：纯推理技术已足够。

## 技术矩阵

| 技术 | 准确率提升 | 成本乘数 | 延迟 | 最适合 |
|-----------|--------------|-----------------|---------|----------|
| 零样本 | 基线 | 1x | ~1s | 简单任务、事实问答 |
| 少样本 | +5-15% | 1.2x | ~1s | 格式匹配、分类 |
| 零样本 CoT | +10-20% | 1.3x | ~1.5s | 快速推理提升 |
| 少样本 CoT | +15-25% | 1.5x | ~2s | 数学、逻辑、多步 |
| 自一致性（N=5） | +2-5% 相对于 CoT | 5x | ~5s | 高风险推理 |
| 自一致性（N=10） | +1-2% 相对于 N=5 | 10x | ~10s | 仅关键决策 |
| 思维树 | 任务依赖 | 10-40x | ~30s+ | 搜索、规划、谜题 |
| ReAct | 任务依赖 | 3-10x | ~5-15s | 知识基础任务 |
| 提示链 | +5-10% 相对于单次 | 2-5x | ~5-10s | 复杂多部分任务 |

## 模型特定指导

### GPT-4o / GPT-4.1
- 强基线推理。零样本 CoT 通常足够。
- 3 个示例的少样本 CoT 在 GSM8K 上达到 95%。
- 自一致性带来边际收益（95% 到 97%）——仅对关键任务值得。
- 原生支持结构化输出以提取答案。

### Claude 3.5 Sonnet / Claude 3.7 Sonnet
- 擅长遵循结构化提示格式（XML 标签）。
- 带 XML 分隔示例的少样本 CoT 效果最佳。
- 扩展思考（Claude 3.7）是原生 CoT——无需提示。
- 自一致性有效，因为 Claude 在温度 0.7 时推理变化良好。

### Llama 3.1/3.3 70B
- 从少样本 CoT 中获益最多（与零样本相比准确率差距更大）。
- 推理任务推荐 N=5 的自一致性。
- 需要比商业模型更明确的格式指令。
- ToT 在本地推理上成本高——仅考虑批处理。

### Gemini 2.5 Pro
- 开箱即用的多步推理能力强。
- 思考模式提供内置 CoT，无需提示工程。
- 少样本示例对格式一致性而非准确率更有帮助。
- 大上下文窗口（1M）使示例丰富的少样本变得实用。

## 反模式

**简单任务的 CoT**：问"2+2 等于多少？让我们逐步思考"浪费 token。模型在没有推理轨迹的情况下也能正确完成简单算术。CoT 在有 3+ 步时需要。

**温度 0.0 下的自一致性**：所有 N 个样本都相同。必须使用温度 > 0（推荐 0.5-0.8）以获得多样化的推理路径。

**对一切使用 ToT**：ToT 需要 O(b^d) 次 LLM 调用，其中 b=分支因子，d=深度。b=3、d=3 的树最多需要 39 次调用。保留给更便宜的技术失败的问题。

**带错误示例的少样本**：带有推理错误的示例教会模型犯这些错误。每个示例必须验证。一个错误示例可能比零个示例造成更大的准确率下降。

**没有一致格式提取答案**：自一致性需要跨样本比较答案。如果答案格式各异（"$18"、"18 美元"、"十八"），投票会失败。始终强制执行："答案是 [数字]。"

## 成本优化

对于每天处理 10,000 次查询的生产系统，使用 GPT-4o 定价（$2.50/1M 输入，$10/1M 输出）：

| 技术 | 平均 Token/查询 | 每日成本 | 准确率 |
|-----------|-----------------|------------|----------|
| 零样本 | ~200 | ~$5 | 78% |
| 少样本 CoT | ~600 | ~$15 | 95% |
| 自一致性（N=5） | ~3,000 | ~$75 | 97% |
| ToT（b=3, d=2） | ~6,000 | ~$150 | 任务依赖 |

对于大多数应用来说成本最优策略：从少样本 CoT 开始。仅对置信度低的查询添加自一致性。

## 与提示链的集成

推理技术与提示链组合：

**链第 1 步**（提取）：零样本，温度 0.0
**链第 2 步**（推理）：少样本 CoT，温度 0.0
**链第 3 步**（验证）：自一致性，N=3，温度 0.7

这个三步链成本约为单次 CoT 调用的 3 倍，但能捕捉提取错误、推理错误，并从验证步骤提供置信度分数。

## 何时超越提示工程

如果您花在工程提示上的时间多于编写应用程序代码，考虑：

1. **微调**：如果您有 500+ 个标注示例且任务狭窄
2. **DSPy 编译**：如果您想要自动提示优化
3. **智能体框架**：如果任务需要多轮工具使用（第 14 课）
4. **RAG**：如果模型需要访问私有/当前知识（第 06-07 课）

提示技术是基础。它们适用于任何模型、任何提供者，且不需要训练数据。但它们有局限性。知道何时升级到下一级别与掌握技术本身同样重要。
