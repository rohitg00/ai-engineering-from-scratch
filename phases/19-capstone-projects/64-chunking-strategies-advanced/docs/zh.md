# 切片策略比一比

> 切片決定了你的檢索器有可能浮現出什麼。邊界一畫錯，沒有任何嵌入模型、任何重排器、任何 LLM 修得好下游的損害。

**類型：** 實作
**程式語言：** Python
**先修單元：** 階段 11 第 04（嵌入）、06（RAG）、07（進階 RAG）課；階段 19 B 軌基礎（第 20-29 課）
**時間：** 約 90 分鐘

## 學習目標
- 從零實作五種切片策略：固定窗口、句子、遞迴切分、語意分群，以及結構化 markdown 標題。
- 在一份帶黃金標註答案跨度的固定語料上量測 recall@k，並解釋為什麼某一種策略在散文上勝出、另一種在技術文件上勝出。
- 讀懂片段長度分布，並認出每一種策略所注入的失敗模式：孤兒句、切在符號中間、只有標題的片段、語意漂移。
- 不必跑基準，只要檢視三項性質就替一份新語料挑出預設值：文件型別、平均段落長度，以及那個格式有沒有帶明確結構。

## 問題所在

每一條 RAG 管線都從把來源文件切成片段開始，這些片段要小到嵌入模型塞得下、又要大到每一片都承載一個自足的想法。「在哪裡切」這個選擇不是一個超參數。它是檢索器有可能回傳什麼的上界。

一個問「那個預算中止門檻長什麼樣」的查詢，只有在「持有那個中止門檻的片段」搆得到時才可能成功。若固定窗口切分器把那個門檻值從周圍脈絡裡切開了，那個嵌入就移到另一個聚類、BM25 分數就掉下去、重排器看到的是雜訊，而 LLM 生成的答案就錯了。2024 年那篇〈LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs〉量到，光是切片選擇就造成檢索召回率 35 個百分點的絕對擺動。2025 年關於脈絡化片段標頭的後續研究縮小了那個差距，但沒有把它關掉。

這一課把五種策略並排建出來、拿它們去跑一份帶黃金標註答案跨度的固定語料，並讓你自己去讀那些召回率數字。

### 固定窗口

那個暴力基線。每 N 個字元切一刀。可選擇性地重疊，好讓在位置 N 被切開的句子，完整地出現在從位置 N - overlap 開始的那個片段裡。快、確定性，在邊界上糟透了。把它當成對照組，不是預設值。

### 句子

用正規表示式或一台簡單狀態機在句子邊界上切分。把一句或多句打包進一個片段，直到一個目標字元預算為止。不會切在字中間。但仍會切在段落中間與章節中間。這是許多早期 RAG 管線的預設值，對於沒有其他結構的散文而言是個合理選擇。

### 遞迴切分

那個由 2023 年代函式庫推廣起來的階層策略。先試著在最強的分隔符上切（雙換行、段落），不行就退到下一個（單換行），再退到句子，再退到字元。當片段塞進預算時遞迴就終止。對於結構不一致的文件很強，因為它逐區域地調適。

### 語意分群

把每一句都嵌入。把共享一個主題質心的相鄰句子聚成一群。只要對質心的運行相似度掉到門檻以下就切一刀。那些邊界反映的是意義，不是字元。建起來比較慢、也依賴那個嵌入模型，但對「在段落內部就轉換主題」的文件很有韌性。

### 結構化 markdown 標題

對於帶明確結構的文件（markdown、reStructuredText、RFC 風格的編號章節），在標題邊界上切。每個片段就是那個標題，加上它底下一直到下一個同級或更高級標題之前的所有東西。每個主題的片段最小，但只有在語料格式良好時才用得上。

### recall@k 怎麼量那個邊界選擇

一個黃金標註的查詢，帶著答案跨度在來源文件中的精確字元偏移量。切片之後，你問：檢索器回傳的前 k 個片段裡，有沒有任何一個與那個黃金跨度重疊？有的話，那個查詢的 recall@k 就是 1。沒有的話就是 0。在整個查詢集上取平均。對每一種策略跑同一份評估，那個差距就會讓你看出哪一套邊界政策挺得過你手上這份語料。

## 動手實作

`code/main.py` 實作：

- `fixed_window(text, size, overlap)` —— 那個基線。
- `sentence_chunks(text, target)` —— 簡單的句子打包器。
- `recursive_split(text, separators, target)` —— 階層式遞迴。
- `semantic_chunks(text, similarity_threshold)` —— 建在一個確定性模擬嵌入之上、以質心為基礎的分群。
- `structural_markdown(text)` —— 感知標題的切分器。
- `mock_embed(text, dim)` —— 一個以雜湊為基礎的嵌入，好讓這條迴路離線跑得起來。
- `DenseIndex` —— 與階段 19 B 軌那堂混合檢索課相同的形狀。
- `eval_recall(strategy, corpus, queries, k)` —— 那條比較迴路。
- 一個 `main()`，在那份固定語料上跑過每一種策略，並印出一張 recall@k 的表。

跑它：

```bash
python3 code/main.py
```

輸出是一張小表，每種策略一列、每個 k 一欄。句子在結構化的固定語料上輸掉。結構化 markdown 在 markdown 固定語料上勝出。遞迴在混合固定語料上撐得住，因為那個遞迴會調適。語意分群在散文固定語料上勝出，因為那裡沒有有用的結構線索。

## 那張表藏不住的失敗模式

**孤兒句。** 句子打包產出的片段漏掉了主題句。那個嵌入於是指向錯的聚類。

**切在符號中間。** 固定窗口在程式碼或 YAML 裡會把一個識別字劈成兩半。那兩半嵌出來的是雜訊。

**只有標題的片段。** 結構化 markdown 會產出一個只含 `## Title` 的片段。把它們濾掉，或把下一個片段的第一段接上去。

**語意漂移。** 當語料整體都在同一個主題上時，語意分群會切得不夠。一個 5000 字元的片段，把許多具體答案塞進一個瀰散的嵌入裡。把語意與一個硬性字元上限結合起來。

**過期的嵌入。** 語意分群用了一個嵌入模型。你若換了模型，就也換了那些片段。把切片模型與檢索模型分開釘住，或把索引一起重建。

## 不跑基準也挑得出預設值

有三項性質決定一份新語料的預設切片器。

| 性質 | 值 | 預設 |
|----------|-------|---------|
| 文件型別 | 沒有結構的散文 | 遞迴切分，目標 800 |
| 文件型別 | Markdown / RFC / API 文件 | 結構化 markdown |
| 文件型別 | 程式碼 | 感知 AST 的（超出範圍；見階段 19 第 02 課） |
| 段落長度 | 長、單一主題 | 句子，目標 500 |
| 段落長度 | 短、主題混雜 | 語意，門檻 0.6 |

拿不定主意時，挑遞迴切分。它是最強的單一策略基線。

## 框架應用

生產模式：

- 出貨一條新管線之前先跑那份評估；不要信任你的函式庫預設給的那個策略。
- 每次你換嵌入模型或換語料組合時就重跑那份評估；贏家是隨語料而定的。
- 把策略名稱持久化到每個片段的中繼資料裡，好讓你日後能替退化歸因。

## 練習

1. 加上第六種策略：用 `tiktoken` 而不是字元數的詞元窗口。在同一份固定語料上與固定窗口比較。
2. 往散文固定語料裡注入 30% 比例的程式碼區塊。重跑那張表。解釋為什麼除了結構化 markdown 之外，每一種策略的召回率都掉了。
3. 把那個確定性嵌入換成你專案裡真實供應商的那個。量測語意分群的召回率差值。回報各策略之間的差距是變寬還是變窄。
4. 替每個片段加上一個 `summary` 欄位：一句話的質心描述。把摘要附在片段本體上再重跑那份評估。量測召回率的提升。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|-----------------|------------------------|
| Recall@k | 「我們有沒有拿到對的片段？」 | 前 k 個片段中有任一個與黃金答案跨度重疊的查詢比例 |
| 片段重疊 | 「滑動窗口」 | 把前一個片段最後 N 個字元重新收進下一個片段 |
| 結構化切分器 | 「感知標題的片段」 | 在 H1/H2/H3 邊界上切；標題文字是片段的一部分 |
| 語意切片器 | 「感知主題的片段」 | 把句子嵌入、依質心相似度分群、在漂移處切開 |
| 質心漂移 | 「主題轉換」 | 運行平均與下一句之間的餘弦相似度掉過某個門檻 |
