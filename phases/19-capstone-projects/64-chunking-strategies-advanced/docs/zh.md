# 分块策略对比

> 分块决定了检索器能够触及的上限。切分边界一旦有误，任何嵌入模型、重排序器乃至大语言模型都无法在下游弥补这一破坏。

**类型：** 动手构建
**语言：** Python
**前置知识：** 阶段 11 第 04 课（嵌入）、第 06 课（RAG）、第 07 课（高级 RAG）；阶段 19 Track B 基础（第 20-29 课）
**时长：** ~90 分钟

## 学习目标

- 从头实现五种分块策略：固定窗口、句子、递归切分、语义聚类以及结构化的 Markdown 标题。
- 在包含黄金标注答案片段的测试语料库上测量 recall@k，并能解释为何一种策略在散文任务中胜出而另一种策略在技术文档中胜出。
- 阅读分块长度分布图，识别每种策略注入的失败模式：孤立句、符号中间截断、纯标题块、语义漂移。
- 无需运行基准测试，通过检查三个属性（文档类型、平均段落长度、格式是否携带显式结构）即可为新语料库选择一个默认分块器。

## 问题

每一个 RAG 流水线都从将源文档切成小片段开始——小到嵌入模型能够容纳，大到每个片段承载一个自洽的思想。切割位置的选择不是一个超参数；它是检索器永远无法突破的上限。

如果查询问的是"预算中止阈值是怎样的"，那么这个阈值所在的分块必须能被检索到才能成功。如果固定窗口切分器将阈值值与周围上下文切开了，嵌入就会移动到不同的聚类，BM25 分数会下降，重排序器看到的是噪声，LLM 生成的答案就是错的。2024 年的论文《LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs》测量到，仅凭分块选择就能让检索召回率产生 35 个百分点的绝对波动。2025 年关于上下文分块标题的后续工作缩小了这一差距，但并未消除。

本课将并行构建五种策略，在带有黄金标注答案片段的测试语料库上运行，并让你亲自读取召回率数据。

### 固定窗口

最暴力的基线方法。每 N 个字符切一刀。可选择设置重叠，使得在位置 N 被切断的句子能够完整地出现在从位置 N - overlap 开始的分块中。速度快、确定性强、边界处理能力差。把它当作对比基准，而非默认方案。

### 句子

通过正则表达式或简单的状态机按句子边界切分。将若干句子打包进一个分块，不超过目标字符预算。不会在单词中间截断，但仍可能在段落中间和章节中间截断。是许多早期 RAG 流水线的默认方案，对于没有其他结构的散文来说是一个合理的选择。

### 递归切分

由 2023 时代的库推广的分层策略。首先尝试用最强的分隔符（双换行、段落）切分，退而求其次用次强的（单换行），然后是句子，最后是字符。递归在分块满足预算时终止。对于结构不一致的文档表现强劲，因为它能按区域自适应。

### 语义聚类

对每个句子进行嵌入。将共享主题质心的连续句子聚类。当当前句子与质心的相似度低于阈值时进行切分。边界反映的是语义而非字符。构建速度较慢且依赖于嵌入模型，但对于在段落内切换主题的文档具有鲁棒性。

### 结构化 Markdown 标题

对于携带显式结构的文档（Markdown、reStructuredText、RFC 风格编号章节），按标题边界切分。每个分块包含标题及其下直到同级或更高级别标题之前的所有内容。每个主题的分块最小，但仅当语料库结构良好时才可用。

### recall@k 如何衡量边界选择

一条经过黄金标注的查询携带着答案片段在源文档中的精确字符偏移位置。分块后，你要问的是：检索器返回的前 k 个分块中，是否有任何一个与黄金片段重叠？如果是，该查询的 recall@k 为 1；否则为 0。对所有查询取平均值。对每种策略运行相同的评估，差值就能反映出哪种边界策略在你拥有的语料库上表现最佳。

## 动手构建

`code/main.py` 实现了：

- `fixed_window(text, size, overlap)` —— 基线方法。
- `sentence_chunks(text, target)` —— 简单句子打包器。
- `recursive_split(text, separators, target)` —— 分层递归。
- `semantic_chunks(text, similarity_threshold)` —— 基于确定性模拟嵌入的质心聚类。
- `structural_markdown(text)` —— 标题感知切分器。
- `mock_embed(text, dim)` —— 基于哈希的嵌入，使循环可在离线状态下运行。
- `DenseIndex` —— 与阶段 19 Track B 混合检索课程中使用的相同结构。
- `eval_recall(strategy, corpus, queries, k)` —— 比较循环。
- `main()` —— 在测试语料库上运行所有策略并打印 recall@k 表格。

运行方式：

```bash
python3 code/main.py
```

输出是一个小表格，每一行是一种策略，每一列是一个 k 值。句子策略在结构化语料库上表现不佳。结构化 Markdown 在 Markdown 语料库上获胜。递归切分在混合语料库上表现尚可，因为递归具有自适应性。语义聚类在没有有用结构线索的散文语料库上获胜。

## 表格不会隐藏的失败模式

**孤立句。** 句子打包可能产生缺失主题句的分块，导致嵌入指向错误的聚类。

**符号中间截断。** 在代码或 YAML 中使用固定窗口切分会将标识符切成两半，两半都变成噪声嵌入。

**纯标题块。** 结构化 Markdown 可能产生只包含 `## Title` 的分块。应过滤掉这些块，或者附加下一个分块的第一段。

**语义漂移。** 当语料库主题高度统一时，语义聚类倾向于欠切分。一个 5000 字符的分块将许多具体答案压缩成一个模糊的嵌入。建议将语义聚类与硬性字符上限结合使用。

**陈旧嵌入。** 语义聚类使用了嵌入模型。如果更换模型，分块也会随之改变。请将分块模型与检索模型分开固定，或者一起重建索引。

## 不运行基准测试如何选择默认方案

三个属性决定新语料库的默认分块器。

| 属性 | 取值 | 默认方案 |
|----------|-------|---------|
| 文档类型 | 无结构的散文 | 递归切分，目标 800 |
| 文档类型 | Markdown / RFC / API 文档 | 结构化 Markdown |
| 文档类型 | 代码 | AST 感知（超出范围；见阶段 19 第 02 课） |
| 段落长度 | 长段落、单一主题 | 句子，目标 500 |
| 段落长度 | 短段落、混杂主题 | 语义，阈值 0.6 |

如有疑问，选择递归切分。它是最强的单一策略基线。

## 使用

生产环境的最佳实践：

- 在发布新流水线之前运行评估；不要相信库默认的分块策略。
- 每当更换嵌入模型或语料库构成发生变化时，重新运行评估；胜出策略是语料库相关的。
- 将策略名称持久化保存在每个分块的元数据中，以便日后追溯回归问题。

## 练习

1. 增加第六种策略：使用 `tiktoken` 而不是字符数的 token 窗口。在同一语料库上与固定窗口进行比较。
2. 在散文语料库中注入 30% 的代码块。重新运行表格。解释为什么除结构化 Markdown 之外的所有策略召回率都下降。
3. 将确定性嵌入替换为你项目实际使用的嵌入提供者。测量语义聚类的召回率差值。报告各策略之间的差距是扩大还是缩小。
4. 为每个分块增加一个 `summary` 字段：一句话的质心描述。将摘要附加到分块正文后重新运行评估。测量召回率的提升。

## 关键术语

| 术语 | 表面含义 | 实际含义 |
|------|-----------------|------------------------|
| Recall@k | "我们找到了正确的分块吗？" | 前 k 个分块中任意一个与黄金答案片段重叠的查询占比 |
| 分块重叠 | "滑动窗口" | 将前一个分块的最后 N 个字符重新包含到下一个分块中 |
| 结构化切分器 | "标题感知分块" | 在 H1/H2/H3 边界处切分；标题文本属于分块的一部分 |
| 语义分块器 | "主题感知分块" | 嵌入句子，按质心相似度聚类，在漂移处切分 |
| 质心漂移 | "主题切换" | 运行均值与下一个句子之间的余弦相似度低于阈值 |
