# 管線平行與氣泡分析

> 張量平行把矩陣乘法切給各 rank。管線平行把模型切給各 rank，一個 rank 一個階段。微批次流過那條管線。開頭與結尾那段空著的時間就是氣泡；把它最小化就是全部的手藝。

**類型：** 實作
**程式語言：** Python
**先修單元：** 階段 19 C 軌第 42-49 課
**時間：** 約 90 分鐘

## 學習目標

- 把一個序列模型切成 N 個階段，並在 N 個 rank 上模擬一條前向管線。
- 用 GPipe 排程（只做前向的填滿，然後才反向）把 M 個微批次排過那條管線，並算出氣泡比例。
- 把氣泡拿去與 Megatron-LM 和 PipeDream 所用的交錯式 1F1B 排程比較。
- 替階段指派辯護：每個階段運算量相等，比每個階段參數量相等更要緊。

## 問題所在

一個 fp16 的 700 億參數模型，光是參數就要 140 GB。沒有消費級 GPU 裝得下。ZeRO-3 把參數切給各 rank，但每一次前向仍然需要每個 rank 把整層 allgather 起來，於是逐層付出 log(N) 跳。管線平行走另一條路：把模型切成 N 個階段，每個 rank 放一個階段。第 1 層的前向在 rank 0 上結束，把那個激活張量交給 rank 1；rank 1 跑第 2 層再交給 rank 2；依此類推。反向反著流。記憶體線性下降，因為每個 rank 只持有一個階段；運算是序列的，那就是氣泡問題。

氣泡是管線開頭（等第一個微批次抵達最後一個階段）與結尾（等最後一個微批次排空回來）的閒置時間。在 M 個微批次與 N 個階段之下，每個階段的氣泡比例是 (N-1)/(M+N-1)。在 M=8、N=4 時那是 27%。在 M=64、N=4 時是 4.5%。當你每一步有很多微批次時氣泡就縮小，那代表每個微批次的批次大小要小，而那正是驅動微批次設計的那項限制。

### GPipe 排程

在開始任何反向之前，先用全部 M 個微批次把管線前向填滿；然後反著排空。每一個微批次的激活都必須保留到它的反向為止，所以記憶體隨 M 線性成長。前向花 M+N-1 個週期，反向再花 M+N-1 個。每個階段有用的工作是 2M 個週期；每個階段的氣泡是 2(N-1) 個週期。當每一次前向與反向各花一單位時間時，氣泡比例是 (N-1)/(M+N-1)。把 M 挑得遠大於 N，就把氣泡藏起來了。

### 1F1B 排程

交錯：一個微批次的前向一抵達最後一個階段，就開始它的反向，讓它串流回去。那個排程在每個階段上一前向、一反向地交替。氣泡仍然是 N-1，但激活記憶體被管線深度框住，而不是被微批次數框住。生產管線用 1F1B（Megatron、PipeDream）。這一課先實作 GPipe，因為它比較簡單，1F1B 則當作練習。

### 為什麼每個階段運算量相等很要緊

若階段 0 花 50 毫秒、階段 1 花 100 毫秒，每一個週期都被階段 1 卡住。其他階段每個週期閒置 50 毫秒等階段 1 放行。參數量相等是錯的那條軸：一個 transformer 的運算由逐層的注意力加 MLP 主導，而嵌入層參數很多、運算卻很少。階段指派該讓每個階段的 FLOPs 相等，而不是權重相等。

### 微批次與批次

一條管線跑 M 個大小各為 B 的微批次。有效批次大小是 M*B。一次管線步驟結束時的梯度，是那 M*B 個合起來的樣本上的梯度。氣泡比例取決於 M；最佳化器看到的是 M*B。調 M 就是拿氣泡（M 高則低）去換每個微批次的記憶體（在 GPipe 上 M 高則激活記憶體高）。

## 動手實作

`code/main.py` 實作：

- `PipelineStage`：一個小小的 `nn.Module`，持有一個階段的參數並暴露 `forward(activation)`。
- `Pipeline(stages, num_microbatches)`：用每個階段的模擬實際時間，在模擬階段上編排那套 GPipe 排程。
- `bubble_fraction(num_stages, num_microbatches)`：封閉解 (N-1)/(M+N-1)。
- 一個四階段示範，印出逐微批次的軌跡與量到的氣泡比例。

跑它：

```bash
python3 code/main.py
```

輸出：一張「階段 × 微批次」的甘特圖，以及氣泡百分比對照那個封閉解預測值。

## 現實世界裡的生產模式

有三種模式，把管線平行加固到足以出貨。

**激活檢查點與管線配成一對。** 在 GPipe 上有 M 個微批次在飛時，激活記憶體是一個微批次的 M 倍。激活檢查點在反向時重算前向，拿運算換記憶體；正是這個組合讓管線在長序列上變得可行。

**階段平衡是量出來的，不是假設出來的。** 生產團隊會跑一趟剖析，在目標硬體上量出實際的逐層運算（FLOPs 與實際時間），然後依那次量測分割。Megatron-LM 的 `--num-layers-per-stage` 旗標接受一份清單，好讓各階段逐層成本不同時能有不均等的層數。

**send-recv 排程必須避開死鎖。** 一條「每個階段都先送再收」的管線會在線路上死鎖。標準修法是交錯：偶數 rank 的階段先送再收，奇數 rank 的階段先收再送。這一課把 rank 明確排程出來，好讓那個樣式看得見。

## 框架應用

生產模式：

- **Megatron-LM。** 大規模管線平行的那份參考。用 1F1B，並支援張量 + 管線 + 資料平行的組合。
- **DeepSpeed Pipeline。** 與 ZeRO 整合；ZeRO-1 + 管線是最大那些開放模型的常見組合。
- **PyTorch Pipe。** PyTorch 原生的管線包裝，建在 `torch.distributed.pipeline.sync.Pipe` 之上。

## 練習

1. 實作 1F1B，並驗證氣泡比例與 GPipe 相符、但激活記憶體被框住了。
2. 在一個更深的模型上剖析真實的逐階段時間，並依量到的實際時間重新平衡階段。
3. 跨管線微批次加上梯度累積，並檢查那個梯度等於等價的全批次前向所給的梯度。
4. 把管線與激活檢查點配成一對，量測記憶體下降相對於運算成本。
5. 把管線與 DDP 結合（每個管線 rank 跨一個資料平行群組被複製），並把那個二維排程推理一遍。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| 管線 | 「沿深度做模型平行」 | 一個 rank 一個階段，激活一階段一階段地流 |
| 氣泡 | 「管線閒置時間」 | 開頭與結尾那 (N-1) 步裡，某些階段沒有工作 |
| 微批次 | 「批次的一片」 | 一個前向／反向單位；M 變大氣泡就縮小 |
| GPipe | 「先填滿再排空」 | 在任何反向之前先做完 M 次前向；激活記憶體高 |
| 1F1B | 「交錯排程」 | 每個階段一前向一反向；激活記憶體有上界 |
