# 流水线并行与气泡分析

> 张量并行将矩阵乘法拆分到多个秩上。流水线并行将模型按层拆分到多个秩上，每个秩负责一个阶段。微批次在流水线中流动。开始和结束时的那段空闲时间就是气泡；最小化气泡是整个技术的核心。

**类型：** 构建
**语言：** Python
**前置条件：** 第 19 阶段 Track C 第 42–49 课
**时长：** ~90 分钟

## 学习目标

- 将一个顺序模型拆分为 N 个阶段，并在 N 个秩上模拟前向流水线。
- 使用 GPipe 调度（先完成所有前向填充，再执行反向）调度 M 个微批次通过流水线，并计算气泡占比。
- 将气泡占比与 Megatron-LM 和 PipeDream 中使用的交错式 1F1B 调度进行比较。
- 论证阶段分配原则：每个阶段计算量均等比每个阶段参数量均等更重要。

## 问题

一个 700 亿参数的模型在 fp16 下仅参数就需要 140 GB。没有消费级 GPU 能装下它。ZeRO-3 将参数分片到多个秩上，但每个前向步骤仍需每个秩对完整层进行 allgather 操作，每层付出 log(N) 次通信开销。流水线并行走了一条不同的路：将模型切分为 N 个阶段，每个秩放一个阶段。第 1 层的前向在秩 0 上完成后，将激活张量传递给秩 1；秩 1 运行第 2 层，再传递给秩 2；以此类推。反向则相反方向流动。内存线性下降，因为每个秩只持有自己那一阶段；计算是顺序的，这就带来了气泡问题。

气泡是流水线开始时的空闲时间（等待第一个微批次到达最后一个阶段）和结束时的空闲时间（等待最后一个微批次反向流回）。对于 M 个微批次和 N 个阶段，每个阶段的气泡占比为 (N-1)/(M+N-1)。当 M=8、N=4 时约为 27%；当 M=64、N=4 时约为 4.5%。当每个步骤的微批次较多时气泡就会缩小，这意味着每个微批次的批尺寸较小，这正是驱动微批次设计的约束条件。

```mermaid

  R1 --> R2[秩 2: 阶段 2 / 层 2]
  R2 --> R3[秩 3: 阶段 3 / 损失]

  R1 -.反向.-> R0
```

### GPipe 调度

先让所有 M 个微批次向前填充流水线，再开始任何反向；然后反向逐次排空。每个微批次的激活必须保留到其反向执行，因此内存随 M 线性增长。前向需要 M+N-1 个周期，反向又需要 M+N-1 个周期。每个阶段的有效工作为 2M 个周期；每个阶段的气泡为 2(N-1) 个周期。假设每个前向和反向各占一个时间单位，则气泡占比为 (N-1)/(M+N-1)。选择远大于 N 的 M 可以隐藏气泡。

### 1F1B 调度

交错执行：一旦某个微批次的前向到达最后一个阶段，立即开始它的反向，让它流回。调度在每个阶段上交替执行一次前向和一次反向。气泡仍然是 N-1，但激活内存受限于流水线深度，而非微批次数量。生产级流水线使用 1F1B（Megatron、PipeDream）。本课先实现 GPipe，因为它更简单，再以练习形式实现 1F1B。

### 为什么每个阶段计算量均等重要

如果阶段 0 耗时 50 毫秒，阶段 1 耗时 100 毫秒，那么每个周期都被阶段 1 阻塞。其他阶段每个周期空闲 50 毫秒等待阶段 1 释放。参数量均等是错误的衡量标准：Transformer 的计算量主要由每层的注意力加 MLP 决定，而嵌入层虽然参数多，但计算量很小。阶段分配应均衡每个阶段的 FLOPs，而非每个阶段的权重数量。

### 微批次与批次

流水线运行 M 个微批次，每个批尺寸为 B。有效批尺寸为 M×B。流水线步骤结束时的梯度是 M×B 个样本合并后的梯度。气泡占比取决于 M；优化器看到的是 M×B。调节 M 意味着在气泡（M 高时气泡小）与每个微批次的内存（GPipe 下 M 高时激活内存大）之间做权衡。

## 生产环境中的实际模式

三种模式让流水线并行足够稳健、可供部署。

**激活检查点与流水线配合使用。** 在 GPipe 中有 M 个微批次同时运行的情况下，激活内存为 M 乘以一个微批次的激活量。激活检查点在反向时重新计算前向结果，用计算换内存；这种组合使得流水线对于长序列也变得可行。

**阶段平衡靠测量而非臆断。** 生产团队会运行一个性能分析（profiling）过程，在目标硬件上测量每层的实际计算量（FLOPs 和墙钟时间），然后根据测量结果进行划分。Megatron-LM 的 `--num-layers-per-stage` 参数接受一个列表，允许在各阶段每层计算成本不同时使用不均匀的层数分配。

**发送-接收调度必须避免死锁。** 如果流水线中每个阶段都是先发送再接收，则会在通信线上死锁。标准解决方法是交错执行：偶数秩的阶段先发送后接收，奇数秩的阶段先接收后发送。本课通过显式调度各秩，使该模式清晰可见。

## 实际应用

生产模式：

- **Megatron-LM**：大规模流水线并行的参考实现。使用 1F1B 调度，支持张量并行 + 流水线并行 + 数据并行组合。
- **DeepSpeed Pipeline**：与 ZeRO 集成；ZeRO-1 + 流水线是最大开源模型的常见组合。
- **PyTorch Pipe**：PyTorch 原生流水线封装，基于 `torch.distributed.pipeline.sync.Pipe`。

## 关键术语

| 术语 | 常说的意思 | 实际含义 |
|------|-----------|---------|
| 流水线（Pipeline） | "沿深度方向的模型并行" | 每个秩一个阶段，激活在阶段之间流动 |
| 气泡（Bubble） | "流水线空闲时间" | 开始和结束时 (N-1) 个步骤中某些阶段无工作可做 |
| 微批次（Microbatch） | "批次的一个切片" | 一次前向/反向的单位；M 增大时气泡缩小 |
| GPipe | "先填充后排空" | 所有 M 个前向完成后才开始反向；激活内存高 |
| 1F1B | "交错调度" | 每个阶段一次前向一次反向交替进行；激活内存有界 |
