给定一个 PDF 语料库（10-K 报告、科学论文、扫描文档），构建一个管道，使用 ColPali 风格的后期交互将页面作为图像索引，并以页面级证据区域回答问题。

构建计划：

1. 使用 PyMuPDF 以 180 DPI 将每个 PDF 页面渲染为 1536x2048 的 PNG。
2. 使用 ColQwen2.5-v0.2 或 ColQwen3-omni 嵌入每个页面。将多向量补丁嵌入存储在 Vespa、Qdrant multi-vector 或 AstraDB 中。
3. 应用 DocPruner 风格的 50% 补丁剪枝。验证在 ViDoRe v3 上的准确率下降保持在 0.5% 以内。
4. 查询时：嵌入查询令牌；对每个页面的补丁计算 MaxSim；排序前 k 个。
5. 使用 Qwen3-VL-30B 或 Gemini 2.5 Pro 进行合成，传入查询加前 5 个页面图像。要求引用 `(doc_id, page, region)` 锚点。
6. 对于公式或表格密集的页面，运行 Nougat 或 dots.ocr 作为可选的文本通道，与图像一起提供。
7. 构建一个 Next.js 15 查看器，在源页面上以边界框形式叠加证据区域。
8. 在 ViDoRe v3 和 M3DocVQA 上评估。生成一个内容类别 × 方法对比矩阵，比较视觉优先 vs OCR-然后文本在纯文本、表格、图表、手写和公式上的表现。

评估量规：

| 权重 | 标准 | 衡量方法 |
|:-:|---|---|
| 25 | ViDoRe v3 / M3DocVQA 准确率 | 在匹配页面上对比 OCR-然后文本基线的基准测试 |
| 20 | 证据区域定位 | 包含答案跨度（span）的引用区域比例 |
| 20 | 存储和延迟工程 | DocPruner 压缩率、索引 p95、答案 p95 低于 2s |
| 20 | 多页面推理 | 在手工标注的 100 问题多页面集上的准确率 |
| 15 | 源检查用户体验 | 覆盖层保真度、比较工具、逐页浏览器 |

硬性拒绝：

- 将 OCR 文本改造到单向量嵌入中，号称"视觉优先"的 OCR 优先管道。
- 任何丢弃补丁级边界框导致无法渲染证据覆盖层的系统。
- 未记录 DocPruner 设置的情况下报告的存储数字。

拒绝规则：

- 拒绝在没有专门编辑策略的情况下索引扫描的法律合同。ColQwen 嵌入会泄露内容。
- 拒绝查询用户未披露的语料库。审计追踪在受监管领域是强制性的。
- 拒绝未在同一语料库上运行两个管道的情况下与 OCR-然后文本进行比较。

输出：一个包含摄取管道、Vespa（或 Qdrant multi-vector）配置、100 问题多页面评估集、查看器 UI 以及一份包含内容类别 × 方法矩阵和关于哪些内容类别在 2026 年仍然适合 OCR-然后文本的具体建议的仓库。
