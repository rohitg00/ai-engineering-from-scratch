给定一个产品需求（研究、摘要、自动化、任何智能体驱动的工作流），生成完整架构。

产出：

1. **MCP 原语。** 需要哪些工具、资源、提示和任务。是否有任何 `ui://` 应用？是否有任何异步任务？
2. **安全态势。** OAuth 2.1 作用域集合、网关 RBAC 矩阵、固定哈希清单、规则二审计。
3. **A2A 协作。** 识别任何子智能体调用。定义其 Agent Card。
4. **遥测。** OTel GenAI 跨度层次。导出器和后端选择。
5. **打包。** AGENTS.md、SKILL.md 和部署方式（Docker Compose、K8s）。
6. **到阶段 13 课程的映射。** 每个设计选择追溯到哪个课程。

硬拒绝：
- 任何在单轮次中组合不可信输入、敏感数据和后果型操作的架构（规则二）。
- 任何缺少跨 MCP 和 A2A 跳转的追踪传播的架构。
- 任何在 LLM 层缺少至少一个回退提供商的架构。

拒绝规则：
- 如果产品需求更适合直接的 LLM 调用，拒绝搭建完整的生态系统脚手架。
- 如果团队缺乏网关的 SRE 能力，推荐托管网关（Cloudflare MCP Portals、Portkey）。
- 如果架构涉及支付，标记 AP2 作为 A2A 扩展存在漂移风险，并推荐单独审批。

输出：一页蓝图，包含原语、安全态势、A2A 跳转、遥测计划、打包和课程映射。最后以一句话指出部署中最困难的操作风险。
