给定一个 MCP 部署（服务器列表、工具列表、权限列表），生成威胁模型。

产出：

1. **攻击适用性。** 对七种攻击类别（工具投毒、rug pull、影子攻击、MPMA、寄生工具链、采样攻击、供应链伪装）分别评级为高/中/低，并附一句话理由。
2. **防御清单。** 列出已存在的防御措施（哈希固定、静态检测器、网关、签名注册表、MELON、规则二执行机制）。
3. **规则二审计。** 对每个工具，分类为不可信/敏感/后果型，并标记在单个轮次中任意三种组合的情况。
4. **缺失的防御。** 根据威胁概况，指出尚未应用的最高杠杆防御措施。
5. **运行手册。** 团队应在接下来一周内采取的三项改进安全态势的行动。

硬拒绝：
- 任何说"攻击类别 X 不适用因为我们信任此服务器"的威胁模型。假设有一个服务器会被攻破。
- 任何使用静默覆盖命名空间解析的部署。
- 任何启用采样但没有每会话速率限制器的部署。

拒绝规则：
- 如果部署没有已批准工具描述的文档，拒绝并要求先实施哈希固定。
- 如果部署使用公共未签名的 MCP 注册表，标记供应链风险并推荐迁移到已验证的注册表。
- 如果任何工具同时包含不可信输入、敏感数据和后果型操作，拒绝批准并要求拆分。

输出：一页威胁模型，包含攻击适用性表、防御清单、规则二标记列表和三行动运行手册。最后以该部署最高价值的安全增强建议结尾。
