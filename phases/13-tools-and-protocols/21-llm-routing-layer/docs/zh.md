# LLM 路由层 — LiteLLM、OpenRouter、Portkey

> 供应商锁定成本高昂。不同的工具调用工作负载适合不同的模型。路由网关提供统一的 API 接口、重试机制、故障转移、成本追踪和安全护栏。2026 年三大主流方案：LiteLLM（开源自托管）、OpenRouter（托管 SaaS）、Portkey（生产级，2026 年 3 月开源）。本课将阐述决策标准，并实现一个标准库路由网关。

**类型：** 学练
**语言：** Python（标准库，路由 + 故障转移 + 成本追踪）
**前置要求：** 阶段 13 · 02（函数调用）、阶段 13 · 17（网关）
**时长：** 约 45 分钟

## 学习目标

- 区分自托管、托管和生产级路由方案。
- 实现一个按定义优先级顺序在供应商故障时重试的回退链。
- 跨供应商追踪每次请求的成本和 token 用量。
- 根据给定的生产约束条件，在 LiteLLM、OpenRouter 和 Portkey 之间做出选择。

## 问题场景

供应商路由在以下场景中至关重要：

1. **成本。** Claude Sonnet 的成本是 Haiku 的 3 倍。对于分流任务，Haiku 足够；对于综合任务，Sonnet 才值得。按请求路由。

2. **故障转移。** OpenAI 故障一小时，每个请求都失败。你希望自动回退到 Anthropic，而无需重新部署。

3. **延迟。** 实时聊天 UI 需要极快的首 token 响应时间，而批量摘要生成则不需要。按延迟 SLA 路由。

4. **合规。** 欧盟用户的数据必须留在欧盟区域。按区域路由。

5. **实验。** 在同一工作负载上对两个模型进行 A/B 测试。按测试分组路由。

每次集成都手写这些逻辑是重复劳动。路由网关提供一个与 OpenAI 兼容的统一 API，其余工作都由它处理。

## 概念

### OpenAI 兼容的代理形态

所有人都采用 OpenAI 的接口形式。路由网关暴露 `/v1/chat/completions`，接受 OpenAI 格式的请求，并在内部代理到 Anthropic / Gemini / Cohere / Ollama / 任何服务。客户端无需关心后端是谁。

### 模型别名

你的代码中使用 `our_smart_model` 而非 `claude-3-5-sonnet-20251022`。网关将别名映射到真实模型。当 Anthropic 推出 Claude 4 时，你只需在服务端更改别名映射，代码完全无需改动。

### 回退链

```
primary: openai/gpt-4o
on 5xx: anthropic/claude-3-5-sonnet
on 5xx: google/gemini-1.5-pro
on 5xx: refuse
```

网关通过配置文件定义此链。重试次数受预算限制，以防止回退级联导致成本失控。

### 语义缓存

完全相同或近乎相同的提示词命中的是缓存而非供应商。在重复的 Agent 循环中，可节省 30% 到 60% 的费用。缓存键基于嵌入向量；近乎相同的提示词共享同一个缓存槽位。

### 安全护栏

网关级别：

- **PII 脱敏。** 在发送提示词之前，通过正则或基于 ML 的方法进行处理。
- **策略违规。** 拒绝含有违禁内容的提示词。
- **输出过滤。** 清理补全结果以防信息泄露。

Portkey 和 Kong 都内置了明确的安全护栏。LiteLLM 将其作为可选功能。

### 按密钥限流

一个 API 密钥 = 一个团队。按密钥设定预算可防止单个团队消耗共享配额。大多数网关都支持此功能。

### 自托管 vs 托管权衡

| 因素 | LiteLLM（自托管） | OpenRouter（托管） | Portkey（生产级） |
|--------|----------------------|----------------------|----------------------|
| 代码 | 开源，Python | 托管 SaaS | 开源（2026 年 3 月）+ 托管 |
| 部署 | 部署代理 | 注册账号 | 两者皆可 |
| 供应商 | 100+ | 300+ | 100+ |
| 计费 | 使用自己的密钥 | OpenRouter 积分 | 使用自己的密钥 |
| 可观测性 | OpenTelemetry | 仪表盘 | 完整 OTel + PII 脱敏 |
| 最适合 | 希望完全控制的团队 | 快速原型开发 | 需要合规的生产环境 |

当你有 SRE 团队且需要数据主权时，LiteLLM 是优选。当你希望单一订阅且无需管理基础设施时，OpenRouter 是优选。当你开箱即用就需要安全护栏和合规性时，Portkey 是优选。

### 成本追踪

每个请求都携带 `provider`、`model`、`input_tokens`、`output_tokens`。乘以每种模型每 token 的价格（来自网关维护的定价表）。支持按用户 / 按团队 / 按项目汇总。

### MCP + 路由

网关可以同时路由 LLM 调用和 MCP 采样请求。当采样请求的 modelPreferences 指定了特定模型时，网关会将其转换为对应的后端。这是阶段 13 · 17（MCP 网关）与本课的路由网关有时合并为一个服务的交汇点。

### 路由策略

- **静态优先级。** 列表中的第一个优先；出错时回退。
- **负载均衡。** 轮询或加权分配。
- **成本感知。** 选择满足延迟/质量要求的最便宜模型。
- **延迟感知。** 选择过去 N 分钟内最快的模型。
- **任务感知。** 提示词分类器将编码类请求路由到一个模型，将摘要类请求路由到另一个模型。

## 使用

`code/main.py` 用约 150 行代码实现了一个路由网关：接受 OpenAI 格式的请求，转换为各供应商的桩代码，运行优先级回退链，追踪每次请求的成本，并对输入进行 PII 脱敏处理。通过三种场景运行它：正常请求、主供应商故障触发回退、被脱敏机制捕获的 PII 泄露。

需要关注的部分：

- `ROUTES` 字典：别名 → 按优先级排序的具体供应商列表。
- 在 5xx 错误时重试的回退循环。
- 成本追踪器将 token 用量乘以各模型费率。
- PII 脱敏器在转发前清除类似社保号的模式。

## 产出

本课产出 `outputs/skill-routing-config-designer.md`。根据工作负载特征（延迟、成本、合规性），该技能会选定 LiteLLM / OpenRouter / Portkey 并生成相应的路由配置。

## 练习

1. 运行 `code/main.py`。触发故障场景，确认回退落在第二个供应商上，并且成本计算正确。

2. 添加语义缓存：以提示词的 SHA256 作为查找键；缓存命中后直接返回。在重复调用中测量成本节省。

3. 添加一个提示词分类器，将 "code ..." 类提示词路由到偏向智能的别名，将 "summarize ..." 类提示词路由到偏向速度的别名。

4. 设计按团队预算：每个团队有月度支出上限；一旦达到上限，网关拒绝该团队的请求。选择一种执行粒度（按请求或按时间窗口）。

5. 横向对比阅读 LiteLLM、OpenRouter 和 Portkey 的文档。指出每个方案独有的、其他两个方案没有的功能。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| 路由网关 | "LLM 代理" | 位于多个供应商前面的统一 API 接口层 |
| OpenAI 兼容 | "遵循 OpenAI 格式" | 接受 `/v1/chat/completions` 格式，转换为任意后端 |
| 模型别名 | "our_smart_model" | 代码中的名称，由网关映射到具体模型 |
| 回退链 | "重试列表" | 按顺序尝试的供应商列表，失败时依次切换 |
| 语义缓存 | "提示词嵌入缓存" | 键为提示词的嵌入向量；近似重复共享缓存命中 |
| 安全护栏 | "输入/输出过滤器" | 脱敏 PII，拒绝策略违规 |
| 按密钥限流 | "团队预算" | 绑定到 API 密钥的配额 |
| 成本追踪 | "每次请求花费" | token 用量 × 各模型单价汇总 |
| LiteLLM | "开源代理" | 可自托管的开源路由网关 |
| OpenRouter | "托管 SaaS" | 基于积分的托管网关 |
| Portkey | "生产级方案" | 开源 + 托管，内置安全护栏 |
