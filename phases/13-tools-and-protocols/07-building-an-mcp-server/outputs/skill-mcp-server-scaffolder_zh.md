给定一个领域（笔记、工单、文件、数据库，或其他），产出一份 MCP 服务器计划：将哪些能力暴露为工具、哪些为资源、哪些为提示，并附带到 Python 或 TypeScript SDK 的升级路径。

产出：

1. **工具列表。** 用户明确请求执行的原子操作。包含名称、描述（何时使用模式）、输入 schema 和注释提示。
2. **资源列表。** 用户想要读取的数据。URI 方案、MIME 类型，以及是否启用 `resources/subscribe`。
3. **提示列表。** 宿主应作为斜杠命令暴露的可复用模板。参数列表。
4. **能力声明。** 服务器在 `initialize` 中返回的确切 `capabilities` 对象。
5. **升级说明。** 每个部分的 FastMCP（Python）或 TypeScript SDK 等价物。指出一个替代脚手架中手写 stdlib 模式的 SDK 特性（例如 `lifespan`、`context`）。

硬拒绝：
- 任何仅作为工具而非资源暴露的"数据库查询"。正确的拆分是：`/list` 和 `/read` 用资源，带参数的 `/query` 用工具。
- 任何将用户输入工具与特权工具混合在同一个命名空间内但没有标注的服务器。
- 任何声称具有 `resources/subscribe` 能力但没有持久通知机制的服务器脚手架。

拒绝规则：
- 如果领域没有只读表面，拒绝搭建资源脚手架；推荐仅工具服务器。
- 如果领域没有自然的斜杠命令模板，拒绝搭建提示脚手架。
- 如果用户要求提供认证方案，拒绝并引导至阶段 13 · 16（OAuth 2.1）。

输出：一页服务器计划，包含三个原语列表、能力对象以及一个 10 行示例 `@app.tool()` 装饰器风格的升级代码片段。最后以服务器应设置的最重要注释标志结尾。
