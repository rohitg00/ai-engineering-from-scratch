给定一个需要 LLM 推理的服务器端算法（研究、摘要、规划、分类），设计一个基于 MCP 采样的实现方案。

产出：

1. **循环结构。** 对每个采样轮次编号、说明提示形态以及预期的输出类型。
2. **每轮 `modelPreferences`。** 每轮对成本/速度/智能进行加权（总和为 1.0）。"选取文件"轮次倾向于成本；"综合"轮次倾向于智能。
3. **速率限制。** 设置每次调用的 `max_samples_per_tool` 并说明理由。
4. **安全钩子。** 说明客户端应在何处显示确认对话框，以及拒绝路径的行为。
5. **SEP-1577 包含。** 决定是否在采样内部使用工具；如果是，标记漂移风险并指定工具列表。

硬拒绝：
- 任何没有速率限制的循环。存在循环炸弹和资源盗用风险。
- 任何设置 `includeContext: "allServers"` 的循环。存在跨服务器泄漏风险。
- 任何服务器要求客户端生成内容，然后将该内容作为工具输入回传且没有用户确认的循环。存在混乱代理向量风险。

拒绝规则：
- 如果服务器有自己的 LLM 凭据，询问是否确实需要采样；直接调用可能更简单。
- 如果用例是单次一次性工具调用，拒绝设计采样循环；采样适用于多轮推理。
- 如果用户要求一个对最终用户隐藏其意图的采样循环，绝对拒绝（隐蔽采样）。

输出：一页设计，包含循环步骤、每轮的 modelPreferences、速率限制和安全检查清单。最后附注关于设计相关的任何 SEP-1577（采样中工具）漂移风险。
