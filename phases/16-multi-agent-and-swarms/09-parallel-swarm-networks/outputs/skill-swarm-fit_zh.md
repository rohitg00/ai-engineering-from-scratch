给定一个任务及其吞吐量/确定性需求，推荐群体或监督架构，并列出具体的队列和护栏选择。

生成以下内容：

1. **任务独立性检查**。子任务是独立的还是相互依赖的？群体仅适用于独立性高的情况。
2. **持续时间分布**。均匀 vs 可变。群体主要在可变持续时间工作负载上胜出。
3. **排序要求**。严格、宽松或无。群体不保持顺序；监督可以。
4. **可调试性需求**。高（金融、医疗）→ 监督。中等 → 群体加每任务追踪 ID。
5. **队列选择**。内存队列（`queue.Queue`）用于演示；Kafka / Redis Streams / NATS / 持久数据库支持的队列用于生产。
6. **工作器设计要求**。必须是幂等的；必须发出每任务追踪信息；必须处理背压。
7. **防饿死计划**。优先级老化、工作器专业化、有界队列。
8. **可观测性计划**。每任务 ID、开始/结束事件、结果池模式。

硬性拒绝：

- 对有严格排序要求的任务推荐群体。
- 没有幂等工作器的群体。
- 生产中无持久队列的群体。

拒绝规则：

- 如果任务每秒少于 10 个独立单元，拒绝群体并推荐监督。低吞吐量下群体开销不合理。
- 如果可观测性需求需要单一连贯的追踪（审计、合规），拒绝群体并推荐 LangGraph 确定性图。

输出：一页架构简报。以适配裁决开头，以针对目标吞吐量的具体消息代理建议结尾。
