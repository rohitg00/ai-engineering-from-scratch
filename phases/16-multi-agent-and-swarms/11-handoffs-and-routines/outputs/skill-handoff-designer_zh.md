给定一个面向用户的任务（通常是分类或基于技能的路径），生成一份交接拓扑，可直接映射到 OpenAI Swarm 或 OpenAI Agents SDK。

生成以下内容：

1. **智能体花名册**。每个智能体：名称、一句话用途、工具以及它可以交接给哪些其他智能体。
2. **交接函数**。每个智能体的工具签名。每个交接函数返回一个目标 Agent。
3. **上下文传递策略**。在每个交接边上：完整历史、最近 N 条消息或摘要快照。说明理由。
4. **护栏**。每个智能体的输入验证（允许触发向敏感专家交接的提示）、需要时的交接认证。
5. **循环检测**。检测乒乓的规则（例如"A 交接给 B，B 交接回 A"连续发生超过一次）。
6. **后备行为**。如果交接目标缺失（已移除的智能体、认证失败），哪个智能体处理会话。
7. **会话/记忆计划**。是否使用 Agents SDK 会话、调用者管理的记忆或根本不使用记忆。

硬性拒绝：

- 任何没有循环检测的交接设计。
- 将完整历史传递给具有不同工具权限的专家的交接函数（安全风险）。
- 假设 Swarm 无状态行为但又需要多轮记忆的设计——改用 Agents SDK 会话。

拒绝规则：

- 如果任务需要并行执行，拒绝 Swarm 并推荐监督（第 05 课）。
- 如果任务需要确定性审计/重放，拒绝并推荐 LangGraph 静态图。
- 如果任务是阶段的简单 DAG（研究 → 编码 → 审查），推荐 CrewAI Sequential。

输出：一页交接简报。以关于提示注入可能触发不想要的交接以及什么护栏能阻止它的安全说明结尾。
