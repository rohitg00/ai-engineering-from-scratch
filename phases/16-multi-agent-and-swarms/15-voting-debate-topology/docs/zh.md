# 投票、自洽性与辩论拓扑

> 最廉价的聚合方式：采样 N 个独立智能体，多数投票。Wang 等人 2022 年的自洽性方法仅用一个模型采样 N 次即实现了这一思想。多智能体将其扩展为**异构**智能体以摆脱单一文化——不同模型、不同提示词、不同温度、不同上下文。除了多数投票，辩论拓扑同样关键：MultiAgentBench（arXiv:2503.01935，ACL 2025）评估了星形/链形/树形/图形的协调方式，发现**图形在研究类任务上最优**，并存在约 4 个智能体之后的"协调税"。AgentVerse（ICLR 2024）记录了两种涌现模式——志愿者行为与从众行为——而从众既是优势（达成共识）也是风险（群体思维，见第 24 课）。本课将绘制拓扑空间地图，构建每种变体，并衡量协调税。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置要求：** 阶段 16 · 07（思维社会与辩论），阶段 16 · 14（共识与拜占庭容错）
**时长：** 约 75 分钟

## 问题

辩论可以提升准确率（Du 等人，arXiv:2305.14325），也可能降低准确率。辩论是否有益取决于四个结构选择：

1. 谁与谁对话（拓扑）。
2. 进行多少轮（Du 2023：轮数和智能体数量各自独立影响结果）。
3. 智能体是否异构（不同的基础模型打破单一文化）。
4. 是否存在对抗性声音（钢盔式论证 vs. 稻草人式论证）。

那些简单将"运行 5 个智能体并投票"嫁接给任务的团队，其表现往往不如单个智能体。这些失败并非随机，而是与拓扑和异构性密切相关。本课即是这份拓扑地图。

## 概念

### 自洽性——单模型基线

Wang 等人 2022 年（《自洽性提升思维链推理能力》）在温度 > 0 的条件下对同一模型采样 N 次，并对推理路径的答案进行多数投票。在 GSM8K 上的结果表明：与单次贪婪解码相比，N=40 个样本带来了显著提升。自洽性是单智能体向多智能体投票过渡的前身。

局限：自洽性只使用一个基础模型。其错误在构造上就是相关的。如果模型存在系统性偏差，所有 N 个样本都将共享这一偏差。

### 多智能体投票——异构扩展

将 N 个样本替换为 N 个**不同**的智能体。不同的基础模型（Claude、GPT、Llama），不同的提示词，不同的工具访问权限。优势在于：不相关的错误。代价在于：不同智能体的成本不同，协调它们会带来额外开销。

2026 年异构辩论的规范名称是 **A-HMAD**——对抗性异构多智能体辩论（Adversarial Heterogeneous Multi-Agent Debate）。虽然尚未被普遍采用，但已有论文使用该术语来描述"不同模型进行辩论，从而减少因单一文化崩溃而产生的关联错误"。

### 四种拓扑

```
star（星形）        chain（链形）        tree（树形）        graph（图形）

    ┌─A─┐           A─B─C─D         ┌──A──┐              A───B
    │   │                           │     │              │ × │
    B   C                           B     C              D───C
    │   │                          / \   / \
    D   E                         D   E F   G           （全连接）
```

- **星形**：一个中心枢纽，其他所有智能体只与中心通信。相当于监督者-工作者模式，无反向通道。
- **链形**：线性结构，每个智能体只能看到前一个的输出。类似流水线。
- **树形**：分层结构，用于分层智能体系统（第 06 课）。
- **图形**：任意对任意通信。包括全连接团和任意有向无环图。

### 协调税（MultiAgentBench）

MultiAgentBench（MARBLE，ACL 2025，arXiv:2503.01935）在包含研究、编码和规划的任务套件上对星形、链形、树形、图形进行了基准测试。关键测量结果：

- **图形**拓扑在研究类任务上最优。信息可以任意流通；智能体可以相互批评。
- **星形**拓扑在快速回答事实性任务上最优。中心枢纽负责过滤和整合。
- **链形**拓扑在逐步流水线（分阶段精炼）上最优。
- **协调税**在图形拓扑中约 4 个智能体之后开始显现。墙钟耗时和 Token 成本的增长速度超过质量提升。

4 个智能体的上限是经验性的，而非根本性限制。它反映了 2026 年 LLM 的上下文容量：每个智能体的上下文被同伴的输出填满，一旦每个人都能看到所有人，增加第 N+1 个智能体的边际价值就会下降。

### 多智能体辩论策略（"我们该 MAD 吗？"）

arXiv:2311.17371 是 2023 年对 MAD（多智能体辩论）策略的综述。被其他研究重复验证的关键发现：那些在**结构上**类似于自洽性（独立采样 + 聚合）的 MAD 变体，在使用相同预算时往往表现不如自洽性。MAD 在智能体真正异构且辩论具有对抗性结构（一个智能体持反对意见）时最为有效。

### AgentVerse 涌现模式

AgentVerse（ICLR 2024，https://proceedings.iclr.cc/paper_files/paper/2024/file/578e65cdee35d00c708d4c64bce32971-Paper-Conference.pdf）记录了两种即使没有明确设计也会从多智能体辩论中涌现的行为：

- **志愿者行为**。智能体主动提供帮助（"我可以进行下一步"）。这很有用：它能将子任务分配给最合适的智能体。
- **从众行为**。智能体调整自身立场以匹配批评者，即使批评者是错的。这是辩论环境中的奉承等效行为（第 14 课）。

从众行为正是为何"辩论至一致"会奖励霸凌者。通过设置有限轮次并引入独立裁判可以缓解这一问题。

### 异构性——真正影响准确率的调节旋钮

2024-2026 年实践文献中的一个模式：将 N 个智能体中的一个替换为不同的基础模型，其带来的准确率提升比简单增加一个智能体（N+1）更大。其直觉在于单一文化——每个新的独立错误源的价值高于一个额外的关联样本。

在极限情况下，异构性胜过数量。在大多数具有清晰正确答案的任务上，三个不同的模型胜过五个相同模型的副本。

### 陪审团方法

Sibyl 框架（在 Minsky-LLM 文献中被引用）形式化了"陪审团"的概念——一组小型专业化智能体，在每个阶段通过投票来优化答案。与简单的多数投票不同，陪审团具有角色分工：一个智能体负责交叉审问，一个提供上下文，一个评估可信度。陪审团方法是普通投票（廉价但易陷入单一文化）与完整 MAD（昂贵且易陷入从众）之间的中间方案。

### 何时投票加辩论占优

- 问题有明确正确答案（事实、数学、代码行为）。投票收敛具有意义。
- 智能体可以访问不同的数据源或工具（异构性可用）。
- 轮次有限（通常 2-3 轮），且存在独立的裁判或验证器。
- 预算允许 3-5 个智能体。在图形拓扑中超过 5-7 个后，协调税将占主导。

### 何时投票加辩论有害

- 问题是观点性的。智能体会趋同于看起来最自信的答案，而非最正确的答案。
- 所有智能体共享同一个基础模型。单一文化使共识失去意义。
- 轮次无限制。从众行为将每次都获胜。
- 任务过于简单。使用单个智能体配合 N=5 的自洽性更便宜且同样准确。

## 动手构建

`code/main.py` 实现了：

- `run_star(agents, hub, question)`——中心枢纽轮询每个工作者并聚合结果。
- `run_chain(agents, question)`——顺序精炼。
- `run_tree(root, children, question)`——深度为 2 的分层聚合。
- `run_graph(agents, question, rounds)`——全对全辩论，有限轮次。
- 脚本化的异构性调节旋钮：每个智能体具有一个 `error_bias` 来表示其系统性错误倾向。
- 测量框架：在 N=3、5、7 下运行每种拓扑，并报告（准确率、token 总量、模拟墙钟耗时）。

运行：

```
python3 code/main.py
```

预期输出：一张拓扑 × N →（准确率、token 数、延迟）的表格。在研究类任务上，图形在 N=3-5 时表现最佳；在快速事实性任务上，星形表现最佳；图形在 N=7 时显示出协调税（延迟的增长速度快于准确率）。

## 使用它

`outputs/skill-topology-picker.md` 是一个技能文件，它读取任务描述并推荐拓扑（星形/链形/树形/图形）、N（智能体数量）、异构性配置（使用哪些基础模型）以及轮次上限。

## 交付它

对于任何集成方案：

- 从使用一个强基础模型的 **N=5 自洽性**开始。这是廉价的基线。
- 如果准确率很重要，升级为 **N=3 的异构投票**。衡量提升幅度。
- 仅在任务具有结构（研究、多步骤）且有限轮次可行时，升级为**辩论拓扑**。
- 始终记录少数派集群。当少数派持续正确时，就获得了多样性信号。
- 将墙钟耗时和 token 数量与准确率一同作为基准。"以 10 倍成本换取更高准确率"是一个商业决策。

## 练习

1. 运行 `code/main.py`。绘制图形拓扑的协调税曲线：准确率 vs N，token 数 vs N。曲线在哪个 N 处发生拐点？
2. 实现 A-HMAD：三个具有不同偏差的智能体。与第 14 课中的单一文化攻击相比，全相同偏差基线与 A-HMAD 的表现如何？
3. 为图形拓扑添加一个"裁判"角色，该角色不投票，仅对最终共识评分。这是否改变了涌现的从众行为？
4. 阅读 AgentVerse 论文（ICLR 2024）。识别你的实现最强烈表现出的涌现行为。能否通过改变提示词来诱导出相反的行为？
5. 阅读 MultiAgentBench（arXiv:2503.01935）第 4 节（拓扑实验）。使用你的测试框架复现论文中一个任务上的"图形在研究类任务上最优"的结果。

## 关键术语

| 术语 | 人们通常说的 | 实际含义 |
|------|------------|---------|
| 自洽性 (Self-consistency) | "采样 N 次，投票" | Wang 2022。单模型，N 个温度>0 的样本，对推理路径进行多数投票。 |
| 异构性 (Heterogeneity) | "不同模型" | 不同基础模型或提示词族的集成。打破单一文化。 |
| MAD | "多智能体辩论" | 智能体之间进行多轮批评交换的通用术语。见 Du 2023。 |
| A-HMAD | "对抗性异构 MAD" | 强调不同模型加对抗性结构的 MAD 变体。 |
| 拓扑 (Topology) | "谁与谁对话" | 星形、链形、树形、图形。决定了信息流动方式。 |
| 协调税 (Coordination tax) | "收益递减" | 在图形上约 4 个智能体后，成本增长速度超过质量提升。 |
| 志愿者行为 (Volunteer behavior) | "主动帮助" | AgentVerse 涌现模式：智能体主动提出执行某一步骤。 |
| 从众行为 (Conformity behavior) | "压力下同意" | AgentVerse 涌现模式：智能体与批评者保持一致。 |
| 陪审团 (Jury) | "小型专业化小组" | Sibyl 风格的集成，具有角色分工（审查员、上下文提供者、评分员）。 |
