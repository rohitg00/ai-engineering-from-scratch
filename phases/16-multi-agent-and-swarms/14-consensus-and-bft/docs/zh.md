# 代理的共識與拜占庭容錯

> 經典分散式系統的 BFT 撞上隨機的 LLM。2025-2026 年冒出三個研究方向：**CP-WBFT**（arXiv:2511.10400）用一個信心探針替每一票加權；**DecentLLMs**（arXiv:2507.14928）走無領導者路線，讓 worker 平行提案並用幾何中位數彙整；**WBFT**（arXiv:2505.05103）把加權投票與階層式結構分群結合，把節點切成 Core 與 Edge。〈Can AI Agents Agree?〉（arXiv:2603.01213）誠實的實證結果是：今天就連純量層級的一致都很脆弱 —— 單一個帶欺瞞性的代理就能攻陷一個 Mixture-of-Agents。BFT 是必要的，但不是充分的。這一課建出一套最小的 BFT 協定、注入三種代理專屬的攻擊（拜占庭謊言、奉承式從眾、相關誤差的單一栽培），並量測每種共識變體如何應付。

**類型：** 學習 + 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 16 · 07（心智社會與辯論）、階段 16 · 13（共享記憶）
**時間：** 約 75 分鐘

## 問題

你有 N 個 LLM 代理，各自產出一個答案。它們意見不合。多數決挑到了錯的那個，因為其中兩個代理是相關的（同一個基礎模型、同一批訓練資料、同樣的失敗模式）。第三個代理剛好以一種新奇的方式答錯 —— 所以那個多數是一個假多數。

現在加一個欺瞞性代理：它故意說謊。或加一個奉承性代理：它同意最後發言的那個人。在經典 BFT 裡，假設是拜占庭節點占比 `f < n/3` 且行為任意。2026 年的現實則是：LLM 節點就算誠實也是隨機的、跨模型是相關的，而且會被彼此的輸出影響。你不能把它們當成獨立的伯努利投票者。

經典 BFT（PBFT，1999）並沒有錯 —— 它只是不完整。它處理任意的位元翻轉。它不處理「三個誠實的代理因為共用訓練資料而共享同一個幻覺」。這一課從 PBFT 的地基出發，往上疊三項 2025-2026 年的調適。

## 概念

### 經典 BFT 給了你什麼

實用拜占庭容錯（Castro 與 Liskov，OSDI 1999）能容忍 `f < n/3` 的拜占庭節點。這套協定有三個階段（pre-prepare、prepare、commit）與兩個原語（簽章訊息、法定人數憑證）。在 `n >= 3f + 1` 個誠實或惡意節點之間，對單一個值達成一致。

那些保證很強，但假設了：

1. **故障是獨立的。** 拜占庭節點不會串通。
2. **誠實節點是真的誠實。** 誠實輸出的正確性不是問題；協定只負責把分歧對齊。
3. **這個問題有基準真值答案。** 對一個錯誤事實達成共識，那也還是共識。

LLM 代理違反這三項。跑同一個基礎模型的兩個代理共享故障。一個「誠實的」LLM 仍然會產生幻覺。而在含糊的問題上，「真理」就是代理們決定的東西 —— 沒有外部神諭。

### 三種 LLM 專屬的攻擊

**拜占庭謊言。** 一個代理輸出一個刻意錯誤的答案。若 `f < n/3`，經典 BFT 處理得了。

**奉承式從眾。** 一個代理在投票前先讀其他人的答案，然後跟最後發言者對齊。不是惡意，但會與最大聲的那個聲音相關。經典 BFT 防不了這件事，因為那個代理通過了每一項簽章檢查。

**相關誤差的單一栽培。** 三個代理共用一個基礎模型。它們幻覺出同一個錯答案。多數是錯的。經典 BFT 幫不上忙，因為那三個都「誠實地」同意。

### 2025-2026 年的回應

**CP-WBFT**（arXiv:2511.10400）—— 信心探針加權的 BFT。每位投票者在答案上附一個信心探針（自我回報的機率，或另一個校準模型的預測）。票的權重隨信心縮放。在完全圖上回報 +85.71% 的 BFT 改善。緩解對象：奉承式從眾（從眾的代理，對自己主動提出的立場往往信心偏低）。

**DecentLLMs**（arXiv:2507.14928）—— 無領導者。Worker 代理平行提案、評估者代理替提案評分，最終答案是被評分立場的幾何中位數。在 `f < n/2` 時仍然穩健。緩解對象：拜占庭謊言與相關誤差（幾何中位數對離群值穩健，並拉向密集的那一團，而不是被模型偏誤影響的平均）。

**WBFT**（arXiv:2505.05103）—— 帶階層式結構分群的加權 BFT。票的權重由回應品質加上一個從歷史學來的信任分數決定。把代理分成 Core 與 Edge；Core 代理必須先達成共識，Edge 代理跟隨。緩解對象：擴展性（Core 共識又小又快），以及部分緩解單一栽培（Core 可以挑得有多樣性）。

### 實證：〈Can AI Agents Agree?〉（arXiv:2603.01213）

這篇論文跨多個前沿模型量測純量一致（LLM 代理對單一數值達成一致）。發現令人不安：

- 就算沒有對手，LLM 代理在許多基準上對純量問題的不一致率也超過 30%。
- 單一個採取欺瞞人設的代理，就能把 Mixture-of-Agents 的共識從誠實基線拉開 40 個百分點以上。
- 不一致率與模型多樣性相關 —— 異質集成的不一致比同質集成多（好事：誤差不相關），但也漂移得更慢（壞事：達成一致的時間更長）。

該帶走的是：BFT 給你把輸出對齊的機具，但它不告訴你被對齊的那個輸出是不是對的。要跟查證（階段 16 · 08 角色特化）、多樣性（階段 16 · 15 辯論變體）與評估者代理（階段 16 · 24 基準）結合。

### 那套核心協定，剝到最精簡

給 LLM 代理用的最小 BFT 回合：

```
1. task arrives; each agent i produces answer a_i
2. each agent attaches confidence probe c_i in [0, 1]
3. aggregator collects (a_i, c_i) from all n agents
4. aggregator groups by semantic cluster (equivalent answers)
5. aggregator computes weight for each cluster C:
     w(C) = sum_{i in C} c_i
6. winner = cluster with max weight, if max > threshold * sum(c_i)
   else: retry or escalate
7. minority clusters logged with provenance for post-hoc audit
```

語意分群那一步是 LLM 專屬的轉折。「該研究回報 4.2%」與「改善 4.2%」這兩個答案屬於同一群。天真的字串相等檢查會漏掉這件事。在生產環境中，用一個便宜的嵌入模型或明寫的正規化。

### 門檻調校

`threshold` 這個參數決定何時接受、何時重試。太低：你會接受很弱的多數。太高：你永遠什麼都不接受。經驗範圍：`n=5-7` 個代理時是 0.5-0.67，`n` 更小時要更高。低於門檻就升級給人，或換另一組代理集成。

### 共識幫不上忙的地方

- **含糊的問題。** 若問題沒有基準真值，共識就是一種意見。就那樣稱呼它。
- **複合問題。** 「寫程式碼並解釋它」—— 兩個答案。分別對每一個投票。
- **對抗性的多回合。** 若代理能觀察先前回合並模仿（Du 2023 的辯論），它們就會開始不論真假地彼此同意。要把回合數框住（通常 2-3）。

## 動手實作

`code/main.py` 實作了：

- `AgentVoter` —— 一份帶 (answer, confidence) 的腳本化策略。
- `MajorityVote` —— 經典的相對多數。
- `CPWBFT` —— 帶語意分群的信心加權投票。
- `DecentLLMs` —— 對被評分提案做幾何中位數彙整。
- `Scenario` —— 讓每個彙整器在三種攻擊樣式下各跑一次。

實作的攻擊樣式：

1. `byzantine`：一個代理以高信心說謊。
2. `sycophancy`：一個代理抄它看到的第一個答案，並配上相符的信心。
3. `monoculture`：三個代理共享一個錯答案（相關誤差），信心中等。

跑：

```
python3 code/main.py
```

預期輸出：一張 (攻擊, 彙整器) -> 最終答案的表格，正確答案會被標出來。相對多數在單一栽培那個情況上失敗。CP-WBFT 的信心加權緩解了奉承。當單一栽培不到族群的一半時，DecentLLMs 的幾何中位數會拉向誠實的那一群。

## 框架應用

`outputs/skill-consensus-designer.md` 替一組多代理集成設計共識協定：分群方法、加權、門檻，以及未達門檻回合的升級政策。

## 產出交付

在出貨任何共識機制之前：

- **至少用上面那三種樣式做攻擊測試。** 你的協定應該以可預期的方式失敗，不是無聲失敗。
- **把每一個少數群連同出處記錄下來。** 少數群是你對相關誤差的早期預警系統。
- **強制有界回合。** 不要「一直辯到達成一致」—— 那是在獎勵奉承。
- **把一致與正確分開。** 共識輸出送給一個查證者；查證者獨立於那組集成。
- **監控一致率。** 陡升代表從眾偏誤；陡降代表模型漂移。

## 練習

1. 跑 `code/main.py`。確認相對多數在單一栽培攻擊上失敗，但當單一栽培的信心低於 0.7 時，CP-WBFT 部分緩解了它。
2. 加上第四種攻擊樣式：**沉默棄權** —— 一個代理拒絕回答（「我不知道」）。每個彙整器該怎麼對待棄權？把你的選擇實作出來。
3. 把語意分群從字串正規化換成嵌入相似度（用任何開源嵌入模型）。奉承攻擊會發生什麼變化？
4. 讀 CP-WBFT（arXiv:2511.10400）。實作那個信心探針的校準步驟（用一個獨立的校準模型檢查每個代理自我回報的信心）。量它在單一栽培情境上的準確率增益。
5. 讀〈Can AI Agents Agree?〉（arXiv:2603.01213）。重現一個簡化版的純量一致實驗：三個代理、一道純量問題、那段欺瞞人設的提示詞。CP-WBFT 或 DecentLLMs 抓得到它嗎？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| BFT | 「拜占庭容錯」 | Castro-Liskov 1999 年的協定，在 `f < n/3` 的任意故障下達成共識。 |
| 拜占庭 | 「任何壞行為」 | 一個可以說謊、丟訊息、無聲失效的節點 —— 除了安全崩潰之外什麼都做得出來。 |
| 信心探針 | 「你有多確定？」 | 附在一票上、自我回報或由校準器預測的機率。 |
| 語意分群 | 「同樣的答案、不同的用詞」 | 在計票之前先把等價的答案歸成一群。 |
| 幾何中位數 | 「穩健的中心」 | 使「到各樣本點距離總和」最小的那個點。與平均不同，它對離群值穩健。 |
| 單一栽培 | 「同一個模型、同樣的失敗」 | 代理共用訓練資料或基礎模型時的相關誤差。 |
| 奉承式從眾 | 「同意那個大聲的聲音」 | 一個代理的票偏向最先發言／最大聲的那個人。 |
| Core/Edge | 「階層式 BFT」 | WBFT 的拆分：先做小規模的 Core 共識，Edge 節點跟隨。把延遲框住。 |
