给定一个由 N 个智能体组成、回答一个共同问题的集成，设计一个对三种典型 LLM 智能体攻击（拜占庭谎言、谄媚从众、相关错误单一文化）具有鲁棒性的共识协议。

生成以下内容：

1. **聚类策略**。答案如何分组？字符串规范化（小写 + 去除标点）、带阈值的嵌入相似度或显式结构规范化（JSON 模式）。说明预期的聚类粒度错误率。
2. **加权策略**。多数制（计数）、置信度探测加权（CP-WBFT）、质量加信任（WBFT）或基于评分的中位数几何稳健性（DecentLLMs）。根据攻击概况说明选择理由。
3. **阈值**。总权重达到什么比例时触发接受？低于阈值时：重试、升级还是弃权？
4. **多样性要求**。集成需要多少个基础模型、提示系列或温度设置？单一文化是多数制无法恢复的攻击；多样性是结构性缓解措施。
5. **独立验证器**。是否存在一个获取真实依据（如果可用）或应用评分标准的只读智能体？验证器的输出流向何处？它必须不重新进入投票池。
6. **轮次限制**。在升级前的最大轮数。大多数任务默认为 2-3 轮。更长的轮次会放大谄媚。
7. **攻击测试表格**。对每种攻击（拜占庭、谄媚、单一文化），展示预期的协议行为和残余风险。如果协议承认已知的故障模式，用一句话说明。

硬性拒绝：

- 任何在单一基础模型上仅使用多数制的设计。单一文化使其静默失败。
- 任何无界轮次或"继续辩论直至达成一致"的设计。这会奖励从众。
- 任何验证器输出反馈回投票池的设计。这会毒化验证器。
- 声称 BFT"解决"分歧的说法。BFT 对齐输出；正确性是另一个问题。

拒绝规则：

- 如果任务没有真实依据（观点、综合、创意），如实说明并推荐"共识作为建议，人类作为决策者"。
- 如果可用智能体少于 3 个，共识不适用；推荐单智能体加验证器。
- 如果所有智能体共享一个基础模型且用户无法改变这一点，明确标记单一文化上限。

输出：一页设计简报。以一句话摘要开头（"5 个智能体（3 个基础模型）上的置信度加权投票，语义聚类阈值 0.55，独立验证器重新获取来源，最多 2 轮"），然后是上述七个部分。以攻击测试表格结尾。
