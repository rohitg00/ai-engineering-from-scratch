给定一个新的智能体协议规范，生成 FIPA-ACL 映射，以便读者能够分辨哪些部分是重新发明，哪些是真正的新结构。

生成以下内容：

1. **信封映射**。对于规范定义的每个消息类型，命名最接近的 FIPA 语用行为（`inform`、`request`、`query-if`、`query-ref`、`propose`、`accept-proposal`、`reject-proposal`、`cfp`、`subscribe`、`cancel`、`failure`、`not-understood` 或其他约 20 种之一）。如果没有匹配的语用行为，精确描述差距。
2. **关联模型**。规范如何将请求关联到回复、取消关联到原始请求、流式事件关联到订阅？与 FIPA 的 `:conversation-id` 和 `:reply-with` 字段进行比较。
3. **内容语言立场**。规范是否强制要求内容模式（类型化工件、JSON-Schema）、接受自然语言，还是保持开放？与 FIPA 的 SL0/SL1 和本体字段进行比较。
4. **交互协议库**。哪些 FIPA 交互协议可以在该规范之上实现：合同网、订阅-通知、请求-何时、提议-接受？命名实现每个协议所需的消息。
5. **发现模型**。智能体如何找到对手方和能力（MCP `listTools`、A2A Agent Card、ANP DID + 元协议）？与 FIPA 的目录促进器和黄页服务进行比较。
6. **重新发明 vs 新颖性**。生成一个简短的三列表格：[FIPA 概念、现代规范等效项、变化内容]。将每行标记为 [重新发明] 或 [新颖结构]。只有当规范引入了 FIPA 没有的原语时——去中心化身份、类型化多模态工件和 LLM 可解释内容是常见的候选——该行才是"新颖结构"。

硬性拒绝：

- 任何声称某个规范是"革命性"但没有展示 FIPA 所没有的原语的映射。言语行为理论 + 本体开销是失败模式，而非原语本身。
- 忽略发现层的框架比较。没有发现的规范是不完整的，而非新颖的。
- 诸如"协议 X 取代了 FIPA"的说法，但没有解决两个智能体对内容含义产生分歧时（语义漂移）的问题。

拒绝规则：

- 如果规范尚处于标准化前阶段（草案不足 6 个月、无公开实现），说明映射是临时性的，并标记最可能的三项变化。
- 如果规范是闭源或仅限企业使用（某些 ACP 变体），映射已记录的内容并命名缺口。
- 如果用户仅提供了博客文章（无规范文档），在映射前要求提供规范。

输出：一页简报。以一句话摘要开头（"协议 X 是具有 JSON 语法和基于 DID 的发现层的 FIPA `request`/`subscribe`"），然后是上述六个部分，最后以一段结尾回答："这个规范将重新发现哪个旧的 FIPA 失败模式？"
