# 給 LLM 用的群體最佳化（PSO、ACO）

> 受生物啟發的最佳化正在 LLM 領域重返舞台。**LMPSO**（arXiv:2504.09247）用 PSO，其中每個粒子的速度是一段提示詞，由 LLM 產出下一個候選；在結構化序列輸出（數學運算式、程式）上效果很好。**Model Swarms**（arXiv:2410.11163）把每個 LLM 專家當成模型權重流形上的一個 PSO 粒子，在 9 個資料集上僅用 200 個實例，就回報相對 12 條基線**平均 13.3% 的增益**。**SwarmPrompt**（ICAART 2025）把 PSO + 灰狼演算法混合起來做提示詞最佳化。**AMRO-S**（arXiv:2603.12933）是受 ACO 啟發、用於多代理 LLM 路由的費洛蒙專家 —— **4.7 倍加速**、可解釋的路由證據，以及把推論與學習解耦的品質把關非同步更新。這一課在提示詞參數空間上實作 PSO、在代理路由上實作 ACO，量測這些經典演算法為何適合 LLM 時代，以及何時不適合。

**類型：** 學習 + 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 16 · 09（平行 Swarm 網路）、階段 16 · 14（共識與 BFT）
**時間：** 約 75 分鐘

## 問題

你有一段提示詞，在任務評測上拿 62%。你想改善它。天真的做法是不用梯度的手動微調，那擴展性很差。強化學習需要獎勵訊號，以及足夠多的 rollout 才訓得起來。對提示詞做反向傳播其實不太可能 —— 提示詞是一個離散字串，不是可微分的參數。

經典的生物啟發最佳化 —— 給連續搜尋空間的 PSO、給路徑選擇的 ACO —— 正是為這種情境而設計的：不用梯度、以族群為基礎、每次評估都便宜。把它們跟 LLM 配起來做那個不用梯度的搜尋步驟，你就得到一個出乎意料實用的最佳化器。

同樣的模式也適用於多代理系統中的代理*路由*。一條 ACO 式的費洛蒙軌跡記錄哪個代理在哪種任務型別上表現最好，讓路由器去利用那條軌跡，並讓費洛蒙衰減，好讓路線可以被重新發現。

## 概念

### PSO 複習（Kennedy 與 Eberhart，1995）

粒子群最佳化：連續搜尋空間中的一群粒子。每個粒子有位置 `x_i` 與速度 `v_i`。每次迭代：

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
evaluate fitness(x_i)
update p_best_i if improved
update g_best if global best
```

其中 `p_best` 是粒子自己的最佳、`g_best` 是整群的最佳、`w, c1, c2` 是慣性 + 認知 + 社會權重、`r1, r2` 是隨機因子。

### 在 LLM 輸出上做 PSO —— LMPSO

arXiv:2504.09247 把 PSO 調適到 LLM 生成的結構化輸出（數學運算式、程式）上。每個粒子是一個候選輸出。速度是一段*提示詞*，描述要怎麼把當前輸出往個人／全域最佳修改。LLM 依那段速度提示詞產出新輸出。速度的「慣性」則是像「做小幅漸進的改動」這樣的提示詞。

這在以下情況效果好：
- 輸出是結構化的（可解析、可評估）。
- 適應度是自動的（跑測試、算術求值）。
- 族群很小（約 10-30 個粒子），所以總 LLM 呼叫數仍在可控範圍。

當適應度需要人工審查時它就不好用 —— 每次迭代的成本會變得無法承受。

### Model Swarms

arXiv:2410.11163 把 PSO 從輸出層挪到*模型*層。每個「粒子」是一個專家 LLM（參數）。整群透過一次不用梯度的更新，把參數往集體最佳移動。回報結果：在 9 個資料集上相對 12 條基線平均增益 13.3%，每次迭代只用 200 個實例。

關鍵洞見是：LLM 專家模型在一個共享的參數流形上本來就彼此相鄰（adapter 權重、LoRA delta）。在這個低維子空間上做 PSO 又便宜又有效。

### ACO 複習（Dorigo，1992）

蟻群最佳化：螞蟻走過一張圖；每條路徑有一條費洛蒙軌跡。螞蟻的移動機率依費洛蒙強度加權。完成任務的螞蟻依解的品質比例沉積費洛蒙。費洛蒙隨時間衰減。

### AMRO-S —— 給代理路由用的 ACO

arXiv:2603.12933 用 ACO 做多代理路由。每種任務型別是一個「目的地」；每個代理是一條可能的路線。費洛蒙強化那些產出好輸出的路線。關鍵貢獻：

- **可解釋的路由證據。** 費洛蒙強度是一個人類讀得懂的訊號。
- **品質把關的非同步更新。** 費洛蒙只有在品質檢查通過後才更新，把推論與學習解耦。
- 在多代理路由基準上**加速 4.7 倍**。

那道品質閘門很要緊：沒有它，又快又錯的代理就會累積費洛蒙，而系統會鎖死在壞路線上。

### 什麼時候該替 LLM 用 PSO／ACO

**用 PSO 的時候：**
- 搜尋空間是連續的，或能對映到連續參數（提示詞嵌入、LoRA 權重、數值型的生成參數）。
- 適應度又便宜又自動。
- 族群可以很小（10-30）。

**用 ACO 的時候：**
- 你有一個路由或路徑選擇的問題。
- 決策會隨時間強化（同樣的任務型別會反覆回來）。
- 你需要替路由決策提供可解釋的證據。

**兩者都不要用的時候：**
- 適應度需要人工審查（每次迭代太貴）。
- 搜尋空間是離散且組合式的，而 PSO 涵蓋不了那種形式（改用遺傳演算法）。
- 即時決策需要嚴格延遲（相對於單趟啟發式，PSO/ACO 收斂得慢）。

### 生物啟發為什麼仍然會贏

基於梯度的方法需要可微分的訊號。LLM 的輸出與路由決策並不容易微分。偽梯度方法（強化學習出來的路由器、DPO 式的提示詞調校器）可行，但需要昂貴的訓練。

PSO 與 ACO 只需要一個*評估器*函數。只要你能替一個候選輸出或一次路由決策評分，你就能在那個空間上最佳化。這讓適用門檻低得多。

### 實務上的極限

- **族群預算。** N 個粒子 × T 次迭代 × 每次評估成本。以約每次呼叫 0.02 美元的 LLM 評測來算，20 粒子的 PSO 跑 50 次迭代約需 20 美元。要據此規劃。
- **探索與利用。** 費洛蒙衰減率與 PSO 慣性彼此取捨；衰減太快 → 忘掉解；太慢 → 卡在早期的局部最佳。
- **災難性漂移。** 若適應度地景移動（新的資料分布），兩種演算法都可能先收斂再發散。要監控最佳適應度的穩定性。

## 動手實作

`code/main.py` 實作了：

- `LMPSO` —— 在數值型提示詞參數（temperature、top_k 權重）上做 PSO。每個粒子的「LLM 生成」以一個腳本化的適應度函數模擬。跑 30 次迭代並顯示 g_best 收斂。
- `AMRO_S` —— ACO 式的路由。3 個代理、4 種任務型別、一個費洛蒙矩陣、100 次任務路由。印出 (任務型別 → 代理選擇) 隨時間的分布，以顯示軌跡的形成。
- 比較：在同一條任務流上，隨機路由對上 ACO 路由。量測品質與延遲。

跑：

```
python3 code/main.py
```

預期輸出：
- LMPSO：g_best 適應度在 30 次迭代中從隨機改善到接近最佳。
- AMRO-S：費洛蒙表在每種任務型別上穩定到正確的代理；ACO 路由在品質上勝過隨機約 30-40%，同時也降低延遲（重試更少）。

## 框架應用

`outputs/skill-swarm-optimizer.md` 幫你在 PSO、ACO、遺傳演算法與基於梯度的最佳化器之間，替 LLM／代理的最佳化問題做選擇。

## 產出交付

- **從小開始。** 10-20 個粒子、20-50 次迭代。只有在收斂曲線顯示明確收穫時才放大。
- **每次迭代都記錄費洛蒙或 g_best。** 沒有軌跡就替群體最佳化器除錯，會很痛苦。
- **對更新做品質把關。** 尤其是 ACO 路由：又快又錯的代理不能累積費洛蒙。
- **分布位移時重設衰減。** 當你的評測分布改變時，老舊的費洛蒙就過期了；重設，或暫時把衰減率加倍。
- **替每次迭代的成本設上限。** 輸出一個「每次迭代成本」指標。一次迭代要 500 美元、只換來 0.5% 增益的 PSO 是出不了貨的。

## 練習

1. 跑 `code/main.py`。觀察 LMPSO 的收斂。把族群大小改成 5、10、20、50。到哪個大小時，收斂所需時間就飽和了？
2. 實作一次「災難性漂移」實驗：第 30 次迭代之後，改變適應度函數。PSO 適應得多快？重設 `p_best` 有幫助嗎？
3. 替 AMRO-S 加一道品質閘門：只有評測分數 > 0.7 的執行才沉積費洛蒙。這相對於沒有閘門的版本，如何改變收斂？
4. 讀 LMPSO（arXiv:2504.09247）。把論文裡「速度即提示詞」對映回你的數值速度。模擬中失去了什麼、又保留了什麼？
5. 讀 AMRO-S（arXiv:2603.12933）。實作那條解耦的「推論快路徑」與非同步費洛蒙更新。在持續負載下，這如何改變系統延遲？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| PSO | 「粒子群最佳化」 | Kennedy-Eberhart 1995。以族群為基礎、不用梯度的最佳化器。 |
| ACO | 「蟻群最佳化」 | Dorigo 1992。透過費洛蒙軌跡做路徑／路線最佳化。 |
| LMPSO | 「配上 LLM 生成的 PSO」 | arXiv:2504.09247。速度是一段提示詞；由 LLM 產出候選。 |
| Model Swarms | 「在專家權重上做 PSO」 | arXiv:2410.11163。在模型參數子空間上做不用梯度的更新。 |
| AMRO-S | 「給代理路由用的 ACO」 | arXiv:2603.12933。作用在 任務型別 × 代理 上的費洛蒙矩陣。 |
| p_best / g_best | 「個人／全域最佳」 | 到目前為止找到的、逐粒子與全群的最佳解。 |
| 費洛蒙 | 「路由記憶」 | 某條邊上的強度；隨時間衰減；依品質沉積。 |
| 品質把關的更新 | 「只從好的執行學習」 | 費洛蒙沉積以品質檢查為條件。 |
| 災難性漂移 | 「分布位移」 | 適應度地景改變；舊的 p_best 與費洛蒙變得過期。 |
