给定一个已发布或内部的多智能体基准性能声明，对声明进行评分并揭示注意事项。

生成以下内容：

1. **基准 + 拆分识别**。哪个基准（MARBLE、COMMA、MedAgentBoard、AgentArch、SWE-bench Pro、SWE-bench Verified、自定义）？哪个拆分（完整、保留、污染清理）？未知拆分是不合格的。
2. **污染状态**。基准是否在被测模型的训练截止日期之后？如果基准早于训练截止日期，标记污染风险并对声明打折。
3. **基线质量**。与单 LLM、与随机、与先前的多智能体工作比较。与未调优的同一系统比较不算数；那是消融实验，而非基线。
4. **统计显著性**。N 次试验、置信区间或标准误差、p 值或等效值。没有 N < 50 次试验的统计数据的声明支持不足。
5. **任务多样性**。一个任务、一个领域还是多个？单任务声明不意味着泛化能力。
6. **成本披露**。每任务令牌数、每任务挂钟时间、每任务美元成本。20 倍成本的 90% 解决方案是业务决策；没有成本，声明是不完整的。
7. **字母等级 + 一句话裁决**。

   - **A：** 所有六项检查通过；声明可能是稳健的。
   - **B：** 一项弱点；声明在注明的注意事项下是合理的。
   - **C：** 两项弱点；声明有提示性但需要复现。
   - **D：** 三项或更多弱点；声明不是证据。
   - **F：** 不合格问题（未披露拆分的污染、无统计、无基线）。

硬性拒绝：

- 引用"SWE-bench"而未指定 Verified 与 Pro 的声明。40+ 分的差距使得这种模糊报告不可接受。
- 没有基线比较的声明。"我们的系统达到 X%"是一个数字，而非结果。
- 基于少于 20 次试验的多智能体系统声明。方差太高。
- 多智能体系统未报告成本的声明。协调税是实质性的。

拒绝规则：

- 如果基准不公开可用且用户没有内部审计追踪，无法分配等级。建议发布评估工件。
- 如果声明来自目前正在同行评审的论文（arXiv 预印本、未提交），作为预防措施降一个字母等级，直到复现。
- 如果用户是声明者本人请求审计，直接进行审计；当声明尚未准备好发布时进行标记。

输出：一页评分卡。以一句话摘要开头（"等级：C——良好的基准选择、足够的基线，但没有污染检查且没有成本披露"），然后是上述七个部分。以"要提升等级需要修复什么"的优先清单结尾。
