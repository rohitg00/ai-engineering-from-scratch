给定一个拟议的多智能体系统设计，选择最接近的规范 2026 案例研究并适配。

生成以下内容：

1. **设计指纹**。任务类型（研究/工程/群体/自动化）、智能体数量、验证要求、运行持续时间、角色区分度、面向用户的网络暴露。
2. **最接近的案例研究**。
   - **Anthropic Research**：如果是研究或知识检索任务、验证是强制的、多小时运行、智能体主要通过上下文和范围区分（新鲜上下文子智能体胜出）。
   - **MetaGPT / ChatDev**：如果是工程或结构化工作流、角色可明确区分（规划者/编码员/审阅者/测试员）、交接工件有良好类型。
   - **OpenClaw / Moltbook**：如果是群体规模、面向用户的智能体网络、提示注入是重大威胁、涌现经济很重要。
3. **要复制的模式**。来自所选案例研究的具体设计决策：新鲜上下文子智能体、彩虹部署、通信去幻觉、DAG 路由、不可写验证器、基板级安全。
4. **框架推荐**。LangGraph、CrewAI、AG2、Microsoft Agent Framework、OpenAI Agents SDK、Google ADK、Anthropic Claude Agent SDK 或自定义。默认使用案例研究的典型框架；如果存在更适合具体设计的框架则注明。
5. **来自案例的反模式**。参考案例发现的*不起作用*的内容。在新设计中避免。
6. **成本预测**。预期令牌倍数（Anthropic Research：约 15 倍；MetaGPT：约 5 倍；OpenClaw：取决于网络效应）。预期的挂钟和美元成本范围。
7. **评估方法**。哪个基准（MARBLE、SWE-bench Pro、内部）相关；针对案例研究基线追求什么样的提升是合理的。

硬性拒绝：

- 当任务有正确性要求时忽略验证的设计。每个案例研究都支付了验证税。
- 声称新的基板但不承认提示注入是攻击表面的设计。OpenClaw/Moltbook 案例表明这是生产关切，而非假设性的。
- 不映射到任何案例研究的"革命性"声明。多智能体自 2024 年就已投入生产；新颖声明需要明确比较。
- 没有理由跳过 MCP 或 A2A 采用的设计。协议支持是入场券。

拒绝规则：

- 如果设计没有明确的任务类型，建议在选取案例研究前先确定任务范围。"什么都用的多智能体"不是设计。
- 如果设计声称生产就绪但没有故障模式审计，建议在参考映射前进行 MAST 风格审计（第 23 课）。
- 如果设计纯粹是实验性/研究性的，说明在采用任何案例研究的生产模式之前，哪些方面需要加固。

输出：一份两页简报。以一句话摘要开头（"最接近的案例研究：MetaGPT / ChatDev。采用角色-SOP 分解、通信去幻觉和结构化交接工件；使用 CrewAI 或自定义"），然后是上述七个部分。以 90 天适配计划结尾：从参考中复制什么、自定义什么、以及针对基准验证什么。
