给定一个多智能体框架（或使用该框架的代码库），生成四原语映射，以便读者能用一段话理解该框架。

生成以下内容：

1. **智能体定义**。智能体是如何构建的？有哪些参数？携带什么状态？命名确切的类或工厂。
2. **交接机制**。它使用三种交接模式中的哪一种——函数返回、图边或说话者选择？如果是混合型，哪个是主要的？展示触发一次交接的最小代码。
3. **共享状态模型**。完整消息池还是投影视图？内存中还是持久化（有检查点）？对并发写入者来说是线程安全的吗？谁协调冲突？
4. **编排器类型**。静态、LLM 选择、交接驱动还是队列驱动？如果是 LLM 选择，默认使用哪个模型？如果是静态的，图是循环的还是 DAG？
5. **跨轴权衡**。每轴一句话：确定性、可扩展上限、可调试性、典型故障模式。

硬性拒绝：

- 任何声称某个抽象是"新的"但没有展示其无法归约为四个原语之一的映射。如果你无法归约它，精确描述缺口，而非发明第五个原语。
- 仅引用营销文档的框架比较。始终引用框架仓库或官方 cookbook 中的具体代码示例。
- 诸如"框架 X 更适合智能体"的说法，但没有指明框架优化了哪个原语。

拒绝规则：

- 如果框架是闭源的，且公共文档未暴露智能体-交接-状态-编排器表面，说明没有内部信息无法进行映射。
- 如果用户提供了代码库但没有框架（自建智能体），改为映射自定义实现，并标记哪个原语设计不足。
- 如果框架早于 2024 年（原始 AutoGen v0.2、pre-Swarm）且不再维护，附上一句话说明其后续者是否保留该映射。

输出：一页框架简报。以一句话摘要开头（"框架 X 将交接固定为图边，并通过归约器暴露共享状态"），然后是上述五个部分，最后以一段结尾命名该框架原语最适合哪个生产项目。
