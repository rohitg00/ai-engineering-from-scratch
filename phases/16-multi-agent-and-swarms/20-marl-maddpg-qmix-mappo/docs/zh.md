# MARL — MADDPG, QMIX, MAPPO

> 多智能体协调的强化学习遗产，在 2026 年仍然为 LLM 智能体系统提供启发。**MADDPG**（Lowe 等人，NeurIPS 2017，arXiv:1706.02275）提出了集中式训练、分散式执行（CTDE）：每个评论家在训练期间观察所有智能体的状态和动作；测试时仅运行局部行动者。适用于合作、竞争和混合场景。**QMIX**（Rashid 等人，ICML 2018，arXiv:1803.11485）是一种带有单调混合网络的价值分解方法；各智能体的 Q 值通过单调网络组合成联合 Q 值，使得 `argmax` 可以干净地分解——在星际争霸多智能体挑战赛（SMAC）上占据主导地位。**MAPPO**（Yu 等人，NeurIPS 2022，arXiv:2103.01955）是具有集中式价值函数的 PPO；在粒子世界、SMAC、Google Research Football、Hanabi 上只需极少的调参即"出奇地有效"。这些算法为必须分散执行的智能体团队训练策略提供了基础。MAPPO 是 **2026 年合作式 MARL 的默认基线**。本课程从一个小型网格世界玩具开始构建每一种算法，在接触 LLM 智能体训练之前将这三个思想深深植入肌肉记忆。

**类型：** 学习
**语言：** Python（标准库，小型无 NumPy 实现）
**前置条件：** 阶段 09（强化学习），阶段 16·09（并行群体网络）
**时间：** 约 90 分钟

## 问题

LLM 智能体系统越来越多地训练智能体间协调的策略：何时让渡控制权，何时行动，调用哪个同伴。告诉你如何训练此类策略的文献是多智能体强化学习（MARL），它早于 LLM 浪潮，并且有一套占主导地位的算法。

没有模式词汇表，阅读 MARL 论文是痛苦的。集中式训练与分散式执行（CTDE）、价值分解和集中式评论家不是流行词——它们是针对特定问题的特定答案：

- 独立 RL（每个智能体独自学习）从每个智能体的角度来看是非平稳的。不好。
- 集中式 RL（一个智能体控制所有）无法扩展且违反执行约束。
- CTDE 两者兼得：用全局信息训练，用局部策略部署。

## 概念

### 论文使用的三个环境

- **粒子世界（多智能体粒子环境）。** 简单的 2D 物理，包含合作/竞争任务。MADDPG 的原始测试平台。
- **星际争霸多智能体挑战赛（SMAC）。** 合作微观管理，部分观测。QMIX 的测试平台。离散动作，连续状态。
- **Google Research Football、Hanabi、MPE。** MAPPO 的基准测试。

不同的环境有不同的动作/观测类型。算法据此选择。

### MADDPG（2017）— CTDE 模式

每个智能体 `i` 有一个行动者 `mu_i(o_i)`，将其自身观测映射到动作。每个智能体还有一个评论家 `Q_i(x, a_1, ..., a_n)`，在训练期间观察所有观测和所有动作。行动者根据评论家的评估通过策略梯度更新。

```
行动者更新：    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) 当 a_i=mu_i(o_i)]
评论家更新：   基于下一状态联合估计的 Q_i(x, a_1..n) 的时序差分
```

为什么需要 CTDE：在训练时，我们知道每个人的动作；我们利用这一点来降低每个评论家的方差。在部署时，每个智能体只看到 `o_i` 并调用 `mu_i(o_i)`。

失败模式：评论家随 N 个智能体增长（输入包含所有动作）。在没有近似的情况下无法扩展到约 10 个智能体以上。

### QMIX（2018）— 价值分解

仅限合作场景。全局奖励是各智能体 Q 值的单调函数之和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n))，其中 df/dQ_i >= 0
```

单调性保证了 `argmax_a Q_tot` 可以通过每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这正是你需要的**分散式执行属性**。在训练时，一个混合网络从各智能体的 Q 值生成 `Q_tot`。

为什么 QMIX 在 SMAC 上获胜：合作式的星际争霸微观管理具有同质智能体、局部观测和全局奖励——非常适合价值分解。

失败模式：单调性约束具有限制性；某些任务的奖励结构无法单调分解（一个智能体为团队牺牲自身）。扩展方法（QTRAN、QPLEX）缓解了这一问题。

### MAPPO（2022）— 被忽视的默认选择

多智能体 PPO：具有集中式价值函数的 PPO。每个智能体有自己的策略；所有智能体共享（或各自拥有）能观察到完整状态的价值函数。Yu 等人在 2022 年的工作中将 MAPPO 与 MADDPG、QMIX 及其扩展方法在五个基准测试上进行了比较，发现：

- MAPPO 在粒子世界、SMAC、Google Research Football、Hanabi、MPE 上达到或超过了离策略 MARL 方法。
- 需要的超参数调优极少。
- 训练稳定；跨种子的可重复性好。

在此论文之前，学术界低估了在策略 MARL。到 2026 年，MAPPO 已成为合作式 MARL 的默认基线；任何新方法必须超越它。

### 为什么 LLM 智能体工程师应该关注

三个直接用途：

1. **路由器训练。** 一个元智能体选择哪个子智能体处理任务。这是一个具有 N 个分散式子智能体和一个集中式路由器的 MARL 问题。MAPPO 适用。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采纳互补角色，本质上是一个 MARL 问题。QMIX 风格的价值分解通过构造强制实现互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过 CTDE 训练它们可以产生尊重资源约束的可部署局部策略。

实际注意事项：在 2026 年，大多数生产级 LLM 智能体系统通过提示词驱动其策略，而非训练它们。当你拥有 (a) 大量交互数据，(b) 清晰的奖励信号，以及 (c) 投资训练基础设施的意愿时，MARL 才会派上用场。

### CTDE 作为超越 RL 的设计模式

即使没有训练，CTDE 也是一种有用的架构模式：

- 在**设计**期间，假设完整的团队可见性。
- 在**运行时**，强制分散式执行：每个智能体只看到 `o_i`。

该模式迫使你将每个智能体的状态保持显式化，并提前考虑部分可观测性问题。许多生产级多智能体系统默认假设到处共享状态——CTDE 的纪律性可以防止这种情况。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包括其他智能体的策略）是非平稳的。经典的单智能体 RL 证明会失效。本课程中的 MARL 算法都解决了这一问题：

- MADDPG：全局评论家看到所有动作，因此其价值估计是平稳的。
- QMIX：价值分解将学习转移到联合 Q 值空间，在该空间中最优性有良好定义。
- MAPPO：集中式价值函数减弱了其他智能体策略变化带来的方差。

在 LLM 智能体系统中，非平稳性表现为"我的智能体上个月工作正常，现在上游的其他智能体变了，我的智能体开始出问题。"使用 CTDE 训练 MARL 是原则性的修复方案；提示词级别的修复更快但持久性较差。

### 本课程不涵盖的内容

训练实际网络是阶段 09 的主题。本课程构建的是脚本化策略版本，无需梯度更新即可演示 CTDE、价值分解和集中式价值模式。目标是在你接触完整的 MARL 库（PyMARL、MARLlib、RLlib multi-agent）之前内化这些模式。

## 构建

`code/main.py` 实现了三种模式演示，全部在一个微型的 2 智能体合作式网格世界上运行：

- 环境：4×4 网格上有 2 个智能体，一个奖励球。如果任一智能体到达球，奖励 = 1；任务结束。
- `IndependentAgents`——每个智能体将其他智能体视为环境。基线。
- `MADDPGStyle`——集中式评论家计算联合价值；行动者策略据此更新。脚本化策略改进。
- `QMIXStyle`——使用单调混合器的价值分解。
- `MAPPOStyle`——集中式价值函数；策略根据共享基线更新。

所有四种方法运行相同的轮次并报告平均达到目标的步数。CTDE 变体收敛到比独立基线更短的路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均约 6 步；CTDE 变体收敛到约 3.5 步（4×4 网格的最优解为 3 步）。尽管是脚本化策略，模式差异仍然显现。

## 使用

`outputs/skill-marl-picker.md` 是一个技能，用于为给定的多智能体任务选择 MARL 算法：合作 vs 竞争、同质 vs 异质、动作空间类型、规模、奖励信号。

## 交付

MARL 在生产中很少见。当你确实要使用时：

- **从 MAPPO 开始。** 2022 年的论文将其确立为基线；先复现它可以节省数周追逐更花哨方法的时间。
- **记录每个智能体的观测和动作流。** 没有每个智能体的追踪信息，调试 MARL 是无望的。
- **将训练代码与执行代码分离。** CTDE 是一种纪律；让执行路径真正只看到 `o_i`。
- **奖励塑形警告。** MARL 对奖励设计极其敏感。塑形中一个协调错误就会让智能体学会利用它。运行对抗性测试。
- **对于 LLM 智能体，** 优先考虑提示词级别的策略。只有当交互数据、奖励信号和基础设施都具备时，才投资于 MARL 训练。

## 练习

1. 运行 `code/main.py`。测量独立智能体与 MAPPO 风格智能体之间达到目标的步数差距。在 6×6 网格上，差距是增大还是缩小？
2. 实现一个竞争变体：两个智能体，一个球，只有先到达的得到奖励。哪种模式能干净地处理竞争？历史上是 MADDPG。
3. 阅读 MADDPG（arXiv:1706.02275）第 3 节。用你自己的话以伪代码形式符号化实现精确的评论家更新规则。
4. 阅读 MAPPO（arXiv:2103.01955）。作者为什么认为集中式价值 + PPO 在其基准测试上优于离策略 MARL？列出三个最强有力的主张。
5. 将 CTDE 作为设计模式应用于一个假设的 LLM 智能体系统（例如，研究智能体 + 摘要智能体 + 编码智能体）。在设计时可用的联合信息中，哪些在运行时不可用？

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|------|-----------|---------|
| MARL | "多智能体强化学习" | 面向多智能体系统的强化学习。 |
| CTDE | "集中式训练，分散式执行" | 用全局信息训练；用局部策略部署。 |
| MADDPG | "多智能体 DDPG" | 每个智能体评论家看到所有观测和动作的 CTDE。 |
| QMIX | "价值分解" | 各智能体 Q 值的单调混合。合作式。 |
| MAPPO | "多智能体 PPO" | 具有集中式价值函数的 PPO。2026 年默认基线。 |
| 价值分解 | "各智能体 Q 值之和" | 联合 Q 值表示为各智能体 Q 值的单调函数。 |
| 非平稳性 | "移动目标" | 每个智能体的环境随其他智能体学习而变化。MARL 的核心问题。 |
| 在策略 / 离策略 | "从当前/回放中学习" | PPO 是在策略的（MAPPO）；DDPG 和 Q 学习是离策略的。 |
| SMAC | "星际争霸多智能体挑战赛" | 合作微观管理基准测试；QMIX 的成名战场。 |
