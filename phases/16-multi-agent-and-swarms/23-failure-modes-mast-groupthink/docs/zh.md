# 故障模式 — MAST、群体思维、同质化、级联错误

> 2026 年的参考分类法为 **MAST**（Cemri 等，NeurIPS 2025，arXiv:2503.13657），该分类法基于 7 个最先进开源 MAS 的 1642 条执行轨迹推导得出，显示出 **41–86.7% 的故障率**。三大根因类别：**规范问题**（41.77%）——角色模糊、任务定义不清晰；**协调失败**（36.94%）——沟通断裂、状态不同步；**验证缺口**（21.30%）——缺乏验证、缺少质量检查。**群体思维**论文系列（arXiv:2508.05687）进一步补充：同质化崩溃（相同基础模型 → 相关故障）、从众偏差（智能体互相强化彼此错误）、心智理论缺陷、混合动机动态、级联可靠性故障。级联示例：重试风暴——支付失败触发订单重试，进而触发库存重试，最终压垮库存服务（数秒内负载飙升 10 倍——需要断路器）。记忆中毒：一个智能体的幻觉进入共享内存，下游智能体将其当作事实；准确率逐渐衰减，使得根因诊断非常棘手。**STRATUS**（NeurIPS 2025）报告称，通过专门的检测/诊断/验证智能体，缓解成功率提升了 1.5 倍。本课将故障模式视为一流工程目标。

**类型：** 学习
**语言：** Python（标准库）
**前置知识：** 阶段 16 · 13（共享内存），阶段 16 · 14（共识与 BFT），阶段 16 · 15（投票与辩论拓扑）
**时间：** ~75 分钟

## 问题

多智能体系统在实际任务上的失败率为 41–86.7%（Cemri 等 2025 年在 7 个开源 MAS 上的测量结果）。这无法通过"多加几个智能体"来调试。这些失败有其结构性原因。MAST 分类法为你提供了分类框架。本课将每个类别映射到具体的检测、诊断和缓解模式，使这些数字不再显得随意。

2026 年的生产实践是将故障模式作为设计输入。只有当你能指出每个 MAST 类别并说出你所部署的缓解措施时，你的架构才算"足够好"。

## 概念

### MAST 分类

**规范问题（占故障的 41.77%）。** 智能体的任务定义不够严谨。示例：

- 角色模糊：两个智能体都认为自己是评审者。
- 任务描述不足："总结一下"——而用户想要的是特定角度的总结。
- 成功标准隐含：智能体无法判断自己是否成功。

缓解措施：
- 编写明确的角色契约。每个智能体的提示词声明其职责范围 *以及不做什么*。
- 每个任务设置验收测试。在智能体开始之前，定义"完成的样子是 X"。
- 前置规范检查：在任务派发前，由另一个独立的智能体审查任务定义。

**协调失败（占故障的 36.94%）。** 通信或状态断裂。

示例：
- 两个智能体无同步地更新共享状态。
- 智能体之间消息丢失（队列故障、超时）。
- 状态漂移：智能体 A 认为任务已完成；智能体 B 仍在执行。

缓解措施：
- 带版本号的共享状态，配合乐观并发控制。
- 关键消息的显式确认（重试直到确认收到）。
- 周期性状态同步检查点；尽早发现漂移。

**验证缺口（占故障的 21.30%）。** 输出缺少独立检查。

示例：
- 一个智能体声称成功；无人验证。
- 智能体链中每个环节都信任前一个的输出。
- 对涌现的组合行为缺少测试覆盖。

缓解措施：
- 独立的验证智能体（第 13 课）。只读、独立的访问源。
- 显式交接契约："A 的输出必须通过检查器 C 之后，B 才能开始。"
- 结果日志记录，用于事后分析。

### 群体思维系列（arXiv:2508.05687）

当智能体同质化或相互模仿时，会出现五种相关的失败模式：

**同质化崩溃。** 相同的基础模型或训练数据 → 相关错误。当三个智能体共享同一个 LLM 时，它们共享其幻觉。

**从众偏差。** 智能体倾向于向最响亮或最自信的同伴靠拢，即使对方是错误的。

**心智理论缺陷。** 智能体无法建模彼此信念；协调崩溃（第 18 课）。

**混合动机动态。** 具有部分一致激励的智能体向折中方案漂移，结果谁都不满意。

**级联可靠性故障。** 一个组件的错误模式会触发依赖组件的错误模式。

### 级联示例 — 重试风暴

一个经典的 2026 年事故模式：

```
支付服务 10% 的请求失败
   ↓
订单智能体重试支付（指数退避但实现粗糙）
   ↓
每次重试都触发新的订单-库存检查
   ↓
库存服务承受 2 倍正常负载
   ↓
库存服务开始超时
   ↓
每个订单都重试库存检查
   ↓
库存服务承受 10 倍正常负载
   ↓
集群宕机
```

解决方案是经典的：**断路器**。当下游错误率超过阈值时，短路并使用缓存或默认结果。此外，每个请求设置有限的重试预算。

断路器是少数几种无需修改即可直接从分布式系统借鉴的多智能体故障缓解措施之一。

### 记忆中毒（重访）

来自第 13 课：一个智能体的幻觉成为共享内存中的事实；下游智能体基于中毒的事实进行推理。用 MAST 术语来说，这是共享内存层的验证缺口。

逐渐的准确率衰减是症状。你不会遇到崩溃；而是缓慢的漂移，难以追溯根因。

缓解措施：仅追加日志、溯源、不可写的验证器。第 13 课已涵盖。

### STRATUS — 专门的故障检测智能体

STRATUS（NeurIPS 2025）报告称，部署以下三类智能体可将缓解成功率提升 1.5 倍：

- **检测智能体。** 监视症状模式（高度分歧、重试峰值、准确率漂移）。
- **诊断智能体。** 根据症状，从 MAST 分类中推断可能的根因。
- **验证智能体。** 在实施缓解措施后，检查症状是否消失。

这是 SRE 风格的事件响应，应用于智能体系统。这三个角色都可以是通过专门提示词驱动的 LLM 智能体。

### 故障模式审计

2026 年的一项最佳实践是年度（或每个重大版本发布时）的故障模式审计：

1. **轨迹采样。** 收集约 1000 条真实执行轨迹。
2. **分类。** 对每条轨迹的失败，映射到 MAST + 群体思维类别。
3. **计算各类别故障率。** 哪些类别在你的系统中占主导？
4. **对缓解措施排序。** 哪个修复方案能消除最多的故障？
5. **选择 2-3 项缓解措施。** 实施；下季度重新审计。

这种纪律比具体选择更重要。没有审计，故障就会融入噪声，永远不会被系统性地解决。

### 当系统静默失败时

最危险的故障类别是静默正确性失败。大声失败的（崩溃、异常、告警）系统可以被监控。但产生看似正确实则错误的输出的系统无法通过异常日志检测到。这就是为什么验证缺口是每个故障中代价最高的类别——尽管按数量计算只占 21.30%。

投入资源于：
- 基于抽样的人工审查。
- 黄金数据集回归测试。
- 重要输出上的跨智能体交叉检查。

### 快速失败与缓慢失败

有些失败是即时的；有些是缓慢的。即时失败（超时、模式不匹配、认证错误）易于检测。缓慢失败（记忆中毒、同质化漂移、角色模糊）难以检测和预防。

2026 年工程方向：为缓慢失败设置代理指标，以便在漂移成为可见错误之前捕获它。一致率、重试率、输出长度分布以及连续智能体版本之间的编辑距离都是有用的代理指标。

## 动手构建

`code/main.py` 实现了：

- `FailureTaxonomy` — 将模拟事件分类为 MAST + 群体思维类别。
- `CircuitBreaker` — 经典模式；当错误率超过阈值时断开。
- `RetryStormSimulator` — 展示级联故障；可切换断路器开/关。
- `DetectionAgent` — 脚本化的 STRATUS 风格症状匹配器。

运行：

```
python3 code/main.py
```

预期输出：
- 无断路器时的重试风暴：库存错误激增（模拟）。
- 有断路器时：在阈值处截断；提供降级模式响应。
- 检测智能体标记该模式并指出 MAST 类别。

## 投入生产

生产环境中的故障模式纪律：

- **每季度一次 MAST 审计。** 不是每年。类别会随系统增长而变化。
- **处处使用断路器。** 对每个依赖服务的出站调用。默认断开阈值为 5-10% 错误率。
- **黄金数据集。** 小规模、高质量、手工审计。每周进行回归测试。
- **STRATUS 三件套。** 检测 + 诊断 + 验证智能体监控生产环境。先从检测智能体开始；当症状嘈杂时再添加诊断。
- **故障预算。** 按类别设定明确的故障率 SLO。超出预算触发停止发布的讨论。

## 练习

1. 运行 `code/main.py`。确认断路器能够限制重试风暴。改变故障阈值并观察权衡。
2. 实现一个**缓慢失败代理指标**：3 个并行智能体之间的一致率。当一致率急剧下降时触发告警。通过逐渐关联智能体输出来模拟同质化漂移。
3. 阅读 Cemri 等人的论文（arXiv:2503.13657）。选择其中 7 个 MAS 系统之一，映射其前三大故障类别。这些与 MAST 预测的有何异同？
4. 阅读群体思维论文（arXiv:2508.05687）。识别其中五种模式中哪种最难在生产环境中检测。提出一个代理指标。
5. 为你熟悉的一个特定多智能体系统设计一个 STRATUS 风格的检测-诊断-验证三件套。检测智能体监视哪些症状？诊断智能体推荐哪些缓解措施？验证智能体如何确认它们有效？

## 关键术语

| 术语 | 通常说法 | 实际含义 |
|------|---------|---------|
| MAST | "2026 年的分类法" | Cemri 2025；3 个根因类别 + 14 个子类故障。 |
| 规范问题 | "角色模糊" | 任务或角色定义不充分；智能体不知道要做什么。 |
| 协调失败 | "状态漂移" | 智能体之间的通信或同步断裂。 |
| 验证缺口 | "没人检查" | 输出未经独立验证就被接受。 |
| 群体思维系列 | "同质化失败" | 同质化、从众、心智理论缺陷、混合动机、级联。 |
| 同质化崩溃 | "相同模型，相同幻觉" | 共享基础模型或训练数据导致的相关错误。 |
| 重试风暴 | "级联错误放大" | 一次失败触发重试，进而放大下游负载。 |
| 断路器 | "错误率过高时快速失败" | 错误率超过阈值时断开；用默认结果短路。 |
| STRATUS | "事件响应三件套" | 检测 + 诊断 + 验证智能体。缓解成功率提升 1.5 倍。 |
| 记忆中毒 | "幻觉传播" | 共享内存中的事实被污染；下游智能体基于毒化信息推理。 |
