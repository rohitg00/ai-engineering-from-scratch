# 談判與議價

> 代理會就資源、價格、任務分配與條款進行談判。2026 年的基準集講得很清楚：NegotiationArena（arXiv:2402.05863）顯示 LLM 可以靠人設操弄（「走投無路」）把收益改善約 20%；〈Measuring Bargaining Abilities〉（arXiv:2402.15813）顯示當買方比當賣方難，而且規模幫不上忙 —— 他們的 **OG-Narrator**（決定性的出價產生器 + LLM 敘述者）把成交率從 26.67% 推到 88.88%；大規模自主談判競賽（arXiv:2503.06416）跑了約 18 萬場談判，發現**隱藏思維鏈**的代理靠著對交易對手藏起推理而勝出；Bhattacharya 等人 2025 年依哈佛談判專案的指標排名，Llama-3 最有效、Claude-3 最進取、GPT-4 最公平。這一課實作合約網協定（FIPA 的祖先，第 02 課）、接上一個 LLM 式的買方／賣方、跑一次 OG-Narrator 式的拆解，並量測每一項結構選擇如何改變成交率。

**類型：** 學習 + 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 16 · 02（FIPA-ACL 傳承）、階段 16 · 09（平行 Swarm 網路）
**時間：** 約 75 分鐘

## 問題

兩個代理需要就價格達成一致。放著讓它們用純語言提示詞自己來，2024-2026 年的 LLM 成交率低得驚人（在 arXiv:2402.15813 那些參數收得很緊的議價上約 27%）。規模修不好這件事：GPT-4 在議價上並沒有結構性地比 GPT-3.5 好；它只是更擅長議價的*語言*。

根本問題是 LLM 把兩件工作混在一起 —— 決定出價，以及敘述出價。OG-Narrator 把它們分開：一個決定性的出價產生器算出數字上的走法；LLM 只負責敘述。成交率跳到約 89%。

這呼應了一項經典的多代理發現：把機制與通訊層解耦就會贏。合約網協定（FIPA，1996；Smith，1980）是那個參考的任務市場機制。把一個 LLM 插進敘述的位置，你就得到一個現代的、由 LLM 驅動的任務市場。

## 概念

### 一段話講完合約網

Smith 1980 年的合約網協定：一位**管理者**廣播一份**徵求提案（cfp）**；**投標者**以帶有各自出價的 **propose** 訊息回應；管理者挑出贏家，並對贏家送出 **accept-proposal**、對輸家送出 **reject-proposal**。贏家執行那份工作。選配訊息：**refuse**（投標者婉拒提案）。FIPA 把這件事編纂成 `fipa-contract-net` 互動協定。

### OG-Narrator 為什麼會贏

〈Measuring Bargaining Abilities of Language Models〉（arXiv:2402.15813）觀察到：

- LLM 常常違反議價規則（開出毫無道理的價格、無視對方的 ZOPA）。
- 它們錨定得很差（接受糟糕的第一次出價；還價時開的是象徵性而非策略性的數字）。
- 光靠規模修不好這些。更大的模型產出更像樣的語言，但策略錯誤差不多。

OG-Narrator 的拆解：

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

出價產生器是一套經典談判策略：Rubinstein 議價模型、Zeuthen 策略，或對價格做簡單的以牙還牙。LLM 負責敘述。訊息裡含著那個決定性的價格，加上自然語言的包裝。

成交率跳升是因為：
- 價格待在議價區間內。
- 錨定是策略性的，不是情緒性的。
- LLM 做的是它擅長的事：寫作。

### NegotiationArena 的發現

arXiv:2402.05863 提供了那份典範基準。頭條發現：

- LLM 可以靠採用人設（「我很急，週五前一定要賣掉」）把收益改善約 20% —— 人設操弄是一項真實戰術。
- 公平／合作型的代理會被對抗型的剝削；防禦需要明確的反向姿態。
- 對稱配對在約 40% 的基準情境中收斂到不公平的結果。

這不是「LLM 是差勁的談判者」。而是「LLM 談判得太像人類，包括那些可被剝削的部分」。

### 思維鏈的隱藏

大規模自主談判競賽（arXiv:2503.06416）跨多種 LLM 策略跑了約 18 萬場談判。贏家把自己的推理藏起來不讓交易對手看到：

- 若某個代理在一塊公開可見的暫存簿上印出「我最多只到 75 美元；我的保留價是 70」，對手就讀到了。
- 贏家私下計算策略；輸出通道裡只有出價與最低限度必要的敘述。

這是經典賽局理論（Aumann 1976 談理性與資訊）在 2026 年的回聲：揭露你的私人估值要付出收益的代價。LLM 沒有這種直覺，會很開心地把自己的保留價打進推理軌跡裡，而那些軌跡對交易對手是可見的。

工程上的帶走重點：把私人暫存簿的脈絡與公開訊息的脈絡分開。這不是選配。

### Bhattacharya 等人 2025 —— 模型排名

依哈佛談判專案的指標（原則式談判、尊重 BATNA、利益互惠）：

- **Llama-3** 在達成交易上最有效（成交率 + 收益）。
- **Claude-3** 是最進取的談判者（高錨定、晚讓步）。
- **GPT-4** 最公平（跨配對的收益變異最小）。

這是一份 2025 年的快照。重點不在於 2026 年 4 月誰贏 —— 而是不同的基礎模型有持續存在的談判風格。異質集成（第 15 課）把這件事納入為一種多樣性來源。

### 用合約網 + LLM 做任務分配

合約網在 LLM 多代理上的現代再利用：

1. 管理者代理把一項任務分解成若干單位。
2. 對 worker 代理廣播帶任務描述的 `cfp`。
3. 每個 worker 回一份出價：`(price, eta, confidence)`，其中 price 可以是詞元、運算單位或美元。
4. 管理者挑出贏家（依任務而定，一個或多個）並授予。
5. 被拒絕的 worker 可以自由去投別的標。

因為協調是廣播加回應、不是同步聊天，這套做法擴展得遠遠超過 100 個 worker。生產環境中已在使用：Microsoft Agent Framework 的編排模式、一些 LangGraph 實作。

### LLM-Stakeholders 互動式談判

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）引入了帶**祕密分數**與**最低接受門檻**的多方可計分賽局。每個利害關係人有私人效用；LLM 必須從訊息中推斷它們。這是把兩方議價一般化到 N 方的聯盟形成。對具備異質 worker 能力的生產級任務市場很相關。

### 敘述與機制的規則

橫跨 2024-2026 年所有談判基準，一致的工程規則是：

> 讓 LLM 敘述。不要讓 LLM 算出價。

若出價必須是一個數字（價格、預計時間、數量），就從談判狀態決定性地產生它，並讓 LLM 產出那層包裝。若出價必須是一份提案結構（任務分解、角色指派），就讓 LLM 起草，但在送出前對照一份 schema 驗證並做限制檢查。

## 動手實作

`code/main.py` 實作了：

- `ContractNetManager`、`ContractNetTask`、`Bid` —— 管理者加投標者、廣播 cfp、收集提案、授予。
- `og_narrator_bargain(state, rng)` —— OG-Narrator 買方：朝中點做決定性的 Zeuthen 式讓步。
- `seller_response(state, rng)` —— 決定性的賣方還價政策（兩種風格共同的結構性基準真值）。
- `naive_llm_bargain(state, rng)` —— 模擬一個全 LLM 的議價者：挑出變異很大、常常落在 ZOPA 之外的價格。
- 量測：跑 1000 次試驗的成交率，每次試驗都重新取樣保留價。

跑：

```
python3 code/main.py
```

預期輸出：天真 LLM 的成交率約 65-75%；OG-Narrator 的成交率約 85-95%；那 15-25 個百分點的落差，就是「把出價產生從敘述中拆出來」的結構性優勢。外加一個帶三位投標者、一項任務的合約網任務市場分配範例。

## 框架應用

`outputs/skill-bargainer-designer.md` 設計一套議價協定：誰產生出價（決定性或 LLM）、誰敘述、私人暫存簿如何與公開訊息分開，以及成交率怎麼被監控。

## 產出交付

生產議價的檢查清單：

- **分開的暫存簿。** 私人狀態絕不進到交易對手的脈絡。這件事不容商量。
- **決定性的出價產生。** 價格、數量、預計時間：用算的，不要用問的。
- **對照 schema 驗證所有進來的出價。** 在協定邊界上就拒絕 ZOPA 之外的出價。
- **回合有界。** 最多 3-5 回合；僵局就升級給調解者。
- **持續量測成交率與收益變異。** 成交率下滑是一個症狀 —— 常常是提示詞漂移或對手側的攻擊。
- **記錄所有被拒絕的提案**，附上那個決定性的理由。對合約網的管理者來說，落選的投標者需要理解為什麼。

## 練習

1. 跑 `code/main.py`。確認 OG-Narrator 在成交率上勝過天真 LLM。多多少？
2. 實作**基於人設的收益改善**（arXiv:2402.05863）—— 買方只在敘述中採用「這週非買到不可」的人設，出價產生器不變。成交率或收益有變嗎？
3. 實作思維鏈的**隱藏**：維護一個不會傳給交易對手的私人暫存簿字串。若你不小心洩漏了它會怎樣（把通道對調來模擬）？
4. 把合約網擴充成帶底價的 N 投標者拍賣。當所有出價都超過底價時，管理者要怎麼在最低價與最高品質之間抉擇？你挑哪條授予規則，為什麼？
5. 讀 Bhattacharya 等人 2025 年談哈佛談判專案指標的部分。實作兩個風格不同的議價者（進取型 vs 公平型）。量測對稱與非對稱配對下的收益變異。
