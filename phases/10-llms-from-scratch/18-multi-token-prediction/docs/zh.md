# 多 token 预测（Multi-Token Prediction, MTP）

> 从 GPT-2 到 Llama 3，每个自回归 LLM 在每个位置只训练一个损失：预测下一个 token。DeepSeek-V3 在每个位置增加了一个损失：预测下下个 token。额外的 140 亿参数（在 671B 模型上）通过梯度流蒸馏回主模型，而训练好的 MTP 头在推理时被重新用作推测解码的草稿模型，接受率超过 80%。生成吞吐量免费提升了 1.8 倍。本课从 DeepSeek 技术报告中构建顺序 MTP 模块，计算损失和共享头的参数布局，并解释为什么 MTP 保持了因果链，而 Gloeckle 等人的原始并行 MTP 破坏了它。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段10·第04课（预训练一个迷你 GPT）、阶段10·第15课（推测解码）
**时间：** 约 60 分钟

## 学习目标

- 阐述 MTP 训练目标，并推导跨预测深度的联合损失。
- 解释 Gloeckle 等人（2024）的并行 MTP 头与 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为什么顺序设计保留了因果链。
- 计算在预训练运行中添加 MTP 模块所带来的参数和内存开销。
- 从头实现一个 MTP 模块：共享嵌入层、逐深度 Transformer 块、投影层和共享输出头。

## 问题

下一个 token 预测是标准 LLM 的训练目标。每个隐状态被监督以预测恰好一件事：紧随其后的下一个 token。这是一个出奇弱的信号。序列中的大多数信息都超出了单个 token 的范围——结构、连贯性、事实性、算术流程。模型必须通过在海量 token 上累积大量单 token 信号来学习这些内容。

MTP 提出的问题是：如果每个隐状态都被监督以同时预测多个未来 token 会怎样？Gloeckle 等人（Meta, 2024）证明了这很有帮助。他们的实现是在主干网络之上放置了几个独立的输出头，每个头预测不同的偏移量。并行、简单，但这些头看到的都是相同的隐状态，没有任何层次化的精炼——而且预测没有因果链，因此不能用于推测解码。

DeepSeek-V3（2024 年 12 月）将 MTP 重新设计为顺序模块，在每个预测深度保持因果链。模型从 `h_i^(0)` 预测 `t+1`，然后从新的隐状态 `h_i^(1)` 预测 `t+2`，而 `h_i^(1)` 是将 `h_i^(0)` 与 `E(t+1)` 嵌入结合而成，以此类推。每个深度都是自己的小型 Transformer 块。共享嵌入层和共享输出头使参数开销保持在适度水平。在 DeepSeek-V3 的规模下，MTP 模块额外增加 140 亿参数，主模型权重为 6710 亿。这 2% 的开销换来了更密集的训练信号以及推理时现成的推测解码草稿。

本课从头构建一个 MTP 模块和 D 深度损失。数学很简洁。实现仅 150 行代码。

## 核心概念

### 顺序 MTP 方案

DeepSeek-V3 在主模型之上添加了 `D` 个 MTP 模块。每个模块 `k`（`k = 1..D`）预测深度 `k` 处的 token——即给定到位置 `i` 的前缀，预测 `t_{i+k}`。

模块 `k` 由以下部分组成：

- Transformer 块 `T_k`，带有自己的注意力和 MLP。
- 投影矩阵 `M_k`，用于将前一深度的隐状态与下一深度的真实 token 嵌入相结合。
- 共享嵌入层 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

在训练中，对于到位置 `i` 的前缀，每个深度的隐状态为：

```
h_i^(0) = 主模型主干网络在位置 i 的隐状态
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

每个深度的预测为：

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

每个深度的损失是相对于真实 token `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个较小的权重因子——DeepSeek-V3 在训练的前 10% 使用 0.3，之后使用 0.1。总的训练损失为 `L_main + L_MTP`。

### 为什么是顺序而非并行

Gloeckle 原始的并行 MTP 有 D 个输出头，每个头直接应用于 `h_i^(0)`。每个头从相同的主干网络隐状态预测 `t_{i+k}`。这在训练时没问题，但预测之间并不相互条件依赖。你不能用 `head_1` 的输出来帮助 `head_2`——这些头是并行触发的。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 加上真实的 next-token 嵌入 `E(t_{i+k})` 构建 `h_i^(k)`。这保留了因果链：为了预测 `t_{i+k+1}`，深度 `k+1` 的模块可以看到 `t_{i+k}` 的内容。这在结构上与自回归解码器消费自身输出的方式完全相同——这使得 MTP 模块可以直接用作推测解码的草稿模型。

在推理时：将 `h_i^(k-1)` 和草稿 token `t_{i+k}` 输入模块 `k+1`，得到 `t_{i+k+1}` 的预测。重复进行。这正是一个 EAGLE 风格的草稿，使用训练好的 MTP 模块作为草稿网络。DeepSeek-V3 报告第一个 MTP 模块的接受率超过 80%，速度提升约 1.8 倍。

### 参数核算

对于一个具有隐层维度 `h` 和词表大小 `V` 的模型：

- 主模型：数十亿参数，加上一个大小为 `V * h` 的输出头。
- 共享输出头：复用主模型的输出头。无额外参数。
- 共享嵌入层：复用主模型的嵌入层。无额外参数。
- 每个 MTP 模块：
  - 投影层 `M_k`：`(2h) * h = 2h^2`。
  - Transformer 块 `T_k`：注意力（MHA 为 `4h^2`）加上 MLP（通常 SwiGLU 为 `8h^2`，比率为 8/3）。每个块约 `12h^2`。

每个模块的额外参数总计：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 个模块：理论上约 `14 * 7168^2 = ~7.2 亿` 参数。DeepSeek-V3 报告为 140 亿——差异主要在于 MTP 模块中的专家层也是 MoE 结构。

### 推测解码的回报

在预训练期间，MTP 模块会使训练速度减慢约 10%（更多前向计算，额外的损失）。回报体现在两个方面：

1. **更密集的训练信号。** 每个隐状态看到 D+1 个监督目标。DeepSeek-V3 的消融实验在 MMLU、GSM8K、MATH、HumanEval 上持续显示出几个百分点的提升。

2. **推理时免费的推测解码草稿。** MTP 模块已经过训练，可以预测接下来的几个 token。重新用作草稿网络时，它能达到 80% 以上的接受率。在这一水平下，N=3 或 N=5 的推测解码可带来 1.8 倍的吞吐量提升。训练时 10% 的额外成本，在第一次运行推理时就已回本。

### 与 EAGLE 的关系

EAGLE 在预训练之后**单独**训练一个小的草稿模型。MTP 则将草稿模型嵌入到预训练中。两种方法在相似的接受率上殊途同归，但流程不同：

| 维度 | EAGLE-3 | MTP（DeepSeek-V3） |
|-----------|---------|------------------|
| 训练时机 | 预训练之后 | 预训练期间 |
| 向后兼容现有权重 | 是 | 否（需要重新训练） |
| 草稿参数 | 1-2 个 Transformer 层 | 1 个 Transformer 块 + 投影层 |
| 接受率 | 0.88-0.92 | 深度 1 处 0.80+ |
| 加速之外的好处 | 仅推测解码 | 更密集的训练信号 + 加速 |

## 动手构建

`code/main.py` 端到端地构建一个 MTP 模块：共享嵌入层、投影层、Transformer 块、共享输出头。然后在一个简短的合成序列上计算逐深度交叉熵损失，并按组件打印参数数量。使用 32 个 token 的小型词表使数字清晰可读。

### 步骤 1：共享嵌入表

一个单一的 `vocab_size x hidden` 表被主模型以及每个深度的每个 MTP 模块使用。不是第二个副本——就是同一个张量。

### 步骤 2：逐深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 沿特征维度拼接，然后投影回隐层维度
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 向量加法替代
    projected = matvec(M_k, concat)
    return projected
```

真实的 DeepSeek-V3 将两个经过 RMSNorm 的向量拼接为 `[2h]`，并使用一个 `h x 2h` 矩阵进行投影。教程中使用向量加法以保持标准库的简洁性。

### 步骤 3：深度 k 处的 Transformer 块

自注意力加 MLP。在教程中，一个单层线性注意力块和一个 SwiGLU MLP 保持了结构的可见性，无需 numpy。

### 步骤 4：共享输出头

复用主模型的输出投影。得到词表上的 logits。

### 步骤 5：逐深度损失

softmax(logits) 相对于偏移 `k` 处的真实 token 的交叉熵。使用 `lambda / D` 缩放因子跨深度聚合。

### 步骤 6：参数核算

打印总参数数量、共享部分（嵌入层、输出头）参数数量以及每个模块的额外参数数量。展示 MTP 额外参数相对于主模型大小的比例。

## 使用方式

MTP 已集成到 DeepSeek-V3（2024 年 12 月）和 DeepSeek-R1 系列中。在推理时：

- DeepSeek 自己的服务栈直接使用 MTP 模块作为推测解码器。
- 截至 2026 年 4 月，vLLM 和 SGLang 已具备 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了一个具体的 MTP 推测解码配置，在 V3 检查点上实测 1.8 倍加速。

在新预训练运行中使用 MTP 的场景：

- 你控制完整的预训练流程，并希望获得更密集的训练信号。
- 你知道自己将大规模部署模型，并希望免费获得推测解码能力。
- 你的隐层维度至少为 4096。在 1B 规模下，开销带来的损害大于收益。

不适合使用 MTP 的场景：

- 对现有的预训练稠密模型进行微调。MTP 模块未经训练。
- 研究模型需要干净的基线进行比较。MTP 改变了架构。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|---------|--------|
| MTP 模块 | "额外的损失块" | 一个小型 Transformer 块加投影层，预测主模型前方 `k` 个位置的 token |
| 预测深度 | "哪个偏移" | 整数 `k`，表示模块 `k` 根据到位置 `i` 的前缀预测 `t_{i+k}` |
| 并行 MTP | "Gloeckle 风格" | D 个独立头，位于相同的主干网络隐状态之上，无条件链 |
| 顺序 MTP | "DeepSeek-V3 风格" | 每个模块依赖前一深度的隐状态加上下一个 token 的嵌入；保留因果链 |
| 共享输出头 | "复用主模型输出头" | MTP 模块调用主模型的 LM 头，而非单独的输出投影 |
| 共享嵌入层 | "复用主模型嵌入表" | 相同的词表嵌入表随处使用；无重复参数 |
| 投影矩阵 M_k | "结合隐状态和下一个 token" | 一个 `h x 2h` 的线性层，将前一深度的隐状态和目标 token 嵌入折叠为下一深度的输入 |
| 联合损失 L_MTP | "平均化的额外损失" | 逐深度交叉熵损失的算术平均值，乘以 `lambda` 缩放 |
| 深度 1 处的接受率 | "MTP 草稿正确的频率" | D=1 MTP 模块的 top-1 预测与主模型 top-1 预测一致的比率；DeepSeek-V3 上达到 80% 以上 |
| Lambda 权重 | "额外损失的重要性" | 逐深度缩放因子；DeepSeek-V3 训练开始时为 0.3，之后为 0.1 |
