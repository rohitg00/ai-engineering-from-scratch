# 多詞元預測（MTP）

> 從 GPT-2 到 Llama 3，每一個自迴歸 LLM 訓練時每個位置只有一個損失：預測下一個詞元。DeepSeek-V3 在每個位置加了第二個損失：預測再下一個詞元。多出來的 140 億參數（在一個 6710 億參數的模型上）透過梯度流被蒸餾回主模型，而訓練好的 MTP 預測頭在推論時被改作推測式解碼的草稿器，接受率超過 80%。1.8 倍的生成吞吐量就這樣白拿。這一課會建出 DeepSeek 技術報告裡的序列式 MTP 模組，算出損失與共享頭的參數配置，並解釋為什麼 MTP 保住了因果鏈，而 Gloeckle 等人最初的平行式 MTP 卻把它切斷了。

**類型：** 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 10 · 04（預訓練一個迷你 GPT）、階段 10 · 15（推測式解碼）
**時間：** 約 60 分鐘

## 學習目標

- 說出 MTP 的訓練目標，並推導出跨預測深度的聯合損失。
- 解釋 Gloeckle 等人的平行式 MTP 預測頭（2024）與 DeepSeek-V3 的序列式 MTP 模組之間的差別，以及為什麼序列式設計能保住因果鏈。
- 算出在一次預訓練中加上 MTP 模組所帶來的參數與記憶體額外開銷。
- 從頭實作一個 MTP 模組：共享嵌入、逐深度的 transformer 區塊、投影，以及共享輸出頭。

## 問題所在

下一個詞元預測是標準的 LLM 訓練目標。每個隱藏狀態被監督去預測的東西剛好只有一個：緊接在後面的那個詞元。這個訊號弱得出乎意料。一段序列裡大部分的資訊都延伸到超過一個詞元之外 —— 結構、連貫性、事實性、算術的流程。模型只能靠在幾兆個詞元上累積大量單詞元訊號，來把那些學起來。

MTP 問的是：如果每個隱藏狀態都被監督去一次預測多個未來詞元呢？Gloeckle 等人（Meta，2024）證明了這有幫助。他們的實作是在骨幹之上放好幾個獨立的輸出頭，各自預測一個不同的偏移量。平行、簡單，但這些頭看到的是同一個隱藏狀態，中間沒有任何階層式的細化 —— 而且這些預測彼此不成因果鏈，所以無法用在推測式解碼上。

DeepSeek-V3（2024 年 12 月）把 MTP 重新設計成序列式模組，在每個預測深度上都保住因果鏈。模型先從 `h_i^(0)` 預測 `t+1`，再從一個把 `h_i^(0)` 與 `E(t+1)` 嵌入結合起來的新隱藏狀態 `h_i^(1)` 預測 `t+2`，依此類推。每個深度都是自己的一個小 transformer 區塊。共享嵌入與共享輸出頭讓參數的額外開銷維持在小量。以 DeepSeek-V3 的規模而言，在 6710 億主模型權重之上，所有 MTP 模組多出 140 億參數。這 2% 的額外開銷買到的是更密的訓練訊號**以及**推論時現成的推測式解碼草稿。

這一課會從頭建出單一個 MTP 模組與 D 層深度的損失。數學很乾淨。實作是 150 行。

## 核心概念

### 序列式 MTP 的作法

DeepSeek-V3 在主模型之上加了 `D` 個 MTP 模組。每個模組 `k`（`k = 1..D`）預測深度 `k` 的詞元 —— 也就是在給定到位置 `i` 為止的前綴時，預測 `t_{i+k}`。

模組 `k` 由這些東西組成：

- 一個有自己注意力與 MLP 的 transformer 區塊 `T_k`。
- 一個投影矩陣 `M_k`，把前一深度的隱藏狀態與下一深度真實詞元的嵌入結合起來。
- 共享嵌入 `E`（與主模型相同）。
- 共享輸出頭 `Out`（與主模型相同）。

訓練時，對於到位置 `i` 為止的前綴，逐深度的隱藏狀態是：

```math
\begin{aligned}
h_i^{(0)} &= \text{main model backbone at position } i \\
h_i^{(k)} &= T_k\Big( M_k \cdot \mathop{\mathrm{concat}}\big(\mathop{\mathrm{RMSNorm}}(h_i^{(k-1)}), \mathop{\mathrm{RMSNorm}}(E(t_{i+k}))\big) \Big) \quad \text{for } k \ge 1
\end{aligned}
```

逐深度的預測是：

```math
\text{logits}_{i+k+1} = \mathop{\mathrm{Out}}(h_i^{(k)}) \quad \text{for } k = 1, \ldots, D
```

逐深度的損失是對真實 `t_{i+k}` 的交叉熵：

```math
L_k = \mathop{\mathrm{CE}}(\text{logits}_{i+k+1}, t_{i+k+1})
```

跨深度的聯合損失：

```math
L_{\text{MTP}} = \frac{\lambda}{D} \sum_{k=1}^{D} L_k
```

`lambda` 是一個小的加權係數 —— DeepSeek-V3 在訓練的前 10% 用 0.3，之後用 0.1。總訓練損失是 `L_main + L_MTP`。

### 為什麼是序列式，不是平行式

Gloeckle 原本的平行式 MTP 有 D 個輸出頭，每個都直接作用在 `h_i^(0)` 上。每個頭都從同一個骨幹隱藏狀態預測 `t_{i+k}`。這樣訓練沒問題，但預測之間沒有互相條件化。你沒辦法用 `head_1` 的輸出去幫 `head_2` —— 這些頭是平行發射的。

DeepSeek-V3 的序列式設計，是用 `h_i^(k-1)` 加上實際的下一個詞元嵌入 `E(t_{i+k})` 來建出 `h_i^(k)`。這保住了因果鏈：要預測 `t_{i+k+1}`，深度 `k+1` 的模組看得到 `t_{i+k}` 是什麼。這在結構上與一個自迴歸解碼器消費自己輸出的方式完全相同 —— 這讓 MTP 模組可以直接拿來當推測式解碼的草稿器。

推論時：把 `h_i^(k-1)` 與草稿出來的 `t_{i+k}` 餵進模組 `k+1`，拿到對 `t_{i+k+1}` 的預測。重複。這正好就是一個 EAGLE 風格的草稿，只是把訓練好的 MTP 模組當作草稿網路。DeepSeek-V3 回報第一個 MTP 模組有 80% 以上的接受率，以及約 1.8 倍的加速。

### 參數帳

對一個隱藏維度為 `h`、詞彙表為 `V` 的模型：

- 主模型：數十億參數，加上一個大小為 `V * h` 的輸出頭。
- 共享輸出頭：重用主模型的頭。不增加參數。
- 共享嵌入：重用主模型的嵌入。不增加參數。
- 每個 MTP 模組：
  - 投影 `M_k`：`(2h) * h = 2h^2`。
  - Transformer 區塊 `T_k`：注意力（MHA 是 `4h^2`）加上 MLP（比例 8/3 的 SwiGLU 通常是 `8h^2`）。每個區塊約 `12h^2`。

每個模組總共多出：`~14h^2`。以 DeepSeek-V3 的 `h = 7168`、D = 1 個模組來算：紙上是 `~14 * 7168^2 = ~720M` 參數。DeepSeek-V3 回報的是 140 億 —— 差距主要來自 MTP 模組裡的專家層同樣是 MoE。

### 推測式解碼帶來的報酬

在預訓練期間，MTP 模組讓訓練慢了大約 10%（更多前向運算、額外的損失）。報酬有兩層：

1. 更密的訓練訊號。每個隱藏狀態看到 D+1 個監督目標。在 MMLU、GSM8K、MATH、HumanEval 上量到的效果：DeepSeek-V3 的消融實驗中呈現一致的幾個百分點提升。

2. 推論時免費的推測式解碼草稿。MTP 模組本來就已經被訓練成能預測接下來幾個詞元。改作草稿網路，它帶來 80% 以上的接受率。在那個水準上，N=3 或 N=5 的推測式解碼能給出 1.8 倍吞吐量。訓練時多付的那 10%，第一次跑推論就回本了。

### 與 EAGLE 的關係

EAGLE 是在預訓練**之後**另外訓練一個小的草稿模型。MTP 則是把草稿烤進預訓練裡。兩種作法收斂到相近的接受率，但走的是不同的管線：

| 面向 | EAGLE-3 | MTP（DeepSeek-V3） |
|-----------|---------|------------------|
| 何時訓練 | 預訓練之後 | 預訓練期間 |
| 能否沿用既有權重 | 可以 | 不行（需要重新訓練） |
| 草稿參數 | 1-2 個 transformer 層 | 1 個 transformer 區塊 + 投影 |
| 接受率 | 0.88-0.92 | 深度 1 時 0.80+ |
| 加速以外的好處 | 只有推測式解碼 | 更密的訓練訊號 + 加速 |

## 動手實作

`code/main.py` 從頭到尾建出單一個 MTP 模組：共享嵌入、投影、transformer 區塊、共享輸出頭。接著它在一段短的合成序列上計算逐深度的交叉熵損失，並按元件印出參數量。一個 32 個詞元的玩具詞彙表讓數字保持好讀。

### 步驟 1：共享嵌入表

一張 `vocab_size x hidden` 的表，被主模型**以及**每個深度上的每個 MTP 模組共用。不是第二份複本 —— 就是同一個張量。

### 步驟 2：逐深度的結合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # concat along feature dim, then project down to hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # vector addition stand-in
    projected = matvec(M_k, concat)
    return projected
```

真正的 DeepSeek-V3 是把兩個做過 RMSNorm 的向量串接成 `[2h]`，再用一個 `h x 2h` 的矩陣投影。玩具版為了 stdlib 的簡潔改用向量相加。

### 步驟 3：深度 k 的 transformer 區塊

自注意力加 MLP。在玩具版裡，一層線性注意力區塊加一個 SwiGLU MLP，讓結構在不用 numpy 的情況下仍然看得見。

### 步驟 4：共享輸出頭

重用主模型的輸出投影。得到詞彙表上的 logits。

### 步驟 5：逐深度損失

softmax(logits) 對偏移量 `k` 處真實詞元的交叉熵。以 `lambda / D` 的縮放係數跨深度彙總。

### 步驟 6：參數帳

印出總參數量、共享的部分（嵌入、輸出頭）的參數量，以及每個模組多出來的參數量。展示 MTP 額外開銷與主模型大小的比例。

## 框架應用

MTP 已整合進 DeepSeek-V3（2024 年 12 月）與 DeepSeek-R1 系列。推論方面：

- DeepSeek 自家的服務堆疊開箱即用地把 MTP 模組當作推測式解碼器來消費。
- 截至 2026 年 4 月，vLLM 與 SGLang 都有針對 DeepSeek-V3 MTP 的整合路徑。
- AMD 的 ROCm SGLang 教學給出一份具體的 MTP 推測式解碼設定，在 V3 檢查點上量到 1.8 倍加速。

在一次新的預訓練中什麼時候該用 MTP：

- 你掌控整條預訓練管線，而且想把更密的訓練訊號收進口袋。
- 你知道這個模型會大規模上線服務，想免費拿到推測式解碼。
- 你的隱藏維度至少是 4096。在 10 億參數的規模上，額外開銷的傷害大於好處。

什麼時候不該用：

- 微調一個既有的密集預訓練模型。那個 MTP 模組沒有被訓練過。
- 需要一條乾淨基準線來比較的研究模型。MTP 改動了架構。

## 練習

1. 執行 `code/main.py`。展示當合成訊號變強時，逐深度的損失會單調下降。把合成資料改成固定模式，並驗證深度 1 與深度 2 的損失都會收斂。

2. 算出一個密集 70B 模型（隱藏維度 8192、80 層）在 D=1 個 MTP 模組下的參數額外開銷。與 DeepSeek-V3 回報的 140 億額外開銷比較。解釋為什麼 DeepSeek 的數字比較高：MTP 的 transformer 區塊沿用了同樣的 MoE 結構，把每個模組的參數量撐大了。

3. 在玩具版裡實作 D=2：加上第二個 MTP 模組，它吃 h^(1) 並預測 `t_{i+2}`。驗證聯合損失與參數帳與 DeepSeek 論文的式 19-21 相符。

4. 把玩具版換成平行式 MTP（Gloeckle 風格）：在主隱藏狀態之上加 D 個輸出頭，各自預測一個不同的偏移量。在同一段合成訊號上，量測逐深度的損失與序列式版本相比如何。序列式版本在 k > 1 時應該產生更低的深度 k 損失，因為它條件化在中間的預測上。

5. 把訓練好的 MTP 模組當作 EAGLE 風格的草稿使用：推論時呼叫模組 k 來提議 `t_{i+k}`。在一段留出序列上，量測這些草稿詞元相對主模型預測的接受率。如果你在玩具版上打到 50% 以上，你就重現了 MTP 可當草稿的實證性質。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|----------------|------------------------|
| MTP 模組 | 「額外的損失區塊」 | 一個小型 transformer 區塊加投影，預測比主模型再前面 `k` 個位置的詞元 |
| 預測深度 | 「哪一個偏移量」 | 整數 `k`，使得模組 `k` 從到位置 `i` 為止的前綴預測 `t_{i+k}` |
| 平行式 MTP | 「Gloeckle 風格」 | 在同一個骨幹隱藏狀態上放 D 個獨立的頭，沒有條件鏈 |
| 序列式 MTP | 「DeepSeek-V3 風格」 | 每個模組條件化在前一深度的隱藏狀態加上下一個詞元的嵌入上；保住因果鏈 |
| 共享輸出頭 | 「重用主模型的頭」 | MTP 模組呼叫的是主模型的 LM head，不是另一個輸出投影 |
| 共享嵌入 | 「重用主模型的表」 | 到處用的都是同一張詞彙嵌入表；沒有重複的參數 |
| 投影矩陣 M_k | 「把隱藏狀態 + 下一個詞元合起來」 | 一個 `h x 2h` 的線性層，把前一個隱藏狀態與目標詞元的嵌入摺進下一深度的輸入 |
| 聯合損失 L_MTP | 「平均後的額外損失」 | 逐深度交叉熵損失的算術平均，再乘上 `lambda` |
| 深度 1 的接受率 | 「MTP 草稿多常猜對」 | D=1 的 MTP 模組 top-1 預測等於主模型 top-1 預測的比率；DeepSeek-V3 上為 80%+ |
| Lambda 加權 | 「額外損失的重要性」 | 逐深度的縮放係數；DeepSeek-V3 訓練初期 0.3，之後 0.1 |
