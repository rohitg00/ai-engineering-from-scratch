## 問題所在

70B 模型的自迴歸解碼，在 H100 上大概只跑得到每秒 35 個詞元。GPU 遠遠沒有吃飽。天花板是記憶體頻寬：每產生一個詞元，就要從 HBM 載入 70B 的權重、做一步算術、吐出一個浮點數。運算單元大多在發呆。

推測式解碼把這件事變成一個你真的解得掉的吞吐量問題。便宜的草稿用 `N` 次小型前向傳播提出 `N` 個詞元。驗證模型對「前綴 + 全部 `N` 個草稿」跑一次。如果驗證模型在位置 `i` 的分布與草稿吻合（吻合的統計意義稍後會講精確），就接受；不吻合就拒絕，並從殘差分布取樣一個修正詞元。一次大模型的前向傳播，產出的不再是一個詞元，而是最多 `N+1` 個被接受的詞元。

真正關鍵的定理是 Leviathan、Kalman、Matias（ICML 2023）：輸出分布與直接從驗證模型取樣得到的結果完全一致。不是近似，是完全相同。這就是推測式解碼能在生產環境被接受的全部理由 —— 它是純粹的延遲最佳化，品質上零妥協。

階段 7 · 單元 16 給你的是數學，這一課給你的是訓練堆疊。好草稿帶來的加速，比便宜草稿高上 2 倍。EAGLE、EAGLE-2、EAGLE-3（Li 等人，2024 到 2025）把「草稿 = 同一個模型的縮小版」變成一門精確的工程學問。2026 年的生產級推論伺服器預設就是 EAGLE-3。

## 核心概念

### 不變量：Leviathan 拒絕取樣

令 `p(t)` 為草稿在某個前綴下對下一個詞元的分布，`q(t)` 為驗證模型的分布。取樣出一個草稿詞元 `d ~ p`，以機率 `min(1, q(d) / p(d))` 接受。被拒絕時，從殘差分布 `(q - p)_+ / ||(q - p)_+||_1` 取樣。這樣得到的樣本服從 `q`。這件事與 `p` 有多爛無關 —— `p` 越爛只是拒絕得越頻繁，輸出仍然精確。

用一次對 `prefix + d_1 + ... + d_N` 的驗證前向傳播，把 `N` 個這種呼叫疊在一起。驗證模型會同時回傳 `q_1, q_2, ..., q_{N+1}`。由左往右走。在第一次於位置 `j` 被拒絕時，從 `residual(q_j, p_j)` 取樣並停下。全部接受時，再從 `q_{N+1}` 取樣一個紅利詞元。

### 加速幅度由什麼決定

令 `α` 為每個草稿詞元的期望接受率，`c = cost(draft) / cost(verifier)` 為成本比。每次驗證前向傳播的期望被接受詞元數為：

```math
\mathbb{E}[\text{accepted}] = \frac{1 - \alpha^{N+1}}{1 - \alpha}
```

每個被接受詞元的期望總牆鐘時間是 `(N * c + 1) / E[accepted]`。對 `N` 取極小，就得到甜蜜點。`α = 0.8, c = 0.05` 時：最佳 `N` 大約在 5 到 7，加速 3.2 倍。`α = 0.95, c = 0.02` 時：最佳 `N` 大約在 8 到 10，加速逼近 5 倍。

最大的槓桿是 `α`。在 `N = 5` 固定的情況下，從 `α = 0.6`（原味草稿）走到 `α = 0.9`（EAGLE-3），每次驗證前向傳播的期望被接受詞元數會從 2.2 升到 4.1。同一個驗證模型，吞吐量接近翻倍。

### 兩年演進

**原味推測式（Leviathan，2023）。** 草稿模型是同家族中另外獨立訓練的較小 LLM。接起來很容易，`α ≈ 0.6`，加速頂多 2 倍左右。

**EAGLE-1（Li 等人，2024）。** 草稿是一個極小的 transformer —— 通常只有一兩層 —— 吃進驗證模型最後一層的隱藏狀態，直接預測下一個詞元。因為草稿看得到驗證模型的特徵表示，它的分布與驗證模型接近得多。`α` 爬到 0.7 到 0.8。

**EAGLE-2（Li 等人，2024）。** 加上動態草稿樹：不再提出單一條 `N` 個詞元的序列，而是提出一棵小的候選樹，用一次前向傳播（樹狀注意力）替每個節點評分，再沿著機率最高的路徑走。草稿長度變成逐步自適應。被接受路徑上的逐詞元 `α` 爬過 0.85。

**EAGLE-3（Li 等人，2025，NeurIPS）。** 又動了兩處。第一，整個丟掉特徵預測損失 —— EAGLE-1/2 訓練草稿去對齊驗證模型的隱藏狀態，這會限制資料量帶來的效益上限。EAGLE-3 直接對詞元預測做訓練。第二，訓練時測試（TTT）：草稿訓練期間，把草稿自己前幾步的預測回餵成輸入，跨多個步驟，完全比照它在推論時的運作方式。這就把訓練與測試的分布對齊了，也擋掉誤差累積。實測加速：聊天場景最高 6.5 倍，在 H100 上用 SGLang 跑 batch 64 時吞吐量提升 38%。

### KV 快取回捲

驗證會用一趟前向傳播把驗證模型的 KV 快取延長 `N` 筆。如果在位置 `j` 發生拒絕，位置 `j-1` 之後的快取內容就是錯的。常見的兩種實作：寫進暫存緩衝區、接受了才提交（vLLM、TensorRT-LLM），或是維護一份實體 KV 快取加上一個邏輯長度、被拒絕時截斷。不論哪一種，回捲的成本都只是每層每個頭的幾個位元組，相較前向傳播的成本可以忽略。

至於 EAGLE-2 的樹狀搜尋，驗證模型跑注意力時用的是一個尊重樹狀拓樸的非因果遮罩。工程上很瑣碎，但計算本身就是一次帶自訂遮罩的標準 flash-attention 呼叫。

## 動手實作

請看 `code/main.py`。這是完整的 Leviathan 推測式迴圈，零件都齊了：起草 N 個、驗證模型平行驗證、逐位置拒絕、殘差取樣、紅利詞元、KV 回捲，以及實證確認輸出分布與直接從 `q` 取樣吻合。

### 步驟 1：拒絕規則

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步驟 2：殘差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步驟 3：一次完整的推測式步驟

`spec_step` 函式從 `p` 起草 `N` 個詞元，再用一次平行的 `q` 評估把它們全部驗證掉。對每個草稿詞元套用拒絕規則，第一次被拒絕時就從殘差取樣出修正詞元。若全部接受，則從 `q_{N+1}` 吐出一個紅利詞元。

### 步驟 4：KV 回捲的帳務

模擬器會為每個 worker 追蹤一個邏輯上的 `kv_length`。接受了 `k` 個草稿時，`kv_length += k`。在位置 `j` 被拒絕時，快取實際上已經寫過 `j` 了，但邏輯長度會設成 `prefix_length + j + 1` —— 也就是修正詞元的後一格。後續讀取一律截斷到邏輯長度。

### 步驟 5：Leviathan 檢驗

跑 50,000 次推測式步驟，統計被接受詞元的經驗分布，拿去跟 50,000 次直接從 `q` 取樣的結果比較。卡方統計量應該遠低於臨界值。定理在實務上站得住。

### 步驟 6：加速幅度對 α

以不同幅度把 `p` 從 `q` 擾動開，藉此掃過草稿品質。量測 `α`，再把每次驗證呼叫的期望詞元數畫成 `α` 與 `N` 的函式。程式碼會印出一張表，顯示 EAGLE-3 等級的草稿品質（`α ≈ 0.9`）如何把每次驗證呼叫解鎖到 4 到 5 個詞元。

## 框架應用

生產級的 `vllm serve` 搭配 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

依 EAGLE-3 論文，SGLang 在 H100 上用 EAGLE-3 跑 batch 64，吞吐量約為同樣 batch 64 原味解碼的 1.38 倍。

什麼時候該搬出推測式解碼：

- 任何 p50 延遲比尖峰吞吐量更重要的互動式聊天工作負載。
- 程式碼生成與結構化輸出（JSON、SQL）。因為目標分布高度可預測，`α` 會在 0.9 以上。
- 長篇生成（數千個詞元）。攤提下來的加速會一直有回報。

什麼時候不要：

- 非常小的模型（小於 3B）。草稿並不會比驗證模型便宜多少。
- 極小的 batch-1 CPU 部署。草稿模型多佔的記憶體可能不划算。
- 溫度極高的創意取樣，`α` 會崩掉。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|----------------|------------------------|
| Leviathan 規則 | 「min(1, q 除以 p)」 | 以機率 `min(1, q(d)/p(d))` 做伯努利接受／拒絕；只要被拒絕時從殘差取樣，就能原封不動保住驗證模型的分布 |
| 殘差分布 | 「(q 減 p) 取正再正規化」 | `(q - p)_+` 夾到零再重新正規化 —— 被拒絕時該取樣的正確分布 |
| 接受率 α | 「草稿猜對的頻率」 | 拒絕規則下逐詞元的期望伯努利成功機率；所有加速數學都由它主導 |
| EAGLE-1 | 「吃隱藏狀態的草稿」 | 以驗證模型最後一層隱藏狀態為條件的極小 transformer 草稿（Li 等人，2024） |
| EAGLE-2 | 「動態草稿樹」 | EAGLE-1 再加一棵候選續寫樹，用樹狀注意力在一次驗證傳播裡評分 |
| EAGLE-3 | 「訓練時測試」 | 丟掉特徵預測損失，改成直接對詞元預測訓練，並在訓練期間把草稿自己的輸出餵回去 |
| 訓練時測試（TTT） | 「exposure bias 的解法」 | 訓練期間讓草稿自迴歸地跑，使訓練與測試的輸入分布一致 —— 正是 scheduled sampling 的直接對應物 |
| KV 回捲 | 「撤銷被拒絕的草稿」 | 拒絕之後把驗證模型的 KV 快取重設回被接受前綴長度的帳務工作 |
| 紅利詞元 | 「免費的那一個」 | `N` 個草稿全部被接受時，從 `q_{N+1}` 再多取樣一個，不用多付驗證成本 |
| 樹狀注意力 | 「一次驗證多個候選」 | 帶有尊重草稿樹拓樸之非因果遮罩的注意力；一次前向傳播就算出樹中每個節點的 `q_i` |
