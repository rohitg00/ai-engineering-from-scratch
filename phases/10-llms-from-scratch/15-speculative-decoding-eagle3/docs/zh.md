# 投机解码与 EAGLE-3

> 阶段7·第16课从数学上证明了一个结论：利维坦（Leviathan）拒绝规则精确地保持了验证器的分布。本课从训练栈的视角审视 2026 年生产级的投机解码。EAGLE-3 将草稿模型从一个廉价的近似方案，转变为在验证器自身隐状态上训练的、特制的小型网络，并在训练阶段加入了一个测试循环，使其训练分布与推理分布对齐。结果：端到端加速 3 倍至 6.5 倍，对话场景下每 token 接受率超过 0.9，且无分布偏移。2026 年所有生产级推理栈默认搭载该技术。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段7·第16课（投机解码数学基础）、阶段10·第12课（推理优化）

## 学习目标

- 用一句话描述利维坦定理，并证明投机循环产生的样本与验证器同分布。
- 梳理从普通投机解码（Leviathan, 2023）到 EAGLE、EAGLE-2 和 EAGLE-3 的两年演进历程，指出每一步消除的具体瓶颈。
- 根据接受率 `α` 和草稿与验证器成本比 `c` 计算预期加速比，并针对不同场景选择最优草稿长度 `N`。
- 从零实现完整的投机循环：草稿、验证、从残差分布中拒绝采样、拒绝时回滚 KV 缓存、完全接受时生成奖励 token。

## 问题

在 H100 上，70B 模型的自回归解码大约每秒生成 35 个 token。GPU 远未饱和。内存带宽是瓶颈：每个 token 都需要从 HBM 加载 70B 的权重，执行一次算术运算，产生一个浮点数。计算单元大部分时间处于空闲状态。

投机解码将这一问题转化为一个可以实际解决的吞吐量问题。廉价的草稿模型通过 `N` 次小型前向传播提出 `N` 个 token。验证器在前缀加上所有 `N` 个草稿 token 上运行一次。如果验证器在位置 `i` 上的分布与草稿一致（在统计意义上，我们后面会精确说明），则接受；如果不一致，则拒绝并从残差分布中采样一个修正 token。一次大模型的前向传播最多可以产生 `N+1` 个已接受的 token，而不是一个。

关键定理来自 Leviathan、Kalman 和 Matias（ICML 2023）：输出分布与直接从验证器采样得到的分布完全相同。不是近似，而是完全相同。这就是投机解码可以在生产环境中被接受的全部原因——它是一种纯粹的延迟优化，没有任何质量损失。

阶段7·第16课教给你的是数学。本课教给你的是训练栈。一个好的草稿模型带来的加速效果是廉价草稿的两倍。EAGLE、EAGLE-2 和 EAGLE-3（Li 等人，2024–2025）将"草稿 = 同模型的小型版本"发展为一项精确的工程学科。2026 年生产级推理服务器默认使用 EAGLE-3。

## 核心概念

### 不变性：利维坦拒绝采样

设 `p(t)` 为草稿模型在给定前缀下对下一个 token 的分布，`q(t)` 为验证器的分布。从草稿分布中采样一个 token `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。如果拒绝，则从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。最终样本服从分布 `q`。无论 `p` 的质量有多差，这个结论都成立——草稿越差，拒绝的频率越高，但输出始终是精确的。

将 `N` 次这样的调用串联起来，验证器在 `prefix + d_1 + ... + d_N` 上执行一次前向传播，同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。如果在位置 `j` 首次拒绝，则从 `residual(q_j, p_j)` 中采样并停止。如果全部接受，则从 `q_{N+1}` 中采样一个奖励 token。

### 加速比的决定因素

设 `α` 为每个草稿 token 的预期接受率。设 `c = cost(草稿) / cost(验证器)` 为成本比。每次验证器前向传播的预期接受 token 数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个接受 token 的预期总耗时（wall time）为 `(N * c + 1) / E[accepted]`。对 `N` 求最小值即可得到最佳取值。当 `α = 0.8, c = 0.05` 时，最优 `N` 约为 5–7，加速比为 3.2 倍。当 `α = 0.95, c = 0.02` 时，最优 `N` 约为 8–10，加速比接近 5 倍。

最大的杠杆是 `α`。在 `N = 5` 固定的情况下，从 `α = 0.6`（普通草稿）提升到 `α = 0.9`（EAGLE-3），每次验证器前向传播的预期接受 token 数从 2.2 增加到 4.1。使用同一个验证器，吞吐量几乎翻倍。

### 两年演进历程

**普通投机解码（Leviathan, 2023）。** 草稿模型是一个独立训练的、同系列的小型 LLM。易于搭建，`α ≈ 0.6`，加速比最好在 2 倍左右。

**EAGLE-1（Li 等人, 2024）。** 草稿是一个小型 Transformer——通常只有一两层——它以验证器最后一层的隐状态作为输入，直接预测下一个 token。由于草稿能看到验证器的特征表示，其分布更接近验证器。`α` 提升至 0.7–0.8。

**EAGLE-2（Li 等人, 2024）。** 增加了动态草稿树：不提议单个 `N` token 的序列，而是提议一个小型的候选树，在一次前向传播中用验证器对每个候选评分（树注意力），然后走概率最高的路径。草稿长度变为每步自适应。每条已接受路径上的 `α` 超过 0.85。

**EAGLE-3（Li 等人, 2025, NeurIPS）。** 两个改进。第一，完全去掉特征预测损失——EAGLE-1/2 训练草稿去匹配验证器的隐状态，这限制了数据的效用。EAGLE-3 直接针对 token 预测进行训练。第二，训练时测试（TTT）：在草稿训练过程中，将草稿自身之前的预测结果作为输入回传多个步骤，这与推理时的运行方式相同。这使得训练分布和测试分布对齐，阻止了误差累积。实测加速比：对话场景最高 6.5 倍，在 H100 上以 batch 64 运行 SGLang 时吞吐量提升 38%。

### KV 缓存回滚

验证过程在一次前向传播中将验证器的 KV 缓存扩展了 `N` 个条目。如果在位置 `j` 发生拒绝，则位置 `j-1` 之后的缓存内容不再正确。两种常见的实现方式：写入临时缓冲区并在接受时提交（vLLM、TensorRT-LLM），或者维护一个物理上的 KV 缓存加一个逻辑长度，拒绝时截断。无论哪种方式，回滚的成本是按层级和注意力头计算的字节量，与前向传播的成本相比可以忽略不计。

对于 EAGLE-2 的树搜索，验证器使用一个非因果掩码来运行注意力，该掩码遵循树的拓扑结构。工程实现比较繁琐，但计算就是一次带有自定义掩码的标准 flash-attention 调用。

### 2026 年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|----------|-----------|-----|---------|---------------|
| 普通方案 | 独立的小型 LLM | 0.55–0.70 | 1.8–2.3 倍 | 无（复用已有小模型） |
| Medusa | 验证器上的额外 LM 头 | 0.65–0.75 | 2–3 倍 | 约 1B SFT token |
| EAGLE-1 | 基于隐状态的 1 层 Transformer | 0.70–0.80 | 2.5–3 倍 | 约 60B token |
| EAGLE-2 | EAGLE-1 + 动态草稿树 | 0.80–0.88 | 3–4 倍 | 约 60B token |
| EAGLE-3 | 多层特征融合 + TTT | 0.88–0.92 | 3.5–6.5 倍 | 约 60–200B token |
| Lookahead | 无草稿（Jacobi 迭代） | 不适用 | 1.3–1.6 倍 | 无 |

在 2026 年生产环境中：vLLM 和 SGLang 在可用时默认使用 EAGLE-3，否则使用 EAGLE-2。TensorRT-LLM 为 Meta 和 NVIDIA 的公开模型提供了最快的 Medusa 路径。llama.cpp 在 CPU 部署中使用普通草稿。

## 动手构建

参见 `code/main.py`。这是完整的利维坦投机循环，包含所有组件：N 步草稿、验证器并行前向传播、逐位置拒绝、残差采样、奖励 token、KV 回滚，以及输出分布与直接采样 `q` 是否一致的实证验证。

### 步骤 1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤 2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤 3：完整的投机步骤

`spec_step` 函数从 `p` 中草拟 `N` 个 token，然后在一次并行的 `q` 评估中验证所有草拟 token。对于每个草拟的 token，它应用拒绝规则，并在首次拒绝时从残差中采样修正 token。如果全部接受，则从 `q_{N+1}` 输出一个奖励 token。

### 步骤 4：KV 回滚记账

模拟器为每个工作线程维护一个逻辑上的 `kv_length`。当接受 `k` 个草稿时，`kv_length += k`。如果在位置 `j` 拒绝，缓存中已写入超过 `j` 的内容，但逻辑长度设置为 `prefix_length + j + 1`——即修正 token 之后的一个位置。后续读取将截断到该逻辑长度。

### 步骤 5：利维坦检验

运行 50,000 次投机步骤。统计已接受 token 的经验分布。与 50,000 次直接从 `q` 采样的结果进行比较。卡方统计量应远低于临界值。该定理在实践中成立。

### 步骤 6：加速比与 α 的关系

通过以不同幅度扰动 `p` 偏离 `q` 来扫描草稿质量。测量 `α`，然后绘制预期 token 数随 `α` 和 `N` 变化的曲线。代码输出一张表格，展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何在每次验证器调用时产生 4–5 个 token。

## 使用方式

生产级的 `vllm serve` 搭配 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在 H100 上以 batch 64 运行 SGLang 并搭配 EAGLE-3：根据 EAGLE-3 论文，吞吐量大约是 batch 64 普通解码的 1.38 倍。

何时使用投机解码：

- 任何交互式对话场景，p50 延迟比峰值吞吐量更重要时。
- 代码生成和结构化输出（JSON、SQL）。由于目标分布高度可预测，`α` 超过 0.9。
- 长文本生成（数千个 token）。分摊后的加速收益持续累积。

何时不应使用：

- 非常小的模型（< 3B）。草稿相比验证器并没有便宜多少。
- 批大小为 1 的 CPU 部署。草稿模型的内存开销可能得不偿失。
- 极高温度的创意采样，此时 `α` 会急剧下降。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------------|------------------------|
| 利维坦规则 | "min(1, q 除以 p)" | 以概率 `min(1, q(d)/p(d))` 进行伯努利接受/拒绝，拒绝时从残差分布采样，精确保持验证器分布 |
| 残差分布 | "(q 减 p) 取正，归一化" | `(q - p)_+` 截断到零并重新归一化——拒绝时采样的正确分布 |
| 接受率 α | "草稿有多准" | 拒绝规则下每 token 的期望伯努利成功概率；所有加速比计算的核心 |
| EAGLE-1 | "隐状态草稿" | 以验证器最后一层隐状态为条件的小型 Transformer 草稿（Li 等人, 2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1 加上一棵候选延续树，在一次验证器前向传播中用树注意力评分 |
| EAGLE-3 | "训练时测试" | 去掉特征预测损失，直接针对 token 预测进行训练，训练时草稿使用自身的输出 |
| 训练时测试（TTT） | "曝光偏差修复" | 训练时让草稿自回归运行，使训练和推理的输入分布一致——课程采样的直接类比 |
| KV 回滚 | "撤销被拒绝的草稿" | 拒绝后将验证器的 KV 缓存重置为已接受前缀长度的记账机制 |
| 奖励 token | "免费的那个" | 当所有 `N` 个草稿都被接受时，从 `q_{N+1}` 额外采样一个 token，不增加验证器成本 |
| 树注意力 | "一次验证多个候选" | 使用非因果掩码的注意力机制，尊重草稿树的拓扑结构；一次前向传播计算树中所有节点的 `q_i` |
