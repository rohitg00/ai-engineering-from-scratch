# LLM 预训练数据质量检查器

在构建或审计 LLM 预训练的数据流水线时，使用此框架在问题到达模型之前发现问题。

## 流水线输出的危险信号

**去重移除了不到 20% 的网络数据。** Common Crawl 通常包含 30-40% 的重复数据。如果去重步骤移除少于 20%，则 MinHash 参数过于保守或阈值过高。检查：分片大小 k、哈希函数数量、LSH 频带数量、Jaccard 阈值。

**压缩比低于 2.0 字符/token。** 这意味着分词器拆分过于激进。要么用更多合并重新训练，增加词汇量大小，要么检查预分词是否不必要地碎片化了文本。

**压缩比高于 6.0 字符/token。** 分词器学习到了非常领域特定的合并，可能无法泛化。这对领域特定模型没问题，但对通用模型是一个警告信号。

**序列利用率低于 90%。** 填充过多。要么文档太短（过滤它们或增加最小文档长度），要么序列打包效率低下（从朴素填充切换到多文档打包）。

**词汇表利用率低于 50%。** 超过一半的词汇表在该语料库上未被使用。要么词汇表对您的领域来说太大，要么分词器是在非常不同的数据上训练的。

## 质量过滤器校准

在每个流水线阶段对 1,000 个文档的随机样本运行这些检查：

1. **阅读清洗后的 20 个随机文档。** 它们是否包含残留的 HTML、JavaScript、导航文本或样板内容？如果是，则 HTML 剥离不完整。

2. **阅读通过了质量过滤器的 20 个随机文档。** 其中是否有垃圾信息、关键词列表或机器生成的内容？如果是，收紧过滤器阈值。

3. **阅读未通过质量过滤器的 20 个随机文档。** 其中是否有真正优质的内容？如果是，过滤器过于激进。放宽阈值或为特定模式添加例外。

4. **阅读去重后的 20 个随机近似重复对。** 它们是否确实相似？如果不是，降低 Jaccard 阈值或增加哈希函数数量。

## 数据混合比例

没有通用公式。从以下基线开始，基于评估进行调整：

| 类别 | Llama 3 比例 | 起始点 |
|----------|--------------|----------------|
| 网络文本 | 50% | 50% |
| 代码 | 25% | 15-25% |
| 书籍/学术 | 13% | 10-15% |
| 数学 | 8% | 5-10% |
| 多语言网络 | 4% | 5-10% |

如果模型需要在编程方面表现强劲，增加代码比例。如果推理能力重要，增加数学比例。如果需要更少噪音，降低网络比例。更改比例后务必在基准测试上进行评估。

## 规模估算

对于给定的目标 token 数量：

- 1T token 的网络数据：预期约 3-5TB 原始文本，清洗和去重后约 1.5-2TB
- 分词速度（Rust）：每核每秒约 1 亿 token
- 分词速度（Python）：每核每秒约 1-1 千万 token
- 128 哈希、16 频带的 MinHash 去重：每核每秒约 1 万文档
- 序列打包：I/O 密集型，对超过 10GB 的语料库使用内存映射文件

对于 15T token（Llama 3 规模），计划约 30-50TB 原始输入数据，在 64 核机器上预处理 1-2 周，以及 100TB+ 的磁盘用于中间文件。

## 训练前检查清单

1. 总 token 数与计算预算匹配（使用 Chinchilla 缩放或 Llama 3 过训练比例作为指导）
2. 去重移除了 30-40% 的网络数据
3. 质量过滤器移除了剩余数据的 10-20%
4. 英语压缩比为 3-5 字符/token
5. 序列利用率高于 95%
6. 在流水线的每个阶段随机抽查显示干净、连贯的文本
7. 数据混合比例已在小规模训练运行中验证
8. PII 移除已在样本上验证
9. 所有二进制格式（打包序列、token ID 数组）通过往返编码/解码测试
10. 流水线可重现：相同输入在固定随机种子下产生相同输出
