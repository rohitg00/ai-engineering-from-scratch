给定一个提议的训练流水线清单（描述分词器、数据、预训练、SFT、对齐、评估、量化和服务阶段的 YAML 或 JSON），生成涵盖以下内容的审查：

1. 阶段图。确认每个阶段有类型化的输入和输出。指出缺失的依赖项、隐式状态，或任何消耗裸目录而非命名工件哈希的阶段。
2. 哈希链。验证阶段 N 的 output_hash 等于每个下游阶段的 input_hashes 之一。任何不匹配意味着清单不连贯，流水线不得启动。
3. 评估门控。门控列表中的每个指标必须是数值型、有运算符、有阈值和测量来源。拒绝任何主观的（"看起来不错"）、无界的（无阈值）或在训练数据上测量的门控。
4. 回归防护。新模型的核心基准测试（MMLU、MATH、HumanEval+、GPQA 或领域特定等价物）必须附有基线数值。没有基线的运行就是没有回归检测的运行。
5. KL 预算。对齐阶段（RLHF、DPO、CAI、GRPO）必须声明相对于参考模型的累积 KL 上限。无界 KL 就是无界漂移。
6. 污染检查。训练数据分片和评估集必须有文档化的重叠检查（精确匹配或 13-gram）。必要通过阈值：< 0.1%。
7. 成本估算。每个阶段的运行前估算加总，与预算门控比较。如果估算 > 预算，流水线拒绝启动。
8. 回滚计划。每个阶段有失败时的命名操作：重新运行、回退到之前的工件、修改输入并重新运行下游。昂贵的阶段（预训练）必须有暖检查点策略。
9. 工件存储。检查点、数据集、分词器、评估报告必须是内容寻址的（SHA-256）。文件名寻址的工件（"latest.pt"）是硬拒绝。
10. 可观测性。每个阶段必须发出结构化日志，包含跟踪 ID、阶段名称、输入哈希、输出哈希、墙钟时间和成本。缺少跟踪 ID 意味着运行后无法调试。

暂停审查的危险信号：
- 缺少测量来源的门控（对没有阶段计算的指标设置门控）
- 与下游阶段共享检查点的阶段（无关注点分离）
- 没有参考模型的对齐阶段（无 KL 锚点）
- LLM 作为评判的评估中评判与策略属于同一模型家族（污染）
- 超出预算 20% 以上的成本估算
- 完全由"从头重新运行"组成的回滚计划

输出：两页审查，每个关卡有 PASS/HOLD、产生每个判断的确切清单字段或缺失字段，以及将 HOLD 翻转为 PASS 所需的最小更改。
