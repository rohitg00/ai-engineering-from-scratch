# 双管道并行（DualPipe Parallelism）

> DeepSeek-V3 在 2,048 块 H800 GPU 上训练，其 MoE 专家分布在跨节点。跨节点专家全对全通信的通信开销与计算开销的比例为 1:1——每 1 GPU 小时的计算就需要 1 GPU 小时的通信。GPU 有一半时间处于空闲。DualPipe（DeepSeek，2024 年 12 月）是一种双向流水线，它将前向和反向计算与它们触发的全对全通信重叠起来。气泡减少，吞吐量提升，而保留两份模型参数副本（即名称中的"双"）的成本在专家并行已经将专家分散到各 rank 的情况下微乎其微。本课是一篇"学习"型讲解，介绍 DualPipe 实际做了什么，以及为什么 Sea AI Lab 的 DualPipeV 改进以略微收紧的气泡为代价，消除了 2 倍参数成本。

**类型：** 学习
**语言：** Python（标准库，调度模拟器）
**前置知识：** 阶段 10 · 05（分布式训练、FSDP、DeepSpeed），阶段 10 · 14（开源模型架构与 MoE）
**时长：** 约 60 分钟

## 学习目标

- 说出 DualPipe 前向-反向块的四个组成部分，以及为什么每个部分都有自己的重叠窗口。
- 解释大规模下的流水线气泡问题，以及"无气泡"在实践中与营销中的区别。
- 为 8 个 PP rank 和 16 个微批次手动跟踪一个 DualPipe 调度，并确认前向流和反向流相互填充对方的空闲时段。
- 说明 DualPipeV（Sea AI Lab，2025 年）所做的折衷：在专家并行未激活时，以略大的气泡为代价消除 2 倍参数复制。

## 问题

在 2k 块 H800 GPU 上训练一个 671B 的 MoE 模型会遇到三个叠加的性能瓶颈：

1. **内存压力。** 每块 GPU 持有模型的一个切片。在序列长度 8k、61 层、128 个注意力头的情况下，激活内存巨大。
2. **流水线气泡。** 传统的流水线并行（GPipe、1F1B）在 GPU 等待其阶段的输入或梯度时使其空闲。在 8 个阶段时，即使采用 1F1B 调度，大约 12% 的 GPU 时间也可能是气泡。
3. **跨节点全对全。** 采用专家并行的 MoE 将专家分散到各节点。每个前向传递触发一次全对全来将令牌分发到其所属专家，另一次来合并。在 2k GPU 规模下，这很容易达到 1:1 的计算与通信比。

每个问题都有各自的解决方案：梯度检查点用于内存，Zero Bubble（Sea AI Lab，2023）用于流水线气泡，专家并行通信内核用于全对全。DualPipe 所做的是让它们协同工作。该调度在单个前向-反向块内重叠计算和通信，同时从流水线的两端注入微批次，并利用由此产生的调度将全对全隐藏在计算窗口内。

报告的结果：几乎消除了流水线气泡，在 DeepSeek-V3 的 14.8T token 训练运行中 GPU 利用率超过 95%。

## 概念

### 流水线并行回顾

将 N 层模型分割到 P 个设备上。设备 `i` 持有层 `i * N/P .. (i+1) * N/P - 1`。一个微批次从设备 0 到 P-1 前向流动，然后从 P-1 到 0 反向流动。每个设备只能在前一个设备发送其输出后开始其前向阶段，并且只能在下游设备发送上游梯度后开始反向阶段。

GPipe（Huang 等人，2019）一次调度一个微批次，这浪费了大部分 GPU 时间。1F1B（Narayanan 等人，2021）为多个微批次交错执行前向和反向传递。Zero Bubble（Qi 等人，2023）将反向传递拆分为两部分——反向-输入（B）和反向-权重（W）——并调度它们来填充气泡。在 Zero Bubble 之后，流水线几乎被填满了。

DualPipe 是下一步。它在上述基础上增加了两个想法：

### 想法 1：块分解

每个前向块被拆分为四个组件：

- **注意力（Attention）。** Q/K/V 投影、注意力计算、输出投影。
- **全对全分发（All-to-all dispatch）。** 将令牌发送到其所属专家的跨节点通信。
- **MLP。** MoE 专家计算。
- **全对全合并（All-to-all combine）。** 将专家输出带回的跨节点通信。

反向块则为每个组件添加对应的梯度版本。DualPipe 的调度方式使得全对全分发与下一个块的注意力计算并行，全对全合并与后续块的 MLP 计算并行。

### 想法 2：双向调度

大多数流水线调度从阶段 0 注入微批次，并向阶段 P-1 流动。DualPipe 从**两端**注入微批次。阶段 0 看到那里起始的前向微批次；阶段 P-1 也看到那里起始的前向微批次。两股流在中间相遇。

为此，设备 `i` 必须同时持有流水线前期的层 `i` **和**流水线后期的层 `P - 1 - i`。这就是 DualPipe 中"双"的含义：每个设备维护两份所需的模型层副本（每个方向一份）。在 DeepSeek-V3 的规模下，这是 2 倍参数复制成本。这是可以承受的，因为专家并行已经将 MoE 专家分散得非常薄，复制非专家层两次的成本相对较小。

关键的是，一个方向上的前向流和另一个方向上的反向流正好在单向调度中会出现气泡的位置重叠。气泡消失了。

### 手动跟踪的调度示例

考虑 P = 4 个 rank，8 个微批次，分为 4 个前向 / 4 个反向。时间从左向右移动；行是设备 rank。

```
           Time →
rank 0:  F1 F2 F3 F4  F5R F6R F7R F8R  B1 B2 B3 B4  ...
rank 1:     F1 F2 F3  F4/F5R F6R F7R   B1 B2 ...
rank 2:        F1 F2  F3/F5R F4/F6R    B1 ...
rank 3:           F1  F2/F5R F3/F6R    ...
```

解读"F4/F5R"符号：rank 1 在同一时间槽中同时运行微批次 4 的前向（在流水线中从左向右）**和**微批次 5 的前向（从右向左）。这就是"双向"在操作层面的含义。

在 rank 2 处，交叉流更早重叠；在 rank 0 和 rank P-1 处，重叠最晚。在调度的稳定中期阶段，每个 rank 都运行着 X 方向的前向与 Y 方向的反向重叠。计算始终繁忙。前向传递的全对全分发隐藏在反向计算中。全对全合并隐藏在前向计算中。气泡被挤压掉了。

### 气泡核算

标准 1F1B 流水线气泡（每个 rank 浪费的时间）：

```
bubble_1F1B = (P - 1) * 前向块时间
```

Zero Bubble 的改进将其降低，但未降至零。DualPipe 在稳定阶段，如果微批次数量能被 2 倍流水线深度整除，则气泡为零。在稳定阶段之外（预热和冷却阶段），存在一些气泡，但它不会随微批次数量增长——这是论文强调的一个关键特性。

用营销术语来说："无气泡"。用技术术语来说：气泡不随微批次数量增长。Sea AI Lab 的后续分析（DualPipeV / Cut-in-half）表明，只有当专家并行不是瓶颈时，才能实现完全零气泡；在存在 EP 驱动的全对全时，总会有一些调度折衷。

### DualPipeV——改进

Sea AI Lab（2025 年）观察到，当 EP 通信重叠不是关键点时，2 倍参数复制是一种浪费。他们的 DualPipeV 调度将双向注入折叠成一种"V 形"调度，在单个参数副本上运行。气泡比 DualPipe 稍大，但内存节省显著。DeepSeek 在其开源的 DualPipe 实现中采用了 DualPipeV 作为 EP 关闭模式。

折衷方案如下：

| 特性 | DualPipe | DualPipeV | 1F1B | Zero Bubble |
|------|----------|-----------|------|-------------|
| 每设备参数副本数 | 2 | 1 | 1 | 1 |
| 气泡 vs 微批次 | 恒定 | 小幅增长 | 增长 | 增长 |
| 计算-通信重叠 | 完全 | 部分 | 极小 | 部分 |
| 适用场景 | EP 密集的 MoE | 密集或 EP 较轻的模型 | 基线 | 任何流水线 |

### 对 14.8T token 训练运行的意义

DeepSeek-V3 的预训练消耗了约 14.8T token，在 2,048 块 H800 GPU 上运行了约 280 万 GPU 小时。如果采用朴素的 1F1B，他们会在流水线气泡上损失 12-15%——即 34-42 万 GPU 小时，这足以训练一个完整的 70B 模型。DualPipe 挽回了其中的大部分。如果没有内部日志，很难直接量化这一贡献，但论文中声称整个训练过程中 GPU 利用率平均超过 95%。

对于较小的运行（1k GPU 以下），DualPipe 有些大材小用——流水线气泡相对总成本较小，密集模型训练很少遇到全对全瓶颈。对于多千 GPU 规模的前沿 MoE 训练，它实际上是必需的。

### 在技术栈中的位置

- 与 **FSDP**（阶段 10 · 05）互补。FSDP 跨 rank 分片模型参数；DualPipe 跨 rank 调度计算。它们可以结合使用。
- 与 **ZeRO-3** 梯度分片兼容。两份副本复制所需的簿记需要与 ZeRO 的分片梯度协作。
- 需要为特定集群拓扑调优的**自定义全对全内核**。DeepSeek 的开源内核是参考实现。

## 使用它

`code/main.py` 是一个流水线调度模拟器。它接受 `(P, n_micro_batches, schedule)` 参数，并输出 1F1B、Zero Bubble、DualPipe 和 DualPipeV 在稳定阶段的利用率。它是一个教学工具——数字与论文中的定性声明一致，并不代表生产环境中实测的加速比。

该模拟器的价值：使用不同的 P 和微批次数量运行它，观察 1F1B 的气泡比例如何增长，而 DualPipe 则不会。

实际训练运行中的集成注意事项：

- 选择能够被你的微批次数量整除的流水线并行深度。
- 确保你的专家并行网格支持双向全对全。DeepSeek 的内核是参考实现。
- 第一次预计要花一周时间调试调度逻辑本身。簿记工作相当繁琐。
- 监控每个 rank 的 GPU 利用率，而不仅仅是整体平均值。DualPipe 的优势来自于收紧落后者的空闲时间。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|-----------|---------|
| 流水线气泡（Pipeline bubble） | "每个 rank 的空闲时间" | GPU 周期被浪费，因为流水线阶段正在等待其输入或梯度 |
| 1F1B | "默认流水线调度" | 一次前向 / 一次反向交错的调度；DualPipe 超越的基线 |
| Zero Bubble | "Sea AI Lab 2023" | 将反向拆分为 B（输入梯度）和 W（权重梯度）；几乎完全填满流水线 |
| DualPipe | "DeepSeek-V3 调度" | 双向流水线 + 计算-通信重叠；气泡不随微批次数量增长 |
| DualPipeV | "Cut-in-half" | V 形改进，以略大的气泡为代价消除 2 倍参数复制 |
| 块（Chunk） | "流水线工作单元" | 一个微批次通过一个流水线阶段的一次前向或反向传递 |
| 全对全分发（All-to-all dispatch） | "将令牌发送给专家" | 将令牌路由到其指定 MoE 专家的跨节点通信 |
| 全对全合并（All-to-all combine） | "将专家输出带回" | MLP 之后收集专家输出的跨节点通信 |
| 专家并行（Expert Parallelism，EP） | "跨 GPU 的专家" | 将 MoE 专家分片到各 rank，使不同 GPU 持有不同专家 |
| 流水线并行（Pipeline Parallelism，PP） | "跨 GPU 的层" | 将模型层分片到各 rank；DualPipe 调度的维度 |
| 气泡比例（Bubble fraction） | "浪费的 GPU 时间" | (气泡时间 / 总时间)；DualPipe 推动趋近于零的比例 |
