# Jamba — 混合 SSM-Transformer

> 状态空间模型（SSM）和 Transformer 追求不同的目标。Transformer 通过二次成本的注意力机制换取质量。SSM 通过循环实现线性时间推理和恒定内存，但在质量上落后。AI21 的 Jamba（2024 年 3 月）和 Jamba 1.5（2024 年 8 月）将两者放入同一个模型：每 7 个 Mamba 层搭配 1 个 Transformer 层，每隔一个块使用 MoE，以及一个可以放入单块 80GB GPU 的 256k 上下文窗口。Mamba-3（ICLR 2026）通过复数值状态空间和 MIMO 投影加强了 SSM 一侧。本课程从头到尾通读这三种架构，并解释为什么当纯 SSM 和纯 Transformer 在长上下文方面的尝试未能成功时，这种混合方案却能经受住三年的规模扩展考验。

**类型：** 学习
**语言：** Python（标准库，层混合计算器）
**前置知识：** 阶段 10 · 14（开源模型架构），阶段 10 · 17（原生稀疏注意力）

## 学习目标

- 解释 Jamba 块中的三种原语——Transformer 层、Mamba 层、MoE——以及 1:7:偶数的交错方案。
- 从高层次描述 SSM 的循环结构长什么样，以及它为什么能实现恒定内存推理。
- 计算 Jamba 模型在 256k 上下文下的 KV 缓存占用，并与纯 Transformer 模型所需量进行比较。
- 说出 Mamba-3 的三项创新（指数梯形离散化、复数值状态更新、MIMO）以及每项创新针对的问题。

## 问题

注意力机制在序列长度上是二次的。状态空间模型是线性的。这种差异会累积：在 256k 个 token 下，Transformer 的注意力图每个头有 650 亿个条目；而 SSM 的循环状态无论序列长度如何都是固定大小的。

纯 SSM 模型（Mamba、Mamba-2）在小规模下与 Transformer 的困惑度相当，但在状态跟踪任务上落后，并且在某些类别的上下文内部检索上表现不佳。直觉：SSM 将历史压缩成一个固定状态，当历史很长时，信息会泄露。注意力机制能精确记住所有内容，但要付出二次成本。

显而易见的解决办法：两者都用。在需要精确回忆的地方放置 Transformer 层。在其他地方使用 SSM 层。调整比例。Jamba 是第一个大规模（520 亿总参数、120 亿活跃参数、256k 上下文、单块 80GB GPU）交付这种混合方案的生产级模型。Jamba 1.5 将家族扩展到 3980 亿总参数 / 940 亿活跃参数。Mamba-3（ICLR 2026）是当前最佳的纯 SSM 基线，可以围绕它重建混合模型。

本课程通读所有三篇论文，并建立"选择正确比例"的心智模型。

## 概念

### 一页纸理解 SSM

状态空间模型通过一个固定大小的状态 `h` 处理序列 `x_1, ..., x_N`：

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

每一步，状态通过线性动力学 `A` 演化，接收输入 `B x_t`，并输出 `C h_t`。`A, B, C` 是可学习的。注意关键特性：计算 `y_t` 只需要 `h_{t-1}` 和 `x_t`，而不需要任何更早的 `x`。内存是恒定的。推理是每个 token O(1) 的复杂度。

建模质量的关键在于 `A` 的结构。S4（Gu 2021）使用了高度结构化的矩阵，可以在训练期间作为长卷积高效计算。Mamba（Gu, Dao 2023）用依赖于数据的参数（"选择性"部分）替换了固定的 `A, B, C`。Mamba-2（2024）进一步简化了结构。Mamba-3（2026）在特定位置重新增加了复杂度。

关键特性：对于解码器 LLM 来说，SSM 层是注意力层的直接替代品，每层使用固定大小的状态而不是不断增长的 KV 缓存。

### Jamba 块

Jamba 块根据两个数字交错排列各层：

- `l`：注意力层与 Mamba 层的比例。Jamba 使用 `l = 8`，意味着每 7 个 Mamba 层搭配 1 个 Transformer 层（每组 8 层 = 7 个 Mamba + 1 个注意力层）。
- `e`：MoE 频率。Jamba 使用 `e = 2`，意味着每隔一层应用 MoE。

一个块内的层序列：

```
M  M  M  M  M  M  M  A    (7 个 Mamba + 1 个注意力层)
|  M  |  M  |  M  |  M    (| 标记应用了 MoE 的位置)
```

每个 Jamba 块有 8 层。在 4 个块深度（共 32 层）下，你会得到 28 个 Mamba 层和 4 个注意力层。其中 16 层使用了 MoE。

### 为什么是 1:7 的比例

AI21 进行了消融实验：注意力层与 Mamba 层的什么比例能在长上下文评估中给出最佳的性价比（perplexity-per-parameter）和上下文内部召回率？

- 注意力过多（1:1）：质量上升，但内存和速度下降。
- 注意力过少（1:15）：内存很好，但上下文内部检索失败。
- 最佳点：1:7 或 1:8。

直觉：Transformer 层负责精确回忆和状态跟踪。Mamba 层负责处理成本低廉的大部分计算。

### 位置编码

Mamba 层本身是感知位置的（通过循环结构）。在原始的基于 Mamba 的混合模型中，注意力层没有使用 RoPE——SSM 层提供了位置信息。Jamba 1.5 为注意力层添加了 RoPE 以实现更长的上下文泛化，这是基于经验性长上下文评估的事后优化。

### 内存预算

对于 Jamba-1 的配置（32 层：28 个 Mamba + 4 个注意力层，隐藏维度 4096，32 个注意力头）：

- KV 缓存（仅注意力层）：`2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB`（256k BF16 精度下）。只有 4 个注意力层有贡献。
- SSM 状态：每个 token 前缀为 `28 * hidden * state_size`，但这是每层固定大小的，不随序列长度扩展。典型的 Mamba 状态大小为每个特征 16，隐藏维度 4096：`28 * 4096 * 16 * 2 = 3.7 MB` 总计。

对比一下同配置的 32 层纯 Transformer（隐藏维度 4096，32 头的完整 MHA）：`2 * 32 * 32 * 128 * 256k * 2 = 128 GB`（256k BF16 精度下）。KV 缓存减少了 8 倍。即使与大多数 2024 模型使用的 GQA(8) 基线（`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`）相比，Jamba 的 1:7 混合模型在 16 GB 下仍然小 2 倍。

这就是 AI21 所说的"在单块 80GB GPU 上实现 256k 上下文"的含义。完整 MHA 纯 Transformer 的 KV 缓存无法放下；即使是 GQA 基线也没有给权重和激活值留下空间；而 Jamba 可以。

### Mamba-3：2026 年的纯 SSM 基线

Mamba-3（ICLR 2026，arXiv:2603.15569）在纯 SSM 方面引入了三项创新：

1. **指数梯形离散化。** 将 Mamba-2 中的欧拉方法离散化替换为更具表现力的循环。在核心循环中对状态-输入应用类似卷积的操作，而不是作为 `x_t` 上的外部卷积。

2. **复数值状态更新。** 先前的 Mamba 模型将状态矩阵从复数（S4）降级为实数对角矩阵（Mamba），再降级为缩放单位矩阵（Mamba-2）。Mamba-3 重新引入了复数值——相当于在状态上应用了依赖数据的旋转嵌入。这恢复了先前实数值简化所损失的状态跟踪能力。

3. **多输入多输出（MIMO）投影。** 不再使用每个特征的标量投影，而是使用矩阵值的投影。在不增加解码延迟的情况下，提高了建模能力和推理时的硬件利用率。

在 15 亿参数规模下，Mamba-3 的平均下游准确率比 Gated DeltaNet 提高了 0.6 个百分点；MIMO 变体额外增加了 1.2 个百分点，总计提升 1.8 个百分点。在相同的状态大小下，Mamba-3 以一半的状态大小就能匹配 Mamba-2 的性能。

Mamba-3 尚未在大规模生产级混合模型中使用——但它是下一代 Jamba 类模型中 SSM 侧最明显的候选者。

### 何时选择混合模型

混合模型胜出的场景：

- 上下文足够长，纯 Transformer 的 KV 缓存变得难以承受（64k 以上）。
- 任务混合了短程结构（适合 SSM）和长程召回（需要 Transformer）。
- 你希望在单 GPU 内存预算下部署，而纯 Transformer 的 KV 缓存单独就无法放下。

混合模型落败的场景：

- 上下文较短（低于 16k）。SSM 的开销是浪费的；纯 Transformer 就很好。
- 任务需要全局到全局的注意力（深度推理、多文档交叉引用）。混合模型中注意力层的稀疏性会带来损害。
- 你在扩展到万亿参数的前沿模型。纯 Transformer + MLA + MoE（DeepSeek-V3 风格）目前正在能力竞赛中胜出。

## 使用它

`code/main.py` 是一个混合架构的内存计算器。给定 SSM-Transformer 比例和隐藏维度/层数配置，它可以计算：

- 目标上下文下的 KV 缓存。
- SSM 状态内存。
- 在不同模型形状下、上下文长度为 N 时的总内存。

该计算器支持：

- 纯 Transformer 基线（KV 缓存随 N 增长）。
- Jamba 风格的 1:7 混合模型。
- 纯 SSM（完全没有 KV 缓存）。

数字直接来自 Jamba-1 和 Jamba-1.5 论文的已发布配置，以及针对假设变体的外推。

实际部署中的集成考虑：

- 大多数生产级推理服务器（vLLM、SGLang）支持 Jamba 和 Mamba。请查阅具体版本。
- 在 256k 上下文下，Jamba 的内存优势体现在并发请求吞吐量上。在相同的 VRAM 上，你可以容纳比 Transformer 序列更多的 Jamba 序列。
- Mamba-3 作为独立模型尚未在生产中发布——仅有 15 亿参数的研究预览版。

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| 状态空间模型（SSM） | "带固定状态的循环" | 具有学习到的循环 `h_t = A h_{t-1} + B x_t` 的层；每个 token 的内存恒定 |
| 选择性 SSM | "Mamba 的绝招" | 数据依赖的 A、B、C 参数，使模型在线性时间内具有类似门控的选择性 |
| 注意力层与 Mamba 层比例 | "有多少个注意力层" | 在 Jamba 中，`l = 8` 表示每 7 个 Mamba 层搭配 1 个注意力层 |
| Jamba 块 | "8 层组" | 一个注意力层 + 七个 Mamba 层 + 在交替位置上使用 MoE |
| SSM 状态 | "隐藏缓冲区" | 每层固定大小的状态，替代 Mamba 层的 KV 缓存 |
| 256k 上下文 | "Jamba 的标志性数字" | Jamba-1 能在单块 80GB GPU 上容纳的序列长度；纯 Transformer 在该规模下无法做到 |
| Mamba-3 | "2026 年的纯 SSM" | 当前最佳的纯 SSM 架构，具有复数状态 + MIMO；混合模型围绕它重建的基线 |
| MIMO | "多输入多输出" | Mamba-3 的创新，使用矩阵值投影替代每个特征的标量投影 |
| 指数梯形离散化 | "Mamba-3 的循环" | 更具表现力的循环，涵盖了 Mamba-2 的欧拉方法离散化 |
| 混合架构 | "混合注意力和 SSM" | 任何交错排列 Transformer 层和 SSM 层的模型；Jamba 是生产级的原型 |
