给定一个模型架构（hidden、heads、KV heads、layers、d_head）、目标上下文长度、幻觉或长上下文概况（在现有评估上的失败模式）以及训练预算（可用 token、GPU 小时），生成 DIFF V2 的集成计划。

输出：

1. 集成模式。从头预训练、训练中途架构替换或 Q 投影上的 LoRA 微调。根据训练预算和可用现有权重论证选择。
2. 架构差异。具体的逐字段更改清单：哪些投影增长、哪些保持不变、添加了多少参数、减法放在注意力块的何处。包括按层深度的 `lambda_init` 计划（`0.8 - 0.6 * exp(-0.3 * (depth - 1))` 是论文默认值；如果逐层遥测显示不稳定，按深度调整）。
3. 内核选择。鉴于 V2 头数翻倍，确认 FlashAttention 2 或 3 支持。除非用户明确需要可重现性，否则拒绝 V1 的自定义内核路径。
4. 内存预算。KV 缓存保持基线（KV 头不变）。计算每 token 激活内存增量（额外的 Q 头、额外计算）。在目标上下文下报告绝对数值。
5. 训练稳定性计划。描述要监控的内容：每层 `lambda` 漂移、每头注意力熵、Q 投影上的梯度方差。命名在遥测显示发散时应触发回滚到基线注意力的具体指标。

硬拒绝：
- 在未继续进行预训练的情况下向预训练模型添加 DIFF 注意力。输出分布会漂移——不是即插即用修复。
- 在 2026 年 4 月之后的任何新运行中使用 DIFF V1。V2 在所有测量维度上严格更好。
- 集成 DIFF 时未启用长上下文训练数据。其好处仅在 32k 以上显现。
- 在没有对照实验的情况下将 `lambda_init` 改为负值。负初始化值减去超过噪声水平后会使训练崩溃。

拒绝规则：
- 如果目标上下文低于 16k，拒绝集成并推荐标准注意力。添加参数的成本不能通过噪声下限论证来证明。
- 如果用户无法提供长上下文评估数据（RULER、needle-in-haystack、MultiNeedle），拒绝并要求先提供校准数据。
- 如果用户使用 pre-FlashAttention-2 栈，拒绝并推荐在尝试集成前升级栈。

输出：一页集成计划，列出模式、参数增量、KV 缓存影响、FlashAttention 确认、`lambda` 计划和 3 指标监控面板。以"成功标准"段落结尾，命名具体的长期上下文评估数值（RULER 64k 上的百分点差异或等效值），该数值将证明保留 DIFF V2 而非恢复到基线注意力。
