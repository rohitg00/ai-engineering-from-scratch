# Native Sparse Attention（原生稀疏注意力）—— DeepSeek NSA

> 在 64k 词元下，注意力操作占用了 70-80% 的解码延迟。每个开源模型实验室都有各自的优化方案。DeepSeek 的 NSA（ACL 2025 最佳论文）是最终被广泛采纳的方案：三个并行的注意力分支——压缩的粗粒度词元、选择性保留的细粒度词元，以及用于局部上下文的滑动窗口——通过一个可学习的门控机制组合在一起。它与硬件对齐（对内核友好）、原生可训练（在预训练中即可使用，而非在推理时额外接入），在 64k 解码上运行速度超过 FlashAttention，同时质量与全注意力匹配或更优。本课程将端到端地构建这三个分支，并展示为什么这种稀疏性是端到端可微的。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段 7 · 12（KV 缓存、闪存注意力），阶段 7 · 15（注意力变体），阶段 10 · 16（微分注意力）
**时长：** ~60 分钟

## 学习目标

- 阐述 NSA 的三个注意力分支以及每个分支捕捉的信息。
- 解释为什么 NSA 是"原生可训练的"，而先前的稀疏注意力方法仅适用于推理。
- 在 64k 上下文中，以压缩块大小和选择 top-k 为函数，计算 NSA 相对于全注意力的注意力计算节省量。
- 在短合成序列上使用标准库 Python 实现三分支组合，并验证门控权重的行为。

## 问题

在序列长度 N 下，全注意力每个层的计算开销为 `O(N²)` 时间，KV 缓存开销为 `O(N)` 内存。在 64k 词元时，计算量和内存带宽的数字是灾难性的。根据 NSA 论文的理论估算：在 64k 下，注意力占解码总延迟的 70-80%。所有下游指标——TTFT、词元/秒、每百万词元成本——都受注意力成本的支配。

稀疏注意力显然是答案。先前的尝试分为两类。固定模式稀疏性（滑动窗口、跨步、局部块）会丢弃信息，并且无法处理长距离召回任务。推理时稀疏性（KV 缓存修剪、H2O、StreamingLLM）应用于在密集注意力上预训练的模型，只能恢复潜在加速的一小部分，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力（Yuan 等人，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）两者兼顾：模型在预训练过程中学习的稀疏模式，以与内核对齐的算法实现，在推理时真正带来计算节省。两年后，NSA 或其直接后代将成为每个前沿长上下文模型的默认注意力机制。

## 概念

### 三个并行分支

对于每个查询，NSA 运行三次注意力，针对 KV 缓存的三种不同视图：

1. **压缩分支。** 词元被分组为大小为 `l` 的块（通常为 32 或 64）。每个块通过一个小型可学习 MLP 压缩为单个摘要词元。查询在这些压缩词元上进行注意力运算，获得整个序列的粗粒度视图。

2. **选择分支。** 利用压缩分支的注意力分数，识别出与当前查询最相关的前 k 个块。读取这些块中的细粒度（未压缩）词元，查询对所有选中的词元进行注意力运算。可以把压缩分支的注意力视为选择的路由信号。

3. **滑动窗口分支。** 查询对最近的 `W` 个词元（通常为 512 个）进行注意力运算，以获取局部上下文。该分支捕获其他两个分支可能遗漏的结构密集型短距离模式（句法、局部共指关系）。

三个分支的输出通过一个可学习的逐位置门控组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 来自一个基于查询的小型 MLP 的门控权重。它们不必相加为 1——可以独立地对各分支加权。

### 为什么这是"原生可训练的"

选择步骤（top-k 块）是离散的。离散操作会阻断梯度流动。先前的稀疏注意力工作要么跳过了通过选择的反向传播（限制了训练），要么使用了在推理时无法实现真正稀疏性的连续松弛方法。

NSA 绕开了这一点：压缩分支的注意力本身就是对整个序列的可微粗粒度注意力。top-k 操作只是复用压缩分支中最高注意力分数来选择要加载哪些细粒度块。梯度通过压缩分支的分数流动（这些分数既影响压缩输出，也影响选择逻辑），而所选块对最终输出的贡献也是可微的。不可微的 `top_k` 操作在前向计算图上是一个空操作——它仅控制从内存中加载哪些块。

这就是为什么 NSA 可以在端到端的预训练中使用。模型学会通过三个分支联合路由信息，产生一个在推理时真正提供所承诺加速的稀疏模式。

### 硬件对齐的内核

NSA 的内核专为现代 GPU 内存层次结构设计。内核按 GQA 组加载查询（外层循环），每组获取相应的稀疏 KV 块（内层循环），并在 SRAM 上运行注意力。由于每个查询组看到相同的所选块（选择基于每个查询组，而非每个查询头），KV 加载在组内被分摊。算术强度保持在高位。

论文报告称，在 64k 解码上，Triton 内核的运行速度比 FlashAttention 快 9 倍，且加速比随序列长度增长。前向和反向内核均已提供。

### 计算预算

设 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择数量，`w` 为滑动窗口大小，`b` 为所选块大小（通常等于 `l`）。

- 压缩分支：每个查询 `O(N/l)` 个键，总计 `O(N * N / l)`。
- 选择分支：每个查询 `O(k * b)` 个键，总计 `O(N * k * b)`。
- 滑动分支：每个查询 `O(w)` 个键，总计 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

当 `N = 64k, l = 64, k = 16, b = 64, w = 512` 时：每个查询的计算成本为 `1000 + 1024 + 512 = 2536` 个键。全注意力为 `64000` 个键。计算量减少 25 倍。

当 `N = 128k, l = 64, k = 16, b = 64, w = 512` 时：每个查询的计算成本为 `2000 + 1024 + 512 = 3536` 个键。全注意力为 `128000` 个键。计算量减少 36 倍。收益随序列长度增长——这正是关键所在。

### 对比

| 方法 | 可微 | 真正的推理加速 | 长距离召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 跨步 / 块稀疏 | 是 | 是 | 部分 |
| KV 修剪（H2O, StreamingLLM） | 不适用（推理时） | 是 | 部分 |
| MoBA（Moonshot） | 部分 | 是 | 良好 |
| NSA | 是（原生） | 是（64k 下 9x） | 匹配全注意力 |

MoBA（Moonshot, arXiv:2502.13189）同期发表，采用了类似的"三个优于一个"的方法，将 MoE 原则应用于注意力块。NSA 和 MoBA 是 2026 年长上下文预训练中需要了解的两个架构。

## 构建

`code/main.py` 在短合成序列上实现了三个分支，并展示了：

- 压缩 MLP（为教学清晰起见，使用简单的均值池化基线；实际 NSA 使用可学习的 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 对最后 `w` 个词元的滑动窗口注意力。
- 门控组合。
- 与全注意力对比的计算量统计。

### 步骤 1：将词元压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤 2：压缩分支注意力

对查询与压缩后的键运行 softmax 注意力。压缩分支的分数同时充当 top-k 选择的信号。

### 步骤 3：top-k 块选择

选取分数最高的 `k` 个压缩块的索引。加载这些块中的原始未压缩词元并对它们运行注意力。

### 步骤 4：滑动窗口注意力

取最后 `w` 个词元并对它们运行标准注意力。

### 步骤 5：门控与组合

一个基于查询的小型 MLP 生成三个门控权重。最终输出是三个分支输出的加权和。

### 步骤 6：计算计数

打印每个查询在每个分支中参与的键数量及总数。与 `N`（全注意力）进行比较。在 1024 词元合成序列上，`l = 32, k = 4, w = 128` 时，NSA 每个查询的键数为 `32 + 128 + 128 = 288`，而全注意力为 1024——减少 3.5 倍。

## 使用

NSA 正在 DeepSeek 自己的长上下文预训练流程中使用。截至 2026 年 4 月在公共推理栈中的集成状态：

- **DeepSeek 内部**：原生支持，已发布的权重使用 NSA 或其后续 DSA（DeepSeek 稀疏注意力）。
- **vLLM**：针对 DeepSeek-V3.x 权重的实验性 NSA 支持正在开发中。
- **SGLang**：NSA 基准测试已发布；生产路径跟随 vLLM。
- **llama.cpp / CPU**：不支持；CPU 吞吐量下内核分解的开销不值得。

何时使用 NSA：

- 针对 64k 以上上下文进行预训练或持续训练，且有较大的计算预算。
- 推理 DeepSeek 自己的长上下文检查点。这些权重是 NSA 原生的。

何时不使用：

- 服务于现有的密集注意力预训练模型。没有持续训练就无法改造 NSA。
- 上下文长度低于 16k。三分支的开销超过了节省。
- 批量大小为 1 的交互式聊天。延迟敏感的解码可以受益，但仅限长上下文。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------------|------------------------|
| 压缩分支 | "粗粒度视图" | 对块平均键的注意力，以每个查询 O(N/l) 个键提供全局上下文 |
| 选择分支 | "Top-k 块" | 对压缩分支分数最高的 `k` 个块的细粒度注意力 |
| 滑动窗口 | "局部上下文" | 对最后 `W` 个词元的注意力，用于短距离模式 |
| 原生可训练性 | "预训练时开启稀疏性" | 稀疏模式在预训练过程中学习，而非推理时额外接入 |
| 压缩块大小 l | "粗粒度视图的组大小" | 多少个词元合并为一个摘要；通常为 32-64 |
| Top-k | "保留的块数" | 其未压缩词元被读取的压缩块数量；通常为 16 |
| 滑动窗口 W | "局部注意力半径" | 通常为 512；过短损害局部连贯性，过长浪费计算 |
| 分支门控 | "如何混合三个分支" | 逐位置 MLP 输出，对三个分支的贡献进行加权 |
| 硬件对齐 | "对内核友好的稀疏性" | 选择的稀疏模式使实际 GPU 内核达到理论加速 |
| DSA | "NSA 的继任者" | DeepSeek 稀疏注意力，DeepSeek 系列中跟随 NSA 的架构 |
