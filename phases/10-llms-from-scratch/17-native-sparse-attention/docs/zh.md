# 原生稀疏注意力（DeepSeek NSA）

> 在 64k 詞元的長度上，注意力吃掉 70-80% 的解碼延遲。每一家開放模型實驗室都有一套修法。DeepSeek 的 NSA（ACL 2025 最佳論文）是留下來的那一個：三條並行的注意力分支 —— 壓縮後的粗粒度詞元、選擇性保留的細粒度詞元，以及負責局部脈絡的滑動視窗 —— 再用一個學習出來的閘門把三者合起來。它是硬體對齊的（對核心友善）、原生可訓練的（能用在預訓練，而不是推論時外掛上去），而且在 64k 的解碼上比 FlashAttention 更快，品質則追平甚至勝過完整注意力。這一課會把三條分支從頭到尾建起來，並說明為什麼這種稀疏性是端到端可微分的。

**類型：** 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 7 · 12（KV 快取、flash-attention）、階段 7 · 15（注意力的變體）、階段 10 · 16（差分注意力）
**時間：** 約 60 分鐘

## 學習目標

- 說出 NSA 的三條注意力分支，以及每一條各自抓到什麼。
- 解釋為什麼 NSA 是「原生可訓練」的，而先前的稀疏注意力方法只能用在推論階段。
- 以壓縮區塊大小與選擇 top-k 為變數，算出 64k 脈絡下 NSA 相對完整注意力省下的運算量。
- 用 stdlib Python 在一段短的合成序列上實作三分支的組合，並驗證閘門權重的行為是否合理。

## 問題所在

序列長度為 N 的完整注意力要付 `O(N^2)` 時間，每層 `O(N)` 的 KV 快取。到了 64k 詞元，運算量與記憶體頻寬的數字都是災難級的。NSA 論文給出的理論估計實測值：在 64k 時，注意力佔了總解碼延遲的 70-80%。下游的一切 —— TTFT、每秒詞元數、每百萬詞元的成本 —— 全都被注意力成本主導。

稀疏注意力是顯而易見的答案。先前的嘗試分成兩類。固定模式的稀疏性（滑動視窗、跨步、區塊局部）會丟掉資訊，在長距離召回任務上失敗。推論期的稀疏性（KV 快取剪枝、H2O、StreamingLLM）是套在一個以密集注意力預訓練出來的模型上，只能拿回潛在加速的一小部分，因為這個模型從來沒被要求把資訊繞過那個稀疏模式來傳遞。

原生稀疏注意力（Yuan et al.，DeepSeek + PKU + UW，ACL 2025 最佳論文，arXiv:2502.11089）兩件事都做了：一個模型在預訓練期間就學會的稀疏模式，並以核心對齊的演算法實作，讓省下的運算量在推論時真的兌現。兩年之後，每一個前沿的長脈絡模型上，預設的注意力都會是 NSA 或它的直系後代。

## 核心概念

### 三條並行分支

對每個 query，NSA 會跑三次注意力，對上 KV 快取的三種不同視角：

1. **壓縮分支。** 詞元以大小 `l`（通常是 32 或 64）分組成區塊。每個區塊透過一個小型的學習式 MLP 壓成單一個摘要詞元。query 在這些壓縮詞元上做注意力，取得整段序列的粗粒度視角。

2. **選擇分支。** 用壓縮分支得到的注意力分數，找出與當前 query 最相關的 top-k 個區塊。從那些區塊讀出細粒度（未壓縮）的詞元，query 在它們全部之上做注意力。可以把壓縮分支的注意力想成選擇用的路由訊號。

3. **滑動分支。** query 注意最近的 `W` 個詞元（通常是 512），取得局部脈絡。這條分支抓的是另外兩條可能漏掉、結構性很重的短距離模式（語法、局部指代）。

三條分支的輸出透過一個學習出來的逐位置閘門合併：

```math
\text{out} = g_{\text{cmp}} \cdot \text{out}_{\text{cmp}} + g_{\text{sel}} \cdot \text{out}_{\text{sel}} + g_{\text{win}} \cdot \text{out}_{\text{win}}
```

`g_cmp, g_sel, g_win` 是由一個作用在 query 上的小型 MLP 產生的閘門權重。它們不必加總為 1 —— 可以各自獨立地為分支加權。

### 為什麼這叫「原生可訓練」

選擇這一步（top-k 區塊）是離散的。離散運算會截斷梯度流。先前的稀疏注意力工作，要嘛跳過選擇這一步的反向傳播（因而限制了訓練），要嘛用連續鬆弛，但那在推論時給不出真正的稀疏性。

NSA 繞過了這件事：壓縮分支的注意力**本身**就是一個對整段序列做的、可微分的粗粒度注意力。top-k 這個運算只是重用壓縮分支排在最前面的注意力分數，來挑出要載入哪些細粒度區塊。梯度會流過壓縮分支的分數（這些分數同時影響壓縮輸出**與**選擇邏輯），而被選中的區塊對最終輸出的貢獻也是可微分的。不可微分的 `top_k` 運算在前向計算圖上是個 no-op —— 它只決定哪些區塊會從記憶體被載入。

這就是 NSA 能端到端用在預訓練的原因。模型學會把資訊聯合地繞過這三條分支傳遞，產生出來的稀疏模式，在推論時真的能兌現承諾的加速。

### 硬體對齊的核心

NSA 的核心是針對現代 GPU 的記憶體階層設計的。核心以 GQA 群組為單位載入 query（外層迴圈），再依群組取出對應的稀疏 KV 區塊（內層迴圈），並在 SRAM 上跑注意力。因為同一個 query 群組看到的是同一批被選中的區塊（選擇是以 query 群組為單位，不是以每個 query 頭為單位），KV 的載入成本能攤在整個群組上。算術強度因此維持在高檔。

論文回報的數字：Triton 核心在 64k 解碼上比 FlashAttention 快 9 倍，而且加速比會隨序列長度成長。前向與反向核心都有提供。

### 運算預算

令 `N` 為序列長度，`l` 為壓縮區塊大小，`k` 為 top-k 的選擇數量，`w` 為滑動視窗，`b` 為被選區塊的大小（通常等於 `l`）。

- 壓縮分支：每個 query `O(N/l)` 個 key，總共 `O(N * N / l)`。
- 選擇分支：每個 query `O(k * b)` 個 key，總共 `O(N * k * b)`。
- 滑動分支：每個 query `O(w)` 個 key，總共 `O(N * w)`。

總計：`O(N * (N/l + k*b + w))`。

在 `N = 64k, l = 64, k = 16, b = 64, w = 512` 時：每個 query 的成本是 `1000 + 1024 + 512 = 2536 keys`。完整注意力是 `64000 keys`。運算量縮減 25 倍。

在 `N = 128k, l = 64, k = 16, b = 64, w = 512` 時：每個 query 的成本是 `2000 + 1024 + 512 = 3536 keys`。完整注意力是 `128000 keys`。縮減 36 倍。好處會隨序列長度成長，而這正是重點所在。

### 各方法比較

| 方法 | 可微分 | 推論真有加速 | 長距離召回 |
|--------|---------------|----------------------|-------------------|
| 只有滑動視窗 | 是 | 是 | 失敗 |
| 跨步／區塊稀疏 | 是 | 是 | 部分 |
| KV 剪枝（H2O、StreamingLLM） | 不適用（推論期） | 是 | 部分 |
| MoBA（Moonshot） | 部分 | 是 | 良好 |
| NSA | 是（原生） | 是（64k 時 9 倍） | 追平完整注意力 |

MoBA（Moonshot，arXiv:2502.13189）是同期發表的工作，走的是類似的「三個比一個好」路線，把 MoE 的原則套用到注意力區塊上。NSA 與 MoBA 是 2026 年長脈絡預訓練必須認識的兩套架構。

## 動手實作

`code/main.py` 在一段短的合成序列上實作三條分支，並展示：

- 壓縮用的 MLP（為了教學清晰，這裡用一個簡單的平均池化基準線；真正的 NSA 用的是學習式 MLP）。
- 由壓縮分支分數驅動的 top-k 區塊選擇。
- 在最後 `w` 個詞元上的滑動視窗注意力。
- 閘門式的合併。
- 一份與完整注意力對比的運算量列印。

### 步驟 1：把詞元壓成區塊

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步驟 2：壓縮分支注意力

把 query 對上壓縮後的 key 跑 softmax 注意力。壓縮分支的分數同時兼任 top-k 選擇的訊號。

### 步驟 3：top-k 區塊選擇

挑出分數最高的 `k` 個壓縮區塊的索引。從那些區塊載入原始的未壓縮詞元，並在它們之上跑注意力。

### 步驟 4：滑動視窗注意力

取最後 `w` 個詞元，對它們跑標準注意力。

### 步驟 5：閘門 + 合併

一個作用在 query 上的小型 MLP 產生三個閘門權重。最終輸出是三條分支輸出的加權和。

### 步驟 6：運算量計數

印出每條分支每個 query 所注意的 key 數量以及總數。與 `N`（完整注意力）比較。在一段 1024 詞元的合成序列上、`l = 32, k = 4, w = 128` 的設定下，NSA 每個 query 看到 `32 + 128 + 128 = 288` 個 key，完整注意力則是 1024 —— 少了 3.5 倍。

## 框架應用

NSA 已經上線在 DeepSeek 自家的長脈絡預訓練管線裡。截至 2026 年 4 月，公開推論堆疊的整合狀態：

- **DeepSeek 內部**：原生支援，已發佈的權重使用 NSA 或其後繼者 DSA（Deepseek Sparse Attention）。
- **vLLM**：針對 DeepSeek-V3.x 權重的實驗性 NSA 支援開發中。
- **SGLang**：已發佈 NSA 基準測試；生產路線跟隨 vLLM。
- **llama.cpp／CPU**：不支援；以 CPU 的吞吐量而言，核心拆解的額外開銷划不來。

什麼時候該用 NSA：

- 目標為 64k 以上脈絡、且有像樣運算預算的預訓練或持續訓練。
- 推論 DeepSeek 自家的長脈絡檢查點。那些權重本來就是 NSA 原生的。

什麼時候不該用：

- 要服務一個既有的密集注意力預訓練模型。沒有持續訓練，你沒辦法把 NSA 改裝上去。
- 脈絡在 16k 以下。三分支的額外開銷會蓋過省下來的量。
- batch-1 的互動式聊天。對延遲敏感的解碼確實有好處，但只在長脈絡下才成立。

## 練習

1. 在一段 1024 詞元的合成序列上執行 `code/main.py`。掃過三組 `(l, k, w)` 預設值並印出運算量。找出在大海撈針測試上相對完整注意力仍保有 95% 召回率的前提下，每個 query 的 key 數量最低的那組預設值。

2. 把平均池化的壓縮器換成一個小型的學習式 MLP（2 層，隱藏維度 32）。在一個訊號是區塊平均值的合成任務上訓練它。在留出資料上量測它與平均池化基準線之間的困惑度差距。

3. 實作閘門 MLP。它以 query 為輸入，輸出三個純量。證明閘門的行為是合理的：對隨機 query 給出接近均勻的權重，當 query 命中很久以前的區塊時，則把重量壓在選擇分支上。

4. 算出一個啟用 NSA 的 70B 模型在 128k 脈絡下的 KV 快取記憶體預算。KV 頭為 8，頭維度 128，BF16。與完整注意力以及 MLA 比較（階段 10 · 14 給過 MLA 的數字）。找出 NSA 的細粒度分支 KV 快取等於完整注意力的那個序列長度。

5. 讀 NSA 論文（arXiv:2502.11089）的第 4 節，用三句話解釋為什麼 top-k 選擇是重用壓縮分支的注意力分數，而不是另外算一個路由分數。把答案扣回梯度流。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際上是什麼 |
|------|----------------|------------------------|
| 壓縮分支 | 「粗粒度視角」 | 在區塊平均後的 key 上做的注意力，用每個 query O(N/l) 個 key 提供全域脈絡 |
| 選擇分支 | 「top-k 區塊」 | 在壓縮分支分數最高的 `k` 個區塊上做的細粒度注意力 |
| 滑動視窗 | 「局部脈絡」 | 在最後 `W` 個詞元上做的注意力，抓短距離模式 |
| 原生可訓練性 | 「開著稀疏性做預訓練」 | 稀疏模式是在預訓練期間學出來的，不是推論時外掛上去的 |
| 壓縮區塊大小 l | 「粗粒度視角的群組大小」 | 多少個詞元會被併成一個摘要；典型值 32-64 |
| Top-k | 「要保留的區塊」 | 有多少個壓縮區塊的未壓縮詞元會被讀進來；典型值 16 |
| 滑動視窗 W | 「局部注意力半徑」 | 典型值 512；太短傷局部連貫性，太長浪費運算 |
| 分支閘門 | 「三條怎麼混」 | 逐位置的 MLP 輸出，為三條分支的貢獻加權 |
| 硬體對齊 | 「對核心友善的稀疏性」 | 稀疏模式的選法，要讓實際的 GPU 核心真的拿到理論上的加速 |
| DSA | 「NSA 的後繼者」 | Deepseek Sparse Attention，DeepSeek 這條脈絡裡接在 NSA 之後的架構 |
