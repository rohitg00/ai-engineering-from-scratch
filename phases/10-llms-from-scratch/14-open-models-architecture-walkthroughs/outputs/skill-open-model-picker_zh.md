给定一个部署目标（GPU 类型、每 GPU VRAM、GPU 数量、目标上下文长度、目标 p50/p99 延迟、峰值并发请求数）和任务概况（聊天、代码、推理、长上下文检索、工具使用），推荐一个开放模型加服务栈，对第 14 课的六个架构旋钮各给出明确推理。

输出：

1. 候选模型短名单。三个候选，各包含总参数、激活参数（MoE 感知）、架构标志（归一化/激活/位置/注意力/MoE/上下文），以及入选短名单的单一理由。
2. 内存预算检查。对最佳候选：BF16 和所选量化下的权重内存；目标上下文和目标批处理大小下的 KV 缓存；激活余量。如果权重 + KV 缓存 + 激活值超过可用 VRAM，停止推荐。
3. 量化选择。GPTQ-4bit、AWQ-4bit、FP8 或 BF16。根据任务对精度敏感度（代码/数学/推理任务比聊天或检索受激进量化影响更大）进行论证。
4. 推理栈。vLLM、TensorRT-LLM、SGLang 或 llama.cpp。根据连续批处理需求、投机解码支持、量化格式兼容性以及单节点 vs 多节点拓扑进行论证。
5. 吞吐量合理性检查。基于 GPU 内存带宽（解码）和 TFLOPS（预填充）估算预填充 tokens/秒和解码 tokens/秒。如果解码吞吐量低于目标的并发用户底线，拒绝该推荐。
6. 备选方案。如果最佳候选超出 VRAM 或吞吐量预算的第二选择。始终给出一个。

硬拒绝：
- 在单 24GB 消费级 GPU 上没有卸载或激进量化的 30B 以上密集模型。
- 在没有专家并行支持的服务栈上的 MoE 模型。
- 在没有 GQA 或 MLA 的架构上的长上下文（128K+）（KV 缓存爆炸）。
- 任何未命名特定模型版本的推荐（例如"Llama 3 8B Instruct v3.1"，而非"Llama 3"）。

输出：一页推荐，列出模型、量化、栈，每个决策附有编号证据。以"如果...值得重新考虑"段落结尾，命名会翻转选择的具体能力或部署参数。
