# 指令遵循作为对齐信号

> 后续对 RLHF 的每一次批评，都是针对这条流水线的。在你学习优化压力如何扭曲代理指标之前，你必须先看清这个代理指标是什么。InstructGPT（Ouyang et al., 2022）定义了参考架构：在指令-响应对上进行监督式微调，基于成对偏好排序训练奖励模型，以及在奖励模型上运行 PPO 并加上对 SFT 策略的 KL 惩罚。一个 1.3B 的 InstructGPT 优于 175B 的 GPT-3。仅此一个结果就解释了为什么到了 2026 年，每一个前沿实验室仍然在使用 RLHF 形态的后训练流水线。

**类型：** 学习
**语言：** Python（标准库，玩具级三阶段流水线）
**前置条件：** 阶段 10 · 06（SFT），阶段 10 · 07（RLHF），阶段 10 · 08（DPO）
**时间：** 约 45 分钟

## 学习目标

- 说出 InstructGPT 流水线的三个阶段以及每个阶段使用的损失函数。
- 解释为什么一个 1.3B 的指令微调模型能在人类偏好评估上击败原始的 175B GPT-3。
- 说明第三阶段中 KL 惩罚防范的是什么，以及为什么移除它会导致模式寻求行为。
- 描述对齐税（alignment tax）以及 Ouyang 等人用于缓解该问题的 PPO-ptx 方法。

## 问题

预训练语言模型完成文本。它们不回答问题。让 GPT-3 "写一个反转列表的 Python 函数"，你得到的往往是一个新的提示，因为训练数据的大部分是网络文本，而网络文本的延续仍然是网络文本。模型正在完成它的任务——但这个任务本身是错误的。

每个严肃实验室用来修复这个问题的代理指标是人类偏好。两个生成结果交给标注员；标注员选出更好的那个；奖励模型学习标注员的偏好。然后一个 RL 循环将策略推向奖励模型评分高的输出。这就是 InstructGPT 全文的精髓，三句话说完。论文的其余部分都是工程实现。

## 概念

### 第一阶段：监督式微调（SFT）

收集提示-响应对，其中响应是善意人类会写出的内容。Ouyang 等人使用了来自标注员和 OpenAI API 的 13000 条提示。使用标准交叉熵损失在数据上对基础模型进行微调。

SFT 给你的：模型现在回答问题，而不是延续问题。SFT 没有给你的：当多个答案都合理时，关于标注员偏好哪个答案的任何信号。

### 第二阶段：奖励模型（RM）

对于每个提示，从 SFT 模型中采样 K 个生成结果。标注员对它们进行排序。训练一个奖励模型，对任意提示-响应对进行评分，使得对于 `y_w` 优于 `y_l` 的配对：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这就是 Bradley-Terry 成对偏好损失。RM 通常从 SFT 模型初始化，并将语言模型头替换为标量头。

奖励模型很小：对于 175B 的 InstructGPT，6B 的模型就足够了。它们也很脆弱——论文第 5 节主要讨论的是在小规模下出现的奖励破解行为。

### 第三阶段：带 KL 惩罚的 PPO

定义目标函数：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

使用 PPO 进行最大化。KL 项防止 `pi` 偏离 SFT 策略太远。没有它，优化器会找到对抗样本——那些在 RM 下得分很高的字符串，不是因为 RM 没见过它们，而是因为人类实际上并不偏好它们。

KL 系数 `beta` 是 RLHF 中最重要的超参数。太低：奖励破解。太高：相比 SFT 没有改进。

### 对齐税

RLHF 之后，模型获得人类偏好，但在标准基准（SQuAD、HellaSwag、DROP）上出现退步。Ouyang 等人将此称为对齐税，并使用 PPO-ptx 来修复：将预训练梯度混合到 RL 目标中，使模型不会忘记那些从未得到奖励的下游任务。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 成为了标准。Anthropic、DeepMind 和 Meta 都使用了某种变体。

### 结果

一个 1.3B 的 InstructGPT（SFT + RM + PPO-ptx）在大约 70% 的情况下被标注员认为优于 175B 的基础 GPT-3。在生产流量的隐藏测试提示上，这个差距还会扩大。从这个数字可以读出两点：

1. 对齐是与能力不同的一个维度。175B 模型能力更强；1.3B 模型对齐程度更高；标注员更喜欢对齐的那个。
2. 能力下限由基础模型决定。你不能通过 RLHF 让基础模型知道它从未见过的事实。

### 为什么这是阶段 18 的参考点

后续课程中的每一次批评——奖励破解（第 2 课）、DPO（第 3 课）、谄媚行为（第 4 课）、CAI（第 5 课）、休眠智能体（第 7 课）、对齐造假（第 9 课）——都是针对这条流水线的某个部分。奖励破解攻击第二阶段。DPO 合并了第二和第三阶段。CAI 替换了人类标注员。谄媚行为表明标注员是一个有偏的信号。对齐造假表明策略可以完全绕过第三阶段。不理解这条流水线，你就无法跟上这些批评中的任何一个。

## 动手实践

`code/main.py` 在玩具偏好数据上模拟了三个阶段。基础的"策略"是一个对动作 {A, B, C} 有偏的硬币。第一阶段 SFT 在 200 条提示上模仿标注员的行为。第二阶段基于 500 组成对排序拟合一个 Bradley-Terry 奖励模型。第三阶段运行一个简化的 PPO 更新，并加上对 SFT 策略的 KL 惩罚。你可以观察奖励上升、KL 散度增长以及策略漂移——你还可以关闭 KL 项，看看奖励破解在 50 步更新内出现。

观察要点：

- `beta = 0.1` 与 `beta = 0.0` 下的奖励轨迹。
- 训练过程中 KL(pi || pi_SFT) 的变化。
- 最终动作分布与标注员偏好的对比。

## 输出产物

本课程产出了 `outputs/skill-instructgpt-explainer.md`。给定一个 RLHF 流水线描述或一篇论文摘要，它能识别出三个阶段中哪一个被修改了，每个阶段使用了什么损失函数，以及是否使用了 KL 惩罚或等效的正则化器。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| SFT | "指令微调" | 第一阶段：在提示-响应对上进行交叉熵微调 |
| 奖励模型 | "RM" | 在（提示，响应）上的标量回归器，使用 Bradley-Terry 在成对标签上训练 |
| Bradley-Terry | "成对偏好损失" | -log sigmoid(r_w - r_l)；将成对排序简化为二分类 |
| KL 惩罚 | "正则化器" | `beta * KL(pi \|\| pi_SFT)`——将 RL 策略约束在 SFT 锚点附近 |
| PPO-ptx | "带预训练混合的 PPO" | 在 PPO 目标中加入一部分预训练对数似然，以抵消对齐税 |
| 对齐税 | "RLHF 导致的退步" | RLHF 后模型在标准基准上的下降，这些基准并非 RLHF 的目标 |
| 标注员偏好 | "地面真相" | 人类排名的一个样本；RM 是它的统计代理，而非"人类价值观"的代理 |
