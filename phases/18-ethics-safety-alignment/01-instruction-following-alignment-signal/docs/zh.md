# 把指令遵循當成對齊訊號

> 後面每一項對 RLHF 的批評，反對的都是這條管線。在你研究最佳化壓力如何扭曲一個代理指標之前，你得先看見那個代理指標。InstructGPT（Ouyang 等人，2022）定義了那套參考架構：在指令－回應配對上做監督式微調、用成對偏好排序訓練一個獎勵模型，然後拿 PPO 對著獎勵模型跑、並對 SFT 策略加上 KL 懲罰。一個 1.3B 的 InstructGPT 贏過了 175B 的 GPT-3。就是那一個結果，讓 2026 年每一家前沿實驗室至今仍在出貨 RLHF 形狀的訓練後管線。

**類型：** 學習
**程式語言：** Python (stdlib, toy three-stage pipeline)
**先修單元：** 階段 10 · 06（SFT）、階段 10 · 07（RLHF）、階段 10 · 08（DPO）
**時間：** 約 45 分鐘

## 學習目標

- 說出 InstructGPT 管線的三個階段，以及每一階段用的損失函式。
- 解釋為何一個 1.3B 的指令微調模型，在人類偏好評估上贏過了原始的 175B GPT-3。
- 說明第三階段的 KL 懲罰在防的是什麼，以及把它拿掉為何會塌成尋峰行為。
- 描述對齊稅，以及 Ouyang 等人用來對付它的 PPO-ptx 緩解手法。

## 問題所在

預訓練語言模型會補完文字。它們不回答問題。你問 GPT-3「寫一個把清單反轉的 Python 函式」，常常拿回來的是另一段提示詞，因為訓練分布裡多半是網頁文字，而網頁文字接下去就是更多網頁文字。模型在做它的工作 —— 是那份工作定義錯了。

每家認真的實驗室拿來修這件事的代理指標，是人類偏好。兩份補完送給評分者；評分者挑出比較好的那個；一個獎勵模型學會那位評分者。然後一個 RL 迴路把策略推向獎勵模型給高分的輸出。這三句話就是 InstructGPT 的完整論點。論文其餘部分都是工程。

## 核心概念

### 第一階段：監督式微調（SFT）

蒐集提示詞－回應配對，其中的回應是一個懷著善意的人類會寫出來的東西。Ouyang 等人用了來自標註員與 OpenAI API 的 13k 個提示詞。用標準的交叉熵損失在這份資料上微調基礎模型。

SFT 給你的：模型現在會回答問題，而不是把問題續寫下去。它沒給你的：當多個答案都說得通時，關於評分者偏好哪一個的任何訊號。

### 第二階段：獎勵模型（RM）

對每個提示詞，從 SFT 模型抽 K 份補完。標註員替它們排序。訓練一個獎勵模型，替任何提示詞－回應配對打分，使得在 `y_w` 優於 `y_l` 的配對上：

```math
L_{\text{RM}} = -\log \sigma\big(r(x, y_w) - r(x, y_l)\big)
```

這就是 Bradley-Terry 成對偏好損失。RM 通常從 SFT 模型初始化，把語言模型頭換成一個純量頭。

獎勵模型很小：對 175B 的 InstructGPT 來說，6B 就夠了。它們也很脆弱 —— 論文第 5 節幾乎都在講小規模下就冒出來的獎勵駭取行為。

### 第三階段：帶 KL 懲罰的 PPO

定義目標函式：

```math
J(\pi) = \mathbb{E}_{x \sim D,\, y \sim \pi(\cdot \mid x)} \big[ r(x, y) \big] - \beta \, \mathrm{KL}\big(\pi(\cdot \mid x) \,\|\, \pi_{\text{SFT}}(\cdot \mid x)\big)
```

用 PPO 最大化它。那個 KL 項讓 `pi` 不會離 SFT 策略太遠。少了它，最佳化器會找到對抗樣本 —— 那些在 RM 之下拿高分的字串，之所以拿高分是因為 RM 沒看過它們，不是因為人類真的偏好它們。

那個 KL 係數 `beta` 是 RLHF 裡最重要的單一超參數。太低：獎勵駭取。太高：相對 SFT 毫無改善。

### 對齊稅

RLHF 之後，模型較受人類偏好，但在標準基準（SQuAD、HellaSwag、DROP）上退步了。Ouyang 等人把這叫做對齊稅，並用 PPO-ptx 修它：把預訓練的梯度混進 RL 目標函式，讓模型不會忘掉那些它從未被獎勵過的下游任務。

```math
J_{\text{ptx}}(\pi) = J(\pi) + \gamma \, \mathbb{E}_{x \sim D_{\text{pretrain}}} \big[ \log \pi(x) \big]
```

PPO-ptx 後來成了標準。Anthropic、DeepMind 與 Meta 都用了某種變體。

### 那個結果

一個 1.3B 的 InstructGPT（SFT + RM + PPO-ptx），在大約 70% 的情況下被標註員偏好於 175B 的基礎 GPT-3。在來自生產流量的隱藏測試提示詞上，差距還會拉大。從這個數字可以讀出兩件事：

1. 對齊跟能力是不同的軸。175B 那個模型能力更強；1.3B 那個對齊得更好；標註員偏好對齊得比較好的那個。
2. 能力的地板是由基礎模型決定的。你沒辦法靠 RLHF 讓一個基礎模型知道它從沒看過的事實。

### 為什麼這是階段 18 的參考點

後面課程裡的每一項批評 —— 獎勵駭取（第 2 課）、DPO（第 3 課）、諂媚（第 4 課）、CAI（第 5 課）、臥底代理（第 7 課）、對齊偽裝（第 9 課）—— 反對的都是這條管線的某個部分。獎勵駭取攻擊第二階段。DPO 把第二和第三階段壓成一個。CAI 換掉人類標註員。諂媚顯示標註員是個帶偏差的訊號。對齊偽裝顯示策略可以整個繞過第三階段。腦子裡沒有先裝著這條管線，你一項批評都跟不上。

## 框架應用

`code/main.py` 在玩具型偏好資料上模擬那三個階段。基礎「策略」是一枚在動作 {A, B, C} 上有偏的硬幣。第一階段 SFT 在 200 個提示詞上模仿標註員的動作。第二階段從 500 組成對排序擬合出一個 Bradley-Terry 獎勵模型。第三階段跑一次簡化的 PPO 更新，並對 SFT 策略加上 KL 懲罰。你可以看著獎勵爬升、KL 散度變大、策略漂移 —— 也可以把 KL 項關掉，看獎勵駭取在 50 個更新步驟之內冒出來。

要看什麼：

- `beta = 0.1` 對比 `beta = 0.0` 的獎勵軌跡。
- KL(pi || pi_SFT) 隨訓練步數的變化。
- 最終的動作分布與標註員偏好的比較。

## 練習

1. 跑 `code/main.py`。設 `beta = 0.0`，回報 200 個 PPO 步驟後的動作分布。用一段話解釋那個尋峰行為。

2. 把獎勵模型改成對動作 B 有 +0.5 的偏差（模擬一個獎勵臭蟲）。用 `beta = 0.1` 跑 PPO。那個 KL 懲罰阻止得了策略去利用這個偏差嗎？`beta` 到多少的時候，利用行為會變得看得見？

3. 讀 Ouyang 等人（arXiv:2203.02155）的圖 1。跑 1、5、20、100 步的 PPO 並對 SFT 模型量測偏好，重現那條標註員偏好曲線。

4. 論文的 4.3 節回報 1.3B 的 InstructGPT 在大約 70% 的情況下打敗 175B 的 GPT-3。為什麼這個比率在隱藏的生產提示詞上，會比在標註員自己的提示詞上更高？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|-----------------|------------------------|
| SFT | 「指令微調」 | 第一階段：在提示詞－回應配對上做交叉熵微調 |
| 獎勵模型 | 「那個 RM」 | 在 (提示詞, 回應) 上的純量迴歸器，用 Bradley-Terry 在成對標籤上訓練 |
| Bradley-Terry | 「成對偏好損失」 | -log sigmoid(r_w - r_l)；把成對排序化約成二元分類 |
| KL 懲罰 | 「那個正則化項」 | `beta * KL(pi \|\| pi_SFT)` —— 讓 RL 策略待在 SFT 錨點附近 |
| PPO-ptx | 「混了預訓練的 PPO」 | 在 PPO 目標函式裡加上一部分預訓練對數概似，以抵銷對齊稅 |
| 對齊稅 | 「RLHF 造成的退步」 | RLHF 之後在它沒針對的標準基準上掉下來的分數 |
| 標註員偏好 | 「那個標準答案」 | 人類排序的一份樣本；RM 是它的統計代理，不是「人類價值」的代理 |
