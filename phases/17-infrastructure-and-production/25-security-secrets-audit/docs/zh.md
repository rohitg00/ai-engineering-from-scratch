# 安全 — 密钥、API 密钥轮换、审计日志、防护措施

> 通过集中式密钥库（HashiCorp Vault、AWS Secrets Manager、Azure Key Vault）消除密钥泛滥。切勿将凭证存储在配置文件、版本控制系统中的环境文件或电子表格中。优先使用 IAM 角色而非静态密钥；CI/CD 中使用 OIDC。AI 网关模式是 2026 年的解决方案：应用 → 网关 → 模型提供商，网关在运行时从密钥库拉取凭证。在密钥库中轮换后，所有应用数分钟内即可获取新密钥 — 无需重新部署，无需在 Slack 中询问"谁有新密钥"。轮换策略 ≤90 天；每次提交使用 TruffleHog / GitGuardian / Gitleaks 扫描。零信任：MFA、SSO、RBAC/ABAC、短生命周期令牌、设备安全态势。PII 脱敏使用实体识别在转发前屏蔽 PHI/PII；一致的标记化（Mesh 方法）将敏感值映射为稳定的占位符，使 LLM 保留代码/关系语义。网络出口：LLM 服务在专用 VPC/VNet 子网中，仅白名单 `api.openai.com`、`api.anthropic.com` 等；阻止所有其他出站流量。2026 年事件驱动：Vercel 供应链攻击通过被攻陷的 CI/CD 凭证窃取了数千个客户部署的环境变量。

**类型：** 学习
**语言：** Python（stdlib，玩具级 PII 脱敏器 + 审计日志写入器）
**前置要求：** 阶段 17·19（AI 网关），阶段 17·13（可观测性）
**预计时间：** ~60 分钟

## 学习目标

- 列举四种密钥管理反模式（版本控制系统中的配置文件、硬编码的环境变量、电子表格、静态密钥）并说明其替代方案。
- 解释 AI 网关从密钥库拉取凭证的模式作为 2026 年生产标准。
- 实现一个具有一致标记化功能的 PII 脱敏器（相同值 → 相同占位符），确保语义不受影响。
- 说出 2026 年 Vercel 供应链事件及其对 CI/CD 凭证管理的教训。

## 问题描述

某实习生提交了包含 API 密钥的 `.env` 文件。他们很快删除了该文件。但密钥已经进入 git 历史 — GitGuardian 扫描捕获到了它，而你的轮换流程是"在 Slack 通知团队、更新 40 个配置文件、重新部署所有服务。"8 小时后，一半服务已上线，另一半还在等待部署窗口。

与此同时，用户提示中包含"我的社会安全号码是 123-45-6789。"该提示被发送到 OpenAI。你虽然签有业务伙伴协议（BAA），但内部策略要求在转发前屏蔽 PII。你没有做到。

另外，你的 EKS 集群中的 LLM Pod 可以访问任何互联网主机。有人通过 DNS 查询将数据泄露到了攻击者控制的域名。没有任何东西阻止它。

LLM 服务的安全必须解决所有三个向量：基于密钥库的凭证、PII 脱敏、网络出口过滤、审计日志。

## 核心概念

### 集中式密钥库 + IAM 角色拉取

**密钥库**：HashiCorp Vault、AWS Secrets Manager、Azure Key Vault、GCP Secret Manager。单一事实来源。

**IAM 角色**：应用/网关通过其 IAM 身份进行身份验证，而非使用静态密钥。密钥库在令牌生命周期内返回密钥。

**AI 网关模式**：网关在请求时从密钥库拉取 `OPENAI_API_KEY`。在密钥库中轮换密钥；下一次请求即可使用新密钥。无需重新部署。

### 轮换策略 ≤ 90 天

所有 API 密钥、密钥库根令牌、CI/CD 凭证。尽可能自动化轮换。手动轮换需记录并跟踪。

### 密钥扫描

- **TruffleHog** — 基于正则表达式和熵值对提交进行扫描。
- **GitGuardian** — 商业产品，高准确率。
- **Gitleaks** — 开源，可在 CI 中运行。

每次提交都运行。如果检测到新密钥则阻止 PR。

### 零信任安全姿态

- 所有账户均需 MFA。
- 通过 SAML/OIDC 实现 SSO。
- 基于 RBAC（基于角色）或 ABAC（基于属性）的细粒度访问控制。
- 短生命周期令牌（小时级别，非天数）。
- 设备安全姿态 — 仅限启用磁盘加密的企业设备。

### PII/PHI 脱敏

在提示离开你的基础设施之前：

1. 实体识别（spaCy NER、Presidio、商业产品）。
2. 掩码匹配的实体：`"我的社会安全号码是 123-45-6789"` → `"我的社会安全号码是 [SSN_TOKEN_A3F]"`。
3. 一致的标记化（Mesh 方法）：相同值映射到相同占位符，使 LLM 保留关系语义。
4. 可选的反向映射用于 LLM 响应。

静态正则表达式过滤器可捕获基本模式；NER 可捕获更多模式。两者结合使用。

### 输入 + 输出防护措施

输入：阻止已知的越狱提示、禁止话题；按用户限速。

输出：正则表达式脱敏泄漏的密钥（API 密钥模式、拒绝上下文中的电子邮件模式）、策略违规分类器。

### 网络出口白名单

LLM 服务处于专用子网中：
- 白名单：`api.openai.com`、`api.anthropic.com`、向量数据库端点、密钥库端点。
- 其他所有流量：丢弃。
- DNS 通过仅允许列表的解析器（避免 DNS 隧道泄露）。

### 审计日志

每次 LLM 调用的不可变日志，包含：
- 时间戳。
- 用户/租户。
- 提示哈希（出于隐私考虑，非原始提示）。
- 模型 + 版本。
- 令牌数量。
- 成本。
- 响应哈希。
- 任何防护措施触发记录。

根据监管要求保留（SOC 2 为 1 年，HIPAA 为 6 年）。

### 2026 年 Vercel 事件

供应链攻击：被攻陷的 CI/CD 凭证窃取了数千个客户部署的环境变量。教训：CI/CD 凭证等同于生产环境凭证。存储在密钥库中。窄化作用域。积极轮换。

### 你应该记住的数字

- 轮换策略：≤ 90 天。
- 每次提交都扫描：TruffleHog / GitGuardian / Gitleaks。
- Vercel 2026：CI/CD 凭证被攻陷 → 数千个客户环境变量泄漏。
- 审计日志保留：SOC 2 = 1 年，HIPAA = 6 年。

## 练习

1. 运行 `code/main.py`。发送两个引用相同社会安全号码的提示。确认两者获得相同的占位符。
2. 为调用 OpenAI + Anthropic + Weaviate 的 vLLM-on-EKS 部署设计网络出口策略。
3. 你在 git 历史中发现了一个密钥（已有 2 年历史）。正确的应对措施是什么 — 轮换密钥、清理历史记录，还是两者都做？请说明理由。
4. 你的审计日志每天增长 10 GB。设计保留层级（热数据 30 天、温数据 12 个月、冷数据 6 年）。
5. 讨论反向标记化（将真实值替换回 LLM 响应）是否值得其复杂性，还是应保持占位符可见。

## 关键术语

| 术语 | 人们通常的说法 | 实际含义 |
|------|---------------|---------|
| 密钥库 | "密钥存储" | 集中式凭证管理服务 |
| IAM 角色 | "基于身份的身份验证" | 应用承担的角色；返回短期凭证 |
| OIDC for CI/CD | "云签发令牌" | CI 中无静态密钥 — 通过 OIDC 进行身份验证 |
| TruffleHog / GitGuardian / Gitleaks | "密钥扫描器" | 提交时检测密钥 |
| RBAC / ABAC | "访问控制" | 基于角色 vs 基于属性 |
| PII 脱敏 | "数据掩码" | 移除或标记化敏感实体 |
| 一致的标记化 | "稳定占位符" | 相同值每次生成相同令牌 |
| Mesh 方法 | "Mesh 标记化" | 保留语义的标记化模式 |
| 出口白名单 | "出站允许列表" | 仅允许访问许可的域名 |
| 审计日志 | "不可变历史" | 仅追加的记录，用于合规 |
