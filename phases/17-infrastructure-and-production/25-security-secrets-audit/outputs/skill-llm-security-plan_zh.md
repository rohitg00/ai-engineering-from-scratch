给定监管范围（SOC 2、HIPAA、GDPR）、当前凭据状态和网络/出口姿态，生成安全方案。

输出：

1. **保险库迁移**。选择保险库（HashiCorp、AWS Secrets Manager、Azure Key Vault、GCP Secret Manager）。网关模式：应用 → 网关 → 运行时保险库。弃用硬编码的环境变量和配置文件凭据。
2. **密钥扫描**。在每个提交上启用 TruffleHog / GitGuardian / Gitleaks。检测到时阻止 PR。
3. **轮换策略**。≤ 90 天。尽可能自动化。CI/CD 凭据专用轮换（更短——建议 30 天）。
4. **PII 脱敏**。实体识别（Presidio + 正则表达式）。一致的令牌化（相同值 → 相同占位符）以保持语义。
5. **出口白名单**。白名单 LLM 提供商域名、向量数据库、保险库端点。DNS 白名单解析器。
6. **审计日志**。仅追加、不可变。必填字段：用户、租户、提示/响应哈希、Token、成本、护栏触发。按框架保留（SOC 2 1年 / HIPAA 6年）。
7. **CI/CD 卫生**。OIDC 身份联合（无静态云密钥）。狭窄限定 CI/CD 凭据。引用 2026 年 Vercel 供应链事件作为动机。

**硬性拒绝条件：**
- 配置文件中的静态密钥。拒绝。
- 在审计日志中存储原始提示。拒绝——仅存储哈希，除非监管框架明确要求其它。
- 允许出口到 `*` 或"互联网"。拒绝——必须白名单。

**拒绝规则：**
- 如果客户不接受任何保险库（空气隔离要求），拒绝常规方案并设计基于文件加轮换的回退方案。明确说明安全性较低。
- 如果出于"延迟"原因拒绝 PII 脱敏，拒绝——延迟通常 <20 ms，而监管风险远超之。
- 如果保险库根令牌的轮换周期要求 >90 天，拒绝——它将成为入侵向量。

**输出**：一页方案，包含保险库、扫描、轮换、脱敏、出口、审计日志、CI/CD 姿态。最后给出单一指标：每月密钥扫描命中数；目标为零。
