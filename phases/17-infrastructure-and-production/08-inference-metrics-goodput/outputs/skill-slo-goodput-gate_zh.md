给定工作负载（模型、硬件、目标并发数、面向用户的交互类型——流式聊天/单次/语音/代理），生成基于 goodput 的 SLO 门控用于 CI/CD。

输出：

1. **SLO 规格**。三个阈值：TTFT P99 界限、TPOT P99 界限、E2E P99 界限。根据交互类型选择可防御的值（流式聊天：TTFT 500 ms、TPOT 25 ms、E2E 3 s；语音：TTFT 300 ms 更严格；代理：E2E 5 s 更宽松）。
2. **基准测试方案**。工具选择（LLMPerf 或 GenAI-Perf——说明你选择哪一个及原因）。提示分布（输入和输出 Token 的均值 + 标准差）。并发扫描（目标值的 25%、50%、100%、150%）。
3. **Goodput 计算**。公式：同时满足所有三个约束的请求占比。生产环境目标 >= 99%，金丝雀环境 >= 95%。
4. **百分位报告**。每个指标报告 P50、P90、P99（绝不仅仅报告均值）。仅在合理性检查时标注均值。
5. **工具陷阱说明**。说明所选工具是否将 TTFT 包含在 ITL 中。在跨团队比较前统一定义。
6. **门控逻辑**。CI 通过条件：goodput 在目标并发下 >= 目标值。标记在 100% 到 150% 并发下 goodput 下降超过 5 个百分点的情况——表明负载测试余量不足。

**硬性拒绝条件：**
- 仅基于吞吐量进行门控。拒绝并要求 goodput。
- 仅报告均值而不报告 P99。拒绝。
- 省略工具名称和工具版本。拒绝。
- 仅在目标并发下进行基准测试；始终执行扫描。

**拒绝规则：**
- 如果用户未写下任何 SLO，拒绝并根据交互类型先编写 SLO。
- 如果提示分布是"循环中相同的提示"，拒绝——这是提示均匀性陷阱。要求现实的合成数据。
- 如果基准测试少于 30 次运行或每次运行少于 100 个请求，拒绝——统计上不充分。

**输出**：一页 SLO 门控规格，列出阈值、基准测试方案、工具选择、百分位报告模板和 CI 通过/失败规则。最后根据已知弱点，指出"下一步测量什么"段落，指明 goodput vs 并发曲线、提示分布敏感性或 chunked-prefill 开/关尾部比较。
