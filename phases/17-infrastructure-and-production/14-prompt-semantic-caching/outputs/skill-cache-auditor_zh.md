给定提示模板、流量模式（到达率、并行因子）和提供商（Anthropic、OpenAI、Gemini、自托管 vLLM），生成缓存审计报告。

输出：

1. **前缀结构**。将模板拆分为静态（可缓存）和动态（不可缓存）部分。标记前缀中当前存在的任何动态内容并提出重写方案。
2. **TTL 选择**。Anthropic 5 分钟（1.25x 写入）vs 1 小时（2x 写入）。根据到达率选择——如果前缀在小时内持续被复用，1 小时更优。
3. **并行化审计**。统计具有共享前缀的并行请求数。如果 N > 2 且为并行，要求使用"先序列化再扇出"模式。量化预期的账单减少。
4. **语义缓存选择**。决定 L1 是否值得。开放式聊天：可能不值得（命中率低）。结构化 FAQ/支持：值得。设置余弦阈值，从 0.95 开始；仅在有响应质量评估的情况下向下调整。
5. **预期节省**。在当前流量和预测命中率下，计算与无缓存基线相比的月度 $ 差值。
6. **可观测指标**。一个仪表板指标用于捕获回归：过去滚动一小时的 L2 缓存命中率；如果下降超过 20% 则告警。

**硬性拒绝条件：**
- 声称"节省 50%"而未计算预期命中率和写入溢价。拒绝——按层计算。
- 将动态内容留在前缀中，而简单的重写就可将其移出。拒绝签字。
- 在未使用"先序列化"模式的情况下发起共享前缀的并行请求。拒绝——说明 5-10 倍的账单膨胀。

**拒绝规则：**
- 如果提示按 Token 计超过 80% 是动态内容，拒绝承诺缓存节省。最多建议语义缓存。
- 如果语义缓存阈值降至 0.85 以下而未经过响应质量评估，拒绝——存在幻觉缓存风险。
- 如果提供商不支持显式 cache_control（非 Anthropic、非 Gemini-v1）且仅支持自动缓存，注意命中率是机会性的，非保证的。

**输出**：一页审计，列出前缀重写、TTL、并行化模式、L1 阈值、预期节省、可观测指标。最后建议季度审查：在任何模板更改后重新审计提示。
