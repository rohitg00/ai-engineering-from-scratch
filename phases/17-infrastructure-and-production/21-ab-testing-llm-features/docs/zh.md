# LLM 功能的 A/B 测试 — GrowthBook、Statsig 与"感觉流"问题

> 传统 A/B 测试并非为非确定性 LLM 而设计。关键区别在于：评估（Eval）回答"模型能完成工作吗？"，A/B 测试回答"用户在意吗？"。两者缺一不可；仅凭"感觉"就上线已是过去式。2026 年需要测试的内容：提示词工程（措辞）、模型选择（GPT-4 vs GPT-3.5 vs 开源；准确性 vs 成本 vs 延迟）、生成参数（温度、top-p）。真实案例：一个聊天机器人奖励模型变体带来了对话长度 +70% 和留存率 +30% 的提升；Nextdoor 的 AI 主题行实验在奖励函数优化后实现了 CTR +1%；可汗学院 Khanmigo 在延迟与数学准确性之间进行迭代权衡。平台对比：**Statsig**（2025 年 9 月被 OpenAI 以 11 亿美元收购）——顺序测试、CUPED、一站式方案。**GrowthBook**——开源、数据仓库原生、支持贝叶斯 + 频率论 + 顺序引擎、CUPED、SRM 检查、Benjamini-Hochberg 和 Bonferroni 校正。选择取决于你对数据仓库 SQL 的偏好，以及"被 OpenAI 收购"对你的组织是否重要。

**类型：** 学习
**语言：** Python（标准库，玩具级顺序测试模拟器）
**前置条件：** 阶段 17 · 13（可观测性），阶段 17 · 20（渐进式部署）
**时长：** ~60 分钟

## 学习目标

- 区分评估（"模型能完成工作吗"）与 A/B 测试（"用户在意吗"）。
- 列举三个可测试维度（提示词、模型、参数），并为每个维度选择指标。
- 解释 CUPED、顺序测试以及 Benjamini-Hochberg 多重比较校正。
- 根据数据仓库 SQL 策略和对公司收购的态度，选择 Statsig 或 GrowthBook。

## 问题

你手动调优了一条系统提示词。感觉更好了。你将其上线。转化率因噪声而波动。你归咎于指标。或者你上线了一个新模型，转化率没有变化——是模型退化了，还是变化太小无法检测？你不知道，因为你没有做 A/B 测试就上线了。

评估回答的是模型能否在标注集上完成某项任务。它们不能回答用户是否更偏好该输出。只有受控的在线实验才能回答这个问题，而且前提是该实验有足够的统计功效、控制了非确定性，并对多重比较进行了校正。

## 概念

### 评估 vs A/B 测试

**评估**——离线、标注集、评判者（打分标准 或 LLM-as-judge 或人工）。回答："在这个固定分布上，输出是否正确/有用/安全？"

**A/B 测试**——在线、真实用户、随机化。回答："新的变体是否推动了重要的用户级指标？"

两者都是必需的。评估在暴露给用户之前捕捉回归问题；A/B 测试在之后确认产品影响力。

### 测试什么

1. **提示词工程**——措辞、系统提示词结构、示例。指标：任务成功率、用户留存率、每次请求成本。
2. **模型选择**——GPT-4 vs GPT-3.5-Turbo vs Llama-开源。指标：准确性（任务）+ 每次请求成本 + P99 延迟。多目标优化。
3. **生成参数**——温度、top-p、max_tokens。指标：特定任务（输出多样性 vs 确定性）。

### CUPED — 方差缩减

利用实验前数据进行受控实验（Controlled-experiments Using Pre-Experiment Data）。在比较实验后数据之前，先回归掉实验前的方差。典型方差缩减幅度：30-70%。有效样本量免费增加。

实现方式：Statsig 和 GrowthBook 均已实现。

### 顺序测试

经典 A/B 测试假设固定样本量。顺序测试（"边看边决定"）在反复查看数据的情况下控制假阳性率。始终有效的顺序过程（mSPRT、Howard 的置信序列）允许你在明确胜出时提前停止。

### 多重比较校正

在 95% 置信水平下运行 20 个 A/B 测试，按偶然性会产生 1 个假阳性。Bonferroni 校正收紧了每个测试的 α 值；Benjamini-Hochberg 控制错误发现率（FDR）。GrowthBook 两者都实现了。

### SRM — 样本比例失配

分配哈希将用户随机分配到各变体。如果 50/50 的分流变成了 47/53，说明出了问题——SRM 检查会标记出来。两个平台都已实现。

### Statsig vs GrowthBook

**Statsig**：
- 2025 年 9 月被 OpenAI 以 11 亿美元收购。托管式 SaaS。
- 顺序测试、CUPED、保留人群。
- 一站式方案：功能开关 + 实验 + 可观测性。
- 最佳适用场景：团队已经想要一个捆绑产品，且不介意 OpenAI 所有权。

**GrowthBook**：
- 开源（MIT）；数据仓库原生（直接从 Snowflake/BigQuery/Redshift 读取数据）。
- 多引擎：贝叶斯、频率论、顺序。
- CUPED、SRM、Bonferroni、BH 校正。
- 自托管或托管云。
- 最佳适用场景：数据仓库 SQL 团队，数据团队控制指标层，希望使用开源方案。

### 非确定性使统计功效复杂化

相同的提示词会产生不同的输出。传统的统计功效计算假设观测值独立同分布（IID）。由于 LLM 的非确定性，有效样本量低于名义样本量。建议将所需样本量乘以约 1.3-1.5 倍作为安全裕度。

### 真实案例结果

- 聊天机器人奖励模型变体：对话长度 +70%，留存率 +30%。
- Nextdoor 主题行：奖励函数优化后 CTR +1%。
- 可汗学院 Khanmigo：延迟与数学准确性的迭代权衡。

### 反模式：凭感觉上线

每一位资深工程师都能说出某个功能因为"感觉更好"而未经 A/B 测试就上线的情况。其中大多数都导致了产品指标的倒退，而团队数月都没有察觉。A/B 测试就是那个强制约束机制。

### 你应该记住的数字

- Statsig 被 OpenAI 收购：11 亿美元，2025 年 9 月。
- GrowthBook：开源 MIT；贝叶斯 + 频率论 + 顺序。
- CUPED 方差缩减：30-70%。
- LLM 非确定性 → +30-50% 样本量缓冲。

## 关键术语

| 术语 | 日常说法 | 实际含义 |
|------|----------|----------|
| Eval (评估) | "离线测试" | 对模型能力进行标注集评估 |
| A/B 测试 | "实验" | 在真实用户中进行的在线随机化比较 |
| CUPED | "方差缩减" | 利用实验前回归减少方差 |
| 顺序测试 | "边看边测" | 允许提前停止的始终有效的过程 |
| 多重比较 | "族系错误" | 运行多个测试会膨胀假阳性率 |
| Bonferroni | "严格校正" | 将 α 除以测试数量 |
| Benjamini-Hochberg | "BH FDR" | 错误发现率控制，不那么保守 |
| SRM | "分流异常" | 样本比例失配；分配错误 |
| Statsig | "被 OpenAI 收购" | 商业一站式平台，2025 年被收购 |
| GrowthBook | "开源的" | MIT 协议，数据仓库原生平台 |
| mSPRT | "顺序概率比测试" | 经典顺序过程 |
