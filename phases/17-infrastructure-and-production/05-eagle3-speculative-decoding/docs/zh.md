# 生产环境中的 EAGLE-3 投机解码

> 投机解码将快速草稿模型与目标模型配对。草稿模型提出 K 个 token；目标模型通过一次前向传播进行验证；被接受的 token 相当于免费获得。到了 2026 年，EAGLE-3 是生产级方案——它在目标模型的隐藏状态上训练草稿头（draft head），而非基于原始 token，从而在通用对话场景下将接受率 alpha 推至 0.6-0.8 区间。关键问题不是"草稿有多快"，而是"我的流量上的 alpha 是多少"。如果 alpha 降至约 0.55 以下，在高并发场景下投机解码会净负收益，因为每次被拒绝的草稿都意味着第二次目标前向传播。本课程教你先测量 alpha，再决定是否开启投机解码。

**类型：** 学习
**语言：** Python（标准库，简易接受率模拟器）
**前置条件：** 阶段 17 · 04（vLLM 服务内部机制），阶段 10 · 18（多 token 预测）
**时长：** 约 60 分钟

## 学习目标

- 说出三代投机解码的名称，并解释 EAGLE-3 相比 EAGLE-2 和经典草稿模型有哪些改进。
- 定义接受率 alpha，根据 alpha 和 K（草稿长度）计算预期加速比，并找出目标并发度下的盈亏平衡 alpha。
- 解释为什么投机解码在 2026 年的 vLLM 中是选择性启用的（而非默认开启），以及不经测量 alpha 就开启它是一种生产反模式。
- 制定测量计划：选择哪个基准测试、哪种提示词分布、哪个并发度水平、以哪个指标作为门控标准。

## 问题

解码是内存受限的。在一台运行 Llama 3.3 70B FP8 的 H100 上，每解码一个 token 需要读取约 140 GB/s 的权重并产生一个 token。解码期间 GPU 计算几乎处于空闲状态——瓶颈是 HBM 带宽，而非矩阵乘法吞吐量。

投机解码利用了这一差距。使用廉价的草稿模型生成 K 个候选 token，然后让目标模型通过一次前向传播验证所有 K 个 token。每个被验证通过的 token 实际上都是免费的（分摊到目标模型原本就需要执行的一次批量 K 前向中）。

经典草稿模型方法使用同系列中较小的模型（例如 Llama 3.2 1B 为 Llama 3.3 70B 起草）。这种方式可以工作，但接受率中等——较小模型的分布与目标模型存在偏差。EAGLE、EAGLE-2 再到 EAGLE-3 直接在目标模型的内部状态上训练一个轻量草稿头，使草稿的分布与目标模型更加接近。这就是为什么 alpha 从草稿模型方法的 0.4 提升到 EAGLE-3 的 0.6-0.8。

关键在于：EAGLE-3 在 2026 年的 vLLM 中是选择性启用的，必须显式设置 `speculative_config`。没有这个标志，就没有加速。那些未测量真实流量上的 alpha 就开启该功能的团队，往往会发现尾延迟变得更差，而非更好。

## 核心概念

### 投机解码实际能带来什么

没有投机解码时，每个 token 的成本是一次目标前向传播。使用投机解码，在草稿长度 K 和接受率 alpha 下，每次目标前向传播的期望 token 数为 `1 + K * alpha`。加速比为 `(1 + K * alpha) / (1 + epsilon)`，其中 epsilon 是草稿加验证的开销。对于 K=5，alpha=0.7：`(1 + 5*0.7) / (1 + 0.1) = 4.5 / 1.1 = 4.1x`。实际值集中在 2-3 倍左右，因为生产流量中的 alpha 很少能达到那么高，且 epsilon 会随着批处理规模增大而增加。

### 为什么 alpha 是唯一重要的指标

被拒绝的 token 不会消失——第一个被拒绝的 token 会触发第二次目标前向传播。在 alpha 降至 0.4 的工作负载上，你需要承担草稿开销、验证开销以及重新生成的开销。在高并发（例如 256 并发）下，解码批次已经足够大，"单独目标模型"和"带验证的目标模型"之间的内存带宽差距会缩小。在 2026 年的大多数硬件上，当 alpha 低于 0.55 时，投机解码就是净负收益。

Alpha 因工作负载而异。在 ShareGPT 风格的通用对话上，基于 ShareGPT 训练的 EAGLE-3 可达到 0.6-0.8。在领域特定流量（代码、医疗、法律）上，基于通用数据训练的草稿头会降至 0.4-0.6。训练领域特定的草稿头可以恢复 alpha——与目标模型微调相比，这是一项轻量且快速的训练任务。

### EAGLE 各代概览

- **经典草稿模型**：同系列小模型。Alpha 0.3-0.5。基础设施简单——加载两个模型，每次目标前向传播执行 K 次草稿前向传播。
- **EAGLE-1（2024）**：在目标模型隐藏状态（最后一层）上训练的单草稿头。Alpha 约 0.5-0.6。在目标模型之上增加少量参数开销。
- **EAGLE-2（2025）**：自适应草稿长度和基于树的草稿（在一次目标前向中验证多个分支）。Alpha 约 0.6-0.7。草稿调度器更复杂。
- **EAGLE-3（2025-2026）**：在目标模型的多个层（不仅仅是最后一层）上训练的草稿头，对齐效果更好。通用对话场景下 Alpha 约 0.6-0.8。

### 2026 年生产实践指南

1. 以纯目标模型部署。在目标并发度下测量基线 TTFT、ITL 和吞吐量。
2. 通过 vLLM 的 `speculative_config` 启用 EAGLE-3 草稿。重新运行基准测试。
3. 记录接受率 alpha。vLLM V1 通过 `spec_decode_metrics.accepted_tokens_per_request` 报告此值。除以请求的草稿长度即可得到 alpha。
4. 如果生产流量分布上的 alpha < 0.55，则禁用投机解码，或训练领域特定的 EAGLE-3 草稿。
5. 在生产并发度下重新运行测试。确认 P99 ITL 没有恶化。

### 生产陷阱：P99 尾延迟

平均 ITL 会因投机解码而下降。但如果未进行调优，P99 可能会变差。被拒绝的草稿会触发两阶段序列（草稿 + 验证失败 + 重新生成）。在满载批次下，这两个阶段会串行化。请关注 P99 ITL，而非 P50。

### EAGLE-3 已在何处部署

Google 于 2025 年在 AI Overviews 中部署了投机解码（相同质量，更快响应）。vLLM V1 将 `speculative_config` 作为文档化的接口提供；V1 中的 N-gram GPU 投机解码是与分块预填充（chunked prefill）兼容的变体。SGLang 支持 EAGLE-3，作为前缀密集型工作负载的推荐草稿方案。

### 盈亏平衡计算（一句话总结）

预期加速比：`S(alpha, K) = (1 + K*alpha) / (1 + verify_overhead)`。令 `S = 1` 求解 alpha：`alpha_breakeven = verify_overhead / K`。对于典型的 verify_overhead 约 0.15 且 K=5：`alpha_breakeven = 0.03`。但这只是原始解码的数学计算。在高并发下，验证开销增加，且解码批次已经将内存读取分摊到多个序列上，因此实际有效的 alpha_breakeven 在实践中的范围约为 0.45-0.55。

### 何时不应使用投机解码

- 延迟不重要的单条离线生成场景。使用纯目标模型即可。
- 非常短的输出（少于 50 个 token）。草稿开销和验证成本占据主导。
- 没有领域训练草稿头的专业领域。Alpha 太低。
- vLLM v0.18.0 加上草稿模型投机解码再加上 `--enable-chunked-prefill`。此组合无法编译。已知的例外是 V1 中的 N-gram GPU 投机解码。

## 关键术语

| 术语 | 日常说法 | 实际含义 |
|------|----------|----------|
| 投机解码（Speculative decoding） | "草稿加验证" | 使用廉价模型提出 K 个 token，在一次目标前向传播中验证全部 K 个 |
| 接受率 alpha（Acceptance rate alpha） | "投机接受率" | 目标模型接受的草稿 token 比例；唯一重要的指标 |
| 草稿长度 K（Draft length K） | "投机 K" | 每次目标前向传播中草稿提出的 token 数量；典型值为 4-8 |
| 验证开销 epsilon（Verify overhead epsilon） | "投机开销" | 验证并重新生成相比纯目标前向传播的额外成本；随批次大小增加 |
| EAGLE-3 | "最新 EAGLE" | 2025-2026 年方案；在目标模型的多个层上训练草稿头；通用对话场景 alpha 0.6-0.8 |
| `speculative_config` | "vLLM 投机配置" | vLLM V1 中显式的选择性启用；没有默认值意味着没有加速 |
| N-gram 投机解码（N-gram spec decode） | "N-gram 草稿" | 使用提示词中的 N-gram 查找进行 GPU 端草稿；兼容分块预填充 |
| 盈亏平衡 alpha（Break-even alpha） | "零增益 alpha" | 投机解码达到零加速时的 alpha 值；在生产并发度下关注此值 |
| 拒绝草稿两阶段（Rejected-draft two-pass） | "重新生成成本" | 草稿被拒绝时触发两次目标前向传播；导致 P99 尾延迟增加 |
