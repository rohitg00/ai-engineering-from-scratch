给定工作负载（模型大小、活跃参数、年 Token 量、质量敏感度——推理密集型或常规）、当前基础设施（H100/H200/B200 GPU、服务引擎）和预算，生成 Blackwell + TRT-LLM 迁移建议。

输出：

1. **当前基线**。根据报告的量和使用每 GPU 小时定价，计算当前 $/M Token 和年度支出。标记基线是否已在 Blackwell + TRT-LLM 上。
2. **目标栈**。推荐精确的精度组合（权重：NVFP4 或 FP8；KV 缓存：FP8；激活值：NVFP4；累加器：FP32）。对于推理密集型工作负载，首先推荐 FP8 权重，仅在评估集上逐块校准验证后才使用 NVFP4。
3. **预期节省**。根据 2026 年成本形态：H100 + vLLM ~$0.09/M → B200 + TRT-LLM ~$0.02/M → GB200 NVL72 + Dynamo ~$0.012/M。推算该工作负载 Token 量的年节省额。
4. **迁移成本**。工程时间（首次迁移 10-30 工程师周）。质量验证环节。GPU 资本支出或租赁承诺。
5. **盈亏平衡周期**。需要数月生产时间来摊销迁移成本。如果 > 18 个月，标记为边缘情况。
6. **锁定风险**。TRT-LLM 仅限 NVIDIA。指明两种退出策略（在 H100 上使用 vLLM 的双栈方案用于迭代层；保持权重可导出为 GGUF/HF 格式以实现非 NVIDIA 平台的可移植性）。

**硬性拒绝条件：**
- 在推理密集型模型上推荐 NVFP4 权重但未经过评估集验证步骤。
- 声称 7 倍差距但未指明计算所依据的 Token 量。
- 忽略 FP4 权重转换的质量验证。始终运行。

**拒绝规则：**
- 如果年推理支出 < $50 万，拒绝迁移。工程成本无法摊销。继续使用 vLLM + Hopper。
- 如果团队在服务中有任何 AMD/Intel GPU，拒绝在多供应商层使用 TRT-LLM。推荐在混合硬件上使用 vLLM。
- 如果模型在任务上的质量已经处于边缘状态，拒绝激进的量化。保持 FP8 或 BF16。

**输出**：一页 Blackwell 建议，列出当前基线、目标栈、预期节省、迁移成本、盈亏平衡周期和锁定退出方案。最后根据主要差距，指出"下一步阅读"段落，指向 MLPerf v6.0 博客、TRT-LLM 概述或 Dynamo 公告。
