给定模型大小、SLA（TTFT P99）、流量形态（稳定 vs 突发性）和预算状况，生成冷启动缓解方案。

输出：

1. **冷启动预算**。分解原始冷启动路径（节点置备、镜像拉取、权重加载到 HBM、引擎初始化、首次前向）。使用所述模型大小的 2026 年标称秒数。
2. **层选择**。选择使总时间低于 SLA 的最少层数：预播种镜像（L1）、模型流式加载器（L2）、GPU 快照（L3）、温池（L4）、分层加载（L5）。针对每个层所攻击的具体阶段论证。
3. **温池大小**。声明主路径的 `min_workers`。如果 SLA 为 TTFT P99 < 60s 且模型为 70B+，无论成本如何，温池为强制要求。
4. **成本估算**。所选温池的月 GPU 成本及预期的每日冷启动次数。
5. **尾部策略**。新副本上的第一个用户会发生什么——他们被排队到温副本，还是承受冷启动代价？指明具体策略（例如，"将第一个请求在 10s 内路由到任何温副本；否则回退到冷启动"）。
6. **故障模式**。如果温副本在会话中间死亡会发生什么。恢复是自动的（实时迁移），还是在下一个请求上冷启动？

**硬性拒绝条件：**
- 提出"只需添加温池"而未计算月度成本。
- 声称一种缓解措施但未指明其攻击的具体阶段（例如，说"使用 Bottlerocket"但未说明它消除 180s 的镜像拉取）。
- 忽略 GPU 快照的每 GPU 拓扑约束——如果平台迁移 SKU，快照无效。

**拒绝规则：**
- 如果 SLA 为 TTFT P99 < 5s 且是全新的 70B 冷启动且无温池，拒绝——在 2026 年基础设施速度下数学上不可能。
- 如果预算不允许温池但 SLA 要求次 30 秒冷启动，指明平台特定的修复方法（Modal GPU 快照、Baseten 预热）并拒绝在没有它的情况下在不同平台上承诺 SLA。
- 如果操作员要求零扩缩容到零配合突发流量和 70B 模型，拒绝承诺 SLA——没有快照或温池，数学上不可行。

**输出**：一页方案，列出阶段、层、`min_workers`、月度成本、尾部策略、故障模式。最后给出需要告警的单一指标：过去滚动一小时的 P99 冷启动持续时间。
