# 生产环境中大语言模型的混沌工程

> 面向大语言模型的混沌工程在 2026 年已成为一门独立学科。在生产环境中开展实验之前需满足以下前置条件：定义 SLI/SLO、链路追踪+指标+日志可观测性、自动化回滚、运行手册、值班机制。架构包含四个平面：控制平面（实验调度器）、目标平面（服务、基础设施、数据存储）、安全平面（防护门+中止+流量过滤器）、可观测性平面（指标+链路追踪+日志）及反馈环路（反馈至 SLO 调整）。防护栏是强制性的：当每日错误预算消耗超过预期 2 倍时，燃烧率告警将暂停实验；抑制窗口+链路追踪 ID 关联可对告警噪音进行去重。节奏：每周进行小型金丝雀实验及 SLO 评审；每月开展游戏日及事后复盘；每季度执行跨团队韧性审计及依赖关系映射。LLM 特定实验：内存过载、网络故障、供应商中断、格式错误的提示词、KV 缓存驱逐风暴。工具选型：Harness Chaos Engineering（LLM 衍生推荐、爆炸半径缩减、MCP 工具集成）；LitmusChaos（CNCF）；Chaos Mesh（CNCF、Kubernetes 原生）。

## 问题所在

混沌测试在传统技术栈中已相当成熟。LLM 技术栈带来了新的故障模式。一个包含恶意字符的 4K Token 提示词会使分词器停滞 12 秒。上游提供商返回 429 状态码；你的网关进行重试；服务因重试放大的并发量而内存溢出。突发负载下的 KV 缓存驱逐风暴会引发重新预填充级联，从而使计算资源饱和。

这些问题在单元测试中均不会显现。混沌工程正是在用户发现问题之前，让你提前发现它们的方法。

## 概念

### 前置条件

未满足以下条件之前，切勿在生产环境中运行混沌实验：

1. **SLI/SLO**——已定义的服务水平指标和目标。
2. **可观测性**——链路追踪、指标、日志，已接入仪表板。
3. **自动化回滚**——阶段 17 · 20 的策略标志回滚。
4. **运行手册**——结构化的手册，见阶段 17 · 23。
5. **值班机制**——有专人响应。

缺少任何一项，混沌实验都将变为真实事故。

### 四个平面 + 反馈

**控制平面**——实验调度器（Litmus 工作流、Chaos Mesh 调度、Harness UI）。

**目标平面**——服务、Pod、节点、负载均衡器、数据存储。

**安全平面**——紧急停止开关、抑制窗口、爆炸半径限制、错误预算门控。

**可观测性平面**——常规指标 + 链路追踪 ID 关联，用于区分混沌实验引发的故障与自然故障。

**反馈回路**——实验结果反馈至 SLO 调整、运行手册更新及代码修复。

### 防护栏是强制性的

- **燃烧率告警**：若每日错误预算消耗超过预期的 2 倍，则暂停实验。
- **抑制窗口**：实验期间，对爆炸半径内的非实验告警进行静默处理。
- **链路追踪 ID 关联**：所有实验引发的错误携带特定标签，以便值班人员去重。

### 五项 LLM 特定实验

1. **内存过载**——通过高并发发送长上下文请求，强制触发 KV 缓存抢占风暴。观察：服务是优雅降级还是崩溃。

2. **网络故障**——切断推理网关与提供商之间的网络连通性。观察：故障转移是否在 SLA 规定时间内生效。（阶段 17 · 19）

3. **供应商中断模拟**——OpenAI 返回 100% 的 429 错误。观察：路由是否故障转移至 Anthropic。（阶段 17 · 16、19）

4. **格式错误的提示词**——注入导致分词器停摆的负载（例如深度嵌套的 Unicode、极大的 UTF-8 码点）。观察：单个请求是否会导致工作者线程锁死。

5. **KV 驱逐风暴**——通过饱和 vLLM 块预算强制触发驱逐。观察：LMCache 能否恢复，还是服务降级。

### 节奏

- **每周**——在预发环境中进行小型金丝雀实验，可能扩展至 5% 的生产流量。
- **每月**——针对特定场景进行计划的游戏日；跨团队参与；事后复盘。
- **每季度**——跨团队韧性审计；依赖关系映射更新。

### 工具选型

- **Harness Chaos Engineering**——商业产品；AI 驱动的实验建议；爆炸半径缩减；MCP 工具集成。
- **LitmusChaos**——CNCF 毕业项目；基于 Kubernetes 工作流。
- **Chaos Mesh**——CNCF Sandbox 项目；Kubernetes 原生 CRD 风格。
- **Gremlin**——商业产品；支持广泛。
- **AWS FIS** / **Azure Chaos Studio**——托管云服务。

### 从小处着手

首个实验：在稳定流量下杀死一个解码副本的 Pod。观察路由重选及恢复情况。如果实验正常且看起来安全，再升级至网络混沌实验。

首个 LLM 特定实验：对某个提供商注入 5 分钟的 429 错误。观察故障转移。多数团队会发现他们的故障转移方案并未经过充分测试。

### 应记住的关键数字

- 四个平面：控制、目标、安全、可观测性。
- 燃烧率暂停阈值：预期每日预算消耗的 2 倍。
- 节奏：每周金丝雀、每月游戏日、每季度审计。
- 五项 LLM 实验：内存、网络、供应商、格式错误的提示词、KV 风暴。
