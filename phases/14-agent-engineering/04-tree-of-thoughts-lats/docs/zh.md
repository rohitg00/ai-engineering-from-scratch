# 思维树与LATS：深思熟虑的搜索

> 单条思维链轨迹没有回头路。ToT（Yao 等人，2023）将推理转化为一棵树，每个节点具有自我评估能力。LATS（Zhou 等人，2024）在蒙特卡洛树搜索下统一了 ToT、ReAct 和 Reflexion。24 点游戏从 4%（CoT）提升至 74%（ToT）；LATS 在 HumanEval 上达到 92.7% pass@1。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段 14 · 01（Agent 循环），阶段 14 · 03（Reflexion）
**时长：** ~75 分钟

## 学习目标

- 将推理建模为搜索：节点是"思考"，边是"扩展"，价值是"前景如何"。
- 使用标准库实现一个 ToT 风格的 BFS 树搜索，附带自我评估评分。
- 扩展为一个玩具 LATS MCTS 循环，包含选择 / 扩展 / 模拟 / 反向传播。
- 判断何时搜索值得 Token 开销倍数（24 点游戏、代码生成），何时单条轨迹已然足够（简单问答）。

## 问题

思维链是一条线性路径。只要第一步出错，后续每一步都在错误的前提上工作。在 24 点游戏（用四个数字和 + − × ÷ 算出 24）中，GPT-4 CoT 的准确率仅为 4%。模型过早选择了错误的子表达式，无法挽回。

推理真正需要的是：提出多个候选方案、评估它们、挑选有前景的、并在遇到死路时回溯。这就是搜索。思维树（Tree of Thoughts）和 LATS 是两个典型的实现形式。

## 概念

### 思维树（Yao 等人，NeurIPS 2023）

每个节点是一个连贯的中间步骤（一个"思考"）。每个节点可以扩展为 K 个子思考。LLM 通过评分提示对每个节点进行自我评估。搜索以 BFS、DFS 或束搜索（beam search）方式探索树。

```
                     （根："用 4 6 4 1 算出 24"）
                    /               |            \
           （"6 - 4 = 2"）    （"4 + 1 = 5"）    （"4 * 6 = 24"）  <- 评分：高
              /   \              |                  |
          ...    ...          ...                finish
```

自我评估是承担核心负载的部分。论文展示了三种变体：`肯定 / 可能 / 不可能` 分类、`1..10` 数值评分、以及候选方案之间的投票。三者都在 24 点游戏中大幅超越了 CoT（使用 GPT-4 从 4% 提升至 74%）。

### LATS（Zhou 等人，ICML 2024）

LATS 在 MCTS 下统一了 ToT、ReAct 和 Reflexion。LLM 扮演三个角色：

- **策略（Policy）**：提出候选下一步行动（ReAct 风格）。
- **价值函数（Value Function）**：对部分轨迹进行评分（ToT 风格自我评估）。
- **自我反思器（Self-reflector）**：失败时，编写自然语言反思（Reflexion 风格），并用于重新播种未来的推出（rollout）。

环境反馈（观测结果）融入价值函数，使搜索不仅依赖模型的主观判断，还能获知真实的工具执行结果。论文发布时的结果：HumanEval pass@1 达到 92.7%（GPT-4，SOTA），WebShop 平均 75.9（GPT-3.5，接近基于梯度的微调方法）。

### MCTS 基础

每轮迭代包含四个阶段：

1. **选择（Select）** — 使用 UCT（上限置信区间树）从根节点走到一个叶节点。
2. **扩展（Expand）** — 通过策略生成 K 个子节点。
3. **模拟（Simulate）** — 从子节点使用策略推出到叶节点，用价值函数（或环境奖励）对叶节点评分。
4. **反向传播（Backpropagate）** — 沿路径更新访问次数和价值估计。

UCT 公式：`Q(s, a) + c * sqrt(ln N(s) / N(s, a))`。第一项是利用（exploitation），第二项是探索（exploration）。根据任务调整 `c` 值。

### 成本现实

搜索会爆炸式消耗 Token。ToT 在 24 点游戏中使用的 Token 量是 CoT 的 100–1000 倍。LATS 类似。这不是免费的；请将搜索保留给：

- 单条轨迹显然不够的任务（24 点游戏、复杂代码）。
- 挂钟时间不如正确性重要的任务。
- 拥有廉价且可靠的价值函数的任务（代码的单元测试、数学的明确目标）。

如果你的任务有单一正确答案但评估器有噪声，搜索往往适得其反——它会找到一个"评分高"的错误答案。

### 2026 年的定位

大多数生产环境中的 Agent 并不运行 LATS。它们运行的是带工具验证的 ReAct（CRITIC，第 05 课）。搜索出现在专门的细分领域：

- 以运行测试作为价值函数的编码 Agent（HumanEval 风格）。
- 探索多条查询路径的深度研究 Agent。
- LangGraph 子图中重度依赖规划的工作流。

AlphaEvolve（第 11 课）是 2025 年的极致代表：对代码进行进化搜索，机器可检查的适应度，前沿突破（56 年来首次 4x4 矩阵乘法改进）。

## 动手构建

`code/main.py` 实现了：

- 在一个风格化的"选择算术运算"任务上实现一个小型 ToT BFS。
- 在同一任务上实现一个玩具 LATS MCTS 循环（选择 / 扩展 / 模拟 / 反向传播），使用 UCT 选择。
- 一个由符号评分和自我评估评分组合而成的价值函数。

运行方式：

```
python3 code/main.py
```

跟踪输出显示了 ToT 使用 BFS 对每个节点扩展三个候选，而 LATS 通过 MCTS 收敛到最佳推出路径。两者都会打印 Token 数量。

## 如何使用

LangGraph 将 ToT 风格的探索作为子图模式提供；LangChain 团队的 LATS 博客（2024 年 5 月）是参考教程。LlamaIndex 提供了一个 `TreeOfThoughts` Agent。对于大多数 2026 年的生产 Agent，此模式位于一个 `if task_complexity > threshold: use_search()` 门控之后——参见第 05 课的评估器-优化器模式。

## 交付物

`outputs/skill-search-policy.md` 根据任务形态、预算和评估器保真度，在线性 ReAct、ToT、LATS 和进化搜索之间进行选择。

## 练习

1. 用 UCT c=0.1 和 c=2.0 分别运行玩具 LATS。跟踪输出有何不同？
2. 将价值函数替换为一个噪声更大的评分器（添加随机抖动）。MCTS 是否仍能找到最佳叶节点？它能容忍的最低信噪比是多少？
3. 实现束搜索 ToT（每层保留 top-k）并与 BFS 比较。在 Token 预算紧张时哪个更好？
4. 阅读 LATS 论文第 5.1 节。复现 HumanEval 的轨迹数量：需要多少次推出才能达到报告中的 pass@1？
5. 阅读 LATS 论文中关于"何时 LATS 帮助不大"的讨论。写一段决策规则，将任务形态映射到搜索策略。

## 关键术语

| 术语 | 大家常说的 | 实际含义 |
|------|------------|----------|
| 思维树（Tree of Thoughts） | "分支式思维链" | Yao 等人——带自我评估的思考节点树 |
| LATS | "面向 LLM 的 MCTS" | Zhou 等人——在 MCTS 下统一 ToT + ReAct + Reflexion |
| UCT | "上限置信区间" | 平衡利用（Q）和探索（ln N / n）的选择公式 |
| 价值函数（Value function） | "这个状态有多好" | 由 LLM 提示评分或环境奖励提供；反馈给反向传播 |
| 策略（Policy） | "行动提案器" | ReAct 风格的生成器；输出候选的下一个思考/行动 |
| 推出（Rollout） | "模拟轨迹" | 使用策略从节点走到叶节点，用价值函数评分 |
| 反向传播（Backpropagate） | "更新祖先节点" | 将叶节点的奖励沿路径向上传递，更新访问次数和 Q 值 |
| 搜索成本（Search cost） | "Token 爆炸" | 在 24 点游戏中是 CoT 的 100-1000 倍；采用前请预算 |
