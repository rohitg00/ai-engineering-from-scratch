# Tree of Thoughts 與 LATS：刻意的搜尋

> 單一條思維鏈軌跡沒有回溯的餘地。ToT（Yao 等人，2023）把推理變成一棵樹，每個節點都做自我評估。LATS（Zhou 等人，2024）在蒙地卡羅樹搜尋之下統一了 ToT、ReAct 與 Reflexion。二十四點從 4%（CoT）拉到 74%（ToT）；LATS 在 HumanEval 上打到 92.7% pass@1。

**類型：** 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 14 · 01（代理迴圈）、階段 14 · 03（Reflexion）
**時間：** 約 75 分鐘

## 學習目標

- 把推理框成搜尋：節點是「思考」、邊是「展開」、價值是「有多看好」。
- 用 stdlib 實作一個 ToT 式的 BFS 樹搜尋，帶自我評估評分。
- 擴充成一個玩具版 LATS MCTS 迴圈，含選擇／展開／模擬／回傳。
- 判斷搜尋何時值得那個詞元倍數（二十四點、程式碼生成），何時單一條軌跡就夠了（簡單問答）。

## 問題所在

思維鏈是一條線性的走法。如果第一步就錯了，後面每一步都建立在壞前提上。在二十四點（用四個數字加上 + − × ÷ 湊出 24）上，GPT-4 的 CoT 只有 4% 準確率。模型很早就挑錯子運算式，之後救不回來。

推理需要的是這種能力：提出多個候選、評估它們、挑出看好的那些，並在遇到死路時回溯。那就是搜尋。Tree of Thoughts 與 LATS 是兩種典範化的表述。

## 核心概念

### Tree of Thoughts（Yao 等人，NeurIPS 2023）

每個節點是一個連貫的中間步驟（「一個思考」）。每個節點可以展開成 K 個子思考。LLM 用一段評分提示詞替每個節點自我評估。搜尋在樹上探索 —— BFS、DFS 或 beam。

```
                     (root: "find 24 from 4 6 4 1")
                    /               |            \
           ("6 - 4 = 2")    ("4 + 1 = 5")    ("4 * 6 = 24")  <- Score: HIGH
              /   \              |                  |
          ...    ...          ...                finish
```

自我評估是那塊承重結構。論文展示了三種變體：`sure / likely / impossible` 分類、`1..10` 數值評分，以及在候選之間投票。三種在二十四點上都大幅勝過 CoT（用 GPT-4 從 4% -> 74%）。

### LATS（Zhou 等人，ICML 2024）

LATS 在 MCTS 之下統一了 ToT、ReAct 與 Reflexion。LLM 扮演三種角色：

- **策略**：提出候選的下一步行動（ReAct 式）。
- **價值函數**：替一條部分軌跡評分（ToT 式自評）。
- **自我反思器**：失敗時寫下一段自然語言反思（Reflexion 式），並用它替未來的 rollout 重新播種。

環境回饋（觀察）會混進價值函數，好讓搜尋是由真實的工具結果所指引，而不只是模型的意見。論文當時的結果：用 GPT-4 在 HumanEval 上 pass@1 92.7%（SOTA）、用 GPT-3.5 在 WebShop 上平均 75.9（逼近基於梯度的微調）。

### MCTS，最精簡版

每次迭代有四個階段：

1. **選擇** —— 用 UCT（樹的信賴上界）從根走到某個葉。
2. **展開** —— 透過策略產生 K 個子節點。
3. **模擬** —— 從某個子節點用策略做 rollout，並用價值函數（或環境獎勵）替葉評分。
4. **回傳** —— 沿著路徑往上更新造訪次數與價值估計。

UCT 公式：`Q(s, a) + c * sqrt(ln N(s) / N(s, a))`。第一項是利用；第二項是探索。`c` 要依任務調。

### 成本的現實面

搜尋會讓詞元爆炸。ToT 在二十四點上用掉 CoT 的 100–1000 倍詞元。LATS 也差不多。這不是免費的；把搜尋留給：

- 單一條軌跡明顯不夠用的任務（二十四點、複雜程式碼）。
- 牆鐘時間沒有正確性重要的任務。
- 有便宜又可靠的價值函數的任務（程式碼的單元測試、數學的明確目標）。

如果你的任務只有一個正確答案、而評估器又很吵，搜尋往往讓事情更糟 —— 它會找到一個「分數很好」的錯答案。

### 2026 年的定位

多數生產代理不跑 LATS。它們跑的是 ReAct 加上工具接地的查證（CRITIC，第 05 課）。搜尋出現在幾個特化的利基裡：

- 拿測試當價值函數的寫程式代理（HumanEval 式）。
- 探索多條查詢路徑的深度研究代理。
- LangGraph 子圖裡那些規劃吃重的工作流。

AlphaEvolve（第 11 課）是 2025 年的極端案例：對程式碼做演化式搜尋、機器可檢核的適應度、前沿級的收穫（56 年來第一次改進 4x4 矩陣乘法）。

## 動手實作

`code/main.py` 實作了：

- 在一個風格化的「挑算術運算」任務上做一個很小的 ToT BFS。
- 在同一個任務上做一個玩具版 LATS MCTS 迴圈（選擇／展開／模擬／回傳），用 UCT 選擇。
- 一個價值函數，把符號式分數與自評分數組起來。

跑它：

```
python3 code/main.py
```

軌跡顯示 ToT 用 BFS 在每個節點展開三個候選，對照 LATS 透過 MCTS 收斂到最好的那條 rollout。兩者都會印出詞元數。

## 框架應用

LangGraph 把 ToT 式的探索當成子圖模式出貨；LangChain 團隊那篇談 LATS 的部落格（2024 年 5 月）是參考教學。LlamaIndex 出貨了一個 `TreeOfThoughts` 代理。對 2026 年多數生產代理來說，這套模式住在一道 `if task_complexity > threshold: use_search()` 的閘門後面 —— 見第 05 課的 evaluator-optimizer 模式。

## 產出交付

`outputs/skill-search-policy.md` 會依任務形狀、預算與評估器保真度，在線性 ReAct、ToT、LATS 與演化式搜尋之間做選擇。

## 練習

1. 用 UCT c=0.1 跟 c=2.0 各跑一次那個玩具 LATS。軌跡有什麼變化？
2. 把價值函數換成更吵的評分器（加上隨機抖動）。MCTS 還找得到最好的葉嗎？它能容忍的最低訊噪比是多少？
3. 實作 beam-search 版的 ToT（每一層保留 top-k），並跟 BFS 比較。在很緊的詞元預算下，哪個比較好？
4. 讀 LATS 第 5.1 節。重現那個 HumanEval 的軌跡數：要幾條 rollout 才打得到論文報告的 pass@1？
5. 讀 LATS 論文裡談「LATS 何時幫助較小」的討論。寫一段話的決策規則，把任務形狀對映到搜尋策略。

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| Tree of Thoughts | 「會分岔的 CoT」 | Yao 等人 —— 由思考節點構成、帶自我評估的樹 |
| LATS | 「給 LLM 的 MCTS」 | Zhou 等人 —— 在 MCTS 之下統一 ToT + ReAct + Reflexion |
| UCT | 「信賴上界」 | 在利用（Q）與探索（ln N / n）之間取平衡的選擇公式 |
| 價值函數 | 「這個狀態有多好」 | 提示詞誘導出的 LLM 分數或環境獎勵；餵給回傳 |
| 策略 | 「行動提議者」 | ReAct 式的產生器；吐出候選的下一個思考／行動 |
| Rollout | 「模擬出來的軌跡」 | 用策略從某節點走到葉，再用價值函數評分 |
| 回傳 | 「更新祖先」 | 把葉的獎勵沿路徑往上推，更新造訪次數與 Q |
| 搜尋成本 | 「詞元爆炸」 | 在二十四點上是 CoT 的 100-1000 倍；採用之前先編預算 |
