给定任务形态（单答案 / 多答案 / 开放式）、token 预算和可用的评估器（标量测试 / 启发式 / 自我评估），生成一个包含具体参数的搜索策略推荐。

产出：

1. 决策。以下之一：线性 ReAct、束搜索 ToT（束宽 k）、BFS ToT（最大深度）、带剪枝的 DFS ToT、MCTS LATS（迭代次数和 UCT c）、演化搜索（仅在评估器是编程式且可检查时）。
2. 参数。对于每种策略，给出具体的数值默认值：束宽、深度上限、分支因子 K、每层级 rollout 次数、UCT c（默认 1.4）、超时时间。
3. 价值函数。明确指出对节点评分的依据。选项：单元测试通过率、到目标数值的距离、带格式的 LLM 提示评分（确定/可能/不可能 或 1..10 或投票）或环境奖励。
4. Token 预算估算。最坏情况 token 数 = 分支因子 ^ 深度 * 平均提示 token 数。显示该数字。如果超出用户预算，推荐更经济的策略。
5. 失败模式。对于每种选定策略，列出前两种失败模式及其缓解措施（例如 LATS + 噪声评估器 -> 添加基于工具的验证，如 CRITIC，第 05 课）。

硬性拒绝：

- 在评估器不可靠时（仅有自我评估，无真实依据）推荐搜索。回退到 ReAct + CRITIC。
- 在没有充分理由的情况下将分支因子 K 设置高于 5。K=3-5 是论文默认值；K=10 会导致成本爆炸。
- 将 LATS 应用于聊天式任务。搜索对没有程序性目标的对话式问答无帮助。
- 在没有机器可检查的适应度函数时使用演化搜索。AlphaEvolve 仅在适应度是程序性时才有意义（运行测试、测量速度、验证定理）。

拒绝规则：

- 如果 token 预算 < 单条轨迹成本的 5 倍，拒绝搜索并推荐 ReAct + Reflexion（第 03 课）。
- 如果挂钟延迟预算 < 10 秒，拒绝 LATS 并推荐 ReAct。
- 如果任务是纯信息检索，拒绝搜索并推荐 ReWOO（第 02 课）。

输出：推荐块（选定的策略、参数、价值函数、预算估算）加上"下一步阅读"注释，指向第 05 课（CRITIC）以了解评估器可靠性，第 11 课（AlphaEvolve）以了解演化变体，或第 30 课（评估驱动开发）以进行基准级验证。
