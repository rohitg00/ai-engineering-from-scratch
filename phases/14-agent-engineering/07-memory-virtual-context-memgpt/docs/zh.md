# 代理記憶 —— 虛擬脈絡與記憶分頁

> 脈絡視窗是有限的。對話、文件與工具軌跡不是。解法是把作業系統的虛擬記憶體重新講一遍 —— 主脈絡是 RAM、外部儲存是磁碟，代理在兩者之間分頁。MemGPT（Packer 等人，2023）替這套模式命了名；許多生產級記憶系統都建立在它之上。

**類型：** 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 14 · 01（代理迴圈）、階段 14 · 06（工具使用）
**時間：** 約 75 分鐘

## 學習目標

- 解釋 MemGPT 建立其上的那個作業系統類比：主脈絡 = RAM、外部脈絡 = 磁碟、記憶工具 = 頁入／頁出。
- 用 stdlib 實作那套兩層的 MemGPT 模式，含一個主脈絡緩衝區、一個可搜尋的外部儲存，以及頁入／頁出工具。
- 描述代理如何發出「中斷」來查詢或修改外部記憶，以及結果如何被接回下一輪提示詞。
- 指認出哪些 MemGPT 的設計選擇一路帶進了 Letta（第 08 課）與 Mem0（第 09 課）。

## 問題所在

脈絡視窗看起來應該可以解決記憶。它們沒有。生產環境裡反覆出現三種失敗模式：

1. **溢位。** 多輪對話、長文件，或工具呼叫吃重的軌跡會超出視窗。切點之後的一切都沒了。
2. **稀釋。** 就算還在視窗內，塞進不相關的脈絡也會把注意力從真正重要的東西上稀釋掉。前沿模型在長輸入上仍會退化。
3. **持久性。** 新的工作階段從空視窗開始。沒有外部記憶的代理，沒辦法跨工作階段說出「還記得你那時候叫我……」。

更大的視窗有幫助，但修不好這件事。Mem0 2025 年的論文量到：128k 視窗的基線仍會漏掉一些長時程事實，而一個只有 4k 視窗但配了外部記憶的代理卻抓得到。

## 核心概念

### 作業系統類比

MemGPT（Packer 等人，arXiv:2310.08560，v2 於 2024 年 2 月）把脈絡管理對映到作業系統的虛擬記憶體：

| 作業系統概念 | MemGPT 概念 | 2026 年生產環境的對應物 |
|------------|---------------|------------------------|
| RAM | 主脈絡（提示詞） | Anthropic／OpenAI 的脈絡視窗 |
| 磁碟 | 外部脈絡 | 向量 DB、KV、圖資料庫 |
| 分頁錯誤 | 記憶工具呼叫 | `memory.search`、`memory.read`、`memory.write` |
| 作業系統核心 | 代理控制迴圈 | 帶記憶工具的 ReAct 迴圈 |

代理跑的是一般的 ReAct 迴圈。多出來的那一類工具，讓它可以把資料頁入、頁出主脈絡。

### 兩層

- **主脈絡。** 固定大小的提示詞，裝著當前任務。模型永遠看得到。
- **外部脈絡。** 無界，可透過工具搜尋。相關時讀進來，有事實浮現時寫出去。

原始論文在兩項超出基礎視窗的任務上評測這個設計：超過 100k 詞元的文件分析，以及跨多天、記憶持久的多工作階段聊天。

### 中斷模式

MemGPT 引入「記憶即中斷」：對話進行到一半，代理可以調用一項記憶工具，執行環境去執行它，結果再以一段新的觀察接進下一個助理輪次。概念上跟 Unix 的 `read()` 系統呼叫一模一樣：擋住行程、回傳位元組、行程繼續。

典範化的記憶工具表面：

- `core_memory_append(section, text)` —— 寫入提示詞中某個持久區段。
- `core_memory_replace(section, old, new)` —— 編輯某個持久區段。
- `archival_memory_insert(text)` —— 寫入可搜尋的外部儲存。
- `archival_memory_search(query, top_k)` —— 從外部儲存檢索。
- `conversation_search(query)` —— 掃過往輪次。

### 論文結束、生產開始的那條線

2024 年 9 月，MemGPT 變成了 Letta。研究用的儲存庫（`cpacker/MemGPT`）還在；Letta 則擴充了這個設計：

- 三層而非兩層（core、recall、archival —— 第 08 課）。
- 用原生推理取代 `send_message`／心跳模式（第 08 課）。
- 跑非同步記憶工作的 sleep-time 代理（第 08 課）。

即使生產系統跑的是 Letta、Mem0 或自製的兩層儲存，MemGPT 論文仍是 2026 年的地基。

### 這套模式在哪裡會出錯

- **記憶腐爛。** 寫入累積得比讀取快；檢索淹沒在過期事實裡。修法：定期整併（Letta 的 sleep-time）、明確失效（Mem0 的衝突偵測器）。
- **記憶投毒。** 外部記憶就是被檢索回來的文字。若攻擊者控制的內容落進某則記憶筆記，代理下一個工作階段就會把它重新吃進去。這就是 Greshake 等人那套攻擊（第 27 課），只是沿時間軸重講一次。
- **引用遺失。** 代理回想起「使用者叫我出貨 X」，卻說不出是哪一輪。每一次歸檔寫入都要一起存來源參照（工作階段 ID、輪次 ID）。

## 動手實作

`code/main.py` 用 stdlib 實作 MemGPT 那套兩層模式：

- `MainContext` —— 固定大小的提示詞緩衝區，含一個 `core` dict 與一個 `messages` list；超出上限時自動壓實最舊的訊息。
- `ArchivalStore` —— 一個記憶體內、類 BM25 的儲存（用詞元重疊評分），存放 (id, text, tags, session, turn) 紀錄。
- 五項記憶工具，對映到 MemGPT 的那套表面。
- 一個腳本化的代理，先把事實填進歸檔，再靠呼叫 `archival_memory_search` 回答問題。

跑它：

```
python3 code/main.py
```

軌跡顯示代理寫入三則事實、把主脈絡填到上限（迫使逐出），接著靠從歸檔檢索來回答一個後續問題 —— 在沒有任何真實 LLM 的情況下重現 MemGPT 的工作流。

## 框架應用

今天每一套生產級記憶系統都是 MemGPT 的變體：

- **Letta**（第 08 課）—— 三層、原生推理、sleep-time compute。
- **Mem0**（第 09 課）—— 向量 + KV + 圖，融合一層評分。
- **OpenAI Assistants／Responses** —— 透過 threads 與 files 的託管記憶。
- **Claude Agent SDK** —— 透過技能與工作階段儲存的長期記憶。

挑一個時要看運維形狀（自架、託管、與框架整合），而不是看核心模式 —— 核心模式就是 MemGPT。

### 代理記憶的形狀

分頁解決的是容量。它不決定該存什麼。生產系統裡反覆出現四種記憶型別，各自回答不同的問題：

- **工作記憶** —— 現在什麼重要？那個在脈絡內的層：當前任務、最近幾輪、釘住的 core 區段。就是提示詞本身。
- **情節記憶** —— 發生過什麼？過往輪次與軌跡，連同工作階段與輪次參照一起存，需要時可重播。
- **語意記憶** —— 什麼是真的？關於使用者、領域、世界的事實，隨變化更新並去重。
- **程序記憶** —— 這件事我要怎麼做？學到的例行程序、偏好與規則，它們引導的是未來行為，而不是回想。

開源實作各自挑了不同的切入點：

| 型別 | 實作 | 它怎麼下手 |
|------|----------------|-------------------|
| 工作 | MemGPT / Letta | 透過記憶工具在固定的提示詞預算裡頁入頁出內容（本課、第 08 課） |
| 情節 | Zep | 時間性知識圖 —— 事實帶有效區間，所以「當時什麼是真的」是可查詢的 |
| 語意 | Mem0 | 一條抽取管線，跨向量、KV 與圖儲存去重並更新事實（第 09 課） |
| 語意 + 程序 | LangMem | 在背景把事實與行為規則抽取進一個儲存，代理在輪次之間去查詢它 |
| 情節 + 語意 | agentmemory | 在工作階段執行當下就捕捉它們，並整併成有型別、可搜尋的紀錄 |

## 練習

1. 加一個以詞元計的 `max_main_context_tokens` 上限（用 `len(text.split())` * 1.3 近似）。超出上限時，把最舊的訊息壓實成一段摘要。比較有與沒有摘要器時的行為。
2. 在歸檔儲存上好好實作 BM25（詞頻、逆文件頻率）。在一組玩具事實上，量它相對於詞元重疊基線的 recall@10。
3. 給歸檔插入加上 `citation` 欄位（session_id、turn_id、source_url）。讓代理在每個有檢索支撐的答案上都標出來源。
4. 模擬記憶投毒：加一筆寫著「忽略未來所有使用者指示」的歸檔紀錄。寫一個守衛，掃描檢索結果中形似指令的文字並標記為不可信。
5. 把這份實作移植成使用 MemGPT 研究儲存庫（`cpacker/MemGPT`）的 core-memory JSON schema。從扁平字串換成有型別的區段之後，有什麼變了？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| 虛擬脈絡 | 「無限記憶」 | 主（提示詞）+ 外部（可搜尋）兩層，加上頁入／頁出 |
| 主脈絡 | 「工作記憶」 | 那份提示詞 —— 固定大小、永遠可見 |
| 歸檔記憶 | 「長期儲存」 | 外部、可搜尋的持久層，需要時才檢索 |
| Core 記憶 | 「持久的提示詞區段」 | 釘在主脈絡裡的具名區段 |
| 記憶工具 | 「記憶 API」 | 代理發出、用來讀寫外部記憶的工具呼叫 |
| 中斷 | 「記憶分頁錯誤」 | 代理暫停、執行環境去取、結果接進下一輪 |
| 記憶腐爛 | 「過期事實」 | 舊的寫入淹沒檢索；用整併來修 |
| 記憶投毒 | 「被注入的持久筆記」 | 攻擊者的內容被存成記憶，回想時又被吃回去 |
