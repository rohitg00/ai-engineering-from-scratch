给定一个仓库、智能体产品及其依赖表面，生成一个项目特定的初始化脚本和 CI 连接。

产出：

1. `tools/init_agent.py`，包含这些探测：运行时版本、列出的依赖项、测试命令可解析性、所需环境变量、状态文件新鲜度。
2. `init_report.json` 模式，记录在脚本旁边。每个探测返回 `(name, status: pass|warn|fail, detail)`。
3. `.github/workflows/agent-init.yml`（或等效），运行脚本并阻塞任何失败严重性探测上的智能体作业。
4. 一个 `pre-task` 钩子脚本，智能体运行时可以在每个会话开始前调用。
5. `docs/init.md` 中的文档，列出每个探测、其严重性以及如何修复失败。

硬性拒绝：

- 没有超时就调用网络的探测。初始化必须快速且离线安全。
- 需要 LLM 调用的探测。初始化是确定性的管道工作。
- 包装器吞没的非零退出码。大声失败是全部意义所在。
- 触摸状态而没有幂等性的探测。连续两次运行必须产生相同的报告（时间戳除外）。

拒绝规则：

- 如果项目没有测试命令，拒绝交付脚本。而是将差距添加到工作台审计中。
- 如果环境变量列表包含脚本会打印的秘密，拒绝并强制编辑。初始化报告不应携带秘密。
- 如果探测在干运行中耗时超过三秒，在交付前提出来时间发现。长探测将初始化变成仪式。

输出结构：

```
<repo>/
├── tools/
│   ├── init_agent.py
│   └── pre_task.sh
├── docs/
│   └── init.md
└── .github/
    └── workflows/
        └── agent-init.yml
```
