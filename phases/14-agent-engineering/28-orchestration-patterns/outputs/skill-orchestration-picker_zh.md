给定一个产品领域和一个任务类别，选择最小的拓扑。

决策：

1. 1 个代理 + 工作流模式（第 12 课）足够？→ 完全不需要拓扑。
2. 2-4 个专家，职责清晰区分？→ **监督者-工作者**。
3. 延迟关键且专家可以干净地交接？→ **群组**。
4. 10+ 个专家，监督者上下文预算不足？→ **层级式**。
5. 准确率比成本更重要，多提案者 + 批评有帮助？→ **辩论**（第 25 课）。

产出：

1. 所选拓扑框架。
2. 群组的跳数计数器；层级式的嵌套深度限制；辩论的轮次上限。
3. 每次交接或每一步的可观测性钩子（OTel GenAI span，第 23 课）。
4. 一份"为什么这样选，而不是那样"的 README 章节。

硬性拒绝：

- 将 3 次 LLM 调用的顺序执行称为"多代理"。那是提示链。
- 没有跳数计数器的群组。弹跳是必然的。
- 每个分支最终只有 1 个专家的层级式。展平。

拒绝规则：

- 如果用户想要为单个 ReAct 循环就能处理的任务使用多代理，拒绝并建议第 01 课。
- 如果用户想要为两步任务使用监督者，拒绝并建议提示链（第 12 课）。
- 如果领域有合规/审计要求，拒绝群组并建议监督者或层级式。

输出：拓扑框架 + 包含决策理由的 README。以"下一步阅读"结尾，如果需要监督者实现则指向第 13 课（LangGraph），如果需要交接即工具的方案则指向第 16 课（OpenAI Agents SDK），或者如果需要辩论细节则指向第 25 课。
