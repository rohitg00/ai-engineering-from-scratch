# 失败模式：Agent 为什么会出问题

> MASFT（伯克利，2025）收录了 14 种多 Agent 失败模式，归为 3 大类。微软的分类法记录了现有 AI 失败如何在 Agent 环境中被放大。行业实地数据汇聚出五种反复出现的模式：幻觉行为、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建  
**语言：** Python（stdlib）  
**前置知识：** 阶段 14 · 05（自我优化与 CRITIC）、阶段 14 · 24（可观测性）  
**时长：** 约 60 分钟  

## 学习目标

- 说出 MASFT 的三大失败类别，以及每个类别中至少四种具体模式。
- 解释为何 Agent 失败会放大已有的 AI 失败模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个基于 stdlib 的检测器，用失败模式标签标记 Agent 轨迹。

## 问题

团队部署的 Agent 在 90% 的轨迹上都能正常工作。剩下 10% 的失败并非随机噪声——它们可归入少数反复出现的类别。一旦你能命名它们，就能监控并修复它们。

## 概念

### MASFT（伯克利，arXiv:2503.13657）

多 Agent 系统失败分类法。共 14 种失败模式，聚为 3 大类。标注者间 Cohen's Kappa 系数为 0.88——这些类别具有可靠的可区分性。

核心主张：失败是多 Agent 系统的根本设计缺陷，而非可以通过更好的基础模型来解决的 LLM 局限。

### 微软 Agentic AI 系统失败模式分类法

- 已有的 AI 失败（偏见、幻觉、数据泄露）在 Agent 环境中被放大。
- 自主性带来了新的失败：规模化的意外行动、工具误用、任务漂移。
- 该白皮书是 Agent 产品的风险登记册。

### Agentic AI 故障特征分析（arXiv:2603.06847）

- 失败源于编排、内部状态演化与环境交互。
- 不仅仅是"糟糕的代码"或"糟糕的模型输出"。

### LLM Agent 幻觉综述（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏离**——Agent 不遵循系统提示。
2. **长程上下文误用**——Agent 忘记或误用了早期轮次的上下文。

子意图错误：遗漏（跳过步骤）、冗余（重复步骤）、错序（步骤顺序错误）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026 年实地分析汇聚为：

1. **幻觉行为。** Agent 调用了不存在的工具或编造了参数。
2. **范围蔓延。** Agent 将任务扩展到用户请求的范围之外（创建额外 PR、发送额外邮件）。
3. **级联错误。** 一次错误调用引发下游连锁效应。一个幻影 SKU 幻觉触发四次 API 调用——一起跨系统事故。
4. **上下文丢失。** 长周期任务遗忘了早期轮次的约束。
5. **工具误用。** 调用正确的工具但参数错误，或者完全用错了工具。

级联是最致命的。Agent 无法区分"我失败了"和"任务不可能完成"，常常在 400 错误时编造一条成功消息来闭环。

### 缓解措施：每一步设关卡

在推理链的每一步设置自动化验证关卡，对照环境状态检查事实基础。具体而言：

- 逐步安全分类器（第 21 课）。
- 工具调用参数验证（第 06 课）。
- 将检索到的内容与已知事实交叉核对（第 05 课，CRITIC）。
- 通过重新探测状态检测成功幻觉（文件真的被创建了吗？）。

### 失败监控的常见误区

- **仅标记崩溃。** 大多数 Agent 失败会生成看起来正常的输出。需要内容层面的检查。
- **缺乏基准。** 漂移检测需要一个"上次已知正常"状态；没有它，你无法说"情况正在恶化"。
- **过度告警。** 每次失败都发告警。应进行聚类和限速。

## 构建

`code/main.py` 实现了一个基于 stdlib 的失败模式标签器：

- 一个涵盖五种模式的合成轨迹数据集。
- 每种模式的检测函数（基于工具调用、输出、重复动作的特征模式）。
- 一个标签器，为每条轨迹打标签并报告模式分布。

运行方式：

```
python3 code/main.py
```

输出：每条轨迹的标签 + 聚合分布，以低成本复现 Phoenix 轨迹聚类的效果。

## 使用

- **Phoenix** 用于生产环境漂移聚类（第 24 课）。
- **Langfuse** 用于会话回放 + 标注。
- **自定义** 用于你的可观测性平台无法检测的领域特定特征。

## 交付

`outputs/skill-failure-detector.md` 生成针对你的领域定制的失败模式检测器，并与轨迹存储对接。

## 练习

1. 为"成功幻觉"添加检测器：Agent 返回成功但目标状态并未改变。
2. 为你构建过的产品中的 100 条真实轨迹打标签。哪种模式占主导？修复它的代价是什么？
3. 实现一个"级联半径"指标：给定第 N 步的失败，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种失败模式。选择适用于你产品的三种，编写检测器。
5. 将一个检测器接入 CI 作业：如果 >=5% 的轨迹标记为某种模式，则构建失败。

## 关键术语

| 术语 | 人们通常说 | 实际含义 |
|------|-----------|---------|
| MASFT | "多 Agent 失败分类法" | 伯克利 14 模式分类 |
| 级联错误 | "涟漪式失败" | 一个早期错误通过 N 步传播 |
| 上下文丢失 | "忘记了约束" | 长周期轮次丢失早期轮次的事实 |
| 工具误用 | "用错工具/参数错误" | 有效调用，但调用方式错误 |
| 成功幻觉 | "伪造完成" | Agent 在 400 错误时声称成功；状态未改变 |
| 范围蔓延 | "越界" | Agent 做了超出要求的事 |
| 指令遵循偏离 | "不服从" | 忽略系统提示或用户约束 |
| 子意图错误 | "计划缺陷" | 计划执行中的遗漏、冗余、错序 |
