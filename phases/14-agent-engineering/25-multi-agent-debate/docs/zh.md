# 多智能体辩论与协作

> Du 等人（ICML 2024，"Society of Minds"）运行 N 个模型实例，各自独立提出答案，然后通过 R 轮迭代互相批评，最终收敛。可提升事实准确性、规则遵循能力和推理能力。稀疏拓扑相比全连接能以更低的 Token 成本达到相同效果。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置知识：** 阶段 14 · 12（工作流模式），阶段 14 · 05（自优化与 CRITIC）
**时长：** 约 60 分钟

## 学习目标

- 解释辩论协议：N 个提议者、R 轮迭代、收敛到共享答案。
- 阐述为什么辩论能提升事实准确性、规则遵循能力和推理能力。
- 解释稀疏拓扑：并非每个辩论者都必须看到所有其他辩论者。
- 使用纯标准库实现一个基于脚本化 LLM 的辩论系统，包括全连接和稀疏两种变体；衡量 Token 成本与准确率的关系。

## 问题背景

自优化（第 05 课）是一个模型自我批评——存在思维趋同的风险。CRITIC（第 05 课）将批评锚定在外部工具上——并非总是可用。辩论引入了第三种模式：多个实例相互批评，通过分歧达成收敛。

## 核心概念

### Society of Minds（Du 等人，ICML 2024）

- N 个模型实例针对同一问题独立提出答案。
- 经过 R 轮迭代，每个模型阅读其他模型的提案并对其进行批评。
- 模型根据批评更新自己的答案。
- R 轮之后，返回收敛后的答案。

原始实验因成本考虑使用了 N=3、R=2。在难题（MMLU、GSM8K、国际象棋走棋合法性、传记生成）上，更多智能体和更多轮次能提升准确率。

跨模型组合优于单模型辩论：ChatGPT + Bard 协同效果 > 任意单独使用。

### 稀疏拓扑

"通过稀疏通信拓扑改进多智能体辩论"（arXiv:2406.11776，2024-2025）表明，全连接辩论并非总是最优。稀疏拓扑（星型、环型、中心辐射型）能以更低的 Token 成本达到相同的准确率。每个辩论者只看到一部分同伴。

影响：

- 全连接 N=5、R=3 = 5 × 3 = 15 个提案，每个阅读 4 个同伴 = 60 次批评操作。
- 星型 N=5、R=3（一个中心 + 4 个辐射节点）= 15 个提案，辐射节点只阅读中心 = 12 次批评操作。

### 辩论何时有益

- **事实准确性。** N 个独立提案相互交叉验证，减少幻觉。
- **规则遵循。** 国际象棋走棋合法性——一个模型遗漏了规则，其他模型能发现。
- **开放式推理。** 多种视角逐步聚焦到正确答案。

### 辩论何时有害

- **对延迟敏感的用户体验。** N × R 轮串行迭代的延迟可能无法接受。
- **对成本敏感的规模化场景。** 每个问题消耗 N × R 个 Token。
- **简单事实查询。** 一次查询比五次辩论更便宜。

### 2026 年的实际实现

- **Anthropic 编排器-工作器**（第 12 课）——辩论的一种变体，增加了综合步骤。
- **LangGraph 监督器**（第 13 课）——中央路由器 + 专家智能体可以将辩论实现为一个节点。
- **OpenAI Agents SDK**（第 16 课）——智能体之间来回交接进行迭代批评。
- **多智能体评估**——将辩论 + 评估器-优化器配对以生成评估信号。

### 该模式可能失败的地方

- **收敛崩塌。** 所有智能体收敛到第一个错误答案。通过强制分歧轮次来缓解。
- **中心节点失效。** 在星型拓扑中，一个错误的中心节点会污染所有其他节点。轮换中心或使用多个中心。
- **提示同质化。** 所有智能体使用相同的提示，产生相同的答案。使用多样化的提示和/或模型。

## 动手构建

`code/main.py` 实现了基于标准库的辩论系统：

- `Debater` 类（脚本化 LLM，每个辩论者有不同的意见漂移）。
- `FullMeshDebate` 和 `SparseDebate` 运行器。
- 三个问题：一个事实型、一个规则型、一个推理型。
- 度量指标：收敛答案、收敛轮次、总批评操作数。

运行方式：

```
python3 code/main.py
```

输出：每种协议的准确率和成本；稀疏拓扑在 2/3 的问题上以更低成本达到与全连接相同的准确率。

## 实际运用

- **Anthropic 编排器-工作器**用于简单的 2-3 个工作器的辩论。
- **LangGraph**用于有状态的多轮辩论，支持检查点。
- **自定义实现**用于研究或需要专门正确性保证的场景。

## 交付产出

`outputs/skill-debate.md` 提供了一个可配置拓扑、N、R 和收敛规则的多智能体辩论模板。

## 练习

1. 实现"强制分歧"规则：在第 1 轮，每个辩论者必须提出不同的提案。衡量其对收敛速度的影响。
2. 添加置信度加权聚合：辩论者返回（答案，置信度）；聚合器按置信度加权。是否有帮助？
3. 将一个"智能体"替换为具有不同意见的另一个脚本化 LLM。异质性是否提高了准确率？
4. 针对你的 3 个问题，衡量全连接与稀疏拓扑的 Token 成本。绘制成本与准确率的关系图。
5. 阅读 Society of Minds 论文。将你的小项目扩展到 N=5、R=3。哪些地方出问题了？哪些方面变好了？

## 关键术语

| 术语 | 字面说法 | 实际含义 |
|------|----------|----------|
| 辩论（Debate） | "多智能体批评" | N 个提议者，R 轮交叉批评，收敛 |
| 全连接（Full mesh） | "每个人看到所有人" | 每个辩论者每轮阅读所有同伴 |
| 稀疏拓扑（Sparse topology） | "有限的同伴视野" | 辩论者只阅读一部分同伴 |
| 中心辐射型（Hub-and-spoke） | "星型拓扑" | 一个中心辩论者，N-1 个辐射节点只阅读中心 |
| 收敛（Convergence） | "达成一致" | 辩论者收敛到共享答案 |
| Society of Minds | "Du 等人的辩论论文" | ICML 2024 多智能体辩论方法 |
