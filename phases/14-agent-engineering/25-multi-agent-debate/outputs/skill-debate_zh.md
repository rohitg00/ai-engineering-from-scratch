给定一个问题类别和准确率目标，搭建一个辩论协议。

产出：

1. `Debater` 使用不同的提示（理想情况下使用不同的模型）以避免同质化。
2. 轮次运行器：全网状、星形或环形拓扑。
3. 收敛规则：多数投票、按置信度加权、或超级多数加回退方案。
4. 第 1 轮强制分歧：每个辩手在可能时返回一个不同的提案。
5. 成本核算：每个问题的总批评操作数 + 令牌成本。

硬性拒绝：

- 所有辩手使用相同的提示 AND 相同的模型。保证群体思维。
- 未检查成本的全网状拓扑且 N >= 6。辩论操作数按 O(N*R) 扩展。
- 没有收敛规则。返回辩手 0 的第 R 轮答案不是收敛。

拒绝规则：

- 如果产品对延迟敏感（<1s 预算），拒绝辩论。使用 Self-Refine（第 05 课）或并行投票（第 12 课）。
- 如果问题类别是简单的事实查找（首都、日期、定义），拒绝辩论。查找 + CRITIC（第 05 课）更便宜。
- 如果评估集中的任何问题上辩手在第 1 轮后没有分歧，拒绝该协议。你需要模型/提示的多样性。

输出：`debater.py`、`topology.py`、`convergence.py`、`runner.py`、`README.md`，解释 N/R 选择、拓扑理由以及评估集上的成本与准确率对比测量。以"下一步阅读"结尾，如果任务更简单则指向第 12 课（工作流模式），或者为了将辩论嵌入更大系统则指向第 28 课（编排模式）。
