# LangGraph：有状态图与持久化执行

> LangGraph 是 2026 年底层有状态编排的参考方案。智能体即状态机；节点是函数；边是转移条件；状态不可变，并在每一步之后进行检查点持久化。可从任意故障处精确恢复，无需重头再来。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 第 14 阶段 · 01（智能体循环），第 14 阶段 · 12（工作流模式）
**时长：** 约 75 分钟

## 学习目标

- 描述 LangGraph 的核心模型：具有不可变状态的状态机、函数节点、条件边及步后检查点。
- 列举文档强调的四个能力：持久化执行、流式输出、人机协同、全面记忆。
- 解释 LangGraph 支持的三种编排拓扑结构：监督者、点对点（群集）、层次化（嵌套子图）。
- 使用标准库实现一个具有不可变状态、条件边和检查点/恢复周期的状态图。

## 问题

智能体和工作流共享一个问题：当一个 40 步的运行在第 38 步失败时，你希望从第 38 步恢复，而不是从头开始。低等的状态模型让运维人员在一个假定每次都是新运行的库上勉强完成重试。

LangGraph 的设计答案：状态是一等类型对象，变更显式，每个节点之后持久化检查点。恢复是一个 `load_state(session_id)` 调用。

## 概念

### 图

一个图由以下部分定义：

- **状态类型。** 一个类型化字典（或 Pydantic 模型），每个节点读取并修改它。
- **节点。** 纯函数 `(state) -> state_update`。更新在返回后合并到状态中。
- **边。** 节点之间的条件转移或直接转移。
- **入口与出口。** `START` 和 `END` 哨兵节点标记边界。

示例：一个包含 `classify`、`refund`、`bug`、`sales`、`done` 节点的智能体——一个作为图的路由工作流。

### 持久化执行

每个节点返回后，运行时会序列化状态并将其写入检查点器（SQLite、Postgres、Redis 或自定义）。如果在第 N 步失败，运行时可以调用 `resume(session_id)` 并从第 N+1 步以精确状态继续执行。

LangGraph 文档明确指出了在生产环境中使用此功能的公司：Klarna、Uber、J.P. Morgan。关键不在于图的形状，而在于图形加上检查点使恢复成本变得低廉。

### 流式输出

每个节点可以产生部分输出。图会流式发送每个节点的增量事件给调用者，因此 UI 可以在图运行时实时更新。

### 人机协同

在节点之间检查并修改状态。实现方式：在关键节点前暂停，向人类展示状态，接受修改，然后恢复。检查点器让这变得简单，因为状态已经序列化。

### 记忆

短期记忆（一次运行内——对话历史记录在状态中）和长期记忆（跨运行——通过检查点器加独立长期存储持久化）。LangGraph 通过工具与外部记忆系统（Mem0、自定义）集成。

### 三种拓扑结构

1. **监督者。** 中央路由器 LLM 将任务分派给专业子智能体。通过 `langgraph-supervisor` 中的 `create_supervisor()` 实现（不过 LangChain 团队在 2026 年建议通过直接的工具调用来实现，以更好地控制上下文）。
2. **群集 / 点对点。** 智能体通过共享的工具表面直接交接，无需中央路由器。
3. **层次化。** 监督者管理子监督者，实现为嵌套子图。

### 此模式的误区

- **检查点粒度过粗。** 仅对对话轮次做检查点会导致工具状态和内存写入不可恢复。完整状态必须序列化。
- **非确定性节点。** 恢复假定节点输入产生相同的状态更新。随机种子、实时时钟、外部 API 必须被捕获。
- **过度使用条件边。** 每条边都是条件边的图是一个无法推理的状态机。优先使用线性链，偶尔分支。

## 构建

`code/main.py` 实现了一个基于标准库的有状态图：

- `State`——一个类型化字典，包含 `messages`、`step`、`route`、`output`、`human_approval`。
- `Node`——可调用对象，接收状态并返回更新字典。
- `StateGraph`——节点 + 边 + 条件边 + 运行 + 恢复。
- `SQLiteCheckpointer`（内存模拟）——每个节点后序列化状态；`load(session_id)` 恢复。
- 一个演示图：classify -> branch(refund / bug / sales) -> human gate -> send。

运行它：

```
python3 code/main.py
```

追踪输出显示第一次运行在 human gate 处失败、持久化，然后恢复产生最终输出。

## 练习

1. 当分类置信度低于阈值时，添加一条从 `classify` 到 `end` 的条件边。在人工手动设置 `route` 后恢复运行。
2. 将模拟 SQLite 检查点器替换为真正的 SQLite 检查点器。测量每步序列化开销。
3. 实现并行边：两个节点并发运行，通过自定义 reducer 合并结果。不可变状态在此有何优势？
4. 阅读 `langgraph-supervisor` 参考文档。将玩具示例迁移到 `create_supervisor`。比较追踪形状的差异。
5. 添加流式输出：每个节点在运行时产生部分状态。打印到达的增量数据。

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|------|-----------|---------|
| 状态图 | "智能体即状态机" | 类型化状态 + 节点 + 边 + reducer |
| 检查点器 | "持久化后端" | 每个节点后序列化状态；支持恢复 |
| Reducer | "状态合并器" | 将当前状态与节点更新合并的函数 |
| 条件边 | "分支" | 由状态函数选择的边 |
| 子图 | "嵌套图" | 作为另一个图节点使用的图 |
| 持久化执行 | "从故障中恢复" | 从最后一个成功节点以精确状态重启 |
| 监督者 | "路由器 LLM" | 专业子智能体的中央调度器 |
| 群集 | "点对点智能体" | 智能体通过共享工具交接；无中央路由器 |
