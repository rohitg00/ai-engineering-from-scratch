# 基于评估的智能体开发（Eval-Driven Agent Development）

> Anthropic 的指导原则："从简单的提示词开始，通过全面的评估进行优化，仅在必要时添加多步智能体系统。"评估不是最后一步。它是驱动第 14 阶段所有其他决策的外层循环。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置条件：** 完成第 14 阶段全部内容
**时长：** 约 60 分钟

## 学习目标

- 说出三个评估层——静态基准、自定义离线评估、在线生产评估——以及各自的作用
- 解释评估器-优化器紧循环（evaluator-optimizer tight loop）
- 描述 2026 年最佳实践：评估与代码共存，在 CI 中运行，门控 PR
- 将第 14 阶段每节课与其产生的评估用例联系起来

## 问题所在

智能体在演示中表现良好，但在生产环境中却以演示无法预测的方式失败。基准测试回答的是"这个模型有广泛的能力吗？"而不是"这个智能体能否为我的产品交付正确的补丁？"答案是：在三个层面持续进行评估，每个护栏和学到的规则都映射到一个评估用例。

## 核心理念

### 三个评估层

1. **静态基准**——代码方面使用 SWE-bench Verified（第 19 课），浏览器/桌面方面使用 WebArena/OSWorld（第 20 课），通用方面使用 GAIA（第 19 课），工具使用方面使用 BFCL V4（第 06 课）。用于跨模型比较和回归门控。数据污染是真实存在的：SWE-bench+ 发现 32.67% 的解决方案泄漏。始终报告 Verified 或 +-audited 分数。

2. **自定义离线评估**——针对你的产品形态：
   - 大模型作为裁判（LLM-as-judge）（Langfuse、Phoenix、Opik——第 24 课）
   - 基于执行的评估（运行补丁，检查测试）
   - 基于轨迹的评估（比较动作序列与黄金标准；OSWorld-Human 显示顶级智能体比黄金标准多 1.4-2.7 倍）

3. **在线评估**——生产环境：
   - 会话回放（Langfuse）
   - 护栏触发的告警（第 16、21 课）
   - 每步成本/延迟追踪（第 23 课 OTel spans）

### 评估器-优化器（Anthropic）

紧循环：

1. 提议者生成输出
2. 评估者评判
3. 持续优化直到评估者通过

这是 Self-Refine（第 05 课）的泛化形式。任何你关心的智能体流程都可以包装成评估器-优化器以提高可靠性。

### 2026 年最佳实践

- 评估与代码共存
- 在每个 PR 的 CI 中运行
- 以评估分数作为合并门控（例如"与主分支相比无超过 5% 的回退"）
- 每个护栏映射到一个评估用例
- 每个学到的规则（Reflexion、pro-workflow learn-rule）映射到一个失败用例

第 14 阶段的每节课都会生成评估用例：

### 基于评估的开发在哪些情况下会失效

- **没有基线。** 没有"上次已知良好"记录的评估毫无意义。请存储基线。
- **大模型裁判缺乏依据。** 裁判也会产生幻觉。CRITIC 模式（第 05 课）——裁判依据外部工具进行判断。
- **过拟合评估。** 针对评估进行优化会偏离生产实用性。请轮换用例。
- **不稳定的评估。** 非确定性用例会导致误报。固定随机种子，快照状态。

## 动手构建

`code/main.py` 是一个基于标准库的评估框架：

- 带有分类的用例注册表（基准、自定义、在线）
- 一个脚本化的待测试智能体
- 评估器-优化器循环：提议、评判、优化直到通过或达到最大轮次
- CI 门控：聚合通过率 + 与基线对比的回归检测

运行它：

```
python3 code/main.py
```

输出：每个用例的通过/失败状态、回归标志、CI 门控裁决。

## 如何使用

- 在与智能体代码相同的仓库中编写评估用例
- 通过 CI 在每个 PR 上运行它们
- 出现回归时使构建失败
- 追踪通过率随时间的变化
- 将每个生产故障与一个新的评估用例关联

## 交付物

`outputs/skill-eval-suite.md` 为一个智能体产品构建包含 CI 门控和回归跟踪的三层评估套件。

## 练习

1. 找一个你曾经遇到的生产故障，编写一个能复现它的评估用例。你的智能体现在能通过它吗？
2. 为你的领域构建一个包含三个维度（事实准确性、语气、范围）的大模型裁判评分标准，并对 50 个会话进行评分。
3. 将评估套件接入 CI。当回归 >=5% 时使构建失败。
4. 添加一个轨迹效率指标：智能体执行了多少步，与黄金轨迹相比如何？
5. 将第 14 阶段的每节课映射到你的套件中的一个评估用例。有没有缺失的？那就是需要填补的空白。

## 关键术语

| 术语 | 日常说法 | 实际含义 |
|------|----------------|------------------------|
| 静态基准 | "现成的评估" | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| 自定义离线评估 | "领域评估" | 大模型作为裁判 / 基于执行 / 基于轨迹，针对你的产品形态 |
| 在线评估 | "生产评估" | 会话回放、护栏告警、成本/延迟追踪 |
| 评估器-优化器 | "提议-评判-优化" | 迭代直到裁判通过 |
| CI 门控 | "合并阻断" | 评估回归时使构建失败 |
| 基线 | "上次已知良好" | 用于检测回归的参考分数 |
| 轨迹效率 | "步数与黄金标准之比" | 智能体步数除以人类专家最小步数 |
