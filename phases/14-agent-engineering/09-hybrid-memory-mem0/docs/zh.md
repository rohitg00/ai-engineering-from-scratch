# 混合记忆：向量 + 图 + KV（Mem0）

> Mem0（Chhikara 等人，2025）将记忆视为三个并行的存储——向量用于语义相似度，KV 用于快速事实查找，图用于实体关系推理。检索时通过一个评分层融合三者。这是 2026 年外部记忆的生产标准。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 阶段 14 · 07（MemGPT），阶段 14 · 08（Letta Blocks）
**时间：** 约 75 分钟

## 学习目标

- 解释为什么单一存储（仅向量、仅图、仅 KV）不足以作为智能体记忆。
- 说出 Mem0 的三个并行存储及其各自的优化目标。
- 描述 Mem0 的融合评分——相关性（Relevance）、重要性（Importance）、时效性（Recency）——以及为什么它是加权求和而非层级结构。
- 使用标准库实现一个玩具版三存储记忆，包含写入全部三个存储的 `add()` 和融合结果的 `search()`。

## 问题所在

单一存储对三类查询中的两类都是错误的：

- **语义相似度** ——"我们上周讨论了关于智能体漂移的什么内容？"向量胜出；KV 和图无法胜任。
- **事实查找** ——"用户的电话号码是多少？"KV 胜出；向量是浪费，图是过度设计。
- **关系推理** ——"哪些客户共享同一个计费实体？"图胜出；向量和 KV 无法回答。

生产环境中的智能体在一次会话中会提出所有三类查询。单一存储记忆总是对其中的两类是错误的。Mem0 的贡献在于将三者统一到单一的 `add`/`search` 接口背后，并通过评分函数将结果融合。

## 概念

### 三个并行存储

Mem0（arXiv:2504.19413，2025 年 4 月）的 `add(text, user_id, metadata)` 流程：

1. 从文本中提取候选事实（由 LLM 驱动的步骤）。
2. 将每个事实写入向量存储（嵌入）以支持语义搜索。
3. 将每个事实写入 KV 存储，键为 `(user_id, fact_type, entity)`，以支持 O(1) 查找。
4. 将每个事实写入图存储（Mem0g），作为带类型边，以支持关系查询。

`search(query, user_id)` 流程：

1. 向量存储通过嵌入余弦相似度返回 top-k 结果。
2. KV 存储返回基于查询派生的 `(user_id, type, entity)` 键的直接命中结果。
3. 图存储返回从查询实体出发可达的子图。
4. 评分层融合三个来源的结果。

### 融合评分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性（Relevance）** ——向量余弦相似度、KV 精确匹配、图路径权重。
- **重要性（Importance）** ——写入时标记或通过学习获得（某些事实更重要：姓名、ID、策略）。
- **时效性（Recency）** ——自上次写入或读取以来按指数衰减。

权重根据产品调整。聊天智能体使用更高的 `w_recency`；合规智能体使用更高的 `w_importance`；检索智能体使用更高的 `w_relevance`。

### Mem0g 与时间推理

Mem0g 添加了一个冲突检测器。当一个新事实与现有边冲突时，现有边被标记为无效但不会被删除。时间查询（"用户三月份所在的城市是哪里？"）会遍历在指定时间有效的子图。

这是 Letta 的失效模式推广后的合规级行为。

### 基准数据

Mem0 论文（2025）报告的数据：

- **LoCoMo**（长对话记忆）：91.6
- **LongMemEval**（长周期情景记忆）：93.4
- **BEAM 1M**（100 万 token 记忆基准）：64.1

对比基线（全上下文 128k LLM、平面向量存储、平面 KV）均落后 10 分以上。基准数据本身不足以决定方案选择——实际操作性才是关键——但这些数字表明融合设计并非四舍五入的误差。

### 作用域分类

Mem0 按作用域划分记忆：

- **用户记忆（User memory）** ——跨会话持久化，以 `user_id` 为键。
- **会话记忆（Session memory）** ——在单个线程内持久化。
- **智能体记忆（Agent memory）** ——每个智能体实例的状态。

每次写入选择一个作用域。检索可以跨作用域查询，并为每个作用域设置不同的权重。不加思考地混用作用域会导致"助手把 Bob 的项目告诉了 Alice"之类的事故。

### 这种模式的常见问题

- **嵌入漂移（Embedding drift）** 。开头一百次查询看起来正确的向量结果，随着语料库增长而退化。定期对使用频率最高的 N 条记录重新嵌入。
- **KV 模式蔓延（KV schema creep）** 。`(user_id, type, entity)` 看起来很简单，直到每个团队都添加自己的 `type`。每季度审计一次类型集合。
- **图爆炸（Graph explosion）** 。一个嘈杂的提取器每消息添加 50 条边。限制每次 `add` 调用的图写入量；丢弃低置信度的边。

## 动手构建

`code/main.py` 使用标准库实现了三存储模式：

- `VectorStore` ——使用朴素 token 重叠相似度作为嵌入的替代品。
- `KVStore` ——以 `(user_id, fact_type, entity)` 为键的字典。
- `GraphStore` ——带类型边（subject, relation, object, valid）。
- `Mem0` ——顶层外观，提供 `add()`、`search()`、融合评分以及作用域感知检索。
- 一个多用户、多会话对话的完整运行示例。

运行：

```
python3 code/main.py
```

输出显示三条独立的召回路径以及融合后的 top-k。修改 `main()` 顶部的评分权重，观察排序的变化。

## 使用

- **Mem0（Apache 2.0）** ——生产就绪。使用 Postgres + Qdrant + Neo4j 自托管，或使用托管云服务。
- **Letta** ——三层核心/召回/归档架构；可自带向量和图后端。
- **Zep** ——商业替代方案，具有时间知识图谱和事实提取功能。
- **自定义构建** ——当你需要精确控制提取器（合规）或融合权重（时效性占主导的语音智能体）时。

## 练习

1. 将玩具版向量相似度替换为真实的嵌入模型（sentence-transformers、Ollama、OpenAI embeddings）。在合成长对话上测量 recall@10。经过 1000 次写入后排序是否发生漂移？
2. 添加时间查询：`search(query, as_of=timestamp)`。只返回在该时间或之前有效的记录。哪个存储需要做最多改动？
3. 实现冲突检测器：如果传入的事实与图边冲突，使旧边失效并记录两者。用"用户住在柏林"→"用户住在里斯本"进行测试。
4. 在融合评分器中加入 `user_feedback` 维度（对检索记录点赞）。如何防止作弊（智能体只返回它已经喜欢的记录）？
5. 阅读 Mem0 文档（`docs.mem0.ai`）。将玩具版移植为使用 `mem0` 客户端调用。在相同的 20 条测试查询上比较检索质量。

## 关键术语

| 术语 | 通常说法 | 实际含义 |
|------|---------|---------|
| 混合记忆（Hybrid memory） | "向量加图加 KV" | 三个并行写入、检索时融合的存储 |
| 事实提取（Fact extraction） | "记忆摄入" | LLM 步骤，将文本拆解为（实体、关系、事实）元组 |
| 融合评分（Fusion scoring） | "相关性排序" | 相关性、重要性、时效性的加权和 |
| 作用域（Scope） | "记忆命名空间" | 用户/会话/智能体——决定谁能看到什么 |
| Mem0g | "记忆图" | 带时间有效性的类型边，用于关系查询 |
| 时间失效（Temporal invalidation） | "软删除" | 将冲突边标记为无效；从不删除 |
| 嵌入漂移（Embedding drift） | "检索腐烂" | 向量质量随着语料库增长而退化；定期重新嵌入 |
