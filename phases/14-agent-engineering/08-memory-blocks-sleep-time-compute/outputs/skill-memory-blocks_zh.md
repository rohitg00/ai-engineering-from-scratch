给定目标运行时、主模型和（可能更强的）休眠时间模型，生成一个包含显式块类型和异步整合的三层记忆系统。

产出：

1. `Block` 类型，包含 `label`、`value`、`limit`、`description`、`version`、`history`。每次写入都会增加版本号并记录旧值。暴露 `near_limit(threshold=0.8)`。
2. 一个 `BlockStore`，至少包含三个默认块：`human`（关于用户的事实）、`persona`（智能体的自我概念）和 `task`（当前范围）。允许用户定义的块。
3. 一个 `Recall` 存储——按会话分页的轮次日志。每轮自动写入。尾部在达到上限时逐出，但仍可检索。
4. 一个 `Archival` 存储——至少两个后端（向量、KV）。插入返回记录 id。在出现矛盾时标记为无效而非删除。
5. 一个 `PrimaryAgent`，处理轮次并仅发出原始写入。关键路径上不进行总结。
6. 一个 `SleepTimeAgent`，在轮次之间运行：总结超过阈值的块、使矛盾的存档记录无效、将 `learned_context` 写入共享块。

硬性拒绝：

- 任何在面向用户的轮次中同步运行的记忆操作，直接查找除外。总结、整合、无效化属于休眠时间传递。
- 在出现矛盾时删除存档记录。使用无效化以便历史记录保持可审计。
- 在没有审查步骤的情况下写入 Persona 或 Safety 块。这些块全局性地塑造行为；静默写入会掩盖错误。

拒绝规则：

- 如果运行时无法跨会话持久化块，拒绝交付描述为"记忆"的产品。降低声称的级别。
- 如果休眠时间代理没有跟踪输出，拒绝。静默整合是调试的死区。
- 如果用户要求"不进行无效化，始终信任最新写入"，在历史性声明重要的领域（合规、医疗、法律）中拒绝。

输出：每个组件一个文件加上一个 `README.md`，命名默认块、休眠时间节奏和矛盾解决策略。以"下一步阅读"结束，如果代理需要对记忆进行图推理则指向第 09 课，如果产品需要对记忆操作使用 OTel span 则指向第 23 课。
