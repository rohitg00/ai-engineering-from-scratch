# 记忆块与休眠期计算（Letta）

> MemGPT 于 2024 年更名为 Letta。2026 年的演进引入了两个新概念：离散的功能性记忆块（模型可直接编辑），以及休眠期智能体（在主智能体空闲时异步整理记忆）。这就是将记忆扩展到单次对话之外的方法。

**类型：** 构建
**语言：** Python（标准库）
**前置条件：** 阶段 14 · 07（MemGPT）
**时长：** 约 75 分钟

## 学习目标

- 说出 Letta 使用的三个记忆层级（核心、回忆、归档）及其各自的作用。
- 解释记忆块模式：人类块、角色块以及用户自定义块，作为一等类型对象。
- 描述休眠期计算是什么、为何它位于关键路径之外，以及为何它可以运行比主智能体更强的模型。
- 实现一个脚本化的双智能体循环：主智能体负责响应，休眠期智能体在轮次之间整理记忆块。

## 问题所在

MemGPT（第 07 课）解决了虚拟内存控制流的问题。但在生产环境中出现了三个问题：

1. **延迟。** 每次记忆操作都位于关键路径上。如果智能体需要在用户等待时进行剪枝、总结或调合，尾延迟会急剧增加。
2. **记忆衰退。** 写入不断累积。矛盾的事实仍然存在。检索被过时内容淹没。
3. **结构缺失。** 扁平化的归档存储无法表达"人类块始终在提示中；角色块始终在提示中；任务块按会话切换"。

Letta（letta.com）是 2026 年的重写版。记忆块使结构显式化；休眠期计算将整理工作移出关键路径。

## 概念

### 三个层级

| 层级 | 范围 | 存放位置 | 写入者 |
|------|------|----------|--------|
| 核心 | 始终可见 | 主提示内部 | 智能体工具调用 + 休眠期重写 |
| 回忆 | 对话历史 | 可检索 | 自动轮次日志 |
| 归档 | 任意事实 | 向量 + KV + 图 | 智能体工具调用 + 休眠期摄入 |

核心即 MemGPT 的核心。回忆是对话缓冲区及其被逐出的尾部。归档是外部存储。这种划分清理了 MemGPT 两层混淆的问题。

### 记忆块

记忆块是核心层级中一种有类型、持久化、可编辑的片段。原始的 MemGPT 论文定义了两个：

- **人类块**——关于用户的事实（姓名、角色、偏好、目标）。
- **角色块**——智能体的自我概念（身份、语气、约束）。

Letta 将其泛化为任意用户自定义块：用于当前目标的`任务`块、用于代码库事实的`项目`块、用于硬约束的`安全`块。每个块都有`id`、`label`、`value`、`limit`（字符上限）、`description`（以便模型知道何时编辑它）。

块通过工具接口进行编辑：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)`——压缩接近上限的块。

### 休眠期计算

2025 年 Letta 新增功能：在后台运行第二个智能体，位于关键路径之外。休眠期智能体处理对话记录和代码库上下文，将`learned_context`写入共享块，并整理或失效归档记录。

由此产生的特性：

- **无延迟代价。** 主响应无需等待记忆操作。
- **允许更强的模型。** 休眠期智能体可以使用更昂贵、更慢的模型，因为它不受延迟约束。
- **自然的整理窗口。** 在用户不等待时去重、总结、失效矛盾的事实。

这种模式与人类的工作方式一致：你完成任务，然后"睡一觉"，长期记忆在一夜间沉淀。

### Letta V1 与原生推理

Letta V1（`letta_v1_agent`，2026）弃用了 `send_message`/心跳以及内联 `Thought:` 标记，转而使用原生推理。Responses API（OpenAI）和 Messages API 扩展思考（Anthropic）在独立通道上输出推理，并在轮次之间传递（生产环境中跨提供商加密）。控制循环仍然是 ReAct。思维轨迹是结构性的，而非提示塑造的。

### 这种模式在何处失效

- **块膨胀。** 无限的 `block_append` 会很快触及上限。在写入即将超出上限之前，接入一个块压缩器。
- **静默漂移。** 休眠期智能体重写了块，但主智能体从未察觉。对块进行版本控制，并在轨迹中展示差异。
- **投毒式整理。** 休眠期智能体将攻击者可触及的内容处理到核心中。第 27 课的内容同样适用于休眠期接口。

## 动手构建

`code/main.py` 实现了：

- `Block` —— id、label、value、limit、description。
- `BlockStore` —— CRUD + `near_limit(label)` 辅助方法。
- 两个脚本化智能体 —— `PrimaryAgent` 处理一轮对话，`SleepTimeAgent` 在轮次之间进行整理。
- 一个追踪轨迹，展示三轮对话中的块写入，以及一个将块总结并失效过时事实的休眠期过程。

运行方式：

```
python3 code/main.py
```

输出记录展示了分离效果：主轮次快速执行并产生原始写入；休眠期过程进行压缩和清理。

## 使用方式

- **Letta**（letta.com） —— 参考实现。可自托管或使用托管云。
- **Claude Agent SDK 技能** —— 作为块状知识。技能是智能体按需加载的一组有名称、有版本、可检索的指令块。
- **自定义构建** —— 适合希望控制存储后端的团队。使用 Letta API 契约，以便后续可以迁移。

## 交付产物

`outputs/skill-memory-blocks.md` 生成一个带有休眠期钩子的 Letta 式块系统，适用于任何运行时，包括安全规则和引用接线。

## 练习

1. 添加一个 `block_summarize` 工具：当 `near_limit` 返回 true 时，用模型生成的摘要替换块的值。哪个触发阈值能使摘要调用次数和块溢出同时最小化？
2. 在归档上实现休眠期去重：两个文本的 token 重叠度超过 90% 的记录合并为一个。仅在休眠期过程中执行，绝不在关键路径上执行。
3. 对块进行版本控制。每次写入时记录旧值和差异。暴露 `block_history(label)` 以便运维人员调试"为什么智能体忘记了 X"。
4. 将休眠期智能体视为不可信写入者。当它们修改角色块或安全块时，需要第二个智能体审核后才能提交。
5. 将示例移植到使用 Letta API（`letta_v1_agent`）。块模式有何变化？原生推理如何改变轨迹形状？

## 关键术语

| 术语 | 通常说法 | 实际含义 |
|------|----------|----------|
| 记忆块 | "可编辑的提示片段" | 核心记忆中有类型、持久化、可被 LLM 编辑的片段 |
| 人类块 | "用户记忆" | 关于用户的事实，固定在核心中 |
| 角色块 | "智能体身份" | 自我概念、语气、约束，固定在核心中 |
| 休眠期计算 | "异步记忆工作" | 第二个智能体在关键路径之外进行整理 |
| 核心 / 回忆 / 归档 | "层级" | 三层记忆划分：始终可见 / 对话 / 外部 |
| 块上限 | "容量" | 每个块的字符上限；强制触发摘要 |
| 原生推理 | "思考通道" | 提供商级别的推理输出，而非提示级别的 `Thought:` |
| 学习到的上下文 | "休眠期输出" | 休眠期智能体写入共享块的事实 |
