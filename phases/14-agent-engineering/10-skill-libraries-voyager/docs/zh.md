# 技能庫與終身學習（Voyager）

> Voyager（Wang 等人，TMLR 2024）把可執行的程式碼當成一項技能。技能是具名的、可檢索的、可組合的，並由環境回饋來精修。這是 Claude Agent SDK 技能、skillkit 與 2026 年技能庫模式的參考架構。

**類型：** 實作
**程式語言：** Python (stdlib)
**先修單元：** 階段 14 · 07（MemGPT）、階段 14 · 08（Letta 區塊）
**時間：** 約 75 分鐘

## 學習目標

- 說出 Voyager 的三個組件 —— 自動課程、技能庫、迭代式提示 —— 以及各自的角色。
- 解釋 Voyager 為何把行動空間做成程式碼，而不是原始指令。
- 用 stdlib 實作一個技能庫，含註冊、檢索、組合與由失敗驅動的精修。
- 把 Voyager 的模式對映到 2026 年的 Claude Agent SDK 技能與 skillkit 生態系。

## 問題所在

每個工作階段都把每項能力從零重建一遍的代理，做錯了三件事：

1. **浪費詞元。** 每項任務都把同一套推理再誘導一次。
2. **丟掉進度。** 在工作階段 A 學到的修正，帶不到工作階段 B。
3. **在長時程的組合上失敗。** 複雜任務需要能力階層；一次性的提示詞表達不出來。

Voyager 的答案：把每項可重用的能力當成一段具名的程式碼，存進一個庫裡，可依相似度檢索、可與其他技能組合，並由執行回饋來精修。

## 核心概念

### 三個組件

Voyager（arXiv:2305.16291）把一個代理圍繞著這些東西來組織：

1. **自動課程。** 一個由好奇心驅動的提議者，依代理當前的技能集與環境狀態挑出下一項任務。探索是由下而上的。
2. **技能庫。** 每項技能都是可執行的程式碼。任務成功時就加入新技能。技能依「查詢對描述」的相似度被檢索。
3. **迭代式提示機制。** 失敗時，代理會收到執行錯誤、環境回饋與自我查證的輸出，然後精修那項技能。

Minecraft 上的評測（Wang 等人，2024）：相對於基線，取得的獨特物品多 3.3 倍、做出石器快 8.5 倍、做出鐵器快 6.4 倍、地圖走的距離長 2.3 倍。這些數字是 Minecraft 專屬的，但模式是可移轉的。

### 行動空間 = 程式碼

多數代理吐出的是原始指令。Voyager 吐出的是 JavaScript 函數。一項技能是：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能組成。以描述與嵌入為鍵存起來。檢索回來的是一支程式，不是一段提示詞。

這就是 2026 年的 Claude Agent SDK 技能：一段具名、可檢索的程式碼加上指示，代理按需載入。

### 技能檢索

新任務「做一把鑽石鎬」。代理會：

1. 把任務描述嵌入。
2. 向技能庫查詢 top-k 個相似技能。
3. 檢索出 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等等。
4. 用檢索到的原語加上新邏輯，組出新技能。

這就是 MCP 資源（階段 13）與 Agent SDK 技能所實作的模式：在一片知識／程式碼表面上做檢索，範圍限定在當前任務。

### 迭代式精修

Voyager 的回饋迴圈：

1. 代理寫下一項技能。
2. 技能對著環境執行。
3. 回傳三種訊號之一：`success`、`error`（含堆疊追蹤）、`self-verification failure`。
4. 代理拿那個訊號當脈絡重寫技能。
5. 迴圈直到成功或達到最大回合數。

這就是 Self-Refine（第 05 課）套用在程式碼生成上，配以環境接地的查證。CRITIC（第 05 課）是同一套模式，只是查證者換成外部工具。

### 課程與探索

Voyager 的課程模組會依「代理已經有什麼、還沒做過什麼」提出像「在湖邊蓋一間庇護所」這樣的任務。提議者用環境狀態加技能清單，挑一項略高於當前能力的任務 —— 探索的甜蜜點。

對生產代理而言，這翻譯成一個「還缺什麼」的運算子：給定當前技能庫與一個領域，我們還沒涵蓋哪些技能？團隊通常會把這件事以課程審查的方式手動實作。

### 這套模式在哪裡會出錯

- **技能庫腐爛。** 同一項技能用略有不同的描述被加了 10 次。要在寫入時去重；檢索只回傳一個。
- **組合技能漂移。** 父技能相依於一個被精修過的子技能。要給技能做版本；釘在 v1 的父技能不會神奇地撿到 v3。
- **檢索品質。** 在技能描述上做向量檢索，當庫長到幾百項以上就會退化。要補上標籤過濾與硬性條件（「只要 `category=tooling` 的技能」）。

```figure
voyager-skills
```

## 動手實作

`code/main.py` 用 stdlib 實作一個技能庫：

- `Skill` —— name、description、code（字串形式）、version、tags、dependencies。
- `SkillLibrary` —— 註冊、搜尋（詞元重疊）、組合（對相依做拓撲排序）、精修（更新時版本進位）。
- 一個腳本化的代理：註冊三項原語技能、組出第四項、撞上一次失敗，然後精修。

跑它：

```
python3 code/main.py
```

軌跡顯示了庫的寫入、檢索、組合、一次失敗的執行，以及一次 v2 精修 —— Voyager 那個迴圈從頭到尾。

## 框架應用

- **Claude Agent SDK 技能**（Anthropic）—— 2026 年的參考做法：每項技能有描述、程式碼與指示；在代理工作階段中按需載入。
- **skillkit**（npm: skillkit）—— 為 32 種以上 AI 寫程式代理提供跨代理的技能管理。
- **自製技能庫** —— 領域專屬（給資料代理的 SQL 技能、給基礎設施代理的 Terraform 技能）。Voyager 的模式縮得下來。
- **OpenAI Agents SDK 的 `tools`** —— 在低階那一端；每項工具就是一項輕量技能。

## 產出交付

`outputs/skill-skill-library.md` 會替任何目標執行環境產出一個 Voyager 形狀的技能庫，註冊、檢索、版本與精修都接好。

## 練習

1. 給 `compose()` 加一個相依環偵測器。當技能 A 相依 B、B 又相依 A 時會發生什麼事？該報錯還是警告？
2. 實作逐技能的版本釘選。當父技能組合了子技能 `crafting@1`，一次對 `crafting@2` 的精修不能無聲地把父技能升上去。
3. 把詞元重疊檢索換成 sentence-transformers 嵌入（或一份 stdlib 的 BM25 實作）。在一個 50 項技能的玩具庫上量 retrieval@5。
4. 加一個「課程」代理：給定當前的庫與一段領域描述，提出 5 項缺少的技能。每週呼叫它一次。
5. 讀 Anthropic 的 Claude Agent SDK 技能文件。把這個玩具庫移植到該 SDK 的技能 schema。可發現性有什麼改變？

## 關鍵術語

| 術語 | 大家怎麼說 | 實際是什麼意思 |
|------|----------------|------------------------|
| 技能 | 「可重用的能力」 | 具名的一段程式碼＋描述，可依相似度檢索 |
| 技能庫 | 「代理對做法的記憶」 | 存放技能的持久儲存，可搜尋、可組合 |
| 課程 | 「任務提議者」 | 由當前能力落差驅動、由下而上的目標產生器 |
| 組合 | 「技能 DAG」 | 技能調用技能；執行時做拓撲排序 |
| 迭代式精修 | 「自我修正迴圈」 | 環境回饋＋錯誤＋自我查證，折回下一個版本裡 |
| 行動空間即程式碼 | 「程式化的行動」 | 吐出函數而非原始指令，以支撐時間上延展的行為 |
| 寫入時去重 | 「技能塌縮」 | 近乎重複的描述塌縮成單一份正典技能 |
