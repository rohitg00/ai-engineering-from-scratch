# 技能库与终身学习（Voyager）

> Voyager（Wang 等，TMLR 2024）将可执行代码视作一种技能。技能是可命名、可检索、可组合、可通过环境反馈进行精炼的。这是 Claude Agent SDK 中 skills、skillkit 以及 2026 年技能库模式的参考架构。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 第 14 阶段 · 07（MemGPT）、第 14 阶段 · 08（Letta Blocks）
**时长：** 约 75 分钟

## 学习目标

- 说出 Voyager 的三个组件——自动课程（automatic curriculum）、技能库（skill library）、迭代提示（iterative prompting）——以及每个组件的作用。
- 解释为何 Voyager 将动作空间设为代码而非原始命令。
- 实现一个包含注册、检索、组合和故障驱动精炼的标准库技能库。
- 将 Voyager 模式映射到 2026 年 Claude Agent SDK 的 skills 和 skillkit 生态系统。

## 问题

在每个会话中从头重建所有能力的代理存在三个问题：

1. **浪费 Token。** 每项任务都会重新触发相同的推理过程。
2. **无法积累进度。** 在会话 A 中学到的修正不会传递到会话 B。
3. **长期组合任务失败。** 复杂任务需要能力层次结构；一次性提示无法表达这些结构。

Voyager 的答案是：将每个可复用能力视为一个命名的代码块，存储在库中，可通过相似度检索，可与其他技能组合，并通过执行反馈进行精炼。

## 概念

### 三个组件

Voyager（arXiv:2305.16291）围绕代理构建了以下三个组件：

1. **自动课程。** 一个好奇心驱动的提议者根据代理当前的技能集和环境状态选择下一个任务。探索是自下而上的。
2. **技能库。** 每个技能都是可执行代码。当任务成功时添加新技能。通过查询与描述之间的相似度来检索技能。
3. **迭代提示机制。** 失败时，代理接收执行错误、环境反馈和自验证输出，然后精炼技能。

Minecraft 评估结果（Wang 等，2024）：相比基线，独特物品数多 3.3 倍，石制工具快 8.5 倍，铁制工具快 6.4 倍，地图遍历距离长 2.3 倍。这些数字是 Minecraft 特有的，但该模式是可迁移的。

### 动作空间 = 代码

大多数代理发出的是原始命令。Voyager 发出的是 JavaScript 函数。一个技能示例如下：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。以描述和嵌入为键进行存储。以程序而非提示的形式被检索。

这就是 2026 年 Claude Agent SDK 技能：一个命名的、可检索的代码块，附带代理按需加载的指令。

### 技能检索

新任务："制造一把钻石镐。" 代理：

1. 对任务描述进行嵌入。
2. 查询技能库以获取 top-k 个相似技能。
3. 检索出 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等。
4. 从检索到的原语 + 新逻辑组合出新技能。

这是 MCP 资源（第 13 阶段）和 Agent SDK 技能所实现的模式：在知识/代码表面对当前任务范围进行检索。

### 迭代精炼

Voyager 的反馈循环：

1. 代理编写一个技能。
2. 技能在环境中运行。
3. 返回三种信号之一：`success`（成功）、`error`（错误，附堆栈跟踪）、`self-verification failure`（自验证失败）。
4. 代理利用该信号作为上下文重写技能。
5. 循环直至成功或达到最大轮数。

这是将 Self-Refine（第 05 课）应用于代码生成，并结合了基于环境的验证。CRITIC（第 05 课）是相同的模式，只是使用外部工具作为验证器。

### 课程与探索

Voyager 的课程模块根据代理已经拥有什么、尚未做什么来提议任务，例如"在湖边建造一个庇护所"。提议者利用环境状态 + 技能清单，选择一项略高于当前能力的任务——即探索的最佳点。

对于生产环境中的代理，这转化为一个"缺少什么"的算子：给定当前的技能库和某个领域，我们还有哪些技能没有覆盖？团队通常以课程评审的方式手动实现这一点。

### 该模式可能出问题的地方

- **技能库腐败。** 同一技能被添加 10 次，仅描述略有不同。应在写入时进行去重；检索时只返回一个。
- **组合技能漂移。** 父技能依赖于某个已被精炼的子技能。应对技能进行版本管理；锁定在 v1 的父技能不会自动升级到 v3。
- **检索质量。** 当技能库增长到几百个以上时，基于向量对技能描述进行检索的效果会下降。应辅以标签过滤和硬约束（如"仅限 `category=tooling` 的技能"）。

## 动手构建

`code/main.py` 实现了一个标准库技能库：

- `Skill`——名称、描述、代码（字符串形式）、版本、标签、依赖项。
- `SkillLibrary`——注册、搜索（Token 重叠）、组合（依赖的拓扑排序）和精炼（更新时版本号增加）。
- 一个脚本化代理，注册三个原始技能，组合出第四个技能，遭遇失败，然后进行精炼。

运行方式：

```
python3 code/main.py
```

运行轨迹展示了库写入、检索、组合、一次失败执行以及 v2 精炼——即 Voyager 完整的端到端循环。

## 使用场景

- **Claude Agent SDK skills**（Anthropic）——2026 年参考实现：每个技能都包含描述、代码和指令；在代理会话期间按需加载。
- **skillkit**（npm: skillkit）——面向 32+ 款 AI 编码代理的跨代理技能管理工具。
- **自定义技能库**——领域专用（数据分析代理的 SQL 技能、基础设施代理的 Terraform 技能）。Voyager 模式可向下伸缩。
- **OpenAI Agents SDK `tools`**——较低端的实现；每个工具都是一个轻量级技能。

## 发布

`outputs/skill-skill-library.md` 生成一个 Voyager 风格的技能库，包含注册、检索、版本管理和精炼功能，可适配任何目标运行时。

## 练习

1. 为 `compose()` 添加一个依赖环检测器。当技能 A 依赖技能 B，而技能 B 又依赖技能 A 时，应该报错还是发出警告？
2. 实现每个技能的版本锁定。当父技能组合了子技能 `crafting@1` 时，对 `crafting@2` 的精炼不得静默升级父技能。
3. 将 Token 重叠检索替换为 sentence-transformers 嵌入（或 BM25 标准库实现）。在包含 50 个技能的测试库上测量 retrieval@5。
4. 添加一个"课程"代理：给定当前技能库和一个领域描述，提议 5 个缺失的技能。每周运行一次。
5. 阅读 Anthropic 的 Claude Agent SDK 技能文档。将测试库移植到 SDK 的技能模式。可发现性发生了哪些变化？

## 关键术语

| 术语 | 人们常说的意思 | 实际含义 |
|------|----------------|----------|
| 技能（Skill） | "可复用能力" | 命名的代码块 + 描述，可通过相似度检索 |
| 技能库（Skill library） | "代理的操作方法记忆" | 技能的持久化存储库，可搜索和组合 |
| 课程（Curriculum） | "任务提议者" | 由当前能力差距驱动的自下而上的目标生成器 |
| 组合（Composition） | "技能 DAG" | 技能调用技能；执行时按拓扑排序 |
| 迭代精炼（Iterative refinement） | "自纠正循环" | 环境反馈 + 错误 + 自验证反哺到下一版本 |
| 动作空间即代码（Action-space-as-code） | "可编程动作" | 发出函数而非原始命令，以实现时间上扩展的行为 |
| 写入时去重（Dedup on write） | "技能折叠" | 近乎重复的描述折叠为一个规范技能 |
