给定用户请求和工具目录（名称、输入模式、描述），生成一个 ReWOO 计划：一个包含工具调用和证据引用（`#E1`、`#E2`、...）的 DAG 步骤图。在将计划交给执行器之前进行验证。

产出：

1. 一个计划 DAG。每个节点包含 id（`E1`、`E2`、...）、工具名称、参数字典（字符串可能包含 `#E<k>` 引用）以及可选的 `parallel_group` 标签。
2. 验证输出。通过拓扑排序进行无环检查；引用解析检查（每个 `#E<k>` 都有一个前置生产者）；工具存在性检查（每个工具名称都在目录中）；参数模式检查（每个参数与工具的输入模式匹配）。
3. 并行性提示。对于每个拓扑层级，列出可以并发执行的节点。
4. 规划器/求解器拆分建议。如果计划少于 3 步，建议使用 ReAct。如果计划有无界循环需求（每一步都重新规划），建议使用带有重新规划器的 Plan-and-Execute。如果计划超过 30 步或针对 Web/移动端，建议使用带有合成计划数据的 Plan-and-Act。

硬性拒绝：

- 包含循环的计划。ReWOO 假定为 DAG；循环属于 ReAct 或 LATS 的范畴。
- 引用了在拓扑顺序中尚不存在的 `#E<k>` 的计划。指出具体失败的边。
- 调用目录中不存在的工具的计划。不要为了让计划可行而发明工具。
- 引用的参数类型与工具模式不匹配的计划（例如，`#E1` 替换了一个字符串，但工具期望的是 int）。

拒绝规则：

- 如果任务是开放式探索（需要未知工具、未知步骤），则拒绝并推荐 ReAct 或 LATS（第 04 课）。
- 如果工具目录包含破坏性工具而没有门控审批工具，则拒绝并指向第 09 课（权限、沙箱化）。

输出：结构化计划（JSON 或 YAML）、验证报告、并行性映射以及指向执行器（ReWOO Worker）、重新规划器（Plan-and-Execute）或更大轨迹采样循环（Plan-and-Act）的后续操作。

以"下一步阅读"注释结尾，如果任务类别之前已尝试过则指向第 03 课（Reflexion），如果计划能从搜索中受益则指向第 04 课（LATS）。
